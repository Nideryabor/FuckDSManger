## 一、为什么「dex = 源码」

这个项目 1.0.7 → 2.22.1xx 是**纯手写 smali**（README 原话：*代码形态：纯手写 Smali（无 java / python 工具链）*）。
那时没有 Java 源，**改的就是 dex**；而 `dex --baksmali--> smali` 是**无损可逆**的。
所以：**手上任何一个当时的 dex / APK，都能 100% 还原出当时的源码。**

## 四、怎么还原成可读 smali

```sh
SC="/usr/share/java/smali.jar:/usr/share/java/baksmali.jar:/usr/share/java/dexlib2.jar:/usr/share/java/smali-util.jar:/usr/share/java/jcommander.jar:/usr/share/java/guava.jar"

# ① 存档 dex → smali
java -cp "$SC" org.jf.baksmali.Main disassemble 版本存档/dex/b110__classes.dex -o /tmp/还原

# ② 任意 APK → smali
java -cp "$SC" org.jf.baksmali.Main disassemble 某包.apk -o /tmp/还原

# ③ smali → 重新组装成 dex
java -cp "$SC" org.jf.smali.Main assemble 版本存档/b110_sm -o /tmp/rebuilt.dex
```

## 五、⚠️ 教训（写给自己）

1. **`tmp/` 不是垃圾桶，是历史仓库。** 这次全靠它救了场。以后 `tmp/` 里的存档目录
   定期**搬进 `版本存档/`**，别等出事才翻。
2. **dex 要当源码对待**（手写 smali 时代）。
3. **APK 不入库 = 一次误删就是灭顶**：`.gitignore` 有 `*.apk`，跟踪清单 15064 条里 **0 个 apk**。
   至少要把 **模块 dex（每个≈200KB）** 入库 —— 它才是真正的源码，而 1141 个成品 APK 反而可以只留最新的。
4. `fdm230_sm/`（39 类）里那份 `GmEntry.smali` 是**最早的手写入口**，别丢。
