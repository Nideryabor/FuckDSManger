## 一句话原理

**不碰 Compose、不改业务逻辑**，直接往宿主同一个 MMKV 实例里写 `kv_settings_<key>`
（本地覆盖层，优先级最高），等于人工拨动服务端灰度开关；
模块自带 UI 从「设置页 › 检查更新」条目偷换进入。

| 项 | 值 |
|---|---|
| 目标宿主 | 某 AI 聊天 App · **2.5.1**（versionCode 271） |
| 模块包名 | `com.little_femaleboy.cannot_show.the_big_won_whale` |
| 入口类 | `...the_big_won_whale.DisableFlagSecure`（内部 `gm/` = 灰度管理器全家桶） |
| 代码形态 | **纯手写 Smali**（无 java / python 工具链） |
| 构建方式 | MT 管理器 MCP（`mt_apk_open → edit_open → edit_* → check → build`） |
| 模板来源 | `Disable-FLAG_SECURE_2.0.0.apk`（标准 Xposed 模板） |

**当前状态**：最新版本 **2.9.7 / versionCode 94**，68 个类，V1+V2+V3 签名。
真机验收通过：模块正常注入 · 环境检测绕过（登录通过）· 灰度改动重启生效。

## 关键结论 / 铁律

1. **MMKV 优先级**：`kv_settings_<k>`（本地）> 内存缓存 > `kv_remote_settings_<k>`（下发）。
   有 `kv_settings_*` 的键 ⇒ 写**裸键**即可，零 hook；没有 ⇒ 写 remote 键 + 必须加 `GmMmkvHook`。
2. **类型必须与宿主读法一致**：MMKV 类型不符会**静默读回默认值**（有 toast、UI 也显示已保存，就是宿主不认）。
   ⇒ 升级宿主后「键名对得上」≠「能生效」，必须逐键核类型。
3. **拦截下发要用影子键**：`fuckds_pin_<key>`（`GmStore.write/remove` 自动镜像），空 = 不干预；
   **绝不能用同键旧值当覆盖值**（会退化成「用户没设过的键被永久冻结」）。
4. **手写 smali 寄存器铁律**：`.registers = 局部个数 + 参数个数`，
   自检「最高 vN < `.registers` − 参数个数」；小 `.registers` 方法最危险（2.4.4 / 2.9.2 / 2.9.6 三次都是它）。
5. **`if-*z` 六兄弟必须逐字念**：`eqz`=「==0 跳」`nez`=「!=0 跳」`ltz`=「<0 跳」`gez`=「>=0 跳」。
   本项目**累计 20+ 次反向判断 bug**，是头号 bug 家族。
6. **`mt_apk_edit_check(runBuildChecks=true)` 不做字节码校验** —— VerifyError 会一路过到真机；
   插完 smali **必须回读人工复核**。
7. **模块自保**：`handleLoadPackage` 里任何一处抛异常都会让**后面的 hook 全不注册**
   ⇒ 危险调用一律用 `GmUtil.envSafe`（内部 try/catch）包住。
8. **DIAG 一行 = 一次定位**：拿不准就先打中间量。
9. **不碰 Compose**：设置页 UI 全是 R8 混淆后的 Composable，改一行动辄重排寄存器；
   改为「主 Activity 连点手势 → 纯 View 子 Activity」。
10. **`View.setBlendMode` 对 `TextureView` 不可用**（摄像头模式下「混合」退化为半透明叠加）。
