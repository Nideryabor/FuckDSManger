## 一句话原理

**不碰 Compose、不改业务逻辑**，直接往宿主同一个 MMKV 实例里写 `kv_settings_<key>`
（本地覆盖层，优先级最高），等于人工拨动服务端灰度开关；
模块自带 UI 从「设置页 › 检查更新」条目偷换进入。

更高阶的两条线（3.4x 起）：
- **系统提示词注入** —— 明文承载 `⟦FDM⟧…⟦/FDM⟧` 拼进 `prompt`，再 hook 渲染层把标记抹掉 ⇒ 界面看不见、服务器收得到
- **AI 气泡富文本 / 任意 HTML** —— 把 AI 回复里的自定义标记**渲染成真样式**（`AnnotatedString` 重建 / WebView 截图）

| 项 | 值 |
|---|---|
| 适配宿主 | **2.5.2（vc273）· 2.6.1** |
| 模块包名 | `com.little_femaleboy.cannot_show.the_big_won_whale` |
| 入口类 | `com.nidyaber.fuckdsmanger.bridge.FdmEntry`（内部 `gm/` = 灰度管理器全家桶） |
| 代码形态 | **Java / Kotlin 真编译**（`mod-src/` + `fdm-app/`）＋ 自造 APK 打包器 |
| 构建方式 | `mod-src/build.sh` → `pipeline/build_ui.py` → `pipeline/build_single.py`（三条脚本一条龙） |
| 模板来源 | `Disable-FLAG_SECURE_2.0.0.apk`（标准 Xposed 模板，早期） |
| 签名 | 自备私钥（jks/pk8/pem）。**私钥不入库** |

**当前状态**：最新 **3.50.4 / vc652**，V1+V2+V3 签名，已装机。
近期主线：**建议按钮全链路闭环**（点一下 ⇒ 自动回话）· **AI 气泡富文本 + 任意 HTML**（含 `<Suggestion>` 可点击）· **系统提示词不留痕投递**。

## 关键结论 / 铁律

1. **MMKV 优先级**：`kv_settings_<k>`（本地）> 内存缓存 > `kv_remote_settings_<k>`（下发）。
   有 `kv_settings_*` 的键 ⇒ 写**裸键**即可，零 hook；没有 ⇒ 写 remote 键 + 必须加 `GmMmkvHook`。
2. **类型必须与宿主读法一致**：MMKV 类型不符会**静默读回默认值**（有 toast、UI 也显示已保存，就是宿主不认）。
   ⇒ 升级宿主后「键名对得上」≠「能生效」，必须逐键核类型。
   ⚠️ 连**读**也有坑：`read2(ctx,key,X)` 的第三参是**类型**不是默认值（3.45.0 的真凶）。
3. **拦截下发要用影子键**：`fuckds_pin_<key>`（`GmStore.write/remove` 自动镜像），空 = 不干预；
   **绝不能用同键旧值当覆盖值**（会退化成「用户没设过的键被永久冻结」）。
4. **手写 smali 寄存器铁律**（历史）：`.registers = 局部个数 + 参数个数`，
   自检「最高 vN < `.registers` − 参数个数」；小 `.registers` 方法最危险（2.4.4 / 2.9.2 / 2.9.6 三次都是它）。
5. **`if-*z` 六兄弟必须逐字念**：`eqz`=「==0 跳」`nez`=「!=0 跳」`ltz`=「<0 跳」`gez`=「>=0 跳」。
   本项目**累计 20+ 次反向判断 bug**，是头号 bug 家族。
6. **改完必须核对产物时间戳** —— 编译失败时打包脚本可能照样出包（用的是**旧 dex**）。
7. **模块自保**：`handleLoadPackage` 里任何一处抛异常都会让**后面的 hook 全不注册**
   ⇒ 危险调用一律用 `GmUtil.envSafe`（内部 try/catch）包住。
8. **DIAG 一行 = 一次定位**：拿不准就先打中间量。但 logcat/DIAG 都是 **256 KiB 环形** ⇒ 抓不住就换通道（frida）。
9. **不碰 Compose**：设置页 UI 全是 R8 混淆后的 Composable，改一行动辄重排寄存器；
   改为「主 Activity 连点手势 → 纯 View 子 Activity」。
10. **`View.setBlendMode` 对 `TextureView` 不可用**（摄像头模式下「混合」退化为半透明叠加）。
11. **模块身份 = 包名 + 签名**（LSPosed 视角）⇒ 换签名后**必须卸载重装**，`install -r` 不认；
    且重装后 LSPosed 会**缓存旧 APK 路径**，要在管理器里**关开模块一次**刷新。
12. **入口看模块类型**：libxposed **新 API** 模块走 `META-INF/xposed/java_init.list`（如 `ModernHook`）；
    `assets/xposed_init` 是老 Xposed 的路子。**写错入口 = 代码一次都不会被调**。
13. **「能调通」≠「是对的」**：`gh2.S` / `x42.s` 都能调、都不崩，但一个会开新会话、一个根本不发。

## 🚀 安装与使用

1. **前置**：手机已 root，并装好 **LSPosed** 框架
2. 到 [Releases](../../releases) 下载 APK 安装（换签名版要**先卸载**旧版）
3. 在 **LSPosed 管理器**里启用「FuckDSManger」，**作用域勾选宿主 App**
4. 强行停止宿主 App，再重新打开（⚠️ `am force-stop` 不一定是真停，**要看进程号变了没**）
5. 进入宿主 **设置页 →「检查更新」**（该条目被替换成模块入口，右侧仍显示版本号）
6. 在弹出菜单里挑需要的能力；**灰度类改动需重启宿主生效**（启动时注册钩子的开关尤其如此）

> ⚠️ **适配版本：某个 APP 的 2.5.2 / 2.6.1**。APP 升级到新版本后需要重新适配，其他版本不保证可用。
