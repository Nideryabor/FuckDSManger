# 宿主 2.8.0 · 数美 so 解剖报告

> 2026-11-13 · 尼得亚伯 🐲 · 2.7.5（vc295）→ 2.8.0（vc297）
> 结论先说：**16 个 .so 字节级完全相同，native 层一句 frida 检测都没有。**

---

## 〇、结论三行

1. **16 个 `.so` md5 全等** —— 2.7.5 和 2.8.0 一个字节都没差（含 `libsmsdk.so`）
2. **`libsmsdk.so` 没有 frida 检测** —— 解码 95.2% 的加密串后，`frida` / `gum-js-loop` / `gmain` / `pool-spawner` / `linjector` / `TracerPid` / `ptrace` 字样**全部为 0**
3. **但它确实有一堆脏活** —— 22 个数据解密器、XOR 加密串、`popen` + `syscall` 直接调系统调用、读宿主 APK 路径

⇒ **native 侧风险与 2.7.5 完全一致**，你现在的环境能跑，2.8.0 照样能跑。

## 一、`libsmsdk.so` 解剖

| 项 | 值 |
|---|---|
| 大小 | 842,488 B（823 KB） |
| 整体熵 | **6.77** ⇒ **没加壳**（UPX/加密壳会 >7.5） |
| `.text` | 723 KB |
| `.rodata` | **仅 2,296 B**（正常库应有几十 KB ⇒ 字符串被搬走/加密了）|
| 导入符号 | 83 个 |
| 导出符号 | 561 个，其中 **只有 `JNI_OnLoad`**（JNI 方法全靠 RegisterNatives 动态注册）|
| `.init_array` | **22 项** |

### 1.1 ★ 幺蛾子一：22 个 `.datadiv_decode` 数据解密器

```
.datadiv_decode8925955236993233930
.datadiv_decode17623125139089623257
.datadiv_decode7094430643223537891
… 共 22 个
```

**22 个 `.init_array` 条目 = 22 个 `.datadiv_decode` 函数**，加载时全部跑一遍，把数据段解开。
⇒ 这是**静态分析的第一道墙**：不跑起来，`.data` 里看到的是密文。

### 1.2 ★ 幺蛾子二：字符串单字节 XOR 加密（每串不同 key）

`.rodata` 里能看到 AES S-box + `0102030405060708` / `0123456789abcdef`（密钥/IV 素材）。

字符串是 XOR 加密，**每个串用不同 key**：

| 密文 | key | 明文 |
|---|---|---|
| `/Kmfqf(kfi\`(Tsuni\`<…` | 0x07 | `(Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;` |
| `X~ubu;xuzs;G\`f}zs/…` | 0x14 | `Ljava/lang/String;)Ljava/lang/String;` |
| `isk/.core/bin/su` | 0x18 | **`magisk/.core/bin/su`** |
| `me/weishu/exposed/Exposed` | 0x4c | 同（太极/Exposed）|

**我把全部 1,386 条串都爆了一遍：95.2%（1,320 条）解出明文**，残留 66 条是半截串。
⇒ 只有**一层**单字节 XOR，没有第二层。

### 1.3 危险导入

| 导入 | 用途 | 危害 |
|---|---|---|
| **`popen` / `pclose`** | 执行 shell | ★ 有 `cat /proc/sys/…` 这样的命令串 |
| **`syscall`** | 直接系统调用 | ★★ **没导入 `ptrace` 符号，但能用 `syscall(117)` 调 ptrace** —— 绕开 libc hook |
| `mprotect` / `mmap` | 改内存权限 | 自解密 / 反 dump 能力 |
| `opendir`/`readdir`/`closedir` | 遍历目录 | 扫 root 文件 |
| `stat`/`lstat`/`access` | 文件存在性 | 查 `/system/app/` 等 |
| `__system_property_get` / `__system_property_read` | 读系统属性 | 查 `ro.secure` / `ro.debuggable` |
| `ioctl` / `nanosleep` / `clock_gettime` | —— | 时序检测素材 |

### 2.1 SMSDK 的 Java↔native 接口（16 个方法）

```
d()                        native
ma()Z                      native  ★ 布尔检测
ma2()I                     native  ★ int 检测
u2(String)J / native_u2    native
u3(String)V                native  ★ 接收宿主 APK 目录
v1(...) / v3(...)          包装
w1(...) / w3(...)          native
x3/x4/x5/x6(String,String) 字符串加解密
```

**`ma()` 谁在用（关键）**：
```
l111l1111llIl（27 个反检测类里的"扫 /proc/self/maps"那个）
   └─ if (!hashSet.contains(x)) { if (SMSDK.ma()) { 记一条可疑 } }
```
⇒ **`ma()` 是 maps 扫描器的补充判据**，结果并进同一个"可疑列表"。

**`u3()` 干什么**：
```
ApplicationInfo.sourceDir            // /data/app/…/base.apk
  → replace("/base.apk", "")          // 去掉文件名，留目录
  → SMSDK.u3(那个目录)                 // native
```
⇒ native 拿到了**宿主 APK 所在目录**，具备完整性校验能力。
⚠️ 但我们用 **Xposed/LSPosed**，宿主 APK 本身一个字节没改 ⇒ 这条对我们无威胁。
（反过来：如果哪天改成**重打包宿主**，这条立刻会咬人。）

## 三、对 frida 验证的实操建议

### 3.1 好消息

- **native 不查 frida** ⇒ 不会因为 frida-server 在内存里就直接上报
- `.so` 与 2.7.5 **完全相同** ⇒ 你现在这套 frida 玩法在 2.8.0 上表现一致

### 3.2 但仍要小心 Java 层

| 风险点 | 说明 | 对策 |
|---|---|---|
| `l111l1111llIl` 扫 `/proc/self/maps` | 找 `/data/app/` + `xposedmodule` 字样 | frida-server **改名**、别放在 `/data/app/` 下；用 `/data/local/tmp/` 且文件名不含敏感词 |
| `SMSDK.ma()` native 布尔 | 未知判据（可能查 maps/线程名） | 若被标红，先 `hook ma()` 返回 `false` 试 |
| `popen("cat /proc/sys/…")` | shell 层面 | 一般无碍 |
| `ro.secure` / `ro.debuggable` | root 检测 | 你这台是 root 环境 ⇒ **本来就会被记**，与 frida 无关 |

### 3.3 ⚠️ 一个容易忽略的冲突：xCrash + ptrace

`libapminsightb.so`（xCrash）在**崩溃时**会 fork dumper 进程并 `ptrace` 主进程抓 tombstone。

- **稳态不冲突**（frida attach 完就 detach 了）
- **但崩溃瞬间会打架**：frida 还在时崩，tombstone 可能生成失败
- ⇒ 你要抓崩溃栈的话，**先摘 frida 再复现**

### 3.4 建议的验证顺序

```sh
# 1. .so 不用动，先确认模块能起
devlog  → 抓 hookM ... count=N

# 2. 优先验这 5 条（上轮清单第 4 节）
yg7.y           点「检查更新」时 this.e 是 22 还是 23
dc8.r / dc8.s   是不是 Modifier.background(Brush) / background(color)
zw7.S           Modifier.paint 挂上后 count>0
hfc.g           气泡单元八参逐位，count>0
a6.v / c6.v     头像/昵称真机生效

# 3. 如果数美报红（登录/风控异常），按这个顺序试
① hook SMSDK.ma() → 返回 false
② hook l111l1111llIl 整个方法 → 返回空 List
③ 检查 frida-server 文件名/端口
```
