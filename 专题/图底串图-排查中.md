## 三、我上一版埋的坑（3.42.32）

为了让「限制放大」重新生效，我把 `GmBubbleFitHook` 的位图来源从**实例自带**改成**全局 `GmBubble.sBmp`**：

```smali
-  iget-object v1, v0, GmBmpShader;->bmp      ← 实例自带（对的）
+  sget-object v1, GmBubble;->sBmp             ← 全局（每次 imgBrush 都被覆盖）
```

⇒ **两个气泡交替渲染时，裁剪用的是"另一张图"的宽高** ⇒ 截断 / 错位 / 跑到别人底下 —— **三种现象全对得上**。

### 3.42.34 的修法（已进包，但主人说"没区别"）

给每个 `jq0` 实例配一张「实例 → 位图」的 `IdentityHashMap`：

```
imgBrush()  造出 jq0 后 →  sBmpMap.put(jq0, sBmp)
FitHook     触发时      →  sBmpMap.get(thisObject)
```

**已静态验证**：反编译 `FDM-3.42.34-single-signed.apk` 的 `classes.dex`
⇒ `GmBubbleFitHook` 里 **确实有** `sBmpMap` / `IdentityHashMap.get`（代码进包了 ✅）

⇒ 所以"没区别"是**运行时**的事，不是没打进去。
