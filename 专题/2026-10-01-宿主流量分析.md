## 二、⭐ 最有价值的四条

### 1. `/api/v0/client/settings` = **宿主权威设置表的源头**

一次下发 **55 个键**，形如：

```json
{ "version": 88,
  "settings": { "enable_wechat_upload": {"id": 1345736671, "value": true}, … } }
```

- **按 `scope` 分片**下发（`main` 给 55 个，别的 scope 只给 1~4 个）
- 里面能看到我们之前"从字节码抄出来"的那些键：`enable_wechat_upload` / `support_chat_file_exts` /
  `max_upload_file_size` / `pow_header_paths` / `hcaptcha_enabled` / `model_configs_v1` / `providers_v1` …
- ⇒ 对应 `专题/C0-宿主权威设置表.md`：**以前是抄字节码，现在能直接看服务端下发表**（真名 + id + 值 + 类型）

### 2. 消息体系的**字段真名**（`/api/v0/chat/history_messages`）

```
chat_messages[]: message_id / parent_id / model / role("USER") / thinking_enabled /
                 ban_edit / ban_regenerate / status / incomplete_message /
                 accumulated_token_usage / feedback / inserted_at / search_enabled /
                 fragments / has_pending_fragment / auto_continue /
                 search_triggered / extra_search_providers
```

- **`role` 就是用户气泡线纠结很久的那个值** ✅（与真机日志 `[ROLE] fy role=USER` 对得上）
- **`fragments`** 正对 `专题/宿主-消息分片(fragments)体系-2.5.2.md`
- ⇒ **用途**：服务端 JSON key 是**不会被 R8 改名**的（要用于反序列化）⇒
  **可以拿它反向锁定宿主字段**（`mr.C()` 返回角色、`mr.j` 是正文……）

### 3. `zztfly.com` = 一整套**第三方风控 SDK**

```
api-auth.zztfly.com/api/initSec          ← 初始化安全
cfgc.zztfly.com/gp/gcf  ?duid=&psid=&ags=&ait=&appkey=&nbs=&ts=
upc.zztfly.com/v6/gcl
log-auth.zztfly.com/api/log
```

- 字段 `duid` / `psid` / `nbs` / `ags` / `ait` —— **我们之前在别处没见过**
- ⇒ 直接命中 `专题/环境伪装与反检测.md`（宿主有独立的风控上报通道）

### 4. PoW 反脚本机制

```
POST /api/v0/chat/create_pow_challenge   → 拿挑战
后续请求头带 x-ds-pow-response           → 交答案
settings 里还有 pow_header_paths / authed_pow_functions 说明哪些接口要 PoW
```
