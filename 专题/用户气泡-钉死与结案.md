## 一、四个问题（真机逐层剥出来的）

| # | 位置 | 代码现状 | 后果 | 修法 |
|---|---|---|---|---|
| **1** | `GmBubble.hostShape()` | `if-eqz v0, :cond_19` | 缓存为空时**反而跳过读取** ⇒ **恒返回 null**，且因没进 try 所以**连 logFail 都没有**（静默） | → `if-nez` |
| **2** | `GmBubble.ubMod()` | `if-nez v0, :cond_65` | shape **非 null 时反而直接 return null** ⇒ 永远不重写 | → `if-eqz` |
| **3** | `GmBubblePaintHook.ub()` | `if-eq v2, v3, :cond_a3` | `args[2] == hostShape`（**正是用户气泡的情形**）反而被跳过 | → `if-ne` |
| **4** | 同上（门太宽） | 门只判「形状相等」 | 修好 1~3 后，`zc.s:1417` / `ob2.b:168` / `xd5.c:184` / `vz8.c:58` … **全被当成用户气泡重写**（现象：**一堆按钮变成图片底**） | 门加硬条件：**`caller` 必须以 `ls9.f` 开头**（原逻辑只在 `sUDepth>0` 时查 caller；而用户气泡底在**绘制阶段**，`ud=0` ⇒ 正好漏掉） |

> #4 不是"反向"，是**设计缺陷**：宿主里**大量元素共用同一个形状对象 `zc.o`** ⇒ 形状不能当身份。

## 四、教训（值得进铁律的）

1. ⭐⭐⭐ **"不报错的 null"最危险**：`hostShape()` 恒返回 null 却**不抛异常**（`if-eqz` 让它跳过了 try）
   ⇒ 上游一句 `if (x == null) return;` 就**静默全灭**，而且**日志里什么都没有**。
   ⇒ **推论：任何"取值可能为 null"的辅助函数，第一次调用后就应该自证"我到底返回了什么"。**
2. ⭐⭐⭐ **公共对象（形状/颜色）不能当身份**（本项目 108 号结论的再次印证）：
   宿主里一个 `zc.o` 被几十处共用 ⇒ 判据必须是 **caller（调用点）**。
3. ⭐⭐ **"门"要窄、"探针"要宽**（教训 292）：这次"门太宽"的副作用（整屏元素被重写）
   比原 bug 更显眼 —— **修 A 却引入 B 的典型**。
4. ⭐⭐ **"生效了但被别处盖住/放大"要分开看**：`ubMod` 的 `logOnce` 让"重写成功"这条日志
   在 `dsm.log` 里看不到（被去重 + 轮转）⇒ 差点又白判一轮。**查日志要连轮转文件一起查。**
5. ⭐⭐⭐ **装机必须 `--user 0`**：今天是真踩了（装进**系统分身**）⇒ 主空间 LSPosed 看不到模块、
   宿主没注入 ⇒ 一度以为"模块坏了"。**工具里已写死：`tmp/dev.sh --install` 自带 `--user 0`。**
