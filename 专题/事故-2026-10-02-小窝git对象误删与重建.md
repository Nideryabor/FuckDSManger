## 〇、一句话

我把沙箱存储层 **`.l2s.*` 数据文件**误当成 git 垃圾清掉了 ——
它们是 **git 对象的真身**（通过软链以正常对象名暴露），而 `git fsck` / `count-objects`
会把这些真身**误报为 "garbage"**。一次 `find … -delete` 删掉 19496 个文件 = 9748 个对象全没。

## 一、事故链（什么时间发生了什么）

| 时间 | 动作 | 结果 |
|---|---|---|
| 10:37 | 提交完 3.42.50 的 4 笔 git 提交后，跑 `git count-objects -vH` | 输出里出现大量 `warning: garbage found: .git/objects/XX/.l2s.tmp_obj_*` |
| 10:38 | **判断错误**：我把它当"垃圾临时文件" | `find .git -name ".l2s.tmp_obj*" \| wc -l` = **19496** |
| 10:39 | **错误执行**：`find .git -name ".l2s.tmp_obj*" -delete` | 9748 个对象（= 9748 × 2 个文件）全删 |
| 10:39+ | 验证 | `git log` → `fatal: bad object HEAD`；`git fsck` → `missing blob …`（对象真身没了，符号链接全部悬空） |

**为什么那么像垃圾**：对象在磁盘上是 `objects/XX/<sha> -> .l2s.tmp_obj_XXXXXX0001`（符号链接）
+ `.l2s.tmp_obj_XXXXXX0001.0001`（真身）。git 只认识 `<sha>` 这个名字，把 `.l2s.*` 那层叫成 "garbage"。
**它一边报 garbage，一边要靠这些 garbage 才能读对象。**

## 二、机制详解（沙箱存储层 = RikkaHub 工作区文件系统）

对这个工作区（挂在 `/data/data/me.rerere.rikkahub/files/workspaces/<uuid>/files`）：

1. **经 `rename()` 落地的文件**（git 写对象/pack/ref 全是 tmp→rename 模式）会被存储层接管：
   ```
   可见名  →  .l2s.<原名>NNNN          （符号链接）
                 .l2s.<原名>NNNN  →  .l2s.<原名>NNNN.0001   （真身/分片）
   ```
   链接里的路径是**绝对路径**（写它时的完整路径）。
2. **不移动就没事**：链接按绝对路径解析；`lstat` 语义、读取全部正常（对照实验：原地新克隆 / 原地新提交全部工作正常）。
3. **一旦整树被移动**（本次：`tmp/restore-clone/.git` → `/workspace/.git`）：
   链接全部指向旧路径 ⇒ 悬空。
4. **手工改写链接前缀救不回来全部**：改完后 `cat/read` 能过（git 大部分命令正常），
   但**新链接的 `lstat` 语义是坏的**（`lexists=False`，`stat` 却能过）——
   git 的"快速有效性检查"（`show-ref` 校验 ref 指向、`has_object_file` 快速路径）**恰好走 lstat**
   ⇒ 表现为 `bad ref …` / `does not point to a valid object!`（而对象明明可读）。
5. **根治**：把"可见名"**平铺成普通文件**（读→删→原地写回，内容不变）⇒ `lstat` 恢复正常
   ⇒ 全绿。工具：**`tools/flatten_l2s.py`**（本次新增，搬过目录就重跑一遍）。
6. ⚠️ **`.l2s.*` 原件永远不要删**（平铺后它们只是"不再被引用的数据副本"，留着占点空间，保命）。

## 六、教训（856 ~ 860）

| # | 教训 |
|---|---|
| **856** | ⭐⭐⭐ **`fsck`/`count-objects` 嘴里的 "garbage"，可能是命根子。** 沙箱存储层把对象真身存成 `.l2s.*`、用软链以正常名暴露；git"不认识这个命名"就喊 garbage。⇒ **在陌生存储系统上，任何"垃圾/无用"判定都要先做归因实验（先复制一份再删一份看反应），不许直接批量删。** 我一次 `-delete` 删了 19496 个文件、一个副本都没留。 |
| **857** | ⭐⭐⭐ **备份的价值 = 它在你毁掉主数据的前一天存在。** 9/27 的逃生包（`小窝全历史.bundle`，239 提交）救了整仓；没有它，历史归零。⇒ 关键仓库**必须有独立副本且定期刷新**；本次后已生成新逃生包（见交接文档）。 |
| **858** | ⭐⭐ **"被移动过的"链式存储 = 隐形雷。** l2s 链是绝对路径；移动目录后即使改写链接前缀，"读写"能过但 **`lstat` 语义坏了**（git 快速校验路径中招 ⇒ `bad ref` / `not a valid object`）。⇒ **搬过 `.git` 后必须跑 `tools/flatten_l2s.py` 平铺 + `git fsck`/`show-ref` 全量体检。** |
| **859** | ⭐⭐ **批量删除前先问三件事**：① 这东西是什么（做过归因实验吗）② 删错了能不能恢复（有副本吗）③ 范围对吗（一个文件 / 一类 / 一目录——教训 806 同族）。三问有一个答不上来，就不许删。 |
