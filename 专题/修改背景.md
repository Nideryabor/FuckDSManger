### 2.5 关键技术点

- **渐变动画**：不用 `ValueAnimator`。`onDraw` 里 `phase = (uptimeMillis % 9000)/10000f`，
  `matrix.setTranslate(-phase*width, 0)` + `gradient.setLocalMatrix()` + `postInvalidateOnAnimation()` 自驱动。
  色组做成 `[c0,c1,c2,c3,c0]`、跨度 `2×width` ⇒ 平移一个 width **无缝循环**。
- **挂载**：`DecorView`（FrameLayout）。`pos=0` → `addView(v, params)`（最上层）；
  `pos=1` → `addView(v, 0, params)`（最底层）。
- **签名去重**：`pos*10000000 + mode*1000000 + grad*10000 + alpha*10 + hasImage`，未变则不重建。
- **触摸穿透**：`GmBgView` 不设 clickable ⇒ `onTouchEvent` 返回 false ⇒ 事件下传 ✓
- **选图**：复用 `GmPickHook`（挂在 `Activity.onActivityResult`），**先问 `GmBg.takePicking()`，再问 `GmAvatar.takePicking()`**
- **混合模式**：
  - （2.5.5，路线①）`GmBg.setBlend(ctx, act)` 把 **App 的** `android.R.id.content` 设成
    `MULTIPLY`（浅色）/ `SCREEN`（深色）/ `null`（关闭）。`View.setBlendMode` 需 **API 29+**。
  - （**2.6.0，路线②**）`GmBgView.h` 字段 + `onDraw` 里 `Paint.setXfermode(new PorterDuffXfermode(MULTIPLY/SCREEN))`，
    背景层放**最上层**，直接与下方已绘制内容混合。**不依赖 App，也不需要 API 29+**。
    ⚠️ 前提：该 View 不能被分层（view 级 alpha / `setLayerType` / `setBlendMode` 三者都不能碰）。

## 七、本轮踩的坑（都是「反向判断」家族）

| 版本 | 位置 | 错误 | 后果 |
|---|---|---|---|
| 2.5.1 | `GmBg.ensure` 开头 | `if-nez sAct, :ret`（应为 `if-eqz`） | **整个挂载逻辑从不执行** |
| 2.5.2 | `GmBg.ensure` 重建判定 | `if-nez v2, :mk` / `if-nez v4, :mk`（应为 `if-eqz`） | 点「底图」**NPE 崩溃** |
| 2.5.4 | `GmPickHook` 选图分流 | `if-eqz v0, :bg`（应为 `if-nez`） | **选背景图走了头像分支 ⇒ 图片模式永远失败** |
| **2.6.1** | **`GmBgView.onDraw` 渲染分支** | **`if-eqz v3, :cond_55`（应为 `if-nez`）** | **`mode==0`（图片）永远渲染成渐变（反向判断第 13 次）** |

> 累计反向判断已 **13 次**。**对策**：写完每个 `if-*z` 分支，立刻在旁边用中文写出
> 「走这条路的条件」；守卫语句（`if (x == null) return`）单独复核；
> **枚举值分支（mode/pos）先列取值表再核对**。

### 10.1 为什么这次更可能成功

1. **不碰 App** —— 只改自己 `onDraw` 的 `Paint`。
2. **不用 API 29 的 `View.setBlendMode`** —— `PorterDuffXfermode` 从 API 1 就有，minSdk 26 直接可用，无需 SDK 守卫。
3. **自绘视图没有被分层** ⇒ `onDraw` 在**同一个窗口画布**上、**在内容之后**执行，
   `MULTIPLY` 的 dst 就是刚画好的内容，混合天然成立。

### 10.2 ⚠️ 唯一的大坑

**只要给 `GmBgView` 设了 view 级 `alpha` / `setLayerType` / `setBlendMode` 中任意一个**，
它就会被 hwui 隔离成独立图层，`onDraw` 里的混合变成对着透明底做 ⇒ **功能直接失效且无任何报错**。
（当前代码满足这三条都不碰；`alpha` 是设在 `Paint` 上的，不是 View 上，✅）

### 10.3 smali 关键片段

```smali

    if-eqz v3, :cond_ble          # 走这条路 = h==0，跳过混合
```

## 11.11 2.7.7 修复（2026-09-12）—— 旋转的真凶：`GmCam.rot()` 映射错位

> 详见 `FuckDSManger-项目总结.md` **第四十一节**。

用户实测 2.7.6 后反馈「**拉伸修好了，但旋转还是没修好**」，DIAG：

```

```

竖屏后置 `sDeg` 应为 90 却是 **0** ⇒ 画面永不旋转。

| # | Bug | 根因 | 修法 |
|---|---|---|---|
| 3 | **`GmCam.rot()` 屏幕旋转→角度 映射整体偏移一格** | 三条 `if-ne` 串联（「不等就跳」被当成「相等才走」）⇒ `0→90 / 1→180 / 2→270 / 3→0`，**四个值全错** | 三条 `if-ne` → **`if-eq`** |

## 三十二、关于「把渐变背景色砍了」的结论（2026-09-12）

**用户决定：只保证默认是「图片」，渐变保留可选，不改代码。**

### 32.1 核查结论（改代码前先验证默认值）

| 项 | 结论 |
|---|---|
| `mode` 默认值 | **0 = 图片** ✅（`GmPrompt.toInt()` 对空/null 返回 0；`mode()` 不做 `ok()` 判空，直接 `toInt`） |
| 有无地方把 mode 设成 1 | **无**。`GmBgSwitch` 只 toast；`GmPickHook` 存图后反而强制 `setMode(0)` |
| 因此 | **无需改代码**，全新用户/未写过键的用户拿到的就是图片 |

### 32.2 之前"总看到渐变"的两个叠加原因（均已定性）

| # | 原因 | 状态 |
|---|---|---|
| 1 | `GmBgView.onDraw` 的 `mode` 分支写反（`if-eqz` / `if-nez`）⇒ `mode==0`（图片）被送进渐变分支 | ✅ 2.6.1 已修 |
| 2 | **没选图时 `bitmap == null` → 退回渐变分支**（占位，避免空白） | ✅ 有意设计，保留 |

### 32.3 ⚠️ 残留与操作提示

- **「默认值」只对从没写过 `fuckds_bg_mode` 的人生效**。若此前点过「渐变」，`fuckds_bg_mode=1` 已落盘，
