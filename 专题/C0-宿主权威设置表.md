# C0 · 宿主权威设置表（DeepSeek 2.5.2）

> 2026-09-26 · 尼得亚伯 🐲
> 产出：`参考/数据/host-2.5.2-设置表.tsv`（83 行）
> 工具：`tools/host_settings_table.py`（可复现）
> 输入：`参考/数据/module-83-keys.txt`（模块自己的键表）

---

## 一、为什么要做

「灰度值改了 → UI 显示改了 → **宿主没变**」这条路上，我们一直在**猜**三件事：

1. 宿主到底读哪个键？（`kv_settings_x` 还是 `kv_remote_settings_x`？）
2. 这个键是什么类型？（写错类型 = 值不被采纳，甚至把原值顶掉）
3. 宿主怎么读的？（有没有内存缓存？）

⇒ **猜错一次就是一个版本。** C0 把"猜"换成"抄"。

---

## 二、表从哪来（字节码里的铁证）

宿主有个 Kotlin data class `n02`（`toString()` 把字段名编成了字符串常量 —— 本项目的老技巧）：

```
SettingModel(key=…, comment=…, type=…, defaultValue=…)
```

而 `Lo02.<init>()`（1738 条指令 / 167 个字符串 / 493 次 invoke）**把每一项设置都 new 一遍**，
每一项紧跟着还会 `MMKV.contains("…")` 探一下键：

```smali
new-instance v3, Ln02;
const-string v6, "normal_history_and_file_token_limit"    ← 纯名
const-string v7, ""                                      ← 注释
const-string v8, "Int"                                   ← 类型 ★
const v4, 0xf000  →  String.valueOf → "61440"             ← 默认值 ★
invoke-direct {v3, v6, v7, v8, v5}, Ln02;-><init>(4×String)V
const-string v5, "kv_settings_normal_history_and_file_token_limit"
invoke-virtual {v2, v5}, Lcom/tencent/mmkv/MMKV;->contains(String)Z   ← 「宿主实际探测的键形」★★
```

⇒ **纯名 / 类型 / 默认值 / 宿主真正读的键形，全在字节码里写着。**

## 三、🔴 三个结论

### ① 宿主的键形是**三选一**，不是一种

| 走哪条 | 判据 | 2.5.2 实测 |
|---|---|---|
| **`kv_settings_<纯名>`** | 在 `Lo02` 的 SettingModel 表里 | **63 项** |
| **`kv_remote_settings_<纯名>`** | 不在表里，但宿主 dex 里有这个字面量 | **18 项** |
| **`<纯名>`（裸名）** | 上面两个都没有，只有裸字面量 | **2 项**（`key_auto_tts_enabled` / `key_tts_voice_id`） |
| 宿主里查不到 | — | **0 项** ✅ |

### ② ⚠️ 我们现在的写法**只对 0 项是对的**

`FdmBridge.grayWrite()` 一律写 `fuckds_pin_` + **`kv_remote_settings_`** + 纯名。
- 对 **63 项**（走 `kv_settings_`）⇒ **键形错位，连覆盖对象都找错**
- 对 **18 项** ⇒ 键形对了，但**读侧替换从来没实现**（见 `专题/铁律…` 之外的另一条：全底座里 `fuckds_pin_` 只在 `GmStore` 的 write/remove 两处，没有任何读）
- 对 **2 项** ⇒ 同样错位

⇒ **这解释了为什么"UI 改了宿主没变"，而且是一条都不用改就必然失败的写法。**

### ③ ✅ 模块的纳管**没有遗漏**

宿主 SettingModel 表 63 项 **⊂** 模块表 83 项 ⇒
「宿主有、模块没纳管」= **0 项**。
（老待办「灰度少了的东西」到此可以结案：**没少，只是键形/读侧没接对**。）

## 四、对 A / B / C 三个方案的影响

| 方案 | C0 给了它什么 |
|---|---|
| **A 写真实键** | ✅ **键形不用猜了**（表里写着 63/18/2）· ✅ **类型不用猜了**（Int 28 / String 12 / Boolean 23）⇒ A 从"要鉴型 + 要判键形"降到"照表写" |
| **B 读侧替换** | ✅ **知道该铺哪几个 getter**（`g`=getInt / `r/d`=getBoolean / `k`=getString）· ✅ **pin 挂哪个键名也知道了** |
| **C 宿主设置层** | ✅ 就是它的核心素材（SettingModel 的 key/type/default 全在） |
| **共同** | 「宿主何时重读」那个老遗留，现在能**按项**判断（走 SettingModel 的项都可能被缓存；走远程的项另说） |

## 五、怎么复现

```bash
# 1) 把宿主的 classes.dex 拿出来
unzip -p DeepSeek2_2.5.2.apk classes.dex > /tmp/classes.dex

# 2) 抽表（63 项 SettingModel + 与模块 83 项对齐的分派）
python3 tools/host_settings_table.py \
    --dex /tmp/classes.dex \
    --keys 参考/数据/module-83-keys.txt \
    --out  参考/数据/host-2.5.2-设置表.tsv

# 输出：
#   宿主 SettingModel 表 : 63 项
#   类型分布            : {'Int': 28, 'String': 12, 'Boolean': 23}
#   未解析字段          : 0
#   模块 83 项的分派     : {'SettingModel': 63, '远程设置字面量': 18, '裸名字面量': 2}
#   ⚠️ 宿主里查不到的    : []
```

**宿主升级后重跑一次**，就等于把「宿主升级适配」里最费劲的那一半自动化了。
