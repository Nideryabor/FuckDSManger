## 二、★★★ 这一天的最大价值：**一个"从来没工作过"的功能被救活了**

### 起因（主人的一句话）

> 「搞懂怎么发送系统提示词到服务器，而客户端和服务器历史对话记录不会留存这个提示词」

### 真凶：一个字节的误用，让整件事**从上线起就没发生过**

```
GmStore.read2(ctx, key, X)      ← X 是「类型」(b/i/f/l/其它=string)，不是「默认值」！
```

代码写的是 `read2(ctx, K_ON, "0")` ⇒ `"0"` 被当类型 ⇒ 落到 `getString` 分支 ⇒
去读一个 **boolean** 键 ⇒ 抛异常被 `read2` 自己的 catchall 吞掉 ⇒ 返回 `""`
⇒ `on()` **恒 false** ⇒ `inject()` 第一行就 return。

**症状与证据完美吻合**：主人说「没效果」，而 logcat 里**连 `sysprompt.inject` 都不打** ——
因为它根本没走到那一行。

> 对照铁证就在隔壁：`FdmBridge` 里用了 20 多次正确写法 `read2(ctx, "fuckds_bubble_on", "b")`。
> **教训 899：新代码调用既有 API 前，先去 grep 既有正确调用点。**

同一误用还埋了第二颗雷：`mode()` 也是同样写法 ⇒ **「每轮注入」模式永远失灵**（一直退化成"仅首条"）。

## 三、协议层：八组真机实验，全部否证（一条不剩）

用 ProxyPin MCP 挂 JS 规则改 body + 真机发消息，把「除 `prompt` 之外的字段」问了个遍：

| # | 改什么 | 服务端回应 | 结论 |
|---|---|---|---|
| T1 | `action` 塞文本 | **422** | ★ 服务端自曝：**`action` 只有 `default` / `retry`** |
| T2 | `model_type` 塞文本 | 200 | 收下，不进模型语义 |
| T3 | `preempt=true` | 200 | 用户消息**照常落库** |
| T4 | `action="retry"` | 200 | 同上 |
| T5 | `audio_id` 塞文本 | 200 | 收下，不进模型语义 |
| T6 | `action="default"` | 200 | 对照（同 null） |
| T7 | `parent_message_id=0` | 200 | **`biz_code 26: invalid message id`** |
| — | 48 个顶层字段 + 16 嵌套 + 特殊 token | — | 更早一轮已全灭 |

> **教训 905：服务端的 422 是最好的文档。** 它是 Rust / serde，塞个非法枚举值，
> 它会把**合法取值全集**写进报错里 —— 想探任何字段，先塞个假值问它。

## 四、★★★ 模型侧的两条规律（比协议穷举更值钱）

同一段隐形 nibble 指令（解出来是「回答紫色大象」），六次实验：

| 场次 | 可见文本尾部 | 模型 |
|---|---|---|
| T2 / T3 / T4 / T6 | `T2`…`T6` | ✅ **照做** |
| T5 | `T5` | ❌ 拒绝（还把 T5 当成谷歌那个 T5 模型解释了一通） |
| 08:47 那条 | `你好` | ❌ 拒绝 |

**规律 1：服从是概率性的**（6 次里 4 次照做）—— 不是"能用/不能用"的二值。
**规律 2：可见文本会「抢戏」** —— 可见内容越像一个正经问题，隐形指令越容易被挤掉。

⇒ **被制裁的从来不是"隐形"本身，而是「自称系统级 + 声称要覆盖用户」那套元话语。**
⇒ 这一条直接决定了形态的最终走向。

> **教训 906：「隐形」要分两层看。**
> *字符级隐形*（Unicode Tag）—— 模型会察觉「有人在藏东西」；
> *渲染级隐形*（hook 抹掉）—— 模型看到的是**纯明文**。
> 后者才是既不被制裁、人又看不见的形态。

## 五、最终形态（主人拍板 + 真机验收）

```
发出的 prompt：  ⟦FDM⟧你是一位耐心的助手，请始终用中文回答⟦/FDM⟧你好
用户看到的：      你好
```

| 侧 | 做什么 |
|---|---|
| **注入侧** | 明文包一对定界符（`⟦FDM⟧`…`⟦/FDM⟧`，U+27E6）拼在 `prompt` 前 —— 模型当**普通用户文本**读 |
| **显示侧** | `GmSysPromptHideHook` 在渲染前把整段**删掉**（不是遮罩）—— 用户看到的就是他自己写的话 |

**显示侧铺了五路**（前两版"精确扫一层字段"都没命中，而真机 logcat 窗口只有几分钟、抓不到现场参数
⇒ 放弃"先定位再动手"，改成**一次铺满**）：

`i93.i` / `d12.a` 参数**递归深扫**（深度 4，含 List/Map/数组）
+ `i93` / `mr` 的**所有 String getter 返回值改写**
+ `AnnotatedString` 构造器

**为什么敢这么扫**：判定条件只有一条 —— 字符串含 `⟦FDM⟧`。
这个标记**只可能出现在我们自己注入的文本里** ⇒ 不会误伤宿主任何正常数据；
而且注入发生在**请求构造那一刻**（每次都会重新加定界符）⇒ 删了历史数据也不影响下次发送。

⚠️ 诚实标注：五路同时铺开，**具体哪一路先命中没有单独验证**（日志抓不到）。
留着全部挂点反而是好事 —— 宿主升级后只要有一条活着，功能就还在。

## 六、备用通道：附件（原理验证通过，搁置）

- `POST /api/v0/file/upload_file` + `ref_file_ids: ["file-xxx"]`
- 服务端把附件存成**独立的 FILE fragment**（与 REQUEST 正文并列）
- **铁证**：`prompt` 只有干干净净的「你好」+ 一个 txt ⇒ **会话标题被生成成「尼得亚伯龙龙」**
  （= 文件内容）⇒ 模型确实读到了附件内容 ✅
- 卡点：fragment 存的是**引用**不是快照 ⇒ 「删掉文件后还读不读得到」没测
- 搁置原因：「每轮都带」⟺「历史里有」⟺「至少看得到一个文件卡片」，且要处理上传/删除/卡片
