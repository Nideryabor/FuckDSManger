# 专题 · 语音输入（按住说话）的两道闸

> 2026-10-02 🐲 尼得亚伯
> 起因：主人「**我在设置里开了语音转文字，宿主还是只有发消息**」
> 结论：**宿主把"能力阀"和"用户开关"拆成了两个键**，只开一个不够。

---

## 一、现象与真因

| | |
|---|---|
| **现象** | 灰度工具箱里「语音输入」开了 ⇒ 宿主输入框**还是没有麦克风**（只有发消息）|
| **真因** | 麦克风要**两个键都真**，而主人只开了其中一个；另一个（能力阀）**默认 false 且从没被设过** |

---

## 二、代码证据：`pn5.<init>`（输入模式管理器）

```smali
const/4 v2, 0x0                                      # v2 = ★false★（默认值）
const/4 v3, 0x1

const-string v1, "key_input_mode"
invoke-virtual {p1, v1}, Lcom/tencent/mmkv/MMKV;->j(Ljava/lang/String;)Ljava/lang/String;  # getString
move-result-object v1
if-eqz v1, :cond_21                                   # key_input_mode 为空 ⇒ 跳
const-string v4, "Voice"
invoke-virtual {v1, v4}, Ljava/lang/String;->equalsIgnoreCase(Ljava/lang/String;)Z
if-eqz v1, :cond_1f
const/4 v1, 0x2                                       # "Voice" ⇒ 2

:cond_1f   move v1, v3                                # 其它      ⇒ 1 (Text)

const-string v4, "key_voice_available"
invoke-virtual {p1, v4, v2}, Lcom/tencent/mmkv/MMKV;->d(Ljava/lang/String;Z)Z   # ★① 裸键，默认 false★

const-string v5, "key_preferred_asr_lang"
...
const-string v3, "kv_settings_voice_input_enabled"
invoke-virtual {p0, v3}, Lcom/tencent/mmkv/MMKV;->contains(Ljava/lang/String;)Z  # ★② 这条存在才用它★
```

## 三、⭐ 两道闸

| # | 键 | 形态 | 宿主默认 | 角色 |
|---|---|---|---|---|
| **①** | `key_voice_available` | **裸键**（不带 `kv_` 前缀）| **`false`** | **能力阀**（宿主自己按"输入模式/环境"写）|
| **②** | `kv_settings_voice_input_enabled` | `kv_settings_` 族 | — | **用户开关**（"输入框显示麦克风"）|

**两个都真 ⇒ 麦克风出现（按住说话）** ✅

---

## 四、处理（已完成）

1. **手工开①**：
   ```sh
   am broadcast -a com.little_femaleboy.fdm.CMD --es cmd gray_put \
     --es arg "key_voice_available<US>b<US>true"
   ```
   ⇒ ✅ `已写宿主覆盖层 key_voice_available = true（type=b）`
2. **重启宿主**（`pn5` 只在构造时读一次）
   ⇒ ✅ 麦克风（**按住说话**）出现
3. **做进灰度工具箱**（`3.42.42` / vc586）：
   - 灰度页**顶部新增一行**「**语音可用（总闸）**」，排在「语音输入」**上面**
   - hint 写明：「**它 + 下面那条都要开，麦克风才出来**」

---

## 五、避坑要点

| # | 要点 |
|---|---|
| **1** | ⭐⭐⭐ **"开了没反应"先怀疑"还有第二道闸"**。宿主常见设计：**能力阀（服务端/环境）** 与 **用户开关** **分开存两个键**。 |
| **2** | ⭐⭐ **能力阀常常是"裸键 + 默认 false"**：`key_voice_available` 不带 `kv_` 前缀、也不在灰度类型字典里 ⇒ **只按 `kv_remote_settings_*` 去找，永远找不到它**。 |
| **3** | ⭐⭐ 这类键**只在对象构造时读一次**（`pn5.<init>`）⇒ **改完必须重启宿主**（铁律 181 的又一次印证）。 |
| **4** | ⭐ 写"裸键"要靠 `grayWrite` 的 `bareKey` 分支（`key_` 开头不加前缀）—— 这是 `3.42.39` 刚修的，这次立刻派上用场。 |
