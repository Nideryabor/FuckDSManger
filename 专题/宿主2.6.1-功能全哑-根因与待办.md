## 四、下一步（还没做完的）

### A. 先钉死"点上传图片崩"（最高优先）

**已知**：崩栈是被**输入事件**（点击）触发的 Compose 重组：
```
ViewRootImpl.deliverInputEvent → … → Choreographer.doFrame
  → pr8.S → m33.x → yx4.o → … → l10.A
      State.getValue() → check-cast dz9   ← 崩（拿到 String）
```
**含义**：投毒发生在**更早**（启动时），点击只是**触发重组**把雷引爆。

**二分方案**（每次只需"装包→点一下"，共约 4~5 轮）：
```
第 1 轮：只留框架类钩子（Resources/Activity/MMKV），关掉所有宿主锚点钩子
        → 还崩？ ⇒ 与宿主锚点无关，往桥/UI 层查
        → 不崩？ ⇒ 进第 2 轮
第 2 轮：只开"读类"钩子（GmSuggestAi / GmRevokeHook / GmGateListHook）
第 3 轮：加"美化类"（GmPainterHook / GmAvatarHook / GmNameHook / GmUAvatarHook）
第 4 轮：加"气泡类"（GmBubbleCellHook / GmBubbleFitHook / GmBubblePaintHook / GmShadowHook / GmAlphaHook）
第 5 轮：加"下发/通话类"（GmDsHook / GmDsHook2 / GmCallHook / GmSuggestHook）
```
> 工具：`tools/install_fdm.sh` 一键装+修路径+自检；GmRemap 里把锚点映射成 `null` 即可"关掉某条 hook"。

## 五、教训（编号接上）

| # | 教训 |
|---|---|
| **326** | ⭐⭐⭐ **R8 改的不只是类名——方法和字段名都会改。** 模块里任何 `callMethod(obj,"名字")` / `getObjectField(obj,"名字")` 都是**跨版本定时炸弹**，升级时必须逐个核。 |
| **327** | ⭐⭐⭐ **"钩住方法直接改返回值"的功能最抗升级；"反射深挖宿主对象"的功能最脆。** 设计上应尽量往前一种靠。 |
| **328** | ⭐⭐⭐ **一次只动一处。** 本轮我一次性改了 7 处成员名（+ 复活 4 条钩子），崩了之后**无法判断是哪一处**，只能全部回滚重来 ⇒ 白烧两小时。 |
| **329** | ⭐⭐ **`private` 字段被别的类反射读 = 长期哑火**。而且它"哑"得安静（每次抛 IllegalAccessError 被 try 吞），**不查日志永远发现不了**。 |
| **330** | ⭐⭐ **排查要读"自己导出的真实数据"，别猜。** 这轮最有价值的一步是**把主人宿主的 MMKV 拉下来解析** —— 一句话证明"设置没问题"，直接砍掉一整条错误路线。 |
| **331** | ⭐⭐ **不擅自动主人的设备。** 为了验证我连续 force-stop / am start，打断了主人正在用的 App。**动设备前先问。** |
