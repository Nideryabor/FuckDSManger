## 〇、一句话

**它不查我们的代码像不像，它查 Xposed 框架本身还在不在、有没有加载过东西。**

### 🔑 最关键的发现

```smali
// hookJava 的采集有三个前置条件，任一不满足就不采集：
const-string v1, "hookJava"
```

## 三、★★ 掀桌级发现：`hookJava` 是「云控」的

`l11l111l11Il` 这个类全是**云控下发键**：

| `local` / `cloud` / `ver` / `enc` / `length` | 配置包结构 |

### 3.1 意味着什么

```smali
invoke-virtual {p4}, l11l111l11Il;->l11l111l1lll()Z    ← 读 "hook_java_switch"
if-eqz p3, :cond_a7                                   ← false ⇒ 整个 hookJava 采集跳过
```

**`hookJava` 采不采，是数美服务端通过云控决定的，不是硬编码。**

⇒ 这条配置是从 `{host}/v3/cloudconf` 拿的。

### 3.2 这把「对抗」降级成「改配置」

原来的三条对抗路径（A/B/C 伪造返回数据）**全都不需要了**：

```
改 sm_sdk_host → 指向我们的假 /v3/cloudconf
   → 返回 {"hook_java_switch": false, "hook_switch": false, "risk_file_switch": false}
   → 数美自己就不采了
   → smid 干净、上报正常、完全无痕
```

**这是官方机制，不是对抗。**

## 3.5 ★★ 云控配置的解密链（已完整还原）

### 3.5.1 内置默认配置（`l11l111l1lll` 的静态常量）

```java

    \"ver\": 1,
    \"code\": 0,
```

密钥 hex：`e6c9f6bc8d546e7a10660affdf64faca1d71afad8442d351f43277ccd5e5ffdb`

### 3.5.2 解密流程（`l11l111l1lll.l1111l111111Il(json, key)`）

```java
length = json.getInt("length");
enc    = json.has("enc") ? json.getInt("enc") : 0;
ver    = json.has("ver") ? json.getInt("ver")  : 0;
data   = Base64.decode(json.getString("data"));

if (enc == 1) {
    b1 = l11l11l1lIl->l1111l111111Il(key, data, length);   // ① AES/CBC/PKCS5Padding
    b2 = l11l1l1I1l->l1111l111111Il(b1);                   // ② Inflater (zlib)
    s  = new String(b2, utf8);
} else {
    s  = l11l11l1lIl->l111l11111lIl(key, data, length);    // 直接 AES → String
}
return ver == 1 ? parseV1(s) : parseV0(s);
```

### 3.5.3 加密原语（`l11l11l1lIl`）

| 方法 | 算法 |
|---|---|
| `l1111l111111Il(String,[B)[B` | **`AES/CBC/PKCS5Padding`**，**IV = `"0102030405060708"`** |
| `l1111l111111Il(String)` | `SecretKeySpec(keyBytes, "AES")` |
