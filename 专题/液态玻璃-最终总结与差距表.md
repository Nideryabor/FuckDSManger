# 液态玻璃 · 最终总结与差距表

> 主人 2026-10-01 收尾语：「**总结吧，因为不是真的液态玻璃**」
> 干活：尼得亚伯 🐲 · 版本跨度 **3.29.0 → 3.41.0**（约 24 个包）

---

## 一、先说结论

**我们做出来的东西是：一套跑在宿主 Compose 绘制管线里的、可切换多方案的「玻璃质感滤镜」。**

**它不等于 iOS 26 那种「液态玻璃」。** 这一点主人看得比我清楚，我把它记在开头。

---

## 二、最终能用的能力（都是真机验证过的）

| # | 能力 | 状态 |
|---|---|---|
| 1 | **三套折射 shader 可切换** | Haze 式 / Cloudy 式 / 轻量扰动，正文由脚本从 `.agsl` 逐字生成 |
| 2 | **两种实现方式** | GPU（`RenderNode`+`RenderEffect` 链）/ CPU（`BitmapShader` 当 Paint 的 shader） |
| 3 | **三种底图来源** | 元素底色 / 屏幕截图 / **我的背景图**（含"背景开关关了自动回退"） |
| 4 | **GPU 管线** | `createChainEffect(blur, runtimeShaderEffect)` —— Haze 2.0 同一条链 |
| 5 | 可调参数 | 浓度 / 模糊 / **色散** / 圆角 / 作用范围 / 方案 / 实现方式 / 擦内容+容差 / 颜色 |
| 6 | **颜色轮盘** | 手搓 Compose：色相环 + SV 方块 + 透明度 + 十六进制（不引第三方） |
| 7 | 兜底 | 连续出错自动停用；底色拿不到就不画（不许"变脸"） |

**实测（背景图模式）**：
```
背景开  饱和度 21.2  亮度 129.5   ← 壁纸透出来了 ✅
背景关  饱和度  0.0  亮度  15.0   ← 自动回退元素底色 ✅
```

## 三、**差距表：为什么它不是真的液态玻璃**

| 真·液态玻璃该有的 | 我们做到的 | 差距的根源 |
|---|---|---|
| **背后内容被真实折射**（掰弯的是内容本身） | 用「底色 / 壁纸 / 截图」当内容 | ⚠️ **拿不到 z 序意义上的"背后内容"**（见下） |
| 镜面高光 / 环境反射 | Cloudy 式 shader 里**有代码**，但没调过参 | 没有真机对比手段（自拍拍不到 GPU） |
| 随手指实时响应（Q 弹） | 早期做过 `GmGlassSpring`，**没接上** | 时间不够 |
| 随背景内容动态变化 | 底图是**静态**的 | 同上 |
| 精确跟随元素的**形状**（圆角/描边） | 画的是矩形（圆角默认 0） | **拿不到元素的 `Shape` 对象** |

### 根因就一句话

> **库能做到，是因为它们「拥有自己的 composition」。**
> `hazeSource` / `sky` 那种写法，本质是**在自己写的 UI 上留一个标记**，
> 框架就会把「这块内容」录进一个图层交给效果使用。
>
> **而我们是寄生在别人已经混淆过的 Compose 里** ——
> 没有自己的 composition、拿不到 `GraphicsLayer`（混淆 + `toImageBitmap` 是 suspend），
> 只能在**绘制管线的缝隙里**找位置。
> 这不是技术不够，是**位置不对**。

## 四、这一夜真正的收获（其实不是玻璃）

### ① 我给自己造了一双眼睛

```
宿主自拍（自己写进自己的 files 目录）→ 我从外面 su 0 cat 纯读拉出来
```

**在这之前我一直在盲修** —— 主人一句「你这没区别啊」把我打醒。
配套做了 `snapab.sh`（关/开逐像素对比）。

⚠️ 它有个盲区：**拍不到 GPU 效果**（自拍用软件画布，`drawRenderNode` 不支持）。
**这条限制我踩过，也写下来了。**

### ② 一堆"有据"的坑（共 17 条，全在 `专题/2026-10-01-液态玻璃-战果总结.md`）

最值钱的五条：
1. **`decor.draw()` 在 Compose 宿主上会卡死** —— 参照物的招数不能照抄
2. **`RenderNode` 复用 + 延迟绘制** ⇒ 每个元素渲染同一块内容
3. **两套存储格式并存，只读旧的那套** ⇒ 永远读到残留值（`FdmPush` 那条）
4. **"兜底"和"清空"撞一起** ⇒ 死循环，用户表现成"改不了"
5. **`GmStore.read2` 第三参是「类型」不是「默认值」**

### ③ 一条方法论

> **"降级为纯噪声"的 bug，优先级最低。**
> 判断标准：**它有没有挡住任何一条"用户能感知的路径"？**
> 没有的话，先记一笔，别动。
> （`GmTouchHook` 那条警告就是 —— 修它的代价是重建底座，收益是零。）

## 五、如果哪天真要做"真·液态玻璃"

按代价从低到高：

| # | 路子 | 代价 |
|---|---|---|
| 1 | **接上弹簧**（`GmGlassSpring` 还在）+ 调 Cloudy 式的高光参数 | 小，**值得做** |
| 2 | 跟随元素**形状**（反射拿 `Shape` 对象画） | 中 |
| 3 | **mortd 架构**：一次全屏 pass，把 N 个玻璃当参数传 | 中，但卡在"拿不到根节点内容" |
| 4 | 让宿主**自己**用 Haze 那种写法（改宿主 = 不可能） | — |
| 5 | frida-gadget 注入（frida 在这台机器上已证不可用） | — |

**我的判断**：**1 值得做**（那是"玻璃感"里最缺的一块）；**2 是性价比第二**；
3/4/5 都撞在同一个墙上 —— **除非我们不寄生**。
