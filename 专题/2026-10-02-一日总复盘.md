## 二、⭐ 这一天的最大价值：**翻案**

### 昨天收工时我的判断（错的）

> 「`FitHook` 管太宽 ⇒ 把宿主**列表级 ShaderBrush** 也接管了，铁证 `目标=(1440,25349)`」

### 今天从宿主直接读出来的真相

把 `DeepSeek_2.6.1.apk` 的 `jq0` 和父类 `Lim9` 反编译出来（**不需要真机 / root / frida**）：

```
jq0  = Compose 的 ShaderBrush
       .field c:I              = tag（1 ⇒ d 是 RuntimeShader）
       .field d:Ljava/lang/Object;
       <init>(RuntimeShader)   ⇒ tag=1、d=它      ← 我们 imgBrush 造的就是这条

Lim9（父类）
       .field a:Ljub;  .field b:J                  ← 缓存 shader / 缓存 size（初值 NaN,NaN）
       a(F,J,Lsf;) {
           if (a == null || !Size.equals(b, size)) {
               if (Size.isInvalid(size)) { a = null; b = NaN; }
               else { v = b(size); a.b = v; b = size; }   ← ★ 把 J 原样传给 b(J)
           }
           if (paint.shader != cached) paint.setShader(cached);
       }
```

⇒ **三件事一次定死**：

| 问题 | 答案 |
|---|---|
| `jq0` 是什么 | Compose 的 `ShaderBrush`，`tag=1 ⇒ d = RuntimeShader`（**正是我们造的那条**） |
| `b(J)` 的 `J` 是尺寸吗 | **是**（父类拿它当 size 缓存键，再原样传给 `b(J)`）⇒ 我们原来解对了 |
| 谁在调 `b(J)` | **4 个调用点**（`ci.w` / `Lim9.a` / `ob7.i` / `ti7.w`）⇒ **「谁在调」比「尺寸多大」更值得当判据** |

### 因此被推翻的

**`1440` 就是屏幕宽** ⇒ 那不是"宿主的 brush 被误接管"，是**我们自己的 brush 被用在一个大节点上**，**正常调用**。
⇒ 3.42.37 那道「目标 > 2500 就放行」的闸门**挡的全是正常路径**，只会让大区域退回"1:1 贴左上角 + 边缘拉伸"⇒ 制造新错位。**已删除。**

### 新判据（3.42.43）：「两把钥匙」

| 钥匙 | 键 | 为什么 |
|---|---|---|
| ① | `thisObject->d`（RuntimeShader） | **一定配得上** —— 那个 shader 是我们亲手 new 的，`jq0.<init>(RuntimeShader)` 原封不动存进 `d` ⇒ IdentityHashMap 天然命中 |
| ② | `thisObject`（brush 实例） | 3.42.34 老路，兜底 |

⇒ **两把都不中 ⇒ 一律 `return-void`，绝不 `setResult`** ⇒ 宿主的 brush 永远进不来。

### 主人那句话是决定性的

> 「**上面镜像了，下面还是空白**」

**"上半有、下半无"** ⇒ 下半那片**根本没被这个 brush 画过**。
而 `TileMode` 只管"shader 平面上取什么颜色"，**管不了"哪块区域被画"**（那由宿主的绘制区域/裁剪决定）。

⇒ **「补」永远救不了「没画」。** ⇒ 3.42.44 折腾 `TileMode` 的方向就是错的。

## 五、❌ 事故：我把自己折腾翻车了

> 「你咋了，我看你跑了很久先中止了，然后进程有残留 rikkahub 又差点打不开还好我重启了」

**原因**（详见 `专题/事故-2026-10-02-连续重手操作与frida残留.md`）：

1. **`timeout 34 frida ... -p <pid>`** ⇒ `timeout` 到点 SIGTERM 掉 frida CLI，**agent 留在宿主里没卸载** ⇒ 连跑 5 次 = **5 层 agent 叠在宿主上**
   （这条坑项目文档里写着，**我自己还抄进了速查笔记，然后自己犯了**）
2. **没设停止条件**：抓不到数据就换姿势再试（滚动→旋转→force-stop→切前台），一路十几分钟
3. **抢了主人的前台**（他在 RikkaHub 里跟我说话）

**⇒ 连带作废一个观察**：「hook 挂上了但零调用」**不可信**
（多 agent 叠加 / `timeout` 杀 CLI 时输出可能丢 / 被测进程状态已漂）
⇒ **基于它推断的「FitHook 从未生效」整条链，全部作废。**
