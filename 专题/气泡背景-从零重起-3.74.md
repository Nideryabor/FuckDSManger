## 四、★ 观察通道（这次最大的基础设施收获）

### ① 模块日志**就在 logcat 里**

```
adb shell "logcat -d --pid=$(adb shell pidof com.deepseek.chat.a) | grep -F 'FDM'"
```

`GmUtil.log` → `XposedBridge.log` → logcat tag = `FDM`（同时还有 `LSPosedFramework`）。

**必须按 pid 过滤** —— 否则会被别的 App（比如我自己的聊天界面）刷屏。

> 这一条以前一直没发现，等于**瞎了一个月**。以后所有宿主侧调试都用它。

### ② 自建文件日志（adb 可直接 pull）

`/sdcard/Android/data/com.deepseek.chat.a/files/fdm-bubble.log`
—— 宿主外部目录，**shell 可读**（已实测）。

⚠️ 写它必须 `getExternalFilesDir`，**目录要宿主自己建**；空目录是我这边 mkdir 的（见教训 2）。

### ③ 配置可以完全绕开 UI（`fdm-config.json`）

```
/sdcard/Android/data/com.little_femaleboy.cannot_show.the_big_won_whale/files/fdm-config.json
```
```json
{ "bools": { "fuckds_bubble_bg_on": true },
  "ints":  { "fuckds_bubble_bg_color": -10777105, "fuckds_bubble_bg_alpha": 100 } }
```
写法：`adb push` 进去 → `am start` 模块 UI（`FdmApp` 里 `FdmPush.push`）→ 推给宿主 MMKV。
**不需要 Root，不需要打包装机。** 调参从此零成本。

> 颜色是 **signed int**：`0xFF5B8DEF` = `-10777105`。

## 五、⚠️ 撞过的坑（都留了铁证，别再撞）

| # | 坑 | 铁证 | 教训 |
|---|---|---|---|
| **1** | **`zi0.o` 不是随便编的 long** | `IllegalArgumentException: Invalid ID: 46` at `Paint.setColor` ← `y1c.c` ← `zi9.a0` ← `zi0.J0` | 宿主 `zi9.Y(J)`：`if ((value & 0x3F) > 0xF) return value;` ⇒ **Compose Color 把 colorSpace id 藏在低 6 位**，瞎写必崩。**结论：别碰 Compose 颜色，直接用 Canvas 画** |
| **2** | `log()` 里 `app()==null` 就 `return` | 3.74.1 安装期日志全丢 | **安装期 Application 还没建好**。日志要先走 `GmUtil.log`（logcat），再尽力写文件 |
| **3** | 只挂 `zi0` 的「1 参 void」不够 | 3.74.1 挂了 `J0` 和 `Y0` 两个 | 必须再加 `looksLikeDrawScope`（0 参返回 long + 0 参返回 float）才认得出真 DrawScope |
| **4** | 拿 Canvas 的链不能猜 | `ah6.a→co1.a→bo1.c(wc)→wc.a` | `wc` 是 `ao1`(Compose Canvas) 的实现，`wc.a` 才是 `android.graphics.Canvas` |
| **5** | 圆角不用自己算 | `okb.e` 的 `clip(t82.t)` 在**上层** Modifier | 在气泡的绘制节点里画**整块矩形**，宿主会自动裁成气泡形状 |

## 六、当前实现（`GmBubbleBg.java`，一个文件只干一件事）

```
① 从 t82.t 取气泡专用 Shape 实例
② 挂 vcc.B(Modifier,Shape)：见 t82.t ⇒ 立旗「下一个 yi0 是气泡」
③ 挂 yi0 构造：旗还在 ⇒ 这个元素就是气泡底色，记下来
④ 挂 yi0.b() / yi0.d(zi0)：把记号传到 zi0 绘制节点
⑤ 挂 zi0 的 draw：①拿 Canvas ②按配置画矩形（被宿主裁成气泡）
```

**为什么用「t82.t → 下一个 yi0」这个时序判据**：`t82.t` 全宿主只有 2 处引用，
都在 `UserChatMessageBubble.kt` 里；而 `vcc.n`（气泡用的 RoundedCornerShape）有 62 处，
根本不能当判据。

## 八、给下一次的我

1. **先 `logcat --pid=<宿主>` 看日志**，别再看私有目录那份。
2. **改宿主状态（写字段）之前，先确认那个字段的编码**。Compose 的 `Color` 是 value class，低 6 位是 colorSpace id。
3. **能自己画就别改宿主的数据**。Canvas 是我们的，画错了顶多难看，不会崩。
4. **一次一处**。3.74.2 就一处写错，立刻有堆栈定位；换上次那种改十处，就得再烧一晚。
5. 定位组件**永远先搜校验串**：`<组件名> (<文件>.kt:<行号>)`。
