# lspctl 调研与白名单网关（结论：**走不通**）

> 2026-10-24 · 尼得亚伯 🐲
> 起因：LSPosed 2.2.0+ 带了官方 CLI `lspctl`，想用它自动化「改模块作用域」
> 结论：**`lspctl` 的写命令在本机永远无法使用**（SELinux 域硬约束）· 网关代码保留备用

---

## 〇、一句话结论

**`lspctl` 的 `module` / `scope` / `hook-debug` 需要「`adb root` 形态的 shell」
（`u:r:shell:s0` 域 + uid 0），而 KSU 的 `su` 给的是 `u:r:ksu:s0` 域 —— 域不对，
uid 再对也没用。本机是生产版 ROM，`adb root` 被禁 ⇒ 这条路彻底堵死。**

`lspctl status` / `-h` / `--version` 能用（不需要鉴权），但**它们没有实用价值**。

---

## 一、lspctl 是什么

| 项 | 值 |
|---|---|
| 路径 | `/data/adb/ksu/bin/lspctl` → 符号链接到 `/data/adb/modules/zygisk_lsposed/lspctl` |
| 本质 | **353 字节的 sh 脚本**（不是二进制）|
| 实现 | `exec /system/bin/app_process -Djava.class.path=$dir/daemon.apk ... org.lsposed.lspd.cli.CliMain "$@"` |
| 依赖 | `daemon.apk`（4.6 MB）+ `framework.dex`（236 KB）|

### 完整命令结构（实测）

```
lspctl [-hV] [--json] COMMAND
  status                        查看 daemon 状态
  stop                          停 daemon
  module    list / show / enable / disable / disable-all
  scope     list / add / remove / set / clear
  hook-debug  enable / disable / dump
```

### 关键参数（实测）

```
module list [--json] [--user=ID] [--disabled | --enabled]
module show    MODULE
scope list  [--json] [--user=ID] MODULE
scope add   [--json] --user=ID MODULE PKG...
scope remove / set / clear   （同 add 形态）
hook-debug  enable / disable / dump
```

## 二、★ 鉴权卡点（本轮核心结论）

### 2.1 表现

| 命令 | 结果 |
|---|---|
| `lspctl status` | ✅ 正常输出（LSPosed 2.2.1 / API 102 / 24 modules）|
| `lspctl -h` / `--version` | ✅ 正常 |
| `lspctl module list` | ❌ `rc=4` `developer commands are only allowed from an ADB root shell` |
| `lspctl scope list <MODULE>` | ❌ 同样拒绝 |
| `lspctl scope add --user=0 M P` | ❌ 同样拒绝（参数补齐后仍是 AUTH_DENIED）|

`--json` 下的结构化错误：
```json
{"ok":false,"error":{"code":"AUTH_DENIED","message":"developer commands are only allowed from an ADB root shell"}}
```

### 2.2 已排除的假设（都实测过）

| 假设 | 实测结果 |
|---|---|
| 需要 uid 0 | ❌ `su -c` 已是 `uid=0(root)`，仍拒 |
| 需要 tty | ❌ 环境无关 |
| 需要特定环境变量（SHELL/HOME）| ❌ 伪造无效 |
| 参数缺漏导致 | ❌ 补齐 `--user=0` / `MODULE` 后仍拒（但**参数校验确实在鉴权之前**——先报 `Missing required parameter` 再报 `AUTH_DENIED`）|

### 2.3 真因：**SELinux 域**

```
KSU 的 su        →  uid=0  · context=u:r:ksu:s0      ← 被拒
adb shell (正常) →  uid=2000 · context=u:r:shell:s0   ← 域对但 uid 不对
adb root 形态     →  uid=0  · context=u:r:shell:s0    ← ★ 这是它要的
```

`CliMain` 反编译里能看到 `Os.getuid()` 检查（那是客户端预检），
**真正的 `AUTH_DENIED` 由 daemon 返回**（字符串走 LSPosed 的 StringFog 混淆，静态解不开）。

### 2.4 本机为什么凑不出来

```
ro.build.type       = user          ← 生产版
ro.debuggable       = 0
adb root            → "adbd cannot run as root in production builds"
adbd 进程           → Uid 2000 · context u:r:adbd:s0
```

⇒ 拿不到 `adb root` 形态的 shell。

### 2.5 试过 KSU 的 App Profile（失败）

在 KSU Next 里把 **adbd** 配成 `uid=0 / gid=0 / SELinux=u:r:shell:s0`：

```
结果：shell 的 SELinux 变成了 u:r:shell:s0 ✅（但这是 adb shell 的**默认域**，不是配置生效的证据）
      但 adbd 进程本身仍是 Uid 2000 ❌
```

原因（逐层查证）：

| 层 | 事实 |
|---|---|
| `NO_NEW_PRIVS` | `NoNewPrivs: 0` ⇒ **不是它** |
| Seccomp | `Seccomp: 0` ⇒ 不是它 |
| `/system/bin/su` | 存在，但 `shell` 域**连读都不许**（`head -c 100` 读到 0 字节）⇒ `Permission denied` |
| KSU 的 su | 在 `/data/adb/ksu/bin/su`，但进不去 `/data/adb`（需要 root，死循环）|
| **★ 真正的卡点** | **KSU profile 是按「包名」匹配的**，而 `adb shell` 启的进程 cmdline 是 `sh`/`cat`，**没有包名** ⇒ 配 `com.android.shell` 永远影响不到它 |

### 2.6 最后试过：重启设备（也失败）

按 KSU 的规矩 profile 要重启才应用，**主人重启后仍是 `uid=2000`**。

⇒ **确认是包名匹配问题，不是"没重启"**。这条路彻底堵死。

## 四、当前的现实

| 项 | 状态 |
|---|---|
| adb shell | `uid=2000` · `u:r:shell:s0` |
| `su` | ✅ 存在于 `/system/bin/su`，但 **Permission denied**（`NO_NEW_PRIVS`）|
| `lspctl status` | 需要能执行 `lspctl` —— **当前 PATH 里没有**，且 `/data/adb` 不可读 |
| 尼尼能做的 | 读 `/data/local/tmp`、装 APK、logcat、抓包、反编译 |
| 尼尼不能做的 | `lspctl`、改 `/data/adb`、读其他 App 私有目录 |

## 五、将来想再试的话（先看这里，别重走）

### 5.1 前提条件（缺一不可）

```
① shell 的 SELinux 域 = u:r:shell:s0
② shell 的 uid = 0
③ lspctl 可执行（在 PATH 里 or 用完整路径）
```

### 5.2 可能的路线（按可行性）

| # | 路线 | 可行性 |
|---|---|---|
| 1 | 换 `userdebug`/`eng` ROM ⇒ `adb root` 可用 | ⭐⭐⭐⭐ 最直接，但要刷机 |
| 2 | 用 `mywalkb/LSPosed_mod`（社区分支，CLI 限制更松）| ⭐⭐⭐ 换框架，SUSFS/ZygiskNext 要重配 |
| 3 | 去掉 `NO_NEW_PRIVS` + 想办法让 `su` 转域到 `shell:s0`（`su --context` / `-Z`）| ⭐⭐ **未验证** |
| 4 | 给 adbd 打补丁让它以 root 起（改 `ro.debuggable`，但需要先有 root）| ⭐ 鸡生蛋 |

### 5.3 别再重复的无效尝试

- ❌ 伪造环境变量（SHELL/HOME）
- ❌ 加 `--json` / `--user=0` / 补全参数
- ❌ 在 KSU App Profile 里配 `com.android.shell` / `adbd`（**按包名匹配，管不到 `adb shell`**；重启过也无效）
- ❌ 期待 `lspctl status` 以外的命令能用
- ❌ 从 `/data/adb/ksu/bin/` 找 KSU 的 su（**进不去 `/data/adb`**，需要 root，死循环）

| 路线 | 结果 |
|---|---|

| KSU App Profile 配 `com.android.shell` | ❌ 按包名匹配，adb shell 的进程无包名 |
| 同上 + 重启设备 | ❌ 仍 `uid=2000` |
| 检查 `NO_NEW_PRIVS` | ❌ 本来就是 0，不是它 |

## 七、结论

**归档。不再尝试。**

- 本机（生产版 ROM + KSU）无法满足 `lspctl` 的鉴权前提
- 尼尼平时干活（反编译 / 装包 / 抓包 / 看日志）**不需要 root**
- 改 LSPosed 作用域这件事，继续**手动点界面**（而且它本来就只需要点一次）

> 什么时候重新捡起来：换 ROM 到 `userdebug`，或换 `LSPosed_mod`。
