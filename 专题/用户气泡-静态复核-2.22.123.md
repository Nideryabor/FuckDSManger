
静态读下来，**三处判据方向与「让用户气泡生效」的目标相反**——全是 `if-*z` 家族（本项目头号 bug 家族）：

| # | 位置 | 现状 | 为什么可疑 |
|---|---|---|---|
| **1** | `GmBubble.wrap()` | `sUDepth>0` ⇒ `fuckds_bubble.png`；否则 ⇒ `fuckds_ububble.png` | **反了**：用户项拿 AI 图、助手项拿用户图（`sUImgName` 的语义就是「用户 ⇒ ububble.png」） |
| **2** | `GmBubble.ubMod()` | `if-nez v0, :cond_65` = **shape 非 null ⇒ 直接 return null** | **反了**：应 `if-eqz`。否则只要 `shape()` 成功（它兜底到 `zc.o`，**几乎不会为 null**）⇒ 用户气泡**永不重写** |
| **3** | `GmBubblePaintHook.ub()` | `if-eq v2, v3, :cond_a3` = **`args[2] == zc.o` ⇒ 跳过** | **反了**：应 `if-ne`。而用户气泡底传的就是 `zc.o`（108 探针：`ls9.f:670` / `形=c84`）⇒ 被挡死 |

**2 与 3 叠加 ⇒ 「用户气泡定点重写」在静态上几乎不可能发生。**

## 二、证据（smali 原文）

### 证据 1 · `GmBubble.wrap()`（`GmBubble.smali` ≈1996行，110/123 同）

```smali
sget v0, Lcom/…/GmBubble;->sUDepth:I
if-lez v0, :cond_7                 # sUDepth <= 0 ⇒ 走 cond_7
const-string v0, "fuckds_bubble.png"      # ← sUDepth > 0（用户项）却用【AI 图】
goto :goto_9
:cond_7
const-string v0, "fuckds_ububble.png"     # ← sUDepth <= 0（助手项）却用【用户图】
:goto_9
sput-object v0, Lcom/…/GmBubble;->sImgName:Ljava/lang/String;
```

对照 `useUImgName()`（同样 110/123 同）：

```smali
.method public static useUImgName()V
    const-string v0, "fuckds_ububble.png"     # 用户 = ububble.png ✅
    sput-object v0, Lcom/…/GmBubble;->sImgName:Ljava/lang/String;
```

⇒ 两处对「用户 = 哪张图」的口径**互相矛盾**，`wrap()` 那条必然是反的。

### 证据 2 · `GmBubble.ubMod()`（`GmBubble.smali` 1829 行起，110/123 **完全一致**）

```smali
.method public static ubMod(Ljava/lang/ClassLoader;Ljava/lang/Object;)Ljava/lang/Object;
    .registers 9
    const/4 v6, 0x0                # 默认返回值 = null
    :try_start_1
    invoke-static {p0}, Lcom/…/GmBubble;->shape(Ljava/lang/ClassLoader;)Ljava/lang/Object;
    move-result-object v0
    if-nez v0, :cond_65            # ★ v0 != null ⇒ 跳到 return（= 什么都不做）
    …                              # 下面全部用 v0 当 shape：
    aput-object v0, v2, 0x2        #   uia.u(mod, brush, shape, 0)
    aput-object v0, v2, 0x2        #   uia.v(mod, color, shape)
    :cond_65
    :goto_65
    return-object v6               # = null
```

**两处自相矛盾**：
1. 判据要求 `v0 == null` 才往下走，可下面的代码**把 v0 当 shape 用** ⇒ 逻辑上只能是 `if-eqz`（null 就放弃）
2. `shape()` 的实现（`GmBubble.smali` 1625 行起）是**自造圆角 → 失败退回 `zc.o`**，
   ⇒ 只有「自造失败 **且** `zc.o` 也拿不到」才返回 null ⇒ 正常环境里 `shape()` **恒非 null**
   ⇒ 现行写法下 `ubMod()` **恒返回 null**

### 证据 3 · `GmBubblePaintHook.ub()`（`GmBubblePaintHook.smali` 868 行起，110/123 **完全一致**）


**作用域门的实际语义**（顺带更正文档）：


⇒ 差在 `sUDepth <= 0` 那一侧：**实现比文档宽**（sUDepth 归零时任何调用点都能往下走）。
而用户气泡底恰恰在**绘制阶段**（`sd=0 ud=0`），⇒ 这条门「宽口」正好对着它。

## 三、第二层疑点（先记着，别急着改）

| # | 项 | 说明 |
|---|---|---|
| A | `shape()` 只读 AI 圆角 | `shape()` → `radius()`（= `fuckds_bubble_radius`）；用户圆角 `fuckds_ububble_radius` 只在 `uRadius()` 里用 ⇒ **用户气泡的圆角会跟着 AI 走** |
| B | `ub()` 无「用户开关」分辨率 | 只判 `uOn()`；不应期/透明度这类用户侧参数（`uRadius/uColor/uImg`）都在 `ubMod` 里，一旦 #2 修好就会一起生效——要顺手验 |
| C | `sUBub` 只做诊断 | `GmUBubbleHook` 只 `sUBub++/--` + 一行 `logOnce`，**不参与任何判据**（文档也这么写）⇒ 它可以当"用户 lambda 到底跑没跑"的**免费探针** |

## 四、修补候选（等真机日志定案后择一）

| 方案 | 动作 | 风险 |
|---|---|---|
| **D（诊断优先，推荐先做）** | 只加日志、**不动逻辑**：`ub()` 每个门各一行（`uOn` / `name==v` / `args≥3` / `sUDepth` / `caller` / `hostShape==null` / `args[2]==hostShape` / `ubMod 返回值==null`），`ubMod` 开头打 `shape() 是否 null` | **零**（纯诊断） |
| **F（按静态判断修）** | ① `wrap()` 图片名互换 ② `ubMod()` `if-nez`→`if-eqz` ③ `ub()` `if-eq`→`if-ne` | 中（三条同时动 ⇒ 现象可能混在一起，难归因） |
| **S（拆开验）** | 一条一条改、一条一条装（①最独立 ⇒ 先改） | 低，但要三版 |

> 铁律 292（本线自己的教训）：**「探针门要宽、重写门要严」，两者别绑同一个条件**。
> 现在 `ub()` 把「诊断」和「重写」写在同一个函数里、共用同一串门 ⇒ #3 一旦改错方向会**静默**。
