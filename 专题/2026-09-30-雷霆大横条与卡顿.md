## 二、根因（两处，都在底座）

### ① 角色分派 `if-nez` 写反（`GmBubbleCellHook`）

```smali
    invoke-static {v5, v3, v4}, XposedHelpers;->callMethod(...)   # v3 = vq.D()
    move-result-object v3
    instance-of v4, v3, Ljava/lang/String;
    if-nez v4, :cond_b2      # ✗ if-nez = 非零才跳 ⇒ 「是 String」就跳「助手块」
    check-cast v3, Ljava/lang/String;
    const-string v4, "USER"
    invoke-virtual {v4, v3}, Ljava/lang/String;->equals(...)      # ← 只有非 String 才走到这里（然后 check-cast 抛）
    move-result v3
    if-nez v3, :cond_df      # 这一条反而是对的（"USER" ⇒ 用户块）
    :cond_b2                 # 助手块：sDepth++ → on() → 扫 args 里的 c76 → wrap()
    ...
    :cond_df                 # 用户块：sUCntCell++/sUDepth++ → 直接 return（不注入）
```

⇒ 修正：**`if-nez v4, :cond_b2` → `if-eqz v4, :cond_b2`**（一行）。
⇒ 副产物：`wrap()` 里那道 `sUDepth>0 ⇒ 跳过用户项` 是**死代码**（能走到 wrap 的只有助手支线，此时 `ud` 恒 0）—— 这解释了上次日志为什么是 `wrap 进入 ud=0` 三连。

### ② `imgBrush()` 每次解码原图（性能）

```smali
    invoke-static {v1}, Landroid/graphics/BitmapFactory;->decodeFile(Ljava/lang/String;)Landroid/graphics/Bitmap;
```
**没有任何缓存判断**（只有 `sput sBmp` 存了没用）。原图 4096×3584 ⇒ 单次 ~60MB 分配；`wrap()`/`ubMod()` **每个消息项各调一次** ⇒ 重组一次解码十几次 ⇒ PPT。

修法：加 `sBmpCache`（`ConcurrentHashMap`，键 = `sImgName`），命中直接跳过解码；`saveImage()` 开头清表。
**为什么不能用"单槽缓存"**：AI 档与用户档会交替调用 ⇒ 单槽会被对方挤掉 ⇒ 永远 miss。
