## 一、构建（一条命令出包）

| 工具 | 位置 | 干什么 |
|---|---|---|
| **做包.sh** | `/workspace/做包.sh` | 一条命令：编桥 → 编 UI → 组单包。**自动找底座 APK**（它被人挪过 ✗）✅ 失败会明确报错（`set +e` 显式取退出码）✅ |
| build_ui.py | `pipeline/build_ui.py` | Compose 链八步：AAR 闭包 → aapt2 → R 类 → kotlinc → R8 → pc 注入 → 组包 → 签名 |
| build_single.py | `pipeline/build_single.py` | 单包组装 + **出包前自检 ①~⑪** |
| patch_r.py | `pipeline/patch_r.py` | 给"被引用但确实拿不到真值"的 R 类生成**占位类**（字段名从 dex 的 field_ids 读，不瞎编 ✅） |
| keys_scan.py | `pipeline/keys_scan.py` | 扫出模块所有配置键（会把 `<clinit>` 里的"字段→键"映射建起来 ✗ 否则只看得到 clinit ✅） |
| README-构建.md | `pipeline/README-构建.md` | 构建速查 + **每处坑的正确写法**（八条自检的由来） |
| build.sh | `mod-src/build.sh` | 桥：桩 → javac → d8 |

**出包前自检（不通过就拒绝出包）**
```
① 同名类 0    ② 底座入口真在    ③ 我们的入口真在    ④ 底座无资源引用
⑤ 条目搬运一件不少（含 META-INF/services ✗ 丢过协程主调度器）
⑥ dex 比 src 新（防"看着成功其实是旧的"）✗
⑨ 清单声明的组件类必须在 dex 里 ✗  ⑩ 父类闭包完整 ✗  ⑪ 引用闭包完整（带理由白名单）
```

## 二、逆向/分析（自己写的，因为 MT 有时不在线）

| 工具 | 位置 | 干什么 | 为什么需要 |
|---|---|---|---|
| **dex_strings.py** | `tools/respipe/dex_strings.py` | 按**代码顺序**抽某个类的 `const-string`（含完整 dalvik 指令长度表） | 原模块 UI 是**手写 smali**，文案内联在代码里 ✗ —— 只有按代码顺序抽才能还原菜单顺序 ✅（池顺序会乱 ✗） |
| **dex_sig.py** | `tools/respipe/dex_sig.py` | 打印指定类的方法**完整签名** | 写桩/反射时参数写错就 `NoSuchMethodException` ✗（实测 `GmEnv.isOn` 不是 `(Context)` ✗）—— 猜签名会浪费好几轮真机验证 |
| dexinfo.py | `mod-src/pack/dexinfo.py` | 类定义表 / 父类 / 被引用类型 / 缺失闭包 | 支撑 ⑨⑩⑪ 三道自检 |
| axml.py | `mod-src/pack/axml.py` | 二进制 AXML 解码/重建 | 自写清单（含**两张排序表** ✗ aapt2 从没解释过） |
| gen_r.py | `tools/respipe/gen_r.py` | 按 aapt2 分配的真 ID 重新生成各库 R 类 | AGP8 的 AAR 里 R 值是 0 ✗ |

## 三、运行时诊断（今天的重中之重）

| 工具 | 位置 | 干什么 |
|---|---|---|
| **抓日志.sh** | `mod-src/out/抓日志.sh` | su 跑一次，抓 **6 类**：① logcat（含崩溃栈）② 我们 App 的 SP ③ **宿主 MMKV 真实键名** ✗（最能破案）④ 灰度键现场 ⑤ 模块日志文件 ⑥ LSPosed 作用域。**结果自动丢进我的 tmp** ✅ |
| 抓日志-精简.sh | `mod-src/out/抓日志-精简.sh` | 同上精简版（拷到 /sdcard 也能跑 ✅） |
| **ui_step**（桥里的动作） | `FdmBridge` | **借宿主当顺风耳**：ColorOS 会把应用进程的 `log` 全吞 ✗ ⇒ 界面把关键步骤发成 cmd，由宿主写进日志 ✅ |
