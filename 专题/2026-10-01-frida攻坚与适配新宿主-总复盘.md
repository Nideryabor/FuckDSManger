## 五·补 · 深夜续查（21:3x~）

### 5.1 ✅ 启动变慢的原因找到了

```
W LSPosedFramework: java.lang.IllegalAccessError:
    Field 'GmProbe.sInst' is inaccessible to class 'GmTouchHook'
    at GmTouchHook.beforeHookedMethod(Unknown Source:67)   ← 每次触摸都抛 + 打堆栈
```

**这就是文档里记过的"陈年哑火"**（`sInst` 是 `private`，4 个类在读它）。
**它一直在抛异常、一直在刷日志** —— 以前也有，但**我们加了更多钩子后，触摸路径更长了，就显出来了**。

**修法：**
- **A（立刻见效）**：不注册 `GmTouchHook` ⇒ 异常消失，速度回来
- **B（彻底）**：`sInst` 改 public ⇒ **会复活那 4 条钩子**，但它们的成员名还是旧的
  ⇒ **得先用 frida 逐个验成员名，验过的才开**

### 5.2 ❌ 内存 DEX 转储：**不需要**（已验证）

```
[A] ClassLoader 共 106 个：
      2 × InMemoryDexClassLoader      ← 只有模块 + LSPosed 两个
    102 × PathClassLoader
[B] 那 2 个都是 "InMemoryDexFile[cookie=[0, -5476...]]"
[C] 已加载类 41354，单段短名 9609（R8 混淆名，正常）
```

**⇒ 宿主没有加固壳 / 运行时解密 —— 静态 dex 就是全部。**

**组合拳评级**：①mapping.txt ❌无 · ②Kotlin Metadata ⭐值得做 · ③Compose 反编译 ⏸收益递减 ·
④内存转储 ❌不需要 · ⑤ClassLoader Hook ✅已在用 · ⑥绕反调试 ⏸不需要

### 5.3 ⭐ 「假类名」的真相：不是伪造，是**包名伪装**

崩栈里出现过两个"随机名"：

```
android.app.Praimoork.w(Praimoork.java)
android.content.MootuntShedath.w(MootuntShedath.java)
```

**挖了造假的代码 —— 结果是空的：** `tmp/h261/lk9.smali` 里那段
`"\tat " + className + "." + methodName + "(" + fileName + ":" + line + ")"`
**就是个普通栈格式化器，没伪造任何东西。**

**⇒ 所以那不是假名，是真的：宿主把自家混淆类【搬进了 `android.*` 包】，
让逆向的人一眼扫过去以为是系统代码。**（另一种反分析手法）

**⇒ 而 `enumerateLoadedClassesSync` 没搜到它，很可能是"不在 Frida 默认那个 ClassLoader 的可见范围里"。**

**下一步（比挖造假代码直接得多）：**

```
遍历【全部 106 个 ClassLoader】→ 每个都 loadClass("android.app.Praimoork")
→ 谁认它就找到了 → 然后正常分析这个类
```
