### 28.2 2.9.8 的两个「完全没效果」（已在 2.9.9 修掉，教训留档）

1. **`findClass` 用了 dex 名**：注册写 `"Ls5"`，但 Xposed 要 Java 名 **`s5`** ⇒ 抛异常被 `hookM` 的 try/catch 吞掉 ⇒ 静默无效。
2. **`painterResource` 对矢量 XML 不走 `Resources.getDrawable`** ⇒ 换资源那条路是死代码；
   头像实际由 **Coil3** 加载（吃 URL 字符串）⇒ 改成 hook 算 URL 的 lambda 返回 `file://`。

> 教训第 58/59/60 条见 `版本/2.9.9.md` 与专题文档第七节。

### 28.3 🔴 未完结：助手头像「蓝方块 / 消失」

**时间线**

| 版本 | 动作 | 结果 |
|---|---|---|
| 2.9.8 | 首版（挂 `Resources.getDrawable`） | 完全没用（矢量资源不走 getDrawable） |
| 2.9.9 | 查明链路，未动 | 蓝方块 |
| 2.9.10 | hook `Icon`（`me4;->a`）把 tint 换成 `Color.Unspecified` | 😵 **头像完全消失** |
| **2.9.11** | **摘掉该注册，回退** | 回到「蓝方块」可观测状态 |

**根因（已确证）**：助手头像由 `Icon(painter, tint=主题色)` 绘制，`ColorFilter.tint`（`SrcIn`）
保留 alpha、RGB 全换 ⇒ 照片变纯品牌蓝方块。绘制链
`Icon` → `PainterElement`/`PainterModifier` → `Painter.paint`（内部 `b` 标志决定走不走 `saveLayer`），
**两条分支都会调 `onDraw()`** ⇒ 按代码「不染色」不该消失，与现象矛盾。

**两个候选（互相可区分）**

- **A** tint 中和本身有问题 ⇒ 装 2.9.11 后头像变回蓝方块
- **B** ⭐ 与 tint 无关：painter 画出的内容本来就不对（接近背景色/尺寸退化），**蓝 tint 只是把它显影了** ⇒ 装 2.9.11 后仍空白

**续做入口**：`版本/2.9.11.md` 第五节（含：已确证「地图」表、两个候选各自的修法、
需要的日志关键字 `PHook:` / `GmVectorHook fired` / `hookM kf5.K` / `Icon tint 已中和`）。

> 修法 A ⇒ 自建 Painter 子类（继承宿主 `Lku6`）在 `onDraw` 无视 `colorFilter`；
> 修法 B ⇒ 给「恒等 filter」`ColorFilter.tint(白, Modulate)`（`SrcIn=5`，**`Modulate=13`**）。
> 教训第 64/65 条（先怀疑「原参数在掩盖另一个 bug」；改不动就先回退到可观测状态）。

### 27.2 核心遗留：底图模式不可见

**已排除的路线（有证据，别再重复走）**：

1. ~~给 `DecorView` 设背景~~ → 被内容盖住（蒙层可见 ⇒ 渲染本身没问题）

   ⇒ **DeepSeek 的 UI 不使用 Material3 `ColorScheme`**（自有一套配色）

**已尝试但未验证**：`android.R.id.content` + `View.setBlendMode(MULTIPLY/SCREEN)`（2.5.5）。
思路是**不把 App 弄透明，而是让 App 内容"混"到底图上**：白底/黑底被底图取代，文字仍可读。

**下一步（按优先级）**：
1. 验证 2.5.5 混合模式 → 有效则收工
2. 无效 → 换层级/换 API：把混合设在 ComposeView 那层，或用 `setLayerType + Paint.setBlendMode`
3. 仍无效 → 追 App 自己的根 composable
   （`MainActivity.onCreate` → `Ly03;->a(Lds;Lxr8;)V` = setContent → `Lir8;` 的 1909 行巨型 lambda）
4. 兜底 → 放弃真底图，打磨「蒙层」并去掉 WIP 标识

### 29.2 ⚠️ 使用注意（重要，别再踩）

| 项 | 说明 |
|---|---|
| **一次性换、换完固定** | device_id 反复变化是**盗号特征**，会被风控盯上 |
| **别清宿主数据 / 别卸载重装** | 伪 ID 存在宿主 MMKV，丢了就重新生成 ⇒ **又是一台"新设备"** |
| **别来回拨开关** | 关 = 变回真实 ID ⇒ 同样是一次突变 |
| **Java/native 可能不一致** | hook 在 Java 层；数美 native 理论上能读到真实 `android_id` ⇒ 潜在暴露面 |
| 建议 | 把当前伪 ID（MMKV 键 `fuckds_device_id`）记下来备用 |
