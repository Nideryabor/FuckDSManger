> 方法：静态逆向（15559 类 smali + 2 个 so）+ 小窝 Java 工具链（JCE）实解 + 小窝联网实测

## 二、★ A 栈（AES）—— 已破解 + 实测解密

### 2.1 逆向证据

`Laec;`（tt-data 助手）里的字符串：
```
tt_data
application/octet-stream;tt-data=a
before encrypt url: / after encrypt url:
AES / AES/ECB/NoPadding
decodeData
```

`Laec.d([B, String)String`（**解密**）：
```java
if (TextUtils.isEmpty(key)) return;
SecretKeySpec key.getBytes(), "AES"
Cipher.getInstance("AES/ECB/NoPadding")     // ← 无 IV、无填充
```

`Laec.e(HttpResponse)JSONObject`（**响应处理**）：
```java
v4 = resp.headers.get("ran");   // ← 没有就试 "Ran"
String data = json.optString("data");
if (!data.isEmpty() && !TextUtils.isEmpty(v4))
    json = new JSONObject( aec.d(data.getBytes(), v4) );   // ← 解密
```

**⇒ 密钥 = 响应头 `ran`；密文 = 响应 JSON 的 `data` 字段。**

### 2.2 实测（小窝本地跑通）

```
ran   = yuNttCSojTyxZods          ← 16 字节 = AES-128（用原始 HAR 取真值）
data  = base64，300 字符 → 224 字节（224 % 16 = 0 ✓）
算法  = AES/ECB/NoPadding + key.getBytes()
工具  = 小窝 Java 工具链（javax.crypto，就是模块用的那套）
```

**明文（火山云控配置，原文）：**
```json
{"error_code":0,"magic_tag":"ss_app_log","message":"success","server_time":"1792140046",
 "is_crash":0,"stop_interval":3600,
 "configs":{"debug_settings":{"should_submit_debugreal":0},"file_settings":{"should_upload_file":0}}}
```

✅ **这条通道 100% 可离线解密。**

> 🔧 复现脚本：`/tmp/dec/Dec.java`（`java Dec <ran> <blob.bin>`）

## 三、★ B 栈（ttEncrypt / native）—— API 已精确定位

### 3.1 so 身份

| so | 大小 | 真身 | 证据 |
|---|---|---|---|
| `libEncryptorP.so` | 83,928 B | **ByteDance 加密库** | 串 `com/bytedance/applog/encryptor/EncryptorUtil` + `ttEncrypt` + `JNI_OnLoad`；dynsym 只有 `JNI_OnLoad`（方法靠 `RegisterNatives` 动态注册） |
| `librscrypto.so` | 336,568 B | **Rust 写的** SHA3 栈 | 串 `rust-sha3` / `jni-0.21.1`（DeepSeek 自家签名用） |

### 3.2 dex 侧（**未混淆**，因为 JNI 要按名找）

`com/bytedance/applog/encryptor/EncryptorUtil.smali`：
```java
public abstract class EncryptorUtil {
    static { System.loadLibrary("EncryptorP"); }        // ← 就是那个 so
    public static byte[] a(int i, byte[] b) {           // ← 唯一入口
        if (b != null && i > 0 && b.length == i) return ttEncrypt(b, i);
        return null;
    }
    private static native byte[] ttEncrypt(byte[] b, int i);
}
```
`com/bytedance/applog/encryptor/IEncryptorType`：
```java
public static final String DEFAULT_ENCRYPTOR = "a";      // ← 对应请求头 tt-data=a
```

### 3.3 用在哪

| 调用点 | 说明 |
|---|---|
| `xmc.smali:1235` → `EncryptorUtil.a(I,[B)` | **AB 配置客户端**（含串 `ab_version` / `device_id` / `key` / `iv` / `AES` / `SHA-256`）|
| `Lxmc;->D(Ljava/lang/String;)[B` | AB 配置的加解密入口 |
| 请求头 `Content-Type: application/octet-stream;tt-data=a` | `tab.volces.com/abtest_config` + `gator.volces.com/app_log` + `apmplus…/cloudcontrol` |

### 3.4 ⚠️ 关键：**dex 里只有 encrypt，没有 decrypt**

⇒ 两种可能：
1. `ttEncrypt` 是**对称**的（同一函数解密）；
2. 响应解密走**别处**（`xmc` 里的 `key`/`iv`/`AES`/`SHA-256` 串暗示：可能有 AES 二次包装）。

**⇒ 这正是必须「运行时 dump」的原因。**

## 五、★ 所以——你说的"更狠的"就是最优解

现在 hook 目标**已经从"猜"变成"精确到函数"**：

### 5.1 最小目标（AB 配置明文）

```javascript
// 请求加密入口：拿到「加密前明文」
XposedBridge.hookAllMethods(
  XposedHelpers.findClass("com/bytedance/applog/encryptor/EncryptorUtil", cl),
  "a", new XC_MethodHook() {
    beforeHookedMethod(m) { dump((byte[]) m.args[1]); }   // ← 明文 JSON
  });
```
- **优点**：类名未混淆，永久稳定；一处 hook 覆盖 AppLog + AB + cloudcontrol
- 如果 ttEncrypt 是对称的 ⇒ 响应解密也走这里 ⇒ **一网打尽**

### 5.2 更上层（AB 配置专属）

```javascript
// Lxmc;->D(String)[B     AB 配置加解密入口
// Laec;->d([B,String)    tt-data AES 解密（已逆向，可直接复刻）
// Laec;->e(HttpResponse) 响应→JSON（含 ran 取值 + AES 解密）
```

### 5.3 或者——直接复刻 AES 通道（**不用 hook**）

`ran` 头 + AES/ECB/NoPadding 已经验证 ⇒ 只要抓包里有 `ran`，
**离线就能把 AppLog/cloudcontrol 全解出来**（本次已示范）。
