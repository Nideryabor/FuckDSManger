## 一、结论先说：**不用解密**

原本以为要逆火山引擎的加密（抓包 `tab.volces.com/service/2/abtest_config/` 的响应是
**3456 字节、熵 7.94** 的密文）。实际走下来发现：

> **火山 AppLog SDK 把 AB 配置解好之后，是明文存进 MMKV 的 `kv_remote_settings_*` 的。**
> 那个密文只是「传输形态」，到本地已经落地成明文了。
> ⇒ 读 MMKV 就够，**不需要逆 .so、不需要 hook 解密函数**。

### 交叉验证（都验过，不是猜）

| 证据 | 结果 |
|---|---|
| `libEncryptorP.so` 的 JNI 注册 | 只有 `EncryptorUtil` + `ttEncrypt` ⇒ **只有上传加密，没有解密** |
| `EncryptorUtil.a(I,[B)[B` | 长度校验后转调 `ttEncrypt`，同样是加密方向 |
| 全宿主 `javax.crypto.Cipher` | 火山相关的只有 `gw3.a(String,String)`：`AES/CBC/PKCS5Padding` + **全零 IV**，但**密钥运行时注入**，静态拿不到 |
| MMKV `mmkv.default`（262144 B） | **60 个 `kv_remote_settings_*` 键，值全是明文** ✅ |
| 另一个库 `1f4f3f9c-*.bin`（65536 B） | 0 个 AB 键 ⇒ 配置只在 `mmkv.default` |

## 四、方法与工具（可重放）

```sh
# 1 从设备拉 MMKV（需要 root，走 devlog 网关）
TOKEN=$(cat tmp/devlogs/.token)
curl -s -H "X-Devlog-Token: $TOKEN" \
  "http://127.0.0.1:8756/file?path=<urlencoded 路径>" -o tmp/mmkv272/default.bin

# 2 全量 dump（所有键，不只 AB）
python3 tools/mmkv_dump.py tmp/mmkv272/default.bin

# 3 只抽 AB + 解类型 + 出 TSV
python3 tools/ab_extract.py tmp/mmkv272/default.bin tmp/ab-all.tsv
```

### MMKV 文件格式（这次现学的，记下来）

```
[varint keyLen][key utf8][varint valLen][val bytes] x N
```

- 全是 **varint 长度前缀**，没有分隔符
- **append-only**：同一个 key 会出现多次，**最后一条才是当前值**
- value 的编码也是 `varint(len) + 内容`；单字节 `0x01`/`0x00` 是 bool 的紧凑写法
- 4 字节小端 float 直接躺在那儿（`cdcc4c3f` = 0.8）

## 六、★ 第二条路：内存直读（上次那条，这次复现成功）

主人提醒「**我怎么记得上次能绕过**」—— 翻到 `巢穴/日记/2026-10-31.md` 第六节，
上次的结论是：

> **不该问「怎么解密」，该问「配置拉下来之后在内存里长什么样」**
> `Java.choose('htc', ...)` → `inst.a()` → 8361 字符完整 JSON

这次在 2.7.2 上**原样复现成功**（`tools/frida/js/ab-mem.js`）：

```
[MEM] 找到 htc 实例: htc@3d292e5
[MEM] a() 长度 = 8361
```

`htc` 和它的 `a()Lorg/json/JSONObject;` 都还在（`tmp/host272/sm1/htc.smali:637`）。
这条路**不需要 root 读 MMKV、不需要解密**，挂上 frida 就能拿。

### 两份数据的关系（重要）

| | 内存 `htc.a()` | MMKV `kv_remote_settings_*` |
|---|---|---|
| 项数 | **22** | **60** |
| vid | **真 A/B 分组号**（`20192926` 这种 8 位） | 另一套内部 id（10 位，见下） |
| 含义 | **服务端这次下发的原始配置** | **本地累计缓存**（含我们自己写过的键） |
| 实时性 | 当前进程的最新 | 可能混着历史 |

> **两边的 `id` 不是一回事**：内存里的 `vid` 是火山 AB 的分组号；
> MMKV 里 `kv_remote_settings_id_*` 解出来是 10 位数字（如 `dead_link_detection` = 1353546749），
> 更像配置项版本/哈希。**要 A/B 分组号就看内存那份。**

### 并集：**64 项**

| 来源 | 项数 | 说明 |
|---|---|---|
| 两边都有 | 18 | |
| **只有内存有**（服务端下发了、MMKV 没落） | **4** | `max_input_files`=50 · `query_title_time_interval`=100000000 · `report_http_biz_error`=true · `stop_stream_wait_times`=1000 |
| **只有 MMKV 有**（本地缓存） | **42** | 含 `model_configs_v1` / `providers_v1` / `welcome_msg` 这些大块 |

> 那 4 项正是 10-31 日记里说的「4 项没覆盖」，**两条路都要走才全**。

### ⚠️ 6 处两边值不一致（要当心）

| 键 | 内存（服务端下发） | MMKV（缓存） | 判读 |
|---|---|---|---|
