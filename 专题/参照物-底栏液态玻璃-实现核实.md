## 零、它是什么

一个 **Xposed 模块**（新 API：`META-INF/xposed/java_init.list` + `module.prop`），
作用域 `com.tencent.mm`（微信）+ `com.tencent.mobileqq`（QQ），
把宿主**底部 tab 栏**换成「液态玻璃」—— 也就是 iOS 26 那种「毛玻璃 + 折射 + 高光边」的观感。

签名主体是 `CN=快播内部工作人员`（作者的玩笑，与本项目无关）。

```
zip 条目

  classes.dex                   87952 B
  META-INF/xposed/java_init.list      52 B   → io.github.liuran001.mmliquidglass.LiquidGlassModule
  META-INF/xposed/module.prop         81 B   → minApiVersion=102 / staticScope=true
  META-INF/xposed/scope.list          36 B   → com.tencent.mm / com.tencent.mobileqq
  resources.arsc                  572 B   （只有一个 label 字符串）
```

⇒ **一个 APK、一个身份（纯 hook 层）**，UI 完全不存在。这点和我们「双层架构」里 hook 层的定位一致。

## 二、核心手法（四条，逐条可复用）

### ① `StackBlur` —— 纯 CPU 的糊

`StackBlur.blur(Bitmap, radius)`：

```
getPixels → 3 趟 [ boxBlurH(src→dst) + boxBlurV(dst→src) ] → setPixels
```

- `boxBlurH/V` 是**滑动窗口盒式模糊**（Mario Klingemann 的 Stack Blur），复杂度 O(w·h)，**与半径无关**；
- 三个通道 **α 也一起糊**（别自作聪明去掉）；
- 三趟盒式模糊 ≈ 一次高斯。

**为什么要 CPU 模糊**：minSdk 26，而 `RenderEffect.createBlurEffect` 要 API 31。
⇒ 我们 3.29.0 的 `GmGlassBlur` 就是**逐字节照抄这一段**。

### ② 「把底层重画进 RenderNode」当 shader 输入 —— **最关键的一手**

`LiquidGlassPanel.drawGlass()`：

```
mBackdropRef (WeakReference<ViewGroup>)  ← 要"透出来"的那层
mPad                                      ← 外扩留白

RenderNode.mBackdrop.setPosition(0,0,w+2*pad,h+2*pad)
RecordingCanvas c = node.beginRecording(w+2*pad, h+2*pad)
    c.drawColor(mBaseColor)
    for (child : backdrop.children)
        if (child visible && getGlobalVisibleRect(rect) 非空)
            c.save(); c.translate(pad - (selfX - childX), pad - (selfY - childY))
            child.draw(c)          ← ★ 把兄弟 View 直接重画进来
            c.restore()
node.endRecording()

LensShader (AGSL) 以这个 RenderNode 为 content，做：
    - sdRoundedRect 求圆角矩形的有符号距离场
    - circleMap 做边缘"折射"偏移（refractionHeight / refractionAmount）
    - depthEffect 叠一个朝中心的厚度感
```

**没在硬件上就退**：`drawPanel` 里 `catchall` 一旦抛异常 ⇒ `mSupported = false` ⇒
退成「实心圆角矩形 + 高光边」的平面兜底（`mSurfacePaint` / `mHighlightPaint`）。

⇒ 我们学到的是：**折射要有，但兜底更要有**。我们的 `GmGlassSink` 同理
（底图拿不到就只画半透明玻璃，绝不卡宿主）。

### ③ `ViewGeom` —— 跨缩放的屏幕坐标

```java
cumulativeScale(view)      // 沿父链累乘 |getScaleX()|
unscaledScreenPos(v, out)  // 逐级 累加 (left+translationX-parent.scrollX)，最后 getLocationOnScreen 一次校正
```

用途：面板被宿主做了缩放（微信 tab 有缩放动画）时，`getLocationOnScreen` 会带上缩放，
得手动剥掉。**我们的宿主（Compose 单视图）没有这个问题，暂不移植**。

### ④ 生命周期 / 重试

```
onModuleLoaded:  forProcess(进程名) == null ⇒ detach()   ← 进程白名单，别的进程立刻退出
onPackageLoaded: HostApp.forPackage(pkg) + isFirstPackage ⇒ TabBarBridge.install
Instrumentation.callActivityOnResume:
     Activity 类名 == HostApp.launcherActivity
       ⇒ GlassConfig.load(activity)
       ⇒ LiquidGlassInstaller.scheduleInstall(activity)     （内部 40 次 x 250ms 重试）
```

⇒ 「装不上就重试、8 秒还没露面就放弃」，这套节奏我们可以直接借鉴。

## 三、和我们 3.29.0 的差异（为什么不照抄）

| 维度 | 参照物 | 我们（宿主 = DeepSeek 2.5.2） |
|---|---|---|
| 宿主 UI 体系 | **View**（`LauncherUIBottomTabView`） | **Compose**（整屏一个 `AndroidComposeView`） |
| 作用对象 | 底部 tab 栏（一个 ViewGroup） | **所有按钮**（Compose 节点，没有 View） |
| 拿底层像素 | 重画兄弟 View 进 RenderNode | **`PixelCopy`** 抄窗口 surface（Compose 的硬件层重画不出来） |
| 折射 | AGSL `RuntimeShader`（API 33+） | v1 先做「糊底 + 浓度 + 高光边 + 水滴」，折射留 v2 |
| 装在哪 | 往 ViewGroup `addView` | **不插 View**，直接劫宿主自己的画布调用（见下） |

### 我们为什么不插一个 `View` 上去

按钮上盖一层 View ⇒ **按钮的文字/图标被糊掉**。
要让玻璃「垫在文字下面」，必须画在宿主**自己的绘制顺序**里 —— 于是我们劫的是
画底原语的元素 `draw(DrawScope)`，把实心底换成玻璃底，文字照原样画在它上面。

**详细做法**（含全部证据）见 `专题/宿主按钮锚点-2.5.2.md`。

## 四、可借鉴但**还没做**的（v2 候选）

1. **真折射**：`RenderNode` + `RuntimeShader`（API 33+ 才有 `RuntimeShader`；宿主 minSdk 23 ⇒ 得按版本分支）。
2. **弹簧回弹**（`Spring`）：按下/松开时玻璃的缩放回弹。
3. **水滴拖拽**（`DropletPanel` + `DropletDragController`）：跟手的液滴 —— 移动端很出彩。
4. **`ViewGeom` 式的缩放剥离**：如果宿主以后给按钮加缩放动画会需要。
