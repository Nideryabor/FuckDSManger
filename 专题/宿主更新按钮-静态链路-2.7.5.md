# 宿主(DeepSeek 2.7.5 / vc295 / com.deepseek.chat.a)「点击更新」静态链路

> 纯静态、从零开始、不复用任何旧结论。样本 = `deepseek_clone.apk`（= /workspace/host_2.7.5.apk，同 size 22271197）
> 全部符号为 R8 重命名后的**当前**名字，随版本会变，勿硬编码。

---

## 0. 一句话结论

**宿主里根本不存在「跳转到别的 App」的代码，除了一个裸的 `startActivity(ACTION_VIEW, Uri)`。**
它不会下载 APK、不会调 `DownloadManager`、不会装包（全 dex 搜 `application/vnd.android.package-archive` → 0 命中）。

所以「点击更新 → 跳我们的模块」**只能由我们这一侧完成**（hook 改写 / intent-filter 抢占）。
宿主侧唯一可插的位置就是那一个方法，链路如下。

## 3. 为什么「点了更新，跳不到我们的模块」（宿主侧可验证的 3 个真因）

1. **宿主只会隐式 ACTION_VIEW**。浏览器（http/https）必然也在候选里 → 要么弹选择器、要么进浏览器；
   我们若不注册 URL 匹配的 intent-filter，连候选都没有。
2. **URL 可能是空串**（`alt_app.android_app_link` 为空 + 远端配置 `android_apk_link` 为空）。
   此时 `Uri.parse("")` → `ACTION_VIEW(空uri)` → `ActivityNotFoundException` → 被 `n4.w` catch → **弹窗直接消失，什么都不发生**（表象就是「点了没反应」）。
3. **强制位恒 false**，所以「取消」永远存在；`show_key` 闸门只拦自动弹，手动一定弹 —— 也就是说
   **能弹、能点，但点完不会有任何指向我们的行为**。宿主结构上就没这条逻辑。

> 结论：不是我们 hook 得不对，是**宿主没有这个能力**，必须我们替它做。

## 4. 建议的注入点（按稳健度排序）

### 方案 1（最稳，版本无关）：拦系统调用，改 Intent 目标
Hook 宿主进程内 `android.content.ContextWrapper.startActivity(Intent)`（或 `Instrumentation.execStartActivity`）：
```
if (action == ACTION_VIEW && data != null) {
    val s = data.toString()
    if (s == kvAndroidApkLink || s matches 更新直链特征 /* 例如 host 含 deepseek 且 path 以 .apk 结尾 */) {
        // 改成我们的模块，并 return（不调原方法）
        startActivity(Intent().setComponent(ComponentName(pkgModule, actUpdate)).putExtra("url", s))
        return
    }
}
```
优点：`zi`/`n4` 名字每版都变，`ContextWrapper` 不变；缺点：要加特征判定，避免误伤聊天里的链接点击（可再叠 `Throwable().stackTrace` 里出现 `Lzi;.a` 或 `UpdateDialog` 类名做二次确认）。

### 方案 2（最精准，单点）：hook `Lzi;->a(String)V`
`beforeHookedMethod` → 拿 `args[0]`（URL，可能为空串）→ 自己起模块 Activity → `result` 置 null 阻止原逻辑。
- 当前是 **2.7.5 / vc295** 的 `Lzi;`
- 每版重排 → 用**特征定位**而不是硬编码名字：dex 里同时含 `"android.intent.action.VIEW"` + `"Can't open "` + `"."`、单字段 `Context`、实现一个空接口、方法签名 `(Ljava/lang/String;)V`，全 dex 唯一。
- 兜底：URL 为空也要跳（我们的判断不能依赖 url 非空）——这正好修掉「点了没反应」。

### 方案 3（零 hook 兜底）：模块 apk 声明 intent-filter
```xml
<intent-filter>
  <action android:name="android.intent.action.VIEW"/>
  <category android:name="android.intent.category.DEFAULT"/>
  <category android:name="android.intent.category.BROWSABLE"/>
  <data android:scheme="https" android:host="<更新直链 host>"/>
</intent-filter>
```
只有在我们是**唯一**匹配者时才可能直接进；有浏览器在就还是选择器（不过选择器里至少会出现我们，可让用户「总是」）。

### 不要做的事
- 不要去 hook `Lqib`/`Lpib`（那俩只是文本与取消埋点）
- 不要指望宿主给 `ComponentName` / `PackageManager.resolveActivity` 之类的可绕过点——它压根没调
- 不要靠 `upgrade_app`/`force_update_dialog_*` 资源 id 定位（字符串只在 `Lqib` 里取，且 id 各版会变）
