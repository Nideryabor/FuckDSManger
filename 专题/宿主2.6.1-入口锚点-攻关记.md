## 二、教训 A：⭐ **LSPosed 缓存的 APK 路径会让模块"静默不加载"**

**这是本轮排查里最阴的一个坑，白白烧掉一个多小时。**

```
实际安装路径: /data/app/~~K7ftBKh05G9epv-6bx7QAg==/…-G7tjNpWnUjAjJHRPfWL9zA==/base.apk
LSPosed 记录: /data/app/~~3X9Y18LOzIira095jX9S9w==/…-SeQ6jexCieIHXr5rypkU-Q==/base.apk  ← 过期
```

**每次 `adb install -r` 安卓都会换一个全新的 `/data/app/~~xxx==/` 目录**，
而 LSPosed 的 `modules` 表缓存着旧路径 ⇒ **它加载不了模块**。

### 症状（极具迷惑性）
- 模块装了、LSPosed 里也是"启用"、作用域也对
- 但**模块日志里一行都没有**（`FuckDSManger` 0 行）
- 表现完全像"功能全哑"，让人以为是判据改错了 → 于是去改代码 → 白改

### 判据（一眼识别）
```sh
# 对比这两条，不一致就是它
adb shell "pm path <模块包名>"
# 再看 LSPosed DB 里的 modules.apk_path
```

### 处置
- **首选**：在 LSPosed 里把模块**取消勾选再勾选**（管理器会刷新路径）
- **备选**：直接改 DB（已备好脚本）
  ```sh
  # 备份
  su -c 'cp /data/adb/lspd/config/modules_config.db /sdcard/lspd_modules_config.bak'
  # 本地 sqlite 改 modules.apk_path → push 回去 → chown root:root + chmod 600
  ```

> 📌 **工程习惯**：以后**每次给主人装测试包，都要顺手确认一遍"模块到底加载了没"**，
> 别等点半天没反应才回头查。判据就是 `modules_*.log` 里搜 `FuckDSManger`。

## 三、教训 B：⭐⭐ **别再"推断"判据常量，让 dex 自己报数**

### 我走过的弯路
- 从 `t5.w()` 的 `packed-switch` 表里数出 `Lz32;->a` 在第 5 项 ⇒ 得出 **case=5** ❌
- 差在哪：方法里有**不止一个** switch 表 / case 编号不是简单下标

### 正确做法（探针）
在 `GmEntryHook.beforeHookedMethod` 里读字段之后、比较之前，插一段"把值打出来"：

```smali
new-instance v4, Ljava/lang/StringBuilder;
const-string v5, "[FDS] row case="
invoke-direct {v4, v5}, Ljava/lang/StringBuilder;-><init>(Ljava/lang/String;)V
invoke-virtual {v4, v1}, Ljava/lang/StringBuilder;->append(I)Ljava/lang/StringBuilder;
invoke-virtual {v4}, Ljava/lang/StringBuilder;->toString()Ljava/lang/String;
move-result-object v4
invoke-static {v4}, Lcom/nidyaber/fuckdsmanger/gm/GmUtil;->log(Ljava/lang/String;)V
```

主人点一下 ⇒ 日志里出现 `[FDS] row case=29` ⇒ **一次搞定**。

> ⭐ **通则：凡是"锚点里的魔法数字"（case 号 / 索引 / 资源 id），
> 都不要靠静态推断，插一行日志让运行时说。** 静态分析用来**缩小范围**，探针用来**定案**。

## 五、入口的完整证据链（可复用）

```
① 老宿主：m5.v() 的 case 0x14 → sget-object Lad8;->a → 交给 sink 接口
② Lad8 是"路由标记"类：public final、2 个静态字段(自类型)、只有 <clinit>、0 字符串
③ 新宿主里找同形 ⇒ 16 个候选；用"被恰好 5 个类引用"筛 ⇒ Lz32;（引用者 g92/gn2/ew1/gh2/yr7）
④ 但 Lz32 被 ew1 和 t5 都引用 ⇒ 分不出来
⑤ ⭐ 上运行时探针（hook 更新 VM xu2）= 打印 Java 调用栈
   ⇒ AndroidComposeView.dispatchTouchEvent → … → m01.w → t5.w → … → ll9.z → xu2.a
⑥ ⇒ 行桶 = t5（不是 ew1）；再用探针读 case ⇒ 29
```

> 第 ⑤ 步的**调用栈**是这一轮最值钱的一招：
> **当你不知道"是哪个类"时，别猜，去 hook 它的下游，让栈告诉你。**
