## 3. 机制（这一步才是能不能"用"的关键）

### 3.1 这些名字是 kotlinx.serialization 的 `serialName`，不是类名

宿主类被 R8 全量改名（`dex_names` 搜 `NestedGraph` = **0 命中**；
`Lcom/deepseek/chat/ui/pages/` 树下只剩 3 个类）。
但每个路由的序列化器是显式重建出来的：

```smali
:pswitch_97  #0xb
new-instance p0, Lia3;
sget-object  v0, Lyb8;->INSTANCE:Lyb8;          # 路由单例（Kotlin data object）
new-array    v1, v1, [Ljava/lang/annotation/Annotation;
const-string v2, "com.deepseek.chat.ui.pages.SettingsNestedGraph.SettingsRoute"
invoke-direct {p0, v2, v0, v1}, Lia3;-><init>(Ljava/lang/String;Ljava/lang/Object;[Ljava/lang/annotation/Annotation;)V
```

`Lia3;<init>(String, Object, Annotation[])` 就是 **kotlinx 的 `ObjectSerializer`**
（`serialName` = 字符串，`objectInstance` = 单例，`classAnnotations` = 空）。
每个路由类形如：`INSTANCE` + `a:Lta5;`(Lazy) + `serializer() = lazy { <lambda>().v() }`。

> ⇒ **原 FQ 名被完整保留在字符串里**（没被 R8 的 serialName 改写吃掉）——这是能用的前提。

### 3.2 宿主用的是 Navigation-Compose type-safe 路由

| 角色 | 混淆名 | 铁证 |
|---|---|---|
| `NavController` | `Lld6;` | `"Navigation destination that matches route "` / `" cannot be found in the navigation graph "` / `"You must call setGraph()…"` / `"android-support-nav:controller:deepLinkIntent"` |
| `NavGraph.matchRoute` | `Lid6;->o(String;Z;Lid6;)Ldd6;` | 返回 `DeepLinkMatch(NavDestination, Bundle)` |
| destination id | `Lx95;->B(Lv35;)I` | `descriptor.serialName.hashCode()` ← **id 只由 serialName 决定** |
| route 串生成 | `Lx95;->C(Object;LinkedHashMap;)String` | `"Cannot locate NavType for argument ["` |
| NavHost | （`Lvc5;` 等） | `androidx.navigation.compose.NavHost (NavHost.kt:490)` |

### 3.3 ⚠️ `navigate` 在 2.5.2 只剩一个重载，且**要求传对象**

`Lld6;` 全部成员只有 23 个方法，navigate 只剩：

```smali
Lld6;->n(Ljava/lang/Object;Lrd6;)V      # navigate(route: Any, extras)
Lld6;->o(Lld6;Ljava/lang/Object;Lrd6;I)V # $default 桥
```

它的第一步是：

```smali
invoke-virtual {p1}, Ljava/lang/Object;->getClass()Ljava/lang/Class;   # ← 对 route 取 Class
invoke-virtual {v1, v0}, Lbn7;->b(Ljava/lang/Class;)Lf15;              # serializer(class)
invoke-static  {v0}, Led5;->K(Lf15;)Lv35;                              # → KSerializer
invoke-static  {v0}, Lx95;->B(Lv35;)I                                  # → serialName.hashCode() = destination id
invoke-static  {v2, v0, v3, v4}, Lld6;->e(...)                         # findDestination
```

⇒ **传 `String` 会被当成 `serializer(String::class)`（serialName `kotlin.String`）→ 找不到目的地
→ `Destination with route kotlin.String cannot be found in navigation graph` → 抛
`IllegalArgumentException`。**

**结论：`navController.navigate("com.deepseek.chat.ui.pages.ChatRoute")` 走不通。**
（2.3.6 上那个模块能做，八成是它的 `navigate(String)` 重载还在，或者它用了别的手段——得让它自己交代。）

## 4. 三条真正可行的跳转路线（按推荐度）

### 方案 A ★ 自造 `@SerialName` 伪路由对象（最优雅，纯 Smali 可写）

因为 destination id 与 route 串**都只由 serialName 决定**：

```
id   = serialName.hashCode()
route = serialName (+ "?arg={arg}")
```

⇒ 我们在模块里自己定义「带同样 serialName 的 @Serializable object」即可：

```java
@Serializable
@SerialName("com.deepseek.chat.ui.pages.SettingsNestedGraph.SettingsRoute")
data object FakeSettingsRoute
```

然后 `navController.navigate(FakeSettingsRoute)`：
- `FakeSettingsRoute.getClass()` → 我们自己的类 → 我们自己的 `$serializer`
- `serialName.hashCode()` == 宿主注册的 id ⇒ **findDestination 命中**
- `generateRouteWithArgs` 生成的 route 串 == 宿主的 route pattern ⇒ `matchRoute` 命中

要求（手写 Smali）：一个 `@Serializable` 类 + `INSTANCE` + `serializer()`/`$serializer`，
`descriptor.serialName` 精确等于目标字符串。**不依赖任何混淆名 → 版本升级免疫。**

### 方案 B ○ 反查真路由对象

按 serialName 反查 dex / `ClassLoader` 找到承载类（如 `Lyb8;`），取 `INSTANCE` 字段，
直接 `navigate(instance)`。能用，但每个版本类名会变，要重建索引。

### 方案 C ○ 绕过 NavController，直接喂字符串

反射走内部两步：

```
NavGraph graph = navController.j()                                  # getGraph()
DeepLinkMatch m = graph.o(routeString, true, graph)                 # Lid6;->o  ← 收 String！
navController.m(m.a /*destination*/, m.b /*bundle*/, extras)        # Lld6;->m  直接入栈
```

**全程字符串**，不需要路由对象；代价是绑死混淆名（每版需重新定位，
好在可用 `Lx95;->B` / `Lid6;->o` 的特征串自动定位）。
