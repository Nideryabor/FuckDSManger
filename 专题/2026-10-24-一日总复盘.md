## 二、两个真凶（都是 R8 的坑）

### ① 玻璃只剩左上角 —— 「取第一个匹配」是定时炸弹

```java
for (Method m : scope.getClass().getMethods()) {
    if (m.getParameterCount() != 0) continue;
    if (m.getReturnType() != long.class) continue;
    return which == 0 ? a : b;      // ← 命中 getCenter() 而不是 getSize()
}
```

**铁证**：屏幕 1440×3168，日志报 **720×1584 = 正好中心点**。

一个原因两个症状：
- 玻璃只覆盖 `(0,0)~(720,1584)` ⇒ 左上角一块
- 整页根尺寸被误判 ⇒ `isFullPage()` 失效 ⇒ 全屏乱铺

**修法**：用不变量 `center = size / 2` 两两配对，大的才是 size。

### ② `<Suggestion>` 点了没反应 —— 名字存在 ≠ 是对的

```
建议链接能力未就绪（ri6 不是 si6 的子类（不像 Clickable））⇒ 只剥标签
```

「只剥标签」= 脱成纯文本 = **死文字**。

| 用途 | 代码找的 | 2.7.1 真名 | 证据 |
|---|---|---|---|
| LinkAnnotation 基类 | `yi6` ❌ | **`gm6`** | `em6`/`fm6` 的 `.super Lgm6;` |
| Clickable | `em6` ✅ | `em6` | 字符串 `LinkAnnotation.Clickable(tag=` |
| Listener | `zi6` ❌ | **`hm6`** | 字段 `c:Lhm6;` + interface |

`si6`/`ri6` 在 2.7.1 里**还在，但指向无关类** ⇒ 自检必败 ⇒ 该功能从未工作过。

## 五、数美封控逆向（新增）

**结论**：`libsmsdk.so` 2.6.1 → 2.7.1 **一字未改**（842,488 B，
imports 83 条一致、init_array 22 槽地址逐个相同）。

**新增成果**：
- SDK 版本 `3.14.3_build1`
- Java 侧全貌（`SmAntiFraud` / `SmOption` 70 成员 / `SMSDK` 9 个 native）
- ★ **`RegisterNatives` 表定位** = `0xc6ec8`，9 项，**fnPtr 全部拿到**
- 宿主侧两个 `ShumeiVerification`（`{rid, region}`）

**一句话**：它不看代码像不像，**看进程里多了什么**（`popen` + `opendir` +
`syscall` + `rand` + `deflate` 压缩上报）⇒ 改类名无效。

详见 `专题/2026-10-24-数美封控SDK逆向-2.7.1.md`。
