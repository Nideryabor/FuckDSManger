## 三、⭐ 关键发现：宿主自带同构组件（复用而非重写）

主人提示的「文件/图片上传后的快捷回复」＝ **`PromptTemplateView`**，与我们要的东西**同构**（一排按钮 → 点击即发消息）。

| 项 | 值 |
|---|---|
| data class | **`Lg56;`** = `com.deepseek.chat.settings.ModelConfig.PromptTemplate{ int a=id; String b=scene; String c=content; Integer d=resId }` |
| 序列化器 | `Lb56;`（字段名 `id` / `scene` / `content`），`Ld56;` = 内嵌 `Scene`，`Lf56;` = Scene 的 value class |
| 默认模板 | `Lm66;<clinit>`（`image` / `file` 两套场景的硬编码默认值） |
| 单按钮 | `Lyb5;->c(Lg56;…)` |
| **列表行** | **`Lyb5;->f(List;…)`** ← 我们 hook 的点 |
| 外层容器 | `Lyb5;->e(Leb6;List;…)` |
| 中转 lambda | `Lz97;`（`PromptTemplateView.kt:163`） |
| 内层 lambda | `Lca7;`（`PromptTemplateView.kt:185`） |
| 点击去抖 | `rememberDebouncedPromptClick (PromptTemplateView.kt:263)`（500ms） |
| 输入区调用方 | `Lnb5;->c(…)` 第 1595 行调用 `Lyb5;->e(...)` |
| 文案解析 | **`Lpd5;->I(g56, Context)`**：`d != null` ⇒ `context.getString(d)`；**`d == null` ⇒ 直接返回 `c`（content）** |
| 埋点 | 点击时上报 `guide_prompt_show`（`chat_session_id` / `model_type` / `file_source` / `guide_prompt_id` / `guide_prompt_text` / `rank`） |

> Compose 源码路径直接留在 dex 字符串里（`PromptTemplateViewImpl (PromptTemplateView.kt:185)`）——**这是本轮能一眼定位的最大功臣**。

### 3.1 复用方式（本方案的灵魂）

hook `Lyb5;->f` 的 `args[0]`（`List<PromptTemplate>`）：

- 宿主传**空列表**（没附件时）⇒ **换成我们的建议列表** ⇒ 宿主用自己的样式/位置/点击链路把我们的按钮画出来；
- 宿主传**非空列表**（真的传了图片/文件）⇒ **原样放行**，不打扰原功能。

按钮写什么、点了发什么，全由 `content` 字段决定（`pd5.I` 已实证）⇒ **点击即发消息＝宿主原生行为**。

### 3.2 构造 `PromptTemplate` 的正确姿势

```smali
new-instance v0, Lg56;
const/4 v1, 0x7                 # Kotlin 默认参数位掩码，必须 (mask & 7) == 7
const/16 v2, 0x2329             # id（避开宿主内置 9/10/11/13/14/15）
const-string v3, "default"      # scene（pd5.I 不用它，显示层也不看）
const-string v4, "能再展开讲讲吗？"   # content = 按钮文案 = 点一下发出去的文字
invoke-direct {v0, v1, v2, v3, v4}, Lg56;-><init>(IILjava/lang/String;Ljava/lang/String;)V
```

> ⚠️ 公开构造器 `(ILjava/lang/Integer;Ljava/lang/String;)V` 会把 **`c`（content）写成空串**，只有 `d` 走 resId 那条路 —— **不能用它**。

## 十、探针第 4 轮（2.10.3-probe · 2026-09-18）：对照实验

第 3 轮「屏幕 Toast 自检」结果：主人反馈 **一个 Toast 都没有**。

但"零 Toast"有两种完全不同的含义 —— 必须先把它们分开，否则会一直瞎猜：

| 可能 | 含义 |
|---|---|
| A | 那 4 个方法**真的没被调用**（输入区不是 `nb5` / 渲染链没走到） |
| B | **Toast 机制本身没生效**（模块没加载 / `GmUtil.app()` 拿到 null / Toast 被系统拦） |

⇒ 加两个**必定会被调用**的对照点，用来判定 A 还是 B：

| 对照点 | 预期 | 意义 |
|---|---|---|
| `MainActivity.onResume` | 打开 App 就弹 `[建议] 命中 MainActivity.onResume` | 证明 **模块已加载 + Toast 能弹** |
| `h91.a`（消息列表组合函数，防撤回用的那个锚点） | 进会话就弹 `[建议] 命中 h91.a` | 证明 **人确实在聊天页 + 该锚点在 2.5.2 有效** |

Toast 文案升级为 `[建议] 命中 <简单类名>.<方法名>（已注入 3 条）`，避免 `a`/`c` 这种名字看不出是谁。

## 三十二、🔧 第 24 轮（2.10.23-probe）：修掉 VerifyError（varargs 误用）

2.10.22 真机：❌ 探针 / bar / 原生建议**全都没了**，日志里 `hookM FAIL` ×N。

### 32.1 ★ 决定性证据（主人完整日志）

```
hookM FAIL yb5.f | java.lang.VerifyError: Verifier rejected class ...GmSuggestHook:
  void ...prompt(MethodHookParam) failed to verify:
  [0x32] register v4 has type Precise Reference: java.lang.Boolean
          but expected Reference: java.lang.Object[]
```

### 32.2 根因：smali 里 varargs **不能展开传**

```smali
; ✗ 错误（Java 思维）
invoke-static {v3, v5, v4}, XposedHelpers;->callMethod(Ljava/lang/Object;Ljava/lang/String;[Ljava/lang/Object;)
;                        ↑ Boolean，但签名要的是 Object[]

; ✓ 正确：自己 new-array
const/4 v4, 0x1
new-array v4, v4, [Ljava/lang/Object;
const/4 v5, 0x0
sget-object v6, Ljava/lang/Boolean;->TRUE:Ljava/lang/Boolean;
aput-object v6, v4, v5
invoke-static {v3, v5, v4}, XposedHelpers;->callMethod(...)
```

⇒ 顺带解开 **2.10.21 `hookM FAIL yb5.e` 之谜**（`GmPromptHook` 同一个错）。

### 32.3 ⚠️ 后果为什么这么严重

**一个方法 VerifyError ⇒ 整个类被 verifier 拒绝 ⇒ 该类上注册的所有 hook 全部失效。**
