## 一、三个同名脚本，只有一个是「启动」用的

| 你以为的 | 它在哪 | 干什么 | 结论 |
|---|---|---|---|
| ❌ `tools/frida/frida.sh` | 工作区 | frida-server 那条**老路**（端口式，`-H 127.0.0.1:27042`） | **本机必失败** —— 它起服务走的是 *adb 的 su*，写不进 `/data/local/tmp`（frida 的 helper dex 路径写死在那儿）⇒ attach 一定挂 |
| ❌ `tools/frida/frida-device.sh` | 工作区 | 起 **frida-server**（老路，手机端真 su 版） | 能起来，但**不是现在用的通道** |
| ✅ **`/data/adb/frida/frida.sh`** | **设备 root 目录**（`root:root 0700`） | **白名单网关的【起停】**（定向注入） | ✅ **就是这个** |

> **一句话记法**：
> - **我（尼尼）** 只干两件事：**投 job** → **读 result.txt**
> - **主人** 只干一件事：**起 `frida.sh` 窗口**

## 二、主人这边（手机终端 / 真 su）

```sh
su -c 'sh /data/adb/frida/frida.sh'        # 起窗口（后台，30 分钟自动退）★ 默认
su -c 'sh /data/adb/frida/frida.sh -f'     # 起窗口（前台，能看进度）
su -c 'sh /data/adb/frida/frida.sh -s'     # 看状态
su -c 'sh /data/adb/frida/frida.sh -k'     # 停掉
```

⚠️ **必须用「真 su」**（手机终端 App 里的 su），**不能经 adb**。
原因：frida 的 Java 桥要往 `/data/local/tmp` 写 helper dex，**那条路径写死、`TMPDIR` 改不动**；
而这台机器上「真 su 写得进、adb 的 su 写不进」。

⚠️ 它必须在 `/data/adb/frida/` 里跑 —— 脚本自带保护：
如果它被放在别处执行会**直接拒绝并报错**（否则等于"让尼尼能改的脚本以 root 跑"，
整个白名单设计当场作废）。

## 三、我这边（尼尼）

### ① 投任务 → `/data/local/tmp/frida_job.txt`

格式（**脚本正文内联**，v3 起不支持 `script=<路径>`，那是故意的）：

```
id=<任务名，自己起>
target=com.deepseek.chat.a
---
<JS 正文，随便多少行>
```

写不进去时的办法（我的 rootfs 隔离，看不到设备的 `/data/local/tmp`）：

```sh
B64=$(base64 -w0 /tmp/job.txt)
sh tools/出笼隧道/adb.sh shell "printf '%s' '$B64' | base64 -d > /data/local/tmp/frida_job.txt"
```

### ② 读结果 → `/data/local/tmp/frida_out/result.txt`

```sh
sh tools/出笼隧道/adb.sh shell 'grep -q "^job=<任务名>$" /data/local/tmp/frida_out/result.txt && cat /data/local/tmp/frida_out/result.txt'
```

结果文件长这样：

```
job=<任务名>
status=ok
target=com.deepseek.chat.a
pid=27904
note=rc=124            ← timeout 到点（脚本里有长驻 hook 时常见）
time=2026-10-02 00:45:56
--- output ---
<你的 console.log / send() 输出>
```

## 四、为什么是这套（而不是端口式）

| 尼尼想绕过 | 结果 |
|---|---|
| 扫端口直连 | ❌ **没有端口**（用的是 `frida-inject`，跑完就退） |
| 读命令行拿 token | ❌ 没有常驻服务、没有秘密 |
| 改白名单 / 改网关 | ❌ `/data/adb/frida/` 是 `root:root 0700` |
| 让网关挂别的 App | ❌ 白名单逐字拦 |
| `-f` spawn 别的 App | ❌ 网关**只用 `-p`，永不 `-f`** |

> **`-p` 而不是 `-f` 是保命条款**：2026-10-01 那次「frida spawn 污染 zygote」
> 把系统设置和支付宝都搞成"一开就崩"，adb 修不回来，只有 `stop; start` 才恢复。
> 详见 `专题/事故-2026-10-01-frida污染zygote.md`。

## 五、还有两条硬规则（血的）

1. **attach 之前先看目标冻没冻**（安卓 15 的应用冻结）：
   ```sh
   adb shell 'dumpsys activity processes | grep -A3 "processName=<包名>" | grep isFrozen'
   ```
   冻了就**把它拉到前台**（`monkey -p <包名> -c android.intent.category.LAUNCHER 1`），
   **别去 `am unfreeze`** —— attach 超时那一刻注入已经开始了一半，再解冻它就崩。
2. **超时了就别再折腾那个进程**：`am force-stop` 重开，回到干净状态。
