## 二、为什么这么难查

全部是**静默失效**：

- `hookAllMethods` 返回 `count=1` → 看着挂上了，但**挂到了不存在/别的方法**
- 异常被 `catchall` 吞掉 → 日志里只有一行「没找到」
- 拿到的对象类型不对 → 只在**真正调用时**才抛 `IllegalArgumentException`，而且一眼看不出是哪个参数

**判据**：不要看「挂上了」，要看**每个功能自己的自检行**是否出现
（`画底原语已挂 x98->t` 这种就骗人 —— 它只是说「字符串拼出来了」）。

## 三、正确姿势

```java
// ❌ 错
private static final String CLS_X = "t82";
// ✅ 对
private static String CLS_X() { return GmRemap.cls("shapeholder"); }
```

**为什么要用「语义键」而不是直接用 2.7.2 的原名当键**：

2.7.5 里 `zi0` / `vcc` / `t82` / `a6` 这些短名**全被复用**（同名诈尸）：
- `cls("zi0")` → 2.7.5 的 `zi0` 是背景 Element（不是绘制节点）
- `cls("vcc")` → 2.7.5 的 `vcc` 是气泡单元碎片（不是 clip 所在类）
- `cls("a6")` → 2.7.5 的 `a6` 是 `a:I+b:String`（不是头像桶）

⇒ 用我们自己的语义键（`nod` / `clipmod` / `shapeholder` / `assistcell`…），一个锚点一条，永不歧义。

## 四、定位方法（本轮验证有效的顺序）

1. **SourceInfo 串**（`File.kt:行号`）—— 最准，行号常跨版本不变
2. **行数 + 字段数**（无 SourceInfo 时）
   - `t82`(35 字段) → `y82`(35 字段)
   - `a6`(1045 行) → `b6`(1045 行)
   - `kc5`(695 行) → `oc5`(695 行，连方法行号 20/63/104/695 都一致)
3. **方法体逐行 diff** —— 最强证据
   - `a6.v` vs `b6.w`：`.registers` / `iget` / `packed-switch` 标签名全同，只差 `Lzda;→Liea;`
4. **全树唯一串**（`tools/fp_index.py` 挑）+ **`toString()` 里的字面量**
   - `kc5` 与 `oc5` 的 `toString()` 都返回 `"RectangleShape"`
5. **frida 实时确认** —— 最后用，别一开始就用

## 六、另一个独立事故：`.registers` 加错把参数槽覆盖了

```smali
.method protected beforeHookedMethod(Lde/robv/android/xposed/XC_MethodHook$MethodHookParam;)V
    .registers 8      ← 只有 1 个参数 ⇒ 可用 v0~v6，p0 = v7
```

我为了加诊断把 `.registers` 改成 **12** 并用了 `v8/v9/v10`
⇒ `v10` 被汇编器映射成 **`p0`**，**覆盖了参数引用** ⇒ 整个 hook 崩
⇒ 连带宿主的聊天背景也坏了（主人：「背景变黑/白/没了」）。

**铁律**：往 smali 方法里加寄存器前，先算 `p` 的起始位置 = `registers - 参数个数(含 this)`。
