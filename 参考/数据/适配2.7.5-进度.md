## 一、三个 bug 的根因（全部找到）

### BUG A · 模块入口「被吃掉」
**真凶有两个，不是一个：**

① **`method()` 表查坏了**（我自己 3.75.0 引入的）
   - 我把 MTH 的键匹配写成「前 N-2 列」，但 MTH 行是 **「3 个键列 + 每代一对(类,方法)」**
   - ⇒ `method()` 恒返回旧名、`methodOwner()` 恒 null ⇒ **整张方法表等于没生效**
   - 已修：改成按「键列含 `.`」这个形状识别（`isKey()`）
   - 回归测试：`tools/remap_selftest.py`（12 条语义抽查 + 列数一致性 + GONE 安全失败）

② **case 号写死错**（跨了 5 个版本没人发现）
   - `GmEntryHook` 认的是 `const/16 v2, 0x1d`
   - 但 2.7.5 的 `z5.w` packed-switch 表**只到 #0x1c** ⇒ `0x1d` 根本不在表里 ⇒ 条件永不成立
   - 「检查更新」真正的 case = **#0x14**（唯一 `return Boolean.TRUE` 的特例）
   - 交叉验证：2.7.2 的 `y5.v` 里同一个 `:pswitch_65` 也是 `return Boolean.TRUE` ⇒ 跨版本稳定
   - 已修为 `0x14`

### BUG C · 提示词注入失败 ✅ 已修
- 请求体真身 = **`qy1`**（`Companion:Lpy1;` + 12 实例字段）
- 构造器 **12 参**（比 2.7.2 的 `ly1` 多一个 String，插在 index 9）
- 已改用「多版签名并存 + 结构兜底」：`CTOR_SIGS[]` 逐个试，再 `findCtorStructural()`
- **devlog 铁证**：`hookM sysprompt count=1 cls=qy1 ctor=12参(String,Integer,String,ArrayList,boolean,boolean,String,boolean,String,String,St…`

### BUG B · 文案跑到账户页 ⚠️ 修了但待验证
- 旧写法写死 `0x7f0f0263` → 2.7.5 那是 **`profile_account_security_section_header`（账户页「安全」小标题）**
  ⇒ 模块名被贴到账户页（主人截图症状）

## 二、native / 反欺诈：零变化（定案）

用 **GNU build-id** 判，不是看大小：

| so | 2.7.2 build-id | 2.7.5 | 结论 |
|---|---|---|---|
| `libsmsdk.so` | `e5bc1dca…446fd7cf` | **同** | 逐字节相同 |
| `libEncryptorP.so` | `38c51b83…68d817b4` | **同** | 逐字节相同 |
| `libmmkv.so` | `16915673…f5c01d46` | **同** | 逐字节相同 |

16 个 so 大小逐条一致；数美 193 类、`xpApp` 采集链（`/proc/self/maps` + `/data/app/` + `xposedmodule`）、
SDK 版本串 `3.14.3` 全部未变。

**数美 so 的能力面**（83 个 import）：`syscall`（直调，绕 libc hook）· `popen` · `access/lstat/opendir`
· `__system_property_get` · `mprotect/mmap` · `clock_gettime` · `regcomp/regexec`
⇒ **想 hook native `open/read` 拦 `/proc/self/maps` 不可靠**；正确路子是 hook Java 层读完之后的字符串。

## 三、Compose 注入路线的结论（重要，别再试）

**「先编 Compose 再注入 dex」走不通。**
- 宿主 APK 里 `androidx/compose/runtime/Composer` **一个类都没有**（`dex_classes` 查询 0 命中）
- 全部被 R8 混淆内联：`Composer→v15`、`Modifier→fk7`、`Brush→ks0`、`Shape→yy9`、`Painter→q88`
- ⇒ 用 Compose 编译器编出来的 `$composer: Composer` 参数类型是 `Landroidx/compose/runtime/Composer;`，
  和宿主要的 `Lv15;` 对不上 ⇒ `NoSuchMethodError` / 崩

**能走的替代**：劫 `DrawScope`/自己画 Canvas（`GmGlassSink` 那套）、复用宿主现成的行（B）、
或悬浮 View。
