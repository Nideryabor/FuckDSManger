## 六、关键技术备忘（踩坑记录）

> §6.1 / §6.2 是**手写 smali 时代**的规范，代码形态已变，但**同类 bug 家族仍然存在**（如 `if-*z` 极性）。

### 6.1 Smali 手写规范（历史，但教训通用）

| 坑 | 教训 |
|---|---|
| **寄存器越界** | 涉及 `J`/`D` 宽类型时，末尾寄存器编号必须 `< .registers 总数` ⇒ 否则**整个类被 verifier 拒绝**，调用即崩 |
| **`if-nez` vs `if-eqz`** | `if-nez` = 「!=0 跳」；`if-eqz` = 「==0 跳」。本项目**累计 20+ 次反向判断 bug**，是头号 bug 家族 |
| **`insert_before_match` 陷阱** | 插入整段方法会 `missing END_METHOD_DIRECTIVE` ⇒ 改用 `replace_match` 带上原方法头 |
| **类加载时机** | 在 hook 回调外引用某类静态字段会**强制加载该类**，有校验问题就当场崩 ⇒ 静态标记位放「已知可用」的类 |

### 6.2 Xposed / Hook 经验

| 坑 | 教训 |
|---|---|
| **hook 挂父类无效** | 会被子类重写覆盖 ⇒ 挂到**实际调用链上的那一层** |
| **`requestCode` 不可靠** | 现代 App 用 `ActivityResultRegistry` 重映射 ⇒ 用**自定义标记位** |
| **上下文时序** | 启动早期 `Activity` 还不存在 ⇒ 用 `AndroidAppHelper.currentApplication()` |
| **hook 在 try/catch 里会静默失败** | 需加**命中计数器**做可视化诊断 |
| **节流必做** | 渲染类 Composable 调用极频繁，hook 里做 IO 必须加时间节流 |
| **⭐ 名字被复用 > 名字变了** | `findClass` 会**成功**但结构不对 ⇒ 必须做**结构自检**（3.49.0 教训） |
| **⭐ `am force-stop` 不一定是真停** | 装完必须**验进程号变了没**（3.47.4 反复翻车） |
| **⭐ 高频方法也能挂钩** | 只要「只赋值」就很便宜（3.50.4 靠 hook `gh2.W()` 选对会话） |

### 6.3 DeepSeek 逆向情报（关键项）

| 项 | 值 |
|---|---|
| 灰度本地键 | `kv_settings_*` |
| 灰度远程键 | `kv_remote_settings_*` / `kv_remote_settings_id_*` |
| 下发数据对象 | 一个 `Map` 实现，字段里装着服务端下发的全部设置项 |
| DS Settings 埋点 | `ds_settings_scope` / `ds_settings_version` / `ds_setting_ids` / `ds_settings_exposure` |
| 助手头像资源 | `assistant_message_avatar` = `0x7f070059` |
| 「检查更新」资源 | `profile_check_for_updates` = `0x7f0f0217` |
| 成品富文本唯一汇流点 | `fz2.p(...)`（全树仅 3 处调用）⇒ 富文本只挂这一个点 |
| HTML 渲染起点 | `MermaidGeneratorWebView`（**内联用的是 Generator，不是 Viewer**） |
| 发送入口 | `gh2.h0(gh2, 文本, [], [], "", m1a, ns, false,false,false,false)` —— **`p6=ns` 指定会话** |
| MMKV 类型方法 | `b(String)Z`=bool、`f(String)I`=int、`i(String)String`=string、`d(String,F)F`=float |
| **MMKV 三坑** | ① **懒加载**：先 `allKeys()` 再 `getAll()`，否则空 Map ② `read2` 第三参是**类型** ③ 类型不符会**静默读回默认值** |
