## 一、真机报错（用户提供，LSPosed 日志）

```
E/LSPosedFramework java.lang.VerifyError: Verifier rejected class
  com.varuns2002.disable_flag_secure.gm.GmEnv:
  void GmEnv.setApi(Context, boolean) failed to verify:
    [0xD] register v2 has type Precise Reference: java.lang.String
          but expected Reference: android.content.Context
  void GmEnv.setOn(Context, boolean) failed to verify: 同上
    at DisableFlagSecure.handleLoadPackage(Unknown Source:38)
```

## 二、根因（**又是「参数寄存器被当局部变量」**）

```smali
.method public static setOn(Landroid/content/Context;Z)V
    .registers 4          ← 2 个参数 ⇒ 局部只有 v0、v1；p0 = v2
    ...
    const-string v2, "b"  ← ⚠️ 把 p0(Context) 压成了 String
    invoke-static {p0, v1, v0, v2}, GmStore;->write(...)V
```

**这是 2.9.2 崩 `GmStore.remove` 的同一个坑（总结 16.2 / 46.6）。**
本轮我把那条教训读过了、写进过总结，**还是又踩了一次**。
⇒ 规则要升级成硬性检查：**每个手写方法先算「局部寄存器上限 = .registers − 参数槽数」，再逐个核对用到的寄存器编号。**

## 三、连锁后果（为什么两个症状是同一个 bug）

`GmEnv` 整类没通过校验 ⇒ 该类**无法加载** ⇒
`GmEnv.install()` 第一次被调用时抛 `VerifyError` ⇒
LSPosed 对该异常的 `handleLoadPackage` 是**整体 try/catch**：异常被吃掉，
但**同一次调用里后面的代码全部不执行** ⇒

1. 「环境伪装」的 hook **一个都没装上**（`install()` 没跑）
   ⇒ 用户看到的「反检测无效」**不是 Java 层打不过 native，而是功能压根没运行**
2. 其后所有模块核心 hook（`GmResTextHook` 偷换入口 / `GmClickHook` / `GmTouchHook` /
   `GmPainterHook` / `GmVectorHook` / `GmResumeHook` / 防撤回 / 头像…）**全部没注册**
   ⇒ 用户看到的「插件是注入了相当于没注入，啥都没有」
