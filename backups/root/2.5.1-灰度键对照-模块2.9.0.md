## 三、✅ 「朗读文本」待办闭环 —— 本条是本次最大收获

`FuckDSManger-项目总结.md` 第五节待办 #3 / 第九节建议 #2 记着：

> **「朗读文本」灰度缺失** —— 用户在某处看到该灰度名，APK 里搜不到（`朗读`/`tts`/`speak`/`aloud` **全零命中**）

**2.5.1 里它落地了**，证据三件套：

1. **dex**：7 个 `kv_remote_settings_tts_*` 键（见上表），getter 在 `Lh02;->c..i`，本地镜像键 `kv_settings_tts_*`
2. **资源**（`resource_table_values` 搜「朗读」，13 条）：

| 资源 id | 名称 | 文案 |
|---|---|---|
| `0x7f0f0057` | `auto_read_aloud` | 自动朗读 |
| `0x7f0f024e` | `read_aloud_start_label` | 朗读 |
| `0x7f0f024f` | `read_aloud_stop_label` | 停止朗读 |
| `0x7f0f0252` | `reading_aloud` | 正在朗读 |
| `0x7f0f0245` | `read_aloud_daily_limit_reached_toast` | 朗读已达今日限额，请稍后再试 |
| `0x7f0f0248` | `read_aloud_language_not_supported_switch_voice_toast` | 当前语言暂不支持朗读，可尝试切换音色 |
| `0x7f0f0358` | `tts_voice_switched_toast` | 朗读音色已切换为 %1$s |
| `0x7f0f0385` | `voice_switch_bottom_sheet_title` | 朗读音色 |

3. **写入口**：`MMKV.n(ILjava/lang/String;)V`（= putInt），下发应用点 `Lh02.u` 内，
   值键 `kv_remote_settings_tts_*` + id 键 `kv_remote_settings_id_tts_*`，与其它 i 型键同型。

> 结论：**「朗读」是 2.5.1 的新灰度功能，模块现在完全没纳管**（既不能在管理器里改，
> 也不在 `GmMmkvHook` 的拦截/重应用名单里）。

## 四、模块侧现状核对

- `GmDialog;-><clinit>`：`const/16 v0, 0x46` → **KEYS/NAMES/TYPES 各 70 项**（0x00~0x45）
  - `DESCS` 是**一整条以 `\n` 拼接的长字符串**（70 行文案），最后 `split("\n")`
- 70 项里有 9 项不在 main 域：`voice_input_enabled` / `input_default_voice` /
  `input_view_voice_gesture_duration_ms` / `record_empty_detect_time_ms` / `record_stop_delay_ms` /
  `max_duration_ms` / `opus_bitrate`（语音域）、`model_configs_v1` / `image_cache_invalidate_before`（model 域）
- main 域 70 项里有 9 项模块没有：上表 A 的 8 项 + `thinking_auto_fold_enabled`
  → 70 − 9 + 9 = 70 ✅ 对得上

**另外**：`welcome_msg` 不在 KEYS 里，但模块早有 `GmHello`（2.4.3）单独管它，
`GmMmkvHook`（2.4.8）也拦了它和 `model_configs_v1` —— 这两个不算漏。
