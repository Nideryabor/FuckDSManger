# 方案A 最后一公里（2026-09-25 记录）

## 现状
`androidx.customview.poolingcontainer.PoolingContainer.<clinit>` 需要
`androidx.customview.poolingcontainer.R$id`（两个 int：is_pooling_container_tag /
pooling_container_listener_holder_tag，只作 View.setTag 的整数键用，不必是资源 ID）。

已证明的三件事：
1. 手写 R.java **能编出** R$id.class（D8 单独打 dex 时验证过：两个字段都在 ✓）
2. 但 **R8 会把这个内部类吃掉**（即便写了 `-keep ...R$id { *; }`）—— dex 里只剩 R.class，R$id 不见
3. **把 pc.dex 追加进 D8 合并时又失败**：因为 dexQ 里已有一个空的
   `androidx.customview.poolingcontainer.R`，与 pc.dex 里的 R 冲突（duplicate class）

## 下一步（已缩小到一条命令的改动）
打包 pc_classes.jar 时 **只放 R$id.class，不放 R.class**：

    rm -rf work/pc_only && mkdir -p work/pc_only/androidx/customview/poolingcontainer
    cp work/pc_classes/androidx/customview/poolingcontainer/R\$id.class work/pc_only/androidx/customview/poolingcontainer/
    jar cf work/pc_only.jar -C work/pc_only .
    # 然后 D8 pc_only.jar → pc.dex；再 D8 合并 (mod122 + dexQ + pc.dex)

若 D8 仍报重复（R$id 可能也在 dexQ 里被半保留），改用
`d8 --classpath`/或先 `zipalign` 无关 —— 更稳的做法是**在 R8 之前把 pc_classes.jar
从输入里去掉**（让 R8 完全不碰它），最后只由 D8 合并注入。
