## 0. 💡 思路：**"你按它，它就会重绘"**

**核心观察**：宿主是 Compose，**按下一个可交互元素时，它不会重绘整屏，而会重绘"被按住的那一小块"**（按下态 / 水波纹 / 高亮）。
⇒ **"手指按住期间画出来的那几笔" = 那个可交互元素自己** ✓✓

**⇒ 不需要猜"哪个长得像按钮" —— 直接观察"按下去的时候谁在动"。**

| 环节 | 实现 |
|---|---|
| **开窗** | `GmTouchHook`（钩着 `Activity.dispatchTouchEvent`）：**`ACTION_DOWN` ⇒ `sTouchOn = true`**；**其它任何事件（UP/MOVE/CANCEL）⇒ `sTouchOn = false`** ⇒ **窗口 = "手指按住期间"** |
| **学习** | 在 `collect()`（每次绘制都会走）里：**若 `sTouchOn` ⇒ 把该绘制的调用点记进 `sSkipList`（排除名单）**，并打日志 **`[交互排除] 学到 xxx`** |
| **生效** | `pg` 的门里：**`sSkipList.contains(caller)` ⇒ 直接 `return`（不透明化）** ⇒ **该元素保持原样** ✅ |

**⇒ 交互元素（按钮/可点项）的底色再也不会"飞走"** ✓

## 2. ⭐ 主人操作（**"教"它认出交互元素**）

1. 装 `2.22.89` → 强停 → 开 App → **进「对话列表」那一页**
2. 「调试」页**拨开捕获器** → **返回对话列表**
3. **把那些可点的东西，一个一个点一遍**（按钮、列表项、可点的卡片…）
   - 每点一下 ⇒ **模块日志里会出现一行 `[交互排除] 学到 xxx`** ⇒ **说明它学到了** ✓
   - 学到之后，那个元素的底**就不会再被透明化** ✓
4. 点完之后：**回到聊天页看看** —— 那些按钮的底应该还在 ✓，而"层"照旧透 ✓

| 观察 | 结论 |
|---|---|
| 日志里出现 `[交互排除] 学到 xxx` | ✅ 学习在跑 |
| 点过的按钮**底色保住了** | ✅ **目标达成** |
| 日志里**一行 `学到` 都没有** | ⇒ 学习没跑 ⇒ 把日志发我（我查 `sTouchOn` 那条链） |
| 学到**太多**（把不该排的也排了） | ⇒ 把日志发我，我改成"**只学按下后 200ms 内的第一笔**"或其他更紧的规则 |

> ⚠️ **前提**：学习需要**捕获器处于开启状态**（`collect` 由采集链路调用）⇒ **先拨开开关，再点**。
> ⚠️ **滚动不会误学**：手指一移动（`ACTION_MOVE`）窗口就立刻关闭 ✓ 只有"**按下去**"才开窗 ✓

## 3. 教训（219~222）

| # | 内容 |
|---|---|
| **219** | ⭐⭐⭐ **"按下窗口"是识别可交互元素的天然信号** —— Compose 的按下态/水波纹是**增量重绘** ⇒ **按住期间画出来的就是被按的那个元素**。⇒ **不要靠"外形像不像按钮"去猜，而是"你按它、它动没动"。** |
| **220** | ⭐⭐⭐ **把"人类才懂的语义"翻译成"可观测的机械信号"** —— "可点击且有功能"这个语义，被翻译成了"**按下时会重绘**"这个机械事实。⇒ **这跟本专题一路的手法同源**：调用点（身份）· 颜色（外观）· 消融（存在性）· 按下重绘（交互性）—— **每一个抽象概念都找到了一个可观测的代理量。** |
| **221** | ⭐⭐ **学习型功能必须"把学到的东西说出来"** —— 每次真正新增都打 `[交互排除] 学到 xxx`；**否则用户不知道它到底学没学到**（与教训 153「开关类功能要有正反馈痕迹」同源）。 |
| **222** | ⭐ **两套机制并存要定优先级**：消融试验台（测试用，优先）→ 排除名单（生产用）→ 白名单（生产用）⇒ 试验台永远能压过生产规则，便于随时验证。 |
