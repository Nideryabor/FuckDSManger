## 〇、一句话

3.45.0 是「把用户气泡里的 `⟦FDM⟧…⟦/FDM⟧` **删掉**」；
这一版反过来 —— **AI 回复里出现 `⟦FDM:模板名|参数⟧`，就把这一段渲染成主人配好的富文本**，
标记前后的普通文字照旧。

```
AI 回复：  今天天气不错 ⟦FDM:tip|记得带伞⟧ 出门吧
界面显示：  今天天气不错 ▸ 记得带伞 出门吧          ← ▸ 是色板6的青色，带样式
```

## 一、★ 挂点怎么找到的（全链实证，不是猜的）

宿主（2.6.1）的 markdown 渲染链：

```
AI 文本
 └─ svb.c(String)          AssistantTextItem（AssistantResponseItem.kt:167）★AI 正文项
     └─ eu6.c(…)           Markdown Composable（Markdown.kt）
         └─ v91.m(String)
             ├─ new in                        AnnotatedString.Builder
             ├─ or6.w(builder, md)            buildMarkdownAnnotatedString
             ├─ in.k() → kn                   成品 AnnotatedString
             └─ fz2.p(kn, …)                  ★★★ 挂这里
                 └─ w2b                       MarkdownBasicText → 绘制
```

**选 `fz2.p` 的理由**：thinking / 引用预览 / 分享预览各走各的入口，但**成品 AnnotatedString
的最后一道门只有它**（全树只有 3 处调用它：`v91:41098`、`nd:30242`、`o63:818`）。
挂一个点 ≈ 全覆盖。

## 二、★ 做法：借宿主自己的 Builder 重建

```
nb = new Builder()
 原文段 → nb.append(origKn, start, end)     ← ★ 样式自动跟着走
 标记段 → nb.pushStyle(style) + nb.append(text) + nb.pop()
args[0] = nb.toAnnotatedString()
```

**这一招的最大好处**：`append(orig, start, end)` 会**把该区间的样式一起搬过来**
⇒ 本来最难的「删掉标记后所有 span 的 offset 要重新映射」问题**直接消失了**，一行都不用写。

**同时**：原文里 AI 已经写好的 markdown 样式（粗体/链接/引用/公式）全部原封不动。

## 三、★ 四种关键 API 的语义（全部 smali 实证，不是推断）

| 混淆 | 真身 | 实证证据 |
|---|---|---|
| `kn` | `AnnotatedString` | implements CharSequence；字段 `a:List`=spans、`b:String`=text；`d(II)Lkn;`=subSequence |
| `jn` | `AnnotatedString.Range` | 字段 `a`=item、`b`=start、`c`=end、**`d:String`=tag**（4 字段版） |
| `hn` | Builder 内部 `MutableRange` | `pushStyle` 拿它入栈，`toAnnotatedString` 时 `hn.a(I)Ljn;` 转回 Range |
| **`in`** | **`AnnotatedString.Builder`** | 字段 `a:StringBuilder`(文本)、`b:ArrayList`(push 栈)、`c:ArrayList`(spans) |
| **`f0a`** | **`SpanStyle`** | toString `"SpanStyle(color="`；15 个字段 |
| **`gx2`** | **`ColorKt`** | `d(J)F`=red（`usr 56`）；`gx2.h:J`=`Color.Unspecified`（在 SpanStyle 构造器里当默认值！）|
| `ko4` | `FontWeight` | clinit 里 new 出 100/200/…/900 |
| `io4` | `FontStyle` | 字段 `a:I`；无静态实例 ⇒ 自己 `new io4(0/1)` |
| `dia` | `TextDecoration` | 静态 `b`=None / `c`=Underline / `d`=LineThrough |

### 四个 Builder 方法逐个验过

| 混淆 | 真身 | 反汇编看到的 |
|---|---|---|
| `c(Lkn;II)V` | **append(AnnotatedString, start, end)** | `StringBuilder.append(sub.b, s, e)` + `pn.a(sub,s,e,buf)` 取区间 spans → 存进 `in.c` ✓ |
| `j(Lf0a;)I` | **pushStyle(SpanStyle)** | 用当前位置造 `hn`(MutableRange) → `b.add` + `c.add` → 返回 `size-1` ✓ |
| `f()V` | **pop()** | 空栈抛异常 → `b.remove(size-1)`（弹出栈顶）✓ |
| `k()Lkn;` | **toAnnotatedString()** | `buf.toString()` + 把 `c` 里每个 `hn` 转 `jn` → `new kn(text, spans)` ✓ |

### mask 语义（这条最关键，也是实证的）

`SpanStyle` 的 15 参构造器：
```smali
.method public constructor <init>(JJLko4;Lio4;Ljo4;Lxm4;Ljava/lang/String;JLoj0;Lgka;Lyl6;JLdia;Lbn9;I)V
    and-int/lit8 v1, v0, 0x1          # mask & bit0 → color
    if-eqz v1, :cond_9
        sget-wide v1, Lgx2;->h:J      # ★ 置位 ⇒ 用 Color.Unspecified
        goto :goto_b
    :cond_9
        move-wide/from16 v1, p1       # 否则用传入的 color
```
⇒ **`bit N 置位 = 第 N 个参数取默认值`**，位序 0=color / 1=fontSize / 2=fontWeight /
3=fontStyle / 4=fontSynthesis / 5=fontFamily / 6=fontFeatureSettings / 7=letterSpacing /
8=baselineShift / 9=textGeometricTransform / 10=localeList / 11=background /
12=textDecoration / 13=shadow。

**⇒ 只设关心的字段，其余 mask 全置 1，传 `null`/`0L` 完全安全**（那些参数压根不会被读）。

### Color 编码（实证）

```smali
.method public static final d(J)F      # Color.red
    and-long/2addr v0, 0x3f            # 低 6 位 = colorSpace id（sRGB=0）
    ushr-long/2addr p0, 0x38           # >>> 56
    and-long/2addr p0, 0xff
```
⇒ **`packed = argb.toLong() shl 32`**

## 四、功能规格

### 4.1 标记

```
⟦FDM:模板名⟧                  无参
⟦FDM:模板名|参数1|参数2⟧      带参（模板里 {1} {2} 被替换）
```

> 定界符刻意与系统提示词那条（`⟦FDM⟧`）**不同前缀**：
> `⟦FDM:xxx⟧` 不含子串 `⟦FDM⟧`，反之亦然 ⇒ 两边判定互不干扰。

**流式容错**：没闭合的标记（AI 正打到一半）**整条忽略**，绝不吃半截进去。

### 4.2 模板 = HTML 子集

| 标签 | 效果 |
|---|---|
| `<b>` `<strong>` | 粗体（FontWeight 700） |
| `<i>` `<em>` | 斜体 |
| `<u>` | 下划线 |
| `<s>` `<del>` `<strike>` | 删除线 |
| `<c1>`…`<c9>` | 色板色（UI 里 9 个颜色可选） |
| `<c#FF0000>` / `<c#F00>` | 直接指定前景色（3/6/8 位都认） |
| `<bg1>`…`<bg9>` / `<bg#FFFF00>` | 背景高亮 |
| `<br>` | 换行 |
| 嵌套 | 支持（Builder 的 pushStyle 自动合并） |
| 不认识的标签 | **整段丢掉**，不会漏出尖括号 |

### 4.3 模板池（存储）

键 `fuckds_rich_tpls`，**每行一条：`名字|HTML`**，`#` 开头当注释。

```
demo|<b>✦ {1}</b> {2}
tip|<c6>▸ {1}</c>
warn|<bg3><c#000000> ⚠ {1} </c></bg>
card|<c7>┌ {1}</c><br><c7>└</c> {2}
```

> 为什么做成"一个池"而不是"每模板一个键"：UI 只要一个多行文本框
> （跟「回复建议」「文件快捷选项」一个路子），主人想加就加、想删就删。
> 代价：模板里不能带真换行，换行用 `<br>`。

**★ 池是空的 ⇒ 自动用开箱示例模板**（装机即能用，方便一眼验证链路通没通）。

### 4.4 配置键

| 键 | 类型 | 说明 |
|---|---|---|
| `fuckds_rich_on` | b | 总开关（默认关） |
| `fuckds_rich_tpls` | s | 模板池 |
| `fuckds_rich_c1`…`c9` | i | 色板（ARGB int，与 UI 的 `K.CO` 一致） |

> ⚠️ `GmStore.read2/write` 第三参是**类型**不是默认值（教训 906 的兄弟）。
> 走 UI 的 `cfg_put` 时，我们自己的键不在 `dispatch`/`uiSet`/`dispatchText` 任何一张表里
> ⇒ 落到 `GmStore.write` ⇒ **与 `GmRichText` 的读法是同一个存储** ✓

### 4.5 UI

「聊天 › AI 气泡富文本 ›」

- 两条 K.INFO 写清用法和标签；
- 开关 + 模板池（多行文本）；
- **① 把格式约定写进系统提示词**（`rich_spec`，幂等）——
  模型不会凭空知道这套标记，不告诉它它就永远只吐普通 markdown ⇒ 这功能看上去"没效果"；
- **② 灌入开箱示例模板**（`rich_demo`）；
- 色板 1–9（`K.CO`）。

## 五、⚠️ 已知边界 / 风险

| # | 项 | 说明 |
|---|---|---|
| 1 | **只在 markdown 段落里生效** | 代码块/表格单元格走别的 Composable，不经 `fz2.p` ⇒ 标记在那儿不渲染（其实更合理） |
| 2 | **`Text` 的 `changed` 跳过** | `fz2.p` 是 @Composable，若 Compose 判定参数没变会 skip；但我们的映射是确定性的（同输入同输出）⇒ 显示不会错 |
| 3 | 混淆名随宿主升级变 | 集中候选名 + **结构自检**；不过就整条不启用并回报日志（宁可不干活，也不咬宿主） |
| 4 | 首次命中未在真机验过 | `richHook.hit` 日志一次就能钉死；`FdmEntry` 里已打 `GmRichTextHook.status()` 回报自检结论 |
| 5 | 参数不转义 | 参数里带 `<` 会被当标签解析 —— 这**既是 feature 也是坑**，先留着 |

## 七、主人验收步骤

1. 装包 → **强停宿主** → 重开（⚠️ `install -r` 后宿主侧代码会滞后一版，见 3.45.0 §六）
2. logcat 搜 `richText`：
   - `richText 自检 OK：自检全过（kn/in/f0a/ko4/io4/dia）` ⇒ 锚点全对
   - `hookM richText count=1 cls=fz2.p …` ⇒ 钩子挂上了
   - 若是 `hookM FAIL richText → …` ⇒ 把那一行发我，我按它重新反查
3. 模块 → 聊天 → **AI 气泡富文本**：
   - 点 **① 把格式约定写进系统提示词**（不然模型不知道有这回事）
   - 打开「开启」开关
4. 随便找个会话，让 AI 说一句带标记的话（或在系统提示词里要求它用 `⟦FDM:tip|xxx⟧`）
5. **期望**：日志出现 `richHook.hit …`，界面上 `⟦FDM:tip|…⟧` 变成青色 `▸ …`，前后文字照旧

### 一键自测（不用等 AI）

在系统提示词里加一句：
```
每次回答的开头都固定输出：⟦FDM:tip|测试成功⟧
```
发一条消息 ⇒ 应看到青色 `▸ 测试成功`。
