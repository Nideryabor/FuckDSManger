## 一、★ 第一个问题的真因：**`fee` 字段，不是 UA**

**沙箱实测三档「客户端伪装」，结果逐字一样**：

```
═══ 伪装 = PC / Android / iPhone（三档完全相同）═══
  晴天(钢琴版)  fee=1  → ⚠️ 试听 45 秒（size = 720813）
  红色高跟鞋    fee=1  → ⚠️ 试听 30 秒（size = 481115）
  稻香          fee=8  → ✅ 完整 320k（size = 7867080）
```

**判据是 `fee`**：

| `fee` | 含义 | 匿名能拿到 |
|---|---|---|
| **1** | **VIP 独家 / 付费曲** | ❌ **只给 30–45 秒试听片段** |
| 8 | 低音质免费（高音质要 VIP） | ✅ 完整（**320k 也完整**） |
| 4 | 数字专辑 | ❌ 完全拿不到 |

⇒ 主人说的「歌不完整」= **遇到 `fee=1` 的歌**。
要拿到完整版**必须登录 + 会员**（主人那句「我还有三个小时」大概就是会员剩余时长）。

**所以「伪装成客户端」这条路是死的**（尼尼诚实汇报：三档实测无差别）。
不过库的 `osMap`/`userAgentMap` 要求 **os 与 UA 一致**，
而尼尼原来写的是 `os=pc` + `UA=iPhone`（**自相矛盾**）⇒ 顺手修正成三档一致，
并留了一个「音源伪装」开关（pc / android / iPhone），**当备用**。

**另一个更小的真因也一起修了**（3.53.0 引入）：
搜索接口的 `album` 里只有 `picId` 没有 `picUrl` ⇒ 封面永远空。
（详见 3.54.1 的 bug②。）

## 二、★ 第二个问题：`save()` 的「静默失败」

**症状**：登录时提示成功，重启模块 UI 显示"未登录"。

**真因（尼尼的错误）**：

```java
// ❌ 旧代码
public static boolean save(Context c, String musicU, ...) {
    if (c == null || musicU == null || musicU.length() == 0) return false;
    //                                                      ↑ 连日志都不打
```

**对空凭证直接 return，没有任何日志** ⇒ 症状就是"看起来成功、实际什么都没发生"，
查起来像见鬼。而 UI 侧那句「✅ 已登录」是**本地文案**，不代表宿主真的存上了。

**三处修复**：

1. **不再静默**：空凭证会明确报错并写日志
   ```
   【FdmBridge】收到登录凭证：长度=0 分段数=1
   【MusicLogin】⚠️ 保存失败：**凭证是空的** —— 多半是 Set-Cookie 里没抠到 MUSIC_U
   ```
2. **UI 不写"假成功"**：改成读**宿主的真实回执**（`last_result`）
   —— 界面上会直接显示「宿主回执：保存失败：凭证是空的」
3. **加诊断字段**（`cfg_state` 回传，界面直接看得到）：
   `宿主侧：文件：有 128B　内存：128字　上次保存：成功：凭证 128 字`

**外加一层自愈**：UI 本地也留一份凭证（键名 `music.token`，**刻意不带 `fuckds_` 前缀**
⇒ 不会被全量推给宿主、免得凭证多一处副本）；
每次打开登录页时若宿主说"未登录"而本地有凭证 ⇒ **自动补推一次**。

**另外顺手修了一个更阴的**（`post()`）：

登录接口经常先回 **302**（`Set-Cookie: MUSIC_U=…` 就在那一跳上），
而 `HttpURLConnection` **默认自动跟随重定向** ⇒ 我们只看到最终响应
⇒ **凭证抓不到**。
改成：`setInstanceFollowRedirects(false)` + **手动跟随（≤5 跳）+ 每跳累积 Set-Cookie**。

## 五、请主人配合的一步

**再登录一次**，然后看登录页上那行「宿主回执：…」：

* 若显示 **`保存失败：凭证是空的`** ⇒ 说明 **Set-Cookie 里没抠到 MUSIC_U**
  （登录接口没过 / 验证码错 / 接口变了）⇒ 尼尼接着查那一步
* 若显示 **`已保存登录态`** 而状态还是未登录 ⇒ 那是读取侧的问题 ⇒ 尼尼查 `apply()`
* 若显示 **`宿主没回执`** ⇒ 广播没到宿主 ⇒ 查那条通道

这一行会把问题**钉死在某一步**上，比继续猜快得多。

## 六、教训

**965 · ⭐⭐⭐ 静默失败是最大的敌人。**
`if (空) return false;` —— 看着是"防御性编程"，实际是**把故障藏起来**。
尼尼为此让主人白试了一轮。**凡是"用户看得见的操作"，失败必须留下痕迹**
（日志 + 回执 + 界面显示），宁可啰嗦。

**966 · ⭐⭐⭐ 界面上别写"假成功"。**
UI 那句「✅ 已登录」是**本地文案**，跟宿主真实状态毫无关系。
自己的提示不能当事实 —— **要显示就显示对方的回执**。

**967 · ⭐⭐ 用户提的"可能原因"要当真，但要用实验回答。**
主人猜"要伪装成客户端" —— 尼尼没有直接采信去大改，也没有否掉，
而是**做了三档对照实验**，结论是"三档一样，真因是 fee"。
**实验比争论快，也比"我觉得"靠谱。**

**968 · ⭐⭐ 账号的"能听多少"是由服务端策略决定的，不是我们伪装得好不好。**
`fee=1` 就是 VIP 曲；匿名只能拿片段。这不是技术能绕的（也不该绕）。
**遇到"内容不完整"先问"这是不是服务端有意为之"**，别一头扎进"怎么绕过"。
