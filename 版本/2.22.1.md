## 一、主人回执

> 「**颜色能换，但为什么圆角选项没用**」

## 二、根因（**我 UI 的一个设计错误**，不是钩子问题）

2.22.0 里，圆角按钮的 `tag` 写的是**构建对话框时算好的绝对值**：

```
tag = GmBubble.radius() ± 4        ← 对话框打开那一刻算一次，之后再也不变
```

⇒ **第一次点才动**（16 → 20，只差 4dp，肉眼几乎看不出）
⇒ **再点就是 20 → 20，等于没反应**
⇒ 手感上就是「圆角选项没用」✓

（对比：颜色能换，是因为色块的 `tag` 是**色值本身**，点哪个就是哪个，天然没有这个问题。）

## 三、修法

| # | 位置 | 改动 |
|---|---|---|
| 1 | **`GmRadiusClick`** | `tag` 语义改为 **增量**：`新值 = GmBubble.radius() + tag` ⇒ **可连点累加**；并把**新数值打进 Toast**（`"AI 气泡圆角 = 24 dp（列表划一下即可看到）"`）⇒ 一眼就能确认有没有生效 |
| 2 | `GmBeautyDialog` | 两个按钮的 tag 改成常量 **`+8` / `-8`**（不再取当前值）；按钮文案 → **「圆角 −8」「圆角 +8」** 提示步长；每档 8dp 更好看出来 |
| 3 | `GmBubbleCellHook` / manifest | 自检行 → `2.22.1`；`331/2.22.0` → **`332/2.22.1`** |

## 五、教训

| # | 要点 |
|---|---|
| **680** | ⭐⭐⭐ **「增量式」控件（± 按钮）的 tag 必须是「增量」，不能是「构建时算好的绝对值」** —— 否则**只有第一下有效**，之后阈值不变 = 永不响应。**凡是「基于当前值的下一个值」，都要在点击时刻现取当前值。** |
| **681** | ⭐⭐ **给我自己一个「看得见的数字」**：Toast 里带上新数值 ⇒ 用户和我**都能一眼判断「是值没变」还是「值变了但渲染没跟上」**。**没有这个数字，两轮都只能猜。** |
| **682** | ⭐ **对照能换的东西定位不能换的东西**：颜色行能换（tag=色值，点谁是谁）、圆角行不能换（tag=快照值）⇒ 差异一眼锁定在「tag 的语义」。**一个功能对、一个功能不对时，先 diff 两者的实现差异。** |
