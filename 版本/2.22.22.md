# NL 2.22.22 —— 🎯🎯 选图真凶：**6 处分支极性写反**（`if-eqz` → `if-nez`）

> 产物：**`FuckDSManger_NL_2.22.22_for_ds2.5.2.apk`**（**vc353 / 117 类 / V1+V2+V3 / sha256(partial) `e690c2e5…`**）

> 关联：`专题/气泡背景可调-阶段总结.md`、`版本/2.22.2.md` ~ `版本/2.22.21.md`（其中 2.22.9~2.22.21 只在 `版本/索引.md`）

## 0. 一句话

「**选择气泡图**读不到内容」**不是权限、不是 URI 类型、不是格式、也不是发起 Activity** ——
是我自己在**读图链里把 if 写反了 6 处**：

| 位置 | 处数 | 症状 |
|---|---|---|
| `GmBubble.saveImage` 四路读图链 | **4** | 解码**成功**被当成失败 ⇒ 一路走兜底 ⇒ 最后 `return false`（图根本没落盘） |
| `GmBubble.imgBrush` 两处解码判空 | **2** | 解码**成功**却 `return null` ⇒ 图片底永远退回纯色 |

⇒ 修法就是 **`if-eqz v3, :cond_8e` → `if-nez v3, :cond_8e`**（6 处），**一个字节的逻辑改动**。

## 1. 铁证：主人日志自己把答案说出来了

主人 2.22.21 的日志（`/upload/fc13da53-…txt`）：

```
[气泡] 选中 uri = content://media/picker_get_content/0/com.android.providers.media.photopicker/media/1000020917 ｜ type=null
[气泡] openInputStream 读不出图 ⇒ 改用 loadThumbnail（Photo Picker 兜底）
[气泡] loadThumbnail 也没拿到 ⇒ 改用 ImageDecoder（现代解码 API，专治 provider URI）
[气泡] ImageDecoder 也失败 ⇒ 改用 MediaStore 直读（从 picker URI 提 id，不需临时授权）
[气泡] 连 MediaStore 缩略图都拿不到 ⇒ 确实是这张图的编码不可解
```

**关键在「这四行各自是『上一步成功』才会打印的那一句」**：

| 日志行 | 它在源码里的位置 | 打印条件 |
|---|---|---|
| 「openInputStream 读不出图」 | `decodeStream` **之后** | `decodeStream` **返回了非 null** |
| 「loadThumbnail 也没拿到」 | 第 1 次 `loadThumbnail` **之后** | 它**返回了非 null** |
| 「ImageDecoder 也失败」 | `ImageDecoder` **之后** | 它**返回了非 null** |
| 「连 MediaStore 缩略图都拿不到」 | 第 2 次 `loadThumbnail` **之后** | 它**返回了非 null** |

⇒ **四行全打 = 四路读法全都读到了图**（picker URI 一直是可读的），
紧接着 `goto :goto_ad` ⇒ **`return false`** ⇒ `PickHook` 弹「气泡图保存失败」⇒ `fuckds_bubble.png` 从不更新。

反过来，**真失败时**（某一路返回 null）才跳 `:cond_8e`，那里做的却是
`FileOutputStream` + `v3.compress(PNG, …)` ⇒ **拿 null 当 Bitmap 用** ⇒ NPE ⇒ 被 catchall 吞成
「`保存气泡图失败 | java.lang.NullPointerException`」（本次 log 里对 `documents` URI 的那条
`UnsupportedOperationException` 就是这么被兜出来的同类尾部现象）。

### `imgBrush` 是同一个反法

```
v0 = decodeFile(filesDir/fuckds_bubble.png)
if-eqz v0, :cond_62                      ← 反！解码成功不该往下走
log "[气泡] 气泡图不可用 ⇒ 改用 fuckds_bg.png"
v0 = decodeFile(filesDir/fuckds_bg.png)
if-eqz v0, :cond_62                      ← 反！第二张成功也一样
log "[气泡] 气泡图与背景图都没有可用图片 ⇒ 退回纯色"
log "[气泡] 解码失败但文件非空：不是可识别的图片格式"
return null                              ← 两张都解码成功时，它返回 null！
```

⇒ **这才是「选了图没反应 / 重启还是颜色底」的根**：即使 `saveImage` 成功过，`imgBrush` 也永远返回 null，
`wrapImg` 的 `if-eqz v3, :cond_3a` 于是退回纯色（`wrapImg` 自身极性是**对的**）。

## 2. 已证伪的旧假设（别再沿着它们想）

| 旧假设 | 现状 |
|---|---|
| 「picker URI 的临时授权不适用于我们的读取过程」 | ❌ **证伪**：四路读法全都读到了（见 §1 表格） |
| 「授权绑在发起 `startActivityForResult` 的 Activity 上」 | ❌ **对本现象不是原因**（2.22.21 的两行结论都要打星号） |
| 「照片选择器的 URI 重定向导致读不出」（`CATEGORY_OPENABLE` 那条） | ❌ **证伪**（2.22.19 已自证） |
| 「这些照片的编码不可解（HEIC/AVIF 之类）」 | ❌ **证伪**：`decodeStream` 第一步就成功了 |
| 「同一张图在『修改背景』能行 ⇒ 差别在发起方」 | ⚠️ 观察是真的，但**差别其实是「两条通道的读图函数不一样」**：`GmBg.saveImage` 是**裸流拷贝**（`read/write` 8192 字节，26 条指令，**没有分支**）⇒ 天然不受这个 bug 影响；`GmBubble.saveImage` 是**解码链**（86 条指令，4 个分支全反）⇒ 必挂 |

> 教训：主人「同一张图一好一坏」的对照实验**依然是最强信号**，只是这次它指向的不是「授权」而是
> **「两个实现的代码差异」** —— 我当时 diff 了 Intent，却**没 diff 函数体**。

## 3. 改动清单（精确）

| 目标 | 改动 |
|---|---|
| `GmBubble;->saveImage(Context,Uri)Z` | 4 处 `if-eqz v3, :cond_8e` → `if-nez v3, :cond_8e`（每处用其后紧随的**各自不同的日志行**做定位，避免歧义匹配） |
| `GmBubble;->imgBrush(ClassLoader)Object` | 2 处 `if-eqz v0, :cond_62` → `if-nez v0, :cond_62`（同上，用「气泡图不可用…」/「都没有可用图片…」两条串区分） |
| `AndroidManifest.xml` | `versionCode 352 → 353`、`versionName 2.22.21 → 2.22.22` |
| `GmBubbleCellHook.beforeHookedMethod` | 自检串 `…（模块 NL 2.22.21 生效）` → `2.22.22`（**用来确认跑的是新 dex**） |

**未改动**（有意保留）：四路读法链本身、`BufferedInputStream`、落盘前 `File.delete()`、
`fuckds_bg.png` 兜底、点选图先 `setImg(true)`、`GmBubblePickStart` 用 `GmBgDialog.act()` 发起。
那条「MediaStore 直读也失败（id 可能不在 images 集合里）」仍是死代码（`goto` 之后的孤岛），
现在也无所谓了 —— 前三路任一成功就落盘。

## 6. 教训（743 起）

| # | 要点 |
|---|---|
| 743 | ⭐⭐⭐ **「反向判断」是本项目的第一号 bug 家族**：`1.9.1`（6 处 `if-nez` 方向错误）· `2.3.2`（保存一直失效）· `2.5.4`（选图分流反向）· **`2.22.22`（本次 6 处）**。**同一类错误已经吃掉 4 轮工期** ⇒ 建议：凡写「成功/失败」分支，**写完立刻回读 smali，拿一条日志串对一遍极性**（成本 1 分钟） |
| 744 | ⭐⭐⭐ **用「日志的自证性」破案**：一串 fallback 日志里，每一条都写着「上一步也失败了」⇒ **这一串全打出来，恰恰证明上一步全成功**。看到「多路全灭」时，先把**每行的打印条件**在源码里核一遍，再考虑环境/权限 |
| 745 | ⭐⭐⭐ **「多路独立读法全灭」有两种相反的解释**：① 公共前置坏了（字节/格式/授权）② **我的判据写反了**。2.22.20/2.22.21 两版都选了 ①（并据此写了「编码不可解」「授权归属」两个结论），实际是 ② |
| 746 | ⭐⭐ **「他们能用我不能用」diff 要 diff 到函数体**：2.22.21 只 diff 了 Intent + 发起 Activity，而真正差异是 `GmBg.saveImage`（裸流拷贝、无分支）vs `GmBubble.saveImage`（解码链、4 分支全反） |
| 747 | ⭐⭐ **`imgBrush` 类的"取不到就 null"函数，要顺手验证"能取到时真的返回了东西"**：本次它返回 null 时才打日志，返回图片时反而打「不可用」—— 日志朝向反了 ⇒ 观感上像"永远取不到" |
| 748 | ⭐ **改完必回读产物**（教训 732 的复利）：本次回读了「4+2 处极性 + 0 处残留 + 版本串 + manifest」，10 秒确认，避免又一轮"改了但现象没变" |
