## 三、修复：灰度键**类型表**两处仍与 2.5.2 不符

> 类型不符的后果见铁律 2：**宿主静默读回默认值**，UI 却显示已保存 ⇒ 用户以为生效了。

核验方法：把宿主 `Lo02`（63 项灰度总表，`kv_settings_<k>` 存在时按 `<类型>` 读）
与 `Ln2a`（录音/语音 7 项）、`pk9`（TTS 2 项）里的 **`MMKV->?` 解码方法**全部提取出来，
与模块 `GmDialog.TYPES` 逐键比对：

- 宿主 `c(...)` = bool → 模块应为 `b`
- 宿主 `g(...)` = int → 模块应为 `i`
- 宿主 `e(...)` = float → 模块应为 `f`
- 宿主 `j(...)` / `k(...)` = string → 模块应为 `s` / `t`

| 键 | 模块（旧） | 宿主实际读法 | 修正 |
|---|---|---|---|
| `input_default_voice` | `s` | `Ln2a` 标记 `"Boolean"` + `MMKV->c(String)Z`（默认 false） | → **`b`** |
| `edit_menu_item_config` | `s` | `Lo02` / `h02.h()` 均 `MMKV->g(String)I`（默认 int） | → **`i`** |

**其余全部一致**（83 项逐条核过）：

| 分组 | 项数 | 结果 |
|---|---|---|
| `Lo02` 灰度总表 | 63 | 62 ✅ / 1 ❌（`edit_menu_item_config`） |
| `Ln2a` 录音·语音域 | 7 | 6 ✅ / 1 ❌（`input_default_voice`） |
| `pk9` TTS 域（`key_*`） | 2 | 2 ✅（`key_auto_tts_enabled`→`c`；`key_tts_voice_id`→`j`） |
| 下发域 `kv_remote_settings_*` | 11 | ✅（`camera/photo_picker_compress_ratio`→`e` float；`model_configs_v1`→`k`） |

**差集结论：宿主 2.5.2 没有新增灰度键** —— 模块 83 项已全覆盖，本轮**无需纳管新键**。

## 六、本轮新增教训（补充第十一节）

| # | 教训 |
|---|---|
| 66 | **升级宿主后先做「锚点存活体检」，再谈改动**：本轮 11 个锚点一次扫完，只有 2 个键出问题 —— 比逐个功能试错快一个数量级 |
| 67 | **类名还在 ≠ 签名还在**：`p66.h` / `h02.u` 参数少了一个。判断"要不要改模块"的关键不是签名，而是**模块有没有按位置读参数**（本模块只读 `args[0]`，故免修） |
| 68 | **宿主自带的「配置总表类」是最好的类型字典**：`Lo02` 里每个 item 都是 `键名 + 中文名 + 类型串("Int"/"Boolean") + 默认值 + contains→decode`，一次读干净比按功能试错高效得多 |
| 69 | **`_id_<key>` 版本键 + `Lbx4` 下发 map = 一套完整证据链**：能反证某键在宿主里"既被本地覆盖、也被下发覆盖"，从而确认它是真灰度键而非别名 |
| 70 | **`t` 这种自定义类型码要盯住**：它既不进 `GmStore.write` 的 `b/i/f/l` 分支（落 `putString`），又要求宿主按 string 读 —— 2.9.7 的 4 个 `b→t` 正是这个原因，本轮复核确认仍正确 |
