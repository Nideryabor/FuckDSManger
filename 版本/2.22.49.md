## 1. 根因：我把 `p0`（`this`）的寄存器覆盖了

```smali
.method protected onDraw(Landroid/graphics/Canvas;)V
    .registers 14          # ← 14 个寄存器
    invoke-super {p0, p1}, View->onDraw(Canvas)V
```

**`onDraw` 是非静态方法 ⇒ `this` 也算参数** ⇒ **两个参数**：

```
.registers 14  ⇒  p0 = v12   ·   p1 = v13
                  ↑↑↑↑↑↑↑
我探针里第一句就是： new-instance v12, Ljava/lang/StringBuilder;
                    → 把 this 覆盖了
```

之后原代码仍在用 `p0`：

```smali
    iget-object v2, p0, GmBgView->a:Landroid/graphics/Paint;    # p0 已经是 int 了 ⇒ 类型冲突
```

⇒ **ART verifier 拒绝整个 `GmBgView`** ⇒ `ensure()` 里 `new-instance v5, GmBgView` 抛
⇒ **`ensure()` 中断** ⇒ 探针 / `cam fx` / 后续全部不执行。

---

## 2. 修法

| 改动 | 内容 |
|---|---|
| `.registers 14` → **`.registers 16`** | ⇒ `p0 = v14` · `p1 = v15`，**p0/p1 被挪到安全的编号** |
| 探针寄存器 `v11`/`v12` → **`v12`/`v13`** | 先确认了原 `onDraw` **只用 v0~v10**（含 `invoke-virtual/range {v4 .. v9}`）⇒ **v12/v13 真正空闲** |

**复核**（读完 `onDraw` 全文 232 行）：

- 原代码寄存器使用：`v0 … v10`（含 `range {v4 .. v9}`）
- `.registers 16` ⇒ 局部 `v0..v13`，参数 `p0=v14`、`p1=v15`
- 探针只用 `v12`/`v13` ⇒ **与 p0/p1 无交集** ✓

## 5. 教训（826~827）

| # | 内容 |
|---|---|
| **826** | ⭐⭐⭐ **手写 smali 用「高位寄存器」前，必须先算出 `p0..pN` 落在哪几个编号**：`.registers N` + 参数个数 `K` ⇒ **`p0 = v(N-K)`**。`onDraw(Canvas)` 是**非静态 + 1 显式参数** ⇒ **K = 2** ⇒ 在 `.registers 14` 下 **p0 = v12** —— 而我第一句就 `new-instance v12`，**等于把 `this` 抹掉**。⇒ **教训 810/743 的同类第 N 次复发；这次把它固化成算式：先算 `p0 = v(regs-K)`，再从低编号挑空闲寄存器。** |
| **827** | ⭐⭐⭐ **「日志突然少了一整段」比「日志报错」更值得警觉**：2.22.48 里探针没出现，**我第一反应以为是"没走到"**，但对比 2.22.47 才发现**连原有的 `cam fx` 也没了** ⇒ 那是**中途抛异常**的信号。⇒ **发现"应有的日志整段消失"时，先做版本间逐行对比，定位"从哪一行开始断的"** —— 断点前后就是出错位置。 |
