## 〇、一句话

**把 Node.js 库的「加密层」用 Java 重写了一遍**，塞进模块 —— 于是模块自己能搜歌、
能拿 **320k 播放地址**、能拉歌词、能播（后台也行），**全程免登录**。

---

## 一、为什么不是「把 Node 塞进模块」

| 路线 | 结论 |
|---|---|
| 打包 node runtime（nodejs-mobile） | ❌ 几十 MB 的 V8 要塞进 Xposed 模块，还要在宿主进程里跑 |
| 模块本地起 node 服务 | ❌ 用户得自己装 node；模块里也没有 node |
| **只移植「加密算法」，用 Java 重写** | ✅ **走这条** |

> ★ 关键判断：**这个库真正的价值是加密算法**，而那是标准的 AES/RSA/MD5 ——
> Android 自带的 `javax.crypto` / `java.security` 完全能复刻。体积代价 ≈ 0。

---

## 二、新增（3 个纯 Java 类 · 零 Android 依赖）

放在 `mod-src/src/.../music/` ⇒ 编进**桥的 dex**（classes2.dex）。
**刻意不依赖任何 Android API**（连 `org.json` 都没用）——
这样能在小窝里用 `javac` 直接编译 + **真发请求验证**（跟 node 对答案）。

| 文件 | 作用 |
|---|---|
| `GmMusicCrypto.java` | 加密层：`eapi`（AES-128-ECB + MD5 摘要）/ `weapi`（双 AES-CBC + RSA-1024 raw）/ `linuxapi` |
| `GmMusicJson.java` | 极简 JSON（自造 + 解析），同样零依赖 —— 只为「能真测」 |
| `GmMusicApi.java` | HTTP + 接口：搜索 / 播放地址 / 详情 / 歌词；**登录接口已预留** |

**逐字对齐**的关键常量（来自 `util/crypto.js`）：

```
iv            = 0102030405060708
presetKey     = 0CoJUm6Qyw8W8jud
eapiKey       = e82ckenh8dichen8
eapi 报文     = AES-ECB( `${uri}-36cd479b6b5-${json}-36cd479b6b5-${md5("nobody"+uri+"use"+json+"md5forencrypt")}` ) → 大写 HEX
RSA           = 裸 RSA（NoPadding，对应 forge 的 'NONE'），加密「反转后的 secretKey」
```

**同样的输入 ⇒ Java 与 node 逐字符一致**：

| 项 | Java | node | |
|---|---|---|---|
| `eapi("/api/search/get", …)` | `1AF0E93B0E3EA03C…EF9BEB` | `1AF0E93B0E3EA03C…EF9BEB` | ✅ |
| `md5(nobody+uri+use+json+md5forencrypt)` | `1359566321b99255e14cd3cb118a4c01` | 同 | ✅ |

## 四、播放器（`MusicService.kt` · UI 侧 · **我们自己的进程**）

**为什么必须在自己的进程**：
- 「后台播放」要前台 Service + 通知 —— 宿主进程是别人的，塞不进 Service
- 播放器不能随宿主死活（宿主关了歌还得放）

| 能力 | 实现 |
|---|---|
| 播放 | `MediaPlayer`（零依赖） |
| **http→https 改写** | 网易云给的是 `http://`，Android 9+ 禁明文；实测 CDN 支持 https ⇒ **统一改写** |
| 后台播放 | 前台 Service + 常驻通知（上一首/暂停/下一首/关闭四个按钮） |
| 循环 | 列表 / 单曲 / 随机 |
| 音质 | standard / higher / **exhigh(320k)** / lossless（切换后自动重载当前曲） |
| 队列 | 点歌即播、`＋`入队、点删、清空 |
| 状态同步 | ① 同进程静态 listener（给 Compose）② 广播 `ACTION_STATE`（**给宿主迷你条**） |
| 外部指令 | 广播 `ACTION_CMD`（toggle/next/prev/stop/loop/query） |

⚠️ 踩到的编译坑：Kotlin 的 SAM 用**表达式体** `override fun d(msg: String) = Log.i(...)`
会因为返回 `Int` 而不满足 `Unit` ⇒ 必须用**块体**。

## 六、★ 类不能重复（差点埋雷）

`music.*` 既会被 UI 引用（`MusicService.kt`），又住在桥的 dex 里 ⇒ 尼尼**专门验证**了「同一类有没有被两个 dex 都定义」：

> 一开始用**字节查找**误判成「重复」（`classes2` 和 `classes4` 都有 `Lcom/…/GmMusicApi;`）——
> 但那是 **类型引用**（方法签名里），不是类定义。
> ⇒ 改用**手写 dex 解析**（读 `class_defs` + `string_ids` 真表）后确认：

```
GmMusicApi      → ['classes2.dex']        ✅ 唯一
GmMusicCrypto   → ['classes2.dex']        ✅
GmMusicJson     → ['classes2.dex']        ✅
MusicService    → ['classes4.dex']        ✅
Track           → ['classes4.dex']        ✅
重复定义的类数: 0
```

（这正是 `FdmEntry` 注释里警告过的那个大坑：同一类被两个 dex 定义 ⇒ 看 dex 顺序、行为随机。）

## 十一、教训

**953 · ⭐⭐⭐ 「把库塞进模块」往往等于「把算法重写一遍」。**
Node/Python/Go 的库塞不进 Android 模块（运行时太大、也跑不了），
但**这类库的核心通常是算法**，而算法是语言无关的。
**动手前先问「它的价值在哪一层」** —— 是运行时？还是算法与约定？
后者一个下午就能移植，前者永远移不动。

**954 · ⭐⭐⭐ 移植要能「对答案」，否则就是自嗨。**
尼尼把加密层写成**零 Android 依赖**（连 org.json 都不用），
就是为了能在沙箱里 `javac` 编译 + 跑 node 侧同输入对比。
**「两边的输出逐字符一致」比「我觉得我写对了」强一百倍** ——
而且它顺带证明了「真请求能通」，一次验证解决两个问题。

**955 · ⭐⭐ 「字节里出现」≠「类被定义」。**
检查 dex 重复定义时，`grep` 字节会把**类型引用**（方法签名里的 `Lcom/x/Y;`）误判成类定义。
**要判断"谁定义了谁"，必须真解析 `class_defs`** —— 否则会为一个不存在的问题返工。

**956 · ⭐⭐ 新属性别猜 id，去 android.jar 里读。**
自定义 AXML 编码时加一个平台属性（如 `foregroundServiceType`），
最稳的办法是 `javap -p -constants android/R$attr.class` —— **编译期常量里就是真值**。
比查文档、比猜，都可靠。

**957 · ⭐ 前台 Service 的类型是硬要求。**
`targetSdk ≥ 34` 时，不声明 `android:foregroundServiceType`，
`startForeground()` 直接抛异常。而且它还要配一条同名权限
（`FOREGROUND_SERVICE_MEDIA_PLAYBACK`）。**少一个都起不来。**
