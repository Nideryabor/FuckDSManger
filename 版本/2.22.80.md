## 0. 主人这个想法**是对的**，它有正式名字：**消融试验（ablation testing）**

| 现在的做法 | 消融试验 |
|---|---|
| 猜颜色 → 加白名单 → 重建 → 看"透没透" | **hook 掉整个元素 ⇒ 它消失了 ⇒ 就是它** |
| 判据**模糊**（50% 半透明在深色底上肉眼难辨） | 判据**二值**（在 / 不在）✅ |
| 每换一个候选 ⇒ **重建一版** ⇒ "调试来调试去" | **运行时切换，零重建** ✅ |

**⇒ 唯一必须补上的能力是「运行时切换候选」** —— 否则它又变回"每换一个都要重编"。

## 1. 本轮实现：`2.22.80` 的三个零件

| # | 位置 | 改动 |
|---|---|---|
| 1 | **`GmBubble`** | 新增三个字段：`sAblateList:Ljava/lang/String;`（候选表，`\|` 分隔）· `sAblateIdx:I`（当前编号，**0 = 关闭**）· `sAblateCur:Ljava/lang/String;`（当前试验目标） |
| 2 | **`GmBubblePaintHook.collect(String)`（新方法）** | 在 `dg` 里**顺手**把每个新出现的调用点追加进候选表（`contains` 去重、上限 `0x600` 字符后只留最新）⇒ **候选表自动生成，不用手抄** |
| 3 | **`pg` 的试验台门** | 在 `caller()` 之后、白名单之前插入：**若 `caller == sAblateCur` ⇒ `args[1] = Long(0)`（全透明 = 凭空消失）并 `return`**（`sPgWhy = 7` 便于日志区分） |
| 4 | **`GmProbe.onClick()` 重写** | **每次单击 = 切到下一个候选**：`#N = <名字>` ⇒ 探针上的字变成 **`试N`**、Toast 报出候选名、**并 `getRootView().invalidate()` 强制重绘**（否则画面不变、人会以为没生效） |
| 5 | **`GmProbe.show()`** | 武装时**清空候选表 / 编号 / 当前目标** ⇒ 每次采集都是干净的一次 |
| 6 | 版本串 ×3 + manifest | `2.22.79/410` → **`2.22.80/411`** |

## 2. ⭐ 主人操作（**不用重建、不用发日志**）

1. 装 `2.22.80` → 强停宿主 → 开 App → **进聊天页**
2. 「调试」页**拨开捕获器** → **返回聊天页** → **划一下**（让候选表有东西）
3. **单击小黑点**，一下一下点：

```
探针上的字 →  试1  →  试2  →  试3  → …  → 捕（回到关闭）
Toast 会报   "试验台 #1 ⇒ zc.s:1417"
             "试验台 #2 ⇒ vz8.c:58"
             …
```

4. **盯着屏幕**：点到某个编号时，那个**挡着背景的方块会凭空消失** ⇒ **记住那个编号和名字**（探针上就写着 `试N`）
5. **把 `试N`（或 Toast 里的名字）告诉我** ⇒ 我按它的**角色**把它正确加进白名单（衬底 ⇒ 50% 半透明；强调/按钮 ⇒ **不进白名单**，另做处理）
6. 点满一圈会自动回到「**捕**」= 关闭（恢复正常）

> ⚠️ 注意：试验台**只对"已经出现在候选表里"的调用点生效** ⇒ 必须先在目标页面**划一下**（让画面重绘过）。

## 3. 教训（189~192）

| # | 内容 |
|---|---|
| **189** | ⭐⭐⭐ **"让它消失"是比"让它半透明"强得多的判据** —— 半透明是**连续量**（50% 在深色底上肉眼几乎无差，教训 844/846 已吃过两次）；消失是**二值量**。⇒ **判定"这个元素是谁"时，默认手段应该是「消融（置零）」而不是「微调参数」**。 |
| **190** | ⭐⭐⭐ **试验手段必须"运行时可变"，否则它还是一种"重建循环"** —— 静态白名单 = 每换一个候选重建一版 = 主人说的"调试来调试去"。⇒ **凡是"要一个个试"的功能，脚手架的价值就在"切换零成本"。** |
| **191** | ⭐⭐ **候选表要"从观测里自动收集"，不要让人手抄** —— `collect()` 直接挂在 `dg` 上（那里本来就算出了调用点）⇒ **顺手多一个函数调用，省掉一整轮"你复制粘贴给我、我抄进白名单"**。 |
| **192** | ⭐ **切换后必须强制重绘** —— 与 `2.22.77` 同一个坑（教训 181）：状态变了但画面没重画 ⇒ 人会以为"没生效"。⇒ **凡是"改状态并期待肉眼可见"的动作，都要带上 `invalidate()`。** |
