# FuckDSManger 2.9.15

> 综述：**修 2.9.14 的免登录入口"没弹出来"** —— 判断逻辑换掉 + 挂载点加保险。
> 产物：`FuckDSManger_2.9.15_for_ds2.5.2.apk`（102 / 2.9.15，80 类，V1+V2+V3）

---

## 一、现象

2.9.14 装到真机后**对话框没弹**（主人反馈"看样子你没挂上"）。

## 二、定位：两个独立的问题叠在一起

### 2.1 ⭐ 判断逻辑有洞：`key_settings_token` 残留

2.9.14 用「宿主 MMKV 的 `key_settings_token` 是否为空」判断未登录：

```java
token = read2(ctx, "key_settings_token", "s");
if (token 为空) 弹();
```

**问题**：主人**之前是成功登录过的**（2.9.6 时代），MMKV 里**残留着旧 token**
⇒ 被判成"已登录" ⇒ **永不弹**。

> 教训：**"有 token" ≠ "当前已登录"**（token 会过期、会被服务端踢、账号可能已登出）。
> 用它当"要不要弹窗"的依据是不可靠的。

### 2.2 挂载点单一

2.9.14 只挂在 `MainActivity.onResume` 上 —— 这条链一旦有问题（找不到方法 / 注册失败 /
时机不对），整个入口就全废，**没有任何兜底**。

---

## 三、修复

### 3.1 判断逻辑：改成「问过就记住」，与登录态彻底解耦

```
promptIfNeeded(activity)
  ├─ sPrompted（进程内）已置位 → 返回
  ├─ 置位 sPrompted
  └─ 读 `fuckds_device_asked`（宿主 MMKV, b）
       ├─ "true"（用户处理过）→ 不弹
       └─ 否则 → 写 "true" + 弹对话框 + 记一行 DIAG
```

- **不再看 token**，只看"用户处理过没有" ⇒ 不会被残留 token 骗到
- 整个方法包 try/catch，异常只写 `device prompt FAIL` 日志，**绝不影响宿主 onResume 后续逻辑**
- 加日志 `device prompt: opening dialog`，一眼能看出走到哪了

### 3.2 挂载点：一主两备，三重保险

| # | 触发路径 | 依赖 | 可靠性 |
|---|---|---|---|
| 1 | `MainActivity.onResume` → `promptIfNeeded` | 2.5.x 老 hook | 若该 hook 失效则不触发 |
| 2 | ⭐ **任意 Activity 的首次触摸** → `promptIfNeeded` | `Activity.dispatchTouchEvent`（**framework hook，必定生效**） | **高** |
| 3 | ⭐ **1 秒内连点屏幕 6 次** → 直接开对话框 | 同上 | **高（手动召唤）** |

**关键改进**：路径 2/3 都**不再依赖 `GmEntry.sAct`**，而是直接从 hook 回调里拿 Activity：

```java
// GmTouchHook.beforeHookedMethod
Activity a = (Activity) param.thisObject;   // dispatchTouchEvent 的 thisObject 必然是 Activity
```

⇒ 哪怕 `onResume` 那条链整条断掉，手势/触摸照样能弹出对话框。

### 3.3 手势细节

- 只认 `ACTION_DOWN`（`getAction() == 0`），滑动/抬起不计
- 距上次点击 > 1 秒 ⇒ 计数归零（重新起算）
- 计数 ≥ 6 ⇒ 触发，并清零
- 触发与判断全程 try/catch，异常静默（不影响宿主触摸流程）

## 五、本轮教训（补充第十一节）

| # | 教训 |
|---|---|
| 80 | ⭐ **"有 token" ≠ "已登录"**：拿宿主状态做判断时，优先找**没有历史残留**的语义（本次用模块自己的"问过没"标记，比读宿主登录态稳得多） |
| 81 | ⭐ **急用功能的入口必须有"不依赖复杂链路"的兜底**：只挂一个 `onResume`（还要经过 5 层调用）太脆；`Activity.dispatchTouchEvent` 这种 framework 级 hook 才是硬兜底 |
| 82 | **hook 回调里 `thisObject` 比全局单例靠谱**：`param.thisObject` 是"当前这个 Activity"，而 `GmEntry.sAct` 依赖别人帮你存过 —— 谁在关键路径上，就用谁 |
| 83 | **给"没生效"留诊断痕迹**（`device prompt: opening dialog` / `device prompt FAIL` / `touch gesture: open device dialog`），否则真机上只能靠猜 |
