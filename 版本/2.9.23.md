# FuckDSManger 2.9.23

> 综述：**对话框改用系统 AlertDialog**（自绘 Dialog 会"存在但看不见"）+ 弹窗条件改为「设备身份未启用」。
> 产物：`FuckDSManger_2.9.23_for_ds2.5.2.apk`（110 / 2.9.23，80 类，V1+V2+V3）

## 一、主人的关键反馈把推断改向了

日志证据：`prompt SKIP done-flag` ⇒ `fuckds_dev_ask2 == "done"`，
而该值**只能由对话框按钮写入**；但主人明确表示**没点过、也没见过窗口**。

⇒ 唯一自洽的解释：

> **对话框确实 `show()` 了（窗口存在、能接收点击），但用户看不见它。**

⇒ 问题出在**自绘 `Dialog + LinearLayout` 的渲染**（背景/尺寸/透明度一类），
而不是逻辑层。**「看不见的窗口 + 恰好被点中」正好解释了标记是怎么被写进去的。**

## 二、本版改动

### 2.1 ⭐ `GmDeviceDialog` 改用系统 `AlertDialog`

```
AlertDialog.Builder(activity)
  .setTitle("设备身份（无需登录即可操作）")
  .setMessage(说明 + 手势提示)
  .setPositiveButton("换新身份并重启 App", new GmDeviceClick(0))
  .setNegativeButton("关闭", new GmDeviceClick(1))
  .setCancelable(true)
  .create().show()
```

- **用系统布局与配色 ⇒ 不可能隐形**
- 不再手拼 `LinearLayout` / 不再 `setBackgroundDrawable(null)`
- 保留 `dialog build start` / `dialog showing` / `dialog shown OK` 三段日志

### 2.2 `GmDeviceClick` 改实现 `DialogInterface.OnClickListener`

- 系统按钮回调签名是 `onClick(DialogInterface, int)`，与 `View.OnClickListener` 不同
- 用 `which == -1`（`BUTTON_POSITIVE`）区分「换新身份」与「关闭」
- Context 改用 `GmUtil.app()`（不再依赖 View）

### 2.3 `promptIfNeeded` 的弹窗条件（新增一条）

```
已弹过（进程内 sPrompted）      → SKIP already-prompted
设备身份已启用（isOn() == true） → SKIP device-already-on   ← 新增
标记为 done                     → SKIP done-flag
否则                            → Toast + 弹窗
```

- 换成**新键名** `fuckds_dev_ask3`，绕开所有历史标记
- 「已启用就不再打扰」比"点过就永不再弹"更合理

### 2.4 版本

`AndroidManifest.xml`：`109/2.9.22` → `110/2.9.23`

## 四、教训（补充第十一节）

| # | 教训 |
|---|---|
| 106 | ⭐⭐ **"功能没生效"还有一种可能：它在生效，只是你看不见**。本次 `done` 标记被写入 = 窗口确实被点中过 ⇒ **"看不见的 UI"比"没执行的代码"更隐蔽**。凡是自绘弹窗，都要问一句"它在任何主题/尺寸下都可见吗" |
| 107 | ⭐ **能用系统组件就别自己拼**：自绘 `Dialog` 要处理背景、圆角、尺寸、主题适配，出错率远高于 `AlertDialog`；**"看起来更定制"的代价是"可能整个看不见"** |
| 108 | **用户的否定反馈价值极高**："我没点过"这一句直接把推断从"误触"改成了"窗口不可见"，方向立刻清晰。**别把用户的否定当噪音** |
