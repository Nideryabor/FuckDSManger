# FuckDSManger NL 2.22.3（🩹 修 NullPointerException：回退路径读到了被覆盖的寄存器）

> 产物：**`FuckDSManger_NL_2.22.3_for_ds2.5.2.apk`**（**vc334 / 120 类** / V1+V2+V3 / sha256(partial) `036751cc…`）

## 一、主人回执

```
java.lang.NullPointerException: Attempt to invoke interface method
  'qr6 md8.a(long, l95, vu2)' on a null object reference
	at na.v(...:865) → np8.d → f95.L → … → AndroidComposeView.dispatchDraw
```
（`md8.a` = **`Shape.createOutline`** ⇒ **有人在 null Shape 上调用它**；且发生在**绘制线程**）

## 二、根因（**我的寄存器覆盖 bug**，2.22.2 引入）

2.22.2 我在 `wrap()` 里插入了「先试图片版」，**却把结果写回了 `v0`** —— 而 `v0` 原本存放的是 **shape**：

```smali
    :no_shape
    move-result-object v0        ← ⚠️ 原来是 shape，这里被 wrapImg 的结果覆盖
    if-eqz v0, :fallback_color
    ...
    :fallback_color
    ...
    aput-object v0, v2, v3       ← ❌ 回退路径仍把 v0 当 shape 用 ⇒ 塞进去的是 null
```

`imgOn()` 默认 **false** ⇒ `wrapImg` 立刻返回 **null** ⇒ **纯色路径也拿到 null 当 shape** ⇒
`background(color, **null**)` 进树 ⇒ 绘制时 `createOutline` 在 null 上 ⇒ **NPE 崩在 dispatchDraw** ✓ 完全吻合。

> ⚠️ 也就是说：2.22.2 只要开着气泡功能就**必炸**（与图片有没有选无关）。

## 三、修法（两行）

```smali
    :no_shape
    move-object v4, v0          ← ✅ 先把 shape 搬到 v4（回退路径专用）
    invoke-static {p0, p1}, …wrapImg(…)…

    :fallback_color
    …
    aput-object v4, v2, v3      ← ✅ 回退路径改用 v4
```
（`wrap` 的 `.registers 8` + 2 参 ⇒ 局部 v0..v5，v4/v5 原本空闲，安全）

## 五、教训

| # | 要点 |
|---|---|
| **687** | ⭐⭐⭐ **在「先试 A、失败回退 B」的写法里，A 用完的寄存器如果被 B 继续依赖，必须先把 B 的输入搬走。** 本次 `v0`（shape）被 A 的结果覆盖，而 B 仍读 `v0` ⇒ 静默传 null。**写法规范：回退分支的每个输入，在进入 A 之前先落到「A 不会碰的寄存器」。** |
| **688** | ⭐⭐ **「传 null 给库」的崩溃信息常常离现场很远**：`aput-object` 那一刻毫无异常，直到 `dispatchDraw` 里 `createOutline` 才炸。**看到「绘制线程 NPE + 库方法」先把「我们传进去的参数有没有可能是 null」列第一假设。** |
| **689** | ⭐⭐ **新加「分支」等于新加「寄存器生命周期」**：本次只加了 5 行调用，却改变了 `v0` 的语义。**插桩/加分支后，第一件事是重新数「每个寄存器在这一段里代表什么」。** |
