## 一、主人日志说明什么
```
[通话] recOn 进入
[通话] 已请求宿主开始聆听（Pressed）      ← 我们这步成功（无异常）
（没有任何 [通话][录音] AudioRecord.startRecording）  ← 宿主根本没开始录
```
⇒ **宿主接受了请求却没启动录音** ⇒ 两种可能：
1. ⭐ **录音权限被撤**（`xe1.s` 内部就检查 `RECORD_AUDIO`；Android「长期未使用自动重置权限」很常见）
2. 宿主的**手势状态机不在 `Idle`**（`s()` 开头有 `if (cur == 目标) return` 的幂等守卫；若卡在 `Pressed/ReleaseToCancel` 就会静默不动）

## 二、2.18.3 两件事
| 动作 | 说明 |
|---|---|
| ⭐ **主动检查 + 申请权限** | 按下时 `checkSelfPermission("android.permission.RECORD_AUDIO")`；缺失则记日志 `[通话] 缺 RECORD_AUDIO 权限 ⇒ 已发起申请（授权后请重试）` 并 `Activity.requestPermissions(...)` 弹系统授权框 ⇒ **授权后重按即可** |
| ⭐ **打印手势状态** | 每次按下记 `[通话] 手势状态=<Idle/Pressed/ReleaseToCancel>` ⇒ 一眼看出状态是否卡住（若卡住，下一步就"先归零再按"） |

## 三、复测
装 → 强停宿主 → 点 🎧 → 按住说话 ⇒
- 若弹权限框 ⇒ **先授权**，再按一次；期望出现 `[通话][录音] AudioRecord.startRecording` ✓
- 若不弹框仍无录音 ⇒ 把 `[通话] 手势状态=` 发我（据此决定"归零"逻辑）
