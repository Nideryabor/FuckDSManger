## 一、采纳主人的思路（很好的一招）

以前的链路每一层都在 `try/catch` 里把异常吞掉（`tryCtor`、`build()`），
⇒ 我们能看到的只有"失败"，看不到"为什么"。

**本版：抛开 `build()/make()/tryCtor` 那一整套，直连构造器，且不写任何 catch**：

```smali
    clazz = findClass("g56", ctx.getClassLoader())
    pool  = GmSuggest.templates(ctx)
    for i in 0..count-1:
        text = pool.get(i % pool.size)
        inst = XposedHelpers.newInstance(clazz, { Integer(0x2329+i), null, text })   ← ★ 不吞异常
        强制写字段 a=id / c=text / d=null
        list.add(inst)
```

⇒ 若失败，异常会**一路冒到我们钩子外层**的 `logE` ⇒ **完整堆栈进日志**（含确切异常类型与原因）。
