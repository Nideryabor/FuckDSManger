# NL 2.22.59 —— 🎯 改用「**两种页面底色的硬白名单**」（不再靠"连续次数"）

> 产物：**`FuckDSManger_NL_2.22.59_for_ds2.5.2.apk`**（**vc390 / 125 类 / V1+V2+V3 / sha256(partial) `9a9c4ac4…`**）
> 基线：**`2.22.53`**（主人指定）

## 0. 主人反馈（2.22.58）

> 「不对不对龙龙，**这次我都看出来了**，你**又把消息列表那堆按钮改成透明了**」

⇒ **「连续出现 ≥2 次」这个判据依然错**：
**一排并排的同色按钮**，在绘制时也是**一个接一个连续调用**的 ⇒ 被当成了"背景色"。

```
页面底色：一层套一层（连续 N 次同色）  ← 我想抓的
一排按钮：并排的同色背景（连续 N 次同色）← 也被抓到了 ❌
```

**⇒ 两者在 `uia.v` 的调用序列里长得一模一样，光靠"连续性"永远分不开。**

## 1. 本版：**只认两个确切的颜色**

把日志里的值算成 `Long`，得到**与日志完全一致**的数字：

| 页面底色 | ARGB | packed（Compose `Color` 高 32 位） | 日志中的值 |
|---|---|---|---|
| **深色** | `#FF0F0F0F` | **`-67818912288342016`** | ✅ **`bg#1~#4` 正是这个值** |
| **浅色** | `#FFFFFFFF` | **`-4294967296`** | ✅ 之前浅色日志里 `bg#1~#4` = `-4294967296` |

**新的 `pg` 判据（极简）**：

```smali
    ① 方法名 == "v"
    ② args[1] 是 Long
    ③ sDepth == 0

    ④ const-wide v6, -67818912288342016L      # 深色页面底色 #FF0F0F0F
       cmp-long v8, v4, v6
       if-nez v8, :do
       const-wide v6, -4294967296L             # 浅色页面底色 #FFFFFFFF
       cmp-long v8, v4, v6
       if-nez v8, :do
       goto :end                               # ★ 其他颜色一律不动

    :do
       …GmBg.real() 检查…
       args[1] = Long(0)                       # 全透空
```

**⇒ 只透空「页面底色」这两层颜色，其他一律不碰** —— 按钮、卡片、标题都保持原样。

## 2. 与之前几版的区别（为什么这次不一样）

| 版本 | 判据 | 结果 |
|---|---|---|
| 2.22.53 | 三槽白名单（**谁先出现谁进槽**） | 按钮/标题可能进槽 ⇒ 被半透明 |
| 2.22.54 | 第一个颜色 ⇒ 全透明 | ❌ 认成了标题按钮 |
| 2.22.55 | 连续 ≥2 次 ⇒ 背景 | ❌ 连续计数被"命中检查"挡住（失效） |
| 2.22.57 | 计数挪到最前 + 用它分档 | ✅ 生效（`#0F0F0F` 37.93%→22.36%）但残留多 |
| 2.22.58 | 曾是背景色 ⇒ 全透明 | ❌ **一排同色按钮也被登记为背景色** |
| **2.22.59** | **只认 2 个确切颜色** | 🎯 **不依赖顺序、不依赖连续性** |

## 5. 教训（845~846）

| # | 内容 |
|---|---|
| **845** | ⭐⭐⭐ **「连续性」不能区分「嵌套」和「并列」**：页面底色是**层层嵌套**（同一位置叠加），一排按钮是**横向并列**（不同位置各一个）—— 但**在调用序列里两者都是"连续多次同色"**。⇒ **不要用"时间/顺序上的相邻"去推断"空间上的从属关系"。** |
| **846** | ⭐⭐⭐ **当"特征判定"反复失败时，退回到"明确点名"**：我已经试过「第一个」→「连续≥2」→「曾是背景色」三种特征判据，**每种都被反例推翻**；而**"只认这两个确切颜色"**一步到位。⇒ **特征不稳定时，直接枚举已知值往往最快**（尤其目标集合很小、且能通过日志确证时）。 |
