## 一、★ 可点击的技术路线：抄宿主自己的（不是猜的）

Compose 里"自己塞控件"对我们封死（`AndroidView` 是 `@Composable`，纯 javac 手写必然破坏 composition）。
但**宿主自己的 markdown 链接是可点的** —— 它走的是 Compose 1.7 原生机制。

**逐字抄自 `or6.smali`（= AnnotatedStringExtKt，markdown 的链接那条路）：**

```smali
new-instance v3, Lri6                                    # LinkAnnotation.Clickable
invoke-direct {v3, v2, v0, v8}, Lri6;-><init>(Ljava/lang/String;Lcla;Lti6;)V
invoke-virtual {p0, v3}, Lin;->h(Lsi6;)I                 # ★ Builder.pushLink(link)
invoke-virtual {p0, v1}, Lin;->e(Ljava/lang/String;)V    # append(显示文字)
invoke-virtual {p0},     Lin;->f()V                      # pop
```

⇒ **我们照抄这个姿势**，就能把任意一段文字变成"宿主自己认可的可点击链接"。
点击回调 `ti6`(LinkInteractionListener) 是个**接口** ⇒ 纯 Java 侧用 `Proxy` 动态代理即可，
**不需要编译期看到宿主类**（符合「模块不依赖宿主类」铁律）。

### 1.1 ★ 新增锚点表（2.6.1 实测）

| 混淆名 | 真身 | 关键点 |
|---|---|---|
| **`si6`** | `LinkAnnotation`（sealed 父类） | 抽象 `a()Lti6;` `b()Lcla;` |
| **`ri6`** | **`LinkAnnotation.Clickable`** | `<init>(String tag, cla styles, ti6 listener)` ★可直接 new |
| `qi6` | `LinkAnnotation.Url` | 备用路线（a=url） |
| `cla` | `TextLinkStyles` | `<init>(SpanStyle×4)`，**四个都可空** |
| **`ti6`** | **`LinkInteractionListener`** | 接口，唯一方法 `a(Lsi6;)V` = `onClick(link)` |
| **`in.h`** | **`Builder.pushLink`** | `(si6)I` ✅ 已扒方法体实证（造 `hn` 栈帧 → 入 `b`+`c` 两个表 → 返回 `size-1`） |
| **`kn.a(I)`** | **`AnnotatedString.getLinkAnnotations`** | 遍历 `kn.a` 字段筛 `instance-of si6` ✅ |
| `kn(String,List)` | AnnotatedString 构造器 | **直接转调** `kn(List,String)`，后者把**原始整个 List 存在字段 `a`** |

### 1.2 ★★ 两道「活的下来」的证明

1. **`in.k()` 出的 AnnotatedString 会保留 annotation** ——
   `kn(String,List)` 构造器只有一句 `check-cast + 转调 kn(List,String)`（已 dump 方法体），
   而 `kn(List,String)` 把原始 List 原样存进字段 `a`。⇒ 我们 pushLink 的东西**活得下来**。
2. **我们的替换不会被下游吃掉** —— `fz2.smali` 里**没有任何 `new-instance Lkn;`**，
   只读 `kn.b`（text 字段）⇒ `args[0]` 原样流到绘制层。

`testSend()` 本体：
```smali
.method public static testSend()V
    const-string v0, "【通话测试】模块通过宿主发送链路发出的消息"
    invoke-static {v0}, GmCallDialog;->send(Ljava/lang/String;)V

.end method
```

**但它在 2.6.1 上是死的（两道断点）：**

1. ⚠️ **`ao1` 这个名字被别的类抢了** —— 2.6.1 的 `ao1` 是个 **Dagger 集合绑定类**
   （`implements bx6`、构造器 `(String,[Lbx6;)`），**没有 `I`/`J` 方法**
   ⇒ `hookM("ao1","I")` 抛异常被 catch 吞 ⇒ `GmCallHook` 从没挂上 ⇒ `sAo1` 恒 null
   （好歹没误挂到错类上乱咬）
2. ⚠️ **`yp1`（输入框状态类）未定位**（`GmRemap` 里 = null）⇒ `sYp1` 恒 null
   ⇒ `send()` 第一道守卫 `if-eqz v1, :cond_101` 就 return ⇒ **按下去静默无反应**

### 2.1 好消息：发送入口已锁定一半

`GmRemap` 里 `ao1 → gh2`，实证 **`gh2.W()Lns;` 与旧 `ao1.M()` 完全对上**
（都是"取消息主存储"，`wr`→`ns`）⇒ **`gh2` 就是 2.6.1 的会话提供接口** ✔

`gh2` 的「public + 非静态 + 单参 + void」方法只有 7 个：
`K(kl2)` · `T(mg2)` · `U(ng2)` · `c(j42)` · `k(z82)` · `m(sf1)` · `l0(String)`
⇒ **全挂上，主人手点一次发送按钮，哪个命中哪个就是。**

> ⚠️ 顺带纠正 `GmRemap` 里两条可疑项：`ao1.I→k`、`ao1.J→l0` **八成是当时人肉猜的** ——

### 3.1 新增

| **`bridge/GmSendProbe`（新）** | ⓐ hook `gh2` 那 7 个候选（**只读只打日志**）ⓑ `onSuggestClick(payload)` —— 建议被点时的落点（本版只打日志） |

### 3.2 语法

```
<Suggestion>▸ 显示文字</Suggestion>              ← 显示与回复同一句
<Suggestion>▸ 显示文字|真正回复的话</Suggestion>   ← 分开（显示短、回复长）
⟦SUG⟧▸ 显示文字⟦/SUG⟧                            ← 保险写法（⟦⟧ 已验证能穿过宿主 markdown）
```

> **为什么要保险写法**：`<Suggestion>` 是尖括号形态，**有可能被宿主的 markdown 解析器
> 当 HTML 标签吃掉**（那样标签在到达 `fz2.p` 之前就没了）；而 `⟦⟧` 定界符是
> `⟦FDM:…⟧` 已在用的、**实证能穿过解析**的形态。⇒ 两种都认。

### 3.3 降级行为

- `GmRichLink` 自检不过 ⇒ `<Suggestion>` **只剥标签**（显示文字照旧），
  绝不让 `<Suggestion>` 三个字露在界面上
- 标记**没闭合**（流式中途截断）⇒ 这一帧原地不动（宁可不动，也不吃半截）
- 链接能力未就绪的记录在 `GmRichTextHook.status()` 里（日志可见）

## 六、教训（927~932）

- **927 ⭐⭐⭐ 「借宿主自己的机制」永远优于「自己造」** ——
  链接可点这件事，宿主 markdown 早就实现了；我们只要**照抄它 pushLink 那三行**，
  连"点击怎么处理"都不用操心（Compose 的 TextLinkScope 会替我们调 listener）。
- **928 ⭐⭐⭐ 「名字被复用」比「名字变了」更危险** ——
  `ao1` 在 2.6.1 **照样存在**，只是变成了别的东西。`findClass("ao1")` 会**成功**，
  只是方法找不到才抛异常 ⇒ 如果新类**碰巧也有 `I` 方法**，就会**挂到错的对象上乱咬**。
  ⇒ **结构自检不能只验"类在不在"，要验"结构对不对"**。
- **929 ⭐⭐⭐ 死代码要分清「源码删了」和「底座删了」** ——
  这次 `mod-src/src` 里早没了，但底座（`tmp/base130/sm`）**一整套原封不动**，
  连注册语句都在。⇒ 找东西别只翻一个地方。
- **930 ⭐⭐ 「静默失败」是这种老代码的常态** ——
  `send()` 两道守卫全是 `if-eqz … return`，两个状态字段恒 null ⇒
  **按下去毫无反应、日志一行没有**。⇒ 排查"没反应"要先看它有没有**前置守卫**。
- **931 ⭐⭐ 接口是"模块不依赖宿主类"的缝隙** ——
  `ti6` 是接口 ⇒ 一个 `Proxy` 就补上了。若是抽象类（非接口），
  就得用 `registerClass` 或字节码生成，代价高一个量级。⇒ **选锚点优先挑接口**。
- **932 ⭐⭐ 尖括号标记有被 markdown 吃掉的风险** ——
  `<Suggestion>` 看着自然，但 `<…>` 在 markdown 里是有语义的（HTML/autolink）。
  ⇒ 同时提供 `⟦SUG⟧…⟦/SUG⟧` 作为**已验证通道**的退路（成本 10 行，省一轮真机往返）。
