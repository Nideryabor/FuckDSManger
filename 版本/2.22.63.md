## 1. ⭐ 教训核心：比较指令的**方向**（第三类同源坑）

**守卫反向（教训 121）之后，比较方向又栽了一次。** 四组比较必须背死：

```
if-eqz  vA, :L  ⇒  跳转条件 = (vA == 0)
if-nez  vA, :L  ⇒  跳转条件 = (vA != 0)

if-lt   vA, vB, :L  ⇒  跳转条件 = (vA <  vB)      ← "less than"
if-ge   vA, vB, :L  ⇒  跳转条件 = (vA >= vB)      ← "greater or equal"  ★ 本轮写错的就是它
if-gt   vA, vB, :L  ⇒  跳转条件 = (vA >  vB)
if-le   vA, vB, :L  ⇒  跳转条件 = (vA <= vB)
```

**记忆锚点**：`if-xx` 一律是「**xx 成立就跳**」，而 **xx 描述的是「前一个寄存器 vs 后一个寄存器」**。
⇒ `if-ge v0, v1, :cnt_ok` 的真实含义是「**v0 ≥ v1 就跳**」。我想表达的是"计数器还没到 10 就继续"，那是 **`if-lt`**。

**同类连带修正（`onTouchEvent` 的拖动阈值）**：

```smali
cmpl-float v3, v3, v4        # |dx| vs 16.0f ⇒ 1 / 0 / -1
if-gtz v3, :mv_chk2          # ✗ 写成"结果 >=0 就跳过" ⇒ 位移很小反而被当成拖动
if-lez v3, :mv_chk2          # ✅ "结果 <=0 就跳过" ⇒ 只有超过 16px 才算拖动
```

### 本轮改掉的 3 处

| # | 位置 | 原（错） | 改（对） | 症状 |
|---|---|---|---|---|
| 1 | `GmProbe.actOf` 循环上限 | `if-ge v0, v1, :cnt_ok` | **`if-lt`** | **永远返回 null ⇒ "拿不到 Activity"**（主人碰到的） |
| 2 | `GmProbe.onTouchEvent` dx 阈值 | `if-gtz v3, :mv_chk2` | **`if-lez`** | 抖动一点点就算拖动（反而拖不动） |
| 3 | `GmProbe.onTouchEvent` dy 阈值 | `if-gtz v3, :mv_apply` | **`if-lez`** | 同上 |

> ✅ 另外新增了一道保险：`GmProbe.show()` 现在**优先取 `GmEntry.sAct`**（`GmDsDialog` / `GmMenuDialog` / `GmBgDialog` 全都用它），只有它为空才退回 `actOf(ctx)`。
> 这样即使 `actOf` 将来再出问题，**开关仍然能用**（双路冗余）。

## 5. 教训（127~130）

| # | 内容 |
|---|---|
| **127** | ⭐⭐⭐ **比较指令的方向是手写 smali 的第三类同源坑**（继 121 的 `if-eqz/if-nez`、120 的匹配串之后）：`if-lt` / `if-ge` / `if-gt` / `if-le` **一律是「条件成立就跳」**，而条件描述的是「前一寄存器 vs 后一寄存器」。**写循环上限时最容易写反**（"还没到上限就继续" ⇒ 要用 `if-lt`）。⇒ **本轮把四组指令连同 `if-eqz/if-nez` 一起写进了本文档 §1，作为速查表。** |
| **128** | ⭐⭐⭐ **`vercheck.pl` 连续两版放过了三个方向性 bug**（守卫反向 ×6、比较方向 ×3）。⇒ **结论：这个工具只覆盖"类型/初始化"，对"逻辑方向"完全无能为力。** 方向类错误的**唯一有效防线是"逐条把条件念出来"**，以及**走一遍最朴素的真机路径**。⇒ 建议后续给 `vercheck.pl` 加一条**启发式检查**：列出每个类里所有 `if-*` / `cmp-*` 指令，输出成一张"条件清单"，供人逐条念（工具只做**摘录**，不判断对错）。 |
| **129** | ⭐⭐ **关键入口要有"双路来源"**：`GmProbe.show()` 原来只认 `actOf(ctx)` 一条路，这一路一坏功能就全哑。改成**先 `GmEntry.sAct`、再 `actOf`** 之后，任何一路活着都还能用。⇒ **凡是"拿到某个上下文/对象才能干活"的功能，都值得问一句「有没有第二个稳定来源？」** |
| **130** | ⭐⭐ **页面的"信息归属"要和用户的心智模型对齐**：`下发点命中 N 次 · X KB` 与「清空」在语义上都属于**「服务器下发内容」那件事**，所以它们该跟内容待在一起，而不是留在上一层菜单页。⇒ **做"菜单页/内容页"拆分时，逐项问：这条信息/这个按钮，是"关于这一页的"还是"关于下一层那件事的"？**（主人一眼就看出来它们站错了地方） |
