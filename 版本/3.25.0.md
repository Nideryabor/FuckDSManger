## 一、`grayWrite` 改写【本地覆盖层】（3.24.0 起，本版沿用）

反编译宿主 `qa5.smali` 得到的**真实读取优先级**：

```
① kv_settings_<bare>          ← 最高！宿主的「本地覆盖层」，有就直接返回
② 内存 ConcurrentHashMap       ← 本次会话缓存（所以要重启宿主）
③ kv_remote_settings_<bare>    ← 服务器下发缓存，最低
```

**旧 UI 写的就是 ①（对的）**；我们新桥 3.23.0 之前写的是 ③（**永远被 ① 压住**）。
3.23.0 的 key 探针还把 ③ 排在前面 —— 所以"怎么写都没效果"。

现在：**主写 ①**（不存在就创建，宿主用 `contains` 判断），副写 ③（本来存在才动）。

## 二、DS DATA 修复

`FdmBridge` 的 `dump_text` 以前调 `GmStore.dumpAll(ctx)` —— 那是**坏的**：
先 `callMethod(sp,"allKeys")`（宿主里 `allKeys` 是 `private native allKeys(long,boolean)`，空参点不到、抛）
再退回 `sp.getAll()`（MMKV **故意抛**）⇒ **DS DATA 永远是空的**。

改成桥自己的 `dumpHostStore(ctx)`：走**已验证**的 `allKeysOf()`（反射 private native `allKeys`），
逐键 `getString` 取值，排除 `fuckds_pin_`/`fuckds_bak_`，排序输出，单值超 500 字截断并标字数。

实测：`已回读日志 + 下发数据 21913 字`（以前约两千字）。
