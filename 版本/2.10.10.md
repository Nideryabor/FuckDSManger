## 一、为什么「代码没跑」：先怀疑守卫链条

`buildMut()` 入口有三道守卫，任何一道拦下都会**静默**（`宿主原型` 那条日志在守卫之后）：

```
1. GmUtil.app() 拿不到 Context ?      ← ★ 首要嫌疑
2. GmSuggest.on() 总开关是关的 ?
3. 输入框/宿主列表状态不满足 ?
```

**为什么首要怀疑第 1 条**：`GmUtil.app()` 平时靠 `GmEntry.sAct`（模块 UI 打开时才有），
而**聊天页里它是 null** ⇒ 只能走 `ActivityThread.currentApplication()` 反射那条路。
模块其它功能都在 UI 里调用 `app()`（`sAct` 非空，走捷径），**只有我们这几个 hook 会走反射** ——
所以「别人好好的、我们拿不到 Context」完全说得通。

### 本版加的第二条来源

`pd5.I(g56, Context)` / `pd5.H(g56, …)` 的**第二个参数就是 Context**（档案早已实证）⇒
在 `GmPromptTextHook` 里**顺手把它存进 `GmGateHook.sCtx`**，
`buildMut()` 改为 **优先用 `sCtx`，退回 `app()`**。

## 二、方案 ③ 落地：场景区分

```
传图/文件（输入框空）  ⇒ 不接管，让位宿主模板（= 你的「文件快捷选项」）
输入框有字（在打字）    ⇒ 接管那排 chip，显示我们的模板池
```

实现：**复活一小半闸门捕获**（这次只捕获、不撒谎 —— 崩溃是「撒谎」造成的，捕获本身无害）

| 类 | 变更 |
|---|---|
| `GmGateHook` | 新增字段 `sState` / `sCtx`；`afterHookedMethod` 重新捕获 `yp1` 实例进 `sState`（**不碰 `isEmpty()`**） |
| `GmSuggestHook.hasText()` | 新增：`sState.b.getValue()` → String → 去空格后是否非空 |
| `GmSuggestHook.buildMut()` | 新增判定：`hasText()` 为假 ⇒ 直接放行（让位宿主） |
| `GmPromptTextHook` | 把 `args[1]`（Context）存进 `sCtx` |
