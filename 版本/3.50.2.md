## 〇、修的一个真 bug：**明文承载时 head/tail 被静默忽略**

`GmSysPrompt.wrap()` 原文：
```java
if (carrier() == CARRIER_PLAIN) {
    return PLAIN_OPEN + sp + PLAIN_CLOSE;      // ❌ 直接 return ⇒ head/tail 根本没拼进去！
}
String h = head();
String t = tail();
// ↑ 只有隐形承载那条路才会用到 head/tail
```

**症状**：切到「明文定界」承载方式后 ——
UI 里「包装前缀 / 包装后缀」照常显示、也照常能编辑，
**但实际发出去的内容里它们一个字都没有** ⇒ **典型的"标识不清"**（主人原话）。

**修法**（就是主人说的"要么改成明文也包装"）：
```java
if (carrier() == CARRIER_PLAIN) {
    StringBuilder pb = new StringBuilder();
    pb.append(PLAIN_OPEN);
    if (h != null && !h.isEmpty()) pb.append(h);
    pb.append(sp);
    if (t != null && !t.isEmpty()) pb.append(t);
    pb.append(PLAIN_CLOSE);
    return pb.toString();
}
```
**⇒ 两种承载语义统一**：`⟦FDM⟧前缀 + 正文 + 后缀⟦/FDM⟧`

**安全性**：`GmSysPromptHideHook` 的判据是"字符串里含 `⟦FDM⟧`" ⇒ **整段（含前后缀）会被一起抹掉**，不会露在界面上 ✔

## 二、新增「清空灌入的约定」

主人提的："加一个清空灌入的提示词（比如回复建议、富文本之类的）"

**实现**（`GmRichText.removeSpecs()`）：
```java
public static String removeSpecs() {
    String cur = GmSysPrompt.text();
    int before = cur.length();
    String out = cutParagraph(cur, SPEC_TAG);        // 摘「回答排版」那段
    out = cutParagraph(out, SUG_SPEC_TAG);           // 摘「追问建议」那段
    out = tidy(out);                                  // 清多余空行
    GmSysPrompt.setText(out);
    return "已清空灌入的约定（" + before + " 字 → " + out.length() + " 字）；你自己写的内容原样保留";
}
```

**★ 关键设计：按「段落」摘，不按「文本匹配」**
- 为什么：`spec()` 的内容会随模板池变化 ⇒ 直接 `replace(旧文本, "")` 会**匹配不上**
- 做法：从特征串定位 → 向前往回找段落头（`\n\n` 之后）→ 向后找段落尾（下一个 `\n\n` 之前）→ 整段剪掉
- ⇒ **用户自己写的提示词一个字都不动** ✔

**UI**：
- 富文本页：`③ 清空灌入的约定`
- 回复建议页：`② 清空灌入的约定`
- 两处同一个动作 `specs_clear`

## 四、教训（946）

- **946 ⭐⭐⭐ 改完 A 忘了改 B："模式"加了，用得上它的地方没跟上** ——
  3.45.0 加了「明文承载」，但 `wrap()` 里那条路**没拼 head/tail**，
  UI 上也还写着"隐形文字" ⇒ **两条路语义不一致，用户看到的就是"填了没用"**。
  ⇒ **加一种"模式"时，要把它经过的每一处都过一遍**（数据路径 + 界面文案），
  别只把主路径改了就算完。
