## 二、失败分析（读宿主源码）

### 2.1 参数看错了 ⇒ 改错了对象

`nb5.c` 的 `.line 1583 ~ 1595` 寄存器搬运：

```
.line 1589
move/from16 v4, v16        ← ★ args[4]（boolean）来自 v16
.line 1591
move-object/from16 v0, v17 ← args[0] = Leb6（holder）
.line 1593
move-object/from16 v1, v21 ← args[1] = List
.line 1595
invoke-static/range {v0 .. v7}, Lyb5;->e(...)V
```

⇒ **真正的「是否可见」是 `args[4]`（第 5 个参数）**；`Leb6` 只是给内部读的 holder。
2.10.20 只改了 `Leb6` ⇒ 无效。

### 2.2 撞上 Composable 的「跳过优化」

`nb5.c` 开头：

```
.line 96
invoke-virtual {v15, v8, v4}, Ley3;->X(IZ)Z     ← Composer.startRestartGroup(key, changed)
.line 99
move-result v4
.line 100
if-eqz v4, :cond_649                             ← 「参数没变 ⇒ 整个渲染体跳过」
```

`yb5.e` 内部也有同样的判定（`.line 139~150`，用 `p7` = changed bits）。

⇒ **改了参数但没改 `changed bits`** ⇒ Compose 认为「没变化」⇒ **跳过渲染** ⇒ 白干。

## 三、本版修复（三管齐下）

`GmPromptHook` 现在改 **4 个地方**：

| # | 改动 | 作用 |
|---|---|---|
| 1 | `args[1] = GmSuggestHook.build()` | 注入我们的建议（**仅当宿主列表为空**，不打扰附件场景） |
| 2 | **`args[4] = Boolean.TRUE`** | ★ **真正的可见性开关** |
| 3 | **`args[7] = Integer(0)`** | ★ 清掉 changed bits ⇒ 让 Compose 判定「有变化」⇒ 不跳过渲染 |
| 4 | `c1(TRUE)` / `i1(TRUE)`（holder） | 保险：内部若读 holder 也拿到 true |

**同时恢复自绘 bar 兜底**：`GmSuggestHook` 重新调用 `bar()`；
并把 `GmSuggestView.sGap` 默认从 8dp 调到 **80dp**（让开 chip 行，避免两者互相遮挡）。
