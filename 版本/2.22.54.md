## 1. 本版改动：透明化时**分档选 alpha**

```smali
    # v4/v5 = 当前层的颜色
    const-wide/16 v2, 0x0                      # 默认：全透明
    sget-wide v6, GmBubble->sPageColor:J       # 槽 1 = 背景色
    cmp-long v8, v4, v6
    if-nez v8, :do_set                         # ✅ 是背景色 ⇒ 保持 0（全透明）

    # 否则：半透明（保留 RGB，alpha = 0x80）
    const-wide v6, 0xffffffffffffffL
    and-long/2addr v4, v6
    const/16 v2, 0x80
    int-to-long v2, v2
    const/16 v6, 0x38
    shl-long/2addr v2, v6
    or-long/2addr v4, v2
    move-wide v2, v4

    :do_set
    invoke-static {v2, v3}, Long->valueOf(J)Ljava/lang/Long;
    …
    aput-object v2, v0, v3                     # args[1] = 分档后的颜色
```

| 层 | 结果 |
|---|---|
| **背景块**（`#FF0F0F0F`） | **`0x0000000000000000`** ⇒ **完全透明** ⇒ 图从底下透出来 |
| **内容衬底**（`#FF292929` 等） | **`0x80292929...`** ⇒ **50% 半透明** ⇒ 文字有衬底 |

> ⚠️ 为容纳新增寄存器，`pg` 的 `.registers` 由 10 提到 **12**（`p0 = v11`）。

## 4. 教训（836~837）

| # | 内容 |
|---|---|
| **836** | ⭐⭐⭐ **同一套"透明化"里，不同层要不同 alpha**：**背景块**要**全透明**（它存在的意义就是被穿透）；**内容衬底**要**半透明**（它的意义是垫住文字）。⇒ **一律置 0 会毁可读性，一律半透明则背景不够透**；**按"这个层的存在意义"分档**才是正解。 |
| **837** | ⭐⭐⭐ **「第一个」常常是最稳的语义锚点**：背景块永远是最先被绘制的那几层 ⇒ **"第一个记录到的颜色"天然就是背景色**。⇒ 当"目标对象"在顺序上有确定位置时（最外/最先/最后），**用顺序语义比用属性特征更可靠**。（与教训 833「能用内容特征就别用次序」不矛盾：**层数序号**会随重组漂移，但**"第一个"是稳定语义**。） |
