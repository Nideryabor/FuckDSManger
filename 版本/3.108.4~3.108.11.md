## 二、导航器（本版重点）

### 2.1 骨架（3.108.4）

```
zs7.<init>(Context)  → this.b = new ms7(...)      ← 全 dex 唯一 new 点
ms7.j()              → NavGraph
vs7.m(route,true,g)  → DeepLinkMatch（rs7：a=dest · b=Bundle）
ms7.n(dest,bundle,gt7) ← 入栈
```
`HostNav.install` 挂 `zs7.<init>` 抓 NavController；列表递归 `NavGraph implements Iterable`，
route 从 `nt.e` 读。

### 2.2 ⭐⭐⭐ 带参页面「假成功」

真机日志（11-15 09:17）：
```
【HostNav】✅ 已导航 → …AuthNestedGraph.MobileVerificationRoute/{signature}
```
「成功」是假的：`matchRoute` 把 `{signature}` 当 pattern 匹配上了，但 Bundle 空
⇒ 宿主页面拿不到参数。

**修法**：
1. 参数 schema 从 **`ss7.c()`** 读（`tmp/h280/ss7.smali:506` 实证）：
   ```smali
   iget-object p0, p0, Lss7;->b:Lnt;
   iget-object p0, p0, Lnt;->d:Ljava/lang/Object;      ← LinkedHashMap
   check-cast p0, Ljava/util/LinkedHashMap;
   invoke-static {p0}, Lw07;->l0(Ljava/util/Map;)Ljava/util/Map;   ← toMap
   ```
   ⚠️ 旧代码判的是 `ss7.d` —— 那是 `Lrea;`（SparseArrayCompat），`instanceof Map` 恒 false
   ⇒ 「需要参数」永远标不出来。
2. **NavArgument（`ds7`）= a:NavType · b:nullable · c:hasDefault**；
   **默认值被 R8 省掉了**（`toString()` 里 " DefaultValue: null" 是硬编码）⇒ 没法凭空造。
3. **样本采样**：在 `ms7.n(dest,bundle,opts)` 上搭耳朵，把 `(route → 参数字典)` 记内存
   （只收 String/Number/Boolean/String[]、≤8 个、值 ≤200 字符）。
4. **跳转流程**：pattern 先 match 拿 schema → 样本打底 + 用户覆盖 → `{name}` 用
   `Uri.encode` 填掉 → 再用填好的 route match（Bundle 带 path 参数）→
   按 schema `NavType.d()`（parseValue）转类型 → `putXxx` → navigate。

### 2.3 ⭐⭐ 短名切割（3.108.7）

真机截图暴露：`MobileVerificationRoute/{signature}` 原样当标题、`SearchResultWebViewRoute/{url}?queries=…`
一整坨把行撑爆。旧 `shortName` 只按最后一个 `.` 切 ⇒ `Route` 后缀没剥掉。

修法：**先切 `?`、再切 `/`、然后按 `.` 取最后一段、最后剥 `Route`**。
`tmp/ShortNameTest.java` 16 条真机 route 用例全过。

### 2.4 ⭐⭐ query 与 path 待遇不同（3.108.7）

`fillRoute`：
- **path 占位符**没值 ⇒ **保留** `{name}`（删了整条 route 就匹配不上）
- **query 项**没值 ⇒ **整项丢掉**（留着会让宿主收到字面值 `"{name}"`，比缺参数更难查）

`tmp/FillRouteTest.java` 8 条用例全过（含 `/` `空格` 编码、只填一半、全空）。

### 2.5 参数表单是**内联卡**，不是 AlertDialog

整页本身就是一个 Dialog，再套 `AlertDialog` = 另建 window + 另建 ComposeView
（`dialog.context` 追根到宿主 Activity）—— 3.108.3 修「彩蛋（点七下）崩」踩的就是这条路。

### 2.6 布尔/列表参数不逼人填（3.108.9）

`P.suggested`：布尔 → `false`、List → 空。字符串**一律不猜**（signature/ticket/url 猜错更危险）。
`canSkip()`：所有参数都可省 ⇒ 点条目直接跳，不弹表单。

## 三、整页配置读写：两次修错，第三次才对

### 3.1 第一版（3.108.6）：靠「抛不抛」判类型 —— 错

```kotlin
for (t in arrayOf("b","i","l","f","s")) {
    val r = runCatching { hostReadStrict(host, hk, t) }
    if (!r.isSuccess) continue      // 「抛了 = 类型不对」
}
```
`GmStore.read2` 的 `.catchall` 把类型不符也吞成空串、**永不抛** ⇒ 第一个 `"b"` 恒"成功"。

### 3.2 第二版（3.108.8）：`getAll()` 拿真实 Java 类型 —— 也错

真机 + 反编译双证据：

```smali
// tmp/h280/com/tencent/mmkv/MMKV.smali:5279
.method public final getAll()Ljava/util/Map;
    const-string v0, "Intentionally Not Supported. Use allKeys() instead,
                     getAll() not implement because type-erasure inside mmkv"
    throw p0          ← 必抛
```

frida 实测（`job=cfgtype6`）：
```
sp = com.tencent.mmkv.MMKV
★ getAll() 抛了: InvocationTargetException
!! allKeys: NoSuchMethodException: com.tencent.mmkv.MMKV.allKeys []   ← 公开包装被 R8 裁了
```

### 3.3 第三版（3.108.10）：**确定性类型表** —— 对

`HostStore.HOST_TYPES`：**90 个键**，每一条都对着模块侧**真实读法**核过，不是按名字猜：

| 来源 | 例子 |
|---|---|
| `Conf.kt` 的 `KType` | `B→b` `I→i` `C→i` `T→s` `E→i`（49 条） |
| `GmBubbleBg` | `read2(c, kOn(kind), "b")` · `kMode/kFit/kColor/kAlpha → "i"` |
| `GmGlassCfg` | `bool(ctx,K_FIT)` · `intOf(K_FORM/K_EDGE/K_FADE)` |
| `GmRichText` | `boolOf(K_ON)` · `read2(K_C+i, "i")` |
| `GmSysPrompt` | `boolOf(K_ON)` · `intOf(K_MODE)` · `read2(K_HEAD/K_TAIL/CARRIER,"s")` |
| `GmPromptVars` | `boolOf(K_ON/K_LYRIC/K_LOCAL_AUTO_OFF)` |
| `GmHtml` | `boolOf(K_ON/K_LIGHT)` |
| `GmMusicDj` / `GmLocalMusic` | `K_OFF→"b"` · `K_SEL→"s"` |

`readHost` 只做一件事的兜底：**值形态不像声明的类型 ⇒ 换 `"s"`/`"i"` 再读**（历史脏值）。

`hostType()` 标 `@Deprecated` 并把两条死路写进注释；`allOf/invalidateAll/typeCharOf` 全删。

### 3.4 ⭐⭐⭐ 账号名 / 头像 / 防撤回：它们根本不在 MMKV（3.108.11）

主人点名的这一批。反编译底座 getter（`GmName/GmAvatar/GmUAvatar/GmDb.smali`）：

```smali
GmName.getText()    → SP("fuckds_gm").getString("accname_text", "")
GmAvatar.isOn()     → SP("fuckds_gm").getBoolean("avatar_on", false)
GmUAvatar.isOn()    → SP("fuckds_gm").getBoolean("uavatar_on", false)
GmDb.isOn()         → SP("fuckds_gm").getBoolean("anti_revoke", false)
```

设备上实读 `shared_prefs/fuckds_gm.xml`：
```xml
<boolean name="accname_set"   value="true" />
<boolean name="anti_revoke"   value="false" />
<string  name="accname_text">dxyabab</string>
<boolean name="uavatar_on"    value="true" />
<boolean name="avatar_on"     value="true" />
```

而 `HostStore.hostKey()` 只认 `cfg.` / `host.` / `fuckds_` 三种前缀 ⇒ `ui_nick` **一个都不匹配**
⇒ 返回 null ⇒ 界面永远显示默认值（开关是关的、名字是空的）。

修法：`LEGACY_SP` 表（键 → SP文件名 + SP键 + 类型），读走**宿主真实 SP**、写也写进去；
另外 `ui_env_on` / `ui_env_api` 补 `key_env_bypass` / `key_env_api`（MMKV，`GmEnv.setOn/setApi` 实证）。

| 界面键 | 真实存储 |
|---|---|
| `ui_avatar_on` | SP(`fuckds_gm`)/`avatar_on` (b) |
| `ui_uavatar_on` | SP(`fuckds_gm`)/`uavatar_on` (b) |
| `ui_db_on` | SP(`fuckds_gm`)/`anti_revoke` (b) |
| `ui_nick` | SP(`fuckds_gm`)/`accname_text` (s) |
| `ui_env_on` | MMKV/`key_env_bypass` (b) |
| `ui_env_api` | MMKV/`key_env_api` (b) |
| `ui_night_mode` | MMKV/`fuckds_ui_night_mode` (i) |
| `toolbox.option` | MMKV/`fuckds_toolbox_option` (b) |

**头像图片本身**没问题：`GmAvatar.file()` = `ctx.filesDir/fuckds_avatar.png`
（设备上确实有 235KB 那张），整页里 `ctx.filesDir` 就是它。

## 六、这一段的教训

1. ⭐⭐⭐ **MMKV 的类型不可能在运行时探出来** —— `getAll()` 必抛、`allKeys()` 被裁、
   `getBoolean` 对 int 非零即 true。类型只能来自「我们知道这个键是什么」。
2. ⭐⭐⭐ **「抛不抛」不是类型判据** —— 宽松转换让错类型也"成功"。
3. ⭐⭐ **界面键 ≠ 存储键** —— `ui_nick` 背后是另一个 SP 文件里的 `accname_text`。
   遇到"读不到"，先反编译 getter 看它到底读哪儿。
4. ⭐⭐ **验证不该动设备** —— `nav_dump` / `cfg_probe` 这类只读 dump 命令，
   比装包+重启+截屏轻得多。而 frida 只读 attach 比 dump 命令更轻。
5. ⭐ **frida 起不来先看内存** —— `Unable to save SELinux policy … Out of memory`
   是无害警告，真凶是 `MemFree` 不够（档案门槛 1384MB）。
