## 一、需求与设计

> 主人：「顺带做一个 demo：**AI 助手气泡美化**」，风格选定 **爱龙款 = 深色底 + 紫青渐变**。

**先做了宿主侧侦察**（`4jxpk0y3`，只读），结论决定了实现方式：

| # | 事实 | 影响 |
|---|---|---|
| 1 | 助手消息单元 = **`c30` = `AssistantChatMessageCell`**（主 Composable 直接吃 `Lvq;`，1354 条指令，且带 `hide_assistant_avatar` 那一套键） | 不可改它本身 |
| 2 | 宿主是 **KMP Compose**，`androidx.*` 类名被 R8 全改（smali 里搜不到 `BackgroundKt`/`SurfaceKt`）⇒ **没有库级锚点** | 只能按「形」找 |
| 3 | 助手 cell **不读 M3 `ColorScheme`**，用的是 `com.deepseek.chat.ui.theme.DeepSeekTheme.colorSchemeV2` | 改 ColorScheme 那条路不保证可见 |
| 4 | ⭐ `Luia;->v(Lc76;JLmd8;)Lc76;` = **`Modifier.background(color, shape)`**（`c76`=`Modifier`、`J`=Compose Color、`md8`=`Shape`、`se0`=`BackgroundElement`、`c76->r`=`Modifier.then`） | ✅ **落点** |
| 5 | ⭐ `Luia;->u(Lc76;Lsn0;Lmd8;I)Lc76;` = **`Modifier.background(brush, shape, alpha)`**（`sn0`=`Brush`） | ✅ **渐变落点** |
| 6 | `c73`（extends `dd8`=`ShaderBrush`，字段两个 `List`，`b(J)Shader`）= **`LinearGradient`**，构造 `(List<Color>, List<Float> positions)` | ✅ 可反射造紫→青 |
| 7 | `Lbw5;`（`AssistantChatMessageCell.kt:449`）**确实调了 `Luia;->u`** | 助手侧真有 brush 背景可劫 |

**核心难点 = 作用域**：这两个 `Modifier.background` 是全 App 通用工厂，全局改会把所有背景都染掉。
⇒ 解法：用 **`c30.a`（助手 cell）做作用域开关** —— Compose 组合是**同步深度优先**，所以 cell 的**整棵子树**都在 `c30.a` 的调用栈里 ⇒ **静态深度计数 + 每个 cell 只改一次** 即可精准圈定。

```
c30.a 进入 → sDepth++ / sHit=false
   └─ 子树里任何 Modifier.background：
        若 sDepth>0 且 !sHit 且 开关开 ⇒ 替换色/刷子，sHit=true
c30.a 退出 → sDepth--
```

## 二、改动（4 个类）

| # | 类 | 内容 |
|---|---|---|
| 1 | **`gm/GmBubble`（新）** | 配置（**`fuckds_bubble_on`，默认开**，走 `GmStore.get()` → `SharedPreferences.getBoolean`，只读一次）+ 作用域字段（`sDepth`/`sHit`/`sBrush`）+ **`brush(ClassLoader)`**：反射造 `c73`(LinearGradient)，颜色 **紫 `#8B5CF6` → 青 `#22D3EE`**，positions 传 null；全程 try/catch |
| 2 | **`gm/GmBubbleCellHook`（新）** | hook **`c30.a`**：`beforeHookedMethod` → `sDepth++` + `sHit=false`；`afterHookedMethod` → `sDepth--`（带 `if-lez` 防负） |
| 3 | **`gm/GmBubblePaintHook`（新）** | hook **`Luia.v` + `Luia.u`**（同一个类按 `param.method.getName()` 分流）：作用域内 `v` ⇒ `args[1] = Long(0xFF2A2140 << 32)`（**深色底**）；`u` ⇒ `args[1] = GmBubble.brush(宿主 ClassLoader)`（**紫→青渐变**）。**Shape 一个都不动**（沿用宿主自己的圆角） |
| 4 | `DisableFlagSecure` | 入口加 **3 条注册**（`c30.a` / `Luia.v` / `Luia.u`）+ 一行注册日志；版本串 `v2.20.0` → **`v2.21.0`** |
| 5 | `AndroidManifest.xml` | `318/2.20.0` → **`319/2.21.0`** |

**设计上的三个「不越界」**
- ❌ 不动 Shape（避免再造 `RoundedCornerShape` 的反射链）
- ✅ 全程 **只改参数值**（`args[1]`），不 hook 渲染/绘制函数、不改返回值
- ✅ 每个 cell **最多改一次**（`sHit`）⇒ 代码块/按钮之类不会被连带染色

**宿主 ClassLoader 怎么拿**：`param.method.getDeclaringClass().getClassLoader()` —— 被 hook 的方法属于宿主类，天然就是宿主 loader（不需要在入口多传一个参数）。

## 五、已知边界 / 下一步

1. **作用域假设有前提**：断言「背景一定在 `c30.a` 的同步调用栈里」。若宿主把消息项放进 `LazyColumn` 的独立组合域或做延迟 recomposition，`sDepth` 可能为 0 ⇒ 表现为「注册成功但无变化」。**第一份日志就能判死**。
2. **没有 UI 开关**：本版走 `fuckds_bubble_on`（默认开、只读一次），菜单项留到下一版补（`美化 › AI 气泡`）。
3. **渐变只覆盖 brush 路径**：`v`（纯色）路径是纯深色，没有描边。要「紫青渐变描边」需要 `Modifier.border` 家族 —— 尚未定位（下一步按「形」找：构造吃 `(Modifier, float宽, long色/Brush, Shape)` 的 Element）。
4. **`hookM` = `hookAllMethods`**：`Luia.v` / `Luia.u` 都是唯一重载（`Luia` 内单字母名互不重复），所以安全；宿主升级后要重新核重载数。
5. 想收紧作用域：可把 `sHit` 从「每 cell 一次」改成「比较传入 shape 是否等于某个已知圆角 Shape 单例」。

## 六、教训 / 归档要点

| # | 要点 |
|---|---|
| **632** | ⭐⭐ **「全 App 通用工厂」也能安全改**——前提是给它一个**作用域**。Compose 组合是同步深度优先 ⇒ 用「外层 Composable 的 before/after 维护深度计数」就能圈出子树，比找「助手专用渲染函数」便宜得多。 |
| **633** | ⭐⭐ **找不到库级锚点就按「形」找**：`androidx` 类名被 R8 全改，但**签名形状**改不了 —— 用 `Lc76;J` / `Lsn0;Lmd8;` 这种**类型邻接**去搜，比猜名字有效。 |
| **634** | ⭐ **参数替换 ≫ 结果替换**：只改 `args[1]`、不碰返回值、不碰 Shape、不 hook 绘制 —— 一旦出问题，症状是「没变化」而不是「崩」。 |
| **635** | ⭐ **宿主 ClassLoader 就在钩子里**：`param.method.getDeclaringClass().getClassLoader()`，不必从入口再传一遍。 |
| **636** | ⭐ **插桩只用「块头会被重新赋值」的寄存器**：入口那串 `const-string v1/v2/v3` 是天然的「寄存器安全带」，把新代码插在块**之前**即可零污染。 |
| **637** | ⭐ **反射造宿主对象必须 try/catch + 返回 null 即回退**（构造失败就保持宿主原 Brush，绝不抛）。 |
