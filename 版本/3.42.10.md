## 一、本版打通的三件事

### ① 入口终于通了（本版最大的事）

| 项 | 旧 | 新 | 怎么定的 |
|---|---|---|---|
| 宿主行桶 | `m5` | **`t5`** | 招牌串 `batch_management_click` + 分支体同构 |
| 方法 | `v` | **`w`** | 同名同形 |
| **case 判据** | `0x14` | **`0x1d`（29）** | ⭐ **运行时探针实测**，不是推的 |

**定案过程**（可复用的方法论，详见 `专题/宿主2.6.1-入口锚点-攻关记.md`）：
1. 老链 `m5.v case 0x14 → sget Lad8;->a`
2. `Lad8` 是"路由标记"（public final / 2 静态字段 / 只有 `<clinit>` / 0 字符串）⇒ 找同形 ⇒ 16 候选
3. 用"被恰好 5 个类引用"筛 ⇒ `Lz32;`
4. ⭐ **不知道是 ew1 还是 t5** ⇒ 挂探针到下游 `xu2`（更新 VM），**打印 Java 调用栈**
   ⇒ `AndroidComposeView.dispatchTouchEvent → … → m01.w → t5.w → … → ll2.z → xu2.a`
5. ⇒ 行桶 = `t5`；再插一行日志读 case ⇒ `29` ⇒ 一次成

### ② 新增三个锚点

| 旧 | 新 | 铁证 |
|---|---|---|
| `c73` | **`f44`** | `.field c:List` + `.field d:List` + `(J)Shader` —— 与老 c73 **逐字段一致**（LinearGradient） |
| `tt7` | **`u19`** | 全 dex 唯一：静态方法返回同一 Shape 类型，且 `a()` / `b(F)` / `c(FFFF)` 三种齐全 = 老 tt7 形状（Shape 伴生） |
| `g56` | **`g87`** | 由 `pd5.H(Lg56;Ley4;)` ↔ `i93.R(Lg87;Lyx4;)` **形参位次**推出 |

### ③ 修掉一处**我自己造成的破坏**

`c1` / `i1` **不是类名，是方法名**（`callMethod(obj,"c1",…)`）。
上一版我把它们当成类名替换成了"保证找不到"的假名 ⇒ **把功能弄坏了**。本版已还原。

> 📌 教训：**同名短串在不同位置语义不同**（类名 / 方法名 / 字段名 / 键名）。
> 替换前必须看**上下文**（`findClass` vs `callMethod` vs `compare`），不能一把梭。

### ⭐ 为什么要有 `install_fdm.sh`

**每次 `adb install -r` 安卓都换一个全新的 `/data/app/~~xxx==/` 目录**，
LSPosed 的 `modules.apk_path` 缓存就过期 ⇒ **模块静默不加载** ⇒ 表现成"功能全哑"。

本轮我在这上面**白烧了一个多小时**（一直在改代码，其实代码没错，是模块压根没跑）。

判据（一眼识别）：
```sh
adb shell "pm path <模块包名>"     # 实际
# 对比 LSPosed DB 的 modules.apk_path
# 模块日志 modules_*.log 里搜 FuckDSManger —— 0 行 = 没加载
```
