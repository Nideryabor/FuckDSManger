## 一、日志落盘（本轮核心）

### 1.1 为什么能写在宿主 data 里

模块代码**运行在宿主进程内**，直接用**宿主的 Context** 就能写它自己的目录 —— **不需要任何权限、不受 scoped storage 限制**。

```
GmUtil.app()                     // 宿主 Context（含 ActivityThread 兜底）
  └─ getFilesDir()               // /data/data/com.deepseek.chat.a/files
       └─ DSMlogs/               // 我们新建
            └─ dsm.log           // 追加写，每行 "时间戳 内容"
```

**⇒ 完整路径：`/data/data/com.deepseek.chat.a/files/DSMlogs/dsm.log`**（MT 管理器直接看）

### 1.2 新增 `GmLog`

| 方法 | 作用 |
|---|---|
| `dir()` | 懒加载 + 建目录 `/files/DSMlogs`（拿不到 Context 就返回 null，**静默不写**） |
| `path()` | 返回绝对路径字符串（给 UI 显示用） |
| `w(String)` | 追加一行 `时间戳 + 内容\n`（`FileOutputStream(append=true)`，**全程 try/catch**） |

### 1.3 一处接入，全局受益

在 `GmUtil.log()` 末尾加了一行 `GmLog.w(...)`：

```smali
invoke-static {v0}, Lde/robv/android/xposed/XposedBridge;->log(...)V   ← 原有（LSPosed 日志）
invoke-static {p0}, …GmDiag;->log(...)V                                ← 原有（设置页诊断块）
invoke-static {p0}, …GmLog;->w(...)V                                   ← ★ 新增（落盘）
```

⇒ **模块里所有 `GmUtil.log` / `logOnce` / `logFail` 的输出，现在都会自动进 `dsm.log`** —— 不用再靠来回贴 LSPosed 日志。

## 二、菜单改造 + 诊断埋点

| # | 改动 | 说明 |
|---|---|---|
| 1 | `GmMenuDialog` 里那一项：**「服务端灰度下发查看」→「调试 / 日志（DSMlogs）」** | 二级菜单入口改名 |
| 2 | `GmMmkvHook.handle` 加两条埋点 | ① `[mmkv] 命中 model_configs 键，评估 switchable`（说明服务器下发**有没有**经过我们的写接管）② `[mmkv] switchable false→true 已替换`（说明**替换有没有**发生） |

**⇒ 这两条正是"被顶掉"定位所需**：
- 若日志里**从没出现**"命中 model_configs 键" ⇒ 宿主的写入**没走 `MMKV.q`**（或被别的路径覆盖）⇒ 要改注入点
- 若出现了但**很快**又被覆盖 ⇒ 需要看是**谁**在后面又写了一次（下一轮可加"写入来源"标记）

## 三、验证

1. 装 `NL 2.10.54` → **强停 DeepSeek** → 打开 → 随便点几下（开「模型切换」）
2. 用 MT 管理器打开：**`/data/data/com.deepseek.chat.a/files/DSMlogs/dsm.log`**
3. 期望：
   - 文件存在且**有内容**（模块启动日志、hook 注册日志都会在里面）
   - 复现"被顶掉"时，搜 `mmkv`：看有没有"命中 model_configs 键"、"switchable false→true 已替换"

> 若 `dsm.log` 不存在 ⇒ 说明写入时机太早（`GmUtil.app()` 还没就绪）或目录权限异常；
> 下一轮可改为**启动后 `handleLoadPackage` 里显式初始化一次**并打一条自检日志。

## 四、教训

| # | 教训 |
|---|---|
| **292** | ⭐⭐⭐ **调试设施要建在"离数据最近"的地方**：日志写进**宿主自己的 data**，随手可见、不需要 root、也不需要来回贴日志 |
| **293** | ⭐⭐⭐ **一处接入、全局受益**：把落盘挂在 `GmUtil.log` 这个**唯一出口**上，比给每个类单独加日志便宜得多 |
| **294** | ⭐⭐ **"被顶掉"这类竞态必须先拿到"谁写的、什么时候写的"证据**，否则只能猜（本轮埋点就是为此） |
| **295** | ⭐⭐ 日志函数**自身绝不能抛异常**（写文件失败、Context 为空都要静默），否则调试设施会变成新的崩溃源 |
