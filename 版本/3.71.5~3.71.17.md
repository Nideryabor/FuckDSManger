## 一、玻璃「只在左上角一块」（3.71.13）★ 最硬的一个

### 现象

主人：「按钮玻璃只有以这个按钮的相对左上角有，其他地方没有」

### 定位过程

1. 先怀疑轮廓原点不是 (0,0) ⇒ 加了 bounds 诊断 ⇒ **没触发**（排除）
2. 再怀疑 GPU `RenderNode.setPosition` 重复偏移 ⇒ 看代码逻辑自洽（排除）
3. 看日志的**尺寸清单**，发现数字不对：

```
【GmGlass】上玻璃的尺寸#1：720x1584（宽块）
屏幕实际：1440x3168 px
```

**720×1584 正好是 1440×3168 的一半** —— 这正是**中心点坐标**！

### 真因

```java
static float dim(Object scope, int which) {
    for (Method m : scope.getClass().getMethods()) {   // ← 遍历取第一个
        if (m.getParameterCount() != 0) continue;
        if (m.getReturnType() != long.class) continue;  // ← 只要 0 参返回 long
        ...
    }
}
```

Compose 的 DrawScope 上**有两个**这种 getter：

```
xe6.P0()J  → 委派 w14.P0()   = getSize()
xe6.k()J   → 委派 w14.k()    = getCenter()
```

`getMethods()` **不保证顺序** ⇒ 命中了 `getCenter`。

后果是两个症状一个原因：
- 玻璃按「中心点尺寸」画 ⇒ 只覆盖 `(0,0)~(720,1584)` ⇒ **只有左上角一块**
- 整页根的真实尺寸被当成 720×1584 ⇒ `isFullPage()` 认不出根节点 ⇒ **全屏乱铺玻璃**

### 修法

不依赖名字，用 DrawScope 的**恒等式**：

```java
// center = size / 2  ⇒ 把候选两两配对，能配成「一半关系」的那对里，大的就是 size
if (Math.abs(a[0]*2f - b[0]) <= 1.5f && Math.abs(a[1]*2f - b[1]) <= 1.5f) {
    pick = b;    // b 是 size
}
```

### 教训

| # | 教训 |
|---|---|
| **Z** | ⭐⭐⭐ **「取第一个匹配」= 定时炸弹** —— Compose 的 DrawScope 同时有 `getSize()` 和 `getCenter()`，都是「0 参返 long」，名字还被混淆了。**必须用不变量去区分**（center = size/2），不能靠遍历顺序 |
| **AA** | ⭐⭐⭐ **症状看着像「坐标偏移」，其实是「尺寸错」** —— 一块矩形的左上角正好贴合元素，直觉会去查 translate/矩阵，但真相是尺寸只有一半 ⇒ 裁剪出来只剩上半块 |
| **AB** | ⭐⭐ **屏幕尺寸是最强的对照物**：日志报 720×1584、设备是 1440×3168 ⇒ 一眼看出「这是中心点」 |

## 二、`<Suggestion>` 点了没反应（3.71.17）★ 主人报的最后一个

### 现象

主人：「AI 回复下面那排『继续问』的建议，点了应该直接发出去，现在点了没反应」

### 那条救命的日志

```
建议链接能力未就绪（ri6 不是 si6 的子类（不像 Clickable））⇒ 只剥标签
```

**「只剥标签」= 把 `<Suggestion>▸ xxx</Suggestion>` 脱成纯文本** ⇒ 屏幕上看到的 `▸ 你能做什么` 是**死文字**。

### 真因：R8 把短名复用给了别的类

`GmRichLink.prepare()` 的自检：

```java
if (!cSi6.isAssignableFrom(cRi6)) return bail("ri6 不是 si6 的子类（不像 Clickable）");
if (!cTi6.isInterface())          return bail("ti6 不是接口（没法动态代理）");
```

代码找的是 2.6.x 的名字：

| 用途 | 代码找的 | 2.7.1 实际 | 怎么证的 |
|---|---|---|---|
| LinkAnnotation 基类 | `yi6` ❌ | **`gm6`** | `em6`/`fm6` 的 `.super Lgm6;`；`kn.h(Lgm6;)I` |
| Clickable | `em6` ✅ | `em6` | 字符串 `LinkAnnotation.Clickable(tag=` |
| TextLinkStyles | `tra` ✅ | `tra` | `em6` 字段 `b:Ltra;` |
| InteractionListener | `zi6` ❌ | **`hm6`** | `em6` 字段 `c:Lhm6;`，且 `public interface abstract` |

而 2.7.1 里 **`si6` / `ri6` 这两个名字还在，但指向完全无关的类**（`si6` 是个 `(sf9,hg9,I)` 的东西）⇒ 自检必然失败。

> 代码注释里当时就写着「⚠️ 2.7.1 未定位」—— 这说明**这个功能在 2.7.1 上从来没工作过**，不是回归。

### 修法

```java
CAND_SI6 = {"gm6", "yi6"};   // 新名优先，老名兜底
CAND_TI6 = {"hm6", "zi6"};
```

### 教训

| # | 教训 |
|---|---|
| **AC** | ⭐⭐⭐ **R8 短名会跨函数/跨类复用**：名字「存在」≠「是对的」。锚点必须按**结构**核（`super` 链、字段类型、字符串常量），不能只按名字 |
| **AD** | ⭐⭐⭐ **降级路径要有声音** —— `bail()` 打了日志才让这一轮不至于瞎猜。**凡是"安全失败"的地方，必须在日志里喊出来** |
| **AE** | ⭐⭐ **代码注释里的「⚠️ 未定位」= 待还的债** —— 这次两个真凶（`p68.y`、`si6`）注释里都写着未定位，一直没补 |
