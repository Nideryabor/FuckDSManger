# FuckDSManger 2.9.14

> 综述：**给「设备身份伪装」加免登录入口** —— 未登录时自动弹对话框，一键换身份 + 重启。
> 产物：`FuckDSManger_2.9.14_for_ds2.5.2.apk`（101 / 2.9.14，**80 类**，V1+V2+V3）

---

## 一、为什么要这版（主人指出的死锁）

2.9.13 把开关放在「设置 › 环境伪装」页里，但：

```
登录被 RISK_DEVICE_DETECTED 拦  →  进不了设置页  →  打不开「设备身份伪装」
                                          ↑__________________________|
                                        （鸡生蛋死锁）
```

**功能必须在"未登录也能碰到"的地方。** 主人在真机上第一眼就看出来了。

---

## 二、方案选型

| 方案 | 评价 |
|---|---|
| 默认开启 | 可用，但用户不知情就被换身份，行为不可预期 ⇒ 不采用 |
| 在手势里藏入口（连点 N 次） | 通用但要解析 `MotionEvent`；`GmTouchHook` 目前只记时间戳，成本高 ⇒ 暂缓 |
| **未登录时自动弹对话框** ⭐ | **零学习成本、不用找 UI 元素、时机正好** ⇒ 采用 |

**关键前提调研**：

- 宿主**只有 `MainActivity`**（+ 分享/表格预览/WX 回调等边缘 Activity）⇒ **登录页就在 MainActivity 里** ✅
- 模块已有 `GmResumeHook` 挂在 `MainActivity.onResume`，**天然覆盖登录页** ✅
- 未登录判断：读宿主 MMKV 的 **`key_settings_token`** 是否为空 ✅

## 三、实现

### 3.1 新增 3 个类

| 类 | 职责 |
|---|---|
| `GmDeviceDialog` | 免登录对话框：标题 / 说明 / 当前状态 / 「换新身份并重启 App」/「关闭」 |
| `GmDeviceClick` | 按钮回调（`m=0` 换身份+重启，`m=1` 关闭） |
| `GmKillRun` | `Runnable`：`sleep(1500)` 后 `Process.killProcess(myPid())` —— 让 toast 先显示出来 |

### 3.2 改动

| 位置 | 改动 |
|---|---|
| `GmDevice` | 新增 `sPrompted` 字段 + `promptIfNeeded(Activity)` + `kill()` |
| `GmResumeHook` | `GmEnv->onResume()` 之后追加 `GmDevice->promptIfNeeded(activity)` |
| `AndroidManifest.xml` | `100/2.9.13` → `101/2.9.14` |

### 3.3 触发逻辑（`promptIfNeeded`）

```
if (activity == null) return;
if (sPrompted) return;                       // 同一进程只弹一次
token = GmStore.read2(activity, "key_settings_token", "s");
sPrompted = true;
if (token == null || token.length() == 0)     // ← 未登录
    GmDeviceDialog.open(activity);
// 已登录就不打扰（登录后可从设置页进）
```

### 3.4 对话框里的两个动作

- **换新身份并重启 App**：`GmDevice.reset()`（生成新伪 ID + 自动打开开关 + 落 MMKV）
  → toast「已生成新的设备身份，即将重启 App…」→ 1.5s 后杀进程 → 用户重开 ⇒ 新身份生效
- **关闭**：只关对话框

> 之所以在对话框里就做「重启」，是因为 `Lex2.b()` 有内存缓存，
> **不重启的话新 `android_id` 不会反映到 `x-device-id`**，用户会以为没生效。

## 五、本轮教训（补充第十一节）

| # | 教训 |
|---|---|
| 76 | ⭐ **功能可用性 = 功能本身 × 入口可达性**。做"救急功能"时先画一遍**用户当前能到达哪些界面**：被拦在登录页时，任何挂在"设置页"的开关都等于不存在。**入口设计要先于功能设计** |
| 77 | **`MainActivity.onResume` 是登录态下最好的通用挂载点**：宿主只有单一 Activity 时，登录页/主页都在它内部，`onResume` 能覆盖全部前台时机（本次不用碰 Compose） |
| 78 | **用宿主自己的状态判断登录态**（`key_settings_token` 空 = 未登录），比"猜 UI 上有没有登录按钮"稳得多 |
| 79 | **改完 ID 必须重启才生效** ⇒ 模块要能自己收尾：`Process.killProcess(myPid())` + 先 `sleep` 让 toast 露个脸（否则用户什么都看不到） |
