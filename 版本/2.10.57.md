## 一、日志把问题**精确**指到一步

```
1789793324253 [model] reapply 跳过：配置里没有 switchable:false
1789793324845 [model] reapply 跳过：配置里没有 switchable:false
1789793324882 [model] reapply 跳过：配置里没有 switchable:false
```

而主人给的配置片段是：

```json
"is_default":false,"enabled":false,"switchable":false,"show_model_name_in_session":false,
```

**⇒ 三件事同时成立**：
1. `reapply` **跑了**（不是开关问题、不是 host=null）
2. 宿主配置里**确实有** `switchable` 字段
3. 但我们的 `replace("\"switchable\":false", …)` **没匹配上**

**⇒ 结论：`.replace()` 是"逐字节精确匹配"，实际存盘文本与那段片段在**格式**上不一致** —— 最可能是**空格/换行**（例如 `"switchable": false`），也就是 kotlinx/服务器下发的 pretty 格式差异。

## 四、教训

| # | 教训 |
|---|---|
| **304** | ⭐⭐⭐ **JSON 文本匹配绝不能用"精确 replace"**：同一份数据在"服务器下发 / 客户端序列化 / 落盘"三种状态下格式可能不同（空格、换行、转义）⇒ **一律用 `replaceAll` + `\s*` 宽松匹配**，或干脆走 JSON 解析 |
| **305** | ⭐⭐⭐ **"条件不满足"必须能看见输入**：这次靠"样本日志"才可能一步看穿格式差异；只报"没匹配到"等于没说 |
| **306** | ⭐⭐ **日志分级很有用**：`reapply 跑了/addressed/host 拿到/匹配失败` 四段拆开后，问题被瞬间锁定在**最后一段** |
