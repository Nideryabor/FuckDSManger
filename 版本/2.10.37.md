# FuckDSManger 2.10.37（回复建议 · 🎯 谜底：chip 文字走 `contentRes`（资源 id），不走 `content`！）

> 产物：`FuckDSManger_2.10.37_for_ds2.5.2.apk`（**188 / 2.10.37**，91 类，V1+V2+V3，sha256(partial) `be37d3ac…`）
> 触发：主人日志（字段 dump 修好后**终于带真值**）

## 一、🎯 决定性的一行

```
[建议] 宿主原型 PromptTemplate(id=9, scene=Scene(value=image), content=这是什么, contentRes=null)
[建议] g56 字段 → a:int=9 | b:String=image | c:String=这是什么 | d:Integer=?
```

**宿主的对象里 `content` 明明写着「这是什么」，可 chip 上却是空的！**
⇒ **chip 的文字根本不读 `content`(c)，而是读 `contentRes`(d)（资源 id）**；
而宿主自己填的是 **null** ⇒ **从头到尾都是空壳** ✓✓✓

这一条同时解释了：为什么宿主的 4 个也永远没字、为什么我们改 `c` 毫无效果、为什么 `pd5.I/H` 接管了也没用。

## 二、本版解法：塞"我们自己的资源 id" + 在 `Resources` 上拦截

| 步骤 | 做法 |
|---|---|
| ① 造对象时 | `d = 0x7f7f0000 + i`（我们自己的**假**资源 id，宿主的资源表里不存在） |
| ② 新钩子 `GmResIdHook` | 挂 `Resources.getString(int)` / `getText(int)`：**id 落在 `0x7f7f0000~0x7f7f00ff` 就 `setResult(我们的文字)`** ⇒ 宿主根本不会去查真正的资源表（也就不会有 NotFoundException） |
| ③ 保留 | `pd5.I/H` 的文案接管继续留着（双保险） |

```smali
# GmResIdHook 核心
    id = args[0]  (Integer)
    if (id < 0x7f7f0000 || id >= 0x7f7f0100) → 放行
    idx = id - 0x7f7f0000
    idx %= templates(ctx).size()
    setResult(templates(ctx).get(idx))        # ★ chip 就有字了
```
