## 一、🎯 决定性事实（终于拿到真值）

```

[建议] g56 字段 → a:int=9 | b:java.lang.String=image | c:java.lang.String=这是什么 | d:java.lang.Integer=null
```

### 字段语义（与宿主 toString 一一对应）

| 字段 | 类型 | 含义 | 值 |
|---|---|---|---|
| `a` | int | **id** | `9` |
| `b` | String | **scene（场景）** | `"image"` |
| `c` | String | **content（文案）** | `"这是什么"` |
| `d` | Integer | **contentRes（资源 id）** | `null` |

⇒ 结论：
1. **`c` 就是文案字段**，且**宿主自己就填了文案**（"这是什么"）—— 说明 `c` 从来不是空的
2. **`d = null`** ⇒ 文案**不**走资源 id（我们之前的"清 d"是多余操作）
3. `b` 是**场景字符串**（"image"），不是对象 ⇒ 点击很可能依赖它 ✓（我们写入的是宿主原值，方向正确）

## 二、❗ 由此得出关键判断：屏幕文字**不读 `c`**

宿主自己 `c="这是什么"`，**屏幕却显示空** ⇒ **渲染路径不读 `c`**。
也就是说：真正的文案来源在别处（很可能是 `Scene`/别的字段的组合，或者模板池被**别的字段**覆盖渲染）。

⇒ 这也解释了为什么：
- 改 `c` 无效
- 在 `pd5.H/I` 里 `setResult` 也无效（**屏上渲染根本没走这两个方法**，它们被调用只是别处的调用）
