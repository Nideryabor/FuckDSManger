## 一、2.9.19 的日志仍然说不通

```
FuckDSManger: promptIfNeeded called        ← 入口被调用（logOnce）
（无 open / 无 skipped / 无 FAIL）          ← 2.9.19 明明给"跳过分支"也加了日志
```

已核实 `GmUtil.log(String)` **没有去重**（每次调用都会写 LSPosed 日志）⇒
日志缺失只能说明：**代码在打第一条日志后、进入 try 之前就返回了** —— 即卡在
`if-eqz v0, :done`（`sPrompted` 已为 true）。

**但"第一次调用"为什么没留下分支日志，仍未解释清楚。**
⇒ 本版改为：**每个分支都留痕**，把黑盒彻底打开。

## 二、本版改动

### 2.1 `promptIfNeeded` 全分支留痕

| 分支 | 日志（全部走 `GmUtil.log` / `logOnce`） |
|---|---|
| 进入 | `prompt ENTER`（`logOnce`） |
| 已弹过 | `prompt SKIP already-prompted`（`logOnce`） |
| activity 为空 | `prompt SKIP null-activity`（`logOnce`） |
| 标记为 done | `prompt SKIP done-flag` |
| 正常 | `prompt OPEN dialog` |
| 异常 | `prompt FAIL` + 堆栈（`logFail`） |

### 2.2 ⭐ 手势门槛：6 次 → **3 次**，超时 1s → **1.5s**

- 之前"1 秒内连点 6 次"节奏太快，实测不好触发
- 现在：**1.5 秒内连点 3 次**即可

### 2.3 ⭐⭐ 手势路径**直接弹窗**，绕过 `promptIfNeeded` 的所有判断

`GmTouchHook` 里的手势分支**不调用** `promptIfNeeded`，而是直接：

```
param.thisObject → (Activity) → GmDeviceDialog.open(activity)
```

⇒ 即便 `promptIfNeeded` 的 `sPrompted` 状态再诡异，**手势也一定能弹出对话框**。

### 2.4 版本

`AndroidManifest.xml`：`106/2.9.19` → `107/2.9.20`

## 四、教训（补充第十一节）

| # | 教训 |
|---|---|
| 97 | ⭐ **"日志该出现却没出现"，本身就是最强线索**：它把范围压缩到"调用点之后、分支之前"。**但前提是每个分支都得有日志** —— 只记成功路径的日志等于没记 |
| 98 | ⭐ **关键功能要有"绕过全部逻辑"的直通入口**：自动触发的链路越长越不可靠，**手动触发的直通路径（本次的手势）才是兜底**。设计时就该这么分层 |
| 99 | **构建后回读产物**（搜索关键字符串）应该成为固定动作：它能把"代码问题"和"没打进去"这两类原因彻底分开，省掉整轮猜测 |
