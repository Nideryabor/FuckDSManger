## 1. 真正的背景块长什么样（回看真机日志）

```
bg#1  #FF0F0F0F   ┐
bg#2  #FF0F0F0F   │ ← 同一颜色【连续 4 次】
bg#3  #FF0F0F0F   │
bg#4  #FF0F0F0F   ┘
bg#5  #FF292929   ← 只出现 1 次（内容区衬底）
```

**⇒ 背景块的特征：同一个颜色「连续出现 ≥ 2 次」。**
而按钮、卡片、标题这类元素**通常只出现一次** ⇒ **天然被排除**。

## 2. 本版改动

### 新增字段

```smali
.field public static sLastColor:J      # 上一个颜色
.field public static sSameCnt:I        # 连续同色次数
```

`GmPageHook.beforeHookedMethod` 里一并清空（与三槽同生命周期）。

### `pg` 的记录逻辑（替换原来的"第一个颜色进槽 1"）

```smali
    :pick
    sget v6, GmBubble->sSameCnt:I
    const/4 v8, 0x2
    if-lt v6, v8, :try2                  # ★ 连续 >= 2 ⇒ 认定为「背景块」
    sput-wide v4, GmBubble->sPageColor:J #    ⇒ 放进槽 1（可覆盖）
    goto :do

    :try2                                # 连续只有 1 次 ⇒ 只当"内容衬底"
    … 槽 2 空则填，否则覆盖槽 3 …
```

### 透明化分档（与 2.22.54 相同，只是"谁是槽 1"变了）

| 层 | 判据 | alpha |
|---|---|---|
| **背景块** | `color == sPageColor`（= 连续 ≥2 次的那个颜色） | **`0`（全透明）** |
| 其他已记录颜色 | 槽 2 / 槽 3 | **`0x80`（半透明 50%）** |
| 未记录 | —— | 不动 |

## 5. 教训（838~839）

| # | 内容 |
|---|---|
| **838** | ⭐⭐⭐ **「第一个」是脆弱锚点，除非确认「第一个」在语义上就是目标**：我把"第一个 `v` 调用"当成"页面底色"，但实际它可能是**按钮/标题的背景**。⇒ **用顺序锚点前，先验证"第一个"到底是什么**（我这里明明有日志，却没核对 `bg#1` 究竟属于谁）。 |
| **839** | ⭐⭐⭐ **「重复出现」是比「出现次序」强得多的结构特征**：背景块会被**多层连续绘制**（同一颜色连着 4 次），而按钮/卡片/标题往往**只画一次**。⇒ **判定"谁是背景"这类问题时，"同一特征连续出现"比"谁先出现"可靠得多。** |
