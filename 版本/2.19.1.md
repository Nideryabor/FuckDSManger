## 一、2.19.0 回执的解读（决定性）

```
[通话][AI] 探查 源=无（未取到 wr 或两个仓库都空）      ← 连着 20 次，整整 20 秒
```

⇒ 先按「一行定性」的思路把它拆开，挖出**两个真因**：

| # | 真因 | 说明 |
|---|---|---|
| **1** ⭐ | **`arrOfMap` 里 `new ArrayList(Object)` 缺 `check-cast`** | smali 里 `invoke-direct {v1, v0}, Ljava/util/ArrayList;-><init>(Ljava/util/Collection;)V` 而 **`v0` 是 `Object` 类型** ⇒ **ART 逐方法校验时会 `VerifyError`**；而它被方法自己的 `try/catch` **吞掉** ⇒ 静默返回 `null` ⇒ 于是永远打印「源=无」。**这是本版最大的坑：诊断代码自己被自己的 try 吃了。** |
| **2** | `wr.x()` 是「某状态下的渲染列表」（空壳） | 2.10.85 早有结论；2.18.8/2.18.9 都栽在这（已换 `wr.f`，但见真因 1 ⇒ 其实两版都没真正读到 `f`） |

> ⭐ **教训级事实**：**「静默 catch」+「类型不对的 VerifyError」组合起来 = 完全看不见的故障**。本版起：**所有反射 helper 的 catch 一律 `GmUtil.logFail` 落 `dsm.log`**。

## 二、本版换打法：不再「导航容器」，改成「接推送」

`ao1` 组件本身一直是好的（`rec: 已取到录音控制器` 就是顺 `ao1.j` 拿的），问题出在「从 `ao1` 走到消息」这一段。
⇒ 干脆**不走了**：在宿主**自己把消息/文本送到我们面前的两个点上**挂钩（只读、绝不改参数）：

| # | 钩子 | 拿到什么 | 为什么选它 |
|---|---|---|---|
| **A** | **`vq.S(Ljava/lang/String;)V`** | `args[0]` = 文本；`param.thisObject` = 那条 `vq`（可用 `D()` 判角色） | `vq` 是所有消息的抽象基类、`S` 是 **public final 的「文本设置」点** ⇒ 一挂就覆盖所有文本更新（**2.18.7 已给它平反**：2.18.0 的事故真凶是 `apply` 分支写反，不是它） |
| **B** | **`wr.z(Lwr;Ljava/util/List;)Ⅴ`** | **`args[1]` = 完整 `List<vq>`** | 宿主「按 `vq.x()` 重建消息表」的**写入点**（2.10.87 实测命中 `n=9`）⇒ 每次刷新都白送一份完整消息表 |

两条路都汇进**同一个入口**：

```java
GmCallDialog.applyAiText(String text, String src)   // src = "S" / "z" / "f"
   ├─ 空/null ⇒ 丢
   ├─ text == sAsr  ⇒ 丢（那是主人自己那条）
   ├─ text == sLast ⇒ 丢（没变，就是主人说的「隔一段时间比一比，没变就不动」）
   ├─ sLast = text; sSame = 0
   ├─ 若「思考中」⇒ sThinkAt = now（有进展就续命）
   └─ log「抓到回复 源=… 长度=… 内容=…」 + stream(text)   ← 就地替换 🤖 行（逐字生长）
```

- **`wr.z` 只会「倒扫末尾找第一条有字且非 USER」**（`GmCallAiHook`），找不到就 `logOnce` 报一声；**全程不抛异常**。
- **`vq.S` 若命中的是主人自己那条**（`D()=="USER"`）⇒ 跳过 + `logOnce` 报一声。
- 轮询（`tick → grabAi`）**保留但降级为计时器**（管「3s 不增长 ⇒ 回待机」与 20s 兜底）；它的取数路径现在也会把 helper 异常打出来。

## 六、教训

| # | 教训 |
|---|---|
| **611** | ⭐⭐⭐ **「静默 catch + 类型不对的 VerifyError」＝完全看不见的故障**。反射 helper 的 catch 必须**落盘报错**；`invoke-direct` 传参前**类型与签名必须对齐**（`Object` 进 `Collection` 参数要 `check-cast`）。 |
| **612** | ⭐⭐⭐ **别在「容器内部结构」上做长链路导航**（`ao1 → ho1 → wr → f/x`，任一环变了就全断）：**能在「宿主动作点」上蹭到的数据，就别自己去捞**（推送 ≫ 轮询导航）。 |
| **613** | ⭐⭐ **钩子要挑「语义唯一 + 参数自足」的点**：`vq.S(String)` 自带文本、`wr.z(wr,List)` 自带完整列表 ⇒ 不需要任何额外导航 ⇒ 抗混淆改名能力强。 |
| **614** | ⭐⭐ **多条路要汇进同一个入口**（`applyAiText`）：去重只用维护一处，且**日志能一眼看出是哪条路打通的**（`源=S/z/f`）。 |
| **615** | ⭐ **改「别人家 hook」时先看它原来漏了什么**：`GmAiTextHook` 是 2.18.0 写的、**没有角色判据、没有去重**，直接 `stream()` —— 若当时注册了，很可能把主人的话显示成 AI 回复（也会刷屏）。 |
