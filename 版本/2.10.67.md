## 一、崩溃给出了最后一块拼图

```
java.lang.IllegalArgumentException: method p66.h argument 1 has type bx4, got java.util.HashMap
	at android.content.TrimootTreemrk.h(TrimootTreemrk.java)
```

**⇒ `p66.h` 的第 1 个参数声明类型是 `bx4`**（宿主的 Map 实现类）⇒ 我替换成普通 `HashMap` ⇒ **类型不符 ⇒ Xposed 传参时报错**。

**⇒ 也顺带解释了"为什么它是不可变的"**：`bx4` 天生就是不可变集合（kotlinx 的 JsonObject）。

## 二、本版：同型副本（拿它自己的类去造）

```java
Map orig = (Map) args[0];
if (orig.containsKey("model_configs")) {
    HashMap tmp = new HashMap(orig);
    tmp.remove("model_configs");

    Constructor<?> c = orig.getClass().getDeclaredConstructor(Map.class);   // ★ 用原对象的实际类
    c.setAccessible(true);
    Object copy = c.newInstance(tmp);          // ★ 造出来天然是 bx4（或其兼容子类）

    if (copy instanceof Map) {
        args[0] = copy;                        // 类型匹配 ⇒ 不会再抛参数类型错
        log("[ds] 已用同型副本替换下发 Map（去掉 model_configs）");
    }
}
```

**关键点**：
1. **不硬编码 `bx4`** —— 用 `orig.getClass()`，宿主再混淆也不怕
2. **`instanceOf` 检查 + 全程 try/catch** ⇒ 万一构造器签名不对，就**放弃替换**（日志 `同型副本替换失败（忽略，不崩）`）
3. 因此本版**不可能再因类型问题崩溃**
