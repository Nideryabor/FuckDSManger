## 一、⭐ 本轮最大收获：模块类加载器**不含宿主类**（铁律实证）

堆栈把话说死了：

| 线索 | 含义 |
|---|---|
| `DexPathList[[dex file "InMemoryDexFile[…]"]]` | 加载 `yp1` 用的是**模块自己的 in-memory dex 加载器** |
| `nativeLibraryDirectories=[…/base.apk!/lib/arm64-v8a, …]` | 它只有 **native 库搜索路径**，**没有宿主的 dex 元素** |
| `Suppressed: … DexPathList[[directory "."]]` | 父加载器也找不到 |

⇒ **模块代码里写死的宿主类引用（`Lyp1;` / `Lao1;` / 任何宿主类）在运行时一律 NoClassDefFoundError**。
⇒ 这就是本项目从第一天起**全程用字符串 + `XposedHelpers.findClass(name, 宿主loader)`** 的原因 —— 现在有堆栈证据了，不是"风格"而是**硬约束**。

**修法（2.13.2）**：`GmCallDialog.send()` 改成全程反射：

```java
ClassLoader cl = act.getClassLoader();                 // 宿主的
Class yp1 = XposedHelpers.findClass("yp1", cl);
Object input = XposedHelpers.newInstance(yp1, new Object[0]);
XposedHelpers.callMethod(input, "c", new Object[]{ text });   // 写文字
XposedHelpers.callMethod(sAo1, "I", new Object[]{ input });   // ⭐ 发送
```

> 验证：产物里 `Lyp1;` 直接引用数 = **0** ✓；`"yp1"` 字符串只剩 `findClass` 用法（且 `DisableFlagSecure` 里本来就有 `hookM("yp1","b",GmSeeHook)`，说明 `yp1` 用宿主的 loader 能找到 ✓）。

## 二、悬浮钮为什么还不出现 + 这版的对策

**已排除**：`GmUtil.dp()` 正常、decorView 这条路本项目**已验证可用**（`GmBg` 的「修改背景蒙层」就是用 `decorView.addView(view, FrameLayout$LayoutParams(-1,-1))`，真机可用）、`GmCallBtn.show()` 的调用已确认在 2.13.1 产物的 `GmResumeHook` 里且在 try 外。

**剩下三种可能**（2.13.2 全部覆盖）：

| 可能 | 对策 |
|---|---|
| `show()` 压根没被调用（onResume 链路出问题） | **新增守护线程 `GmCallTick`**：每 1s 拿 `GmEntry.sAct`（模块早就在用的活动记录，与我的代码无关）调 `GmCallBtn.ensure()` ⇒ **第二条独立上钩路径** |
| 挂上后被**后来添加的宿主子 view 盖住** | `ensure()` 检查「我们的 view 是不是父容器的**最后一个 child**」，不是就 `bringToFront()` + 落盘日志「悬浮钮被盖住，重新置顶」 |
| 被摘下来（宿主重建内容视图）后 `sView != null` 导致**永远不再重建**（旧代码的死结） | `ensure()` 检查 `getParent() == null` ⇒ 清空 `sView` 并重建 |

`ensure()` 另外加了 `isFinishing()/isDestroyed()` 守卫（守护线程拿到的是"记录里的活动"，可能已死）。

## 六、教训（本轮）

| # | 教训 |
|---|---|
| **499** | ⭐⭐⭐ **模块类加载器看不见宿主类（有堆栈实证）** ⇒ 模块里**一个宿主类名都不能写死**，一律 `XposedHelpers.findClass(name, 宿主ClassLoader)` + `callMethod/newInstance`。宿主 loader 最方便的取法：`activity.getClassLoader()`。 |
| **500** | ⭐⭐⭐ **「挂上去」不等于「看得见」**：往别人家的 View 树里塞 view，必须考虑**后来者覆盖**（后加的 child 画在上面）与**被摘下来**（宿主重建内容视图）。**一次性 addView 是脆的，要配一个"守护/复检"**（本项目已有 `GmBg.ensure` 的先例）。 |
| **501** | ⭐⭐ **别用 `logE` 记"要拿去排查"的东西** —— 它不落盘。凡是要出现在 `dsm.log` 里的，一律 `GmUtil.log(Log.getStackTraceString(t))`。 |
| **502** | ⭐ **守护线程要选无关的锚点**：`GmCallTick` 用 `GmEntry.sAct`（模块早就在维护的活动记录）而不是我自己那套 `sAct`，这样才能在"我这条链路整个没跑起来"时依然工作（**交叉验证**）。 |
