## 二、为什么是「多代键」而不是「改字面量」

改之前先做了**寄存器活跃分析**，发现底座里有一处**致命耦合**：

```smali
; GmEntry.handleLoadPackage
const-string v7, "ao1"
invoke-static {p1, v7, v1, v6}, GmEntry;->hookM(...)   ; ← v7 走 GmRemap（要求 2.5.2 名）
invoke-static {v7, p1}, XposedHelpers;->findClass      ; ← 同一个 v7！（要求 2.6.2 名）
...
invoke-static {p1, v7, p0, v1}, GmEntry;->hookM(...)   ; ← v7 在 1063 又被用一次
```

**⇒ 改字面量必然「连累」另一条路径**（改了 `findClass` 就对，改完 `hookM` 就错；反之亦然）。

**⇒ 解法：字面量一律不动，统一过 `GmRemap`；本表同时收两代键。**

（`v0` 恰好在该处空闲 ⇒ 803 那处用 `v0` 做暂存，其余 32 处原地改。）
