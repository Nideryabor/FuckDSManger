# 3.55.0（vc673）—— 🐲 常驻卡「按钮不生效」修复

> 🐲 尼得亚伯 · 2026-10-06
> 前置：`版本/3.54.2.md`（歌不完整真因 + 登录静默失败）
> 主人原话：**「常驻播放卡按钮不生效（是真·常驻，开关都没用）」**

---

## 一、真因：按钮落在**系统手势导航区**里

卡片默认位置是**贴屏幕最底**（`ph - 高度 - 24dp`）。
而 Android 的手势导航条会**拦住屏幕底部约 48dp 范围的触摸**
⇒ 卡片的**按钮行正好落在里面** ⇒ 点了全无反应。

> 这也解释了主人描述的"真·常驻、开关都没用"：
> **卡片是活的、按钮也是活的，只是手指的触摸被系统先一步接走了。**

**修法：默认位置上抬到 96dp**（稳稳避开手势区）。

---

## 二、顺手做的四件事（都是"点击不灵"的常见成因）

| # | 改动 | 为什么 |
|---|---|---|
| ① | 卡片根布局 `setClickable(true)` + `setFocusable(true)` | 让卡片是个**实体**，落在卡片上的触摸不穿透到宿主界面 |
| ② | `setFilterTouchesWhenObscured(false)` | 免得被系统判定"被遮挡"而吞掉触摸 |
| ③ | **按钮全部撑大** | 统一 `BTN_H = 38dp`、左右各 4dp 内边距；`♪` 那排以前是"一行字那么高"，手指很难点中 |
| ④ | `≡` 把手 20→30dp、`✕` 20→34dp、四角拉伸 18→26dp、列表 `＋` 22→34dp | 同上：**小目标点不中** |

**另外加了两条诊断日志**（主人下次点不中也能一眼定位）：

```
【GmMiniBar】👋 触摸到达卡片 (120,45) 位置=(10,360)dp 尺寸=330×210dp   ← 限流 2 秒一条
【GmMiniBar】👆 点了 ◀◀                                              ← 每个按钮都打
```

* 有 👋 没 👆 ⇒ 触摸到了卡片但没落到按钮上（布局问题）
* 连 👋 都没有 ⇒ **根本没到卡片**（被系统/上层拦了 ⇒ 位置问题）

---

## 三、顺手修掉一个「开关状态不一致」

音乐页那个开关**读的是新格式**（`cfg.fuckds_bar_on`）而**写的是旧格式顶层键**
⇒ 重启 UI 后开关显示会和实际不符（看着像"开关没用"）。
统一成新格式。

## 五、教训

**969 · ⭐⭐⭐ 屏幕边缘的触摸不属于你 —— 系统手势区会先接走。**
"按钮没反应"这类问题，除了查代码，还要查**位置**：
贴边、贴底的控件，触摸可能被系统导航/状态栏吃掉。
**默认摆放要给系统留余地**（本版给底部留了 96dp）。

**970 · ⭐⭐ 点击目标要「大到手指能点中」。**
`WRAP_CONTENT` 的文字按钮在一行里可能只有十几 dp 高 ——
**看起来有、点起来没有**。给按钮一个固定高度（38dp）是低成本的确定收益。

**971 · ⭐⭐ 加一条「触摸到达了吗」的日志，比猜十次快。**
👋（触摸到达卡片）和 👆（点了某按钮）两条日志一对比，
立刻能把问题**切成"没到"还是"到了没点中"**两类 —— 这两类的修法完全不同。
