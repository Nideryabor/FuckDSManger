## 二、★ 崩溃真因：跨类读 private 字段（历史遗留的手写 smali）

日志（主人给的）：
```
java.lang.IllegalAccessError: Field '…gm.GmProbe.sInst' is inaccessible to class '…gm.GmTouchHook'
    at com.nidyaber.fuckdsmanger.gm.GmTouchHook.beforeHookedMethod(Unknown Source:67)
    …
    at android.view.ViewGroup.dispatchTouchEvent
```

**定位过程**（两步都做了，第一步先排除掉一个诱人但错误的猜想）：
1. 先怀疑「classes.dex 与 classes2.dex **重复定义**了 `gm.GmProbe`」——
   用 dex `class_defs` 解析**证伪**：class 1 定义 `gm.GmProbe` / `gm.GmTouchHook`，
   class 2 是 **`bridge.GmProbe`**（不同包）⇒ 没有重复定义。
2. 再看**字段的访问级别**：底座 smali 里
   ```smali
   .field private static sInst:Lcom/nidyaber/fuckdsmanger/gm/GmProbe;
   ```
   而 `GmTouchHook` / `GmBubblePaintHook`（**别的类**）都 `sget-object … GmProbe;->sInst`
   ⇒ **跨类读 private** ⇒ 每次触发都抛 `IllegalAccessError`。

**为什么表现成"最近老崩/刷屏"**：`GmTouchHook` 由底座的 `GmEntry` **无条件注册**，
钩的是 **`dispatchTouchEvent`** ⇒ **每碰一下屏幕就抛一次**（LSPosed 接住了，所以不是必定闪退，
而是"日志刷屏 + 那条链上的功能失效"）。

**修法**：字段改 `public`（语义不变、访问合法），然后**重建底座**：
```sh
python3 tools/重建底座.py --smali tmp/base130_261/sm \
    --base mod-src/out/FuckDSManger_NL_2.22.133_for_ds2.6.1.apk \
    --out  mod-src/out/FuckDSManger_NL_2.22.133_for_ds2.6.1.apk --api 26
python3 tools/check_base_sync.py --smali tmp/base130_261/sm --base <上面那个>   # ⇒ ✓ 同步（137 文件）
```
⚠️ 它**在底座里** ⇒ 必须**重启宿主**才生效（主人今天开 DeepSeek 时自然生效）。

## 三、★ 布尔口径：库里两种写法，"只认一种"的读法就会骗人

```
UI 里存的值：cfg.fuckds_bar_on = "1"     ← 宿主 "b" 类型的惯用值
Music.kt 的读法：== "true"                ← 只认这一种
⇒ 界面显示「关」，实际是 "1"（开）；宿主读到的 bar_on = True ⇒ 迷你条一直挂着
```

**修法**：`Bridge` 加两个公共函数，全 App 统一：
```kotlin
fun boolOf(s: String?): Boolean   // 读："1"/"true"/"yes"/"on" 都算 true
fun boolStr(v: Boolean): String   // 写：统一成 "1"/"0"
```
接进去的地方：`Music.kt` 的三个开关（bar/pvar/lyric）读+写 · `Pages.kt` 的 `saveLocal`（布尔归一）·
`Rows.kt` 的 `SettingSwitch`（读回执判定）。

> 顺手验证：改完直接给宿主发了一条 `cfg_put fuckds_bar_on b false`（用**真 `\x1f` 分隔符**，
> shell 里写字面量 `\x1f` 不解析 —— 老坑），`宿主 bar_on = False` ⇒ 迷你条当场收起 ✓

## 五、教训

**1037 · ⭐⭐⭐ 「跨类读 private」是**编译能过、运行必炸**的那种错。**
　　手写 smali 时代留下的字段可见性（`private`），在别处被 `sget-object` 读 ——
　　dex 校验不拦，运行时才 `IllegalAccessError`。
　　⇒ 排查顺序：**先证伪"重复类"**（用 `class_defs` 真解析），**再看字段可见性**。
　　★ 教训 553 那条「字节里出现 ≠ 类被定义」今天又救了一次 —— 它让我没有一头扎进错误猜想。

**1038 · ⭐⭐⭐ 同一个开关，库里可能有**两种合法写法**；"只认一种"的读法一定会骗人。**
　　`"1"` 与 `"true"` 在我们这儿**都合法**（一个来自宿主 `"b"` 约定、一个来自早期 UI），
　　而某个读法只认后者 ⇒ **界面说关、实际是开**，用户当然会觉得"功能坏了"。
　　⇒ 修法要**成对**：读的入口收敛成一个 `boolOf`，写的入口收敛成一个 `boolStr`。
　　（只改一边 = 把坑从 A 挪到 B。）

**1039 · ⭐⭐⭐ UI 没在跑时，**所有跨进程动作都会静默失效** —— 必须把这件事说出来。**
　　"拼合结果还是旧的"真因是：**宿主（DeepSeek）没在运行**，而预览读的是**上一次的缓存**。
　　⇒ 两件事：**① 判新鲜度**（`host.at` 比时间戳，只认新回话）；**② 说人话**
　　（"宿主没回话：提示词是宿主里的模块写的，请先打开 DeepSeek"）。
　　★ 把"没做到"和"做不到"分开讲，比让人以为界面坏了强得多。

**1040 · ⭐⭐ 进页面**把可展开的东西全部折叠**，是个便宜又稳的选择。**
　　主人这次提的（"原先展开的、现在被锁了还是展开的"）—— 说明**状态恢复**要跟**当前规则**对账：
　　存档里那个 `expanded` 是"上一次合法"的，但规则变了之后它就不合法了。⇒ 不恢复、只折叠。

**1041 · ⭐（自记）"并排发命令"这个毛病今天犯了 4 次以上。**
　　`改文件` 和 `做包.sh` 一起发 ⇒ 编出来的是**中间态**（哈希都不一样），只能重编确认。
　　⇒ 已写进硬规矩：**构建 / 安装 / 拉取这类"读世界"的命令，永远单独发一条。**
