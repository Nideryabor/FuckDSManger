## 〇、这一版解决的两个"看着像 bug、其实是边界"的事

### ① 「AI 生成建议」开关：开着的建议点不动、关了反而能点

**★ 真因（主人自己找出来的）**：这类开关（`fuckds_suggest_ai`）是
**宿主启动时注册钩子**的（`GmEntry` 里 `hookAllConstructors("wr"/ns)` + `hookM`），
钩子一挂就一直在跑 ⇒ **改完开关不重启宿主，配置和实际行为就对不上**。

⇒ 你看到的"开关反了"其实是**旧状态还在跑**。

> 尼尼顺路把 `GmSuggestAi` 的 hook 扒了一遍：它的 `afterHookedMethod` **全是只读**
> （只 `getResult()` 存进静态字段 `sList`/`sWr`，没有 `setResult`/改 `args`）
> ⇒ **它不会改坏渲染** —— 所以"反了"这件事从来就不是它干的。

**⇒ UI 补一条醒目的 INFO**（回复建议页）：
> ⚠ 改完开关要「重启宿主」才生效
> 「AI 生成建议」这类开关是在【宿主启动时】注册钩子的。改完必须强停宿主再打开…
> （真机踩过：「AI 生成建议」开着时建议点不动、关了反而能点 —— 其实只是旧状态还在跑）

### ② HTML 渲染：按钮和文字都在，但点了没反应

**★ 这是已知边界**：HTML 那套是「**投递那一刻跑 JS，再截图成 PNG**」交给 Compose 显示
⇒ **它是一张静态图，不是活网页** ⇒ 页面里的按钮/输入框/链接**天然点不了**。

要真正可交互 = 让宿主**别截图、直接把 WebView 显示出来** —— 那是宿主 Compose 架构决定的，改不了。

**⇒ UI 补进 HTML 开关的说明里**：
> ⚠ 它渲染出来是一张【静态图片】（投递那一刻跑完 JS 再截图）——
> 页面里的按钮、输入框、链接全都点不动，那是设计如此，不是坏了。

## 二、教训（942~943）

- **942 ⭐⭐⭐ 「改了不生效」先问「是不是要重启」** ——
  Xposed 类模块的开关分两种：**渲染时现读**（如富文本的 `rich_on`，改了马上生效）
  和**启动时注册钩子**（如 `suggest_ai`，钩子挂了就一直在跑）。
  ⇒ 后者**必须重启宿主**。**这类"坑"要写在开关旁边**，否则下次还会被当成 bug 查半天。
- **943 ⭐⭐ 把"设计如此"写进 UI，比修一个修不了的 bug 更有价值** ——
  HTML 的"点不动"是架构决定的边界（截图 vs 活网页），
  与其反复解释，不如直接在开关说明里写清楚 ⇒ **管理预期就是解决问题**。
