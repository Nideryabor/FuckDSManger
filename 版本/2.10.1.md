## 三、★ 关键实现点（都对着历史教训改的）

| 点 | 做法 | 对照教训 |
|---|---|---|
| **造 `g56` 用宿主 ClassLoader** | `GmUtil.app().getClassLoader()` → `XposedHelpers.findClass("g56", cl)` → `getDeclaredConstructor(Integer.TYPE, Integer.TYPE, String, String)` → `newInstance(7, id, "default", text)` | G.10.2：模块专属 Loader 看不见宿主 dex，**绝不能 `new-instance Lg56;`** |
| **可见性三管齐下** | ① `args[4]`（`Z`）置 TRUE ② `getObjectField(holder,"b")` → `setValue(TRUE)`（真身 = 父类 `o32.b`）③ 兜底 `c1/i1` | 33.1 教训 131/132：`c1/i1` 只是影子；B.2 #4：`yb5.e` 的 `args[4]` 才是「是否可见」 |
| **无条件替换列表** | 开关打开时，命中即把 `List` 换成我们的模板（不再要求宿主列表为空） | B.2 #5：**宿主列表默认非空**，「仅空列表才替换」会把自己挡在门外 |
| **两道防御** | ① 先 `array-length` 查参数个数再取下标 ② 全程 try/catch + `logE` | 2.10.31 就是 `AIOOBE` 在链首 ⇒ 后续全跳过 |
| **不碰通用 AnimatedVisibility** | `dm0.c` / `dm0.g` 一律不挂 | 2.10.30：它们是 7 个调用点共用的包装，强开会把「修改输入」横幅顶出来 |

**缓存策略**：`GmSuggestHook.sCache` 静态缓存列表；保存 / 恢复默认时调 `clear()` ⇒ **改完立即生效，不用重启**。

## 四、真机验收

```
1. 覆盖安装 FuckDSManger_2.10.1_for_ds2.5.2.apk（vc152 > 151，可直接覆盖）
2. 强停宿主 com.deepseek.chat.a → 重开 → 进任意会话
3. 先看 LSPosed 日志有没有这两行：
      FuckDSManger: [建议] 提示词容器命中（yb5.e/f）
      FuckDSManger: [建议] 宿主列表 list=N
4. 再在会话里传一张图片 / 一个文件（★ 必做：宿主设计上「有附件才显示提示词行」）
5. 看输入框上方：应变成我们的模板池内容（默认 3 条）
6. 点其中一个 ⇒ 应把该文字当用户消息发出去
7. 设置路径：设置页 › 检查更新 › （菜单）回复建议 ⇒ 可开关 / 改数量 / 改模板池
```

### 判读表

| 现象 | 含义 | 下一步 |
|---|---|---|
| 有 `提示词容器命中` + 有 chip + 点击发出去 | 🎉 **主干达成** | 补「不打扰附件场景」+ 常显（见第五节） |
| 有 `命中` 但 `list=` 一直没变 | 走了 `yb5.f` 那条（`e` 没命中） | 只保留 `f` 那条，删 `e` |
| 有 `list=N` 但画面没变化 | 渲染层还有 skip（`dm0.c` / Composer changed bits） | 切 `yb5.c` 单 chip 渲染（G.10.4 预留的下一刀） |
| **完全没有** `命中` 日志 | 提示词区没进组合树 ⇒ **闸门没开**（无附件） | 见第五节：撬 `yp1.a` 的 `isEmpty()` |
| chip 出现了但点了没反应 | 点击链路问题 | 查 `GmClick` / `pd5.I` 文案解析 |

## 五、遗留（下一刀：常显 = 不再依赖附件）

**闸门链（档案 G.3/G.4 已挖到底）**：

```
xl1.q  .line 722~737   v3 = !(输入状态 yp1).a(附件列表 hp8).isEmpty()
                        └─ dm0.g(v3, …)          ← 外层 AnimatedVisibility（第 1 参＝是否显示）
nb5.c  .line 277~316   内含 PromptTemplateSection：hp8.isEmpty() ⇒ 整段跳过
```

⇒ **没附件 ⇒ 整段提示词区根本不进组合树**，任何挂在它下游的 hook 一次都不会命中（前 4 版探针全卡在这）。

**建议做法（比 2.10.28 的 `dm0.g` 强开干净，避开「修改输入」横幅副作用）**：

1. `hookAllConstructors("yp1")` 的 `afterHookedMethod` ⇒ `getObjectField(thisObject,"a")` 拿到那个 `hp8` 实例，存静态
2. hook `hp8.isEmpty()` ⇒ **仅当 `this == 存下的实例`** 时 `setResult(FALSE)`
   ⇒ 同一个 `isEmpty()` 结果同时喂给 `xl1.q` 的外层可见性 与 `nb5.c` 的内层闸门 ⇒ **一处改，两道门一起开**
3. 恢复「不打扰」：`hp8` 真实非空（真有附件）时照旧让位给宿主模板

⚠️ 风险自评：`isEmpty()` 说谎可能被别的读取方（上传状态 / 发送按钮）看到 ⇒ 需真机回归；开关关掉即回退。

**其它遗留**：Phase 1.5「真贴在最后一条 AI 气泡下方」· Phase 2「文案由宿主模型生成」· 与防撤回共用 `h1.a` 消息状态（仅最后一条是 AI 回复时显示）。
