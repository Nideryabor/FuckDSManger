## 1. 🔴 真根因：`GmLog.w` 把「参数寄存器」当临时变量用

```smali
.method public static w(Ljava/lang/String;)V      # p0 = 要写入的日志内容
    ...
    const-string p0, "dsm1.log"                   # ★ p0 被覆盖成轮转文件名
    invoke-direct {v6, v0, p0}, Ljava/io/File;-><init>(...)V
    invoke-virtual {v6}, Ljava/io/File;->exists()Z
    move-result p0                                # ★ p0 又变成 boolean（int）
    if-eqz p0, :cond_28
    ...
    :cond_28
    invoke-virtual {v1, v6}, Ljava/io/File;->renameTo(...)Z
    :cond_2b                                       # ★ 汇合点：p0 一边是 String、一边是 int
    ...
    invoke-virtual {v3, p0}, Ljava/lang/StringBuilder;->append(Ljava/lang/String;)V   # ★ 要求 String
```

**后果（与 2.22.32 那个 VerifyError 同一病理）**：

- `:cond_2b` 是**汇合点**，`p0` 在「文件 > 256KB」这条路径上已不是 `String` ⇒ **ART verifier 拒绝整个 `GmLog` 类**
- `GmDiag.log` 里那句 `GmLog->w(...)` 于是抛 `NoClassDefFoundError`，被自己的 `try` 吞掉
- ⇒ **内存 DIAG 照常写**（所以模块 UI 里看得到日志）· **文件 `dsm.log` 永远写不进去**

> 📌 **这不是本版引入的** —— `GmLog.w` 是 **2.22.25「日志地基 v1」** 手写的，也就是说
> **从 2.22.25 起，「三通道」里的文件通道其实一直是死的**，只是大家都在看模块 UI（DIAG），没人去翻文件夹。

**修法（最小改动，不动寄存器数量）**：把轮转分支的临时值从 `p0` 换成**当时空闲的 `v2`**：

```smali
    const-string v2, "dsm1.log"
    invoke-direct {v6, v0, v2}, Ljava/io/File;-><init>(...)V
    invoke-virtual {v6}, Ljava/io/File;->exists()Z
    move-result v2
    if-eqz v2, :cond_28
```

⇒ `p0` 全程保持「日志内容」不变 ⇒ `:cond_2b` 汇合点上 `p0` 恒为 `String` ⇒ **冲突消失**
（新引入的 `v2` 在 `:cond_2b` 之后**立即被 `new-instance v2, SimpleDateFormat` 重新赋值** ⇒ 不读 ⇒ 安全）

**全库同类扫描**：`search smali "const-string p"` → 30 处，逐个核对后**其余都是安全的**
（`p0` 用完即弃，或后续不再读该寄存器）；`GmLog.w` 是**唯一一处「覆盖后又被读取」**。

## 4. 教训（799~801）

| # | 内容 |
|---|---|
| **799** | ⭐⭐⭐ **「参数寄存器 `p0..pN` 不是只读的」是手写 smali 的隐形雷**：`GmLog.w` 用 `p0` 当轮转分支的临时变量，结果**参数被覆盖 + 汇合点类型冲突** ⇒ 整个类被 ART 拒绝。**规矩：方法参数寄存器只读；要当临时用就先 `move-object vX, pN` 拷出来。** |
| **800** | ⭐⭐⭐ **「三通道」要有一条「验尸」路径**：文件通道**死了 9 个版本没人发现**，因为大家只看模块 UI（内存 DIAG），而内存通道**恰恰是被文件通道的异常"绕过去"的那个**（`GmDiag.log` 里 `GmLog.w` 抛异常 ⇒ 后续裁剪不执行 ⇒ 内存里内容更全 ⇒ 看起来一切正常）。⇒ **凡是"主通道之外的备份通道"，必须有一条明确的「怎么确认它还活着」的检查步骤**，否则它死了也不会有人知道。 |
| **801** | ⭐⭐ **日志类里「先拼字符串再写文件」的顺序决定了故障模式**：本例 `append` 在 `GmLog.w` **之前**、裁剪在**之后**，于是「写文件失败」不但不报警，反而让内存缓冲**永不裁剪**（内容看起来更全）—— **故障伪装成正常**。⇒ 关键副作用之后要补 `catch` 并**在别处留痕**（例如失败时往内存通道写一行 `文件通道异常`），否则静默。 |
