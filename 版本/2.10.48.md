## 一、47 为什么还崩：我停漏了一处

47 版我停掉了 `buildMut`（末端列表接管），**但漏掉了它上面紧挨着的那一行**：

```smali
:cond_f
invoke-static {v0}, Lcom/varuns2002/disable_flag_secure/gm/GmSuggestHook;->forceVis([Ljava/lang/Object;)V   ← 还在
check-cast v2, Ljava/util/List;
…
```

`forceVis` 是 2.10.10「方案③」时代的产物，**每次那排 chip 渲染都会跑**，而它干的是：

```smali
# 1) 篡改宿主方法的入参！
array-length v0, p0 ; const/4 v1, 0x6 ; if-lt v0, v1, :cond_12
const/4 v1, 0x4 ; aget-object v2, p0, v1 ; instance-of v3, v2, Boolean
sget-object v3, Boolean;->TRUE ; aput-object v3, p0, v1        ← args[4] 被强改成 true

# 2) 改宿主的 Compose 状态
v4 = getObjectField(args[0], "b") ; callMethod(v4, "setValue", TRUE)
callMethod(args[0], "c1", TRUE)
callMethod(args[0], "i1", TRUE)
```

⇒ 这正是项目硬约束里明令禁止的「**伪造宿主状态**」（2.10.9 常显闸门崩宿主就是同款机制：**给宿主假情报 ⇒ 宿主按假情报去取数据 ⇒ 越界/不一致 ⇒ 崩**）。
⇒ 它在**渲染热路径**上，所以「开关打开 + 上传图片（chip 重建）」正好触发 ⇒ 完美解释主人的现象。

`GmGateListHook` 里「谎报 `isEmpty()` 非空」的代码**一直还在**：

## 三、本版改动（4 处）

| # | 改动 | 说明 |
|---|---|---|
| 1 | `GmSuggestHook.beforeHookedMethod`：**不再调 `forceVis`** | 改为一行 `[建议] 可见性强改已停用（不再篡改宿主状态）`；`report()` 只读 size 打日志，安全 |
| 2 | `GmGateListHook.beforeHookedMethod`：**删掉 `setResult(Boolean.FALSE)`** | 不再伪造 `isEmpty()`；只留 `[建议] 闸门谎报已彻底停用` |
| 3 | **新增 `GmCrashHook`**（崩溃捕手） | `install()` 时接管 `Thread.setDefaultUncaughtExceptionHandler`，把宿主崩溃堆栈用 `Log.getStackTraceString` 取全，`XposedBridge.log("[FuckDSManger-CRASH] 线程=…\n<堆栈>")` + `GmDiag.log`，然后**转交原 handler**（不改变宿主原有崩溃行为） |
| 4 | `DisableFlagSecure` 里加 `GmCrashHook.install()` | 与 MMKV 注册相邻；全 try/catch，失败只记日志 |

### 3.1 崩溃捕手为什么重要

之前**一直拿不到堆栈**（模块日志里没有 FATAL，因为崩在宿主自己的代码里）。现在：
- 崩了以后，**模块日志里会直接出现** `[FuckDSManger-CRASH] 线程=main\n…Caused by: …`
- 打开「设置 › 回复建议」的诊断块也能看到一行 `[崩溃] …`（截断版）
- **旧 handler 照常调用**，所以宿主的崩溃表现跟以前一模一样（不掩盖问题）

⇒ 下一轮主人只要「照常崩一次 + 把模块日志里 `CRASH` 那段给我」即可，不用折腾 logcat。

### 3.2 现在的接管格局

```
✅ 源头：MMKV.q(写) / MMKV.k(读) → patch prompt_feature（自包含 / 零异常 / JSON 校验）
❌ 末端：列表替换 —— 停用
❌ 强改：forceVis（入参 + setValue/c1/i1）—— 停用
❌ 谎报：hp8.isEmpty() —— 删除
✅ 捕手：宿主崩溃堆栈 → 模块日志
```

## 五、教训

| # | 教训 |
|---|---|
| **266** | ⭐⭐⭐ **停功能要"整段停"，不能只停最后一步**：我 47 停了 `buildMut`（末端替换），却漏了同一段里更早的 `forceVis`（改宿主状态）⇒ 崩因仍在。**停之前先把这段代码从头读一遍** |
| **267** | ⭐⭐⭐ **"改宿主入参/状态"是最危险的一类注入**，哪怕有 try/catch 也救不了（宿主拿到假情报后的越界发生在**我们的 catch 之外**） |
| **268** | ⭐⭐ **"已停用"必须落实到代码删除**：`GmGateListHook` 的谎报靠"某个字段恰好恒为 null"侥幸不触发 ⇒ 早晚会被别的改动激活 |
| **269** | ⭐⭐ **必须有崩溃现场捕获**：没有堆栈的排查全靠猜（前 20 版都在猜）。给宿主装 `UncaughtExceptionHandler` + 转交原 handler，是"零副作用拿堆栈"的正解 |
