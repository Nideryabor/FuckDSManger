## 0. 108 日志抓到"用户气泡底"的真身

门一开就露出来了：

```
16:01:25.601 ls9.f 用户气泡 lambda 已调用（…）
16:01:25.602 ls9.f:670 | 色=-9208960518906183680 | sd=0 | ub=1 | ud=0 | 形=c84
                                                    ↑↑        ↑↑
                                              计数器都是 0   形状 = 宿主 zc.o（与助手同一个）
```

**⇒ 结论（回答主人的疑问："是不是判断写错"）**：
**不是角色判断错**（`role=USER` 完全正确）——
是**重写门设错了**：`ub()` 要求 `sUDepth>0` 才重写，而**用户气泡的底是在布局/绘制阶段建的**，那时 `sDepth`/`sUDepth` 早已归零 ⇒ **门直接 bail** ⇒
用户档的颜色/圆角/图**永远挂不上去**；而图像底又走 `sBmp` 那条路 ⇒ 于是"图和 AI 一样 / 改用户顺便改 AI"。

顺带这次日志把整张 `uia.v` 地图也打全了（`ju.q:2104` / `zc.s:1417` / `ob2.b:168` / `ls9.f:670` …），
其中**只有 `ob2.b:168`（助手）与 `ls9.f:670`（用户）是"气泡底"**，两者**形状相同**（`c84`=`zc.o`）⇒ 必须靠**调用点**区分。

## 1. 本版改动（一处，最小）

`ub()` 的重写门：

```
sUDepth > 0                       → 允许（原逻辑保留）
  或  caller.startsWith("ls9.f")  → 允许（★ 新增旁路：用户气泡 lambda）
否则                              → bail
```
⇒ **用户气泡的底从此会被换成用户档的颜色/圆角/图** ✓
⇒ 助手气泡（`ob2.b:168`）依旧走 `sDepth>0` 原逻辑，互不干扰 ✓
（`uOn()` / `args[2]==宿主 zc.o` 两道既有门保留 ⇒ 不会误伤别的背景）

## 3. 教训 292 ~ 294

| # | 要点 |
|---|---|
| **292** | ⭐⭐⭐ **"重写门"和"探针门"要分开设**：探针门要**宽**（不漏任何一类调用），重写门要**严**（不误伤）。我把两者用同一个 `sUDepth>0` 绑在一起，结果"看不见"和"够不着"同时发生 ⇒ 连错 3 版 |
| **293** | ⭐⭐⭐ **同一个元素的"底"可能在不同阶段生成**：助手气泡的底在组合期（`sDepth>0`），用户气泡的底在**布局/绘制期**（计数为 0）⇒ **靠"组合期计数器"区分角色，天生只能覆盖一半** |
| **294** | ⭐⭐⭐ **调用点（caller）是最稳的身份证之一**：形状相同（`c84`）时靠 `形=` 分不开，靠 `调用点 ls9.f` 一次分清 ⇒ **宿主自带的结构信息永远优先** |
