# FuckDSManger NL 2.10.76（🐛 修 2.10.75 的两个 bug：AI 开关按钮空白 + 点击无反应）

> 产物：`FuckDSManger_NL_2.10.76_for_ds2.5.2.apk`（**227 / NL 2.10.76**，94 类，V1+V2+V3，sha256(partial) `74115688…`）
> 触发：主人 —— 「你那个 AI 生成的按钮怎么文字都没有，点了还没反应」

---

## 一、根因（**两个都是我自己写的 bug，且同属"反判断/跳转目标"家族**）

### bug ①「按钮没有文字」= `GmSuggestDialog.sync()` 里一行写反的 `if`

我写的：

```smali
sget-object v0, ...GmSuggestDialog;->sAiBtn:Landroid/widget/Button;
if-nez v0, :ai_sw_done          # ← 「非 null 就跳过」
```

**⇒ 按钮存在时（非 null）反而跳过了 `setText`** ⇒ 永远空白；
**⇒ 按钮不存在时**才会往下走（然后 NPE，被吞掉）⇒ 彻底本末倒置。

**修正**：

```smali
if-eqz v0, :ai_sw_done          # null 才跳过
```

### bug ②「点击没反应」= `GmClick` 里 0x38 分支**不可达**

`GmClick.onClick` 是**顺序 if 链**，每个 case 的「不匹配」跳转目标指向**下一个 case 的 label**。
我用 `insert_after_match` 把 0x38 插在 0x37 之后，**却没改 0x37 那条 `if-ne` 的目标**：

```smali
:cond_1b6
const/16 v1, 0x37
if-ne v0, v1, :cond_1be      # ← 目标还是"最终 return"，0x38 段被整段跳过
invoke-static {}, ...->toggle()V
return-void

:cond_1b7                     # ← 永远到不了
const/16 v1, 0x38
...
```

**修正**：把 0x37 的目标改成 `:cond_1b7`。

### bug ③（顺手发现）`GmSuggestDialog.toggleAi()` 的 `sAct` 判空也写反

```smali
if-nez v0, :ai_tg_done       # ← sAct 非 null 就跳过 ⇒ toast 永不弹
```
**修正**：`if-eqz v0, :ai_tg_done`。

## 二、加固（防同类再犯）

1. **`open()` 里 AI 按钮创建后立即 `setText("AI 生成：已关闭")`** —— 不再把"初值"完全托付给 `sync()`；就算 `sync()` 将来又出问题，按钮也不至于空白。
2. 版本号 → `2.10.76 / vc227`（含两处 `ENTER` 日志 + 设置页诊断标题）。

## 四、教训

| # | 教训 |
|---|---|
| **369** | ⭐⭐⭐ **顺序 if 链新增 case 时，必须改「前一个 case」的跳转目标** —— 用 `insert_after_match` 插到上一个 case 之后，上一个 case 的 `if-ne` 目标仍指向"最终 return"，新 case **静默不可达**（不报错、不崩、就是没反应）。**插完必须回头看前一条 `if-*` 的 label** |
| **370** | ⭐⭐⭐ **反判断第 N 次**：`if-nez X, :skip` 的语义是「X 存在就跳过」—— 凡是「有值才处理」的场景，必须是 `if-eqz X, :skip`。**本项目累计 22+ 次，已列入最高频 bug 家族** |
| **371** | ⭐⭐ **"按钮没文字 + 点击无反应"这种双症状，往往是两个独立 bug 叠加** —— 别指望一个根因解释全部，逐个查 |
| **372** | ⭐⭐ **UI 控件的初值不要只靠 `sync()` 一条路径**：创建时给一次保底文字，`sync()` 再刷新。**多一条腿，少一次挨骂** |
