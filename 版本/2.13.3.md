### ❌ 收获 2：悬浮钮挂在**一个不存在的 API** 上

```
NoSuchMethodError: No virtual method setGravity(I)V in class Landroid/widget/FrameLayout$LayoutParams;
  at GmCallBtn.show(Unknown Source:144)
```

**`FrameLayout$LayoutParams` 根本没有 `setGravity()`**（那是 `LinearLayout$LayoutParams` 的），它的 gravity 是**公开字段**。
⇒ 而在本项目自己的代码里，**早就一直是"直接写字段"**：

```smali
# GmCam（摄像头预览）：FrameLayout$LayoutParams + 0x11
iput v9, v8, Landroid/widget/FrameLayout$LayoutParams;->gravity:I
# GmEntry：FrameLayout$LayoutParams + 0x30
iput v3, v2, Landroid/widget/FrameLayout$LayoutParams;->gravity:I
```

⇒ **2.13.3 改法**：`setGravity(0x33)` → `iput v4, v3, ...->gravity:I`
⇒ 产物复查：`FrameLayout$LayoutParams;->setGravity` 命中 **0**，`->gravity:I` 命中 **1** ✓

### 🔍 收获 3：守护线程**当时没跑起来**（顺带修的隐患）

日志里**没有** `[通话] 悬浮钮守护已启动（1s 一次）`，也没有后续每秒的重试。原因是 2.13.2 把 `start()` 排在了 `show()` **后面**、且在同一个 try 里（`show()` 抛错后链路就断了）。
⇒ **2.13.3**：① `GmCallTick.start()` **提到 `show()` 之前** ② 两者**各用独立 try**，异常分别记 `[通话] 守护线程启动异常` / `[通话] 悬浮钮调用异常` ⇒ 再出事一眼看清是哪一半。
