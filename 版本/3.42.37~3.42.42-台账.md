## 二、⭐ 通话：从"完全没有"到"只差服务端"

### 2.1 宿主的通话开关 = `model_configs[].call_feature`（**空标记对象**）

```
ChatPageTopBar.kt:105
    callFeature = config.call_feature          # ModelConfig 第 14 字段（Lv87;->n:Lw77;）
    null ⇒ 不画「打电话」图标；非 null ⇒ 画
```

`ModelConfig$CallFeature`（`Lw77;`）**零字段** ⇒ **存在即开启**。

⇒ 做法与我们已有的 `GmTts`（补 `tts_feature`）**完全同构**：
往 `kv_remote_settings_model_configs_v1` 的每个 model 里补 `"call_feature":{}`。
锚点用 `"model_type":"`（每个 model 的第一个字段，稳定且不与 GmTts 撞车）。

### 2.2 抓包实证（`抓包/ProxyPin10-2_10_33_12.har`，脱敏版 `脱敏-call.har`）

| 接口 | HTTP | 业务码 | 结论 |

| `GET /api/v0/call/config` | 200 | `biz_code:0` | ✅ **完全放行**（4 个音色：贝壳/白浪/海星/暗潮）|
| `POST /api/v0/call/start` | 200 | **`biz_code:5`** | ❌ **`call mode disabled`**（服务端 feature flag）|

## 三、⭐ 通话页留驻（3.42.40 + 3.42.41）

### 3.1 闸门找到了

```
ChatCallHost (do1.c, ChatCallHost.kt:32)
   └─ if (callPageViewModel.a())  CallPage(i93.f)

Loq1;->a()Z   （= CallPageViewModel）
   val v = vy0.v0(state)      # state 是 v01(进行态) 取出标记；w01(空闲) ⇒ null
   if (v == this.b) return vy0.u0(state)
   return false
```

⇒ 服务端一还错误 ⇒ 状态回落到 `w01`(空闲) ⇒ `a()` 变 false ⇒ **通话页被摘掉**（来不及看清）。

### 3.2 做法：hook 返回值（**不动底座**）

- 新类 `bridge/GmCallPin.java`：`XposedHelpers.findAndHookMethod("oq1", "a", ...)`
- 注册点：**`FdmEntry.handleLoadPackage`**（那里才有 `lp.classLoader` = 宿主自己的CL）
- 开关：`fuckds_call_pin`；动作 `call_pin_set` / `call_pin_state`
- UI：灰度页顶部第二行「通话页留驻」

### 3.3 ⚠️ 3.42.40 的过度（主人实测抓出来的）

> 主人：「**留住了，但是杀后台再打开也是通话页**」

⇒ 恒 true 把**冷启动**（状态本来就是空闲 `w01`）也一起强拉了。

**修（3.42.41）**：加一道门 —— **只有本进程内"通话页真的活跃过"(`sOpened=true`)，之后才允许留驻**。
冷启动时 `sOpened=false` ⇒ **完全不干预** ⇒ 不会再无中生有一个通话页 ✅

**验证**：冷启动后日志只有 `[留驻] 已挂钩子 oq1.aZ`，**没有** `强制 true` ✅

### 3.4 已知副作用

`a()` 还被 `hq`(ChatCallState) / `o82` / `y42` 调用 ⇒ 开着留驻时，**聊天页也可能认为"正在通话中"**
（多一条横幅）。不崩，关开关即还原。

## 四、⭐ 灰度工具箱审计（3.42.38 + 3.42.39）

### 找到并修掉的 5 处

| # | 问题 | 真因 |
|---|---|---|
| **1** | 🔴 **「全部恢复灰度」恢复不了** | ① `gray_restore_all` 只撤 `fuckds_pin_*` 影子键，而 `grayWrite` 从 3.24.0 起**主写真实键** ⇒ 真值永远回不去<br>② 备份用 `sp.getString(k)` ⇒ **int/bool/long/float 型抛 ClassCastException**，被 catch 吞 ⇒ **35I + 26B = 61 个键从没备份上** |
| **2** | 🔴 **「保存并推给宿主」是假按钮** | 它只发 `gray_all`（**回读**），什么都没推 —— 而每项改动在 `GrayRow` 里**已经实时写宿主**了 ⇒ 已删 |
| **3** | 🔴 **`input_default_voice` 文案骗人** | hint 写「如 zh-CN」，但宿主 `yib.smali` 注册的是 **Boolean**（UI 是开关）⇒ 用户想填字符串根本没地方填 |
| **4** | 🟡 `key_auto_tts_enabled` / `key_tts_voice_id` 被误加前缀 | 它们是宿主的**裸键**（不带 `kv_`），`grayWrite` 无脑拼成 `kv_settings_key_*`（靠 pin 表侥幸兜住）|
| **5** | 🟡 `volcengine_enabled` 文案 | 说"开关"，其实宿主类型是 **String**（输入框）|

### 修法

```java
// grayWrite 备份（三件套）
for (String k : new String[]{loc, full}) {
    if (sp.contains("fuckds_bak_" + k)) continue;      // ② 只在第一次备（改3次也能回到最初）
    Object cur = anyValue(sp, k);                       // ① 全类型（不抛）
    sp.edit().putString("fuckds_bak_" + k,
            cur == null ? BAK_NONE : String.valueOf(cur)).apply();   // ③ 哨兵
}
```

```java
// gray_restore_all
① ed.remove("fuckds_pin_" + 三种键形)          // 撤影
② bak == BAK_NONE ⇒ GmStore.remove(real)       // 原本没有 ⇒ 删回去
   bak 非哨兵     ⇒ GmStore.write(real, bak, type)  // 写回真值
③ pins().clear()                                // 清内存 pin 表
```

## 五、教训（接编号）

| # | 教训 |
|---|---|
| **360** | ⭐⭐⭐ **"让它一直显示"和"让它该显示时显示"是两件事**。恒 true 会在**冷启动**（本该空闲）时也强拉 ⇒ 必须有"**曾经活跃过**"这道门。主人一句"杀后台再打开也是通话页"就把它抓出来了。 |
| **361** | ⭐⭐⭐ **桥可以自己注册 hook，不必动底座**。`FdmEntry.handleLoadPackage` 里拿 `lp.classLoader`（宿主自己的 ClassLoader）就能 `findAndHookMethod`，**完全绕开改 `GmEntry.smali` 的寄存器风险**。 |
| **362** | ⭐⭐ **备份必须"只备第一次"**：无条件覆盖 ⇒ 改 N 次后备份是"第 N-1 次的值" ⇒ 回不到最初。 |
| **363** | ⭐⭐ **"键不存在"必须用哨兵记下来**：否则恢复时分不清该 `remove` 还是该写空串 —— 而宿主大量用 `contains` 判断，留个空串等于留了个"存在但空"的坑。 |
| **364** | ⭐⭐ **`getString` 读未知类型的键会抛**，被 catch 吞掉就是**静默漏备**（61/86 个键中招）。读"不知道类型"的存储值，一律用**挨个试**的 `anyValue()`。 |
| **365** | ⭐ **生成物（GrayTable.kt）里的手工修正，必须在文件头钉警告**，否则下次重生成静默冲掉（同 341「重跑生成器本身就是一个改动」）。 |
| **366** | ⭐⭐⭐ **"开了开关没反应"要先问"是不是还有第二道闸"**。主人开了「语音输入」还是没麦克风 —— 真因是宿主 `pn5` 还看另一个键 `key_voice_available`，**而它默认 false**。宿主把"能力阀"和"用户开关"拆成两个键，是常见设计。 |
| **367** | ⭐⭐ **能力阀常常是"裸键 + 默认 false"**（`key_voice_available` 不带 `kv_` 前缀、也不在灰度字典里）⇒ 只按 `kv_remote_settings_*` 一套去找，永远找不到它。 |

### 语音输入的真闸门（实测挖出来的）

宿主 `pn5.<init>`（输入模式管理器）原文：

```smali
const/4 v2, 0x0                                      # v2 = ★false★（默认值）
const-string v4, "key_voice_available"
invoke-virtual {p1, v4, v2}, MMKV;->d(String, Z)Z     # ① 裸键，读不到就是 false

const-string v3, "kv_settings_voice_input_enabled"
invoke-virtual {p0, v3}, MMKV;->contains(String)Z      # ② 这条存在才用它
if-eqz v4, :cond_2f
invoke-virtual {p0, v3}, MMKV;->c(String)Z             # getBoolean
```

⇒ **两个都真，麦克风才出现**：

| # | 键 | 形态 | 默认 |
|---|---|---|---|
| ① | `key_voice_available` | **裸键**（不带 `kv_`）| **false** ← 主人漏的就是它 |
| ② | `kv_settings_voice_input_enabled` | `kv_settings_` 族 | — |

⇒ ① 已作为「**语音可用（总闸）**」加进灰度页（排在「语音输入」**上面**，hint 写明"两个都要开"）。
⇒ 顺带印证：3.42.39 修的**裸键支持**是必需的（`key_` 开头不加前缀，否则会写成 `kv_settings_key_...`）。
