## 2. 🐛 「长按复制不了」的真凶：又是一个方向反了的守卫

```smali
sget-boolean v0, Lcom/…/GmProbe;->sMoved:Z
if-eqz v0, :true        # ✗ 「没移动就跳过」—— 反了
```

**实际行为**：
- **长按（不挪动）** ⇒ `sMoved == false` ⇒ 命中 `if-eqz` ⇒ **跳走 ⇒ 什么都不做**（剪贴板当然是空的）❌
- **点击时手指带一点滑动（>16px）** ⇒ `sMoved == true` ⇒ 不跳 ⇒ 往下走 ⇒ 时长 < 400ms ⇒ `onClick` ✅

⇒ **完美解释**：「单击能出 dump（因为手抖挪动了），长按复制没反应（因为真的没挪动）」。

**正解**：`if-nez v0, :true` —— **没挪动 ⇒ 处理点击/长按；挪动过 ⇒ 跳过**。

> ⚠️ 这一处是 **2.22.62 我"修"的时候改错了方向**（把 `if-nez v0, :tap` 改成了 `if-eqz v0, :true`，看似"修了"，其实从一种错法换成了另一种错法）。**这是第 8 个方向类 bug。**

### 本轮 `if-*` 条件清单（教训 131 纪律）

| 指令 | 真实语义 | 我要的语义 | ✓ |
|---|---|---|---|
| `if-nez v3, :pass` ×6 | `equals == true` 就跳 | 命中白名单 ⇒ 放行 | ✓ |
| `goto :c2…:c6` | — | 不命中就查下一条 | ✓ |
| `goto :cond_8f` | — | 6 条都不命中 ⇒ **原样不动** | ✓ |
| `if-nez v0, :true` | `sMoved != 0` 就跳 | **挪动过 ⇒ 跳过点击/长按** | ✓（本轮修正） |
| `if-eqz v3, :true`（MOVE 分支） | `sMoved == 0` 就跳 | 没挪动 ⇒ 不更新位置 | ✓（未动，本来就是对的） |

## 4. 教训（155~158）

| # | 内容 |
|---|---|
| **155** | ⭐⭐⭐ **"数层数"天生会漏，"点名白名单"不会漏** —— `cnt<=6` 把 `cnt=6/7` 那两条真实的页面底色层漏在外面。⇒ **凡是"覆盖层全集"这种要求，用"枚举身份"而不是"截断位置"**（前者加一条是一条，后者总要在某处切一刀）。 |
| **156** | ⭐⭐⭐ **"看起来在工作的功能"可能只在"意外路径"上工作** —— 单击能出 dump（因为手指带滑动），长按不能（真的没动）⇒ **如果只看"单击正常"，会以为整个触摸逻辑是对的**。⇒ **验证交互功能时，必须把"每种动作的最纯粹形态"各试一次**（纯点不动 / 纯长按不动 / 纯拖拉）。 |
| **157** | ⭐⭐⭐ **同一个方向类 bug 我"修"过一次反而更错**：2.22.62 把 `if-nez v0, :tap` 改成 `if-eqz v0, :true`，**从一种错法换成了另一种错法**，而且当时自认为修好了。⇒ **改判据方向时，必须写下"改前是什么行为、改后是什么行为"两句话对账**，不能只判断"新写法看起来更合理"。 |
| **158** | ⭐ **关键输出要有"双通道"** —— 剪贴板受系统策略影响（后台/权限/厂商 ROM），所以 `onLong` 现在**同时写剪贴板 + 写模块日志**。⇒ **只要拿到数据的路不止一条，就不会被单一通道的系统限制卡死。** |
