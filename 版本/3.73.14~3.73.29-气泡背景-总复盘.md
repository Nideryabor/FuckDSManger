## 二、真正修好的三个问题（有据可查）

### 1. 死循环 → ANR（3.73.15 修）

```smali
:cond_89
    aget-object v2, v0, v2
    invoke-static {v1}, GmBubble->hostShape(ClassLoader)   # 2.7.2 恒抛 px6#o
    move-result-object v3
    if-eqz v3, :cond_89      # ✗ 取不到就跳回 :cond_89 = 每帧无限自旋
```

`:cond_89` 在**上面**。我 3.73.8 写"取不到就放行"，实际写成"取不到就跳回去重取"。
2.7.2 的 `px6` 没有 `o` 字段 ⇒ 恒 null ⇒ 主线程卡死。
**尸检铁证**：ANR 主线程栈里 `GmBubblePaintHook.ub` 出现 **28 次**。

修：`if-eqz` → `if-nez v3, :cond_skipdiag`（**向前**跳），并给 `hostShape` 加 `sShapeBad` 失败缓存（失败一次以后直接返回 null，不再构造异常）。

### 2. 宿主 2.7.2 方法改名（3.73.16 修）

| 原语 | 2.6.1 | 2.7.1 | **2.7.2（实测）** |
|---|---|---|---|
| 4 参刷子版 | `qk7.C` | `B` | **`x98.s`** |
| 3 参颜色版 | `qk7.D` | `C` / `z` | **`x98.t`** |

真机日志：`NoSuchMethodError: x98#B[...]` / `x98#z[...]`。
修：4 处调用点全改 `GmPrims`（按签名找：首参==返回类型 + 第3参是 Shape 实例），不再认名字。

⚠️ 顺带发现陷阱：`GmRemap` 表里的键是 **2.6.1 名**，`qk7.C` 指"刷子版"；但 2.7.1 起 `C` 是"颜色版"——**按字面查表会张冠李戴**。

### 3. 溢出（3.73.18 停用行级注入）

`wrap` 挂在 `cfb.g`（**整条消息行**）上，拿的是整行的 Modifier ⇒ 一注入，气泡/代码块/复制按钮/工具栏全被套同一张图。
**结构上的必然结果**，不是调参能救的。3.73.18 停掉调用点（不调 `wrap`，直接 `move-object v5, v3` 让下面的 `if-eq` 不成立）。

## 三、气泡背景为什么没修好（静态分析结论）

### 宿主真实实现（`l23.a` = AppSurface）

```smali
.method public static final a(Lyj7;Lsy9;JJLr33;Lr15;I)V
    move-wide/from16 v3, p2                        # v3 = args[2] 底色
    :cond_a0
    invoke-static {p0, p1}, Lvcc;->B(Lyj7;Lsy9;)   # 先按 shape 裁剪
    move-result-object v10
    invoke-static {v10, v3, v4, v11}, Lx98;->t()   # ★ 气泡底色就是这行画的
```

**两条铁结论：**
1. 气泡底色**只有这一处**，颜色来自 `args[2]`
2. 想换图片必须 **同时** 改 `args[0]`（挂 background）**和** `args[2]`（置透明 0）
   —— 只改 `args[0]` 会被宿主自己的 `x98.t` 盖住

### 我最大的判断错误

3.73.16 看到"AI 气泡有背景了"，就认定 `ub()` 这条路打通。
**那是 `wrap` 的功劳。** 之后围绕 `ub()` 改了六版，全在修一条从没通过的路。
3.73.18 停 `wrap` 时以为气泡级注入会接住 ⇒ **AI 气泡背景也一起没了**。

## ★ 附：if-* 真值表（本项目已栽 10 次，写代码前逐个对）

| 指令 | 含义 |
|---|---|
| `if-eqz v` | v **== 0** 则跳 |
| `if-nez v` | v **!= 0** 则跳 |
| `if-ltz v` | v **< 0** 则跳 |
| `if-gez v` | v **>= 0** 则跳 |
| `if-gtz v` | v **> 0** 则跳 |
| `if-lez v` | v **<= 0** 则跳 |
| `if-eq v1,v2` | v1 **== v2** 则跳 |
| `if-ne v1,v2` | v1 **!= v2** 则跳 |
| `if-lt v1,v2` | v1 **< v2** 则跳 |
| `if-ge v1,v2` | v1 **>= v2** 则跳 |

⚠️ 单寄存器 vs 0 **只能用 `if-*z`**；用 `if-gt v, :x` 会汇编报错。
⚠️ 写"放行/跳过"前先看标签在**上面还是下面** —— 往回跳 = 死循环。

### 今天 10 次反判断清单

1. `if-eqz v3, :cond_89`（往回跳 ⇒ 死循环）
2. `if-gt` 用于寄存器 vs 0（汇编报错）
3. `if-lez → 放行` 语义反
4. `if-lez v6 → useUImgName`（用户/助手整体颠倒）
5. `if-nez v3, :cond_shapeok`（放行变 return）
6. `if-eq v4, v5, :cond_cast`（同上）
7. `if-nez v6, :cond_img`（透明判断反）
8. `if-lt v10, v11, :cond_ret`（日志抑制反）
9. `if-eq(校验) → 继续` 写成 `if-ne`
10. `if-eq v0, v1, :cond_notsurf`（7 参分流反，=7 反而跳过）
