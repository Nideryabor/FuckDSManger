# FuckDSManger 2.10.0-probe（探针版）

> 综述：新功能「**回复建议**」的**可行性探针** —— 验证「借用宿主自带的 `PromptTemplateView`（上传文件后的快捷回复那排按钮）来渲染我们的追问按钮」这条路是否成立。
> 产物：`FuckDSManger_2.10.0-probe_for_ds2.5.2.apk`（118 / 2.10.0，**83 类**，V1+V2+V3）
> 完整逆向过程与判读表：**`专题/回复建议.md`**

---

## 一、为什么先打探针

需求要求「把按钮追加在 AI 最新回复下方」。聊天页是**纯 Compose**（项目铁律 #9：不碰 Compose），
自绘悬浮条要自己解决「位置从哪来」；而主人提醒的宿主自带组件（图片/文档上传后的快捷回复）
**与我们同构**（一排按钮 → 点击即发消息），且**位置天生就在输入框上方**（＝最后一条回复下方）。

⇒ 与其盲写大功能，先花一版验证「能不能借到那排按钮」，成本极低、信息量极大（铁律 #8 的思路）。

## 二、本版改动

| # | 目标 | 改动 |
|---|---|---|
| 1 | **新增** `GmSuggestHook` | `XC_MethodHook` 子类：命中时首次打日志 `promptView hit list=N`；**若 N==0 ⇒ 把 `args[0]` 换成 3 条写死的测试建议** |
| 2 | `DisableFlagSecure`（主类） | 注册 `hookM("yb5", "f", GmSuggestHook)`；banner 日志 `v2.9.30 → v2.10.0` |
| 3 | `.../the_big_won_whale/DisableFlagSecure` | banner 日志 `v2.9.30 → v2.10.0`（防僵尸版本号） |
| 4 | `AndroidManifest.xml` | `117 / 2.9.30 → 118 / 2.10.0` |

**hook 点**：`Lyb5;->f(Ljava/util/List;Lwv3;Lc76;ZLwv3;ZLey3;I)V`
＝ `com.deepseek.chat.ui.pages.chat.session.input.prompt.PromptTemplateViewImpl (PromptTemplateView.kt:185)`

**构造按钮数据**（`Lg56;` = `ModelConfig.PromptTemplate`）：

```smali
const/4 v1, 0x7            # Kotlin 默认参数位掩码（必须 (mask & 7) == 7）
const/16 v2, 0x2329        # id 9001，避开宿主内置 9/10/11/13/14/15
const-string v3, "default" # scene
const-string v4, "…"       # content = 按钮文案 = 点一下发出去的文字
invoke-direct {v0, v1, v2, v3, v4}, Lg56;-><init>(IILjava/lang/String;Ljava/lang/String;)V
```

> 关键实证：`Lpd5;->I(tpl, ctx)` 在 `tpl.d == null` 时**直接返回 `tpl.c`** ⇒ 只要不填 resId，宿主就用我们的 `content` 当文案/发送内容。

## 三、真机验收步骤

```
1. 安装 FuckDSManger_2.10.0-probe_for_ds2.5.2.apk（覆盖安装即可）
2. 强制停止宿主 App（com.deepseek.chat.a）→ 重新打开 → 进任意一个会话
3. 看 LSPosed 日志：应出现一行  promptView hit list=0
4. 看输入框上方：应出现 3 个按钮 ——「能再展开讲讲吗？」「举个具体的例子」「用表格总结一下」
5. 点其中一个：应按宿主原生行为把该文字当用户消息发出去、AI 开始回复
```

判读表（出现不同结果分别意味着什么、下一步怎么改）见 `专题/回复建议.md` 第四节。
