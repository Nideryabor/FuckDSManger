## 一、点不动：DecorView 子 view 拿不到「窗口级触摸」

2.13.x 把 🎧 作为 **DecorView 的子 view**（`addView` + `bringToFront`）。结果：
**绘制**能被我抢到手（所以看得见），但**触摸**归**窗口**管 —— 宿主那层全屏 Compose 视图把点击吃掉了；`bringToFront()` 只改绘制顺序，改不了窗口内的触摸归属。

**2.14.0 ⇒ 改用 `PopupWindow`**（独立窗口，永远在 activity 窗口之上、永远收得到点击、**不需要悬浮窗权限**）：

```java
PopupWindow pop = new PopupWindow(view, dp44, dp44);
pop.setClippingEnabled(false); pop.setOutsideTouchable(false); pop.setFocusable(false);
pop.showAtLocation(decorView, Gravity.TOP|Gravity.LEFT /*0x33*/, sX, sY);
// 拖动 → pop.update(sX, sY, -1, -1)
```

顺带好处：**不再需要**「查是不是最后一个 child / 被盖住就 bringToFront」那套逻辑（`ensure()` 现在只看 `sPop == null || !isShowing()`），代码反而简单了。
另外把触摸全程打点：`悬浮钮按下` / `悬浮钮点击 → 开通话页` / `悬浮钮拖动结束（不触发点击）` —— 下次若还"没反应"，日志能直接说明**触摸到底有没有到我这里**。

## 二、另开新对话：`ao1.I()` 的会话取自 **component 自己的状态**

读了宿主 `Lao1;->I(Lyp1;)V` 的真身（158 条指令）：

```
v1 = yp1.b()                       // 文本
if (!this.u.e(text)) return;       // 校验
v1 = this.v.getValue()  → ho1
if (v1 instanceof fo1) return;     // 忙碌守卫
v1 = ho1.b() → wr                  // ⭐ 会话对象
v2 = wr.a                          // ⭐⭐ 会话 id ←—— 决定"发到哪个会话"
v10 = yp1.a.i()                    // 附件
...
tya.l(sessionId, …, wr.h() ?: this.N(), …)   // 埋点
... z61.k(this.L().a) 遍历附件 ...
```

⇒ **会话 id 来自 `this.v`（component 的状态）**，而 `this` 是**按会话构造**的（`Lao1;-><init>(Lwr;…)` 第一个参数就是会话对象 ⇒ 每次加载会话会 new 一个 component）。

**2.13.x 的错**：我反射 `new yp1()` 造了个**全新输入状态**去发 ⇒ 丢掉宿主真实的输入上下文 ⇒ 落到"新会话"。
（本项目 `专题/回复建议.md` **2.10.9 就写过这条教训**：「复用真实 `yp1`，不再 `new yp1()`」——我没照抄。）

**2.14.0 ⇒ 复用真实的一对对象**：

- `GmCallHook`（挂在 `ao1.I` 上）现在同时抓 **`thisObject`（component）** 与 **`args[0]`（真实 `yp1`）** → `sAo1` / `sYp1`
- `send()`：`callMethod(sYp1,"c",text)` → `callMethod(sAo1,"I",sYp1)` ⇒ 与"用户自己打字点发送"走**完全相同的对象**
- **`sAo1`/`sYp1` 为空时不再硬发**，改为 Toast：**「请先在当前对话里手动发一条消息（模块要复用宿主的发送上下文，否则会另开会话）」**

**同时移除了 `ao1.J` 的注册**：`J` 是总命令入口（send/regenerate/edit/stop 都走它），会在非发送时机刷新 `sAo1`，容易把上下文刷成别的 component ⇒ 只认 `ao1.I`（真正的"发送"）。
