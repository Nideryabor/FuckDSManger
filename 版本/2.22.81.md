## 0. 先回答主人的问题：**判据没有写反**

把 `pg` 的试验台门逐条念一遍：

```smali
sget-object v7, GmBubble->sAblateCur
if-eqz v7, :no_ablate          # sAblateCur == null ⇒ 跳过 ✓
invoke {v1, v7}, equals → v7
if-eqz v7, :no_ablate          # 不相等 ⇒ 跳过 ✓
<置 0 并 return>                ✓
```

**方向是对的。** 但 **"点了必然没反应"** —— 因为**模型错了**：

> ⭐ **同一个层有多个绘制来源。**
> `#292929` 这个颜色，**已经由两个调用点在画**：`ob8.a:82` **和** `vz8.c:58`（`2.22.79` 就是靠这个事实加的白名单）。
> ⇒ **只把其中一个来源置 0，另一笔照画 ⇒ 肉眼毫无变化。**

**⇒「逐个替换」这个模型本身是错的，应该是「逐个叠加」。**

## 3. 教训（193~196）

| # | 内容 |
|---|---|
| **193** | ⭐⭐⭐ **"多来源"是这个专题的底层事实，它已经咬了我第五次** —— `#0F0F0F` 有 5 个来源 · `#292929` 有 2 个 · `#507BF2` 有 2 个。⇒ **凡是"要作用在某个可见对象上"的改动（透空/消融/染色），都必须假设"这个对象由多笔绘制叠加而成"** ⇒ **手段必须是"叠加式/集合式"，不是"单点式"。** |
| **194** | ⭐⭐⭐ **试验台必须自带"命中计数"** —— "有没有生效"不能靠用户描述（"没反应"可能是"生效了但看不见"）。⇒ **把"命中次数"和"切换动作"绑在同一句回执里**（本版：下次点击的 Toast 报上一个状态命中几次）。 |
| **195** | ⭐⭐ **判据"写对"和"模型对"是两件事** —— 主人问"是不是又写反了"，我逐条念过：**判据方向没错**；错的是我**对"消融一个来源 = 消融整个元素"的假设**。⇒ **当"代码明明对、结果就是不对"时，要去检查"我默认成立的那个前提"。** |
