## 2. 本次四处修复

### ① 🔑 让图**真的插到底**（`GmBg.ensure`）

```smali
# 改前：只有 pos == 1 才插到 index 0
    invoke-static {p0}, GmBg->pos(Context)I
    move-result v8
    const/4 v9, 0x1
    if-ne v8, v9, :cond_e5
    const/4 v8, 0x0
    invoke-virtual {v6, v5, v8, v7}, ViewGroup;->addView(View;I;LayoutParams)V

# 改后：pos != 0（即「底图」或「混合」）都插到 index 0
    invoke-static {p0}, GmBg->pos(Context)I
    move-result v8
    if-eqz v8, :cond_e5                                  # ★
    const/4 v8, 0x0
    invoke-virtual {v6, v5, v8, v7}, ViewGroup;->addView(View;I;LayoutParams)V
```

**⇒ 图现在插到 `decorView` 的 index 0 = 真正的**最底层**；只有 `pos=0`（蒙层）仍走上层。**

### ② 去掉**内容层**的混合（`GmBg.setBlend`）

```smali
# 改前：pos==1 时给 android.R.id.content 设 BlendMode（白天 MULTIPLY / 夜间 SCREEN）
#        ⇒ 整个内容层跟底图相乘 ⇒ 看起来「半透明」
# 改后：
    const/4 v1, 0x0
    invoke-virtual {v0, v1}, Landroid/view/View;->setBlendMode(Landroid/graphics/BlendMode;)V   # null = 不混合
```

**⇒ 内容不再被混合，气泡/文字是干净的实心覆盖在图上。**

### ③ 去掉**图自己**的混合（`GmBg.ensure` 里的 `GmBgView.setBlend`）

```smali
# 改前：pos == 2 时按 dirMul 给 GmBgView 设 setBlend(1 或 2)
# 改后：
    invoke-static {p0}, GmBg->pos(Context)I
    move-result v6
    goto :cond_c4                      # ★ 直接跳过（原逻辑保留为死代码，便于回滚）
```

### ④ 让「图片透明度」对图片底也生效（`GmAlphaHook`）

```smali
# 改前：发现 Brush 是我们的 GmBmpShader 就整段跳过
    const-string v1, "b"
    invoke-static {v0, v1}, XposedHelpers->getObjectField(Object;String)Object
    move-result-object v1
    instance-of v2, v1, Lcom/varuns2002/disable_flag_secure/gm/GmBmpShader;
    if-eqz v2, :end                    # ← 删掉这两行
# 改后：直接往下走，照常写入 alphaF()
```

⇒ **「图片透明度」±10% 现在对图片底也真的生效了**（主人的第 3 条观察已修）。

## 6. 教训（819~820）

| # | 内容 |

| **819** | ⭐⭐⭐ **「半透明感」不一定是 alpha，可能是「图层顺序 + 混合」**：我花了 5 个版本在 Compose 层追 alpha、颜色、作用域，而真凶是 **View 层的 `addView` 索引**（图被追加到最上层）。⇒ **排查"看不见/透出来"类问题时，先确定「谁在谁上面」，再谈"透明多少"。** |
