## 二、本轮最值钱的 8 条教训

| # | 教训 |
|---|---|
| **D** | ⭐⭐⭐ **「必须同时成立」的两步，一步换名即变毒药** —— 图片替换要「改 `tv.string`」+「`getDrawable` 返回 BitmapDrawable」。前者挂着、后者 `findClass("dec")` 失败 ⇒ 宿主把 `fdm_replaced` 当位图解析 ⇒ **首页头像变蓝方块**。凡成对 hook，**A 挂上而 B 挂了，必须立刻把 A 也关掉** |
| **E** | ⭐⭐⭐ **拆类会让同一旧类的两个方法跑到两个新类** —— `dec.w(clip)→ee.s` 但 `dec.U→pac.y`。表里一行只记一个类，遇到必须**拆成两个语义键** |
| **F** | ⭐⭐⭐ **能派生就不要写死** —— `q88.g` 的首参从 `(X,long,float,Paint)` 形状反推，比再写死一个 `d34` 强 |
| **G** | ⭐⭐ **`findClass` 失败是静默的** —— 必须加「表里没键就抛」的硬闸 |
| **H** | ⭐⭐⭐ **资源 id 会漂移，一律按资源名** —— `profile_check_for_updates_newest` 在 2.7.5 是 `0x7f0f0267`、2.8.0 是 `0x7f0f0275`；而 `GmResTextHook` 写死的 `0x7f0f021f` 在 2.8.0 已指向**「思考时长」** |
| **N** | ⭐⭐⭐ **`y37.C` 只能改路径，改不了域名** —— 传整条 `https://127.0.0.1:1/...` 会被 Ktor 拼成 `https://chat.deepseek.com/https://127.0.0.1:1/...`（抓包铁证）。域名来自 `sib.d:Luib`，路径在 `sib.a` |
| **O** | ⭐⭐⭐ **服务端对未知路径返回 200 而非 404** —— 换路径**根本不算拦住**：`/__fdm_disabled__/check_client_update` 照样 200 + `biz_data:null`，宿主认为「检查完成」 |
| **P** | ⭐⭐⭐ **两个入口各弹各的 ⇒ 叠窗** —— 选择页是进程内 Compose（24ms 弹出），旧 hook 的点击要等 Composition 重绘（晚 1.26s）。**必须明确分工：一个负责弹、一个只记录** |

## 四、最终方案：三层拦截

| 层 | 落点 | 效果 | 零 R8 依赖 |
|---|---|---|---|
| **① 请求层** | `sib.b()` 抛 `IllegalStateException` | URL 都构不出来 ⇒ **零外发流量** | ✅ 只按 `check_client_update` 字符串判断 |
| **② 显示层** | `Resources/Context.getString` 按**资源名**匹配 | 命中给空串 | ✅ 运行时 `getIdentifier` |
| **③ 入口层** | `FdmUpdateIntercept.maybeShowChoice` → `FdmComposeDialog.tryShowChoice` | **进程内 Compose 选择页** | ✅ 不碰混淆名 |

### 4.1 选择页为什么必须内嵌

| 方案 | 结果 |
|---|---|
| 跨进程 `startActivity` 显式 | ❌ `ActivityNotFoundException`（包可见性）——实测 **5 次成功 1 次** |
| `fdm://open` scheme | ❌ 0/4 |
| 显式组件广播 | ❌ 0/4 |
| **进程内 ComposeView** | ✅ **100%**，而且**不用关隐藏应用列表** |

**根因**：宿主 `targetSdk=36`，`<queries>` 只声明了微信/GMS/华为/荣耀音频引擎，**没有我们** ⇒ 跨包查询全被过滤。

### 4.2 选择页 UI（复用 `FallbackHost`）

```
┌─────────────────────────────────┐
│ 检查更新                          │
│ 这一行已被 FuckDSManger 接管。      │
│ · 打开模块：进入插件自身的设置界面    │
│ · 检查宿主更新：走宿主原本的检查更新  │
│ [ 打开模块 ]    [ 检查宿主更新 ]    │
└─────────────────────────────────┘
```

复用 `FdmComposeDialog.show()` 的「ComposeView + 三件套 owner + 手工 recomposer」——
2026-11-07 血证：少一样就 `IllegalStateException: ViewTreeLifecycleOwner not found`（下一帧才炸，catch 不到）。

## 五之二、3.106.1 → 3.106.5 收尾（四条真机反馈驱动的修补）

| 版本 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **3.106.1** | 点一次弹**两个**窗 | 选择页进程内 Compose 24ms 弹出；旧 `FdmUpdateRowJumpHook` 的点击要等 Composition 重绘，**晚 1.26s 抢跑** | 旧 hook **停用拉起**，只记录；并把 `FdmUiHook` 的「假成功 `return true`」改成 `false` |
| **3.106.2** | 选择页只弹**一次**，之后"点了没反应" | 我把选择页挂在 `getString(标题)` 上 —— 那个串**只在设置页首次渲染时取一次** | 改挂**真正的点击入口** `FdmUpdateRowJumpHook`（宿主 `updatevm.check`）→ `FdmUpdateIntercept.showChoiceFromHook(ctx)` |
| **3.106.3** | 点「打开模块」没反应 | 跨进程三路全被**包可见性**挡 | 双路：先试跨进程 + 兜底 `GmHomeUi.open()`（进程内旧 View UI）|
| **3.106.4** | 兜底要的是**保底卡片**，不是旧 View UI | 主人指定 | 兜底改为 `FdmFallbackDialog.show(...)` |
| **3.106.5** | 保底卡片**代码跑了但屏幕没有** | `FdmFallbackDialog.show()` 里两道防重入闸（① 已有 Dialog 在显示 ② 2s 窗口）把选择页自己的 Dialog 也算进去了 | 新增 **`showForce()`**：先 `FdmComposeDialog.dismissShowing()` 关选择页、清闸，再弹 |

### 保底为什么会被自己的闸挡住（值得记）

```
22:43:26.924  【FdmUpdateIntercept】选择页：已弹保底卡片（兜底）   ← 日志打了
（屏幕上什么都没有）                                              ← 被闸挡住
```
两道闸是 2026-11-07 为「一次点击弹两个保底」加的 —— 那场景是**两条路各自弹保底**，
和「选择页 → 用户主动点按钮 → 要弹保底」完全不同。⇒ 主动场景必须有后门。
