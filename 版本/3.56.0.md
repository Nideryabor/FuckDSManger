## 四、教训

**931 · ⭐⭐⭐ 「撤掉文件」不等于「撤掉数据」—— 工作区层和历史层是两套账。**
主人当初写了 6 个 `chore(security): 撤掉…`、甚至留了句 `_别带我进仓库.md`，
**工作区确实干净了**，但 git 历史里那 58 个路径**一个都没少**。
⇒ **凡是"不公开"的东西，动手前先问：它在历史里躺过没有**（`git log --diff-filter=D` 一查便知）。

**932 · ⭐⭐⭐ 删文件要趁「还没提交」，一旦提交就只能重写历史。**
本轮代价：`git filter-repo` 重写 326 个提交 + 强推 + 换钥 + 重发版。
**如果当初进门之前加一行 `.gitignore`，这一切都不需要。**

**933 · ⭐⭐ 重写历史只改「指针」，不改「对象」——别把强推当"已删除"。**
强推完实测：旧提交仍能 `git fetch`、私钥 blob 仍能按 SHA 取出。
⇒ **判断"数据删干净了没有"，必须用干净克隆去实测**，不能看"操作成功"。

**934 · ⭐⭐⭐ `watchers = 0` 不等于「没人会捞」。**
主人拿 0 watch 质疑风险，方向对了一半：**确实没人专门盯**（`forks=0` 是最硬的证据）。
但**来捞密钥的不是人，是机器** —— 代码搜索索引、push 事件数据集、爬虫，**都不看 watchers**。
⇒ **衡量"有没有被看见"，要看索引/数据集/搜索命中，不是看关注数。**

**935 · ⭐⭐ 口令写在文档里 = 钥匙插在锁上。**
本轮把「密钥文件不入库」做得很好（`.gitignore` 挡了文件名），
**却把口令明文写在 `mod-src/README.md`** —— 而那个文件是入库的。
⇒ **"密钥不入库"要连"口令/别名/路径"一起管**：文档里只写占位符。

**936 · ⭐⭐ 换钥要连带改「文档里的指纹表」，否则以后核对会认错钥。**
`mod-src/README.md` 那张 SHA-1/SHA-256 表是**用来核对产物**的 ——
只换钥不改表 ⇒ 下次自检会拿旧指纹比新包，白排查一轮。

**937 · ⭐ 顺手修掉一个文档小谎：本项目是 V2+V3 签名，不是 V1+V2+V3。**
`minSdk 26` ⇒ apksigner 不生成 v1（JAR）签名。旧文档一直写「V1+V2+V3」，
实测 3.55.1 与 3.56.0 都是 `Verified using v1 scheme: false` ⇒ 已改口。
⇒ **签名说法别照抄，`apksigner verify -v` 的输出才是事实。**
