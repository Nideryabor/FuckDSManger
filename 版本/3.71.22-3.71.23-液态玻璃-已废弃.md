## 二、教训（这是本篇唯一有价值的部分）

| # | 教训 |
|---|---|
| **AS** | ⭐⭐⭐ **"技术上做出来了" ≠ "好看"。** 液态玻璃管线确实跑通了（GPU 模糊 + AGSL 折射，截图能证明），但**在一块 311×320dp 的深色悬浮卡上，折射把底下的文字掰弯 = 花掉的乱纹**。iOS 的迷你卡用 `SystemThinMaterialDark`（**只模糊、不折射**）不是偷懒，是因为小元件上的折射就是脏。<br>**下次动手前先问：这个尺寸/这个用途，参照物为什么选了那个材质？** |
| **AT** | ⭐⭐ **`PixelCopy` 的回调会永远不回来。** `glass/` 里的 `GmGlassBackdrop` 已经踩过并写了 `STUCK_MS = 2500` 看门狗 + `sCapturing` 防自反馈 + `MIN_GAP_MS = 260` 限流。我自己重写一份时**只抄了限流、漏了看门狗** ⇒ `glassCapturing` 永久 true ⇒ 之后每次调用都在第一行 return，**一条日志都没有**。<br>⇒ **复用踩过坑的代码时，要把它的"防御"跟"功能"一起抄。** |
| **AU** | ⭐⭐ **静默 return 是排查的最大障碍。** 3.71.22 上"底图永远 null"查了两轮，全是因为第一行 `if (glassCapturing) return;` 连日志都不打。**任何"守卫导致跳过"的分支都该留一行日志**（这条在 `专题/待办与遗留.md` 的教训 96 里已经写过一次，又犯了）。 |
| **AV** | ⭐ **"换位置会闪" 的正解就在架构里。** v3 底图是"卡片区域截图" ⇒ 一动就必须重抓 ⇒ 闪。v4 底图是"整窗缩略图 + 绘制时按 `(ox,oy)` 裁切" ⇒ **移动零重抓**。这个思路是对的（`GmGlassGpu` 的 `stretch=false` 分支本来就是为它设计的），只是配上折射太丑。**换成"只模糊不折射"的话这条路可以复用。** |

### 如果以后还想试（处方）

v4 里**只有一处是真正值得保留的**：整窗底图 + 按坐标裁切（零重抓、零闪）。

想救的话，把 `onDraw` 里的调用从：

```java
GmGlassPanel.drawAt(canvas, glassBack, ox, oy, w, h, r,
        blurPx, 0x22FFFFFF, /*dispersion*/ 1.2f, ENGINE_HAZE, ...);
```

改成 **只模糊、不折射**：

```java
// 直接用 RenderEffect.createBlurEffect，跳过 createRuntimeShaderEffect
// ⇒ 就是一张"会跟着卡片移动的真·模糊背景"，没有折射乱纹
// ⇒ 等价于 iOS 的 SystemThinMaterialDark
```

再把 UI 两处（队列按钮文字 / 加减号）从 v4 拷回来 —— **那两条主人是认的**（当时真机点了三次「切换 搜索结果/队列」，日志有）。
