**已排除的可能**：

1. `pg` 没被调用 —— ✗ 已回读 `beforeHookedMethod`，`invoke-static …->pg(...)V` **就在 `dg` 后面一行**
2. `pg` 逻辑写错 —— ✗ 已回读 `pg` 全文，`if-lez`（depth）· `if-ge`（cnt）· `if-eqz`（args）· `if-lt`（len）· `if-eqz`（name）· 哨兵，**逐条核对全部正确**

## 1. 本版改动（两件事，都为了让 A/B 可分）

### ① `pg` 每个卡点前写入 `sPgWhy`（新字段 `GmBubble.sPgWhy:I`）

| `why=` | 含义 |
|---|---|
| **1** | `sPageDepth <= 0`（不在 ChatPage 作用域内） |
| **2** | `sPageCnt >= 4`（本页配额用完） |
| **3** | `args == null` |
| **4** | `args.length < 2` |
| **5** | 方法名不是 `v` |
| **6** | **哨兵命中**（`args[1]` 等于我们的注入色） |
| **0** | ✅ **判据链全通过**（此时 `sPageCnt` 已 +1） |
| **7** | `GmBg.real()` 返回 false（背景没开，或档位是「蒙层」） |

### ② `pg` 的 `catchall` 不再静默

```smali
    :catchall_0
    move-exception v0
    const-string v1, "[实化] pg 内部异常（已吞）"
    invoke-static {v1, v0}, GmUtil;->logFail(...)V      # ★ 以前这里什么都没有
    return-void
```

### ③ `dg` 的日志加上 `why=` 字段

```
[实化] bg#N depth=D cnt=C why=W <方法名> = <args[1]>
```

> `dg` 在 `pg` **之前**执行 ⇒ 打出来的是**上一次 `pg` 留下的卡点编号**（对连续调用完全够用）。

## 2. 主人验证（只要一行 `why=`）

装 `2.22.41` → 强停 → 进聊天页 → 搜「实化」，重点看：

```
[实化] bg#2 depth=1 cnt=0 why=? v = -67818912288342016
```

把这几行的 `why=` 值发我即可：

- **`why=1~7`** ⇒ 我立刻知道卡在哪个判据，直接对症修
- **`why=0`** ⇒ 判据全过了（那就是**透明化执行了但效果没显现**，方向要换到宿主那侧）
- **出现 `[实化] pg 内部异常（已吞）`** ⇒ 是异常路线（堆栈会一起打出来）

## 3. 教训（813~814）

| # | 内容 |
|---|---|
| **813** | ⭐⭐⭐ **「静默 catchall」会让「抛异常」和「正常返回」完全无法区分**：`pg` 从 2.22.32 起就带着 `catchall → return-void`，于是「它因为异常提前退出」这件事**连一层日志都没有** —— 我只能靠「`cnt` 不动」反推它没跑完，却分不出是**跳走**还是**炸了**。⇒ **每个自定义的 catchall，至少留一行 `logFail`**（这条在教训 807 写过，**又一次栽在同一件事上**）。 |
| **814** | ⭐⭐ **「给每个分支编号」是排查判据链的最短路径**：与其在 6 条分支上各写一条日志（代码翻倍、还要读 6 行），不如**用一个 `int` 记录「最后停在第几号检查」**，在别处一次性打出来。**一个变量 = 整条判据链的状态快照。** |
