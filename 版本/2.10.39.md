# FuckDSManger 2.10.39（回复建议 · 主人观察摘清我们的锅 + dump 我们自建的对象）

> 产物：`FuckDSManger_2.10.39_for_ds2.5.2.apk`（**190 / 2.10.39**，91 类，V1+V2+V3，sha256(partial) `0b714675…`）
> 触发：主人关键观察 —— **关掉总开关后，宿主用自己的文案，同样不显示字**

## 一、🎯 这条观察把我们的锅摘清了

| 事实 | 推论 |
|---|---|
| 总开关 OFF（我们完全不介入） | 宿主用自己的数据渲染 |
| **宿主的文案同样不显示** | ⇒ **"空壳"是宿主自己的行为**，与"回复建议"逻辑无关 |

顺手排查了模块里挂在 `Resources.getString/getText` 上的既有代码 **`GmResTextHook`**：

```smali
    const v1, 0x7f0f021f          ← 只针对这一个 id
    if-ne v0, v1, :cond_1c
    setResult("FuckDSManger")     ← 把它换成模块名
    :cond_1c 返回（其余全部放行）
```

⇒ **它不是元凶**（不会清空任何文本，只替换一个特定 id）✓

## 二、由此确立的结论

**chip 的标签来自 `contentRes`（资源 id）**；而服务器下发的数据里 `contentRes=null`
⇒ `getString` 不会被调用 ⇒ **一片空白** ✓（这也解释了"以前有字、现在没字"）

## 三、但我们的假 id 也没触发 `getString` —— 所以要查我们自己造的对象

2.10.37 我们给 `d` 塞了 `0x7f7f0000+i`，日志里**没有**「按资源 id 接管」⇒
可能我们的字段**根本没写进去**（`put` 静默失败？对象不对？）

### 本版：dump **我们自己造的对象**

```smali
    inst = newInstance(...) ; 写 a/c/d
    dumpObj(inst)      ← ★ 打印我们对象自己的字段与值（logOnce 一次）
    list.add(inst)
```

（原来对"宿主对象"的那次 dump 已移除，避免占用同一个 logOnce 键。）

```
2. 进会话 → 传图（别发送）
3. 日志搜「字段」，把这一行发我：
      [建议] g56 字段 → a:int=? | b:String=? | c:String=? | d:Integer=? | …
```

| 若 dump 显示 | 结论 | 下一步 |
|---|---|---|
| `c=能再展开讲讲吗？` `d=2138898432(0x7f7f0000)` | 我们的写入**成功** | 那 chip 就是不读这些字段 ⇒ 换自绘路线 |
| `c=?`（空）或 `d=?` | **写入失败**（字段名/类型不符） | 按 `put` 的失败日志（`suggest.set`）精准修正 |
