## 二、真凶：网易云接口在拒绝（**不是我们的逻辑**）

```
【Music】[MusicApi] POST https://interface.music.163.com/eapi/search/get → 200，正文 54 字，Set-Cookie 136 字
【Music】[MusicApi] search code=405
```

* 正文只有 **54 字** ⇒ 是**错误响应**，不是"没有结果"；
* `code=405` ⇒ 接口**拒绝**（限流 / 登录失效一类的权限问题）；
* 我们**一直带着 `MUSIC_U`**（`GmMusicLogin.load()` → `GmMusicApi.setLogin(mu)`，登录态 uid=8444474100 已读回）⇒ 不是"没带凭证"；
* 时间线：**我们之前在短时间内搜了 189 次**（就是 3.69.5 修掉的那个"重复执行"造成的）
  ⇒ 极可能**把接口打进了限流**。

### 而且提示是**误导**的（这是我们的锅）

`GmMusicPlayer.search()` 在接口出错时只返回**空列表** ⇒ 调用方分不清
「这首歌真搜不到」和「接口不让搜」⇒ 用户看到的是「♪ 没搜到「红色高跟鞋」」，
**而歌明明有**。

## 三、修法

### ① 让"接口拒绝"可被识别

```java
// GmMusicApi
private static volatile int sLastCode = -1;
public static int lastCode() { return sLastCode; }
// eapiPost 里：非 200 ⇒ 记下 code **并打印响应体**（54 字，排查的唯一线索）
if (c != 200) d("[MusicApi] " + uri + " 非 200 ⇒ code=" + c + " · " + brief(raw));
```

### ② 点歌侧分开处理

```java
int code = GmMusicApi.lastCode();
if (list 空 && code != 200 && code != -1) {
    if (noteApiError(code)) {
        toast("♪ 网易云拒绝了搜索（code=" + code + "）—— 可能被限流，稍后再试；一直不行就去音乐页重新登录");
    }
    return;                       // ★ 不做兜底搜索（别再打接口）
}
```

### ③ 报错冷却 20 秒

`API_COOLDOWN_MS = 20000`：一旦发现 `code != 200`，
20 秒内**不再发搜索**（`apiCooling()`），且这段窗口里**只提示一次**。

★ 理由：接口拒绝时继续重试**只会越打越狠**（我们就是这么进的限流）。

### ④ 顺手收紧 `djgate` 诊断

原来只要文本里有 `DJ` 两个字就记一条 —— 真机日志里被模型正文
「…所以用 **DJ** 标记」误触发了一次。⇒ 改成必须含 `DJ:`。

## 六、教训

**1097 · ⭐⭐⭐ 「空结果」和「出错了」必须分开 —— 不然提示会骗人。**
　　`search()` 用"空列表"同时表示"没有"和"失败"⇒ 用户看到「没搜到「红色高跟鞋」」，
　　而真实原因是接口返回 `code=405`。**歌明明有，界面却说没有** —— 这是最坏的那种错。
　　★ 判据：**任何"返回集合"的接口，都要能区分"空"与"失败"**
　　（返回值、错误码、异常，选一样，但必须能区分）。

**1098 · ⭐⭐⭐ 出错时的第一反应是"退避"，不是"重试"。**
　　接口拒绝（限流/风控）时继续打只会更糟。⇒ 冷却 20 秒 + 一个窗口只提示一次。
　　★ 这条和 3.69.5 的"去重"是一对：去重治"我们自己的重复"，冷却治"被拒绝后还硬打"。

**1099 · ⭐⭐ 出错的**响应体**一定要打出来（哪怕只有 54 字）。**
　　这次就是靠"正文 54 字"判断出"是错误响应而不是空结果"。
　　⇒ 非 200 时把 `code` + `brief(raw)` 一起打 —— 排查时这是唯一能直接读到的线索。

**1100 · ⭐ 诊断日志的条件要写紧一点。**
　　`djgate` 原本只要正文含 `DJ` 就记一条，结果被模型的正常文字
　　「…所以用 DJ 标记」误导了一次。⇒ 诊断的条件宁紧勿松（要 `DJ:` 而不是 `DJ`）。
