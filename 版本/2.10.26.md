# FuckDSManger 2.10.26（回复建议 · `tryCtor` 按参数个数分流 ⇒ 适配真实的 3 参构造器）

> 产物：`FuckDSManger_2.10.26_for_ds2.5.2.apk`（**177 / 2.10.26**，90 类，V1+V2+V3，sha256(partial) `1ab2e453…`）
> 触发：主人发来 `dumpCtors` 的真实输出

## 一、宿主 `g56` 的真实构造器（主人日志）

```
public g56(int, int,               java.lang.String, java.lang.String)    ← 4 参
public g56(int, java.lang.Integer, java.lang.String)                      ← 3 参 ★
```

**3 参那个正是我们要的形状**：按档案 `pd5.I` 的逻辑 `d != null ? getString(d) : c`
⇒ 第 2 个参数（`Integer`）传 **null**，文案就会走 `c`（我们给的文字）✅

## 二、旧 `tryCtor` 为什么必然失败

```smali
const/4 v1, 0x4
new-array v1, v1, [Ljava/lang/Object;     ← 永远拼 4 个参数
v1[0]=Integer(7) ; v1[1]=Integer(id) ; v1[2]="default" ; v1[3]=text
```

| 面对 | 结果 |
|---|---|
| `g56(int, Integer, String)` ★ | **参数个数不符 ⇒ 直接抛异常** ✗ |
| `g56(int, int, String, String)` | 个数对，但 id/场景位置猜错 ⇒ 字段验证失败 ✗ |

⇒ 两个都失败 ⇒ `build()` 失败 ⇒ 诊断显示「退出:宿主列表空且自建失败」+ dumpCtors 输出 ✓（正是这次的信息来源）

## 三、本版改动：`tryCtor` 按参数个数分流

```smali
    getParameterTypes().length
    if (len == 3) → args = { id, null, text }   ★ d 传 null ⇒ 文案走 c
    else          → args = { 7, id, "default", text }   （原逻辑保留）
    :inst  newInstance(args)
    → 造完立刻读回字段 "c" 与文案比对，一致才认（自验证）
```

⇒ 3 参构造器现在能造出来了，`build()` 也就能返回我们的列表 ⇒ 空列表场景也有 chip 了。
