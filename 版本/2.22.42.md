## 0. 破案：`why=6`

`why=` 探针上线后，主人日志里第一次出现完整序列：

```
00:24:05.704 [实化] bg#1 depth=0 cnt=0 why=0 v = -67818912288342016
00:24:05.726 背景实化作用域开启
00:24:05.727 [实化] bg#2 depth=1 cnt=0 why=1 v = -67818912288342016   ← why 描述的是上一条 bg#1 ✓
00:24:05.729 [实化] bg#3 depth=1 cnt=0 why=6 v = -67818912288342016   ← ★★ bg#2 的结果 = 6
00:24:05.735 [实化] bg#4 depth=0 cnt=0 why=6 v = -67818912288342016   ← ★★ bg#3 的结果 = 6
00:24:05.735 [实化] bg#5 depth=0 cnt=0 why=1 v = -60471863922393088
```

**`why=6` = 哨兵命中**，而且 `bg#2`/`bg#3`（唯二两个 `depth=1` 的调用）**都是 6**。

---

## 1. 根因：哨兵的判据是「颜色相等」，而它撞车了

哨兵原本的设计意图是「**把「我们注入的气泡底」和「宿主的页面底色」分开**」，我用的判据是：

```
args[1] == GmBubble.colorLong()   ⇒ 认为是我们自己的注入，放它一马
```

**把数值摆在一起就看见问题了**：

| 项 | 值 | 颜色 |
|---|---|---|
| 宿主页面底色（`bg#2`） | `-67818912288342016` | **`#FF0F0F0F`** |
| 我们注入的气泡色 `colorLong()` | 同上 | **`#FF0F0F0F`** |

⇒ **两者相等**（主人的气泡颜色被设成了 `#FF0F0F0F`，正好等于 DeepSeek 深色模式的页面底色）
⇒ 哨兵把**宿主的页面底色**当成"自己人"，**主动跳过** ⇒ **页面底色永远不透明化**。

> ⚠️ 这正是「用一个**数值**当身份牌」的固有风险：它**只在数值碰巧不同的时候才成立**。

---

## 2. 修法：换成**结构位置**判据（不可能撞车）

```
我们注入的气泡底   →  发生在 pn9.c（助手消息项）里  ⇒ sDepth > 0
宿主的页面底色     →  发生在 ChatPage 层            ⇒ sDepth == 0
```

**新哨兵**：

```smali
    const/4 v6, 0x6
    sput v6, GmBubble->sPgWhy:I          # why=6 仍保留（含义变为「在助手项内 ⇒ 跳过」）
    sget v1, GmBubble->sDepth:I
    if-gtz v1, :end                      # sDepth > 0 ⇒ 跳过
```

**为什么这条更可靠**：

| | 旧（颜色） | 新（作用域层级） |
|---|---|---|
| 依据 | **数值**（可能撞车） | **结构位置**（不可能撞车） |
| 撞车风险 | ⚠️ 用户改个颜色就可能撞上 | ✅ 无（`pn9.c` 与 ChatPage 是两个不同层级） |
| 顺带解决 | —— | 页内小卡/气泡底的 `v` 调用（都在 `sDepth>0`）**一并排除**，正好不属于「页面底色」 |
