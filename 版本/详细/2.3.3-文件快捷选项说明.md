# 2.3.3 —— 「文件快捷选项」JSON 编辑器（2026-09-12）

## 一、需求

把 `model_configs` 里的 `prompt_feature` 单独拎出来，
放到「美化」二级菜单下，做成简洁易编辑的 JSON，方便自定义**文件上传后的快捷发送选项**。

---

## 二、逆向结论

| 项 | 结论 |
|---|---|
| `prompt_feature` 的位置 | `model_configs` JSON 里**每个模型对象**的一个字段 |
| 有无独立 MMKV key | **没有**。全 APK `"prompt_feature"` 只在 `Llx5`（ModelConfig 的 kotlinx 序列化器）出现 1 次 |
| 元素类型 | `com.deepseek.chat.settings.ModelConfig.PromptTemplate` |
| 元素字段 | `id`(Int) / `scene`(String) / `content`(String) |
| 是否必填 | ⚠️ **三个字段都必填**（描述符里 `j(name, false)` = 非可选） |
| scene 取值 | `image` / `file`（服务端实测） |
| 服务端实际值 | image: 这是什么 / 分析一下 / 怎么办<br>file: 分析一下 / 答案是什么 / 总结 / 解释一下 |
| 读取路径 | `kv_remote_settings_model_configs_v1` → 反序列化（**没有** `kv_settings_` 本地覆盖层） |

## 三、实现

### 3.1 新增类 `GmPrompt`（数据层）

| 方法 | 作用 |
|---|---|
| `get(ctx)` | 读用户编辑的 JSON（`fuckds_prompt_feature`） |
| `current(ctx)` | 从 `kv_remote_settings_model_configs_v1` 里**抠出**第一段 `"prompt_feature":[...]` |
| `display(ctx)` | 显示优先级：用户 JSON → current → 内置 DEF 模板 |
| `put(ctx,json)` | 存用户 JSON |
| `apply(ctx)` | `patch()` 后写回 `kv_remote_settings_model_configs_v1`（先 `bak` 备份） |
| `restore(ctx)` | 还原 model_configs + 清用户 JSON |
| `patch(src,user)` | **核心**：把 src 里所有 `"prompt_feature":[` … 首个 `]` 换成用户 JSON |

**patch 算法**（纯字符串，无 JSON 解析）：

```
needle = "\"prompt_feature\":["
from = 0
while (true):
    a = src.indexOf(needle, from);  if a < 0: break
    b = src.indexOf(']', a + needle.length());  if b < 0: break
    out += src[from..a] + "\"prompt_feature\":" + user
    from = b + 1
out += src[from..]
```

> 局限：`prompt_feature` 数组内不允许出现 `]`（服务端的值里没有，用户 content 也别写方括号）。

### 3.2 新增类 `GmPromptDialog`（UI）

```
┌─────────────────────────────────┐
│ 文件快捷选项                      │
│ 上传文件后的快捷发送项，JSON 数组； │
│ 每项需含 id / scene / content     │
│ ┌─────────────────────────────┐ │
│ │ [{"id":9,...}, ...]         │ │  ← EditText，多行，可滚动
│ └─────────────────────────────┘ │
│  [ 保存 ] [ 恢复默认 ] [ 返回 ]    │
└─────────────────────────────────┘
```

- 打开时预填：用户 JSON → 当前配置抠出来的值 → 内置模板
- 保存：`put()` + `apply()`，成功 toast「已写入配置，重启 App 生效」
- 恢复默认：`GmPrompt.restore()` 还原 model_configs

## 四、内置默认模板（DEF）

```json
[{"id":9,"scene":"image","content":"这是什么"},
 {"id":10,"scene":"image","content":"分析一下"},
 {"id":11,"scene":"image","content":"怎么办"},
 {"id":13,"scene":"file","content":"分析一下"},
 {"id":14,"scene":"file","content":"答案是什么"},
 {"id":15,"scene":"file","content":"总结"}]
```

---

## 五、注意 / 风险

1. **id 必须保留** —— `PromptTemplate` 的三个字段都非可选，
   少了 `id` 会让 kotlinx 反序列化抛异常，导致整个 model_configs 解析失败。
2. **需重启 App** —— 模型配置在内存里缓存。
3. **服务端重新下发会被覆盖**（model_configs 原本的 bak 备份仍在）。
4. `]` 不要出现在 content 里（patch 用的是「首个 `]`」）。
5. 保存时会**一次性改写所有模型**的 prompt_feature（default / expert / vision 全都一样）。
