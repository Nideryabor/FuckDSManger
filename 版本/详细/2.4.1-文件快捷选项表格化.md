## 一、修的第二批 bug：`GmPrompt` 里 4 处 `isEmpty` 判断反向 ⭐

和 `GmDialog.save()`（2.3.2）、`GmPromptDialog.open()`（2.4.0）**同一个家族**的坑。

```smali
# ❌ 错
invoke-virtual {v0}, Ljava/lang/String;->isEmpty()Z
move-result v1
if-eqz v1, :cond_d          # 非空 → 跳走；空串 → return，完全反了

# ✅ 对
if-nez v1, :cond_d          # 空 → 跳走
```

| 位置 | 后果 |
|---|---|
| `GmPrompt.display()` ×2 | 用户 JSON / 服务端 JSON **非空时被跳过**，空串反而被 `return` → **编辑框显示空** |
| `GmPrompt.apply()` ×2 | 用户 JSON **非空时直接返回 false** → 保存永远判定失败（toast 也弹错） |

**修复手法**：抽出一个语义清晰的小工具方法，一次写对、到处复用：

```smali
.method static ok(Ljava/lang/String;)Z
    .registers 3
    const/4 v0, 0x0
    if-eqz p0, :ret                 # null → false
    invoke-virtual {p0}, Ljava/lang/String;->isEmpty()Z
    move-result v1
    if-nez v1, :ret                 # 空 → false
    const/4 v0, 0x1
    :ret
    return v0
.end method
```

> 📌 **教训**：`isEmpty()` 的布尔判断是**反向高发区**。
> `if-eqz`（==0 → 跳）与 `if-nez`（!=0 → 跳）在 `isEmpty` 语境下极易搞反。
> **对策：不要内联判断，抽成 `ok(String)` 这类语义化方法**，调用处只写 `if-eqz`/`if-nez` 两种简单形态。

另：`GmPromptDialog.save()` 里「已写入配置」/「未找到模型配置」两条 toast 的判断也是反的（`apply()==true` 反而弹失败），一并修正。

[{"id":9,"scene":"image","content":"这是什么"},

## 三、表格化编辑器（新 UI）

原来是一个大 JSON 文本框，现在拆成**三列表格**，每个单元格一个 `EditText`：

```
┌──────────────────────────────────────────────┐
│ 文件快捷选项                                   │
│ 上传文件后的快捷发送项。场景填 image 或 file；  │
│ 内容为点击后发送的文字，清空「内容」即删除该行。 │
│ ┌──────────────────────────────────────────┐ │
│ │ ID      │ 场景     │ 内容                 │ │ ← 表头
│ │ ┌─────┐ │ ┌──────┐ │ ┌──────────────────┐ │ │
│ │ │  9  │ │ │image │ │ │ 这是什么          │ │ │
│ │ └─────┘ │ └──────┘ │ └──────────────────┘ │ │
│ │  10     │  image   │ 分析一下               │ │
│ │  ...（可竖向滚动，210dp）                   │ │
│ └──────────────────────────────────────────┘ │
│        [ ＋ 添加一行 ]                        │
│   [ 保存 ]  [ 恢复默认 ]  [ 返回 ]              │
└──────────────────────────────────────────────┘
```

### 3.1 数据流

```
读：MMKV 用户覆盖(fuckds_prompt_feature)
      ↓ 无
    服务端 kv_remote_settings_model_configs_v1 里抠出 "prompt_feature":[...]
      ↓ 无
    内置 DEF（= 上面那份完整服务端值）
      ↓
   GmPrompt.items(ctx) → JSONArray 解析 → List<String[]>{id,scene,content}
      ↓
   GmPromptDialog.fill() → 逐行 addRow() → 生成 EditText 表格

写：遍历表格 → 丢弃「内容」为空的行 → JSONArray/JSONObject 重新拼 JSON
      ↓
   GmPrompt.put() 存用户 JSON
      ↓
   GmPrompt.apply() → patch() 改写 kv_remote_settings_model_configs_v1（先 bak 备份）
```

### 3.2 新增 / 改动的工具方法

| 类 | 方法 | 作用 |
|---|---|---|
| `GmPrompt` | `ok(String)Z` | **语义化判空**（非 null 且非空）—— 根治反向判断 |
| `GmPrompt` | `items(Context)List` | 用 `org/json/JSONArray` 把 JSON 拆成 `List<String[]>` |
| `GmPrompt` | `build(List)String` | 用 `JSONArray/JSONObject` 把表格拼回 JSON（**不再是字符串拼接**） |
| `GmPrompt` | `row(String[])JSONObject` | 单个元素 → JSONObject，内部 try/catch |
| `GmPrompt` | `toInt(String)I` | 安全转 int，失败给 0 |
| `GmPromptDialog` | `et(Context,widthDp,weight)EditText` | 造单元格（width≤0 走 weight 模式） |
| `GmPromptDialog` | `htv(Context,text,widthDp)TextView` | 造表头单元格 |
| `GmPromptDialog` | `addRow(id,scene,content)` | 追加一行（三个 EditText 存进三个 ArrayList） |
| `GmPromptDialog` | `addNew()` / `nextId()` | 「添加一行」：取现有最大 id + 1 |
| `GmPromptDialog` | `collect()List` | 收表 → `List<String[]>`，**内容为空的行自动丢弃** |
| `GmPromptDialog` | `fill()` | 清空并重建整个表格 |
| `GmClick` | 动作 `0x15` | 分发到 `addNew()` |

> 用 `org/json` 而不是字符串拼接后，**`content` 里可以放心出现 `]`、`}`、引号**等字符。

### 3.3 交互约定

| 操作 | 行为 |
|---|---|
| 改任意单元格 | 直接编辑 |
| **清空「内容」** | 保存时该行被丢弃 = **删除该行** |
| ＋ 添加一行 | 追加 `id=最大+1`、`scene=image`、`content=空` 的一行 |
| 保存 | 写入 + 提示「已保存，重启 App 生效」 |
| 恢复默认 | 还原 `model_configs` 并清用户 JSON，表格重新加载 |

## 七、遗留 / 风险

1. **`kv_remote_settings_*` 是服务端设置的落地层**，下次拉 `/api/v0/client/settings` 若含该键，覆盖会被冲掉（`bak` 备份仍在）。
2. **需重启 App** —— `Luv1` 有 `ConcurrentHashMap` 内存缓存。
3. 表格行高固定 210dp 滚动区，行数很多时需要滚动（符合预期）。
4. 仍带少量调试 toast（「已保存…」），功能稳定后可考虑加开关。
