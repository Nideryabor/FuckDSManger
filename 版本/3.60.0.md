## 一、实时保存：开闸时机是这件事的全部难点

```kotlin
val initial = remember { readLayout(ctx) }         // ① 初值**同步**从盘上读一次
var inDrawer by remember { mutableStateOf(initial?.first ?: allCardIds()) }
…
var watch by remember { mutableStateOf(false) }
LaunchedEffect(Unit) { watch = true }              // ② 首帧之后再开闸
LaunchedEffect(inDrawer, inBox, expanded, watch) {
    if (watch) writeLayout(ctx, inDrawer, inBox, expanded)
}
```

**为什么非要那个 `watch`**：如果不挡，自动保存的 effect 会和「读盘」在**首帧同一次**跑起来，
而那时状态还是**默认值**（三张卡全在抽屉、没有展开）⇒ **盘上的存档会被默认值冲掉**，
然后读回来的值看起来"还在"，但用户下次进来就全没了（一个只在"退出再进"时才现形的 bug）。

⇒ 两件事定死：**① 初值必须同步读到**（用 `remember` 的初始化，别放在 effect 里）；
**② 自动保存必须等首帧**。

💾 按钮保留，语义变成**「保险 + 回执」**：写一次 + 吐司告诉主人当前摆放。

## 二、★ 真卡片跟手：牵出三个必须同时做对的东西

做法本身很小：卡片留在自己的槽位里，只叠一个位移：

```kotlin
.offset { IntOffset(dragOff.x.roundToInt(), dragOff.y.roundToInt()) }
```

`dragOff` 是拖拽增量的**累加**。但"卡片自己在动"这件事会连锁影响三处：

### ① 位移只能用 `dragAmount`（增量），**不能用 `change.position`**

`change.position` 是**相对卡片自己**的坐标 —— 而卡片正在被 `offset` 挪走
⇒ 手指不动、卡片自己往前跑（"自己追自己"）。

```kotlin
onDrag = { change, amount -> onDragMove(amount); change.consume() }   // ✅ 增量
```

### ② 槽位矩形要在**拖拽开始时冻结**

判定"落哪个区"和排序都要卡片矩形。而卡片一动，`onGloballyPositioned` 报的坐标就跟着动
⇒ 拖到一半再读，读到的是**已被位移污染**的坐标。

两道保险（都做了）：
* `onGloballyPositioned` 放在 **`offset` 之前** ⇒ 它报的永远是**槽位**坐标，不被位移带偏
* 拖拽开始时把槽位矩形**缓存进 `dragSlot`**，判定时用 `dragSlot.translate(dragOff)`

### ③ `clip(...)` 会把拖出去的东西**裁掉** ⇒ 圆角只能当背景画

容器/抽屉原来都是 `.clip(圆角).background(色)`。**裁切会连带把出界的卡片一起裁掉** ——
卡片一拖出容器边界就**消失**（这是幽灵方案当初绕开的坑，现在必须正面解决）。

```kotlin
.background(MaterialTheme.colorScheme.surfaceContainerHigh, RoundedCornerShape(28.dp))  // ✅ 只当背景
```

**视觉上会不会露馅？** 不会：容器内边距 8dp + 卡片圆角 20dp = 28dp，
正好与容器外圆角 28dp **同心**（卡片弧线整段落在容器弧线里侧）。

**还有一个必然的连带问题**：从**容器**往外拖时，卡片在内容层、而抽屉叠在内容层之上
⇒ 拖到抽屉上方时卡片会**钻到抽屉底下看不见**。修法 = 拖拽期间把内容层 `zIndex` 提到 2：

```kotlin
.zIndex(if (draggingFromBox) 2f else 1f)      // 抽屉固定 1f
```

**会不会把抽屉挡住？** 不会：容器给抽屉让了位（`padding(bottom = handlePx + live)`），
两者**永不重叠** ⇒ 提层没有视觉副作用（这也是 3.59.0 "让位"那个改动的额外红利）。

## 五、教训

**1000 · ⭐⭐⭐ 「跟手」要跟的是**位移**，不是**位置**。**
　　UI 上"东西跟着手指走"看着是"位置"，但一旦这个控件**自己也在动**，
　　再拿"相对自己的坐标"当位置就成了**自己追自己**。
　　⇒ 认增量（`dragAmount`）。**凡是"对象自身在移动期间采集它的坐标"，都要问一句：
　　这个坐标是相对谁、它在动的时候还准不准。**

**1001 · ⭐⭐ 判定用的矩形，要在"开始动"那一刻冻结。**
　　拖动中随时可以读坐标，但读到的是**被自己的位移污染**过的值。
　　⇒ 关键量在动作起点采样一次（`dragSlot`），全程用"采样值 + 位移"推算，
　　既稳又便宜。（加一道 `onGloballyPositioned` 放在 `offset` 之前做双保险。）

**1002 · ⭐⭐⭐ `clip` 会把你"拖出去"的东西裁掉 —— 想要拖出去还看得见，圆角只能当背景画。**
　　`.clip(圆角)` 是**裁剪**，不只是视觉圆角；子节点一旦越界就整个消失。
　　⇒ 改用 `.background(色, 形状)`：**圆角还在，裁切没有**。
　　★ 附带一条：**谁叠在谁上面**要跟着想一遍 —— 卡片从下层容器拖到上层抽屉时，
　　要么让"被拖的那张"所在的层临时提到最上（`zIndex`），要么它会在抽屉底下消失。
　　（这次提层是**免费**的，因为容器早就给抽屉让了位、两者永不重叠。）

**1003 · ⭐⭐ 「实时保存」的难点不在写，在**首帧别写**。**
　　自动保存一旦和"读存档"在同一次里跑，写会把读的结果冲掉 ——
　　而且症状**延迟一行出现**：当场看布局是对的，**退出再进才全没了**。
　　⇒ 两道闸：① 初值必须**同步**读（`remember` 初始化而不是 effect）；② 写要等首帧之后。

**1004 · ⭐⭐ 状态别写成文件级的 `var`（这次我自己写错又自己抓回来）。**
　　两个投放区矩形本该是页面内的 `remember`，我一度写成了顶层 `private var` ——
　　**看起来也能跑**，但它是"进程里只有一份"的状态：切页/多次重组会互相踩，
　　而且是那种"平时看不出、某次重进就错"的错。⇒ **状态一律留在组件里**，文件级只放常量。
　　⚠️ 附带一条操作教训（**989 号的第二次**）：这一版我**又一次把"改文件"和"跑构建"并排发**，
　　结果先编出来一个**没带修复**的包（哈希都不一样）——
　　**有前后依赖就一步一步来**，改完再编。
