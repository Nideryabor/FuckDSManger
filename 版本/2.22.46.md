## 1. 我做错的两件事

### ❌ 错一：把 `GmBgView.setBlend` 当成"多余的混合"砍掉了（2.22.44 的 ③）

读完 `GmBgView.onDraw` 才发现它**不是多余的**：

```smali
    iget v3, p0, GmBgView->h:I              # h = setBlend 写入的「混合模式索引」
    if-eqz v3, :cond_30                     # h==0 ⇒ 不设 Xfermode（默认 SRC_OVER）
    const/4 v4, 0x1
    if-ne v3, v4, :cond_26
    sget-object v3, PorterDuff$Mode;->MULTIPLY
    goto :goto_28
    :cond_26
    sget-object v3, PorterDuff$Mode;->SCREEN
    :goto_28
    new-instance v4, Landroid/graphics/PorterDuffXfermode;
    invoke-direct {v4, v3}, PorterDuffXfermode;-><init>(Landroid/graphics/PorterDuff$Mode;)V
    invoke-virtual {v2, v4}, Landroid/graphics/Paint;->setXfermode(Landroid/graphics/Xfermode;)Landroid/graphics/Xfermode;
    :cond_30
```

```smali
.method public setBlend(I)V
    iput p1, p0, GmBgView;->h:I        # ★ 写的就是这个 h
    invoke-virtual {p0}, Landroid/view/View;->invalidate()V
```

**⇒ `setBlend` 决定的是「图怎么画」，不是「多不多余」。已回滚 ③。**

> ⚠️ 不过客观说：`h=0` 走 `SRC_OVER`，本是**最正常**的绘制 ⇒ **跳过它并不会让图消失**。
> 所以"看不见"的**主因不是 ③**，而是下面这条。

### ❌ 错二（**真正主因**）：把图插进底层，却没管「上面那层 View 的背景」

2.22.44 的 ① 让图插到 **`decorView` 的 index 0**。

```
DecorView (FrameLayout)
  ├─ [0] ← 我们的 GmBgView（图）
  └─ [1] LinearLayout
          ├─ 状态栏背景
          └─ FrameLayout(android.R.id.content)  ← Compose 宿主
```

**我们的实化只透明化了 Compose 画的 4 层**（`bg#1~#4`，那是 Compose 内部的 `Modifier.background`），
而 **View 层（`Window` / `DecorView` / `LinearLayout`）的背景仍然是实心的** ⇒ **图被它们盖住** ⇒ **看不见**。

> 这也解释了为什么"**底图和混合都用不了了**"：两个档位现在都插底层 ⇒ 都被盖住。

## 2. 本版改动

### ① 回滚「跳过 `GmBgView.setBlend`」

```smali
# 改回：
    invoke-static {p0}, GmBg->pos(Context)I
    move-result v6
    const/4 v7, 0x2
    if-ne v6, v7, :cond_c4
```

### ② 新增 `GmBg.clearBg(Activity)` —— **把 View 层的背景清掉**

```smali
.method private static clearBg(Landroid/app/Activity;)V
    # 1) Window 背景 → null
    invoke-virtual {p0}, Activity->getWindow()Window
    …
    invoke-virtual {v0, v1}, Window->setBackgroundDrawable(Drawable)V      # v1 = null
    # 2) DecorView 的每个直接子 View 背景 → null
    invoke-virtual {v0}, Window->getDecorView()View
    … getChildCount() … 循环 … getChildAt(i).setBackground(null) …
    :end / :catchall 均静默返回
```

**调用点**：`ensure()` 里 **`addView` 完成之后、`applyFx` 之前**：

```smali
    :goto_ee
    sget-object v6, GmEntry->sAct:Activity
    invoke-static {v6}, GmBg->clearBg(Activity)V      # ★
    invoke-static {p0, v5}, GmCam->applyFx(Context;View)V
```

⇒ **图在 index 0，上面所有层的背景都被清掉 ⇒ 图能从最底透出来。**

## 3. 本版保留的另两项修复

| 项 | 内容 |
|---|---|
| ① | `addView` 判据 `pos==1` → **`pos!=0`** ⇒ 「底图」「混合」都插 `decorView` index 0 |
| ② | `GmBg.setBlend` 不再给 `content` 设 `MULTIPLY`/`SCREEN` ⇒ `setBlendMode(null)` |
| ④ | `GmAlphaHook` 删掉 `instance-of GmBmpShader ⇒ :end` ⇒ **图片透明度对图片底生效** |

## 4. ⚠️ 风险与回滚路径

| 风险 | 回滚方式 |
|---|---|
| 清背景导致**状态栏/导航栏变透明**（视觉上与内容重叠） | 删掉 `ensure` 里那两行 `clearBg` 调用 |
| 清背景导致**某些界面背景变黑/变透明** | 同上（`clearBg` 只在 `ensure()` 里被调一次，且整体包 try/catch） |
| 图仍然看不见（说明还有别的层） | 下一步：把 `addView` 目标从 `decorView` 改成 **`android.R.id.content`**（少一层容器） |

## 6. 教训（821~822）

| # | 内容 |
|---|---|
| **821** | ⭐⭐⭐ **删代码前必须先弄清「它到底在干什么」**：我把 `GmBgView.setBlend` 从名字上判成"多余的一次混合"，而它实际写的是 `onDraw` 用来选 `PorterDuffXfermode` 的关键字段。⇒ **凡是「看起来只是设置/通知」的方法，先看它的字段被谁读**。 |
| **822** | ⭐⭐⭐ **「图看不见」是分层问题，不是 alpha 问题**：图插到 index 0 之后，**Compose 透明了但 View 层没透明** ⇒ 图被 View 层背景盖住。⇒ **"让下层可见"必须把「从下到上的所有不透明层」都数一遍**（Compose 层 + View 层 + Window 层），只透明其中一段不够。 |
