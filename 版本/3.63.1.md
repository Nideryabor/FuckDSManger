## 一、★ bug ③「卡片被当夜宵吃了」+ 主人那句线索

### 线索

主人说「UI 里面没有可以拖的自定义文本了……（包括内置的）」——
**连内置的都不见了**，而存档里明明是有的（左侧内置：`suggest` / `richtext`；
右侧自定义：`textsrc` / `text#3` / `text#6` / `text#7`；容器里 `music`）。

### 病根（两个叠在一起）

**① 卡片全部隐形 = 列宽算成了 1px。**
3.63.0 的两列宽度是"**先测量、再回填**"：

```kotlin
var colPageW by remember { mutableFloatStateOf(1f) }          // ← 首帧就是 1f（1 像素！）
Box(Modifier.onSizeChanged { colPageW = it.width.toFloat() }) // ← 靠这一次回填纠正
Column(Modifier.width(with(density) { colPageW.toDp() }))     // ← 列宽 = 1px
```

回填只要没跟上（首帧、重组次序），**两列就只有 1 像素宽 ⇒ 卡片是一根看不见的细条**。

**修法**：改用 `BoxWithConstraints` 的 `maxWidth` —— **组合期就已知**，首帧就是对的：

```kotlin
BoxWithConstraints(...) {
    val pageDp = if (maxWidth.value.isFinite() && maxWidth.value > 1f) maxWidth else 320.dp
    val pagePx = with(density) { pageDp.toPx() }
    Row(Modifier.offset { IntOffset((-colFPos * pagePx).roundToInt(), 0) }) { … }
}
```

> 顺带：横滑手势的 lambda 在**外层作用域**里，看不见 `pagePx`（编译期就报出来了），
> 改用 `PointerInputScope` 自己的 `size.width` —— 同一份宽度，两种拿法都对。

**② 卡片真的会丢 = 卡片表被当成"可丢的附属品"。**
`normalized()` 原来只认「**列表里提到的**卡片」：

```kotlin
drawer.forEach { keep(it) }        // 只收 drawer 里的
box.forEach { keep(it) }           // 只收 box 里的
```

⇒ 表里存在、但"两边都没提到"的（孤儿）会被**当脏数据丢掉，而且写回存档** ⇒ 永久丢失。
主人这次丢的正是 `text#1 / text#2 / text#4 / text#5`（都是默认文本，重拖即可）。

**修法 —— 卡片表 = 唯一真相**：

* 表里有的卡片**一张都不许丢**；
* 「两边都没提到」的 ⇒ **补回抽屉**（绝不静默丢）；
* 老存档（只有 id 列表、没有卡片表）⇒ 内置三张 + 源卡片的**键就是它自己的类型名**，现造；
* **`nextId` 加保险**：`nextId = max(nextId, 现有 text#N 最大值 + 1)` ——
  撞键就会让"复制"变成"覆盖别人的内容"；
* **存档没读回来之前不许写盘**（`commit()` 里 `if (!seeded) return`）——
  否则一次"半加载"的提交就能把卡片吃光。

> ⇒ 从此**只有一条路能让卡片消失**：主人点那张红删除。

## 二、★ bug ②「蓝色的对齐线位置严重偏移」= 坐标系搞混了

* **判定**用的是**根坐标**（`boundsInRoot()` / `positionInRoot()`）；
* **画线**用的是 `Modifier.offset {}` —— 而 `offset` 是**相对父容器**的！

而页面那个 `Box` 的原点在根坐标里已经被 Scaffold 的 padding（顶栏 + 状态栏）推下去了
⇒ 线整体**偏了一个顶栏的高度**。

**修法**：记下页面 Box 自己的原点，画线时减掉：

```kotlin
Box(Modifier.fillMaxSize().onGloballyPositioned { pagePos = it.positionInRoot() })
…
.offset { IntOffset((rect.left - pagePos.x).roundToInt(), (hint.third - pagePos.y - 1.5f).roundToInt()) }
```

**顺带修一处**：抽屉里算插入序号时，原来把**另一列**（屏幕外那列）的卡片也算进去了
（它们只是"在屏幕外"，不是"在那条线上"）⇒ 现在**只跟同一列比**。

## 三、bug ①「抽屉收起时就带淡蓝色归档图标」

主人确认的期望：**只在"拉住卡片拖"的时候出现**（平时、抽屉收着都不显示）。

**改法**：
* 原来的"整页蓝罩 + 随抽屉浮动的图标"撤掉 —— 那等于屏幕上常年挂着一层淡蓝滤镜；
* 现在的蓝底铺在**容器内部**（卡片在它上面 ⇒ **不压卡片、不穿模**）、抽屉里那层高亮照旧；
* **归档图标**落在**容器与抽屉之间的那条空档**里（`-(live + 10dp)`）——
  既看得见，又**不压任何卡片**；只有拖动时才画。

## 四、采纳建议：图层序重排（防穿模）

主人：「可把卡片设置成最高层级，可以解决一些穿模 bug」——
但**卡片自己的 `zIndex` 只在它的父层里有效**，跨层（容器 ⇄ 抽屉）还得靠"抬整层"。所以：

| 元素 | zIndex | 说明 |
|---|---|---|
| **被拖的那张卡所在的层** | **4f** | 拖动中把整层抬到最上 ⇒ 跨容器/抽屉不会被另一半吃掉 |
| 内容层（容器） | 2f | 平时 |
| 抽屉层 | 2.5f | 平时（压住容器） |
| 归档图标 | 200f | 页面级，恒在最上（但它落在空档里） |
| 落点线 | 210f | 页面级 —— 它**就该**盖在卡片上 |
| 拖动中的卡片本体 | 100f | 层内 |

> 一摞 z 值全部写在源码注释里，免得下次又算错（这是 3.63.0 的头号返工点）。

## 六、教训

**1022 · ⭐⭐⭐ 「先测量再回填」是个陷阱 —— 首帧的值必须是**对的**，不能是"待纠正的"。**
　　我给列宽设的初值是 `1f`（1 像素），把"正确"寄托在 `onSizeChanged` 的回填上；
　　回填一旦没跟上（首帧/重组次序），**卡片就全部隐形**。
　　⇒ 能用**组合期就已知**的量（`BoxWithConstraints.maxWidth`），就别用"测量回调"。**初值必须是合法值。**

**1023 · ⭐⭐⭐ 判定用哪个坐标系，画的时候就得用**同一个**。**
　　`boundsInRoot()` 给的是根坐标，而 `Modifier.offset {}` 是**相对父容器** ⇒
　　混用就整体偏一个顶栏的高度。⇒ 统一到"页面坐标"，或者两边都换算。

**1024 · ⭐⭐⭐ 「附属关系」不能当成「存在证明」。**
　　我把"卡片在不在"的判据交给了**两个列表**（谁提到谁存在），
　　于是一次不一致就把卡片**当脏数据清掉、还写回存档**。
　　⇒ **谁是真相、谁是索引** 必须分清：卡片表是真相，列表只是摆放。
　　并且"清理脏数据"这件事**永远要偏向"留住"**（宁可补回、不可丢弃）。

**1025 · ⭐⭐ 「拖动中的东西」和「提示层」谁在上面，要按用途定，不是按直觉。**
　　归档图标压在卡片上 = 穿模；落点线压在卡片上 = **本来就该**。
　　⇒ 一摞 z 值写进注释（这次做了）。

**1026 · ⭐ 同一个错的值，**两种拿法都要能用**。**
　　横滑手势的 lambda 在**外层作用域**，看不见 `BoxWithConstraints` 里的 `pagePx`（编译期就报出来）
　　⇒ 用 `PointerInputScope.size.width`。**这不是妥协，是那个作用域里本来就该用的量。**
