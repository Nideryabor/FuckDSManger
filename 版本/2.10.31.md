# FuckDSManger 2.10.31（回复建议 · 「必响探针」：第一次调用时无条件直连构造，不吞异常）

> 产物：`FuckDSManger_2.10.31_for_ds2.5.2.apk`（**182 / 2.10.31**，90 类，V1+V2+V3，sha256(partial) `695f17e1…`）
> 触发：主人「没反应，app 没崩溃，日志没有新东西」

## 一、为什么"没反应"最可能是**没被走到**

2.10.30 的直连构造写在「宿主列表为空」那个分支里 —— 如果这一轮所有调用都是
`传入列表为 null`（另一条分支），那段代码就**永远不会执行** ⇒ 自然"没反应、没日志、不崩溃"。

## 二、本版：把探针放到**必经之路**

`buildMut2` **一进来**就检查一次性标志 `sDbg`：

```smali
    sget sDbg ; if (sDbg == 1) → 跳过
    sDbg = 1
    probeDirect()        ← ★ 直连构造 g56 + 强制写 a/c/d，全程不吞异常
```

`probeDirect()` 内部：`app()` → `findClass("g56")` → `templates()` 取第 1 条 →
`newInstance(g56, {Integer(0x2329), null, text})` → 强制写字段 → **成功则打一行日志**。

⇒ 结果只有两种，**不可能再"没反应"**：

| 日志 | 含义 | 下一步 |
|---|---|---|
| `[建议] 探针：g56 构造成功（未抛异常）` | 构造其实没问题 | 问题在"返回给宿主后没被采用" ⇒ 转渲染层/返回值时机 |
| `java.lang.XXXException: …`（堆栈） | **根因到手** | 按异常类型精确修 |

## 三、请顺便确认这两行（判断"新包是否生效"与"那排是否渲染"）

```
FuckDSManger v2.10.31 handleLoadPackage ENTER     ← 新包是否加载
[建议] buildMut2 进入                              ← 那排是否渲染 / 钩子是否被调用
```

| 情况 | 结论 |
|---|---|
| 两行都有 | 探针一定会响（若没响 ⇒ 我继续查调用链） |
| 只有第二行没有 | 那排这次没渲染（回去多试几次/换场景） |
| 连第一行都没有 | **新包没生效** ⇒ 强停宿主重来 |

## 四、教训

| # | 教训 |
|---|---|
| 222 | ⭐⭐⭐ **诊断代码必须放在"必经之路"上** —— 放进条件分支里，很可能正是那个分支本轮不走 ⇒ 白等一轮 |
| 223 | ⭐⭐ **一次性探针（static flag）**：既保证"必响"，又不会每帧刷屏/反复抛异常 |
| 224 | ⭐ **"没反应"要先排除"没执行"**：先用一行横幅/入口日志确认代码路径，再谈逻辑对错 |
