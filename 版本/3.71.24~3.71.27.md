## 二、★ 最关键的一次认知纠错

### 2.1 原话

> 我：**「我明白了 —— 抓背景本身就会闪，不管延迟多久。」**
> 主人：**「你确定？」**
> 我：（重新想了一遍）**「不确定……我那个判断是对的，但结论带偏了。」**

这一问救了两件事：

1. **判断是对的** —— 抓屏需要「藏自己 2 帧」，这个动作本身就有可见的闪，
   延迟只是把闪挪到别处（手指刚松开时眼睛还在那儿）。
2. **但结论带偏了** —— 我当时的结论是「Android View 层做不到，只能选实色」，
   这话对，但我说得太早，**没给出"实色也能做好看"的具体方案**，
   听起来像"我放弃了"。

### 2.2 抓屏模糊的两条死路（这次彻底想清楚了）

```
死路① 保真 ⇒ 必须藏自己 ⇒ 必然闪
       抓屏的每一帧，卡片都是透明的。这不是"频率太高"，是"这个动作本身"。

死路② 抓的是"卡片身下那块"，可那儿本来就没内容
       卡片盖住的地方被卡片压暗了 ⇒ 抓到的图没有信息量
       ⇒ 模糊完就是一坨脏灰。**怎么调参都是脏的。**
```

⇒ **这两条是原理性的，不是实现问题。** 我在 3.71.21 就该看出来。

## 三、3.71.27 的解法：纯材质

**零抓屏、零隐藏、零帧操作。** 四层纯绘制：

| 层 | 值 | 作用 |
|---|---|---|
| `vBgTint` | 竖向渐变 `0xF2161A24` → `0xFA0C0E14` | 主体。alpha 0xF2~0xFA ⇒ 近乎不透明，只留极轻微通透（主人要求"透明度提高"） |
| `glow` | 顶部 64dp `0x26FFFFFF → 0` | 玻璃厚度感 |
| `rim` | 底部 40dp `0x16FFFFFF → 0`（BOTTOM_TOP） | 受光亮边。**没有它，深色卡片看起来像贴纸** ← 这条是这次新加的 |
| `vHairline` | 1dp 描边 `0x3DFFFFFF` | 玻璃边 |

**为什么这个"接近 iOS"**：iOS 深色模式的 `SystemThinMaterialDark` 本来也很暗。
在深色卡片上看，几乎看不出有没有模糊 —— **差别主要在"有没有层次"**，
而层次靠的是 渐变 + 柔光 + 亮边 + 描边 四件套，不是靠模糊。

### 改动量

删掉的：

```
vBgShot / bgBitmap / bgCaptured / bgCapturing / bgFailCount / bgLastCaptureMs
refreshBackdrop() / done() / blurFast() / boxBlur() / blurLine() / bgReload
C_TINT / C_GLOW
```

`GmMiniBarView` 从 **2,077 行 → 1,880 行**（净减 197 行）。
`PixelCopy` / `boxBlur` 在该文件里命中 **0**。

## 四、3.71.25：一次有价值的"考古"

3.71.24 回退错了版本，因为：

- `v2-灰色版`（1,633 行）其实是 **3.71.20**
- **3.71.21 的源码我从来没备份过** —— 被自己覆盖了

**补救办法（这个值得记住）**：

> **apk 就是最好的备份。** 用 `baksmali` 反编译 `classes2.dex`，
> 从 smali 里读出**地面真值**：字段清单、方法清单、常量值、方法体。
> 然后从后续文件（v4）反推重建，最后用**方法数 + 关键符号**对账。

这次的对账结果：

```
新文件方法数     : 97
3.71.21 方法数   : 97    ✓
```

参数也是从 smali 里读出来的（不是凭记忆）：

| 参数 | v3 真值 |
|---|---|
| `refreshBackdrop` 冷却 | `const-wide/16 0xfa` = **250ms** |
| 藏自己后等多久再抓 | `const-wide/16 0x28` = **40ms** |
| `onSizeChanged` debounce | `const-wide/16 0x140` = **320ms** |
| `C_TINT` | `0x78090b12` |

## 五、3.71.26：修对了一半的补丁

主人：「点击卡片空白处都会闪一下」

**真因**：`Drag` 挂在整卡 `setOnTouchListener` 上，`ACTION_DOWN` 就 `return true`
⇒ **任何一次点击**都会走到 `ACTION_UP` ⇒ `refreshBackdrop(true)`。

**修法**：Drag 加 `moved`（位移 > 3px 才算拖）、Resize 加 `resized`。
点一下什么都不做。**这一步是对的。**

但紧接着又加了两层"优化"：

```
松手后延迟 220ms 再抓
force 也留 120ms 最小间隔
```

结果：主人「现在又变成拖动闪了」。

**因为延迟不解决"抓这个动作会闪"，只是把闪从"点一下"挪到"松手之后"。**
拖完松手时眼睛必然在卡片上 ⇒ 看得更清楚。

⇒ 这两个"优化"是**在错误的路上更努力**。

## 六、教训

| # | 教训 |
|---|---|
| **AY** | ⭐⭐⭐ **"加延迟/加冷却/debounce" 解决不了"这个动作本身可见"。** 只要操作会让画面产生可见变化，加多少层时序优化都是在推迟它，不是在消除它。**先问：这个动作能不能不做？** |
| **AZ** | ⭐⭐⭐ **一个"看起来可行"的方案，如果每次真机都有新毛病，那就是方案本身错了。** 抓屏模糊在 3.71.21/24/25/26 四次上机四次有毛病（丑 / 闪 / 点也闪 / 拖也闪），我每次都归因为"参数没调好"。**四次同源，就是原理问题。** |
| **BA** | ⭐⭐⭐ **主人问「你确定？」的时候，是真的该重新推一遍。** 那次我重新想完，发现自己判断对但结论窄 —— 如果没被问，我可能就停在"只能选实色"这句上了，而不会去把"实色也能好看"做出来。 |
| **BB** | ⭐⭐ **回退版本要看内容，不要看文件名。** `v2-灰色版` 这个名字让我以为是"上上个版本"，实际它是 3.71.20；而 3.71.21 根本没备份。**回退前先 `grep` 关键特征**（比如 `applyPlayLayout(float`、`C_ACC = 0x0A84FF`）。 |
| **BC** | ⭐⭐ **apk 就是最好的源码备份。** 反编译 smali 读字段/方法/常量，比凭记忆重建可靠一个数量级。**以后每个"主人认可的版本"出包后，立刻从 apk 反编译一份 smali 存进 backups/**。 |
| **BD** | ⭐ **"接近 iOS 材质"的关键不是模糊，是层次。** 渐变 + 顶部柔光 + 底部亮边 + 1dp 描边 —— 这四件套带来"浮起来"的感觉；模糊只是其中一味，而且在小元件上是最不值钱的那一味。 |
