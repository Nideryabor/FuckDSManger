## 一、彩蛋完善：文案全部搬进 `resources.arsc`

**3.67.0 的状态**：`Lang.kt` 里直接写着中文字符串（`t(ctx, "人话版", "龙龙语版")`），
弹窗那几句也是硬编码在 `Screens.kt` 里 —— 主人嫌难受，对。

**现在**：`Lang.kt` / `Screens.kt` 里**一行文案都没有了**，只有资源 id。

```kotlin
// 3.67.0（硬编码）
fun t(ctx: Context, human: String, dragon: String)

// 3.68.0（走 arsc）
fun t(ctx: Context, human: Int, dragon: Int) =          // 两个参数都是 String 资源 id
    ctx.getString(if (current(ctx) == DRAGON) dragon else human)
```

### 18 条新资源（`fdm-app/res/values/strings.xml`，前缀 `fdm_lang_`）

| 组 | 键 |
|---|---|
| 弹窗本体 | `_title` · `_desc` · `_note` · `_confirm` · `_cancel` |
| 两个选项 | `_human` · `_human_sub` · `_dragon` · `_dragon_sub` |
| 回执 Toast | `_toast_human` · `_toast_dragon` |
| 已接进去的句子（成对） | `_tagline_human/_dragon` · `_emptybox_human/_dragon` · `_help_human/_dragon` |

**命名约定**：`fdm_lang_xxx_human` / `fdm_lang_xxx_dragon` ——
**加一句新话 = ① strings.xml 加一对 ② `Lang.S` 加一行**。

### 为什么这样就"不难受"了

改了文案**不用碰 Kotlin**（也就不会碰 dex）：改 `strings.xml` 重编，或者
拿 MT 管理器直接改包里的 `resources.arsc` 都行。

## 二、顺手修掉的三个小坑

| # | 坑 | 修法 |
|---|---|---|
| 1 | **"连点七下"没有时间窗** —— 早上点三下、下午点四下，照样把弹窗叫出来（那就不叫"连点"了） | 加 `TAP_WINDOW_MS = 1500L`：两次点击间隔超时就从 1 重新数（`SystemClock.uptimeMillis`，不受改系统时间影响） |
| 2 | 弹窗里那句是**开发笔记**：「现在接进去的地方还不多 …… 要加哪一句跟我说」 | 换成正经说明 `fdm_lang_note`：「换完立刻生效：页面上那些跟着变的句子马上就是新的说法。」 |
| 3 | 关于页标语其实**靠"碰巧有重组"才刷新**（`Lang.S.tagline(ctx)` 直接读 SP，不是 state） | 改成 `remember(lang) { Lang.S.tagline(ctx) }` ⇒ 显式依赖 `lang`，换完立刻变 |

## 三、手势：首页改成**左滑**进关于

**原来**只有一个 `SwipeRightToGo`（`dx` 被夹在 `0f..width`，**只认右滑**），
两个页面的语义却是相反的 ⇒ 首页被挂成了「**右**滑 → 关于」，方向反了 ✗

**现在**：加一个方向参数，一个函数管两边。

```kotlin
private fun SwipeToGo(dir: Int, onGo: () -> Unit, content: @Composable () -> Unit)
//                          ↑ +1 = 向右滑    -1 = 向左滑
```

| 页面 | dir | 手势 | 过渡 |
|---|---|---|---|
| 首页 | `-1` | **左滑** → 关于 | `Tr.IN_RIGHT`（关于从右边滑进来，跟手方向一致） |
| 关于 | `+1` | **右滑** → 首页（主人：「没问题」⇒ 一个字不动） | `Tr.IN_LEFT` |

**两个踩点记在代码注释里**：
1. `pointerInput` 的 key **不能放 `onGo` 这个 lambda** —— 每次重组都是新实例，
   放进去会让手势识别**在拖动中途重启**（拖一半就断）。它闭包里读的
   `page` / `stack` / `tr` 都是 state，所以读到的一定是新值 ✓
2. 没到阈值才 `dx = 0f`（弹回）；到阈值就走 `onGo()` —— 保持和关于页**一模一样**的观感（主人认可过的那套）。

## 六、★ 机制升级：伪 locale + 资源变体（「全部接上」的地基）

主人看完第一版追加了一句：「**全部接上!!!!**」—— 要让**整个界面**都跟着说话方式变。

### 为什么不能沿用"一句两个 key"

第一版是 `t(ctx, R.string.xxx_human, R.string.xxx_dragon)`，**每加一句都要改调用点**。
几百条文案 = 几百次改动，而且以后每加一句都得记得写两遍 ⇒ 不可维护 ✗

### 换成 Android 原生的资源变体（实测可行）

```
res/values/strings.xml       ← 人话（默认）
res/values-zz/strings.xml    ← 龙龙语（zz = BCP47 保留码，真机不会被设成它）
```

**同一个 key 写两份**，运行时把 Context 换成带 `zz` locale 的：

```kotlin
// Lang.kt
fun wrap(base: Context, v: Int): Context {
    if (v != DRAGON) return base
    val cfg = Configuration(base.resources.configuration)
    cfg.setLocale(Locale("zz"))
    return base.createConfigurationContext(cfg)      // 异常时静默降级回 base
}

// MainActivity.kt —— **只在这一层** provides；App.kt / Screens.kt / Music.kt 一行都不用改
val uiCtx = remember(Lang.version) { Lang.wrap(base, Lang.current(base)) }
CompositionLocalProvider(LocalContext provides uiCtx) { FdmTheme { … } }
```

### 三个关键好处

1. **调用点永远同一句话**（`ctx.getString(R.string.xxx)` / `stringResource(R.string.xxx)`）
   ⇒ **加新文案不用动 Kotlin**；
2. **`values-zz` 不用写满** —— 没写的 key 自动回落到人话（Android 资源 fallback）
   ⇒ 龙龙语可以**一句一句慢慢加**，界面永远处于"能用的中间状态"；
3. `Lang.version` 是 Compose state ⇒ 切换时整棵树换 ctx，**不重启 Activity、不闪**。

**核验**：`aapt2 dump resources` 里每个 key 都是两份 ——
`string/c_nav_home` → `() "首页"` / `(zz) "窝"` ✅（最终包 15 条 zz 变体）

### 三件工具（都在 `tools/`，可重放）

| 工具 | 干什么 |
|---|---|
| `tools/i18n_migrate.py` | `scan` 盘点 · `apply 前缀=文件.kt` 提取+回填 · `render` 产出两个 strings.xml · `status` 覆盖率 |
| `tools/i18n_dragon.py` | 按**词库 + 语气尾巴**生成龙龙语（可复现：同一 key 永远同一个尾巴） |
| `tools/ktcheck.sh` | **只跑 kotlinc** 的快通道（9 秒）—— 批量改写要反复试错，全量 R8 太慢 |

> 中间件在 `fdm-app/i18n/`：`keys.json`（人话 771 条）· `zz.json`（龙龙语 645 条）。
> **改龙语只改 `zz.json`（或 `i18n_dragon.py` 的词库）再 `render`** —— 不用碰 Kotlin。

### 机械收敛（这次的关键手法）

搬完 895 条后 kotlinc 报了 **1240 处错**。别慌 —— 分两类：

1. **`stringResource` 用在了非 Compose 上下文**（`try{}` 里 / 局部函数里 / `const val`）
   ⇒ 报错行就在眼前、且那行十有八九有 `ctx` 在作用域里
   ⇒ 写了个循环：**只把报错那行的 `stringResource(` 就地换成 `ctx.getString(`**，
   **反复编译直到不动**。第一轮自动修掉 63 处，剩下 19 处才是真要动结构的。
2. **真要改结构的**（只有 4 个函数 + 3 个 object）：

| 位置 | 改法 |
|---|---|
| `typeTitle(type)` / `cardHint(c)` | 改成**返回资源 id** 的纯函数（`typeTitleRes`），或补 `ctx` 参数 |
| `DEF_TITLE` / `DEF_TEXT`（`const val`） | → `DEF_TITLE_RES` / `DEF_TEXT_RES`（资源 id），调用点解析 |
| `normalized()` / `defaultCards()` | 补 `ctx: Context` 参数 |
| `Conf` / `GrayTable` / `Tree` 里那些 `val xxx = listOf(...)` | → `fun xxx(ctx: Context)`（显示名要按语言取）+ 调用点补 `ctx` |
| `SysPromptItems`（顶层 val） | → `sysPromptItems(ctx)` |
| `PromptCard(...)` | 函数体开头补 `val ctx = LocalContext.current` |

### 两个自己踩的坑（记账）

* **import 插到了 `package` 之前**：`Tree/GrayTable/Conf` 原来是"注释 + package + 正文"，
  没有 import 段，我的兜底把新 import 顶到了第 3 行 ⇒ `syntax error` ×N、报错 1240 条。
  ⇒ 规则：import 一律插在 `package` **之后**。
* **改了代码没重新生成 R，就跑去编译**：新键在 `R.string` 里还不存在 ⇒ 满屏
  `unresolved reference 'tree_XXX'`，看得人以为搬歪了。
  ⇒ `ktcheck.sh` 的 classpath 里 **`b_rcls.jar` 必须放最前**（`work/` 里还躺着旧时代的
  `rcls_app.jar`，先被解析到就会"新键找不到"）。

### 龙龙语的取舍（★ 主人要的"全部接上"，但尼尼**主动收窄了词库**）

第一版词库把"默认"→"原样"、"系统提示词"→"系统提示词"这类也换了，结果出了
**「默认 1000」→「原样 1000」**（改了意思 ✗）、**「功能原理」→「本事原理」**（小学生味 ✗）。
⇒ 收窄成**只换"換完还是同义词、绝不会改错意思"的**（宿主→大窝 / 气泡→泡泡 / 返回→回窝…），
其余一律**只加语气尾巴**。再加两条规则：**多行串不加尾**（尾巴会飘到下一行）、
**以标点/破折号收尾的不加尾**。

最终：**645 条龙龙语 + 126 条自动回落人话**（超 26 字的长段落保持人话 ——
那些是"要读懂"的技术说明，翻歪了只会让人看不懂）。

## 十、教训

**1047 · ⭐⭐ 「文案走资源」改的是**来源**，不是「把字符串挪个地方」。**
　　把字符串从 `Lang.kt` 挪进 `strings.xml`、调用点却仍然传字符串 —— 那是没用功。
　　真正要改的是**调用点的类型**：从 `t(ctx, "人话", "龙龙语")` 变成
　　`t(ctx, R.string.a, R.string.b)`。判据：改完之后 Kotlin 里搜不到中文。

**1048 · ⭐ aapt2 会把含 `%` 的字符串当格式串。**
　　`FDM-100%由DS鬼脑发动…` 差点被当成占位符 ⇒ 必须 `<string … formatted="false">`。
　　另外 `&` 在 XML 里要写 `&amp;`（`功能原理 &amp; 帮助`）。
　　★ 好在**编译期**就能发现（`aapt2 compile` 就报），不用等装机 —— 我先单跑了一次
　　`aapt2 compile --dir res` 才敢往下走。

**1049 · ⭐ 「连点 N 下」必须带时间窗。**
　　不带窗口的话，7 次点击可以横跨半小时 —— 那不是彩蛋，是**误触**。

**1050 · ⭐⭐ 一个"只认单向"的手势函数被两个语义相反的页面复用，必有一边是反的。**
　　`SwipeRightToGo` 被「首页→关于」和「关于→首页」同时用 ⇒ 只能对一半。
　　修法是**给函数加方向参数**，不是复制一份 `SwipeLeftToGo`（复制出来的两份迟早会漂移）。

**1051 · ⭐⭐⭐ 「一句两个 key」和「一个 key 两套资源」是**两个数量级**。**
　　前者要求每个调用点都知道"这句话的两种说法"；后者只要调用点知道"这一句话"。
　　⇒ 全站换语言从「改 N 处」变成「包一层 ctx」。
　　★ 挑方案时先问一句：**这个做法在"文案涨到 300 条"时还成立吗？**

**1052 · ⭐⭐ Android 的资源变体可以拿"保留 locale"当私有开关。**
　　`zz` 是 BCP47 保留码 ⇒ 真机不会被设成它 ⇒ 当"我们的第二语言"最安全。
　　（别用 `eo` / `ja` 这种真语言 —— 哪天主人把系统语言设成它，界面就莫名其妙变龙了 ✗）

**1053 · ⭐ 「不用写满」是这套机制最舒服的地方。**
　　资源 fallback 让 `values-zz` 只需要写"想变的那几句" ⇒
　　这个功能可以**永远处于半成品状态**而不出错，也就不会烂尾。

**1054 · ⭐ 只在一层 provides，比穿透传参干净得多。**
　　彩蛋的开关本来要从「关于页」穿到「整个 App」—— 用 `Lang.version`（全局 state）
　　+ `CompositionLocalProvider` 之后，**一个回调都没传**。

**1055 · ⭐⭐ 先在最小用例上验证机制，再搬 300 条。**
　　机制（`values-zz` 能不能编 / aapt2 收不收 / `stringResource` 能不能当默认参数）
　　只用 7 条样板就全验完了。反过来做 = 拿 300 条文案去撞一个未知的坑。

**1056 · ⭐⭐⭐ 批量改写之后，别去读那 1240 条报错 —— 写个循环让机器收敛。**
　　搬完 895 条，kotlinc 报 1240 处。看着像灾难，其实**只有两类**：
　　①「`stringResource` 用在了非 Compose 上下文」（那行十有八九有 `ctx` 在手边
　　⇒ 就地换成 `ctx.getString` 就行）；②「真要动结构」（只有 4 个函数 + 3 个 object）。
　　⇒ 先写循环把①全部自动修掉，**剩下的才是真正需要动脑的**。
　　★ 判据：循环跑到"改不动了"为止 —— 那时剩下的每一条都值得人看。
　　（本次：第 1 轮自动修 63 处，第 2 轮就只剩 19 条真的。）

**1057 · ⭐⭐ 改写工具必须**自己**正确跳过注释。**
　　第一次盘点报"932 条中文"，其实大量是**注释里的引号**。换成"识别字符串字面量
　　+ 跳过 `//` `/* */`"的词法扫描后，真实数字是 895。
　　★ 盘点的数字错了，后面的所有决定（要不要脚本、分几批）都跟着错。

**1058 · ⭐⭐ 改了代码不重新生成 R，就会满屏 `unresolved reference`。**
　　`R.string.xxx` 是 aapt2 编资源时生成的 ⇒ 搬完文案**必须先跑一次流水线**，
　　`ktcheck.sh` 才认那些新键。★ 而且 classpath 里 **`b_rcls.jar` 必须排最前**
　　—— `work/` 里那几个旧时代的 R jar（`rcls_app.jar`）会被先解析到，
　　报出来的全是假错误（我在这上面白折腾了两轮）。

**1059 · ⭐ 自动插 import 时，注意有的文件**没有** import 段。**
　　`Tree/GrayTable/Conf` 是"注释 + package + 正文"的结构，我的兜底把
　　`import ...` 顶到了第 3 行（`package` 之前）⇒ `syntax error` 刷屏。
　　⇒ 规则：import 一律插在 `package` **之后**。

**1060 · ⭐⭐⭐ 全自动翻译会**改错意思**，而这类错是最贵的。**
　　第一版词库把「默认」→「原样」，于是 **「默认 1000」变成「原样 1000」**（意思变了 ✗）；
　　「功能原理」→「本事原理」（小学生味 ✗）。
　　⇒ 收窄词库：只留"换完还是同义词、绝不会改错意思"的（宿主→大窝 / 气泡→泡泡 / 返回→回窝），
　　其余**只加语气尾巴**（尾巴再怪也只是好笑，不会让人理解错）；长段落（>26 字）保持人话。
　　★ 判据：**宁可少变，不可变歪** —— 好笑是彩蛋，看错是事故。
