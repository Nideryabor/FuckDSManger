# 3.68.1（vc706）—— 🐛 修「换龙龙语后，除了音乐/灰度，其它页面全崩」

> 🐲 尼得亚伯 · 2026-10-11
> 前置：`版本/3.68.0.md`（「说话方式」全量落地）
> 主人原话：「**换语言以后点击原本的调试菜单会崩溃**」
> 补充：「**除了音乐和灰度两个能打开，其它全都会崩溃**」

---

## 一、真凶（不是猜的，是崩溃栈）

```
java.lang.IllegalStateException: No ActivityResultRegistryOwner was provided
    via LocalActivityResultRegistryOwner
  at androidx.activity.compose.ActivityResultRegistryKt.rememberLauncherForActivityResult
  at com.nidyaber.fuckdsmanger.PagesKt.ItemRow(Pages.kt:141)
```

**机制**：Compose 里有两个 local 的取值方式是——

> 「**没被显式 provide 的话，就把 `LocalContext` 向下转型成 Activity 来用**」

| local | 谁在用 | 找不到时 |
|---|---|---|
| `LocalActivityResultRegistryOwner` | `rememberLauncherForActivityResult()`（我们的**选图片**） | **checkNotNull 抛异常** |
| `LocalOnBackPressedDispatcherOwner` | `BackHandler()`（返回键） | 一样抛 |

而尼尼在 3.68.0 干的正是**把 `LocalContext` 换掉** ——
换成 `Lang.wrap()` 出来的、带 `zz` locale 的**包装 Context**（`createConfigurationContext`）。
包装 Context **不是 Activity** ⇒ 上面那两个转型全部失败。

**所以现象完全对得上主人那句话**：

| 页面 | 谁渲染的 | 结果 |
|---|---|---|
| **音乐**（`Music.kt`）/ **灰度**（`Screens.kt`） | **手写 Compose 页面**，不走 `ItemRow` | ✅ 正常 |
| 其它一切（聊天/美化/过检/调试/…） | `TreePage → ItemsBlock → ItemRow` | ❌ **崩** |

关键在于 `ItemRow` 里 `val picker = rememberLauncherForActivityResult(...)` 是
**无条件调用**的（在函数第 141 行，`when (it.k)` 之前）——
于是**只要那一页有任何一个条目**，就一定崩。不是"选图才崩"。

> ⚠️ 人话时不崩，是因为那时 `uiCtx` **就是** Activity 本身，转型成功 ——
> 所以这个坑**只在换语言之后才现形**，属于典型的"改了 A 崩了 B"。

## 二、修法：`MainActivity` 里把**真的 Activity** 显式喂下去

```kotlin
val activityLocals = remember(base) {
    buildList<ProvidedValue<*>> {
        (base as? Activity)?.let { add(LocalActivity provides it) }                       // 三重保险
        (base as? ActivityResultRegistryOwner)?.let {
            add(LocalActivityResultRegistryOwner provides it)                              // 选图片
        }
        (base as? OnBackPressedDispatcherOwner)?.let {
            add(LocalOnBackPressedDispatcherOwner provides it)                             // 返回键
        }
    }
}
CompositionLocalProvider(
    LocalContext provides uiCtx,          // 说话方式（文案从这里出去）
    *activityLocals.toTypedArray(),       // Activity 的能力（选图 / 返回键）
) { FdmTheme { … } }
```

**思路**：我们只换了「说话方式」，**Activity 本身一个字都没动** ——
那就把那个真的 Activity 原样告诉 Compose：「你要的 owner 在这儿」。
`base` 就是 `LocalContext.current` 在 **wrap 之前**的值（本来就是那个 Activity）。

★ 三个都 provide 而不是只修崩的那一个 —— `BackHandler` 那颗雷**只是还没轮到踩**
（一旦换语言后按返回键就会爆），一起拆掉。

⚠️ **没能在设备上自动复现**（想省主人一次操作）—— 用的是
`am start --es page debug` 深链接，但 ColorOS 把**后台启动**拦了：

⇒ Activity 起来一下就被销毁，**根本没渲染**，自然不崩。
⇒ 按铁律**没有去抢前台**，最终还是请主人点一下。

## 四、教训

**1062 · ⭐⭐⭐ 换掉 `LocalContext` 会连带拆掉「Activity 的能力」。**
　　`LocalContext` 不只是"取字符串用的" —— Compose 里**好几个能力**都是
　　「没显式 provide 就去 `LocalContext` 转型」：
　　`LocalActivityResultRegistryOwner`（`rememberLauncherForActivityResult`）、
　　`LocalOnBackPressedDispatcherOwner`（`BackHandler`）、`LocalActivity`…
　　⇒ **换 ctx 的那一刻，这些路全断**。
　　★ 正确姿势：**换 ctx 的同时，把 Activity 的能力显式 provide 回去**
　　（不是只修"崩的那一个"—— 同类的一起拆）。

**1063 · ⭐⭐ 崩溃栈里那行 `PagesKt.ItemRow(SourceFile:141)` 就是答案的一半。**
　　主人说"调试崩"，但报错位置是**条目渲染的公共函数** ⇒ 说明不是"调试页特有的东西"，
　　而是**所有走这条路的页面**都会崩。后来主人补了"除了音乐和灰度都崩"，
　　两者一对：音乐/灰度是**手写页面**、其余全走 `ItemsRow` ⇒ 现象与机制**完全吻合**。
　　★ 判据：**报错位置在"公共函数"里 ⇒ 别只看用户报的那个页面**，去找"谁不走这条路"。

**1064 · ⭐⭐ 「无条件调用的 Composable」= 一条谁都躲不开的路。**
　　`rememberLauncherForActivityResult` 写在 `when (it.k)` **之前** ⇒
　　哪怕这一页根本没有"选图"条目，也照样执行 ⇒ 崩。
　　★ 要么放进真正用到它的分支里（按需），要么保证它需要的东西一定在。

**1065 · ⭐ 没复现 ≠ 没修好；但"没复现"要说清楚为什么。**
　　这次没能在设备上自动复现，原因是**系统拦了后台启动**（日志有 `destroySurface`），
　　而不是"崩溃不存在"。⇒ 文档里必须写明白这层区别，
　　否则下一个接手的人会以为"这 bug 修了之后没再出现 = 已解决"。
