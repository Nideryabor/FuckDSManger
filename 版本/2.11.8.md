## 一、🏆 结构彻底摸清（不再需要猜）

**库**：`deepseek_chat_<id>.db`（**标准 SQLite 明文** ✅，非加密）+ `-wal`

**消息表**：`chat_session_messages_<会话UUID>`（一个库里可有多张，每会话一张）

```sql
CREATE TABLE 'chat_session_messages_xxx'(
  message_id INTEGER PRIMARY KEY,   -- 排序用
  parent_id INTEGER,
  role TEXT,                        -- USER / ASSISTANT
  status TEXT,                      -- FINISHED / …
  inserted_at REAL,
  tips TEXT,                        -- 空数组
  fragments TEXT,                   -- ★ 正文（JSON 数组）
  … )
```

**`fragments` 的真实内容**：

```json
[{"type":"REQUEST",  "id":1, "content":"<用户输入>"}]
[{"type":"THINK",    …}, {"type":"RESPONSE","id":2,"content":"<AI 正文>"}]
```

**会话索引表**：`chat_session_list(id, title, updated_at, current_message_id, …)`

## 二、取数公式（已在本机用 Perl 验证）

```sql
-- ① 最近在聊的会话
SELECT id FROM chat_session_list ORDER BY updated_at DESC LIMIT 1
-- ② 该会话最近几条消息
SELECT role, fragments FROM chat_session_messages_<id>
WHERE status='FINISHED'
ORDER BY message_id DESC LIMIT 8
-- ③ 解析 JSON：只取 REQUEST / RESPONSE 的 content（跳过 THINK），倒序拼成上下文
```

## 三、本版实现：`dbSid()`

遍历 `databases/deepseek_chat*.db`，从 `chat_session_list` 取**最近会话 id** ⇒ `probe()` 里 log `SID <uuid>`。

**⇒ 下一步**：用这个 id 查消息 → 解析 JSON → 接入 `ctxText()`。

## 六、教训

| # | 教训 |
|---|---|
| **470** | ⭐⭐⭐ **"拿到原始文件"比"在设备上试探"快一个数量级**：在手机上折腾了 8 版（`hp8`/`nx`/`blocks`/`NOTADB`），而文件一到手，**Perl 十分钟就把表结构+正文格式全摊开了** ⇒ **遇到"黑盒"，先想办法把黑盒拿出来** |
| **471** | ⭐⭐⭐ **"内存对象"≠"持久化真身"**：Compose 里的 `nx` 是空骨架，**真身在 SQLite**（`fragments` 字段）⇒ **数据密集型 App 的正文十有八九在落盘层** |
| **472** | ⭐⭐ **读库只看结构、不看内容**：能写工具就别靠眼睛扫 —— 我的 Perl 脚本默认**打码输出**，既验证了逻辑，也守住了边界 |
| **473** | ⭐⭐ **不依赖"会话 id 从哪来"**：与其去 hook 一个拿 id 的方法，不如**用 `updated_at` 排序选"最近活跃会话"** —— 少一个 hook，少一处失败点 |
