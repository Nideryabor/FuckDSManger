## 二、根因（**我自己的锅，而且是反复警示的那个家族**）

`GmUtil.logOnce` 是**两参数** `(String tag, String msg)`，我在 `wrap()` 里写成了**单参调用**：

```smali
# ❌ 2.21.1 里
const-string v1, "[气泡] 没取到 Shape，放弃注入"
invoke-static {v1}, Lcom/.../GmUtil;->logOnce(Ljava/lang/String;Ljava/lang/String;)V

# ✅ 2.21.2
const-string v1, "[气泡] 没取到 Shape"
const-string v2, "放弃注入（shape 为空）"
invoke-static {v1, v2}, Lcom/.../GmUtil;->logOnce(Ljava/lang/String;Ljava/lang/String;)V
```

**偏移对得上**：`[0x8]` 是 **DexPC（代码单元）**偏移 = 字节 `0x10`
　`0x0` invoke-static(3 unit) → `0x3` move-result-object(1) → `0x4` if-nez(2) → `0x6` const-string(2) → **`0x8` = 那条 invoke** ✓

**为什么后果这么大**：ART 的校验是**类级**的 ⇒ 一个方法不过 ⇒ **整个 `GmBubble` 被拒**
- `GmBubble.on()` 也一起炸 ⇒ 点「美化」直接崩宿主（`GmBeautyDialog.open` 里那行新 Switch 读 `GmBubble.on()`）
- 气泡钩子里的 `GmBubble.*` 调用全部抛异常 ⇒ 被各自的 try/catch **静默吞掉** ⇒ 表现就是「没效果 + 一行日志都没有」

> 🎓 **但它带来一个硬结论**：崩在 `GmBeautyDialog.open:327`（那行只有 2.21.1 才存在）
> ⇒ **主人跑的确实是新 dex** ⇒ **铁律 181「没强停宿主」这个嫌疑被排除**。

## 五、教训

| # | 要点 |
|---|---|
| **642** | ⭐⭐⭐ **`invoke-*` 参数个数必须逐条数**（本项目教训 583 复现）—— **smali 汇编器不校验**，`mt_apk_edit_check` **也不校验字节码**，一路过到真机才炸。**本项目专用自检清单应加一条：每个 `invoke` 的寄存器个数 = 目标签名的参数个数**（宽类型 long/double 占 **2** 个寄存器）。 |
| **643** | ⭐⭐⭐ **ART 是「类级」拒绝**：一个方法不过 ⇒ **整类不可用** ⇒ 该类所有功能静默失效（还可能被自己的 try/catch 吞掉）。⇒ **一个类里任何一处 VerifyError，症状都是「这个类的功能整体不存在」**。 |
| **644** | ⭐⭐ **Diagnostic 代码本身是最大的风险源**（教训 259 复现）：这次挂的是**诊断用的 `logOnce`**，而不是功能代码。 |
| **645** | ⭐⭐ **崩溃栈里那一行能反推「跑的是哪版 dex」**：`GmBeautyDialog.open:327` 只存在于 2.21.1 ⇒ 一举排除「没强停宿主」的嫌疑。**崩溃位置也是版本指纹。** |
| **646** | ⭐ **给「新类」做入口 UI 时，第一件事是确认它 Verify 得过**：菜单是「第一次触达该类」的入口，类被否 ⇒ 用户第一眼就是崩。**先把类跑通，再上 UI。** |
