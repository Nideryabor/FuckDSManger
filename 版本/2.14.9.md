## 一、终于有"铁证"了：`wr.a` 就是会话 id，而我们手里那只容器是空的

`nn1.A()`（发送协程体）里的埋点代码：

```java

v9 = wr.a                              // ⭐ 直接作为 "chat_session_id" 上报！
invoke-static {"chat_session_id", v9, "sse_transaction_uuid", ...}
invoke-virtual {v7}, Lwr;->h()Ljava/lang/String;   // 服务端回传的新会话 id
invoke-virtual {v5, v1}, Lwr;->B(Ljava/lang/String;)V   // ← 写回容器
```

再加上 `M()` 的真身：`this.v → getValue() → ho1.b() → wr` —— **和 `I()` 用的是同一个字段** ✓

⇒ 所以：
1. **`wr.a` 就是会话 id**（2.14.8 我改去读 `h()` 是错的：`h()` 是**新会话时服务端回传**的 id，旧会话里当然是 null）；
2. 我们手里那个 component 的容器 `wr.a` **真的是空** ⇒ **在宿主眼里那就是"还没有会话的新对话"** ⇒ 我们一发，它当然只能新开一个 ✓✓（不是"挑错组件"，而是"这个组件确实没有会话"）。

## 二、2.14.9：不再从 component 里"读"会话 —— 借宿主自己用过的容器

关键：**发送命令 `nn1` 自带容器**：

```java
new nn1(wr /*g*/, text /*h*/, ao1 /*i*/, …, pr8 /*l*/, modelType /*m*/, attachments /*n*/)
```

⇒ 在**真实发送**时（`ao1.J` 收到 `nn1`）把它缓存下来：

| 缓存字段 | 来源 | 作用 |
|---|---|---|
| `sCwr` | `nn1.g` | ⭐ **会话就在它身上（`wr.a`）** |
| `sCcomp` | `nn1.i` | 发起那次发送的 component |
| `sCmodel` | `nn1.m` | 模型类型 |

之后我们发送时**直接调宿主自己的 `V(Lao1;String;List;String;Lpr8;Lwr;ZZZ)`**（它就是 `I()` 最后用来组命令+派发的那个方法）⇒ **组出来的命令带着那只 `wr` ⇒ 会话跟着走 ⇒ 消息落回同一对话** ✓✓✓

技术细节（全部用纯 Java 反射，避开桥 API 差异）：
- 用 `Class.getDeclaredMethod("V", 9个参数类型)` 精确取方法（三个 `boolean` 用 `Boolean.TYPE` 取 → 反射会自动拆箱）
- `pr8` 现造一个：`getDeclaredConstructor(Long.TYPE, String.class)` + `newInstance(elapsedRealtime(), UUID)` 
- 附件传空 `ArrayList`
- 缓存没准备好时 → **回落到原来的 `I()` 通道**（并在日志里说明）
