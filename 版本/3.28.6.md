> （另：主人还提了「上传图片不显示对勾」—— 本轮**未定性**，见第五节）

## 一、真机取证

```

  {"messages":[{"id":0,"text":"你好，我能帮你什么忙？"},{"id":1,…},{"id":2,…},{"id":3,…},

  {"messages":[{"id":0,"text":"你好"},{"id":1,"text":"测试"}],"fallback_message":[]}  ← 只剩 2 条
UI 侧 cfg_state： "welcome":""（读不到）· "suggest_text":"…\n…"（换行已正确 ✓）
```

## 二、三个根因

### ① 上版那个"写入"是**整体替换**，把其余 6 条冲掉了

宿主是**按 id 分时段**挑招呼语的（默认 8 条：早上/白天/深夜各若干）。而 UI 那个框的**读是坏的**（见 ②），
主人看到的是空框 ⇒ 填了 2 行 ⇒ 我们把整份配置替换成 2 条 ⇒ **宿主挑不到对应时段 ⇒ 回落默认** ✗

**修**：`dispatchText` 写招呼语时**先读回原条目 id，逐行沿用**（第 i 行延用原第 i 条的 id，多出来的行才新编号）
⇒ 行数不变时 id 全保留，宿主的时段语义不丢。

### ② 读不到（`welcome` = 空）

`helloLines()` 只走 `GmHello.get()`，拿不到就静默返回 ""（连日志都没有 ✗ —— 这是我埋的坑：
helper 里 `catch → return ""` 把证据全吞了）。
**修**：走不到就**兜底直读宿主键** `kv_remote_settings_welcome_msg`（`GmStore.read2`），并且**失败要出声**（打日志）。

### ③ 「恢复默认」按钮从来没人接

UI 的 `hello_reset` / `suggest_reset` / `prompt_reset` 三个动作**桥里根本没有分支** ⇒ 点了毫无反应 ✗
**修**：接上 ——
- `hello_reset` → `GmHello.restore(ctx)`（**从备份键还原**那一刻宿主真值）+ `GmHello.reapply(ctx)`
- `suggest_reset` → `GmSuggest.restore(ctx)`
- `prompt_reset` → `GmPrompt.restore(ctx)` + `GmPrompt.apply(ctx)`

⇒ **主人那条"变成默认"的招呼语，点一下「招呼用语 › 恢复默认」就能从备份还原回 8 条** ✅

## 六、教训

| # | 要点 |
|---|---|
| 1 | ⭐⭐⭐ **"读不到"是危险的**（比"写不进"更危险）—— 用户看到空框就会**凭记忆重填**，而"整体替换式写入"会把剩下的条目**静默删掉**。**编辑器的"读"坏了 = 数据会被用户亲手毁掉。** |
| 2 | ⭐⭐⭐ **结构化配置不能用"纯文本行"当唯一入口** —— 招呼语带 id（时段语义），文本行只是它的投影。**投影式编辑必须"按位对回 id"，否则一定丢结构。** |
| 3 | ⭐⭐ **helper 里的 `catch → return ""` 等于把证据吃掉**（本轮排查卡在这里一轮）。**兜底要出声**：要么打日志，要么把失败原因带回去。 |
| 4 | ⭐⭐ **UI 上的按钮/动作，桥里必须逐个对账**（三个 `*_reset` 从来没人接，UI 看起来"点了没反应"）—— 出包自检可以加一条：UI 里出现的 `cmd=` 值，桥的 `onCmd` 里必须都有分支。 |
