## 一、3.72.7 · 昵称替换：「hook 没装」是**误判**

### 1.1 复盘里怎么写错的

复盘 §十一 #3 的原文：「配置推过来了（`fuckds_nick=dxyabab`），但 **LSPosed 日志里没有任何「昵称 hook 已安装」** ⇒ 那个 hook 根本没装」。

**真相**：`GmEntry` 里注册昵称那条**本来就没有写日志**（`GmEntry.java:96` 只有一行 `hookM`，上下只有气泡那一条 `log`）⇒ 用「找不到日志」推「没装」是**拿不存在的东西当证据**。

真凭据在 LSPosed 日志里，一直在：
```
(com.deepseek.chat.a)[…FuckDSManger…] FuckDSManger: hookM c6.v count=1     ← 每次启动都有
```
`c6` 就是 2.7.2 的「账号名桶」（`GmRemap.CLS5` 的 `s5/a6/a6/z5/c6` 那一行）。**hook 装上了，一个字节没漏。**

### 1.2 真因：那个 `when` 枚举被插了新分支

`GmNameHook.beforeHookedMethod` 的判据是：

```
getIntField(thisObject, "a") == 8   ⇒  setResult(GmName.getText(ctx))
```

`8` 是 **2.6.1 时代** `Ls5;->v()` 里「账号名」那个 `a` 值（当时全库构造点只有一个传 `0x8`，就是 `UserInfoFooter`）。
但 2.7.1 起宿主给这个 `when` **插了一个新分支**，下标整体后移：

| `a` | 2.6.1 | 2.7.1 (`z5.w`) | 2.7.2 (`c6.v`) |
|---|---|---|---|
| 8 | **账号名** | `session_list`（侧边栏会话点击埋点） | 同左（`:pswitch_470`，字面量 `"session_list"`） |
| 9 | — | **账号名** | **账号名**（`:pswitch_413`） |

证据（`tmp/h272/c6.smali`，`v()` 的 `:pswitch_data_660`）：

| index | 标签 | 干了什么 |
|---|---|---|
| `0x8` | `:pswitch_470` | 取 `fy4.v()` 两次 + `ox1.i(0,"session_list")` ⇒ **纯埋点** |
| `0x9` | `:pswitch_413` | `olb.c` → 否则 `yy.b()`（昵称）→ 空则 `yy.e()`（手机号）→ `"****"` 打码 ⇒ **侧边栏那行字** |

`tmp/h271/z5.smali` 的 `w()` 同样是 index 9 ⇒ **这条从 2.7.1 起就是坏的**，只是没人验过昵称。

### 1.3 顺手拆掉的一颗雷

`a == 8` 在 2.7.1+ 是**埋点分支**，而我们的 `beforeHookedMethod` 会 `setResult(String)` ——
等于把「点侧边栏会话列表」的返回值从宿主自己的单例对象换成了字符串。
**这不是"没效果"，这是往宿主的事件链里塞了一个错类型。** 改对下标之后这颗雷自然消失。

### 1.4 改法（`tmp/base130_261/sm/.../gm/GmNameHook.smali`）

```smali
const/16 v2, 0x9
if-eq v1, v2, :gm_accname
goto :cond_2b
:gm_accname
const-string v2, "【昵称】a=9 命中账号名分支，替换为自定义名"
invoke-static {v2}, Lcom/nidyaber/fuckdsmanger/gm/GmUtil;->log(Ljava/lang/String;)V
```

⚠️ **自己咬了自己一口**：第一遍把 `if-eq` 写成了 `if-ne`（"不相等就替换"），
smali 汇编**不报错**，语义正好反过来。反编译回来核对 `const/16 v2, 0x9` + `if-eq` 才看出来。
**教训 1117。**

## 二、3.72.8 · A/B 分组号 `kv_remote_settings_id_<键>`

### 2.1 宿主那边是怎么用它的（读 `mj7.b()` 才知道）

`mj7` = 2.7.2 的配置源头 model 域。它把每个下发键做成一对
`(key, "kv_remote_settings_id_"+key)`，然后：

```
if (本轮下发里带这个 key) { 拿本轮 id → 覆盖 _id_ → 刷 kv_remote_settings_<key> → 进内存 map }
else                      { 走「老缓存的 _id_」 }
```

而宿主 `getXxx` **优先读那个内存 ConcurrentHashMap**。
我们的实例是**会话中途才初始化**的 ⇒ 永远收不到下一次下发 ⇒
凡是「我们新写、宿主自己没下发过」的键，`_id_` 是空的 ⇒ **它进不了 map** ⇒
表现就是「键写了、面板上有值、宿主不认」。

### 2.2 两条安全约束（写进代码注释了）

| 约束 | 为什么 |
|---|---|
| **只在缺失时补** | 宿主已有真 `_id_` 就一个字节都不动 —— 覆盖真 id 等于伪造下发批次 |
| **不知道就不写** | 值取自 `AB_IDS`（= 本机真实下发那份 `tmp/abcfg-2.7.2.json`），表里没有的键宁可不写，也不编假 id 骗服务端 |

实现：`FdmBridge.abIdPatch(ctx, sp, bare)` + `FdmBridge.AB_IDS`（22 项键→vid），
在 `grayWrite` **最后**调用（主通道 / 缓存层 / 影子键 / pin 表都写完再补）。

### 2.3 灰度表补 4 项（`GmDialog.<clinit>`）

`const/16 v0, 0x56`（86）→ `0x5a`（90），末尾追加：

| 键 | 名称 | 类型 |
|---|---|---|
| `max_input_files` | 单次最多文件数 | `i` |
| `query_title_time_interval` | 标题查询间隔 | `i` |
| `report_http_biz_error` | 上报 HTTP 业务错误 | `b` |
| `stop_stream_wait_times` | 停止流等待次数 | `i` |

（4 项都来自 `tmp/abcfg-2.7.2.json` 全量 22 项的清单，与遗留 #5 点名的完全一致）

## 三、教训

| # | 教训 |
|---|---|
| **1115** | **「日志里没有」≠「没发生」** —— 先确认那条日志**本来存在**（`GmEntry` 昵称那行压根没有 `log`），拿「不存在的东西」当证据，会把结论带偏一整晚 |
| **1116** | **`when` 的下标是"宿主随时会插队的序号"** —— `a == 8 / 0xf` 这种判据必须每轮重验；而且**判错不是"不生效"这么轻**，可能把别的分支的返回值换成错类型 |
| **1117** | smali 的 `if-eq` / `if-ne` 反了一眼看不出来（`e9`/`9e` 差一个字节）—— **改完必须反编译回来逐字读一遍**，汇编不报错不代表语义对 |
