## 0. 两个锅，第二层是我自己埋的

### 锅一：N 从 6 改成 10 是贪了

`前 10 层` 太宽。**2.22.51 当时用的就是 6**，而且那次是主人亲口说「**这次有背景（第一次成功！）**」。多出来的 4 层就是闯祸的那 4 层。

### 锅二（更要命）：**我把 `sPageCnt` 的语义弄坏了，然后用这个坏值去推理**

2.22.66/67 我把"调用点门"插在了 `sPageCnt++` **前面**：

```smali
if-lt cnt, 10, :pass     ← 门读 cnt
...                      ← 门不通过就 return
sPageCnt++               ← 计数在门后面 ⇒ 只有"过了门的"才被计数
```

⇒ **计数器在给自己的门计数** ⇒ 它不再是「本页第几层绘制」，而变成「过了几次门」。

⚠️ **后果**：我在 2.22.67 里写的推理「那堆按钮的 `cnt` 在 20+」——**那个 20 就是被污染的读数**。**我拿一个被自己改坏的数去做了判断。**

## 1. 本轮修法

**① 把计数挪回判据之前**（恢复它本来的语义 = 本页第几次合格绘制）：

```smali
sget sDepth ; if-gtz → return          # 只处理最外层（原守卫）
sPageCnt++                             # ★ 无条件自增（判据之前）
```

**② N 回到 6**：

```
if (caller() == "ju.q:2104")  → 放行          # 调用点白名单（精确）
if (sPageCnt <= 6)            → 放行          # ★ 最外前 6 层（2.22.51 验证过）
否则                           → 原样不动
```

**改动清单**：

| # | 位置 | 改动 |
|---|---|---|
| 1 | `pg` 尾部 | **删掉** `sget sPageCnt / add-int/lit8 / sput sPageCnt`（那三行的位置在判据之后，会污染语义） |
| 2 | `pg` 判据前 | **插入** `sget sPageCnt / add-int/lit8 v1, v1, 0x1 / sput`（无条件自增） |
| 3 | `pg` 层数门 | `const/16 v2, 0xa` + `if-lt v1, v2, :pass` ⇒ **`const/16 v2, 0x6` + `if-gt v1, v2, :pass`**（因为已经自增过，这里用 `<=`） |
| 4 | `logOnce` 文案 | `… 本页前 6 层（NL 2.22.68：计数已恢复为绘制序号）` |
| 5 | 版本串 ×3 + manifest | `2.22.67/398` → **`2.22.68/399`** |

**产物回读验证**：`2.22.68` · `399` · **`128 类`** · V1+V2+V3 · sha256(partial) `6895027d…` ✓
