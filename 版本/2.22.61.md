## 0. 一句话结论

上一轮（`2.22.60`）只把「**调用点**」打进了日志；这一版把**「器」**做齐了：

1. **`GmProbe`** —— 一个能拖的小悬浮点，单击把整段 `sProbeLog` 写进模块日志文件，长按复制到剪贴板；
2. **挂载点** —— 它不是散落的开关，而是**「调试」页里的一条二级菜单**；
3. **「调试」页被改造成菜单页** —— 原来那一大坨文本框（`===== DIAG =====` + `===== DS DATA =====`）搬进新弹窗 `GmDumpDialog`，页面上只留一条二级菜单指向它；
4. **标题改名** —— `服务端灰度下发` → **`调试`**（那个文本框的名字则变成二级菜单项：**`模块日志&服务器最新下发内容`**）。

## 1. 「调试」页 · 改造前后

### 改造前（2.22.53）

```
Dialog GmDsDialog
 ├─ 标题    「服务端灰度下发」
 ├─ 副标题  「下发点命中 N 次 · X KB」
 ├─ 分割线
 ├─ ScrollView（weight=1）
 │    └─ TextView（可选中，9f）
 │         ===== DIAG =====\n + GmDiag.text()
 │         ===== DS DATA =====\n + GmDs.read()
 └─ Button「清空」(0x10)  ·  Button「返回」(0xf)
```

### 改造后（2.22.61）

```
Dialog GmDsDialog               ← 主面板里那条「调试 / 日志（DSMlogs）」仍指向它
 ├─ 标题    「调试」                                      ← ④ 改名
 ├─ 副标题  「下发点命中 N 次 · X KB」（保留：一眼看状态）
 ├─ 分割线
 ├─ ScrollView（weight=1）
 │    └─ 二级菜单列表
 │         ├─ 「模块日志&服务器最新下发内容」  → GmClick(0x3f)  ← ③
 │         │    desc: DIAG 诊断 + 服务器最新下发数据
 │         └─ 「元素捕获器」                   → GmClick(0x42)  ← ②
 │              desc: 挂一个小悬浮点：拖到目标元素上，单击写日志 / 长按复制
 └─ Button「清空」(0x10)  ·  Button「返回」(0xf)
```

### 新增弹窗 `GmDumpDialog`（文本框的新家）

```
Dialog GmDumpDialog
 ├─ 标题    「模块日志&服务器最新下发内容」
 ├─ 分割线
 ├─ ScrollView（weight=1）→ TextView（可选中，9f，内容**与改造前逐字一致**）
 └─ Button「复制」(0x41 → 整段进剪贴板) · Button「返回」(0x40)
```

> **为什么把文本框搬走而不是留着**：它搬走之后，「调试」页才有位置放**二级菜单**；而它自己换个弹窗仍然一字不少地显示同样的内容，外加一个**复制**按钮（原来只能长按选中，9f 字号下很难选全）。
> `GmDumpDialog` **不重复调 `GmDs.scan()`** —— 进「调试」页时已经扫过一次，数据同源，避免每次开二级页都重扫。

### 为什么 `0x42` 要连关两个弹窗

「调试」页是从**主面板**（`GmMenuDialog`）顶上弹出来的，两个都是 **Dialog 窗口**；而 `GmProbe` 是插进 **`decorView`** 的。
⇒ 不关弹窗，悬浮点被压在弹窗下面**根本摸不到**。所以点「元素捕获器」= **挂上/摘掉 + 关掉调试页 + 关掉主面板** ⇒ 直接回到聊天页就能拖。

## 4. 教训（116~120）

| # | 内容 |
|---|---|
| **116** | ⭐⭐⭐ **删一个「没用」的手势前，先查它还有没有别的副作用**：`GmTouchHook` 表面是「连点 3 下开设备弹窗」，实际**它还在给 `GmEntry.sTick` 打心跳**（`GmEntry.run()` 用 `0xbb8` 判「3 秒无触摸 ⇒ `hide()` 顶部悬浮条」）⇒ **整类删掉 = 悬浮条行为被改变**。**正确手术：只摘手势与它的计数器，心跳留下**。方法：动手前对目标字段跑 `mt_apk_dex_xref`，看还有谁读它。 |
| **117** | ⭐⭐ **「改造」比「重写」安全的做法：把内容**搬**走，而不是**删**掉**：调试页要腾位置给二级菜单，但那一大坨文本**一个字都不能少** ⇒ 建一个 `GmDumpDialog` **原样承载**（连拼接顺序都照抄），页面只留一条指路菜单 ⇒ 主人看不到任何"功能丢了"。**遇到"这一页要变成菜单页"的需求时，先问「原来的内容搬去哪」，别急着删。** |
| **118** | ⭐⭐ **新类先落盘成 `.smali` 再进会话**：`tmp/GmProbe.smali` → `perl tools/vercheck.pl` → `mt_apk_edit_text(targetVersion="missing")`。`"missing"` **可以创建不存在的类**（本项目首次验证可用，`GmProbe` / `GmDumpDialog` 都走这条路）。 |
| **119** | ⭐⭐ **寄存器纪律 = 一个用途一个寄存器 + try 内早返回**：同一寄存器在不同分支写不同类型会在 merge 点冲突（正是 `vercheck.pl` 抓的第 2 类问题）；早返回能直接消灭大量 merge 点。本版两个大方法（`GmDsDialog.open` 用 `v0..v9`、`GmDumpDialog.open` 用 `v0..v7`）都是**线性布局 + 固定槽位**。 |
| **120** | ⭐ **`matchText` 要从「搜索结果的片段」里逐字复制，不要凭记忆写**：`轮转256KB` 我写成了 `轮转 256KB`（多一个空格）⇒ `TEXT_MATCH_NOT_FOUND`。这类失配代价很小（原子失败、可重试），但**同一批 `edits[]` 是原子的** ⇒ 一条失败会让同批另一条也不生效（本例 `handleLoadPackage` 那条字符串就白写了）。**小批量、多批次**比一次塞一堆更稳。 |

## 5. 遗留 / 下一步

1. **等主人的 `from=` 日志** ⇒ 对照「页面背景」与「那堆按钮」的调用点是否不同 ⇒ 下一步做**按调用点精确透空**（颜色从此不参与判定）。
2. **`元素捕获器` 菜单项目前不显示「已开启/关闭」状态**（靠 Toast 反馈）。若主人觉得需要，可改成进页面时读 `GmProbe` 的静态字段、把 desc 换成「当前：已挂上 / 未挂上」。
3. **`GmDumpDialog` 的「复制」不刷新内容** —— 它复制的是**点按钮那一刻重新拼的**文本（`text()` 现算），所以数据是最新的；但弹窗里**显示的**仍是打开时的快照，想刷新就 `返回` 再进一次。
4. **顶部悬浮条**（`GmEntry.sBar`）与本捕获器是两个独立的东西，互不影响；捕获器在**左上 12dp / 上 240dp** 起步（避开悬浮条）。
