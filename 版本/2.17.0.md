# FuckDSManger NL 2.17.0（🎙 自动化：从通话页直接驱动宿主的录音控制器）

> 产物：`FuckDSManger_NL_2.17.0_for_ds2.5.2.apk`（**293 / NL 2.17.0**，104 类，V1+V2+V3，sha256(partial) `9e39d298…`）

## 一、主人两条反馈 → 同一个根因
1. "文字不在通话页显示"
2. "想再发一条语音，必须先关闭通话界面，再按宿主麦克风"

⇒ **根因同一个**：我们的通话页是**全屏 Dialog**，开着的时候**够不到宿主输入栏的麦克风** ⇒ 主人只能关掉它去按麦克风 ⇒ 而语音消息发出时**通话页是关的**，转录自然无处可显。

## 二、⭐ 找到了"宿主的录音控制器"（自动化关键）
```
Lxe1;  = com.deepseek.chat.ui.pages.chat.session.record.ChatPageRecordCapabilityImpl
   ├─ 由 ao1（会话 component）持有 → 字段 j:Lxe1;     ← 我们早就握着 ao1！
   ├─ s(Lgz3;Ljava/lang/String;)Z   手势入口（含 RECORD_AUDIO 权限处理）
   ├─ k()V  → J(Z)V   "gesture commit!"  松手提交（停录 + 发送，含 record_stop_delay_ms）
   ├─ E()V            "cancel recording!" 取消
   └─ p:Lqra;  ← 就是录音器（V()起录 / Q()停录）
Lgz3; 枚举 = Idle / Pressed / ReleaseToCancel
```
⇒ **自动化三步**：`s(Pressed,"")` 开始听 → `k()` 松手提交（宿主自己停录并发送）→ `E()` 取消 ✓

## 三、2.17.0 实现
| 新增 | 说明 |
|---|---|
| `GmCallDialog.recOn()/recOff()/recCancel()` | 取 `ao1.j` → 调 `s(Pressed,"")` / `k()` / `E()`（全程 try+catch+落盘日志） |
| 新类 **`GmCallPTT`**（`View$OnTouchListener`） | DOWN→`recOn()`、UP→`recOff()`、CANCEL→`recCancel()` |
| 通话页第 4 个按钮 **「🎙 按住说话」** | 挂在按钮行（与 挂断/免提/允许AI被打断 同级） |

⇒ **全流程都在通话页里**：按住说话 → 宿主开始录音+ASR → 松手 → 宿主停录并自动发送 → 识别文字进转录（`fn1.a`）→ AI 回复由宿主朗读 ✓

## 四、复测
1. 装 **2.17.0** → 强停宿主 → 进对话 → 点 🎧 开通话页
2. **按住通话页里的「🎙 按住说话」** → 说一句 → 松手
3. 期望：
   - 日志 `[通话] 已请求宿主开始聆听（Pressed）` → `已请求宿主开始聆听` → `[通话][录音] AudioRecord.startRecording`
   - 松手：`[通话] 已提交说话（宿主停录并发送）` → `命令 args[0]=fn1` → `👤 <你的话>` 出现在转录区
   - AI 回复自动朗读；随后**可以直接再按**，不必退出页面 ✓
4. 若按下没反应：日志会有 `[通话] 开始聆听失败（见上一条堆栈）`；另一种可能是**需要先让输入栏进入"语音模式"**（那样我再补一步：先走宿主麦克风按钮的同一入口）

## 五、教训
| # | 教训 |
|---|---|
| **558** | ⭐⭐⭐ **"界面挡住宿主"是产品级坑**：全屏 Dialog 让宿主入口不可达 ⇒ 必须**自己提供入口**（本轮＝页内 PTT 按钮），否则用户被迫来回切换、功能看起来"时好时坏"。 |
| **559** | ⭐⭐⭐ **自动化钥匙就在"已经握着的那条链"上**：`ao1` → `j:Lxe1;`（录音控制器）—— **先查"我已有的对象能不能直达目标能力"，再考虑新增 hook/模拟触摸**。 |
| **560** | ⭐⭐ **枚举常量名就是语义文档**：`Idle / Pressed / ReleaseToCancel` 直接把手势状态机讲清了 ⇒ 搜 `<clinit>` 里的字符串比读代码快得多。 |
