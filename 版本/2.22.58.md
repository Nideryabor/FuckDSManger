## 2. 本版改动：分档判据 → **「这个颜色是否曾被确认为背景色」**

```smali
    # 改前
    sget v6, sSameCnt:I ; const/4 v8, 0x2 ; if-lt v6, v8, :half
    const-wide/16 v2, 0x0 ; goto :set

    # 改后
    const-wide/16 v2, 0x0                      # 默认：全透明
    sget-wide v6, sPageColor:J
    cmp-long v8, v4, v6
    if-nez v8, :set                            # ★ 等于「背景色」⇒ 全透明
    …（否则按 50% 半透明）…
    :set
```

**配合上一版已有的**：`sSameCnt >= 2 ⇒ sput sPageColor`（把连续 ≥2 的颜色**登记为背景色**）。

⇒ **一旦某颜色被登记为背景色，之后它每次出现都全透明** —— 不再受"中间夹入别的颜色"影响。

## 3. 还有一个"可能不是 bug"的情况（先记下）

**半透明 50% 的 `#0F0F0F` 叠在背景图上，若背景图该处也很暗**：

```
结果 = 0.5 × 0x0F + 0.5 × (图色 ≈ 0x0F) ≈ 0x0F
```

⇒ **仍然是 `#0F0F0F`** —— 这种情况**不是没生效，而是"看不出来"**。
本版改用**全透明（α=0）**后 ⇒ 结果 = **纯背景图** ⇒ 该区域不会再被判为 `#0F0F0F`。
⇒ **所以下一张图里 `#0F0F0F` 的占比应该继续下降**（这是可量化的验证）。

| # | 内容 |
|---|---|
| **843** | ⭐⭐⭐ **"看不出来"不等于"没生效"——用数值对比代替肉眼判断**：主人说"没看出来区别"，但**占比从 37.93% 降到 22.36%** 是硬证据。⇒ **改动效果可量化时，先量再谈"有没有变化"**，否则会被"暗色下看不出来"误导，去改本来已经对了的地方。 |
