## 〇、先修掉三个真机 bug

### bug① 宿主收不到状态，但能暂停（症状很怪）

**真因**：状态广播里尼尼写了 `setPackage(我们自己的包名)`。
`setPackage` 过滤的是「**收广播那个 App** 的包名」，而我们的接收器虽然由我们注册，
却住在**宿主进程**里（= 宿主的 UID）⇒ **被过滤掉**。
而「卡片 → 播放器」方向没被过滤（接收器真在模块进程）⇒ 所以**暂停能用、别的全空**。

修法：发隐式广播，安全性交给接收器那边的**令牌校验**。

### bug② 封面永远是空的

**真因**：搜索接口返回的 `album` 里**只有 `picId`，没有 `picUrl`**
（实测打印原始 JSON 证实的）。而 `/api/v3/song/detail` **给 picUrl**。
修法：搜索后自动补一次 `songDetail`（一次请求补齐整批）。

### bug③ 位置只能上下拖

修法：拖动同时改 X/Y，并存 `fuckds_bar_x`。

## 二、★★ 版权（主人 2026-10-06 明确要求）

**一律不落盘的东西**（代码里逐条注释了）：

| 东西 | 处理 |
|---|---|
| **音频** | `MediaPlayer` 直接流式播 CDN 链接 —— **永不下载、永不落盘** |

## 三、★ 网易云登录（三条路，无二维码）

主人：「去掉二维码，换成手机或者 cookie 或者密码登录」。

**新增** `music/GmMusicApi` 的 **weapi** 通道（登录走 weapi，不是 eapi）：

```
POST https://music.163.com/weapi/<uri 去掉 /api/>
body = params=<base64>&encSecKey=<hex>
```

（加密早就实现了 —— `GmMusicCrypto.weapi()`，这次补上 http 那层 + 抓 Set-Cookie。）

| 方式 | 接口 | 说明 |
|---|---|---|
| ① 手机 + 短信验证码 | `/api/sms/captcha/sent` → `/api/w/login/cellphone` | 先发码（60s 倒计时）再登录 |
| ② 手机 / 邮箱 + 密码 | `/api/w/login/cellphone` / `/api/w/login` | 密码本机 md5，**不保存** |
| ③ 直接粘 cookie | 无需请求 | 从浏览器抠 `MUSIC_U`；给整条 cookie 串也行（会自动挑） |

**沙箱实测**（不真发短信，只验通道）：
```
loginStatus       → code=200（请求成功）
假密码登录         → code=502 «账号或密码错误»   ← 真服务器在处理 ✅
```

**登录态怎么存**（`bridge/GmMusicLogin.java`）：

* 文件：`/data/data/<宿主>/files/FDMmusic/login.json`
* 为什么是宿主私有目录：**只有宿主自己能读** —— 实测连 adb 都 `Permission denied`
* 模块 UI 登录成功后，凭证通过桥（`music_login_save`）送给宿主，由宿主写自己的目录
  （模块没有权限写宿主 /data/data）
* 宿主每次启动 `GmMusicLogin.apply()` 读回来注入 ⇒ 重启宿主仍是登录状态

### ⚠️⚠️ 明文存储（主人特意要求告诉用户）

**文件是明文的，没有加密。** 界面上专门做了一张「隐私」卡说明：

> · 存在哪：宿主私有目录（别的 App 读不到）
> · ⚠️ **root 用户请注意**：root / 备份 / 调试工具能直接读到，拿到它等于拿到你的网易云账号
> · 永远不要分享、截图、上传这段凭证
> · 不放心就点「退出登录」，文件会被删除

（代码注释 + 界面卡片 + 本文档 **三处**都写了这条警告。）

## 六、教训

**961 · ⭐⭐⭐ `setPackage()` 过滤的是「收广播那个 App」，不是「发广播那个」。**
我们的接收器由我们注册、却住在宿主进程 ⇒ 被自己的 `setPackage` 拒收。
症状极具迷惑性：**一个方向通、另一个方向哑**。
跨进程广播别用 `setPackage` 来"限定自己人"，要用**令牌校验**。

**962 · ⭐⭐⭐ 「字段名对了一半」比完全写错更难查。**
尼尼的 `normalize()` 里 `ar` 对（`artists` 是别名）、`al` 错（搜索返回的是 `album`），
于是「歌手有、封面没有」—— 看着像"接口不给封面"，其实是字段名不对。
**遇到"数据缺一块"，先打印原始 JSON 看真名**，别照着记忆猜。

**963 · ⭐⭐ 把「不能做什么」写进文件本身。**
版权要求"封面/歌词/音频不落盘"—— 尼尼除了在代码注释里写，还在
`state.json` 里塞了一行 `_note` 说明"本文件不含受版权保护内容"。
**让文件自己解释自己**，后来的人（包括未来的自己）就不会手滑加字段。

**964 · ⭐⭐ 敏感数据要「存在只有自己能读的地方 + 显著告知」。**
登录凭证放宿主私有目录（实测 adb 都读不到），
同时在代码注释、界面卡片、版本档**三处**写明「明文存储、root 用户注意」。
**技术上做到位**（权限）**和**表达上做到位**（知情）是两件事，都要做。
