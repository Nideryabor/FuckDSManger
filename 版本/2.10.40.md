# FuckDSManger NL 2.10.40（重适配第一步 · 把宿主配置键全列出来）

> 产物：`FuckDSManger_NL_2.10.40_for_ds2.5.2.apk`（**191 / NL 2.10.40**，91 类，V1+V2+V3，sha256(partial) `4973c331…`）
> 命名：本版起产物带 **NL**（NewLine）前缀，与 mcp 文件夹里那条老线（2.10.1-probe / 2.10.33 …）区分开
> 触发：主人「**最新版和旧版文件功能找不到模型配置表，可能是更新宿主后被 R8 混淆，需要重新适配**」

## 一、问题定性

宿主机**更新过** ⇒ R8 重新混淆 ⇒ **两条线**（新版 / 旧版）的「文件快捷选项」都找不到那张模型配置表
⇒ 也就是说：**之前 2.10.1-probe 能显示文字，是因为当时的宿主版本还能找到那张表**；现在通路断了。

## 二、好消息：不需要宿主 APK 就能重适配

我们的代码**就跑在宿主进程里**，而模块里**早已有一个** `GmStore.dumpAll(Context)`：

```smali
    sp = GmStore.get(ctx)                 ← 宿主的 SharedPreferences（其实是 MMKV，它实现了该接口）
    sp.allKeys() / sp.getAll().keySet()   ← 枚举全部键
    → 只保留 "kv_" 开头的（= 宿主的远程配置键）
```

⇒ 把它打出来，就能看到**宿主现在把那张表叫什么名字**（或被搬到哪里去了）✓

## 三、本版改动

把 `dumpAll` 挂进「必响探针」里（进会话第一次命中断点就会打一次，`logOnce`）：

```
[建议] 宿主配置键 → kv_xxx | kv_yyy | …
```
