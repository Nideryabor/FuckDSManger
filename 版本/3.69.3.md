## 二、剩下的真 bug：括号形态

约定里写的是 `⟦DJ:歌名-歌手⟧`（数学白方括号 U+27E6/U+27E7），
**模型敲出来的是 `[DJ:红色高跟鞋-蔡健雅]`**（ASCII 方括号）。

⇒ `scan()` 只认 U+27E6 ⇒ **没匹配上** ⇒ 标记**原样漏进气泡**、
既没换成「♪ 正在给你放…」、也没去搜歌（迷你条一直"未在播放"）。

**次要证据**：同一条气泡里 `▸ 还有别的版本吗` 被渲染成了**可点按钮**
（那是 `<Suggestion>` 家族，`scan` 认得的形态）⇒ **富文本 hook 本身是活的**，
只是 DJ 这一族的字符对不上。

### 修法：与其求模型写对字符，不如接住它会写的几种

```java
public static final String[] DJ_OPENS  = {"\u27E6DJ:", "[DJ:", "\uFF3BDJ:", "\u3010DJ:"};
public static final String[] DJ_CLOSES = {"\u27E7",    "]",    "\uFF3D",    "\u3011"};
```

数学白方括号（约定的）· ASCII `[]` · 全角 `［］` · 中文 `【】`。
`scan()` 里对四种形态**取最靠左**的那个，闭括号**与开括号一一对应**。

★ 只对 DJ 族放宽：其它族（FDM/SUG）跑了很久没出过这问题，
放宽反而可能把普通正文里的 `[注释]` 误吃掉。
★ 逻辑标注也一并改掉（`dop`/`dcl` 取代写死的 `DJ_OPEN`/`DJ_CLOSE`）。

## 三、顺手加的"远程诊断"（这次最疼的教训换来的）


**为什么加它**：这次定位靠的是**主人手工抄了一份提示词**（很费力）。

（`GmSysPrompt` 那边已经在 3.69.2 加了 `dj.section`：约定补入时会报字数。）

## 五、附：截图②那句「（大窝没应声嗷）」

**不是 bug 的证据链**：`host.at` 读出来是"读取前 69 秒"，说明宿主**一直在回话**。

那句提示来自 `SysPromptV2.showComposed()`：

```kotlin
val before = sp.getLong("host.at", 0L)
repeat(12) { delay(300); sendCmd("cfg_state"); delay(300); if (at > before) {…return} }
promptPreview = "（大窝没应声嗷）…"        // ← 约 7.2 秒内没等到**更新**
```

⇒ 7.2 秒的窗口**太短**：宿主当时正在跑对话（思考/流式），回执晚到就判"没应声"。
★ 这是**既有的小毛病**（不是本次改动引入），改善方向：把窗口拉长 + 文案改成
"再点一次/宿主忙"，或干脆用"请求-响应"而不是"比时间戳"。已记入待办。

## 六、教训

**1084 · ⭐⭐⭐ 让模型"写对特殊字符"是靠不住的 —— 匹配端要宽容。**
　　约定里明明写着 `⟦DJ:…⟧`（U+27E6），模型敲出 `[DJ:…]`。
　　⇒ **不要靠提示词约束字符**，要在**解析端接受多种形态**（ASCII / 全角 / 中文括号）。
　　★ 顺带一条设计判据：**标记的"开"和"闭"要一一对应**，别让 `[DJ:…⟧` 这种混搭蒙对。

**1085 · ⭐⭐ 只放宽"出过问题的"那一族。**
　　宽容度是双刃剑：`[注释]` 在普通正文里很常见，把 FDM/SUG 族一起放宽
　　会引入误吃正文的风险。⇒ **哪族出问题放宽哪族**，并在注释里写明为什么。

**1086 · ⭐⭐⭐ 每次"靠人肉取证"定位完问题，就要把取证手段自动化。**
　　这次靠主人**手工抄提示词**才定位 ⇒ 立刻加 `dj.section`（补入时报字数）、
　　`richHook.djhit/djmiss`（认出/没认出各留痕）。
　　★ 判据：**同类问题下次应该"看日志就知道"，而不是"再求人抄一遍"。**

**1087 · ⭐⭐ debug 包能 `run-as` 读私有偏好 —— 这是极好的现场取证手段。**
　　`adb shell run-as <pkg> cat shared_prefs/fdm_ui.xml`
　　⇒ 一眼看到 `host.at`（宿主在不在回话）、`cfg.fuckds_dj_off`（开关到底写没写）。
　　★ 这条应该写进「抓日志.sh」旁边，作为标准手段。
