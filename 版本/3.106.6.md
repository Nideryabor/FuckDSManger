## 二、第 1 条：`GmResTextHook` 真正的两个病灶

### 2.1 病灶 A —— 锚点

底座 `GmEntry.smali:607` 一直这么挂：

```smali
const-string v0, "G"
const-string v1, "com.nidyaber.fuckdsmanger.gm.GmResTextHook"
const-string v4, "k47"
invoke-static {p1, v4, v0, v1}, GmEntry;->hookM(ClassLoader;String;String;String)V
```

`hookM` 会先问 `GmRemap.clsFor("k47","G")` / `GmRemap.method("k47","G")` —— 可**表里根本没有 `k47` 这一行**
（`GmRemap.CLS7` 里没有、`MTH` 里也没有）⇒ 原样返回 `k47` + `G`。
`k47` 在 2.8.0 **还在**（同名诈尸），但它的方法只剩 `<init>` / `equals` / `hashCode` / `toString`（4 个，全是 record 类那套）
⇒ `hookAllMethods(k47,"G")` 命中 0 ⇒ **静默失败**。

真身定位（两棵树对照，同一句 source-info 串 `StringResources.android.kt:33`）：

| 宿主 | 类 | 方法 | 签名 |
|---|---|---|---|
| 2.7.2 | `l47` | `u` | `(I,Lr15;)Ljava/lang/String;` |
| 2.7.5 | `k47` | `G` | `(I,Lv15;)Ljava/lang/String;` |
| **2.8.0** | **`i77`** | **`C`** | `(I,Lh25;)Ljava/lang/String;` |

⚠️ 2.8.0 的 `i77` 里还**有**一个 `G`，但返回 `Lhfa;`（StringResource 包装类，不是 String）⇒
**按方法名 `G` 硬撞会挂到完全不同的方法上**（这正是教训 F「能派生就不要写死」的反面教材）。

⇒ 处置：`GmRemap` 加两行（键沿用 `k47` / `k47.G`，底座那行不用改）：

```java

{"k47.G", "k47.G", "k47.G", "l47", "u", "k47", "G", "i77", "C"}, // MTH
```

### 9.1 装机时踩到的一个**工具坑**（值得记）

`tools/install_fdm.sh` 的第③步（修 LSPosed 路径）和第⑤步（读模块日志）都走 `su`，
而这台设备 `adb shell` 里 **`su: inaccessible or not found`**（没有 root shell）⇒
第③步 `sqlite3.DatabaseError: file is not a database`（`su 0 cat` 返回空）、
第⑤步 `模块日志行数: 0 ❌ 没加载` —— **全是假阴性**。

⇒ 正确做法：**用 `devlog` 网关**（它在设备侧是 uid=0 起的，`ping` 里就写着 `root=True`），
`sh tools/logs/devlog.sh sync <标签>` 一次性把 `lspd` + `app` 两类日志拉回小窝；
要截图就用 `sh tools/出笼隧道/adb.sh exec-out screencap -p`。
（教训：**「检查脚本报 0」不等于「功能挂了」**，先确认那条检查自己有没有权限。）
