## 二、★ 三大技术真相（本轮最值钱的三条）

### ① R8 是「**部分重排**」——名字在 ≠ 还是那个类

拿 2.6.1 的 **42 个已定位类名**去 2.6.2 批量搜 ⇒ **42/42 全部命中**。
第一眼像"全绿"，实测**一批已换主**：

| 2.6.1 名 | 2.6.1 里是什么 | 2.6.2 里同名的是什么 |
|---|---|---|
| `fu2` | 灰度总表字典（65 项） | 5 行的小类 |
| `yib` | 录音语音字典 | ViewModelProvider 工厂 |
| `wza` | TTS 字典 | 枚举（`NotStarted`） |
| `zx8` | 字节 APM root 检测 | 别的类 |
| `x97` | **Modifier 接口** | `ModelConfig.CallFeature` 的 serializer |
| **`hs7`** | **建议 Prompt 视图** | **某个小类（只有 `<init>` + `m`）** ← 本轮真凶 |

> ⚠️ `yb5→hs7` 这条就是**靠名字放行**的后果：`hookAllMethods(hs7,"e")` 命中 **0 个方法** ⇒
> **文件上传建议 + AI 建议一起静默失效**（主人报的两个症状是同一个根因）。

### ② 底座里「新旧两代名字混杂」，且**寄存器共享**

```smali
; GmEntry.handleLoadPackage（改前）
const-string v7, "ao1"
invoke-static {p1, v7, v1, v6}, hookM(...)   ; ← v7 走 GmRemap（要 2.5.2 名）
invoke-static {v7, p1}, findClass            ; ← 同一个 v7！（要 2.6.2 名）
...
invoke-static {p1, v7, p0, v1}, hookM(...)   ; ← v7 在 1063 又被用一次
```

⇒ **改字面量必然「连累」另一条路径**（改了 `findClass` 就对，改完 `hookM` 就错）。
**解法**：字面量一律不动，统一过 `GmRemap`；本表**同时收两代键**。

### ③ `GmRemap` 这类「集中表」是对的方向（本轮把它补齐了）

2.6.1 轮**只做了一半**（只有 `GmEntry` 走它，其余 12 个文件仍是硬编码字面量）。
本轮：**底座 33 处 + 桥侧 9 个文件全部接表** ⇒ 以后宿主升级**只改一个文件**。

## 三、加密栈破解（抓包分析副产品）

抓包里**两套加密栈**，都摸清了：

| # | 栈 | 用在哪 | 算法 | 密钥 | 状态 |
|---|---|---|---|---|---|
| **A** | **`tt-data`** | AppLog / cloudcontrol 响应 | **AES/ECB/NoPadding** | **响应头 `ran`** | ✅ **已破解 + 已实测解密** |
| **B** | **`ttEncrypt`** | AB 测试配置（`tab.volces.com`） | native（`libEncryptorP.so`） | so 内部 | ⚠️ API 已定位（`EncryptorUtil.a`）|

**A 栈实测**（用小窝的 Java 工具链，就是模块自己那套 JCE）：

```
ran   = yuNttCSojTyxZods          ← 16 字节 = AES-128（从原始 HAR 取真值）
data  = base64 → 224 字节（224 % 16 = 0 ✓）
算法  = AES/ECB/NoPadding + key.getBytes()
```

**明文**（火山云控配置原文）：
```json
{"error_code":0,"magic_tag":"ss_app_log","message":"success","server_time":"1792140046",
 "is_crash":0,"stop_interval":3600,
 "configs":{"debug_settings":{"should_submit_debugreal":0},"file_settings":{"should_upload_file":0}}}
```

**B 栈**：`libEncryptorP.so` = ByteDance 加密库（`ttEncrypt`，`RegisterNatives` 动态注册）；
`librscrypto.so` = **Rust 写的** SHA3 栈（DeepSeek 自家签名）。
dex 侧 `com.bytedance.applog.encryptor.EncryptorUtil`（**未混淆**）：
```java

public static byte[] a(int i, byte[] b) { ... ttEncrypt(b, i); }
// IEncryptorType.DEFAULT_ENCRYPTOR = "a"   ← 对应请求头 tt-data=a
```

## 五、★ 系统提示词的「bug」真相：**开关没开**（不是代码 bug）

主人最后一条：「**操，我是傻逼，这个确实没开**」。

**查案过程**（值得留档，因为手法可复用）：

1. 今天所有日志里**没有** `hook 活了` / `sysprompt.inject` —— 但**钩子是装上的**
   （`hookM sysprompt count=1 cls=tv1`）⇒ 排除"没挂上"。
2. 翻历史日志发现 **10-04（宿主 2.6.1 时代）它工作过**：
   `hook 活了 on=true mode=0 textLen=7` + `sp=7 first=true mode=0` ⇒ 逻辑本身是对的。
3. 比对今天两次 UI 配置推送（18:39 / 18:53）：
   ```
   "fuckds_sysprompt_on": 0     ← 开关=关！
   ```
   而 10-04 那次是 `1` ⇒ **根因锁定**。
4. 源码印证：`inject()` 第一行 `if (!on()) return` ⇒ 关着就**一行都不执行、连日志都不打**。
5. 开关位置：`聊天 › 系统提示词 › 右上角 ⋮ 更多 › 开启注入`（副标题写明「**默认关**」）。

**⇒ 零代码改动**。顺带留两条待办（下版做）：
- 宿主回读清单（`OUR_KEYS`）里**没有** `sysprompt_on` ⇒ 界面那个开关显示的是本地值，不是宿主真值。
- 这类「关着就全静默」的入口，值得在**打开设置页时**补一行 `logOnce`（省得下次再查一遍）。

## 八、教训 1106 ~ 1114

| # | 教训 |
|---|---|
| **1106** | ⭐⭐⭐ **「名字还在」不等于「还是那个类」** —— R8 只改名字不改形状，但**名字会被复用**（`hs7` 从建议视图变成小类）。★ 附：**挂错方法名是静默的**（`hookAllMethods` 找不到方法只返回 `0`，不抛异常）⇒ 必须看 `count=N` 的 **N**，不能只看"挂上了" |
| **1107** | ⭐⭐⭐ **改字面量前必须做「寄存器活跃分析」** —— `handleLoadPackage` 里 `v7` 同时喂 `hookM` 和 `findClass`，改一处必坏另一处 |
| **1108** | ⭐⭐⭐ **「锚点表」必须支持多代键** —— 底座里新旧混杂（`GmEntry` 用 2.5.2 名、其余文件被文本替换成 2.6.1 名），单代键的表一定会漏 |
| **1109** | ⭐⭐ **「集中表」是对的方向** —— 2.6.1 轮只做了一半（只有 `GmEntry` 走它），本轮补齐 |
| **1110** | ⭐⭐ **类型/字段「形似」比「数量对」更重要** —— `se0` 那条曾因「都是 3 字段」被误判；后来靠**构造器参数形态**（`(X,X,ArrayList)`）才认对。同形的 lambda 桶要靠**方法体指纹**（cast 数 + cast 类型集）分开 |
| **1111** | ⭐⭐⭐ **「功能没效果」先问「开关开着吗」** —— 系统提示词查了一整轮，真因是设置里的「开启注入」**默认关**。**先验证入口状态，再拆代码** |
| **1112** | ⭐⭐ **「日志读不到」≠「事情没发生」** —— ColorOS 对宿主进程日志有**配额丢弃**（`LOGS OVER PROC QUOTA… DROPPED`）⇒ 该打点的地方要打**自己的 DIAG 文件**，不能只依赖 logcat |
| **1113** | ⭐⭐⭐ **抓包的潜力比想象大** —— `ran` 头 + AES/ECB/NoPadding 就足以**离线解密**整条 AppLog 通道。**先读实现再断定"解不开"** |
| **1114** | ⭐⭐ **调试通道值得投资** —— `adb am broadcast` 能给真机上的模块发命令、`dumpsys activity broadcasts` 能读回执；本轮靠它**不用主人配合**就摸清了现场 |
