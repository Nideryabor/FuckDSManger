# 3.28.4（vc542）· 底座沿用 2.22.132 —— 招呼语写不进去 / 账号名读出来空白

## 一、招呼语（以及所有文本框）**一个字都写不进去**

UI 把**文本**项当**整数**发：

```kotlin
FdmPush.sendCmd(ctx, "cfg_put", it.key!! + "\u001f" + "i" + "\u001f" + v)   ✗ "i"=整数
```
桥里 `GmStore.write(ctx,key,val,"i")` ⇒ `Integer.parseInt("你好")` ⇒ **NumberFormatException** ⇒ 什么都没写 ✗

**两处修**：
1. UI：文本项类型 `"i"` → **`"s"`**；
2. 桥：新增 `dispatchText()`，让文本键走**模块自己的入口**（老 UI 的存法）——
   因为它们的存储值不是裸文本：
   | 键 | 存储形态 | 入口 |
   |---|---|---|
   | `fuckds_welcome_msg` | `{"messages":[{id,text}…]}` | `GmHello.build(List<String[]>)` → `put` → `apply` |
   | `fuckds_prompt_feature` | `[{id,scene,content}…]` | `GmPrompt.build(List<String[]>)` → `put` → `apply` |
   | `fuckds_suggest_text` | 裸文本（每行一条） | `GmSuggest.setText(ctx,text)` |
   （`GmHello.apply` 内部是 `GmStore.write(..., "s")` —— 反证 UI 的 `"i"` 就是错的。）

## 二、账号名「读出来空白」——真值一直在，是**界面把它冲没的**

真机取证：
```
/data/data/com.deepseek.chat.a/shared_prefs/fuckds_gm.xml
    <string name="accname_text">原神</string>        ← 写进去了 ✓
日志 state_all：{"fuckds_nick":"原神","ui_nick":"原神", …}   ← 读得到 ✓
UI 侧 cmd.cfg_state：{"name":"原神", …}                     ← 界面也收到了 ✓
UI 侧 fdm_ui.xml：  cfg.ui_nick = （空串）· cfg.fuckds_nick = 原神
```
`SettingText` 里这条逻辑无条件采纳回执：
```kotlin
LaunchedEffect(key, cfgAt) { if (!touched && !focused && cfgAt > 0L) tv = sp.getString("cfg.$key","") }
```
而桥回执里 `cfg.ui_nick` 是**空串** ⇒ 每 1.2 秒轮询一次就把已经显示好的"原神"清成空白 ✗✗

**修**：空值不再覆盖（`if (v.isNotEmpty()) tv = v`）。

## 三、顺手补「读」——原来这三项在界面上永远是空框

`cfg_state` 回读里**没有**招呼语/回复建议/提示词 ⇒ 界面无从显示。
新增 `helloLines()` / `promptLines()`（把 JSON 摊成"每行一条"），cfg_state 补三项；
UI 侧给三个文本框接上 `sk`（`welcome` / `suggest_text` / `prompt`）⇒ 进去就能看到当前值。

## 六、教训

| # | 要点 |
|---|---|
| 1 | ⭐⭐⭐ **"类型码"也是协议** —— `cfg_put` 的 `i/s/b` 是三层（UI/桥/底座）共用的约定，UI 侧一个 `"i"` 就让**整类文本框**失效。**跨进程协议字段要枚举化并集中定义**（不能各处手拼字符串）。 |
| 2 | ⭐⭐⭐ **"读到的空值"要区分"真空"与"没这条"** —— 回执里 `cfg.<key>` 是空串不代表用户把它清空了。**UI 采纳回执前先判 empty**（这次一条 `isNotEmpty()` 就解决了"名字显示不出来"）。 |
| 3 | ⭐⭐ **"写不进去"要一路查到存储层** —— 这次真值其实早就写进去了（`accname_text=原神`），症状是**显示**被冲掉。**先看"存了没"，再怀疑"写没写"。** |
