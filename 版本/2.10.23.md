> 产物：`FuckDSManger_2.10.23_for_ds2.5.2.apk`（**174 / 2.10.23**，90 类，V1+V2+V3，sha256(partial) `37d54fc4…`）

## 一、为什么「宿主列表一直为空」

结合已知事实推理：

| 事实 | 推论 |
|---|---|
| 宿主 `yb5.e/f` 一直在被调用 | 那排**确实在渲染** |
| 传进来的 List **恒为空**（最优从未亮） | 宿主**当前场景没有模板条目** |
| 你的配置里只有 `image` / `file` 两套场景 | **输入框一有字 ⇒ 场景切到 `text` ⇒ 该场景没有配置 ⇒ 列表天然为空** ★ |

⇒ 也就是说：**想要的那一幕（打字时给建议）恰好就是宿主"没有模板"的场景**，
而我们此前遇到空列表就退出 ⇒ 永远没机会。

## 二、本版改动：空列表时**自建列表**

```smali
    if-lt <宿主size>, 1, :sz_ok        ← 有货 → 原逻辑（改造宿主对象）
    # ↓ 新增兜底：空列表时，用我们自己的模板造对象返回
    GmSuggest.count(ctx) → n
    GmSuggestHook.make(n) → List       ← 2.10.2 就写好的「自建 g56 对象」机器
    if 成功 → noteOk("自建列表成功…") + 返回它
    if 失败 → note("退出:宿主列表空且自建失败")（`make()` 会打印宿主构造器签名，供我修）
```

> `make()` / `tryCtor()` / `dumpCtors()` 是 2.10.2 写好的（会遍历宿主构造器、**造完读回字段自验证**、
> 失败时 dump 构造器签名）——当年因为别的 bug 从没真正跑到过，这次终于用上了。
