## 三、根因：**smali 里 varargs 不能展开传**

```smali
; ✗ 错误写法（Java 思维）
invoke-static {v3, v5, v4}, XposedHelpers;->callMethod(Ljava/lang/Object;Ljava/lang/String;[Ljava/lang/Object;)Ljava/lang/Object;
;                        ↑ 这是 Boolean，但签名要的是 Object[]

; ✓ 正确写法：自己 new-array
const/4 v4, 0x1
new-array v4, v4, [Ljava/lang/Object;
const/4 v5, 0x0
sget-object v6, Ljava/lang/Boolean;->TRUE:Ljava/lang/Boolean;
aput-object v6, v4, v5
invoke-static {v3, v5, v4}, XposedHelpers;->callMethod(...)
```

⇒ 同时也解开了 **2.10.21 `hookM FAIL yb5.e` 之谜**（`GmPromptHook` 里是同一个错），
当时我只看到 FAIL 就去猜「二次注册限制」，绕了一大圈 😅

### 3.1 ⚠️ 为什么后果这么严重

**一个方法 VerifyError ⇒ 整个类被 verifier 拒绝 ⇒ 该类上注册的所有 hook 全部失效。**

`GmSuggestHook` 上挂着 **30 个** hook（`ao1.*` / `hx2.*` / `h91.a` / `b51.a` / `yb5.*` …），
它们**连同自动发送探针一起全灭** ⇒ 表现就是「什么都没有了」。

## 四、本版修复

| 动作 | 说明 |
|---|---|
| `GmSuggestHook.prompt()` | 两处 `callMethod` 改为 `new-array` + `aput-object` 后传数组 |
| `GmPromptHook`（未注册的旧类） | 同样修掉，避免以后复制粘贴踩坑 |
| **全局排查** | 搜索模块内所有 `XposedHelpers;->` 调用，确认其它 `callMethod`/`newInstance` 都正确传了数组（`GmSendRun` ✅；`GmHello`/`GmRevokeHook`/`GmStore` 为旧代码 ✅） |

## 七、教训

| # | 教训 |
|---|---|
| 128 | ⭐⭐⭐ **smali 里 varargs（`Object...`）必须显式 `new-array` + `aput-object`**，不能像 Java 那样展开写 —— 这是低级字节码，编译器不会帮你打包 |
| 129 | ⭐⭐⭐ **一个方法 VerifyError 会让整个类被拒** ⇒ **该类上的所有 hook 全部失效**。所以「只加了一个小方法」也可能让**整个模块功能归零** |
| 130 | ⭐ **`hookM FAIL` 一定要看后面跟的异常堆栈** —— 2.10.21 那轮我只看到 FAIL 就去猜「二次注册限制」，绕了一大圈；这轮主人给了完整堆栈，一眼定位 |
