## 1. 漏掉的那一层

```
Window
 └─ DecorView (FrameLayout)
     └─ LinearLayout                        ← 2.22.46 的 clearBg 清了它的背景 ✓
         ├─ 状态栏背景
         └─ FrameLayout(android.R.id.content)   ← ★ 没清！它是 Compose 的宿主
                └─ ComposeView
```

2.22.46 的 `clearBg` 只遍历了 **`DecorView` 的直接子**（= `LinearLayout`）就停了，
**没往下走**到 `android.R.id.content` —— 而 `content` 的背景来自 theme 的 **`windowBackground`**，是**实心**的
⇒ 图在 index 0，**照样被 `content` 盖住**。

---

## 2. 本版改动

### ① `clearBg` 改成**递归清整棵子树**

```smali
.method private static clearBg(Landroid/app/Activity;)V
    # Window.setBackgroundDrawable(null)
    # decorView = Window.getDecorView() as ViewGroup
    # clearBgGroup(decorView)          ← ★ 递归入口

.method private static clearBgGroup(Landroid/view/ViewGroup;)V
    :loop
      子 i → setBackground(null)
      若是 ViewGroup ⇒ clearBgGroup(它)      ← ★ 递归
    :end
```

⇒ **`DecorView → LinearLayout → content → …` 整条链上的背景全部清空**（整体 `try/catch` 静默）。
（Compose 内部是自绘，没有 View 子节点，递归自然终止。）

### ② 加**挂载探针**

```smali
    const-string v1, "[背景] ensure 走到挂载后：开始清 View 层背景"
    invoke-static {v1}, GmUtil->log(String;)V
```

**⇒ 这条日志出现 = `ensure()` 确实执行到了「插入图之后」**；**不出现 = 图压根没插进去**（问题在别处）。

## 5. 教训（823）

| # | 内容 |
|---|---|
| **823** | ⭐⭐⭐ **「清一层」和「清整条链」是两回事**：`DecorView` 的直接子清掉了，但**子下面的 `content` 还盖着**；而"图在 index 0"意味着**从下往上每一层都必须可透**。⇒ **凡是「让最底层可见」的改动，收尾时一定要问：从 `Window` 到目标层之间，**每一层**都处理了吗？** 数层数比试效果快得多。 |
