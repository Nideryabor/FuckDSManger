## 三、🎯 真相（反编译宿主才看到的）

宿主跑过 **R8**，MMKV 被压成这样：

```smali
.field  private final nativeHandle:J
.method private native allKeys(JZ)[Ljava/lang/String;
```

**三个巧合叠在一起，才让这件事如此难查：**

1. **`allKeys` 是 `native` 方法 ⇒ 名字改不掉**（JNI 按名字绑定），所以它还叫 `allKeys`
2. **但它被 R8 从 `public` 压成了 `private`**
   ⇒ `getMethod("allKeys")` 找不到、`getMethods()`（只要 public）也不列它
3. **MMKV 原本那个 `public String[] allKeys()`（无参包装）被整段删掉了**
   —— 因为全类**没有任何调用点**，只剩 `getAll()` 里那句**字符串常量**提到它
   ⇒ 那句 `Use allKeys() instead` 是**指向一个已经不存在的方法的死提示**

> **教训**：报错信息也是"别人写的代码"，它可能已经过期。
> 光读日志读到 3.21.0 就打住了 —— **得把对方的包拉下来看。**

## 四、修法

`FdmBridge.allKeysOf()` 的第 ①' 条路：

```java
Field hf = findNativeHandle(sp.getClass());            // private final long nativeHandle
long handle = hf.getLong(sp);
Method am = sp.getClass().getDeclaredMethod("allKeys", long.class, boolean.class);
am.setAccessible(true);                                 // ← 关键：把 private 挖出来
String[] keys = (String[]) am.invoke(sp, handle, true); // true = 过滤过期键
```

`findNativeHandle()` 做了两层保险：
1. 先按名字 `nativeHandle`（实测没被混淆）
2. 找不到就找「唯一的 long 实例字段」；**有多个 long 就不猜**（返回 null）

原来那几条路（名字 → 无参签名 → `getAll()`）全部保留做兜底。
