## 2.9.8 为什么完全没效果（两个独立真因）

### 🐛 真因 ①：账号名 —— `findClass` 写成了 dex 名，hook 从来没挂上

`GmNameHook` 注册时写的是 `"Ls5"`，但 Xposed `XposedHelpers.findClass(name, cl)` 要的是 **Java 名**。
宿主那个类在 dex 里叫 `Ls5;` ⇒ **Java 名是 `s5`**。于是 `findClass("Ls5")` 直接抛异常，
被 `hookM` 自己的 try/catch 吞掉，只留一行 `hookM FAIL Ls5.v`。

> 项目里所有 app 类 hook 用的都是 Java 名（`h91` / `p66` / `m5` / `h02` / `bx4` / `kf5`），
> 我把 `L…;` 直接当成类名用了 —— 见教训第 58 条。

### 🐛 真因 ②：账号头像 —— `painterResource` 对 vector XML 根本不走 `Resources.getDrawable`

头像那一行是 `painterResource(0x7f07010f)`（`Lkf5;->K`），而 Compose 的 `painterResource`：

```
value = resources.getValue(id)
if (value.string endsWith ".xml")  -> loadVectorResource: resources.getXml(id) + 解析 XML
else                               -> BitmapFactory / getDrawable 那条路
```

`ic_profile`（`res/BI.xml`）是**矢量 XML** ⇒ 走 `getXml` **解析**，
`Resources.getDrawable` 一次都不会被调用 ⇒ 2.9.8 那个 hook 是死代码。

**改用 Coil 这条路**（这才是头像真正的加载器）：

```
UserInfoFooter
 ├── v14 = remember { Lp5(State<Lit9>, 0xf) }   ← 取头像 URL（Lit9->e）
 ├── Ljt5;->N(url, …) = coil3.compose.rememberAsyncImagePainter
 └── 有图 → 画 Coil 的 painter；没图 → painterResource(ic_profile) 兜底
```

所以 hook **`p5;->v()`**（`a == 0xf` 分支）→ 返回 `file://<私有目录>/fuckds_uavatar.png?v=<mtime>`
⇒ Coil 直接加载我们选的图，**而且这条路没有 Icon tint**，不会退化成纯色块。

- 挂载文件在**宿主**私有目录（模块跑在宿主进程里，`GmEntry.sAct` 就是宿主 Activity）⇒ 宿主自己读得到
- `?v=<lastModified>` 用来破 Coil 的缓存（不然后换图会一直显示旧的）

## 教训（补充第十一节）

**第 58 条：Xposed 注册 hook 用「Java 类名」，不是 dex 描述符。**
`Lh91;` → `"h91"`；`Ls5;` → `"s5"`。写成 `"Ls5"` 不会报错——它只是被 `hookM` 的 try/catch 吞掉，
表现为**功能静默完全无效**。**注册完必须看一行 `hookM … count=N` 的日志**（`count=0` 或 `hookM FAIL` 就是没挂上）。

**第 59 条：Compose `painterResource` 对「矢量 XML」不调 `Resources.getDrawable`。**
它走 `getXml` + 解析成 `ImageVector`。所以「hook `Resources.getDrawable` 换图」这条老路
**只对 PNG/非-XML 资源有效**；`res/*.xml` 矢量资源必须换别的下手点。
→ 判断方法：`painterResource` 反编译里看 `TypedValue.string` 是否 `endsWith(".xml")`。

**第 60 条：换不掉资源，就去换「资源的前一步」。**
本项目里头像真正的加载器是 **Coil3**（`coil3.compose.rememberAsyncImagePainter`），
它吃的是 URL 字符串 ⇒ 只要 hook 那个**算 URL 的 lambda**，返回 `file://` 就能让它加载本地图，
而且绕开了 Icon 的 tint（顺带解释了「蓝色方块」为什么总出现在资源替换那条路上）。
