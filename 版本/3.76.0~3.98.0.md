## 二、3.76：本地音乐（主人 11-01 提的需求）

### 四条定案

| 项 | 定案 |
|---|---|
| 曲库 | **用户用系统选择器挑一个文件夹**（不是写死路径） |
| 进歌 | App 内 SAF 导入 → 拷进那个目录 |
| 提示词 | 变量 `{local_music}` + 「自动追加」开关；每首「序号. 歌名 - 歌手」 |
| 点歌 | `⟦DJ:⟧`=在线 · `⟦LOCAL:序号⟧`=本地，**两条路彻底分开** |

### ⭐ 权限：三层取证，只有一层是通的

| 方案 | 真机结果 | 结论 |
|---|---|---|
| 宿主按绝对路径读 `/sdcard/...` | `FileNotFoundException: EACCES` | 宿主清单**没有 `READ_MEDIA_AUDIO`**，系统连权限项都不给它显示 ⇒ 机制上不可能 |
| 我们的 provider 借 fd | `resolveContentProvider=null` / `No content provider` | **Android 11+ 包可见性**（跟 3.75.x「Compose UI 打不开」同一个坑） |
| **宿主自己 SAF 授权文件夹** | ✅ 通 | `ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission`（**读+写都要**） |

**关键推论**（这条决定了整个架构）：
> SAF 授权记在**宿主 uid** 上，我们 UI 进程用不了。
> ⇒ 扫描 / 导入 / 生成提示词文本**全部在宿主做**；
> UI 只负责「请它扫（`local_list`）→ 显示 → 勾选发给它（`local_sel`）」。

### 踩过的两个 SAF 坑

| 坑 | 症状 | 修法 |
|---|---|---|
| `getDocumentId(treeUri)` | `IllegalArgumentException: Invalid URI` —— **tree uri 上没有 document id** | 第一层用 `getTreeDocumentId()`；递归层把子目录自己的 `docId` 传下去 |
| 用 `logFail` 吞异常 | 扫目录失败只进 DIAG 缓冲，常规日志**一片空白**，界面永远 0 首 | 失败必须走 `GmUtil.log`（常规通道） |

## 三、3.80：误触发（复制/重新生成/删除对话 → 跳模块页 + 吐司）

### 真凶在**底座 dex**，不在桥

```smali
GmEntry line 69:
  hookM(cl, "m5", "v", "com.nidyaber.fuckdsmanger.gm.GmEntryHook")

GmEntryHook.beforeHookedMethod:
  if (getIntField(obj,"a") == 0x14)   ← 判据
      toast("FDS: check-update row hit")
      GmHomeUi.open()
```

`0x14` 是 **2.2.x 时代**给宿主 2.6.x 写的；到 2.7.5，`m5 → lp9`，而 `lp9.j` 的 **case 0x14 变成了 `list.add(...)`**：

```smali
:pswitch_1c1
    iget-object v1, v0, Lr4b;->j:Lzaa;
    invoke-virtual {v1, v11}, Lzaa;->add(Ljava/lang/Object;)Z   ← 就是 list.add
```

⇒ 复制 / 重新生成 / 删除对话（任何走 `add` 的）全部命中 ⇒ 吐司 + 拉起模块 UI。

### frida 抓到的两条调用链（`e` 值完全相同，所以 `e` 不能当判据）

```
pg7.x e=23 f=0 ← k23.d0 ← s0.x0 ← yu7.E/F ← jv.a:262   【长按菜单】
pg7.z e=22 f=0 ← sj0.h  ← wy3.run ← Handler             【协程/检查更新】
```

### 修法

1. **彻底停用我们的点击接管**（`FdmUpdateRowHook.install` 注释掉）——它会误伤四个功能
2. `FdmUiHook` 挂在 `GmHomeUi.open` 上，先判断「栈里有没有 `GmEntryHook`」→ 有就**吞掉，什么都不弹**
3. 过滤掉那句 `check-update row hit` 吐司

> ⚠️ 结构性教训：**Xposed 的 `t.intercept / m.proceed` 会挡掉中间栈**，
> 实测栈顶只剩 `JairlkMouthRoolt.h <- hc3.L`，靠调用栈区分入口这条路在 Xposed 里**走不通**。

## 四、⭐⭐⭐ 3.87~3.98：追了 20 版才找到的真因 —— `DEDUP_MS`

### 主人的描述（逐步收敛）

| 轮次 | 主人原话 | 我当时的错误理解 |
|---|---|---|
| 1 | 「切回本地海阔天空再切回红色高跟鞋又不能放了」 | 以为播放器起了但没声音 |
| 2 | 「蓝牙没开，没有线，就是代码问题」 | 排除了外部原因 |
| 3 | 「留后台再切回来，能切到海阔天空了」 | 以为音频焦点 |
| 4 | **「播放器也显示的是红色高跟鞋」** | ⭐ **这句是决定性的** |

### 第 4 句为什么决定一切

「播放器显示红色高跟鞋」⇒ **第三次切歌时 `playLocal` 根本没被调用**（卡片都没更新）。
不是"放了没声音"，是**压根没放**。

### 真因

```java
// GmMusicDj
private static final long DEDUP_MS = 15000L;   // ← 15 秒去重窗口

final String dedupKey = "L|" + it.n + "|" + it.path;
if (recentlyHandled(dedupKey)) {
    return "♪ 正在给你放（本地）：" + it.label();   // ← 只回一句话，一行播放都没跑
}
```

```
第1次 放海阔天空   → 记 L|1|<path>，T0
第2次 切红色高跟鞋  → 记 L|2|（+2s）
第3次 切回海阔天空  → 距 T0 只 4s，仍在 15s 窗口内
                   → 直接 return
```

### 所有症状一次解释完

| 症状 | 原因 |
|---|---|
| 第三次没声音 | 没起播 |
| 卡片还显示红色高跟鞋 | `state()` 没变过 |
| **切后台回来又能放** | 切后台 > 15 秒，去重过期 |
| **有时灵有时不灵** | 取决于切歌间隔是否超 15 秒 |

### 修法

去重只该挡「同一条消息流式渲染重复触发」，**不能挡真正的切歌**：

```java
if (recentlyHandled(dedupKey)) {
    // 只有"确实正在放这首"才跳过；否则这是用户真心想切 ⇒ 必须执行
    if (GmMusicPlayer.isPlayingLocalUri(it.source())) {
        return "♪ 正在给你放（本地）：...";
    }
    // 否则继续往下走，真的去播
}
```

在线点歌（`DJ`）同款问题，一并修了。

## 五、这一路上被误导的四次「假线索」

**必须记下来，因为这四次每一次都花了好几个版本。**

| # | 假线索 | 为什么被误导 | 真相 |
|---|---|---|---|
| 1 | 音频焦点（`requestAudioFocus` 没请求） | 症状确实像（切后台就好） | 焦点代码加了，**问题没变** |
| 2 | `MediaPlayer` 实例泄漏 | frida 显示无新实例，推理"旧实例占着" | 无新实例是因为**压根没走那段代码** |
| 3 | 播放代次（`playGen`）重入 | 模块日志说"起播成功"、frida 说"没调用" ⇒ 以为旧回调冒充 | 两个日志都对，只是**它们讲的是不同的事** |
| 4 | `onPrepared` 实例校验 | 同上 | 同上 |

### 第 3、4 条尤其值得记

**「模块日志说有播放」和「frida 说没调用 MediaPlayer」可以同时为真** ——
因为那句话（`♪ 正在给你放…`）是 `GmMusicDj.handleLocal` 的**返回值**，
它先于播放、且**去重命中时也会返回**。我把它当成了"已经起播的证据"。

## 六、教训（接 296，本轮 297~302）

| # | 教训 |
|---|---|
| **297** | ⭐⭐⭐ **「没声音」先分清「放了没声」还是「根本没放」。** 判据不是日志，是**播放器 UI 显示什么** —— 我这轮问到第 4 次才问到句关键的话。 |
| **298** | ⭐⭐⭐ **两条日志矛盾时，矛盾本身就是答案。** frida 说没调用、模块说调用了 ⇒ 不是谁错了，是**中间有一条我看不见的分支**（去重 return）。别急着认定"日志不可信"。 |
| **299** | ⭐⭐⭐ **`if (x == null) return;` 这类静默 return 必须留一行日志。** `startCurrent()` 的 `if (t == null) return;` 让我查了 6 个版本。 |
| **300** | ⭐⭐ **去重/缓存这类"优化"是最容易变成 bug 的地方**，尤其它用**时间窗口**而不是精确状态。任何"跳过执行"的分支，都必须验证"跳过"的前提是否真的成立。 |
| **301** | ⭐⭐ **返回值 ≠ 副作用。** `handleLocal()` 返回「♪ 正在给你放」不代表播放器动了。判断"有没有执行"只能看**被调用的那一层**（frida hook 构造函数是最硬的证据）。 |
| **302** | ⭐⭐ **先问「哪个观察能一击定案」，再去查。** 这轮最有效的一步是「hook `MediaPlayer` 构造函数」——它一次就分清了"没创建"和"创建了没回调"。前面十几版我都在猜。 |
