## 一、日志第一行就把线索交出来了

```
1789801505644 [AI] hook wr args: | null | null … (×11)
```

**读法**：`param.method.getName()` 对**构造器**返回的是**类名** ⇒ 这行就是 `wr` 的**构造器**被调用（11 个参数，全 null）。

**⇒ 价值**：它证明 `hookAllConstructors(wr)` 挂上了；同时也说明——**`beforeHookedMethod` 会被多个 hook 点共用**，日志里出现"不是预期方法名"的行完全正常。

## 二、真凶：`afterHookedMethod` 里的 `wr.x()` 分支**没有上锁**

2.10.88 我只在 `beforeHookedMethod`（`h91.a` 扫描路径）加了 `sFromZ` 优先级判断，**漏了 `afterHookedMethod` 里那一条**：

```smali
:aft x 分支
    if-eqz v0, :aft_done            # result == null → 退
    sput-object v0, …->sList        # ← 这里没检查 sFromZ ⇒ 覆盖 z 的成果
```

**⇒ 于是又一次**：`wr.z` 拿到 `ArrayList(9)` → 随后 `wr.x()` 返回 `hp8(2)` → 把 9 条顶掉 → 点按钮时用的是那 2 条。

### 修正

```smali
    if-eqz v0, :aft_done

    sget v3, …->sFromZ
    if-nez v3, :aft_done            # ★ z 已供数 ⇒ 直接退，不覆盖
```

**⇒ 至此两条入口（`before` 的扫描 / `after` 的 x 返回值）都上了锁**，`wr.z` 的数据不会再被顶掉。
