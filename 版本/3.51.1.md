## 二、⚠️ 顺手修掉一个「看不见」的真 bug

`Pages.kt` 的 `ItemRow`：

```kotlin
K.INFO -> SettingInfo(it.label, "")      // ← hint 被丢掉了
```

`SettingInfo(label, value, hint)` 第二个参数是 `value`，渲染成那个可选中的正文；
而**所有 `K.INFO` 行的说明都写在 `hint` 里** ⇒ **一个字都没显示过**。

> 典型受害者：「系统提示词」页那两条长篇原理说明（隐形字符 / 不是真 system prompt）——
> 界面上一直只有标题，正文是空的。主人大概以为是设计如此。

修法（**严格只增不减**）：

```kotlin
K.INFO -> SettingInfo(it.label, it.hint ?: "")
```

*hint 为 null 的行 ⇒ value 仍是 `""` ⇒ 渲染与改动前完全一致*；
有 hint 的行 ⇒ 那段文字**终于显示出来**了。

## 三、⚠️ 一个必须掐掉的隐患（②的连带）

3.51.0 里，`FdmBridge.applyPushed()` 末尾有一段：

```java
// 整包推送 → 也写一次便签文字
if (strs.has(GmNote.K_TEXT)) GmNote.setTextFromCfg(ctx, strs.optString(K_TEXT));
```

它当时是对的（设置页有那个框）。**但框一拿掉，它就变成毒**：

* UI 的 `FdmPush.push()` 是**全量推**的 —— 只要 UI 的 SP 里还留着
  `cfg.fuckds_note_text`（主人在那个框里打过的字），**每次 UI 启动都会跟着推过来**
* 而这里再 `setTextFromCfg` ⇒ **用一句老文字反复覆盖便签当前内容**
  （现象会是：便签写着写着，切一下就变回几十年前那句话）

⇒ 这段**删掉**。便签文字从此只由 ①便签自己 ②adb 的 `cfg_put … note_text` 改。
（`dispatchText` 里那条分支**留着**，是我调试便签文字用的后门。）

## 六、教训

**950 · ⭐⭐⭐ 拿掉一个输入口，要连带掐掉「它留下的推送」。**
「删掉一个设置项」不止是删一行 UI —— 那个键**已经存在用户的 SP 里**，
而全量推送会把老值一直送过来。**删功能时要问「谁还在往这儿写」。**

**951 · ⭐⭐ 「字段存在」不等于「用户看得见」。**
`It(..., hint = 长文字)` 这种写法看起来天经地义，但渲染函数把 hint 丢了 ⇒
写了一大段、界面上是空的，而且**没有任何报错**。
**只读说明这类"纯文案"功能，改完必须真看一眼屏幕**（静态检查证明不了"显示出来了"）。

**952 · ⭐ 容器页是免费的，别怕套深一层。**
`App.kt` 的导航 = 页面 id 栈 + `Tree.page(id)` 查表 ⇒ 加一层「悬浮全家桶」
只是加一个 `Pg` 对象，**零导航改动**。想做「以后功能的归置地」时，直接建。
