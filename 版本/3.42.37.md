### ③ 是什么（重要）

台账里记着：

> `（3.42.37）| — | FitHook 尺寸闸门（目标 > 2500 放行）| — | ⏳ 未出包（重建报错没收尾）`

真因找到了：

```smali
const/high16 v11, 0x451c4000    # 2500.0f      ← ❌ 非法
```

`const/high16` 只能装 `0xNNNN0000`（**低 16 位必须全零**），而 `2500.0f` 的位模式是 `0x451C4000`，低位是 `4000` ⇒
`smali a` 直接拒收：`Invalid literal value: 1159479296. Low 16 bits must be zeroed out.`

**修**：改用 `const`（31i，可装任意 32 位）⇒ 组装一次过（196568 B）。

## 二、通话开关：原理（宿主机 2.6.1 实测）

```
ChatPageTopBar.kt:105
    callFeature = config.call_feature          # ModelConfig 的第 14 个字段（Lv87;->n:Lw77;）
    if (callFeature == null) → 不画「打电话」图标
    if (callFeature != null) → 画
```

而 `ModelConfig$CallFeature`（`Lw77;`）是个**零字段的空标记对象**
（= 存在即开启，同款套路见 `think_feature:{}` / `search_feature:{}`）。

⇒ **开关的本质 = 往 `kv_remote_settings_model_configs_v1` 的每个 model 里补 `"call_feature":{}`**

### 实现（全在桥里，Java）

| 文件 | 内容 |
|---|---|
| **`bridge/GmCall.java`（新）** | `fix()` 幂等补串 · `ensure()` 读→改→备份→写回 · `setOn()` · `state()` |
| `bridge/FdmBridge.java` | `onHostReady()` 里调 `GmCall.ensure(ctx)`（**宿主每次冷启动补一次** = 防下发覆盖）<br>+ `onCmd` 加 `call_state` / `call_set` 两个动作 |
| `fdm-app/src/Pages.kt` | `GrayPage` 顶部新增 `CallFeatureRow`（显示「已开启·已生效 / 未生效」）|

### 几个刻意的设计

1. **锚点用 `"model_type":"`**（每个 model 的第一个字段）—— 稳定、唯一，且**不与 `GmTts` 的锚点**（`"search_feature":{}` / `"think_feature":{}`）**撞车**。
2. **幂等**：串里已含 `call_feature` 就直接返回原串，绝不叠加。
3. **关的时候先查备份**：`GmStore.restore` 在**没有备份**时会把原键 **remove**（smali 实证：
   `if (bak 为空) remove(key)`）⇒ 那等于把宿主的 model_configs 删了。所以 `setOn(false)` 里先
   `read2("fuckds_bak_"+KEY) != null` 才敢 restore。
4. **不依赖 `GmPrompt.ok`** —— 它是**包内可见**（`gm` 包），桥在 `bridge` 包，直接调会 `IllegalAccessError`（教训 3）。
   改成自带的 `looksJson()`。

## 三、wip「音频通话」怎么停的（**没动 `GmEntry` 注册表**）

### 为什么不清 `GmEntry.smali` 里那几行注册

那段代码的寄存器是**交织**的：

```
.line 95   const-string v1,"I" / const-string v6,"...GmCallHook" / const-string v7,"ao1" → hookM
.line 96   const-string v1,"J" / const-string v6,"...GmCallHook"                → hookM   (v7 复用)
.line 98   findClass(v7, p1)  ← ★ v7 在这里还要用
.line 105  findClass(v5, p1)  / v2 = 方法名
.line 109  findClass(p0, p1)  / v8 = 方法名
```

删任何一段都得重算 v5/v7/p0/v8 与后续 label —— 正是**教训 E**（"一次改 7 处 ⇒ 崩了无法定位"）的翻版。
⇒ 改用**更安全、可逐个验证**的做法：**清空那些 hook 的方法体**。

### 清空的 10 个方法（原文件已备份到 `tmp/wip_bak-20261002-022548/`）

| 类 | 方法 | 为什么 |
|---|---|---|
| `GmCallHook` | `beforeHookedMethod` | ⚠️ **真在跑**（日志 `[通话] 已捕获发送上下文 ao1.k`）|
| `GmCallCtorHook` | `beforeHookedMethod` · `afterHookedMethod` | ⚠️ 真在跑（`hook ctor ao1 OK`）|
| `GmCallSeeHook` | `beforeHookedMethod` | yp1→GONE，本来就不注册 |
| `GmCallYpHook` | `afterHookedMethod` | 同上 |
| `GmAsrHook` | `beforeHookedMethod` | 同上 |
| `GmRecHook` | `beforeHookedMethod` | 未注册（死码）|
| `GmCallAiHook` | `beforeHookedMethod` | 未注册（死码）|
| **`GmCallBtn`** | **`show(Activity)`** | ⚠️ **活入口**：`GmResumeHook:148` 每次 onResume 都调（悬挂浮钮）|
| **`GmCallDialog`** | **`open()`** | ⚠️ **活入口**：`GmClick:557` 动作码 0x39 ⇒ 全屏通话页 |

**断掉这三条活入口 ⇒ 整条 wip 链全死**（`GmCallTick` / `GmCallPTT` / `GmCallRun` / 其它 36 个 `GmCallDialog` 方法都无人可达）。

## 六、教训（接编号）

| # | 教训 |
|---|---|
| **355** | ⭐⭐⭐ **`const/high16` 只能装 `0xNNNN0000`**。想装 float 位模式（如 `2500.0f = 0x451C4000`）必须用 `const`（31i）。写错 **`smali a` 直接拒收整个包**，而台账上只会留下"未出包"三个字。 |
| **356** | ⭐⭐⭐ **"新建一个类"和"删一个类"的成本不对称**：加类只需一句 `new-instance`；删类要重算**交织的寄存器 + label**。⇒ 停用**用清空方法体**，删类**单独排一版**。 |
| **357** | ⭐⭐ **"空标记对象"是最省事的开关形**（`CallFeature` 零字段 / `think_feature:{}`）—— 存在性即语义，我们只需**把 key 补进 JSON**。以后找宿主功能开关，先看 `*_feature` 有没有零字段的。 |
| **358** | ⭐⭐ **`GmStore.restore` 没备份会 `remove(key)`** ⇒ 想"关"一个改动前，**先确认备份存在**，否则是在删宿主的配置。 |
| **359** | ⭐ **同包可见性是隐藏的墙**：`GmPrompt.ok` 是 `gm` 包内可见，桥在 `bridge` 包 ⇒ 直接调 `IllegalAccessError`。桥要用底座的能力，**只用 public 的**（GmStore/GmUtil），否则自己写一份小工具。 |
