## 一、根因：**component 选错了**（不是 `yp1` 的问题）

`ao1.I(Lyp1;)V` 里会话 id 的来源（宿主真身）：

```
v1 = this.v.getValue() → ho1
if (v1 instanceof fo1) return;     // 未就绪就退出
v1 = ho1.b() → wr
v2 = wr.a                          // ⭐⭐ 会话 id ← 决定"发到哪个会话"
```

⇒ **会话完全由"你调的那个 component 自己的状态"决定**。

而上一轮日志告诉我们：主人这次**只点了我们的 🎧，全程没碰宿主界面** ⇒ `ao1.J` 从没在"当前对话的 component"上响过 ⇒ `sAo1` 一直是**启动阶段捕获到的那个"空会话"component** ⇒ 于是"另开新对话"。
（`yp1` 反而是对的 —— 它从 `yp1.b` 渲染心跳拿到，是**活的**那个 ⇒ 精确地印证了"输入状态对、会话上下文错"。）

## 二、2.14.4 的做法：给 component 加"会话判据"

| 步骤 | 做法 |
|---|---|
| 1 | **新类 `GmCallCtorHook`** + `hookAllConstructors("ao1")`：每次 `ao1` 构造就把实例存进 **`sNewA`（最新 component）** |
| 2 | 新增 **`sid(Object) → String`**：调 `M()`（＝`this.v.getValue().b()` 同一表达式）拿 `wr`，再读字段 `a` ⇒ **该 component 身上的会话 id**（全 try/catch，拿不到就返回 null） |
| 3 | `send()` 选 component：**`sNewA` 的 sid 非空就用它**；否则试 `sAo1`（`J` 捕获的那个）的 sid；**都不行就弹提示、不发**（宁可不发，也不再造新会话） |
| 4 | 发送前**落盘一行** `[通话] 发送目标会话 sid=<会话id>` ⇒ 下次可拿它和真实对话核对 |

```smali
# 选择逻辑（方向已逐条回读 ✓）
if sNewA.sid 非空 → 用 sNewA
else if sAo1.sid 非空 → 用 sAo1
else → toast 提示，不发
```
