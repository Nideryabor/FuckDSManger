## 一、这一版干了什么（一句话）

**把模板作者的包名从整个 dex 里拔干净了。**
`com.varuns2002.disable_flag_secure.*` → `com.nidyaber.fuckdsmanger.*`，一个字节的代码都没改。

## 二、四处改动

### 1. gm 整包搬家（123 个类）

| 旧 | 新 |
|---|---|
| `com.varuns2002.disable_flag_secure.gm.*` | **`com.nidyaber.fuckdsmanger.gm.*`** |

### 2. FLAG_SECURE 三件套正名（3 个类）

原来叫 `a` / `b` / `c`（`source ""` + Kotlin `Intrinsics` 说明它们是**匿名 hook 对象的编译产物**）。
它们是模块的**老本行**——扒掉防截屏标志：

| 旧 | 新 | 干什么 |
|---|---|---|
| `...disable_flag_secure.a` | **`GmFlagSecureIntHook`** | `args[0] & ~0x2000` |
| `...disable_flag_secure.b` | **`GmFlagSecureLpHook`** | `WindowManager.LayoutParams.flags &= ~0x2000` |
| `...disable_flag_secure.c` | **`GmFlagSecureBoolHook`** | `args[0] = Boolean.FALSE` |

### 3. 死类清理（2 个）

| 删掉 | 为什么 |
|---|---|
| `com.varuns2002.disable_flag_secure.DisableFlagSecure` | 2.22.111 起被 `GmEntry` 取代（1026 行手写 smali） |
| `com.little_femaleboy...whale.DisableFlagSecure` | 老转发壳（34 行），`xposed_init` 早就不指它了 |

### 4. 隐形引用（最容易漏的那类）

| 位置 | 处理 |
|---|---|
| 51 个 hook 类名字面量（`Class.forName` 用） | 在新建的 `GmEntry.java` 里已经指向新包（旧字面量随死类一起删） |
| `GmUtil.caller()` 的栈帧过滤前缀 `"com.varuns2002."` | → `"com.nidyaber."` |
| `GmEnv` 里那句 `"com.little_femaleboy.cannot_show.the_big_won_whale"` | **保持不动**（那是模块自己的 appId，防检测用的） |

> 类数：**129 → 128**（删 2 死类，+1 我们的 GmEntry；三件套只是改名）

## 三、怎么保证"只改了名字"

改名器 `mod-src/work/rename_pkg.py` 跑完自带一道**反向归一化比对**：
把新树的包名/类名换回旧的，跟原树**逐字节 diff**。

```
删死类  com.varuns2002.disable_flag_secure.DisableFlagSecure
改名字  ...a → ...gm.GmFlagSecureIntHook   （b / c 同理）
改写文件数: 126
残留 varuns2002: 0 处
═══ 反向归一化比对 ═══
比对 127 个文件，不一致 0 个
  🎉 干净：只改了名字，代码一个字节没动
```

再加一道**汇编往返验证**（整树 smali → dex → 再拆回 smali）：

```
往返验证：dex → smali 与汇编前的树【逐字节相同】（128 个类）
```

## 六、两个要记一笔的地方

1. **现在有两个 `GmEntry`**：
   - `com.nidyaber.fuckdsmanger.GmEntry` —— **我们的模块入口**（`xposed_init` 指它）
   - `com.nidyaber.fuckdsmanger.gm.GmEntry` —— 老类，是**宿主内悬浮条**那套（`sAct` / `sTick`）
   包不同、不冲突，但看代码时容易愣一下 —— 记在这里。

2. **`a.a.a` 留着没动**：那是 Kotlin `Intrinsics` 的内联副本（`"Parameter specified as non-null"` 那套），
   现在**只有那三个 FLAG_SECURE 钩子在用它**。它不含 `varuns2002`，所以这版不动。
   哪天把那三个钩子也翻成 Java 真编译，它就能一起退休。
