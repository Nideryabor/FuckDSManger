## 一、主人的问题
> "什么时候能把服务器流式输出显示到模块上？"

**答案：这一版就有了**，而且不用去啃 SSE 解析。

## 二、原理：找到"消息文本"的唯一入口
`Lvq;` = 宿主的消息基类（abstract），其中：
```smali
vq->S(Ljava/lang/String;)V     ← public final（8 条指令：new cy5 + rs8.l 写入）
```
- 它是 **final** 且**声明在基类** ⇒ 所有子类都走它 ⇒ **hook 它就等于拦截"所有消息文本更新"**（含流式追加）✓✓
- 另：`wr`（消息容器）里 `A(List,Integer,Z)` / `z(Lwr,List)` 是"应用流式补丁"（181 条指令），`wr.h():String` 是 String 状态 —— 都印证了文本是"逐段写进消息对象"的 ✓

## 三、2.18.0 实现
| 组件 | 职责 |
|---|---|
| **`GmAiTextHook`**（挂 `vq.S`） | 取 `args[0]`（文本）→ 非空则交给 `GmCallDialog.stream()` |
| **`GmCallDialog.stream(String)`** | 只在**「思考中」期间**生效（避免把用户自己发的消息也画上去）；主线程 post 到 `apply(type=2)` |
| **`apply` 新增 `type==2`** | **就地替换最后一条 `🤖 …` 行**（读当前文本 → 砍掉最后一个 `\n🤖 ` 之后的内容 → 写入 `head + "\n🤖 " + 新文本`）⇒ 视觉上就是"逐字长出来" ✓ |
