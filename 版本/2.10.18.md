## 一、这条日志排除了最关键的两个可能

```
[建议] buildMut2 进入（入口日志；能出现就说明真被调用了）
```

| 结论 | 依据 |
|---|---|
| ✅ `buildMut` **确实被调用了** | 入口 `logOnce` 打出来了（它在 `if-nez p0` 之前） |
| ✅ **没有抛异常** | 包装层的 `catchall` 会 `note + logE`，堆栈里含 `buildMut2` 字样 ⇒ 搜 "buildMut2" 只会命中一行 |
| ❗ 那界面为什么没有？ | **界面那块文字被截断了** —— 诊断块是拼在说明文字**后面**的多行长文本，屏幕/控件只显示最上面几行 |

⇒ **我的诊断设计失误**：把"历史"放在了最显眼的位置，而"最关键的状态"藏在折叠区。

## 二、本版改动

| 改动 | 说明 |
|---|---|
| 新增静态 `sStat` | `note()` 每次同时把**当前事件**写进 `sStat`（= 最后一次关键事件） |
| `infoText()` 改为 **「最后：<sStat>」置顶** + 「— 历史 —」在后 | 打开设置**第一眼**就能看到最新状态 |
| 对话框说明文字**大幅缩短** | `模板池每行一条，点按钮即发送。` + `【诊断 v2.10.18】` ⇒ 「最后：」落在第 2~3 行 |

## 三、下次只看一行：「最后：…」

| 「最后：」显示 | 含义 | 下一步 |
|---|---|---|
| `退出:输入框空` | 场景区分在生效（当时输入框是空的） | 打字后再看应变成"已接管列表" |
| `已接管列表` | 🎉 列表替换成功 | 画面没变 ⇒ 渲染层（remember 缓存） |
| `已接管文案` | 🎉 文案接管成功 | 画面没变 ⇒ 同上 |
| `退出:拿不到Context` | Context 两条来源都空 | 改从 `args` 取 |
| `退出:总开关关` | 开关状态读错 | 查键 |
| `进入 buildMut 宿主=N` | 只走到入口 | 说明它后面某一步提前 return（含 N 值可直接判断） |
| `(还没跑到任何关键点)` | 一次都没跑到 | 那排没渲染 |
