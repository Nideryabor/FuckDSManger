> 产物：**`FuckDSManger_NL_2.22.25_for_ds2.5.2.apk`**（**vc356 / 119 类 / V1+V2+V3 / sha256(partial) `9a4eb1b1…`**）
> 基线：`FuckDSManger_NL_2.22.24_for_ds2.5.2.apk`（vc355 / `3c9575de…`，弹窗滚动）
> 出场：`GmLog.w`（重写）· `GmDiag.log`（重写+落盘）· `GmUtil.log`/`logE`/`logFail`（重写）· `DisableFlagSecure.handleLoadPackage`（banner）

## 0. 一句话

这篇**没动任何业务逻辑**，只把「日志」这件事本身修好：
**改造前 3 条日志通道各走各的**（`logE` 丢了文件、`GmDiag` 不落盘、崩溃栈根本不进文件），
**改造后 = 一个出口**：`GmUtil.log / logE / logFail / logOnce` 和 `GmDiag.log` **全部**同时进
**logcat + 内存 DIAG + `files/DSMlogs/dsm.log`**，并且文件里是**人眼可读的时间戳**、**有轮转上限**、**崩溃栈不再丢**。

## 1. 改造前的体检（问题清单）

| 通道 | 实现 | 谁在写 | 病灶 |
|---|---|---|---|
| ① logcat | `GmUtil.log/logE/logFail` → `XposedBridge.log` | 全模块 | 要连电脑/看 Xposed 日志 |
| ② 内存 DIAG | `GmDiag.log` → 环形 `StringBuilder` | **只有** `GmUtil.log` + 零散几处 | ⚠️ 满 **6000 字符直接 `setLength(0)`** ⇒ 早期日志整段消失 |
| ③ 文件 | `GmLog.w` → `files/DSMlogs/dsm.log` | **只有** `GmUtil.log` | ⚠️ 无轮转/无上限 · 时间戳是**裸毫秒数**（`1758...`）· 每行 open→write→close |

**四个明确缺口**：

1. ❌ **`GmUtil.logE(Throwable)` 只进 logcat** ⇒ **崩溃堆栈永远不在文件里**（这就是为什么历史上反复「索要 logcat」）
2. ❌ **`GmCrashHook`（崩溃捕手）把宿主崩溃栈塞进 `GmDiag`，而 `GmDiag` 不落盘** ⇒ 最关键的诊断信息既进不了文件、还会被后续日志冲掉（**本版最值钱的一条修复**）
3. ❌ 一批日志点**只调 `GmDiag.log`**（如 `GmPainterHook` 的 `PHook: file NOT EXIST` / `sAct NULL`）⇒ 同样不落盘
4. ❌ `logFail` 把 `消息 | 堆栈` **压成一整行**塞进去 ⇒ 文件里没法读

## 2. 本版 5 处改动（全部在日志三件套）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `GmLog.w`（重写） | ① 时间戳：裸毫秒 → **`MM-dd HH:mm:ss.SSS`**（`SimpleDateFormat`）② **轮转**：`dsm.log` 超过 **256 KB** ⇒ 先删 `dsm1.log`，再把 `dsm.log` 改名过去（保留上一批，只留一代） |
| 2 | `GmDiag.log`（重写） | ① 时间戳 → **`HH:mm:ss.SSS`** ② 上限 **6000 字符 → 32768**，且溢出时**不再整段清空**，改为 `StringBuilder.delete(0, len-24576)` **滚动保留尾部 24 KB** ③ **新增一行 `GmLog.w(p0)` ⇒ DIAG 落盘**（这是「落盘职责下移」的关键） |
| 3 | `GmUtil.log` | **删掉**自己那行 `GmLog.w`（避免与 #2 重复写文件）—— 现在它只做 `XposedBridge.log` + `GmDiag.log` |
| 4 | `GmUtil.logE` | 从「只 logcat」改成 **三通道**：logcat + `GmDiag.log("E " + 栈)`（→ 顺带落盘）。崩溃栈第一次进文件 |
| 5 | `GmUtil.logFail` | 不再压成单行，改为 **`log(消息)` + `logE(堆栈)` 两条**（文件里可读）。**`.registers 3` 不变、零风险** |

**附带**：`DisableFlagSecure.handleLoadPackage` 里睡了很久的 `"NL v2.21.0"` 串更新到 `2.22.25`，
并在**包名匹配成功之后**插一行启动 banner（见 §4）。

## 3. 改后的数据流（一张图）

```
GmUtil.log(msg) ──┬─→ XposedBridge.log("FuckDSManger: " + msg)       ← ① logcat
                  └─→ GmDiag.log(msg) ──┬─→ 内存 StringBuilder（滚动 24/32 KB）  ← ② DIAG
                                        └─→ GmLog.w(msg) ─→ DSMlogs/dsm.log     ← ③ 文件

GmUtil.logE(t)  ──┬─→ XposedBridge.log("FuckDSManger: " + 栈)
                  └─→ GmDiag.log("E " + 栈) ──→ ② + ③
GmUtil.logFail(m,t) ─→ log(m) + logE(t)
GmUtil.logOnce(k,m) ─→ log(m)（HashSet 去重，同键只第一次）
GmCrashHook     ──→ XposedBridge.log + GmDiag.log ⇒ ② + ③（本版起崩溃栈落盘）
其它 GmDiag.log(...) ─────────────────────────────→ ② + ③（本版起全部落盘）
```

⇒ **结论：任何一条 `GmUtil.*` 或 `GmDiag.log` 的调用，都必然在三处留痕，且文件里格式统一可读。**

## 5. 性能与取舍（必读）

| 项 | 说明 |
|---|---|
| 文件写入成本 | 每次 `w` = `length()` + `SimpleDateFormat` + `open/write/flush/close`。**关键步骤级**日志量下完全无感 |
| 唯一可疑高频点 | `GmPainterHook.afterHookedMethod` 的 `PHook: kf5.K id=0x…` —— **已有 `sCalls < 600` 自限流** ✅（不是每帧无限刷） |
| 另一处绘制 hook | `GmPaintModHook` 有 `sTold` 一次性闸门 ✅ |
| `logFail` 行为变化 | 从 1 行变 2 行（`消息` + `E 栈`）。**判读习惯要跟着改**，但文件可读性大幅提升 |
| 轮转代价 | 超过 256 KB 时旧内容整体改名到 `dsm1.log`（只有一代），再超就覆盖它 |

**没有做的事**（有意留下）：
- 没加「日志分级开关」（主人选的是关键步骤级，不需要分级）
- 没做日志管理 UI（主人说「这次只做底层，UI 以后再说」）
- 没改高频 hook 的既有策略（限流门都还在）

## 7. 下一条线（覆盖度，尚未做）

本版解决的是「**有日志的地方，日志可靠**」。**覆盖度**（主人说的「每一步」）还差这些：

| 优先级 | 事项 |
|---|---|
| 🔴 | **「hook 被调用了没」** —— 目前约 50 个 `GmXxxHook` 里，只有一半在 `beforeHookedMethod` 里有痕迹。历史多次踩「以为没生效，其实没装上 / 没被调用」 |
| 🟠 | 各 hook 的 **bail 分支**（静默 `return-void`）逐条点亮 |
| 🟠 | 启动时把**关键开关状态**（气泡/头像/防撤回/环境伪装…）一次性打进日志 —— 以后看日志不用问「你开着没」 |
| 🟢 | 菜单「调试 / 日志（DSMlogs）」页做成**真·日志管理页**（路径/大小/行数/刷新/清空/复制）—— 主人说 UI 以后再说 |

**候选方案（待主人拍板）**：
- **A 逐点补**：按功能线一批批加「进入 / 分支 / 结果 / 失败」日志，风险最低、可控
- **B 自动 trace 层**：新增 `GmWrapHook` 包装所有注册的 hook，**自动**记录「首次进入」+ 调用计数（一次覆盖全部），但要在 `hookM/hookM2/hookC2/findAndHookMethod` 四处包一层 + 用反射回调 protected 的 `beforeHookedMethod` ⇒ **一旦反射失败会让所有钩子失效**，风险显著更高

## 8. 教训（本次新增）

| # | 教训 |
|---|---|
| 750 | ⭐⭐⭐ **「内存 DIAG 不落盘」= 最关键的日志永远拿不到**：`GmCrashHook` 抓到的宿主崩溃栈只进 DIAG，而 DIAG 满 6000 字符就整段清空 ⇒ 崩溃现场被**下一个日志刷掉**。诊断设施必须「每条出口都落盘」 |
| 751 | ⭐⭐⭐ **`logE` 只写 logcat 的代价**：本项目历史上**每次要崩溃堆栈都得让主人抓 logcat**，根因就是这 5 行代码。**异常通道和普通通道必须同等** |
| 752 | ⭐⭐ **环形缓冲别用「清空」，要用「滚动」**：`setLength(0)` 会把最值钱的**启动期日志**（hook 装载结果）第一个扔掉；`delete(0, len-keep)` 才是对的 |
| 753 | ⭐⭐ **时间戳可读性 = 诊断效率**：裸 `currentTimeMillis` 让「哪个动作对应哪条日志」变成算术题；`MM-dd HH:mm:ss.SSS` 一眼对上 Toast/操作 |
| 754 | ⭐ **「谁负责落盘」要唯一**：两个通道各自调 `GmLog.w` 会**写两遍**。本版把落盘职责**收拢到 `GmDiag.log` 一处**，`GmUtil.log` 不再重复 —— 加通道容易，去重复容易忘 |
| 755 | ⭐ **写 smali 时 `.catchall {A .. B} :label` 结尾没有 `}`** —— 本版手写时连犯两次（`SMALI_COMPILE_FAILED_IN_SESSION: mismatched input '}'`）。**标签行 = `.catchall {…} :catchall_x`，就一个闭合括号** |
