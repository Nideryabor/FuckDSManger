## 0. 🐛 真凶：`collect()` **第一次调用就 NPE**，而异常被它自己的 `catch` 吞了

```smali
sget-object v0, GmBubble->sAblateList
if-eqz v0, :set_first          # ★ 列表为 null ⇒ 跳到 :set_first
…（去重 / 追加）
:set_first
invoke {v0}, String->length()  # ✗✗ 这里 v0 仍然是 NULL ⇒ NPE!
sput-object v0, sAblateList
```

**执行链**：
1. 第一次调用 ⇒ 列表为 null ⇒ 跳到 `:set_first`
2. `invoke {v0}, length()` 对 **null** 调用 ⇒ **NPE**
3. 被 `collect()` 自己的 `.catchall` **吞掉** ⇒ 静默返回
4. **每一次调用都重复 1~3** ⇒ **候选表永远是 `null`**
5. `onClick` 于是每次都走「`:empty_msg`」分支 ⇒ 吐司 =「**试验台：还没有候选——请先在目标页面划一下**」
6. ⇒ **永远不会消融** ⇒ **"和上一轮一样的毛病"** ✅

> ⚠️ **这条 bug 是 `2.22.80` 引入的** ⇒ **两轮的"一样的毛病"，是同一个原因。**
> ⚠️ 也就是说：**主人看到的那个吐司，字面就是"还没有候选"** —— 我前两版都在错误的方向上找原因。

## 1. 修复：重写 `collect()`（去掉空指针，也去掉没必要的长度上限）

```smali
.method private static collect(Ljava/lang/String;)V
    .registers 5
    :try_start_0
    if-eqz p0, :ret                                    # null / 空 ⇒ 忽略
    invoke-virtual {p0}, String->length()I
    move-result v0
    if-eqz v0, :ret
    sget-object v0, GmBubble->sAblateList
    if-eqz v0, :set_direct                             # ★ 为空 ⇒ 直接设（不再去解引用！）
    invoke-virtual {v0, p0}, String->contains(CharSequence)Z
    move-result v1
    if-nez v1, :ret                                    # 已存在 ⇒ 返回
    <append: v0 + "|" + p0 → v0>
    sput-object v0, GmBubble->sAblateList
    goto :ret
    :set_direct
    sput-object p0, GmBubble->sAblateList              # ★ v0 非空时才会走到后面的追加
    :ret
    :try_end_0
    .catchall {…}
    return-void
    :catchall_0
    move-exception v0
    return-void
.end method
```

**关键改动**：`if-eqz v0, :set_direct`（**为空就跳**）⇒ 之后所有 `length()`/`contains()` 都只会在**非空**时执行 ⇒ **不可能再 NPE**。
顺带**去掉了 `0x600` 长度上限**（候选表本来就只有十来条，不需要）。

| # | 内容 |

| **200** | ⭐⭐⭐ **"首帧初始化"逻辑不能放在"可能解引用空值"的路径上** —— 我的写法是经典错法：`if (x == null) goto L; …; L: use(x)` ⇒ **判空之后必须立刻赋值，再落到公共标签**，否则标签处 `x` 还是 null。⚠️ 更隐蔽的是它**每次都被自己的 catch 吞掉** ⇒ 功能静默失效、毫无痕迹。 |
