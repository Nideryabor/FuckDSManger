## 一、判读主人日志（这次窗口够了）

```
1790246062285 [气泡] 已发起选图（pick 已武装）   ← 点击
1790246063163 [prompt] reapply …                 ← +0.9s：宿主 Activity 又 resume
1790246075005 [prompt] reapply …                 ← +12.7s：又一次 resume
（★ 全程没有一条 PickHook: entered）
```

⇒ **宿主压根没回过 `onActivityResult`** ⇒ **选图 Activity 十有八九根本没被拉起来**。
而两次 `reapply`（onResume）也吻合：「只弹了个对话框又回来」不会产生 `onActivityResult`。

### 根因：**我在 2.22.5 引入的退化**

```smali
    invoke-static {}, GmBubble;->pick()V
    <log 「已发起选图」>                      ← ⚠️ 这行打完才去取 Activity
    sget-object v0, GmEntry;->sAct:Activity   ← ⚠️ 2.22.5 从这里起把 GmBeautyDialog.sAct 换成了它
    if-eqz v0, :ret                           ← ⚠️ 空就 return，而且【静默】
```

- 「已发起选图」**不能证明选图被拉起**（它在取 Activity 之前）
- `GmEntry.sAct` 在这个场景很可能为 null/失效 ⇒ **直接静默 return** ⇒ 没弹窗、没回调 ✓ 现象全吻合
- ⚠️ 而且我当初把**本来更可靠的 `GmBeautyDialog.sAct`**（按钮就在这个对话框里，必然非空）换掉了 —— **这是我自己改坏的**

## 三、复测（装 2.22.7 → 美化 → 选择气泡图 → 选图 → 划一下）

| 日志 | 结论 |
|---|---|
| `已发起选图` 后**有** `选图已拉起（等待返回…）` | ✅ 选图弹窗应该出来了 |
| `已发起选图` 后**有** `拿不到 Activity…未能拉起选图` | 两个字段都是空 ⇒ 我改用「视图所属 Activity」兜底 |
| `选图已拉起` 后**终于出现** `PickHook: entered` / `已收到选图回调` | ✅ 回到结果链，看后面 `气泡图已保存` / `图片版注入已启用` |
| `选图已拉起` 后**仍然一条 `PickHook: entered` 都没有** | 宿主不回结果（或钩子不在 `onActivityResult` 这条路上）⇒ 我改挂 `GmPickHook` 的注册点/多重重载 |

## 四、教训

| # | 要点 |
|---|---|
| **699** | ⭐⭐⭐ **「打点位置」决定它能证明什么**：`已发起选图` 打**取 Activity 之前** ⇒ 它永远无法区分「拉起了」与「静默 return」。**诊断要打在最靠近"成败分界"的那一行之后**（本次在 `startActivityForResult` 之后补 `选图已拉起`）。 |
| **700** | ⭐⭐⭐ **换「同类型但语义不同」的依赖要留回退**：`GmEntry.sAct`（全局当前 Activity）与 `GmBeautyDialog.sAct`（本对话框的 Activity）看着都行，但**后者在按钮所在场景必然非空**。**换依赖时先问「哪个场景下它一定有值」**，并**保留旧值作兜底**。 |
| **701** | ⭐⭐ **「我自己改坏的」也要靠日志抓**：这轮现象与上一轮一模一样，差别只是**新日志把「已拉起」与「静默 return」区分开了** ⇒ 一眼看到是 Activity 取值那段。**两轮现象相同但代码不同时，优先怀疑"我这两版之间动过的那一处"。** |
