## 一、① 毛玻璃 + iOS 蓝

### v2 为什么丑

| | v2 | iOS |
|---|---|---|
| 底 | `0xF218181C` **实色灰板** | `SystemThinMaterialDark`（半透明 + 真模糊） |
| 强调色 | `0xFF5CC7FF`（天蓝，太浅） | `#0A84FF`（systemBlue dark） |
| 边 | 一条 `0x33FFFFFF` 描边 | 毛玻璃自带边缘高光 |

### v3 怎么做的

**真·抓屏模糊**（不是假玻璃）：

```
vBgShot    ← PixelCopy(宿主窗口在卡片身下的那块) → 缩 8 倍 → 3 遍 box blur
vBgTint    ← 深蓝半透明罩（0x78090B12 → 0x8C090B12 → 0xA0090B12 竖向）
glow       ← 顶部 56dp 柔光（0x1FFFFFFF → 透明）＝ 玻璃厚度感
vHairline  ← 1dp 内描边（0x3DFFFFFF）＝ 玻璃边
```

- **抓之前要藏自己**，否则抓到的是卡片自己 ⇒ `pagePlay` INVISIBLE + 顶栏/边线/底图 alpha=0，等 40ms
- **失败降级**：PixelCopy 抛异常 / 结果非 SUCCESS / SDk<24 ⇒ 用 `C_SOLID`（0xF00E1017 深蓝黑），功能零影响
- **连续失败 3 次就停**，别一直戳
- 配色全换：`C_ACC = 0xFF0A84FF`、`C_ACC_HI = 0xFF4FA8FF`、文字 `0xFFF5F7FA`（掺蓝，不是纯白）

### ★ 踩到的坑（真机抓到的，不抓日志发现不了）

```
11:37:52 毛玻璃底已更新 149×142
11:37:56 毛玻璃底已更新 148×151
11:37:57 毛玻璃底已更新 148×158
11:37:57 毛玻璃底已更新 148×165
11:37:57 毛玻璃底已更新 148×171
11:37:58 毛玻璃底已更新 148×173
11:37:58 毛玻璃底已更新 148×173
11:37:58 毛玻璃底已更新 149×173
11:37:59 毛玻璃底已更新 163×152     ← 3 秒 9 次
```

**根因**：`applyPlayLayout` 每帧都改封面的宽高 ⇒ `onSizeChanged` **每帧都响** ⇒
每帧都去抓一次背景（而且每次都要藏自己 40ms）⇒ **界面疯狂闪**。

**修法（两层）**：
1. `refreshBackdrop` 加 **250ms 冷却** + **`layoutAnim.isRunning()` 时直接 return**
2. `onSizeChanged` 改成 **debounce 320ms**（`postDelayed` + `removeCallbacks`）

修完（11:39:12~17）：
```
11:39:12 毛玻璃底已更新 132×141
11:39:14 毛玻璃底已更新 148×105
11:39:17 毛玻璃底已更新 140×152      ← 4 次，分散，不闪
```

## 二、② 过渡动效

v2 是**瞬切**（我当时文档里写"故意不做"，主人的原话是"动效不足" ⇒ 该做）。

**实现**：一个 `ValueAnimator` 驱动 `layoutT`（0=常态 / 1=聚焦），
`applyPlayLayout(t)` 每帧**插值所有控件的矩形和透明度**。

```java
a.setDuration(300);
a.setInterpolator(new PathInterpolator(0.4f, 0f, 0.2f, 1f));  // ≈ iOS ease-in-out
```

逐帧插值的东西：

| 控件 | 常态 | 聚焦 |
|---|---|---|
| 封面 | `(PAD, bodyTop, 84, 84)` | **`(0, 0, w, h)`** ← 整卡 |
| 歌词 | `(PAD+84+10, bodyTop, w-PAD, bodyTop+bodyH)` | `(PAD, bodyTop, w-PAD, h-PAD)` |
| 封面圆角 | 10dp | 0（交给卡片裁剪）— 靠 `invalidateOutline()` 逐帧改 |
| 进度条 / 按钮行 | alpha 1 | alpha 0 → 收尾 GONE |
| 渐变暗膜 | alpha 0 | alpha 1 |
| 顶栏 ♪ / ✕ | alpha 1 | alpha 0 → GONE |
| 顶栏 `‹` | GONE | alpha 1 |

纯图态另有 220ms 的 `animate().alpha()` 淡入淡出。

### ★ 另一个坑：`alpha=0` 的 View 照样吃触摸

如果只把进度条/按钮设 `alpha=0` 不设 GONE，**它们仍然接收点击** ⇒
聚焦态点封面下半部分 = 永远在切态，双击纯图根本做不出来。
⇒ 动画收尾（`t > 0.98`）时切 `GONE`（中途切会闪，所以不能一上来就切）。

## 三、③ 封面铺满整卡（**改结构**）

### v2 为什么做不到

```
v2 结构：
  content (VERTICAL)
  ├── topBar        (28dp)        ← 顶栏在 body **外面**
  ├── vBody  (weight=1)           ← 封面在 vBody 里
  ├── vSeekRow
  └── vBtnRow
```

封面在 `vBody` 里 ⇒ `vBody` 的上边界就是「顶栏高度 + 内边距」
⇒ **封面在数学上永远够不到标题栏那一块**。

### v3 结构（绝对定位）

```
GmMiniBarView (FrameLayout, 圆角裁剪)
├── vBgShot / vBgTint / glow          毛玻璃
├── pagePlay (整卡大小)
│   ├── vCover      ← ★ 提到这里，聚焦时矩形就是 (0,0,w,h)
│   ├── vScrim
│   ├── vLyric
│   ├── vSeekRow
│   └── vBtnRow
├── pageSearch
├── vTopBar (LinearLayout)  ← 浮在封面**之上**，字靠白色阴影读
├── vHairline
└── 四角手柄
```

**为什么这样就对了**：封面和顶栏成了**兄弟节点**，封面在下、顶栏在上。
聚焦时封面 `(0,0,w,h)` 直接盖住整张卡（含标题栏区域），
顶栏那几个按钮和文字靠 `setShadowLayer(4f, 0, 1f, 0x99000000)` 压在图上还读得清 ——
这正是 iOS 的做法（`_playPage` 压到 index 1，顶栏单独浮在上面）。

**顺带**：v2 里 `vBody` 的 `weight=1`（"拉高自动给歌词"）现在由
`applyPlayLayout` 里的 `bodyBottom = seekTop - seekGap` 算出来，效果一样。

## 六、教训

| # | 教训 |
|---|---|
| **AO** | ⭐⭐⭐ **动画里每帧改宽高 ⇒ `onSizeChanged` 每帧响 ⇒ 任何挂在它上面的"重活"都会变成每帧一次**。给重活加**冷却 + 动画期间跳过 + debounce** 三件套 |
