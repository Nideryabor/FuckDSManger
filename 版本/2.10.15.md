## 一、这一版做了什么

新增类 **`GmSuggestView`**（`implements Runnable, View.OnClickListener, ViewTreeObserver.OnGlobalLayoutListener`）：

| 方法 | 作用 |
|---|---|
| `attach()` | 任意线程可调：post 到主线程再挂载 |
| `run()` | 主线程：把一条 **黄底 + 红/绿/蓝三个按钮**的 `LinearLayout` 加进 `decorView`<br>（`FrameLayout.LayoutParams`、`gravity=BOTTOM`、`bottomMargin=100dp`） |
| `onClick(View)` | 点击 ⇒ Toast「[建议] 点到按钮：xxx」+ 移除按钮条（便于反复测） |
| `onGlobalLayout()` | decor 高度变化时上报 `decor h=` 与 `barY=`（**专门用来判断键盘行为**） |

**挂载触发点**：hook `b51.a`（`ChatInputActionBar` 组合）⇒ `GmSuggestHook.bar()` ⇒ `GmSuggestView.attach()`。
（`b51.a` 只在聊天页组合，等于「聊天页已就绪」的信号。）

**复用的现成基础**：

| 项 | 来源 |
|---|---|
| 拿 Activity | **`GmEntry.sAct`**（由 `GmResumeHook` 在 `MainActivity.onResume` 写入） |
| addView 到 decor 的写法 | 照抄 **`GmEntry.show()`**（本项目**已验证可行**的 overlay 实现，真机在用的入口条） |

⇒ 没有新引入任何 API 风险，只是换 `gravity` 到 `BOTTOM` + 换颜色。

## 四、潜在的坑（提前记下）

| 项 | 说明 |
|---|---|
| **Z 序** | `GmEntry.show()` 用的是同一个 decor，证明「加得进去且看得见」；但**输入框**也是 Compose 画的，若按钮条被输入框盖住 ⇒ 说明我们加的位置层级不对（要改 `addView` 顺序或换父容器） |
| **Activity 重建** | 旋转/切主题会重建 Activity，`sBar` 会指向旧 view ⇒ 正式版需在 `onResume` 检查并重挂 |
| **`sBar` 语义冲突** | `GmEntry.sBar`（入口条）与我们 `GmSuggestView.sBar` 是**两个独立字段**，不冲突 ✔ |
| **点击穿透** | 按钮条只占自己那块区域，背景 `LinearLayout` 未设 clickable ⇒ 空白处点击会穿透到宿主 ✔（好事） |
