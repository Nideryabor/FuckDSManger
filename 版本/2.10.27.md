### 1.1 两个结论

**① `report()` 的 Toast 会抛 NPE 并打断后续代码**

`beforeHookedMethod` 的顺序原本是：

```
fire → inject → report（★ 在这里抛异常）→ bar → prompt → fill → core
```

⇒ `report()` 之后的代码**全部不执行** ✗
⇒ 某些 hook 点（在非主线程命中）触发时，`bar` / `prompt` / `fill` / `core` 全被跳过 ✗

**② `dm0.c` 命中了，但 `yb5.e` 完全没有**

⇒ 说明 `dm0.c` 是被**别处**调用的（它也服务其它动画）
⇒ **`yb5.e` 确实没被调用** ⇒ 「`nb5.c` 被 skip」的推断成立 ✓

## 二、本版修复

| # | 动作 | 说明 |
|---|---|---|
| 1 | **`GmUtil.toast` 整体包 `try/catch`** | 非主线程不再抛异常（静默失败，绝不影响调用方） |
| 2 | **`report()` 移到 `beforeHookedMethod` 最后** | 即使它内部出问题也只影响自己，不会挡住功能调用 |

⇒ 顺序变成：`fire → inject → bar → prompt → fill → core → report`
