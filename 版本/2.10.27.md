# FuckDSManger 2.10.27（回复建议 · 修 `templates()` 的空判断反转 ⇒ 模板池一直是 0 条）

> 产物：`FuckDSManger_2.10.27_for_ds2.5.2.apk`（**178 / 2.10.27**，90 类，V1+V2+V3，sha256(partial) `49b3be40…`）
> 触发：主人日志 —— **`[建议] build 模板=0 造出=0`** + `g56 构造器 → …` + `宿主列表空且自建失败`

## 一、真凶：`GmSuggest.templates()` 里同一类反转

```smali
    invoke-virtual {v4}, Ljava/lang/String;->isEmpty()Z
    move-result v5
    if-nez v5, :cond_add          ← if-nez = 「不为零（= 是空串）就跳去 add」
    goto :goto_inc
    :cond_add
    invoke-interface {v0, v4}, Ljava/util/List;->add(…)Z
```

语义变成了：**空串被加进列表、非空的行被跳过** ⇒ 你那三行默认文案（`能再展开讲讲吗？` 等）**全被丢弃** ⇒ 模板池 0 条
⇒ `build()` 无事可造 ⇒ `造出=0` ⇒ 自建失败 ⇒ 宿主列表空时无兜底 ✓✓ **全链条对上**。

### 修法（一个助记符）

```smali
-    if-nez v5, :cond_add
+    if-eqz v5, :cond_add      ← v5==0（非空）才去 add；空串落空到 goto :goto_inc（跳过）
```

## 二、这条 bug 的影响面

| 路径 | 影响 |
|---|---|
| 空列表时的自建（本版主线） | 0 条 ⇒ 造不出对象 ⇒ 只剩宿主那排空壳 ✓ 与现象一致 |
| 宿主列表非空时的替换 | 没有文案可填 ⇒ 替换也无效 |

⇒ 也就是说：**这一行让"注入文案"这条路从 2.10.1 到现在一直空转**（和 2.10.19 修的 `if-nez p0, :ret` 是同一天的两个同源错误）。

## 四、教训

| # | 教训 |
|---|---|
| 211 | ⭐⭐⭐ **`isEmpty()` 这类"返回布尔"的判断最容易写反**：`if-nez`/`if-eqz` 与 `isEmpty()` 的返回值叠加，形成"双重否定"错觉 ⇒ 建议**写完后立刻用一句自然语言复述一遍**（"非空才加"），再核对分支目标 |
| 212 | ⭐⭐ **同源错误要一起排**：本版与 2.10.19 的 `if-nez p0, :ret` 是同一天写下的、同一类错误 ⇒ 修一处后应**全文搜索同类模式**，而不是等下一个真机日志 |
| 213 | ⭐ **「模板=0」是决定性线索**：一个数字直接把范围从"构造器猜错"缩小到"池子本来就空"，省掉一轮试错 |
