## 一、2.18.8 为什么失败（主人日志实证）

主人日志（`v2.18.8`）关键三行对照：

| 日志 | 结论 |
|---|---|
| `[通话] 命令 args[0]=fn1` + `a=你是谁？` | ✅ 宿主识别 + 发送成功 |
| **完全没有 `[通话] um1（生成结束）⇒ 回待机`** | ❌ **`um1` 根本没来**（至少在 6.7s 窗口内没来） |
| **完全没有 `[通话][AI] …`（连 `um1 后已尝试抓取回复` 都没有）** | ❌ ⇒ **`grabAi()` 一次都没被调用**（取数/投递代码没问题，是「触发点」错了） |
| `[通话] 思考中超过 6s 无信号 ⇒ 自动回待机` | ← AI 回复要 ~11s，**6s 兜底抢在前面**把状态刷回待机 ⇒ 看起来就是「自动回挂机」 |

> ⚠️ **2.18.8 的错**：把「抓取」死绑在 `um1` 上 ⇒ 这个赌注不成立。
> （历史注：2.17.8 记的「`um1` 出现在 AI 说完那一刻」是**那一次**的观察；本环境里它至少**不可靠/不可等**。）

## 二、本版做法：方案 B（把 `um1` 降级为「加分项」，不当前提）

```
通话页「思考中」期间：GmCallTick（1s 守护线程）→ tick()
   ├─ ① 只读轮询 grabAi()：读「最新一条有字的消息」的 vq.l()
   │      文本变了  ⇒ sLast=文本、sSame=0、sThinkAt=now（续命）、stream(文本)   ← 逐字生长
   │      文本没变  ⇒ sSame++；连续 3 次不变 ⇒ 认定生成结束 ⇒ 回「待机｜按住说话」
   └─ ② 总兜底：sThinkAt 起 60s 无任何进展 ⇒ 回待机（旧的 6s 太短，抢在 AI 之前）
```

**同时加了「别把主人自己那条当成 AI 回复」的双保险**（轮询第一次读到的必然是主人那条）：

| 判据 | 说明 |
|---|---|
| `vq.D()` == `"USER"` | 最新一条「有字」的消息如果是主人自己那条 ⇒ **放弃本次**（继续等） |
| 文本 == `sAsr` | 兜底判据（`sAsr` = 本模块抓到的识别文字） |

> 逻辑要点：**从末尾倒扫「第一条有字的消息」**；若它是 USER ⇒ 说明 AI 那条还没长出字来，直接收工（不会去显示更早的旧回复）。

## 六、教训

| # | 教训 |
|---|---|
| **600** | ⭐⭐⭐ **不要把「抓取」死绑在一个「还没被证明可靠」的信号上**。2.18.8 全押 `um1` ⇒ 它不来，功能就整个是空的。**任何"结束信号"都该有第二条路（轮询/超时/增长停止）兜底。** |
| **601** | ⭐⭐⭐ **「日志一行都没有」＝那段代码没执行**：主人日志里连 `um1 后已尝试抓取回复` 都没有 ⇒ 直接锁定「触发点没到」，一步排除掉取数/投递的嫌疑（**别去改没错的地方**）。 |
| **602** | ⭐⭐ **兜底窗口必须大于「正常路径的耗时」**：AI 回复 ~11s，而兜底 6s ⇒ 兜底反而成了常态（用户看到的就是"自动回挂机"）。**定兜底值前先问：正常最慢要多久？** |
| **603** | ⭐⭐ **轮询第一次读到的必然是「主人自己那条」**：任何「读最新消息」的实现都要先判角色/内容，否则会把用户的话冒充 AI 回复（本次用 `D()=="USER"` + `sAsr` 双判据）。 |
| **604** | ⭐ **「文本停止增长 N 次」是免费的生成结束信号**（1s 轮询下 N=3 ⇒ 3s），比去猜宿主的结束指令稳得多。 |
| **605** | ⭐ **smali 里绕开 `const-wide/32` 语法风险**：需要 60000 这种超 16 位的宽常量时，写 `const-wide/16 X` + `add-long/2addr vX, vX`（X×2）最稳。 |
