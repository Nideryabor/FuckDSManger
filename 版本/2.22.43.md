## 2. 💥 根因：页面底色是「套娃」，而我的作用域只罩住了中间两层

| 层 | 深色模式 | 浅色模式 | 在 `zc.s`（ChatPage）作用域内？ |
|---|---|---|---|
| `bg#1` | `#FF0F0F0F` | `#FFFFFFFF` | ❌ **不在**（`depth=0`，在 ChatPage 之前） |
| `bg#2` | `#FF0F0F0F` | `#FFFFFFFF` | ✅ 在（`depth=1`）→ **被透明化** |
| `bg#3` | `#FF0F0F0F` | `#FFFFFFFF` | ✅ 在（`depth=1`）→ **被透明化** |
| `bg#4` | `#FF292929` | `#FFFFFFFF` | ❌ **不在**（`depth=0`，在 ChatPage 之后） |

⇒ **最外那层和最里那层都在 ChatPage 之外** ⇒ 没被透明化
⇒ 深色模式下它们接近黑（看不出来）· **浅色模式下是纯白（刺眼）** ⇒ 就是那块白

> ⚠️ 也就是说：**「只透明化作用域内的层」这个策略从一开始就漏了两层**，只是一直被深色模式掩盖着。

## 3. 🛠 修法：不再依赖「作用域」，改成「**记住页面底色，见到同色就透明**」

```
rec (新增，挂在 hook 入口，dg/pg 之前)：
    若 sPageColor == 0 且 方法名 == "v" 且 args[1] 是 Long
      ⇒ sPageColor = args[1]          # 记住本次会话的「页面底色」

GmPageHook.before：每次 ChatPage 组合 ⇒ sPageColor = 0（重新记忆）

pg（判据链重写）：
    ① 方法名 == "v"
    ② args[1] 是 Long
    ③ args[1] == sPageColor            ← ★ 不再看作用域深度
    ④ sDepth == 0                      ← 排除助手项内的气泡底
    ⑤ sPageCnt < 8                     ← 放宽（原来 4）
    ⑥ GmBg.real() 为真                  ← 确保背景确实开着
    ⇒ cnt++ 并 args[1] = Long(0)（全透明）
```

**为什么这样就不会漏**：判据从「**这段代码在不在 ChatPage 里**」换成了「**这层颜色是不是页面底色**」——
后者**与调用位置无关**，所以 `bg#1`/`bg#4` 这些作用域外的同色层**也会被一起透明**。

**`why=` 编号随之更新**：

| `why=` | 含义 |
|---|---|
| **1** | 方法名不是 `v` |
| **2** | `args` 有问题（null / 长度 < 2 / 不是 `Long`） |
| **3** | **颜色不是页面底色** |
| **4** | 在助手消息项内（`sDepth > 0`） |
| **5** | 配额用满（`cnt >= 8`） |
| **0** | ✅ 通过（`cnt` 已 +1） |
| **7** | `GmBg.real()` 返回 false |

## 6. 教训（817~818）

| # | 内容 |
|---|---|
| **817** | ⭐⭐⭐ **「套娃」不能只修看得见的那几层**：页面底色一共 **4 层**，我只透明化了作用域内的 2 层 —— 深色模式下漏掉的黑层**和背景图颜色相近，看不出来**，直到浅色模式（白）才暴露。⇒ **改「隐藏/覆盖」类逻辑时，要按「一共有几层」来验证，而不是按「看起来对不对」**；深浅色各跑一遍是最便宜的交叉验证。 |
| **818** | ⭐⭐⭐ **「位置判据」比「范围判据」稳**：一开始我用「在不在 ChatPage 作用域内」来决定透明谁 —— 结果**作用域边界和绘制层级不对齐**（外两层就在 ChatPage 外面）。换成「**颜色 == 记录的页面底色**」后，判据与**内容**绑定、与**位置**无关，一次覆盖全部 4 层。⇒ **能用「这东西是什么」判断时，别用「它在哪」判断。** |
