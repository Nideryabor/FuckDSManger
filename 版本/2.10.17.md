## 一、这份截图给出的两个事实

1. ✅ **v2.10.16 生效**（横幅 `【诊断 v2.10.16】`）⇒ 安装/强停流程没问题
2. ❗ **`buildMut` 连"进入"都没记录** —— 而它紧跟在 `report()` 之后被调用（同一条语句流）
   ⇒ **要么没被调用、要么在第一条指令就出事**（我上一版怀疑的 `String.valueOf + concat` 正好符合这个特征）

## 二、本版改动（只为定位，不改行为）

| 改动 | 目的 |
|---|---|
| 原 `buildMut` **改名 `buildMut2`** | 让出名字给包装层 |
| 新增 `buildMut` **包装层**：`try { buildMut2() } catch (Throwable) { note + logE }` | 内部抛异常不再静默：**界面+日志双留痕** |
| `buildMut2` 入口加 **`logOnce` 日志** `[建议] buildMut2 进入` | 用**日志**（logOnce 不刷屏）确认是否真被调用，绕开界面缓冲机制 |

## 三、三种结果的含义（一步定位）

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| 诊断块出现 `buildMut 内部抛异常` + 日志有堆栈 | 在跑但抛异常 | 按堆栈修那一行 |
| 日志出现 `[建议] buildMut2 进入` | 在跑 ⇒ 是**界面诊断缓冲**的问题 | 改用日志做诊断通道 |
| 两者都没有 | **压根没被调用** | 查 hook 内 `report → buildMut` 的调用链 |
