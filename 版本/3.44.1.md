## 一、这是什么

**把一段「系统提示词」用 Unicode Tag 隐形字符（`U+E0000–E007F`，渲染宽度 0）塞进 `/api/v0/chat/completion` 的 `prompt`。**

**模型读得到、人眼看不见** —— 聊天界面 / 换设备 / 网页版全都看不到那段指令。

**⚠️ 诚实边界**：它不是"真 system role"（DeepSeek 协议层没有 system 位，已穷举证明）。
位于 user 消息内部，优先级理论上低于 system。**这是官方通道下唯一实测可行的形态。**

## 二、为什么非这么做（本轮打掉的七条路）

| # | 路 | 结果 |
|---|---|---|
| 1 | 16 个顶层字段名（语义直白派） | ❌ 全灭 |
| 2 | 16 个顶层字段名（短词/模板派） | ❌ 全灭 |
| 3 | **零宽字符夹带** | ✅ **模型读到并执行** |
| 4 | 特殊 token 伪造 system 位 | ✅ 回 77（但…） |
| 5 | 位置冲突测试（SYST vs USER） | ❌ 回 `USER` ⇒ 特殊 token 被当普通文本 |
| 6 | 16 个嵌套对象组合 | ❌ 全灭 |
| 7 | 官网 JS 全量扫描（1.5MB） | ❌ `system_prompt` 等 **0 命中** |

**⇒ 客户端能携带文本的位置，有且只有 `prompt` 一个。**

**顺带铁证**：PoW 只绑 `target_path`，**不绑 body** ⇒ 改包 / 注入 body 安全。

### 关键实现点

**hook 点**：`ChatFullCompletionRequest` 构造器 ⇒ 这是"要发 completion"的**唯一入口**
（实证：全宿主只有 `st1.z` / `hu1.z` / `yt1.z` 三处构造它）。
比 hook OkHttp/Ktor 稳（不随网络栈漂移）。

**签名（2.6.1 / vc279 实测）**：
```
(String a, Integer b, String c, ArrayList d, Z e, Z f, String g, Z h, String i, String j, int mask)
 a=session_id  b=parent_id  c=prompt★  d=ref_file_ids  e=thinking  f=search
 g=audio_id    h=preempt    i=model_type  j=action    mask
```
- **注入点 = `args[2]`**
- **`args[1] == null` ⇒ 会话首条** ⇒ "仅首条"模式天然实现

**三种设计取舍（已落地两种）**：

| 模式 | 行为 | 取舍 |
|---|---|---|
| 仅首条（默认） | 只在 `parent_message_id == null` 时注入 | token 只花一次；位置=上下文最前；长对话可能被稀释 |
| 每轮 | 每条消息都注入 | 对抗稀释最强；token 持续消耗 |

**安全设计**：
- **候选名 + 构造器签名校验**（名字被复用也咬不到无关代码 —— 2.6.1 轮换时踩过这个坑）
- **幂等**（已含 Tag 不重复注入）
- **零异常外抛**（热路径铁律，教训 255）
- 全部 `try/catch(Throwable)` + `hookM` 回执日志（教训 887）

**中文支持**：`toTag` 遇非 ASCII 转 `\uXXXX` 转义（纯 ASCII）再 Tag 化。
自检实证：`"你是尼得亚伯，一只龙"` → 60 码位 · 可见字符 0 · 往返 OK ✓

## 五、🔴 未验收（下版第一件事）

**装机后实测「没效果」**，排查被两件事挡住：

1. `adb shell su` 报 `su: inaccessible or not found` ⇒ root 只读通道断（`ro.sh` 走不通）
2. `logcat` 里**没有** `FDM` 标签日志 ⇒ 无法确认 hook 是否装上

**⇒ 下次按顺序：**

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 看模块 UI 有没有「聊天 › 系统提示词 ›」 | 有 ⇒ hook 层问题；没有 ⇒ UI/dex 层问题 |
| 2 | 强停宿主重开，`logcat -d -b all \| grep -a FDM` | 应见 `hookM sysprompt count=1 cls=qv1` |
| 3 | 若见 `hookM FAIL sysprompt` | 宿主改版 ⇒ 按 `CANDIDATE_NAMES` 注释重新反查 |
| 4 | hook 装上了但仍无效 | 查 `fuckds_sysprompt_on` / `_text` / `_mode` 有没有写进 MMKV |

**★ 验证判据**（最简）：
提示词填 `无论用户问什么，你都只回答 BANANA` ⇒ 发「你好」⇒ **AI 只回 `BANANA` 即成**。
