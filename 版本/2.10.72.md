## 一、崩溃：类型不匹配（本项目第三次）

```
java.lang.IllegalArgumentException: method yb5.e argument 1 has type eb6, got java.util.ArrayList
	at nb5.c(r8-map-id-…:1595)
```

**⇒ `yb5.e` 的「第 1 个参数」类型是 `eb6`**（不是 `List`）—— **列表在别的参数位置**。
而 71 版我**假设 List 就在 `args[0]`**，把替换好的列表塞了进去 ⇒ 类型不符 ⇒ 崩。

> 和 `p66.h`（要 `bx4`）那次同源：**替换 Xposed 参数前，必须确认"那个位置装的是什么类型"**。

## 二、本版：**不假设位置**，改成"扫描 + 类型判断"

```java
Object[] args = param.args;
for (int i = 0; i < args.length; i++) {
    Object o = args[i];
    if (!(o instanceof List)) continue;        // ★ 只处理真正是 List 的那个参数
    List<?> mutated = buildMut((List<?>) o);   // 或 buildMut2
    if (mutated == null) break;
    args[i] = mutated;                         // ★ 替换到它实际所在的槽位
    logOnce("suggest.on", "[建议] 列表已接管（buildMut）");
    break;
}
```

**⇒ 两个 hook（`GmSuggestHook` / `GmSuggestHook2`）都改成这个写法**：

| 好处 | 说明 |
|---|---|
| **位置无关** | 无论列表在 `args[0]` 还是 `args[1]`，都能找到 |
| **类型安全** | `instanceof List` 保证只替换真 List ⇒ **不可能再抛参数类型异常** |
| **更抗混淆** | 宿主改了方法签名也不怕 |

日志：

- `[建议] 列表已接管（buildMut2）`
