## 一、先排除"字段来源"问题

在宿主里搜 `prompt_feature`，全 APK **只有 1 处**：

```smali
# Lw46;（ModelConfig 的序列化器）
const-string v0, "prompt_feature"
invoke-virtual {v1, v0, v3}, Lm47;->j(Ljava/lang/String;Z)V
```

**⇒ 它只是 `ModelConfig` 的一个字段，没有独立的下发键** ⇒ 数据源确实是我们已经保护的那份 `kv_remote_settings_model_configs_v1` ✓

## 二、真凶：`reapply` 是"老线废码"，从没碰过宿主

`GmSync.reapplyAll()`（每次 onResume / 服务器下发后都会跑）：

```smali
invoke-static {v0}, …GmPrompt;->reapply(Landroid/content/Context;)Z   ← 位置对！但它…
invoke-static {v0}, …GmModel;->reapply(Landroid/content/Context;)Z
```

而 `GmPrompt.reapply` 的老实现：

```java
String v2 = read2(c, MK, "s");        // 读【模块侧快照】
String v3 = patch(v2, v0);
GmStore.bak(c, MK, "s");
GmStore.write(c, MK, v3, "s");        // 写回【模块侧快照】← 宿主完全没被碰！
```

**⇒ 所以"持续保住"这一环一直是空的** —— 和 `GmModel` 当初一模一样的病（只改快照）。

## 三、本版：把它改成直写宿主（跟 `GmModel` 同等待遇）

```java
String user = get(c);                  // 用户在编辑器里保存的那份（模块侧 KEY）
if (!ok(user)) return false;           // 没编辑过 ⇒ 不打扰
String src = host();                   // ★ 宿主真值（decodeString 本体）
if (!ok(src)) return false;
String out = patch(src, user);         // ★ JSON 结构化改写（2.10.68）
if (out.equals(src)) return false;     // 已是我们的内容 ⇒ 不写
return hostPut(out);                   // ★ 直写宿主
```

**⇒ 现在每次进 App（onResume）或服务器下发之后，都会把用户编辑的 `prompt_feature` 重新写回宿主** ⇒ 不会再被打回服务器版本。

日志：
- `[prompt] reapply 已把编辑内容写回宿主`
- `[prompt] reapply 跳过：宿主已是最新`
