# FuckDSManger 2.10.19（回复建议 · 🎯 真凶：`buildMut` 第一行的空判断写反 ⇒ 从 2.10.1 起全程空转）

> 产物：`FuckDSManger_2.10.19_for_ds2.5.2.apk`（**170 / 2.10.19**，90 类，V1+V2+V3，sha256(partial) `f6f21804…`）
> 触发：主人更正截图内容为 **`最后: f 命中（首次）`**（不是 e）

## 一、证据链闭合

```
【诊断 v2.10.18】
最后: f 命中（首次）        ← sStat 停在这里，之后再没有任何 note 成功
```

而日志里**有** `[建议] buildMut2 进入`（入口 logOnce）。两者之间只隔着**一条指令**：

```smali
    invoke-static {…logOnce…}V      ← 执行了 ✓
    if-nez p0, :ret                 ← ★ 真凶
    invoke-interface {p0}, size()I
    …
    note("进入 buildMut 宿主=N")     ← 从没执行 ✗
```

### 语义

| 助记符 | 真实含义 |
|---|---|
| `if-eqz` | **等于零（null）**时跳转 |
| `if-nez` | **不等于零（非空）**时跳转 |

我写的是「**列表为空才返回**」，实际是「**列表非空就返回**」
⇒ **`buildMut` 每一次调用都在第一行返回 null** ⇒ 从 2.10.1 起**全部六七十版都在空转**。

## 二、这一个字节解释了此前所有怪现象

| 现象 | 解释 |
|---|---|
| 没有 `宿主原型 g56(…)` 日志 | 它在该判断**之后** |
| 三道守卫（noctx/sw/pass）无任何输出 | 同样在之后 |
| 界面诊断块只有 `e/f 命中（首次）` | `note()` 再没被调用过 |
| chip 永远是宿主自己的 4 个空壳 | 列表从未被替换 |
| 2.10.14 的 `进入 buildMut 宿主=N` 从不出现 | 同上 |
| 「钩子在但代码没跑」 | **代码进去了，但第一行就出门了** |

## 三、修法（一个助记符）

```smali
-    if-nez p0, :ret
+    if-eqz p0, :ret
```

顺带复查了同类写法：`if-nez v1, :ctx2` / `:ctx3` / `:on2` / `:hat2` 等
都是「**非空/为真 → 继续**」的正确用法（目标不是 return 标签），**只有这一处写反**。

## 五、教训（这次要刻深一点）

| # | 教训 |
|---|---|
| 191 | ⭐⭐⭐ **「空则返回」必须用 `if-eqz`** —— 写成 `if-nez` 就是「非空则返回」，**静默空转**。这是本项目第 **4** 次踩同类（前三次在 `GmGateHook`/`GmGateListHook`/`GmPromptTextHook` 上修过），说明审计必须**覆盖到每一个 early-return**，不能只修发现的那几个 |
| 192 | ⭐⭐ **「入口标记 + 状态行」是抓这类 bug 的终极手段**：入口 logOnce 证明"进去了"，界面 `最后：` 证明"没往下走"，两点一夹，中间那条指令无处可藏 |
| 193 | ⭐ **一行错误可以掩盖五十版努力**：这十几轮修的 VerifyError / 寄存器 / 分支语义都是真问题，但只要这一行还在，所有后续工作都看不到效果 |
