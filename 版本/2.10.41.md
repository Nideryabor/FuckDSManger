# FuckDSManger NL 2.10.41（🎯 找到"旧版能显示"的秘密：**MMKV 读取接管**）

> 产物：`FuckDSManger_NL_2.10.41_for_ds2.5.2.apk`（**192 / NL 2.10.41**，91 类，V1+V2+V3，sha256(partial) `50a7e307…`）
> 触发：主人提示「mcp 文件夹有最新版你咋不打开看」+「2.10.1-probe 宿主能正常显示字段并且能点击」

## 一、打开老包一看：秘密就在一行注册

老包 `FuckDSManger_2.10.1-probe_for_ds2.5.2…apk` 的 `GmSync` 里：

```smali
    findClass("com.tencent.mmkv.MMKV", loader)
    XposedBridge.hookAllMethods(clazz, "q", new GmMmkvHook())     ← ★★ 关键
```

而 `GmMmkvHook`（老的）做的事：

```java
key = args[0] ; val = args[1]
if (key.equals("kv_remote_settings_model_configs_v1")) {
    if (GmPrompt.ok(我们的配置))
        val = GmPrompt.patch(val, 我们的配置);      // 把我们的 prompt_feature 打进去
    args[1] = val;                                  // ★ 宿主【读到】的就是我们的配置
}
```

⇒ **宿主用自己的正常流程（`p66.f()` → `w46` serializer）解析并渲染 chip** ⇒ 文字与点击全部正常 ✓✓✓
⇒ 这解释了：为什么老版"能显示"；也解释了为什么我们在 `yb5.f` 里塞列表**字段全对却不显示** —— **太晚了**，宿主的对象早就从配置建好了 ✗

## 二、我们新线的差异：**类在，但没注册**

| | 老线 | 我们新线 |
|---|---|---|
| `GmMmkvHook` 类 | ✓（有） | ✓ **也有**（哈希一模一样） |
| `MMKV.q` 注册 | ✓ | ✗ **没有注册**（宿主 hook 列表里没有它） |

## 三、本版改动

1. 在 `DisableFlagSecure` 里补上注册：`hookM("com.tencent.mmkv.MMKV", "q", "…GmMmkvHook")`
2. （保留）原有 yb5/pd5 等接管作为兜底
