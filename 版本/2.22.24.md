## 0. 主人回执与一句话结论

**回执**：
> 「我注意到我们的模块是固定长度的，所以一些功能被压到下面点不了了」

**结论**：**不是「写死了长度」，是「缺滚动容器」**。

我们每个自绘弹窗的收尾都是这三行（12 个弹窗里 7 个如此）：

```smali
sget-object v2, ...->sDlg:Landroid/app/Dialog;
invoke-virtual {v2, v1}, Landroid/app/Dialog;->setContentView(Landroid/view/View;)V   # v1 = 竖 LinearLayout
# 然后 getWindow().setLayout(-1, -2)  ← 宽 MATCH_PARENT、高 WRAP_CONTENT
```

- 窗口高 `WRAP_CONTENT` **不等于**「无限高」：它被测量时拿到的规格是 `AT_MOST(可用屏高)`
  ⇒ 内容比屏幕高时，`LinearLayout` 自己会被**截到屏高**，多出来的行**布局在窗口之外** ⇒ **画不出来、也点不到**。
- 而 `LinearLayout` **本身不会滚动**（不是 `ScrollView`）。

⇒ 于是「2.22.0 给美化页加了色盘 / 圆角 / 图片底三行」之后，**美化页总高越过屏幕**，
底部那几行（含「关闭」）就落到了窗口外面 —— 完全对得上回执。

## 2. 改动清单（一个 helper + 7 行）

| # | 位置 | 改动 |
|---|---|---|
| 1 | **新方法 `GmUtil.sc(Landroid/app/Dialog;Landroid/view/View;)V`** | `.registers 4`（v0=`ScrollView`、v1=`Context`）：拿内容 `getContext()` 造 `ScrollView` → `setFillViewport(true)` → `addView(内容)` → `dlg.setContentView(ScrollView)`。插在 `logOnce` 与 `sub` 之间（本类方法按字母序排） |
| 2 | `GmBeautyDialog` · `GmMenuDialog` · `GmBgDialog` · `GmChatDialog` · `GmEnvDialog` · `GmSuggestDialog` · `GmCallDialog` | 各 **1 行**：`invoke-virtual {v2, v1}, Landroid/app/Dialog;->setContentView(...)V` → **`invoke-static {v2, v1}, .../GmUtil;->sc(...)V`** |
| 3 | manifest | `versionCode 354→355`、`versionName 2.22.23→2.22.24` |
| 4 | `GmBubbleCellHook` 自检串 | `模块 NL 2.22.23 生效` → **`模块 NL 2.22.24 生效`** |

**为什么这样改最小**：
- 两条指令都是 `35c`、都只用 `{v2, v1}` 两个寄存器 ⇒ **不动任何方法的 `.registers`**（本项目最容易踩的坑之一）。
- `ScrollView` 作为**对话框内容视图**时，会被 `FrameLayout` 用 `MATCH_PARENT` 生成布局参数、
  进而用 **`AT_MOST(可用屏高)`** 测量；而 `ScrollView.measureChild` 给子视图的**高度规格是 `UNSPECIFIED`**
  ⇒ 内容按**真实总高**测量，`ScrollView` 自己再夹到屏高 ⇒ **可滚** ✓。
- **短内容外观不变**：`ScrollView` 高 = `min(内容, 屏高)` ⇒ 内容装得下时窗口高度与改前逐像素相同。

## 3. 取舍与副作用（写清楚，免得下一版当成 bug）

1. **「关闭」按钮现在跟着内容滚**（原来是页尾固定）。已交付的 5 页是「列表滚、按钮固定」；
   本次为「零寄存器改动」选择了「整页滚」。若主人想要按钮钉底，需按那 5 页的写法给每页加
   `MATCH_PARENT × 0 + weight 1` 的 `ScrollView`（改动大得多，可另开一版）。
2. **`GmCallDialog`（全屏黑底）**：它的窗口是 `MATCH_PARENT × MATCH_PARENT`，
   整页进 `ScrollView` 后内容（根 `LinearLayout`，`gravity=center`）会按内容高测量
   ⇒ 黑底只包内容、四周露宿主。为此 helper 里加了 **`setFillViewport(true)`**：
   视口比内容高时把内容**撑到视口高** ⇒ 全屏黑底 + 内容居中不变 ✓（其余页面不触发这条）。
3. **竖向滑动会先被 `ScrollView` 吃掉**（正常）：色盘那支 `HorizontalScrollView` 与竖滑互不干扰（系统自己做方向消歧）。
4. 美化页那支 `HorizontalScrollView` 嵌在竖 `ScrollView` 里，是标准嵌套，不需要额外处理。

## 6. 教训（756 ~ 761）

| # | 教训 |
|---|---|
| **756** | ⭐⭐⭐ **「固定长度」不是写死的长度，是「没有滚动容器 + 窗口高被屏高夹住」**：`WRAP_CONTENT` 的窗口在测量时拿的是 `AT_MOST(可用屏高)`，`LinearLayout` 自己**不会滚** ⇒ 多出来的子视图**被裁在窗外**（既不可见也不可点）。诊断时先问一句「这页有竖向 `ScrollView` 吗」。 |
| **757** | ⭐⭐⭐ **「同类页面里已经有好使的」= 抄它的机制**：本项目 5 个老弹窗早就有滚动（`ScrollView + MATCH_PARENT×0 + weight 1`），这次只是**把同一个机制统一补到其余 7 个**（本专题最贵的一课 709/742 的又一次落地）。 |
| **758** | ⭐⭐ **改布局优先挑「不碰寄存器」的形状**：`invoke-virtual` → `invoke-static`，参数个数一致 ⇒ 一行替换、零 `.registers` 改动、零新类（`119 类` 不变）。手写 smali 里「少改一个寄存器」＝「少一次 `VerifyError` 的机会」。 |
| **759** | ⭐⭐ **「整页滚」vs「列表滚+按钮钉底」要在交付时说明**：前者零成本但按钮会跟着滚，后者好看但每页要加一支带 weight 的 `ScrollView`；**别让主人下次把它当 bug 报**。 |
| **760** | ⭐⭐ **`setFillViewport(true)` 是「整页进 ScrollView」的必备补丁**：内容比视口矮时把内容撑满视口 —— 否则全屏页（`GmCallDialog`）的黑底只包内容、`gravity=center` 也会失效。 |
| **761** | ⭐ **回读产物要连「没动的部分」一起核**：本次特意确认 5 个老页**仍是**直调 `Dialog.setContentView`（只有 7 处被替换），避免「改动范围比以为的大」。 |
