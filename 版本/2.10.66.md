## 一、日志终于指出真正的拦路虎

```
[ds] 移除 model_configs 抛异常（忽略）      ← ★ 就是它
```

**⇒ 那个下发 `Map` 是「不可变实现」**（`Map.remove` 直接抛 `UnsupportedOperationException`）⇒ 我的 catchall 拦下了、没崩、但也**没改到**。

> 换句话：**不是"没执行"，而是"执行了但对象不允许改"** —— 比 64 版那次进了一大步。

---

## 二、本版思路：**不改它，改"引用"**

```java
Map orig = (Map) args[0];
if (orig.containsKey("model_configs")) {
    Map copy = new HashMap(orig);        // ① 复制成可写的
    copy.remove("model_configs");        // ② 在副本上摘掉
    args[0] = copy;                      // ③ 替换整个参数（原对象原地不动）
}
```

- **不触碰不可变对象** ⇒ 不会抛异常
- 宿主拿到的就是**没有 `model_configs` 的那份** ⇒ 不再覆盖模型列表 ⇒ 保住我们写在 MMKV 里的 `true`
- 整段 try/catch，失败只记 `[ds] 替换下发 Map 抛异常（忽略）`

**另外**：`[ds2]`（`GmSyncHook` 的 `uv1.u`/`az5.h`）日志**始终没出现** ⇒ 那两个应用点在当前宿主版本里**没被调用**（宿主换了下发路径）⇒ 主战场确实在 `p66.h` 这一侧。

## 四、这套思路可以复用（主人提到的"文件快捷功能"）

| 手法 | 适用场景 |
|---|---|
| **可写副本 + 替换参数** | 宿主传入不可变的 Map/List/JsonElement，而我们要"去掉/改掉其中一项" |
| **同形替换（保持类型）** | 宿主会按类型校验时（如必须仍是 `bx4`/`Lev4`） |
| **源头摘除 vs 事后修正** | 能摘就摘（`null` 分支通常宿主自己就有），摘不动才考虑构造同类型对象 |
