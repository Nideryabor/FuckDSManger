## 一、`cls=hp8` ⇒ 对象抓对了

宿主侧反查 `Lhp8;`：

```
.class public final Lhp8;
.implements [Landroid/os/Parcelable;, Lws8;, Ljava/util/List;, Ljava/util/RandomAccess;, Lf25;]
.toString() → "SnapshotStateList(value=…)"
```

⇒ **它就是 `SnapshotStateList`**（Compose 的可变状态列表），**实现了 `java.util.List`** ⇒ `size()`/`get(int)` 反射畅通。

## 二、元素类型也确认了：**就是 `vq`**

`h91.a` 里读这个列表的原始代码：

```smali
invoke-virtual {v10}, Lhp8;->size()I
invoke-virtual {v10, v13}, Lhp8;->get(I)Ljava/lang/Object;
check-cast v2, Lvq;                          ← 元素 = vq（消息）
new-instance v3, Le91;
invoke-direct {v3, v2}, Le91;-><init>(Lvq;)V ← e91 只是渲染时临时包装
```

⇒ `one()` 里反射调 `vq.l()` 的思路**没有错**。

## 三、那剩下的唯一可能：**列表是空的 / 取不到文本**

⇒ 本版加一个 `nOf()` 探针（反射读 `size()`，失败返回 `-1`），并把结果并进 Toast：

```
AI 已捕获列表但取文本失败；cls=hp8  n=12
                                      ↑ 这个数字是决定性的
```

**判读表**：

| `n` | 结论 | 下一步 |
|---|---|---|
| `n > 0` | 列表有内容，卡在 `vq.l()` 取文本 | 读 `vq.l()`/`vq.t()`/`vq.k()` 的实现，改用正确入口（或直接取字段） |
| `n = 0` | 我们缓存的这个列表**是空的** | 换数据源：改用 `ao1.M()` 拿的 `wr` 实例（现取），或 hook 列表更新点 |
| `n = -1` | `size()` 反射失败 | 异常原因另查 |

## 五、教训

| # | 教训 |
|---|---|
| **401** | ⭐⭐⭐ **"抓到对象"≠"抓到数据"** —— `cls=hp8` 证明类型对了，但**内容的"量"没被验证**。**诊断要报"量"（size/length/count），不能只报"类型"** |
| **402** | ⭐⭐ **`insert_before_match` 的 `writeText` 绝不能包含锚点本身**（我又犯了一次 ⇒ `missing END_METHOD_DIRECTIVE` 编译失败）。**锚点是"位置"，不是"内容模板"**（与 2.10.75 的教训 363 同源，已第二次） |
| **403** | ⭐⭐ **反查"宿主自己怎么用这个数据"是最快的类型判定法**：`check-cast v2, Lvq;` 一行就定死了元素类型，比猜名字可靠一万倍 |
