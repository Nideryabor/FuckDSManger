## 三、画布是怎么拿到的（最硬的一关）

**结论：Compose 的画布类是 `Lk59;`（`AndroidCanvas`），它同时有**

```
.field public a:Landroid/graphics/Canvas;
.method public final a()Landroid/graphics/Canvas;
```

它**每帧当参数传进 DrawScope**（`Lda5;->c(Lvv0;JLuh6;Lr23;Ln24;)V` 里那个 `Luh6;`），
所以从 DrawScope 的对象图上**爬不到**。

**做法**：在 DrawScope 实现类（`Lda5`）上挂 15 条「画布截获」钩子 ——
任何方法的**任何一个实参**里带原生画布，就记进 `ThreadLocal`。
Compose 绘制是单线程一帧一帧跑的 ⇒ ThreadLocal 天然对齐。

```
【GmGlass】画布截获钩子 15 条（da5）
【GmGlass】画布截获 ✓ 来自 tb @ c
【GmGlass】换掉绘制 #1
```

## 四、「这是按钮」怎么认（组合期 → 绘制期的记号接力）

作用域计数（`sDepth`）只在**组合期**有效，绘制期早归零了。所以要**把记号带过去**：

```
组合期：uia.v 被调用 且 sDepth>0
          ⇒ 把刚造出来的那个「元素对象」记进 sBtnElements（WeakHashMap）

attach 期：se0.create() 返回 Node
          ⇒ 元素带着记号 ⇒ 把 Node 记进 sBtnNodes

绘制期：te0.draw(DrawScope) 被调用
          ⇒ sBtnNodes.contains(thisObject) ⇒ 这才是按钮 ⇒ 画玻璃
```

日志铁证：`【GmGlass】按钮 Node 记号已建立（te0）`

## 五、玻璃长什么样

```
① 糊过的窗口像素（PixelCopy 抄 surface → 1/4 降采样 → GmGlassBlur）
② 浓度蒙层（白/黑，按深色主题切）
```

# 3.30.1 —— 修「不透 / 不 Q 弹 / 所有元素是死样」

> 主人原话：「**为什么选择所有元素就成了这死样，而且不透不 q 弹**」
> 三条全是我的锅，逐条认。

## ① 「所有元素」为什么是死样（架构性原因，不是调参）

```
GmGlassScope 的计数（sDepth）发生在【组合期】
draw 回调发生在【绘制期】     ← 到这儿 sDepth 早归零了
```

⇒ 绘制期**根本没有「这是不是按钮」的判据**。3.29.x 硬开「全部」，等于
**把每一个背景都换成玻璃**（卡片 / 列表条目 / 分隔 / 面板 / 气泡全中招）⇒ 界面被抹平。

**3.30.1 的解法不是"让全部能用"，而是把更多可点控件认成按钮**（同一套 source-info 定位法）：

| 新增锚点 | 控件 |
|---|---|
| `Li52;->e` | **AppSelectableChip**（可选芯片 ——「深度思考 / 专家模式」这一族） |
| `Lyb5;->c` / `d` | PromptFeatureChip / PromptFeatureSkeletonChip |
| `La18;->q` | InputModeToggleButton（输入模式开关） |
| `Lzl9;->H` / `Z` | ChatInputToggleableToolView / ToggleLottieIcon |

同时**放宽 composable 识别**：原来卡「≥8 个参数」，把 6 参的 AppSelectableChip 漏了；
改成「**结尾是 int + 中间夹着接口（Composer）**，参数 ≥4」。

## ② 「不透」的真因

```java
sBitmapPaint.setAlpha(255);   // ← 3.29.x：把糊过的底图【不透明】糊上去
```

那不叫玻璃，**那叫贴纸**。再加宿主深色主题 + 黑蒙层 ⇒ 越叠越黑。

**改成**（`GmGlassSink.Painter`）：

```
浓度 0   ⇒ 完全透（只剩高光边，一眼还看得出是玻璃）
浓度 100 ⇒ 完全不透
底图 alpha = 浓度×2.55
蒙层 alpha = 浓度×2.55×0.55     ← 再薄一档，别糊成一块
```

## ③ 「不 Q 弹」的真因

**我压根没写动画**。参照物的 `Spring` 我只抄了笔记没抄代码。

**新增 `GmGlassSpring`**（阻尼谐振子，数值积分）：

```
a = 900·(target − x) − 26·v        // k=900 硬、c=26 只过冲一次
按下 target=0.94，松手 target=1.0
```

驱动链：

```
hook Activity.dispatchTouchEvent   ← 框架类，名字永不变
   按下 ⇒ onDown() / 松手 ⇒ onUp()
   同时 Choreographer.postFrameCallback 逐帧 decorView.postInvalidateOnAnimation()
        （最多 1.2 秒，或者弹簧停了就收）
```

⚠️ **不加逐帧 invalidate 的话，弹簧算得再对也不会动** —— Compose 不知道我们在动。

# 3.30.3 ~ 3.30.5 —— 修「文字/图标消失」+「模糊度没区别」

主人两条反馈，都是硬伤：

## ① 按钮里的文字/矢量图没了（**最严重**）

**真因**：Compose 的 `Modifier.Node` 体系里，`DrawModifierNode.draw()` 的语义是
「**我画完要自己调 `drawContent()`**」。我整个方法替换掉了却没调 ⇒
**按钮的内容（文字/图标）从绘制链上被直接摘掉**。

**修法**：玻璃画完之后，把 `drawContent()` 接回去。
宿主实测那是 `Lda5;->a()V`（判据：本类声明的、0 参、void、非 static —— `Lda5` 上正好只有一个）。

```
【GmGlass】drawContent 已接回：da5.a()
```

⇒ 顺序必须是 **玻璃 → drawContent**（反过来玻璃会盖住内容）。

## ② 模糊度怎么调都没区别

**真因**：底图一直是 null。

```
❌ 【GmGlass】底图截取失败：java.lang.IllegalArgumentException: Window doesn't have a backing surface!
```

`PixelCopy.request(Window, …)` 在真机上直接抛；而且 **PixelCopy 根本没有 `View` 重载**
（只有 Window / SurfaceView / Surface）。

**修法**：改用**把视图树重画进一张缩小的位图**（就是参照物 `LiquidGlassPanel` 的做法）——
不需要 surface，纯 CPU。并且：

- **必须 `post` 出去**执行，不能在 Compose 的绘制回调里同步重画（重入 / 死循环）；
- 加**防自反馈**开关 `capturing()`：抓图期间 `GmGlassSink` 跳过玻璃绘制
  ⇒ 抄到的永远是「没有玻璃的原始画面」。

```
【GmGlass】底图 OK 360x792 · 模糊半径=1
```

## ③ 「深色主题下看不见」—— 3.30.2 已修，这里补记

`isNight() ? 黑 : 白` ⇒ 深色主题下是**黑玻璃叠黑底**，肉眼「和没画一样」（真机差分 Δ=1.8）。
改成**永远用白**（真实世界的暗色玻璃是"比背景亮一点 + 亮边"），并加了：
斜向高光 / 双层亮边 / 水滴柔光。

## ④ 别的

- `换掉绘制 #1` 那条日志原来用了 `logOnce`（按 tag 去重）⇒ **永远只打第一条**，
  让人误以为"只画了一次"。改成 1 / 50 / 200 / 1000 / 每 2000 打一条。
- `onResume` 现在带统计：`已钩类=3 按钮元素=0 按钮Node=20 绘制次数=0`
  ⇒ 以后「有没有在画」一眼可判。

| 现象 | 真因 | 修法 |
|---|---|---|

| 部分元素 `原点=(-1112,79)` 被跳过 | 我用 `ox>=0` 当守卫，而滚动容器的变换可能是负的 | **待修**：改成允许负值（shader 的 CLAMP 会兜住） |

# 3.31.7 —— 「机制全通了，但看不出」的根因（**重要**）

主人反馈：「**没区别，改浓度还是只改透明度**」。查证后确认**不是 bug，是方案的固有问题**。

## 证据链

| 项 | 状态 |
|---|---|
| AGSL 折射 shader | ✅ 执行了（`折射已生效（1141x102）`） |
| 底图（PixelCopy） | ✅ 有 |
| 按钮上玻璃 | ✅ 尺寸清单里确实有 `112x112` / `154x154` / `416x171` 这些**小控件** |
| **观感** | ❌ 关/开逐像素 Δ 只有 **±1.5**，最大变化块还是 `1244x326` 这种大块 |

## 为什么看不出（三个叠加）

1. **玻璃主体 = 把同一块背景糊一遍贴回去**
   宿主大片是**纯色** ⇒ 糊完还是纯色 ⇒ **零变化**。
2. **折射只对"有纹理的内容"可见** —— 纯色区没有可"掰弯"的东西。
3. **模糊半径其实小得可怜**：`blur/SCALE = 6/4 ≈ 1px`（1/4 缩略图上）—— 这么点糊根本看不出来。
   （把它拉到 40 也只有 ~10px，仍然不够在纯色区产生可见差异。）

## 根本矛盾

> **深色 + 大面积纯色** 的界面，正好是液态玻璃**最不显效果**的场景。
> 苹果那种惊艳感来自「**有内容的背景从玻璃下面滑过**」——
> 参照物选**微信底栏**也是同一个道理（消息列表从底栏下面滚动）。

## 三条出路（待主人拍板）

| | 做法 | 代价 |
|---|---|---|
| **A** | 把玻璃放到**有内容经过的地方**（顶栏 / 输入栏 / 列表项），内容滑过时模糊才看得见 | 要重新挑目标，不是"所有按钮" |
| **B** | 加强**乳白蒙层 + 高光边** | 会向"刷白"滑（3.30.x 踩过） |
| **C** | 接受"微妙质感"—— 深色纯色界面上玻璃本来就该是微妙的 | 主人可能仍觉得"没区别" |

## ② 抓取作用域修正（主人：「会抓取页面全部部分…导致会出现文字」）

**真因**：取坐标的三条路里，`matrixFromFields`（在对象图里瞎找 `float[16]`）
可能摸到**任意一个矩阵**（颜色矩阵 / shader 矩阵…）⇒ 采到页面别的区域 ⇒ **把别处的文字抓进玻璃里**。

**修法（宁可不涂，也不涂错）**：
1. 坐标**只认画布矩阵**，且必须是**纯平移**（缩放/斜切不为 1/0 就拒绝）；
2. 采样区**越界就跳过**（元素必须完整落在窗口内）；
3. `matrixFromFields` 那条路**彻底弃用**。

## ③ 这轮修掉的另外两个真 bug

| 现象 | 真因 |
|---|---|
| **每个玻璃元素渲染出同一块内容**（主人：「把对话内所有的东西全部渲染出来了」） | 硬件画布上 `drawRenderNode` 是**延迟绘制**；我复用了同一个 `RenderNode` 并在同帧反复改写 ⇒ 所有引用指向同一块被改烂的内容。**⇒ 每次新建 node**，shader 按参数缓存 |
| 底图**永久抓不到** | `PixelCopy` 回调可能不回来，而 `sBusy=false` 写在回调里 ⇒ 一卡就永久拒掉所有请求。**⇒ 加 2.5s 看门狗** |

**宿主不在前台时它的窗口没有 surface**，PixelCopy 必然失败 ⇒ 那段时间没有底图 ⇒ 玻璃退化。
正常使用（宿主在前台）不影响。

# 3.34.1 —— 「擦掉内容」（只让背景色参与折射）

主人：「**效果很好**，但是还是会抓到别的文字……实在不行加个开关，
打开只把特定颜色做折射背景」

## 根因

底图是 **PixelCopy 截的整屏** —— **连文字一起截进去了**。
玻璃盖在卡片/气泡上时，采样的正是"那块卡片 + 上面的字"
⇒ 糊出来带字 ⇒ 和上层清晰的字**叠影**。

## 做法（比"手选颜色"更省事：**全自动**）

1. **Java 侧从元素边缘估背景色** —— 元素四条边基本是纯背景（字都在中间），
   采 8 个内缩 6% 的点取平均 ⇒ 得到"这块东西的底色"；
2. **shader 侧 gate**：离背景色超过容差的像素（= 文字/图标）**替换成背景色**。

前奏由 `tools/gen_glass_shaders.py` **注入到全部三套方案**，
并把正文里的 `content.eval(` 全部换成 `fdmSample(`（不手抄）。

## 新增键

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `fuckds_glass_clean` | b | false | 擦掉内容（只留背景色） |
| `fuckds_glass_clean_tol` | i | 12 | 擦除容差 ×0.01（0~60） |
