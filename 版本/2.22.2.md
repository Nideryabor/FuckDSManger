## 二、关键突破：`tn0` —— 任意 Android Shader → Compose Brush 的包装器

扫 `sn0`(Brush) 的 5 个实现得到：

| 类 | 真身 |
|---|---|
| `c73` / `ch5` | `LinearGradient`（要 `List<Color>` ⇒ 就是 2.21.9 那个 `q32` 装箱坑） |
| `s09` | `SweepGradient` |
| `up8` | `SolidColor` |
| **`tn0`** | ⭐⭐ **`public <init>(Landroid/graphics/Shader;)V`**，字段就是 `android.graphics.Shader` ⇒ **「任意 Android Shader」的 Compose Brush 包装器** |

⇒ **图片底整条链 = 标准 Android + 1 个宿主类，完全绕开 `ImageBitmap`/颜色装箱**：

```
BitmapFactory.decodeFile(filesDir/fuckds_bubble.png)
  → new BitmapShader(bmp, CLAMP, CLAMP)
  → new tn0(shader)                    # 反射，公开构造器
  → uia.u(modifier, brush, shape, 0)   # 早就探好的「brush 版 background」
```

## 六、教训

| # | 要点 |
|---|---|
| **683** | ⭐⭐⭐ **引擎里往往有个「逃生舱」类，能让宿主类型与平台类型互通**：`tn0(android.graphics.Shader)` 一下子省掉了 `ImageBitmap` / `Color` 装箱 / 解码链三层麻烦。**遇到「宿主专用类型」先找有没有「包装任意平台对象」的类**（名字通常毫无线索，靠扫「构造器参数类型」找）。 |
| **684** | ⭐⭐ **接进别人现成的「多路分发链」要照抄协议**：`pick()`/`takePicking()` 的语义（先武装、取走即清、返回旧值）是从 `GmBg`/`GmAvatar` 抄来的 ⇒ **不要自创语义**，否则链上其它家会被误伤。 |
| **685** | ⭐⭐ **能「顺手达成」的开关就别再加控件**：点色块 = 回到颜色底（在 `setImg(false)` 里），省掉一个按钮/监听类；**复用既有交互路径**比新增控件便宜且不易错。 |
| **686** | ⭐ **拷文件用「流拷贝」而不是「解码再编码」**：省掉 `BitmapFactory`/`compress` 一整串，也更稳（不挑格式、不失真）。 |
