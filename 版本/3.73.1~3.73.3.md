## 二、#1 气泡炸了 · 真因与修法

### 2.1 日志原话（`tmp/devlogs/1030_184941/app/files/DSMlogs/dsm.log`）

```
[气泡] 图片版注入失败（B / y 两个锚点都不存在）
[气泡] 注入底板抛异常（不影响宿主）
E java.lang.NoSuchMethodError: x98#z[class y6a, class Long, class ib9]
        at com.nidyaber.fuckdsmanger.gm.GmBubble.wrap(Unknown Source:119)
```

### 2.2 真因：**按名字调宿主的原语**

底座 `GmBubble` 里有 4 处「把 Modifier 变成一块底色」，原来全是 `callStaticMethod(cls, "z"/"B"/"C", {…})`。
名字对上过几次，但 2.7.2 全部错位：

| 原语 | 2.5.2 | 2.6.x | 2.7.1 | **2.7.2** | 旧代码写的 |
|---|---|---|---|---|---|
| 颜色版 `background(M, long, Shape)` | `z` | `D` | `z` | **`x98.t`** | `"z"` ✗ |
| 刷子版 `background(M, Brush, Shape, int)` | `y` | `C` | `B` | **`x98.s`** | `"B"` / `"y"` ✗ |
| `x98.z` 现在是什么 | — | — | — | **`z(View)View`（完全另一个函数）** | — |

⇒ `NoSuchMethodError` 是必然的，而且**每次宿主升级都会再炸一次**。

### 2.3 修法：不再猜名字，按**签名**找

新增 `bridge/GmPrims.java`：

```
判据 = 静态 + 首参类型 == 返回类型（Modifier 链式）+ 第 3 参是 Shape（用现成样本实例判定）
       颜色版 = 3 参（M, long, Shape）
       刷子版 = 4 参（M, Brush, Shape, int）
```

- 扫描范围 = `GmRemap.clsAll("uia")` 的**每一个碎片**（2.7.2 该桶被 R8 拆成
  `x98,qu7,z2c,g83,j37,zi9` 六个，只看第一个会漏）
- 找到就缓存（按 ClassLoader），后续零查找
- 找不到 ⇒ 返回 `null` ⇒ 调用方退回"不注入"，**绝不影响宿主**
- 自检结论进日志：`【GmPrims】背景原语自检：可用 · 桶=… · 颜色=x98.t · 刷子=x98.s`

`GmBubble` 的 4 处调用全部换成 `GmPrims.background / backgroundBrush`，
文件里**再没有一处** `const-string "z"/"B"/"C"`。

### 2.4 顺手补的一道闸（针对那条 `ClassCastException`）

`GmBubblePaintHook` 顶部加：

```smali
方法不是 Method ⇒ 跳过
方法返回值不是接口 ⇒ 跳过        ← Modifier 链式函数全都返回 Modifier（接口）
```

为什么：2.7.2 里同一个短名可能被 R8 挪给 `v(J,w48)V` 这种 void 函数，
对着它 `setResult(Modifier)` 就是往实现里塞错类型
（真机日志里那条 `ClassCastException: k30 cannot be cast to go7` 就是在猜这个）。
现在**不是"Modifier 链式函数"就当场放弃，一个字节都不碰**。

## 三、#6 `yp1` 语音门控：结论是**不该修**

### 3.1 它现在是什么状态

`GmRemap.CLS5` 里：

```java
{"yp1", "yp1", "yp1", null, null},   // 语音门控（GmAsrHook / GmSeeHook）
```

2.6.2 / 2.7.1 / 2.7.2 三列都是 `null` ⇒ `cls()` 返回**必然不存在**的 `com.gm.gone.yp1`
⇒ `findClass` 必抛 ⇒ 那几条 `hookM` **从来没注册过**。这是**设计好的安全失败**。

### 3.2 但它喂的两个 hook 早就停用了

| hook | 现状 |
|---|---|
| `GmAsrHook` | `beforeHookedMethod` **只有一句 `return-void`**（2026-10-02 注释：宿主官方语音通话 TRTC 已接管） |
| `GmSeeHook` | 只把 `yp1.b()` 的**返回值抄进日志**，不改任何东西 |
| `GmCallYpHook` | 配合「音频通话」WIP，同样停用 |

⇒ 就算把 `yp1` 定位出来，也**没有任何功能会因此复活**。

### 3.3 那到底"修"了什么

每次开机日志里都有：

```
hook ctor yp1 (pair) FAIL
hook yp1 ctor FAIL
```

—— 混在真错误里，看着像出了事。改成：

```
语音门控 yp1 未定位（2.6.1 起）⇒ 跳过（预期，不影响其它）
语音门控 yp1 构造器未挂（未定位，预期）      ← logOnce，不再带堆栈
```

**教训 1121：把"设计好的失败"和"真错误"用同一个词（FAIL）说出来，等于给未来的自己挖坑。**

## 五、#7 / #8：这两条**本机做不了**（如实说明）

### 5.1 #7 · ttEncrypt 响应方向

- 请求方向已经**明文突破**（`专题/2026-10-31-ttEncrypt明文突破.md`），够用了
- 响应方向要解 `libEncryptorP.so` 的**输出**，等于逆一个 native 加密实现：
  需要真机 dump `.so` + 一段真实响应对照 + IDA/Ghidra 级别的分析 ——
  **工作区里没有这个 `.so`，也没法跑 frida**（`adb` 现在 `offline`）
- 结论：**留着**，等哪天要抓响应体时再做

### 5.2 #8 · GMS 登录 vs 环境伪装

- 症状是「伪装 `ro.build.fingerprint` / `Build.MODEL` 后，Google 登录可能报 `SERVICE_INVALID`」
- 这条**必须真机 + 真 Google 账号**才能验：改完要清 GMS 缓存、重新走一遍 OAuth
- 静默改任何东西都是**盲改**，比不修更危险（可能让人彻底登不上）
- 结论：**不动**，等主人在真机上配合验

| # | 教训 |
