# FuckDSManger NL 2.17.1（🐛 "按一次就死"的根因：宿主 `s()` 是**目标状态式**接口）

> 产物：`FuckDSManger_NL_2.17.1_for_ds2.5.2.apk`（**294 / NL 2.17.1**，104 类，V1+V2+V3，sha256(partial) `28e21580…`）
> 主人反馈：通话页那个「🎙 按住说话」**点不动**

## 一、读 `xe1.s(Lgz3;String)Z` 的真身（关键）
```java
gz3 cur = this.i.getValue();        // 当前手势状态
if (cur == 目标) return false;       // ⭐ 幂等：状态一样就什么都不做
switch (map[目标.ordinal()]) {
   case 1:                                   // 目标 = "抬起"
       if (cur == ReleaseToCancel) E();      //   已经划走了 ⇒ 取消
       if (cur == Pressed)         J(false); //   ⭐ 正常抬起 ⇒ 提交（停录 + 发送）
   case 2:                                   // 目标 = "按下"
       if (cur == Idle) → 开始录音（权限检查 + 起协程）
}
```

⇒ 我 2.17.0 用的是 **`k()`**（= 直接 `J(...)`，绕过状态机）⇒ **状态停在 `Pressed`**
⇒ 之后每次 `s(Pressed,"")` 都被"幂等"拦下 ⇒ **按一次就再也按不动** ✓ 完全对上主人的现象。

## 二、2.17.1 的修正
| 改动 | 说明 |
|---|---|
| **松手改调 `s(Idle,"")`** | 走宿主自己的"抬起"路径：`Pressed`⇒提交发送 / `ReleaseToCancel`⇒取消 ✓（状态机也跟着回到 Idle，下一次能按） |
| `k()` 降级为兜底 | `s(Idle)` 抛异常时才用 |
| **新增触摸到达日志** | `GmCallPTT.onTouch` 打 `[通话] PTT 按下` / `[通话] PTT 抬起` ⇒ 一眼分清"触摸没到"还是"逻辑没跑" |

## 三、复测
装 → 强停宿主 → 进对话 → 点 🎧 → **按住「🎙 按住说话」** → 说一句 → 松手。期望日志：
```

[通话][录音] AudioRecord.startRecording
```

并且通话页出现 `👤 <你说的话>`；**可以连续按多次**。

若连 `[通话] PTT 按下` 都没有 ⇒ 触摸没到按钮（那就是布局/事件问题，我把 PTT 换到别的元素上）。

## 四、教训
| # | 教训 |
|---|---|
| **561** | ⭐⭐⭐ **调用前先看"这个接口是不是状态式/幂等的"**：`s()` 开头就有 `if (cur == 目标) return`，**绕过它（直接 `J()`）会留下脏状态**，症状表现为"只能用一次"。**凡是 setState 类接口，务必看它的入参语义与幂等守卫。** |
| **562** | ⭐⭐ **UI 手势类能力要"按状态机模仿"**：宿主 UI 是 `Pressed → Idle` 两步，我们就该照做两步；少一步就等着状态卡死。 |
