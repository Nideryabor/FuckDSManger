## 一、3.42.55 为什么没中（诚实复盘）

55 版让行判据 = **"brush 里藏着我亲手 new 的 RuntimeShader"**。没修好 ⇒ 两种可能：
- ⓐ 判据在运行时没命中（宿主可能**复制/包装**过那个 brush ⇒ 指纹对不上）；
- ⓑ 问题**根本不在"绘制接管"这条路上**（另有机制）。
⇒ 盲改不如先**看得见**。

## 二、本版两件事

### ① 规则改硬：**玻璃只接管「纯色底」**
- 判据从"指纹"换成"**结构事实**"：**Node 的 brush 字段非空 ⇒ 让行**。
- smali 实证：元素 `eh0.b:Liq0`（brush）在 update 时被搬进 Node `fh0.p:Liq0`，
  而 `fh0` 的 draw **真的读 `p` 来画**（305/537 两处）。
  ⇒ 只要是刷子底（渐变 / 我们自造的图底 / 宿主任何 brush 背景），玻璃**一律不碰**。
- 纯色底（按钮/芯片走 `qk7.D`）不受影响 ⇒ 玻璃该在的地方照常。

### ② 黑匣子：`<宿主外部目录>/files/fdm_glass_diag.txt`
- **免 root 可读**（adb uid 2000 属于 `ext_data_rw` 组，已实测能读该目录文件）。
- 记录：安装头（画底原语数 / shapeCls / brushCls）· 每次 draw 决策
  （`cls= / brush= / rt= / scope= / form= / => LET-THROUGH`）· 所有 why 原因。
- 上限 900 行 · 首条清空重写 · 缓冲 10 条落盘（不拖慢绘制）。
