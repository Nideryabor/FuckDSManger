## 0. 两个现象是**同一个原因**

| 现象 | 含义 |
|---|---|
| 日志里**没有 `[交互排除] 学到 …`** | **学习没跑** |
| **按钮点了也不会变回去** | 没有学习 ⇒ 排除名单是空的 ⇒ 按钮照样被透明化 ⇒ 看起来"没变" |

**⇒ 不是"判据不对"，是"链路没跑"。**
⇒ 此时**不该改参数**，而该**在链路的关键节点上放"一次性痕迹"**（教训 223）。

## 1. 三个可能断点，一次全照亮

| # | 断点 | 诊断行（`logOnce`，只报一次） |
|---|---|---|
| ① | **`dispatchTouchEvent` 钩子到底有没有被调用** | `[触摸钩子] dispatchTouchEvent 钩子已被调用（说明触摸钩子生效）` |
| ② | **`args[0]` 是不是 `MotionEvent`、`ACTION_DOWN` 有没有到** | `[触摸] DOWN 收到 ACTION_DOWN（开窗）` |
| ③ | **采集链路的 `collect()` 有没有在跑** | `[采集] collect() 已被调用（采集链路活着）` |

**改动**：

| 位置 | 改动 |
|---|---|
| `GmTouchHook` | 在 `sTick` 心跳后加 **①**；在 `ACTION_DOWN` 分支加 **②** |
| `GmBubblePaintHook.collect` | 在方法最开头（早于所有 early-return）加 **③** |
| 版本串 ×3 + manifest | `2.22.89/420` → **`2.22.90/421`** |

**产物回读验证**：`2.22.90` · `421` · **`128 类`** · V1+V2+V3 · sha256(partial) `975da33f…` ✓

**为什么用 `logOnce`**：每个只报一次 ⇒ **既能判定"跑没跑"，又不会刷屏**（教训 225）✓

## 2. 主人操作（**只要点一下**）

1. 装 `2.22.90` → **强停宿主** → 开 App
2. 「调试」页**拨开捕获器**（这一步必须有 —— `collect` 走采集链路）
3. **随便点一下某个按钮**（让它有 DOWN/UP）
4. 打开「模块日志」，**搜这四行**：

```
[触摸钩子] dispatchTouchEvent 钩子已被调用（说明触摸钩子生效）
[触摸] DOWN 收到 ACTION_DOWN（开窗）
[采集] collect() 已被调用（采集链路活着）
[交互排除] 学到 xxx
```

### 判读表（**一眼定断点**）

| 看到什么 | 断点位置 | 我的下一步 |
|---|---|---|
| ①②③ **都出现**，也有 `学到` | ✅ **链路全通** | 那"按钮没变回来"是另一类问题（排除名单生效了但按钮由别的锚点画）⇒ 发我日志 |

| **① 都不出现** | **`dispatchTouchEvent` 钩子根本没被调用**（宿主可能覆写了它） | 我改钩更底层/更通用的入口（如 `ViewGroup.dispatchTouchEvent` 或 `View.onTouchEvent`） |
| **③ 都不出现** | **采集链路没跑**（捕获器没开 / `collect` 没被调） | 我查 `dg → collect` 那一段 |

## 3. 教训（223~225）

| # | 内容 |
|---|---|
| **223** | ⭐⭐⭐ **"没有输出"＋"没有效果"同时出现 ⇒ 不是"效果不对"，而是"链路没跑"** —— 此时**改判据/调参数全是白费**，应该在**链路的每个关键节点上放"一次性痕迹"**。⇒ 与教训 194/201 同源，但这次是**主动预埋**而不是事后补救。 |
| **224** | ⭐⭐⭐ **一次照亮所有可能断点，不要一个一个试** —— 三个 `logOnce` 同时上线 ⇒ **一次实验就能判定断点在哪一环**。⇒ **当一条链路有 N 个可能断点时，应该在 N 个节点上都放痕迹，让一次实验回答 N 个问题**（这是教训 199「一次覆盖所有剩余假设」在"链路诊断"上的推广）。 |
| **225** | ⭐⭐ **诊断痕迹用 `logOnce`** —— 每个只报一次 ⇒ **既能判定"跑没跑"，又不会把日志刷满**（用户可以安心地把整段日志发过来）。 |
