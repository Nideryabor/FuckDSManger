## 1. 盖住它的是哪两层（主人自己发现的 `why=1`）

```
bg#1 depth=0 cnt=0 why=0 v = -67818912288342016   ← ★ 作用域外，未处理
bg#2 depth=1 cnt=0 why=1 v = -67818912288342016   ← 已透明化 ✓
bg#3 depth=1 cnt=1 why=7 v = -67818912288342016   ← 已透明化 ✓
bg#4 depth=0 cnt=2 why=7 v = -67818912288342016   ← ★ 作用域外，未处理
bg#5 depth=0 cnt=2 why=1 v = -60471863922393088
```

**`bg#1` 与 `bg#4` 都是 `#FF0F0F0F`（不透明深灰），且都在 ChatPage 作用域之外**（`why=1` = `sPageDepth<=0`）
⇒ **没被透明化** ⇒ **正是这两层把底图压住**。

> 这正是 **2.22.43** 当初想解决的事 —— 那时它失败是因为**图还在上层**（`pos=2`）；
> 现在图已插底层、View 层背景也清了，**只差这两层 Compose 底色**。

## 2. 本版改动：判据从「作用域」换成「颜色」

（把 2.22.43 的 `rec` + `sPageColor` 拿回来，与 2.22.42 之后的所有修复共存）

| # | 内容 |
|---|---|
| ① | `GmBubble` 新增 **`public static sPageColor:J`** |
| ② | `GmBubblePaintHook` 新增 **`private static rec(MethodHookParam)`** —— 记住本次会话第一个 `v` 调用的颜色（页面底色） |
| ③ | `beforeHookedMethod` 里 `rec` → `dg` → `pg` 依次调用 |
| ④ | **`pg` 判据改为颜色匹配**：`args[1] == sPageColor`（**不再要求 `sPageDepth > 0`**）⇒ **作用域外的 `bg#1`/`bg#4` 也会被透明化** |
| ⑤ | `GmPageHook.beforeHookedMethod` 每次 ChatPage 组合 ⇒ `sPageColor = 0`（重新记忆） |

**`why=` 编号（本版）**

| `why=` | 含义 |
|---|---|
| **1** | 方法名不是 `v` |
| **2** | `args` 问题（null / 长度 < 2 / 不是 `Long`） |
| **3** | **颜色不是页面底色** |
| **4** | 在助手消息项内（`sDepth > 0`）——排除气泡底 |
| **5** | 配额满（`cnt >= 8`） |
| **0** | ✅ 通过（`cnt` 已 +1） |
| **7** | `GmBg.real()` 为 false |
