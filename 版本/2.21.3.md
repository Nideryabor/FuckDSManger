### 🎯 真凶（低级但经典）

**我把 smali 的「类型描述符写法」当成 Java 类名用了：**

```
smali:        .class public abstract Luia;     ←  = L + "uia" + ;
真实 Java 名:   "uia"
```

⇒ `XposedHelpers.findClass("Luia", cl)` 去找一个**真的叫 `Luia`** 的类 ⇒ `ClassNotFoundException`。

**反证**：同一个 `cl` 找 **`"kq"`** 是成功的（日志里没有 `取 kq.d 圆角 Shape 失败`）
⇒ **规则确认：传 `findClass` / `Class.forName` 的必须是「裸 Java 名」，不能带 smali 的 `L…;`**
（`"kq"` / `"zc"` / `"c73"` / `"c76"` 我都写对了 —— 因为那些是从 `findClass` 调用点抄的；只有 `Luia` 是从 `dex_class:Luia;` 抄的，连前缀一起抄了。）

## 五、教训

| # | 要点 |
|---|---|
| **647** | ⭐⭐⭐ **`findClass` / `Class.forName` 只能传「裸 Java 名」** —— smali 里的 `Luia;` 是**类型描述符**（`L`+包路径+`;`），不是类名；`Luia` 的真名是 `uia`。**混淆名以 `L` 开头时特别容易踩**（`Lc73;`→`c73` 就不会错，因为去前缀后还是 `c73`；`Luia`→`uia` 就少了一位）。<br>📌 **可机械化的判据**：`mt_apk_dex_outline_class` 返回的 **`javaName`** 就是该传进去的名字。**以后抄类名一律抄 `javaName`，不抄 `locator`。** |
| **648** | ⭐⭐ **日志里「哪个失败、哪个成功」是黄金对照**：`kq` 成功 + `Luia` 失败 ⇒ 一句话锁定是**名字写法**问题，而不是 dex/loader/版本问题。**同一函数里的成功调用可以当对照组。** |
| **649** | ⭐⭐ **先让「必然出现的诊断」跑起来**（2.21.1/2.21.2 埋的自检行）——这一轮的三个硬结论**全是靠它拿到的**，否则又要瞎猜一轮。 |
| **650** | ⭐ **栈里的 `r8-map-id-…` 是「跑的是哪份 build」的指纹**：与分析工作区的 `source` 字段一比，立刻排除「宿主版本不对」这个方向。 |
