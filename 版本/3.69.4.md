## 二、附带发现：**日志缓冲被我们自己刷爆了**

```
main: ring buffer is 256 KiB        ← 默认
```

我们这种"边说边查日志"的对话，`adb logcat -d | grep FDM` 只剩 1 行 ⇒
**早期诊断全被冲掉了**（尼尼一度以为"三条日志全空 = 桥没跑"，其实是读不到）。

⇒ **`adb logcat -G 16M`** 把缓冲调到 **16 MiB**（已执行，不用 root）。
★ 这条应该成为**标准动作**：以后凡是"要看模块日志"，先调缓冲再让主人测。

（另：那一次"三条全空"还叠了一次 `device offline` —— **读不到 ≠ 没有**。）

## 五、教训

**1088 · ⭐⭐⭐ 加一族标记 = 三处一起改：常量 / `scan()` / **渲染前的快速闸**。**
　　这次三处里漏了第三处 ⇒ 标记根本没进 `scan()` ⇒ 后面所有修复都是白做（3.69.3 白热了三天）。
　　★ 判据：**"我加了新语法"之后，先搜一遍这个语法的所有"入口判定"**（有没有别的地方也在
　　`indexOf(标记前缀)` 做预判）。快速闸/短路优化最容易漏。

**1089 · ⭐⭐⭐ 日志缓冲默认 256 KiB，我们这种刷屏对话会把它冲掉。**
　　`adb logcat -G 16M` 是**免 root** 的，应该成为"要看模块日志"的**前置动作**。
　　★ 否则会出现最坏的情况：**"日志为空"被误读成"代码没跑"**，然后往错的方向改好几版。

**1090 · ⭐⭐ 「读不到」≠「没有」。**
　　同一次排查里，设备刚好 `device offline` ⇒ 那条 `grep` 是在**空数据**上跑的，
　　结论却是"三条日志全空"。⇒ **取证命令要先确认设备在线**（`adb get-state`）。

**1091 · ⭐⭐ 当"两种解释都成立"时，先做能排除一种的那个实验。**
　　这次主人补的一句「模型写的是 `⟦DJ:…⟧`」直接把"括号形态"排除掉，
　　剩下的就是"快速闸" ⇒ 省掉一整轮瞎改。
　　★ 请求补充信息时，要**问能排除分支的那种**（"它写的到底是哪种括号"），
　　而不是问"好了没"。
