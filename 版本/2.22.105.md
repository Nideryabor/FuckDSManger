## 1. 本版两处改动

### ① 角色来源：从"扫第一个 `vq` 实例"改成**优先取 `args[4]`**

`pn9.c` 的签名是 `(ILpe5;Ljb1;Lwr;Lvq;Lc76;Ley3;I)V`（**static**）⇒ 按 **p0..p7** 数：

| 位置 | 类型 | 含义 |
|---|---|---|
| `p0` → `args[0]` | `int` | 状态/索引 |
| `p1` → `args[1]` | `pe5` | |
| `p2` → `args[2]` | `jb1` | |
| `p3` → `args[3]` | `wr` | 消息容器 |
| **`p4` → `args[4]`** | **`vq`** | **★ 这一条消息本体**（宿主自己就在这个位置调 `vq.D()`） |
| `p5` → `args[5]` | `c76` | **Modifier**（我们注入用的那个） |
| `p6` → `args[6]` | `ey3` | Composer |
| `p7` → `args[7]` | `int` | flags |

⇒ 本版：**若 `args[4]` 是 `vq` 实例，就用它当"角色来源"**（否则回退到原来的"扫第一个 `vq`"）✓
**理由**：原来"扫 args 里第一个 `vq` 实例"**可能扫到不是这条消息的对象**（引用的消息 / 父节点 / 其它 `vq` 子类）⇒ 角色判定必然错 ⇒ **这正是"用户项被当成助手项"的最可能机制**。

### ② 探针换"绝不去重"的通道

- 已确认 `GmUtil.logOnce(tag, msg)` 是 **只按 tag 去重**（`HashSet.add(tag)`，打的是 `msg`）
- 所以本版把 `roleLog` 里所有输出改成 **`GmUtil.log(String)`（无去重、无 HashSet）** ⇒ **它不可能再"装死"**
- 另在钩子里加一条"我到这了"标记：`[HOOK] 找到消息项，开始打印参数`
