## 二、两个根因

### ① 我在 3.28.0 的缓存里**把 `if-*z` 又写反了**（我的锅）

```smali
    sget-object v2, sBmpCache
    if-eqz v2, :ub_cache_ready      ✗ if-eqz = 「为零才跳」⇒ 表为空时【跳过建表】⇒ 下一句 get() 抛 NPE
    new-instance v2, ConcurrentHashMap
    ...
    :ub_cache_ready
    invoke-virtual {v2, v3}, ConcurrentHashMap;->get(...)   ← v2 == null ⇒ NPE
```

⇒ `imgBrush` 抛异常 → 返回 null → `ubMod`/`wrapImg` 都退回**纯色**。
**修**：`if-eqz` → **`if-nez`**。
> ⚠️ 教训：**这是同一天第二次栽在 `if-*z` 家族上**（第一次是角色分派 `if-nez` 写反）。写完立刻用一句话写"为真/为零时跳到哪"——这条纪律必须变成肌肉记忆。

### ② 「点图片」走的是一条**结构性死路**（老 bug，不是这轮引入）

UI 把原图写到公共中转目录 `/sdcard/Pictures/FDM/img_bubble.png` → 桥 `Uri.fromFile(src)` ⇒ `file://` →
`GmBubble.saveImage()` 里走的是 `ContentResolver.openInputStream()` / `loadThumbnail()`
⇒ **`file://` 没有 content provider** ⇒ `FileNotFoundException` ⇒ 保存必失败（选图永远不生效）。

**修（改桥，不用动底座）**：`FdmBridge.img_path` / `img_end` 两条路对 `bubble`/`ububble` **直接按字节拷**进
`<宿主 filesDir>/fuckds_bubble.png` / `fuckds_ububble.png`（复用已有的 `copyFile`），并：
- 调 `GmBubble.setImgOn/setUImgOn(ctx,true)` 把图片开关打开
- 调新助手 `clearBubbleCache()`（反射把 `GmBubble.sBmpCache` 置 null）⇒ 换了图立刻用新图

## 三、主人问的「颜色为什么是负数」

**不是 bug，是 32 位 ARGB 的正常表示**：最高字节 alpha=`0xFF` ⇒ 有符号 int 就是负数。

| 键 | 存的 int | 实际颜色 |
|---|---|---|
| `fuckds_ububble_color` | `-12964260` | **`#FF3A2E5C`**（用户气泡，深靛蓝） |
| `fuckds_bubble_color` | `-13944235` | **`#FF2B3A55`**（AI 气泡，深藏青） |

> 下一版可以在 UI 上顺手把显示改成 `#RRGGBB`（`(v and 0xFFFFFF)` 格式化），免得看着像出错。
