## 〇、一句话

**往宿主窗口的 `decorView` 里塞了一张便签** —— 可拖动、可就地编辑、可变外观、可多张，
**零权限**（不用「显示在其他应用上层」那条），开关在「美化 › 悬浮便签」。

---

## 一、为什么是「注入宿主窗口」而不是「系统悬浮窗」

| | 注入 decorView（本版） | `TYPE_APPLICATION_OVERLAY` |
|---|---|---|
| 权限 | **不需要** ✅ | 要「显示在其他应用上层」，得用户手动去设置里开 |
| 清单/Service | **零改动** ✅ | 要加 Service + 清单条目 |
| 生命周期 | 宿主关了自然消失 ✅ | 得自己管 |
| 覆盖面 | 只在宿主界面上 | 能压在任何 App 上 |

主人 2026-10-06 选了前者 —— 便签本来就是「给自己在宿主里看的」，覆盖面不是需求。

## 二、新增

### `bridge/GmNote.java`（状态 + 安装）

* 钩 **`android.app.Activity`** 的 `onResume` / `onPause`
  （**框架类，名字永远不变** —— 跟 `FdmEntry` 判宿主的思路一致，不新增脆弱点）
  * `onResume` → 取 `getWindow().getDecorView()`，把便签 `addView` 上去
  * `onPause`  → 摘掉（不泄漏、不串页；回来时再挂）
* 状态模型（一个 JSON）：`{idx, min, items:[{t,x,y}]}`
  * `t` = 文字 · `x`,`y` = 左上角位置（**dp**；`-1` = 还没放过 ⇒ 自动摆到右侧）
  * 存 `fuckds_note_data`（`GmStore.write(ctx,key,val,"s")`）
  * **内存缓存 + 结构自愈**：`items` 一定是「至少一个 JSONObject」的数组 ——
    这样 `curItem()` 拿到的永远是数组里的**真身**，写进去才存得住
* `attach()` 判「同一扇窗就只刷新、不重挂」（避免每次 onResume 都重建一遍）

### `bridge/GmNoteView.java`（外观 + 手感）

**纯代码画的 View，零资源依赖** —— 我们 dex 里**没有资源表**，一用 `R.drawable` 就
`Resources$NotFoundException`。所以：圆角底走 `GradientDrawable`，图标用**纯几何符号**当文字。

```
┌──────────────────────────────┐
│ ≡   ＋  ‹ 1/3 ›  －  ▣  ✕     │  ← 顶栏；只有 ≡ 是拖动把手
├──────────────────────────────┤
│  正文（点一下就地变输入框）      │
└──────────────────────────────┘
最小化形态 = 一颗圆球（点它回来）
```

* **`≡` 单独当把手**（主人拍板）：整条顶栏可拖的话，点「＋」时手一抖就被判成拖动
  （Android 的 touch slop）⇒ 按钮时灵时不灵。收进一小块就没这问题。
* **一个 `EditText` 走全场**：平时 `focusable=false / cursorVisible=false`，
  点一下才 `requestFocus + showSoftInput` 并就地把光标放末尾；失焦 ⇒ 落盘。
  不弹 Dialog ⇒ 少一个崩点。
* 拖动用 `setX/setY`（= translationX，不触发 measure/layout，很顺），
  `ACTION_DOWN` 里 `requestDisallowInterceptTouchEvent(true)` 防宿主容器抢事件。
* `clamp()`：允许露出一半，但**不允许整个拖出屏幕**（够抓回来就行）。

## 五、三条保命规矩

1. **全程 try/catch** —— 出任何事只写日志，绝不连累宿主；锚点/窗口拿不到 ⇒ 等于没装
2. **零资源依赖** —— 底色代码画、图标用符号（我们 dex 没资源表）
3. **`onPause` 摘掉** —— 不泄漏、不串页；摘之前 `saveNow()` 把没落盘的编辑存了

## 六、`✕` 的语义（主人 2026-10-06 定的）

> **「本次宿主进程里不再出现，重启宿主或在模块里把开关拨一次就回来」**

实现：`sSessionClosed` 只活在进程内存里
* `✕` → `closeSession()` ⇒ 置位 + 摘掉
* `GmNote.setOn()` ⇒ **清位**（所以拨开关就回来）
* 进程重启 ⇒ 自然清空（所以重启宿主也回来）
* `refresh()` **只刷已挂上的**，**不会**把 `✕` 关掉的重新拉出来 —— 语义边界就在这里

## 九、教训

**947 · ⭐⭐⭐ 「能加进窗口」和「能加进无资源 dex」是两件事。**
`decorView.addView` 这条路上有个隐形前提：**我们自己没有资源表**。
所以外观只能用代码画（`GradientDrawable`）+ 纯文字符号 ——
先用 layout XML 写、再发现 `R` 不存在，就要从头再来一遍。
**动手前先问「这个东西需不需要资源」。**

**948 · ⭐⭐ 拖动把手要跟按钮分开。**
「整条顶栏能拖」看着大方，实际是**让每个按钮都去和 touch slop 抢事件**。
把拖动收进一个小把手，按钮就恢复了确定性 —— **可拖区域和可点区域别重叠**。

**949 · ⭐⭐ 「就地编辑」优于「弹对话框」。**
一个 `EditText` 切换 `focusable` 就能覆盖编辑全流程（含输入法、含失焦落盘），
而弹 Dialog 要多管一个 window、多一个崩点、还要处理宿主的 Activity 状态。
**同一个控件改行为，比新建一个控件便宜。**
