## 一、真因（代码级）

```java
// ❌ 旧 endEdit()
private void endEdit() {
    if (!editing) return;        // ← 没在编辑就什么都不做
    ...
    GmNote.setText(edit.getText().toString());
}
```

而**切页**（`‹` `›` `＋` `－`）走的是 `refreshAll()`，里面有这一句：

```java
if (!editing && !t.equals(edit.getText().toString())) edit.setText(t);
//   ↑ 编辑中就不刷新 ⇒ 没落盘的字**留在 edit 里**
```

**串起来就是主人的两个现象**：

| 主人的操作 | 代码里发生的事 | 现象 |
|---|---|---|
| 改完字，**没点别处** | `editing` 仍为 `true`，字只在 `edit` 里**没落盘** | — |
| 点 `›` 切页 | `refreshAll()` 因为 `editing==true` **不刷新**；`edit` 里还是第一页的字 | 页码变了、文字像没变 |
| 在第二页一敲字 | 一落盘 ⇒ **第一页的字写进了第二页** | ✅ **「第一页覆盖后面页」** |
| 「必须点别处才保存」 | `endEdit()` 只在**失焦**（`onFocusChange`）时被调 | ✅ **「必须失去焦点」** |

**一句话**：**切页前，没把当前页「提交」。**

---

## 二、修法

新增 `commitEdit()` —— 语义是**「动当前页之前，先把当前页存了」**：

```java
private void commitEdit() {
    if (!editing) return;              // 没在编辑 = 没有未落盘的东西
    editing = false;
    edit.setFocusable(false); ...      // 退出编辑态
    GmNote.setText(edit.getText().toString());   // ★ 关键：先存
    GmUtil.log("【GmNote】落盘当前页（切页/增删前）");
}
```

然后挂到**所有会离开当前页的地方**：

| 动作 | 加 `commitEdit()` |
|---|---|
| `‹` 上一页 | ✅ |
| `›` 下一页 | ✅ |
| `＋` 新建 | ✅ |
| `－` 删除 | ✅ |
| `▣` 最小化 | ✅ |
| 圆球还原 | ✅ |
| `onPause` 摘视图（`saveNow`） | ✅（并改走 `commitEdit`，顺带收键盘） |

**顺手做的两件**：

1. `refreshAll()` 里的 `editing` 分支改成「**只记日志、不动内容**」——
   万一将来有人漏了 `commitEdit`，也别把用户正在敲的字冲掉（宁可留个警告）
2. `endEdit()` 收敛成「`commitEdit()` + 收键盘」——**别再维护两套逻辑**
3. 落盘时打日志 `【GmNote】落盘当前页（切页/增删前）` ⇒ 下次出问题一眼定位

## 四、教训

**974 · ⭐⭐ 「当前页」是个状态，凡是要离开它的地方都得先落盘。**
`commitEdit` 这个名字尼尼挺喜欢：**提交，然后才允许你离开。**
（同类：编辑框失焦、Activity 切走、进程被杀 —— 都是"要被带走的中间状态"。）

**975 · ⭐⭐ 「跑通了」不等于「用起来对」——测的路径要覆盖"用户真会怎么用"。**
尼尼测的是「点正文 → 打字 → 点别处 → 字在」，
而主人用的是「点正文 → 打字 → **直接翻页**」。
**差别就在那一个"没点别处"** —— 而它恰恰是 bug 的触发条件。
⇒ **测完主路径，还要问一句「用户可能怎么偷懒」**。

**976 · ⭐ 两个看起来无关的症状，可能是一个根因。**
「串页」和「必须失焦才保存」在主人那儿是两件事，
在代码里是同一条链（`editing` 标志 + 只在失焦时落盘）。
**先把症状连成一条线，再动手** —— 比各修各的省一半力气。
