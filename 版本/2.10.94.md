## 一、定性：**方法找到了，是它自己炸的**

| 异常 | 含义 |
|---|---|
| ~~`NoSuchMethodException`~~ | 元素没有这个方法（类型不对） |
| **`InvocationTargetException`** ✅ | **`getMethod` 成功了，`invoke` 时被调方法内部抛了** |

⇒ 说明 `vq` 上那串"取文本"方法（`l`/`t`/`k`/`G`/`D`/`A`）**在这个元素上执行到一半抛了**。

## 二、本版两件事

### 1. 挖出真正的 `cause`

`InvocationTargetException` 只是"包装"，真正的异常在 `getCause()` 里。本版 `pick()` 的 catch 改成：

```smali
invoke-virtual {v1}, Ljava/lang/Throwable;->getCause()Ljava/lang/Throwable;
move-result-object v2
if-eqz v2, :pick_no_cause
move-object v1, v2            # 有 cause 就用 cause
:pick_no_cause
… logOnce(toString) …
```

**⇒ 日志里会出现真正的原因**（如 `NullPointerException: … at wuq.D` 之类）。

### 2. 加一条**不依赖那些方法**的兜底：`toString()`

`one()` 的失败分支现在会：

```
① 记录元素类名（sErr → Toast 的 e=）
② 尝试 element.toString()，非空则截 200 字返回   ★ 新增
```

Kotlin 的 data class 通常 override `toString()`，会打印**各字段内容** ⇒ 即使"取文本方法"全炸，**至少能拿到一份含正文的字符串**（先保证有东西用，之后再换成干净的取法）。
