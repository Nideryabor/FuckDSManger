# FuckDSManger NL 2.10.53（🔁 修「模型切换/灰度」被服务器下发顶掉：开关动作直写宿主 + 下发时保住）

> 产物：`FuckDSManger_NL_2.10.53_for_ds2.5.2.apk`（**204 / NL 2.10.53**，91 类，V1+V2+V3，sha256(partial) `58b1b0f2…`）
> 触发：主人「原来是**灰度选项**好像**注入太早了**，切换模型的按钮启用时，重启 app 能**在一瞬间看到切换卡**，但很快被**服务器的下发顶掉**」

---

## 一、链路还原（现象完全对得上）

模块的「模型切换」= `GmModel`：

| 项 | 值 |
|---|---|
| 模块开关键 | `fuckds_model_switch` |
| 目标配置键 | `kv_remote_settings_model_configs_v1` |
| 改写内容 | `"switchable":false` → **`"switchable":true`**（让切换按钮出现） |

**⇒ 但 `reapply()` / `setOn()` 全程只读写「模块侧快照」（`GmStore`），从不碰宿主 MMKV。**

那"能在一瞬间看到"是怎么来的？—— 靠**旧的 `GmMmkvHook` 写接管**（宿主写盘瞬间把快照里的改动掺进去）。
而"被顶掉"的两个原因叠在一起：

1. **2.10.52 我把 `GmMmkvHook.handle` 停了**（为了让出 `prompt_feature`，避免污染「文件快捷选项」）⇒ 写接管没了；更早的版本里，`handle` 也**只处理 prompt_feature、没处理 `switchable`**
2. **服务器下发会重写同一个键** ⇒ 快照里的改动没有任何时机能落到磁盘上

⇒ 于是"启动时闪一下（某次写入曾经带上过）→ 下发覆盖 → 没了"。

## 二、本版修复（3 处）

| # | 改动 | 说明 |
|---|---|---|
| 1 | **`GmModel.reapply(ctx)` 重写** | 不再读模块快照；改为 **`GmPrompt.host()` 读宿主 → replace(false→true) → `hostPut()` 直接写宿主** ✓ |
| 2 | **`GmModel.setOn(ctx, on)` 重写** | 记开关后**立即直写宿主**（开→false→true，关→true→false），返回值＝"是否真写进宿主" ✓ |
| 3 | **`GmMmkvHook.handle` 恢复但**只做 `switchable`** | 服务器下发写盘那一刻把 `"switchable":false` 替换成 `true` ⇒ **不再被顶掉**；**完全不碰 `prompt_feature`**（「文件快捷选项」的地盘保持干净） |

### 2.1 现在的职责边界（很干净）

| 功能 | 数据 | 谁负责 |
|---|---|---|
| **文件快捷选项**（宿主的） | `prompt_feature` | 宿主自己 + 模块编辑器（`GmPrompt.host/hostPut`），**我们不再 patch** |
| **模型切换 / 灰度** | `switchable` 等字段 | `GmModel` 直写宿主 + `GmMmkvHook` 在下发时保住 |
| 回复建议 | 模板池 | 下一步做独立位置（不借 `prompt_feature`） |

> 注：`host()`/`hostPut()` 走的是 `decodeString`/`encodeString` **native 本体**，所以**不会**触发我们挂在包装 `k`/`q` 上的 hook —— 读到的永远是宿主真实值。

## 四、教训

| # | 教训 |
|---|---|
| **288** | ⭐⭐⭐ **"闪一下就没了" = 注入时机与数据源刷新竞态**：凡是"服务端会重写"的键，注入必须发生在**写盘那一刻**或**写盘之后**，不能在启动早期一次性写 |
| **289** | ⭐⭐⭐ **同一份数据被多个功能使用时要划清"谁负责写"**：`prompt_feature` 归文件快捷选项、`switchable` 归模型切换 ⇒ 各管各的字段，互不覆盖 |
| **290** | ⭐⭐ **改公共基础设施（如停用 GmMmkvHook）必须清点"谁在依赖它"**：本次停用顺手打掉了模型切换的注入 |
| **291** | ⭐⭐ **`host()`/`hostPut()` 走 native 本体**是"模块读写宿主数据"的标准姿势：既绕过自己的 hook，也不受宿主 R8 改名影响（只要 `nativeHandle` 字段名在场） |
