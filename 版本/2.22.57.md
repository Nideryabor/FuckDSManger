## 2. 🎯 找到 2.22.55「没区别」的确切原因

**问题出在代码结构**：我把「连续同色计数」写在了**「未命中三槽」的分支里**。

```
第 1 次遇到 #0F0F0F ⇒ 未命中 ⇒ 记进槽 2，sSameCnt = 1
第 2 次遇到 #0F0F0F ⇒ 【命中槽 2】⇒ 直接透明化
                       ★ 根本不进"记录分支" ⇒ sSameCnt 永远是 1
                       ⇒ 槽 1(sPageColor) 永远不被设置 ⇒ 分档失效
```

⇒ **连续计数被"命中检查"挡在门外了** —— 这就是 54/55「没区别」的根因。

## 3. 修法：计数挪到**最前面**（每次调用都算），并用它直接决定 alpha

```smali
    # ①…③ 方法名 / args / sDepth 检查（不变）
    check-cast v3, Long; longValue() ⇒ v4/v5 = color

    # ★ ④ 连续计数放最前（无论是否命中槽位都执行）
    sget-wide v6, sLastColor:J
    cmp-long v8, v4, v6
    if-nez v8, :cnt_inc
    sput-wide v4, sLastColor:J ; sSameCnt = 1
    goto :cnt_done
    :cnt_inc
    sSameCnt++          (sput sSameCnt)
    :cnt_done
    sget v6, sSameCnt:I ; if-lt v6, 2, :chk_slot
    sput-wide v4, sPageColor:J          # 连续 ≥2 ⇒ 认定为背景色

    :chk_slot
    # ⑤ 命中三槽 ⇒ 透明化（逻辑不变）
    # ⑥ 未命中 ⇒ 空槽填入 / 覆盖槽 3

    :do
    … GmBg.real() 检查 …

    # ★ ⑦ 分档：用"当前颜色的连续次数"决定 alpha
    sget v6, sSameCnt:I ; if-lt v6, 2, :half
    v2/v3 = 0L                          # 连续 ≥2 ⇒ 背景块 ⇒ 全透明
    goto :set
    :half
    v4 &= 0xffffffffffffffL             # 其余 ⇒ 保留 RGB
    v2 = 0x80 << 56 ; v4 |= v2          #   alpha = 0x80（50%）
    move-wide v2, v4
    :set
    aput-object Long.valueOf(v2/v3) → args[1]
```

**效果**：
- 连续出现 ≥2 次的颜色（页面底色 `#0F0F0F`）⇒ **全透明**
- 只出现一次的颜色（按钮/卡片/标题）⇒ **半透明 50%**
- 且**计数不再被命中检查挡住** ⇒ 分档真的会生效

## 5. 教训（841~842）

| # | 内容 |
|---|---|
| **841** | ⭐⭐⭐ **"诊断逻辑"如果放在"命中分支"里，就永远不会被正确触发**：连续计数写在"未命中三槽"分支 ⇒ 第二次同色命中后直接跳走 ⇒ **计数器永远停在 1**。⇒ **凡是"用于判定"的状态更新，必须放在所有提前返回/提前跳转之前**（与教训 826 的"守卫顺序"同源）。 |
| **842** | ⭐⭐⭐ **用户的截图可以用"数值化"来读**：`#0F0F0F` 占比 **37.93%** 这个数字，比任何肉眼描述都更准确地告诉我"哪个颜色、占多大面积、集中在哪一列"。⇒ **不能看图时，就把图变成"每个候选色的占比 + 分布"** —— 它既能验证改动是否生效（前后占比对比），也能定位问题区域。 |
