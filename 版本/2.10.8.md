# FuckDSManger 2.10.8（回复建议 · 修 VerifyError：寄存器踩了参数槽）

> 产物：`FuckDSManger_2.10.8_for_ds2.5.2.apk`（**159 / 2.10.8**，89 类，V1+V2+V3，sha256(partial) `04e42f3b…`）
> 触发：主人回报 `hookM FAIL pd5.H | java.lang.VerifyError`

---

## 一、崩溃/失效点：`GmPromptTextHook` 整个类被校验器否掉

```
java.lang.VerifyError: Verifier rejected class GmPromptTextHook:
beforeHookedMethod(...) failed to verify:
[0x51] tried to get class from non-reference register v9 (type=Precise Constant: 1)
```

### 原因：寄存器数给小了，临时寄存器踩进了**参数槽**

`beforeHookedMethod` 是**实例方法且带 1 个参数** ⇒ 参数占 2 个寄存器：

| `.registers` | p0(this) | p1(参数) | 可用局部 |
|---|---|---|---|
| **10（原）** | **v8** | **v9** | v0~v7 |
| 12（修后） | v10 | v11 | v0~v9 |

我原以为局部能用到 v9，于是：
- `const/4 v9, 0x1`（当临时寄存器）
- `const-string v9, "[建议] 文案已接管("`
- `iget-object v9, p1, …->method`（**把 p1 的值读进 v9**）

⇒ v9 里既有 `int 1` 又有 `Member`，而它**同时还是 p1 的槽位** ⇒ 后面 `invoke-virtual {p1, v6}, …setResult` 时类型对不上 ⇒ **类被否**。

⇒ 一个类被否 = **该类所有注册全灭**（`pd5.I` + `pd5.H` 一起废）—— 正是主人日志里 `hookM FAIL pd5.H` 的来历。

### 修法

```smali
.method protected beforeHookedMethod(…MethodHookParam;)V
-    .registers 10
+    .registers 12
```

## 三、⚠️ 关于「崩了」：VerifyError 不是崩溃原因

`hookM` 内部**自带 try/catch**（`logFail` 那套），VerifyError 只会打成一行 `hookM FAIL …`，
**不会让宿主崩溃** ⇒ 主人看到的崩溃**另有原因**。

**首要嫌疑：常显闸门**（`GmGateListHook` 对 `hp8.isEmpty()` 谎报「非空」）。

宿主别的读取方（上传状态 / 发送按钮 / 附件行）可能因此读到「有附件」而去取元素 ⇒ 越界崩溃。
这正是 2.10.6 文档里登记的**已知风险**。

## 四、教训

| # | 教训 |
|---|---|
| 159 | ⭐⭐⭐ **`.registers` 必须 ≥ 局部寄存器 + 参数个数** —— 参数占的是**最高的那几个**。写 `.registers 10` 却用 `v9`，在「1 参实例方法」里就等于**直接改参数**，编译器/汇编器不报错，运行前被校验器否掉 |
| 160 | ⭐⭐ **一个类被否 = 该类所有 hook 全灭**（2.10.23 的旧教训重演）⇒ 注册失败日志必须逐个看，别只看第一个 |
| 161 | ⭐ **「异常有日志」≠「异常导致崩溃」**：`hookM` 自身吞异常 ⇒ 崩溃要找别处（本轮据此把嫌疑指回闸门） |
