# FuckDSManger 2.10.29（回复建议 · `make()` 不再限定 4 参 + 造完强制写字段）

> 产物：`FuckDSManger_2.10.29_for_ds2.5.2.apk`（**180 / 2.10.29**，90 类，V1+V2+V3，sha256(partial) `69a08117…`）
> 触发：主人说「没有构造或者字段的日志」

## 一、先澄清一件事

主人那份 `模板=1 造出=0` 的日志（10:19:11）应当是 **2.10.27** 的产物 ——
"口供"是 **2.10.28** 才加进去的，所以"没有那两类日志"很自然。

不过顺着 `make()` 的代码，已经看到**下一个必然拦路的硬编码**：

```smali
    array-length v6, v5
    const/4 v7, 0x4
    if-ne v6, v7, :next          ← make() 只尝试「4 个参数」的构造器
    …
    if-eq params[2], String, :next
    if-eq params[3], String, :next
```

⇒ 宿主那个 **3 参构造器 `g56(int, java.lang.Integer, String)`（我们的最优选）永远轮不到**。

## 二、本版两处改动

| 改动 | 说明 |
|---|---|
| ① `make()` 过滤条件改为 **参数个数 ≥ 3 就试** | 两套构造器都会进入 `tryCtor`（3 参走 `{id,null,text}`，4 参走原逻辑） |
| ② `tryCtor` 造完**强制写字段**：`a=id`、`c=文本`、`d=null` | 不再赌"构造器参数落到哪个字段" —— 只要**对象能造出来**，字段就是我们要的（`d=null` 还能让 `pd5.I` 回落到 `c`） |

⇒ 随后仍读回字段 `c` 与文本比对：一致即认（自验证保留），不一致则由 2.10.28 加的 `suggest.ctorV` 日志报出来。

## 三、验证

```
1. 覆盖安装 FuckDSManger_2.10.29_for_ds2.5.2.apk（vc180）→ ★ 强停宿主 → 重开
2. 进会话 → 传图（别发送）→ 看 chip
3. 日志里搜： 造出=  /  构造抛异常  /  造完字段c
```

| 日志/现象 | 结论 |
|---|---|
| `build 模板=1 造出=1` + chip 是我们的文字 | 🎉 **通了** ⇒ 收尾 |
| `构造抛异常：…` | 按异常内容调参数（下一步） |
| `造完字段c=… 期望=…` | 强制写入也没成功 ⇒ 说明连 `put` 都失败（字段名/类型不同） |

## 四、教训

| # | 教训 |
|---|---|
| 216 | ⭐⭐⭐ **"只试一种形状"的过滤逻辑是隐藏地雷**：`make()` 里那句 `length == 4` 让我误判了好几轮 —— 过滤条件应当**宽进**（≥3 参），由被调方按实际签名分流 |
| 217 | ⭐⭐ **反射造对象的正确姿势：造出来 + 强制写字段** —— 与其研究构造器参数语义（`default`？id？scene？），不如造完直接覆盖关键字段 |
| 218 | ⭐ **诊断要贴时间戳/版本**：本轮差点被"旧日志"误导 —— 用「版本横幅 + 时间」一起判断，能省一轮往返 |
