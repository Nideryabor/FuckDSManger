## 二、排版对比

| | 老（左右两栏） | 新（上下分区 · 抄 iOS） |
|---|---|---|
| 结构 | `HORIZONTAL`：左列封面+控件 / 右列 info+歌词 | `VERTICAL`：顶栏 / body(weight=1) / 进度条 / 按钮行 |
| 封面 | 权重 1.15 占左半 | 常态 84dp 小方块靠左上；聚焦铺满 body |
| 歌词 | `ScrollView` + 一堆 `TextView`（全部一次性 addView） | `ListView` + `BaseAdapter`（虚拟化，可滚，当前句居中） |
| 进度条 | 在左列控件区顶部（写死位置） | **吸附在按钮行上沿**（靠 `weight=1` 自动实现） |
| 按钮行 | 5 个按钮各 `weight=1f` 平分 | 固定宽度 42/50/42/30/30 + 6dp 间距，`gravity=CENTER` |
| 形态 | 1 种 | **3 种**：常态 / 聚焦（全歌词）/ 纯图（只封面） |

### 三态

| 态 | 触发 | 表现 |
|---|---|---|
| 常态 | 默认 | 顶栏 ♪ + 曲名 + ✕，封面 84dp，歌词窄条在右，进度条 + 5 按钮 |
| 聚焦 | 点歌词 | 封面铺满 body，渐变暗膜，**全歌词可滚**，当前句白色加粗居中；进度条/按钮/♪/✕ 全 GONE，左上角出 `‹` |
| 纯图 | 聚焦时双击 | 歌词 / 暗膜 / 标题 / 返回键全隐藏，只剩封面；再双击恢复，单击回常态 |

## 三、★ 三个关键决定（都不是"抄过来就行"）

### ① 用 `ListView` 不是 `RecyclerView`

处方里写的是 `RecyclerView` —— **但那在安卓这边用不了**。

模块是**零依赖**的（`build.sh` 只挂 `android.jar` + Xposed 桩）：

```
$ unzip -l /workspace/tools/jvm/lib/android.jar | grep -c recycler
0
```

`androidx.recyclerview` 不在 `android.jar` 里，引它 = 编译期就挂，
或者得往 dex 里塞一层 androidx，`build_single` 的 ⑪ 引用闭包自检也会跟着炸。

⇒ 改用框架自带的 `ListView`。它和 `UITableView` 本来就是同源设计：

| UITableView | ListView |
|---|---|
| `dataSource / delegate` | `BaseAdapter` + `setOnScrollListener` |
| `rowHeight` | itemView 的 `AbsListView.LayoutParams.height`（固定 28dp） |
| `scrollToRowAtIndexPath:atScrollPosition:Middle` | `smoothScrollToPositionFromTop(row, (h-rowH)/2)` |
| `scrollViewWillBeginDragging` | `onScrollStateChanged(SCROLL_STATE_TOUCH_SCROLL)` |
| `reloadRowsAtIndexPaths` | `invalidateViews()`（不用传索引 ⇒ **天然躲开 iOS 那个"空数组崩溃"**） |

### ② `body` 用 `weight=1`，不要抄 iOS 的手算

iOS 是手算的：

```objc
CGFloat btnY = h - kPad - btnH;
CGFloat slY  = btnY - 6 - slH;
CGFloat lyricH = slY - 6 - lyricTop;   /* 剩下的全给歌词 */
```

安卓这边只要：

```java
content.addView(topBar,  MATCH_PARENT, dp(28));
content.addView(vBody,   MATCH_PARENT, 0, 1f);   /* ★ weight=1 */
content.addView(vSeekRow, MATCH_PARENT, dp(22));
content.addView(vBtnRow,  MATCH_PARENT, dp(30));
```

剩余高度自动全给 `vBody` ⇒ **卡片拉高 = 歌词行数变多，中间不留白**。
处方里那句话是对的：别抄手算。

### ③ 纯图态必须 `setVisibility(INVISIBLE)`，不能只 `setAlpha(0)`

iOS 用的是 `_lyricTable.userInteractionEnabled = NO`。
安卓没有这个开关，而**透明度不影响触摸** —— 一个 `alpha=0` 的 `ListView`
照样把触摸全吃掉 ⇒ 纯图态在封面上**拖不动卡片**。

⇒ 用 `INVISIBLE`（不参与命中测试）。恢复手势改挂到**卡片级**的
`GestureDetector`：纯图态点封面 = 单击回常态 / 双击恢复歌词。

## 四、按 iOS 血泪清单逐条对齐

| iOS 踩过的坑 | 安卓这版怎么防 |
|---|---|
| `reloadRowsAtIndexPaths` **收空数组会崩**（前奏 `newRow = -1`） | 不传索引，用 `invalidateViews()`<br>另外 `lyricScrollToCurrent` 里 `row < 0 \|\| row >= size` 双重判 |
| 歌词缓存只比 `songId` ⇒ 歌词后到永远不重建 | 缓存键 = **`songId` + 源 LRC 长度**（`lrcId` + `lrcSrcLen`）<br>长度变化 = 歌词到手 ⇒ 重建；-2 = 还没建 / -1 = 取不到 |
| tag 从 0 起导致整卡拖不动 | 四角手柄 `setTag(1000 + i)`<br>（虽然这版手势不靠 tag，但别再埋这颗雷） |
| `CAGradientLayer` 不跟 frame 变 | 用 `GradientDrawable` 当 View 背景 ⇒ 跟着 View 尺寸走 |
| 动画必须显式做（iOS 白送） | **这版故意不做动画** —— 见 §六 |
| 四角缩放用"累加增量"有死区 | 保持原样（`起点 + 总位移`），**一个字没改** |

## 六、⚠️ 与 iOS 的三处**故意不同**（都是安卓这边的限制，不是漏做）

| # | iOS | 安卓这版 | 原因 |
|---|---|---|---|
| 1 | 聚焦态封面**铺满整张卡**（连顶栏下面都是封面） | 封面铺满 **`body`**（左右上下各留 10dp 内边距） | iOS 靠 `_playPage` 压到 index 1 + 顶栏单独浮在上面实现；安卓的顶栏在 `LinearLayout` 里占位。处方 §四 也写了「封面铺满 body 就够，反而更好做」。视觉上是"图片内缩 10dp"，不是"图片被切掉" |
| 2 | 三态切换有 0.28s 动画 | **瞬切，无动画** | 处方 §步骤 2 说的 `TransitionManager` 在宿主的 `DecorView` 下偶尔不生效。用 `View.animate()` 手算 scale 需要先知道 `body` 尺寸，是本轮唯一有崩风险的地方 —— **先让功能对，动画下轮再加** |
| 3 | 常态歌词**不可滚**（`scrollEnabled = NO`） | 常态**可滚** | `ListView` 没有"禁用滚动"的开关。要不吃触摸就得自己 return true，那卡片右半边就拖不动了。反正常态只有约 3 行，滚一下不碍事 |

另外一处**必要的偏离**：

> 按钮宽度 iOS 是 `44/52/44/32/32 + 8dp 间距 = 236pt`，
> 但安卓最小卡宽 `240dp` − 两侧 10dp 内边距 = **只剩 220dp**
> ⇒ 照抄会让 `◀◀` 和 `⇄` **两头被裁**。
> 改成 `42/50/42/30/30 + 6dp = 218dp`，最小卡宽下也放得下，视觉上没差别。

尺寸上下限也跟着 iOS 对齐了：`MIN 240×150 / MAX 560×560`
（原来安卓是 190×120 / 640×720）。
⚠️ **老存档里小于 240 宽 / 150 高的卡片会被重置成默认 330×210**（`GmMiniBar.attach` 里那句 `< MIN_W ⇒ DEF_W`）。

## 七、★ 顺带发现的一个真 bug（跟排版无关）

`GmMusicPlayer` 的 500ms 心跳里有这一句：

```java
if (mp != null) notifyState();
```

**`mp == null` 时一次都不推状态。** 而"没歌 / 播完释放 / 暂停"这几种情况
`mp` 都可能是 null —— 偏偏「歌词下载完成 → 卡片补上歌词」正好发生在这段时间里
⇒ 界面上永远等不到那次刷新，得等用户手动操作。

iOS 那边是**卡片自己**定时器驱动（`FDMMiniBar.m` 文件头原话：
「本卡片只由定时器驱动刷新（0.5s 一拍）」）。

⇒ 这版给 `GmMiniBarView` 加了自己的 `tick`（`onAttachedToWindow` 起 /
`onDetachedFromWindow` 停），只调 `p.state()` + `applyState()`，
不碰播放器本身的逻辑。

## 十、教训

| # | 教训 |
|---|---|
| **AK** | ⭐⭐⭐ **"处方写 RecyclerView" 不等于"能用 RecyclerView"** —— 先查 `android.jar` 里有没有。本项目是零依赖模块，**框架外的一切类都等于不存在** |
| **AL** | ⭐⭐ **iOS 的 `userInteractionEnabled = NO` 在安卓没有对应物**：`alpha=0` / `INVISIBLE` 语义完全不同，前者照样吃触摸。要"看不见也不能点"只能 `INVISIBLE` 或 `setEnabled(false)` |
| **AM** | ⭐⭐ **照抄尺寸前先算最小可用宽度**：236dp 的按钮行塞进 220dp 的可用区，结果是**两头被裁**而不是"自动缩小" —— `LinearLayout` 不会替你缩 `WRAP_CONTENT` 子项 |
| **AN** | ⭐ **"我自己再加一个心跳"往往是对的** —— 上游的刷新条件（`mp != null`）是为它自己的场景写的，界面需求的时效性不一定被覆盖 |
