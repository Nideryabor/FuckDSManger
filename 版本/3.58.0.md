## 一、为什么抽屉不是 `ModalBottomSheet`

组件库里最顺手的那个**直接否掉了**，理由只有一个：**形态对不上。**

| | `ModalBottomSheet` | 主人要的 |
|---|---|---|
| 初始态 | 一打开**至少半个屏** | **收在底部、只露一条把手** |
| 背后 | 压一层 scrim（把底下的界面变暗变不可点） | 它是**常驻在页面里的抽屉**，底下内容照常 |

⇒ 自己搭：一个 `Box` 贴在页面底部 + `draggable` + 松手 `animate` 到最近的一档。

```kotlin
// live = 已经拉起来多少（0 = 收在底部；travel = 拉满）
Box(Modifier.offset { IntOffset(0, (travel - live).roundToInt()) })
```

**★ 方向这件事得记牢**：Compose 的 drag delta 沿轴**正向为正**（竖向 = **往下为正**）⇒
**「往上拉」是负 delta** ⇒ 必须写 `live = live - delta`。
这类「符号错一次，整个就反着动」的地方，代码里留了一行注释钉住。

**两档吸附的判据**：先看甩动速度，再看距离 ——

```kotlin
val open = when {
    v < -600f -> true      // 往上甩（快）⇒ 开
    v >  600f -> false     // 往下甩（快）⇒ 收
    else -> live > travel / 2f   // 慢慢拖 ⇒ 看过没过一半
}
```

> 为什么不能只看距离：**慢慢拖**和**一甩**是两种意图 ——
> 甩一下就该走完，慢慢拖就该"过半才算数"。这条阈值（600px/s）是待真机校准的数。

## 二、改公共积木的正确姿势：**只加可选参数**

`FdmTopBar` 是全 App 共用的顶部栏（首页 / 关于 / 十几个功能页都在用）。
这次给它加「更多」按钮，做法是：

```kotlin
fun FdmTopBar(
    title: String,
    scrollBehavior: TopAppBarScrollBehavior? = null,
    onBack: (() -> Unit)? = null,
    onMore: (() -> Unit)? = null,     // ★ 新增，默认 null ⇒ 老调用点一个字都不用改
) { … actions = { if (onMore != null) IconButton(onClick = onMore) { Icon(MoreVert, "更多") } } … }
```

⇒ **十来个老调用点零改动、零回归**（行为与改动前逐帧一致：`onMore == null` 连 `actions` 都是空 lambda）。

## 八、教训

**990 · ⭐⭐⭐ 选型的第一判据是「形态」，不是「哪个现成」。**
　　组件库里最像的那个（`ModalBottomSheet`）一打开就至少半屏、还压一层 scrim，
　　而需求是「**初始收在底部只露一条把手**」⇒ **形态直接冲突，用不了**。
　　⇒ 先问"它能不能摆成我要的那个样子"，再问"我要不要自己搭"。
　　（自己搭也就 30 行 —— 比"硬掰一个不对的组件"便宜得多。）

**991 · ⭐⭐ 「方向/正负」这类符号约定，要拿注释钉在代码里。**
　　Compose 的 drag delta **沿轴正向为正**（竖向 = 往下为正）⇒ 往上拉是 `-delta`。
　　写反了不是"报错"，而是**整个抽屉反着动**（看着像完全不同的 bug）。
　　⇒ 凡是"错一次就整体反向"的地方（正负 / 上下 / 顺逆），**当场写下一句注释**。

**992 · ⭐⭐ 「甩」和「拖」是两种意图，吸附判据要分开。**
　　只看距离：慢慢拖到 49% 会弹回去（用户觉得"我明明拉上来了"）；
　　只看速度：慢慢拖到底也定不住。
　　⇒ **速度优先、距离兜底**（这次 600px/s + 过半）。

**993 · ⭐⭐ 给「公共积木」加功能，用「可选参数 + 默认值」。**
　　`FdmTopBar` 被十几个页面共用，这次只加了一个默认 `null` 的参数
　　⇒ 老调用点**零改动**、行为与改动前完全一致。
　　（对照 3.50.2 的教训 946：加一种新「模式」时，忘了让它经过的每一处跟上 ——
　　  公共件上的改动，"不影响老路径"要能一眼看出来，才敢做。）

**994 · ⭐ 报错驱动，比"我看别的文件有所以我也加"可靠。**
　　这次的 `@OptIn` 是 kotlinc 一句话点出来的。**先跑一次、让编译器说**，
　　比通读一遍别人写的注解去猜"我该抄哪几条"更快也更准。
