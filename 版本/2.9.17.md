# FuckDSManger 2.9.17

> 综述：**真凶找到** —— 运行环境不提供 `de.robv.android.xposed.AndroidAppHelper`，
> 导致取 Context 全链路失败。改用 `GmEntry.sAct` + 反射 `ActivityThread`。
> 产物：`FuckDSManger_2.9.17_for_ds2.5.2.apk`（104 / 2.9.17，80 类，V1+V2+V3）

## 一、主人贴的真凶日志

```
FuckDSManger: GmEnv install FAIL |
  java.lang.NoClassDefFoundError: Failed resolution of: Lde/robv/android/xposed/AndroidAppHelper;
    at GmEnv.install(Unknown Source:24)
    at GmUtil.envSafe(Unknown Source:0)
    at DisableFlagSecure.handleLoadPackage(Unknown Source:38)
Caused by: ClassNotFoundException: Didn't find class "de.robv.android.xposed.AndroidAppHelper"
  on path: DexPathList[[dex file "InMemoryDexFile[...]"], ...]
```

**关键**：`XposedHelpers` / `XposedBridge` 都能用（前面几十条 hook 都成功了），
**唯独 `AndroidAppHelper` 在这个 LSPosed 环境里不存在** —— 它是 Xposed 的老 API，
不同 LSPosed 发行版/版本的 API 供给范围不一样。

### 1.1 为什么这是「设备身份伪装完全失效」的根因

```
GmDevice.ctx()  →  AndroidAppHelper.currentApplication()  →  NoClassDefFoundError  →  返回 null
   ↓
GmDevice.ensure() 拿不到 Context → 不 refresh → sOn 永远 false（默认关）
   ↓
GmDeviceHook 里 isOn() 永远 false → **从不替换 android_id** → x-device-id 不变
```

⇒ 功能"看起来装上了、开关也能点"，但**底层一次都没生效**。

### 1.2 波及范围（全模块 4 处）

| 类 | 位置 | 后果 |
|---|---|---|
| `GmDevice` | `ctx()` | ⭐ 设备身份伪装**完全失效**（本次真凶） |
| `GmEnv` | `install()` 尾部 | 打 `GmEnv install FAIL`，install 后半段（refresh/toast）不执行 |
| `GmSync` | `ctx()` | 返回 null ⇒ `reapplyAll()` 不执行（自定义招呼语/模型切换等不被重应用） |
| `GmDsHook3` | 类名写错成 `Landroid/app/AndroidAppHelper;` | 历史笔误，一直静默失败（本次未动，仅记录） |

## 二、修复：彻底不依赖任何 Xposed API 取 Context

### 2.1 新增 `GmUtil.app()`（统一入口）

```
app()
 ├─ 1) GmEntry.sAct        ← onResume 时记录的当前 Activity（**最可靠**）
 └─ 2) 反射 android.app.ActivityThread.currentApplication()
        （framework 隐藏 API，永远存在）
```

- 两条路都包 try/catch，失败返回 null，**绝不抛异常**
- 只用 framework 类 + ``（不碰任何 Xposed API）⇒ **免疫环境差异**

### 2.2 三处调用点改为走 `GmUtil.app()`

| 类 | 改动 |
|---|---|
| `GmDevice.ctx()` | 整个方法简化为 `return GmUtil.app();` |
| `GmSync.ctx()` | 同上 |
| `GmEnv.install` | `AndroidAppHelper.currentApplication()` → `GmUtil.app()` |

### 2.3 顺带：换掉 "已问过" 的键名

2.9.15 曾把 `fuckds_device_asked=true` 写进 MMKV（"先写标记再弹窗"的旧逻辑），
会让 2.9.16 之后的版本**不再弹**。⇒ 键名换成 **`fuckds_dev_ask2`**，绕开历史痕迹。

### 2.4 版本

`AndroidManifest.xml`：`103/2.9.16` → `104/2.9.17`

## 四、本轮教训（补充第十一节）

| # | 教训 |
|---|---|
| 88 | ⭐⭐ **不要依赖"老 Xposed API"里的非核心类**：`XposedBridge` / `XposedHelpers` / `XC_MethodHook` 是必给的，但 `AndroidAppHelper` 这类**不保证存在**（本环境直接 ClassNotFound）。要用 framework 类 + 反射兜底 |
| 89 | ⭐ **`GmEntry.sAct` 比任何"系统级"取 Context 的手段都可靠**：它是我们自己记下来的当前 Activity，不依赖隐藏 API、不依赖环境差异。取 Context 的优先级应是「**自己的缓存 → framework 反射 → Xposed API**」 |
| 90 | **一个类解析失败（`NoClassDefFoundError`）会沿调用链把整条功能打死，而且往往静默**（被 try/catch 吞成"返回 null"）。**凡是"返回 null 就当没配置"的写法，都要问一句：null 是"没设置"还是"环境不支持"？** 本次两者混在一起，排查了三轮才见底 |
| 91 | **旧标记要随逻辑变更换键名**：改判定逻辑时，历史写入的标记会变成"幽灵"（本次 `fuckds_device_asked`）。换键名是最省事的清场方式 |
