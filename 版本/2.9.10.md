# FuckDSManger 2.9.10

> 综述：**查明并修掉「修改助手图片 → 蓝色方块」的根因** —— Compose `Icon` 的 tint 把照片染成了单色。
>
> 相关：`专题/账号名与账号头像.md`

## 一、先说结论

「蓝色方块」不是解码失败、不是尺寸错、也不是 Drawable 有问题，而是：

> 助手头像那条绘制路径是**按图标（单色矢量）画的** —— `Icon(painter, tint = 主题色)`；
> tint 用 `SrcIn` **保留 alpha、把 RGB 全部换成 tint 色** ⇒ 照片 = 一块纯蓝方块。

## 二、助手头像的完整链路（**三条 hook 一起才生效**）

这块以前没写清楚，趁这次补全：

| 步骤 | 代码 | 作用 |
|---|---|---|
| ① 骗过矢量分支 | `GmVectorHook` hook `Resources.getValue` → 把 `TypedValue.string` 置 **null** | `painterResource` 里 `string.endsWith(".xml")` 判断失效 ⇒ 不再走 `getXml` 解析矢量 |
| ② 换掉 painter | `GmPainterHook` hook `kf5;->K`（= `painterResource`）的 `afterHookedMethod` | `BitmapFactory.decodeFile` → `newInstance("le", bmp)`（`AndroidImageBitmap`）→ `newInstance("ok0", …)`（`BitmapPainter`）→ `setResult` |
| ③ 画（**出问题的地方**） | 宿主 `Lbka;->c`（消息列表项）→ `Lme4;->a(painter, desc, modifier, **tint**, …)`（= Material3 `Icon`） | 这里带 tint |

> 顺带确认：`0x7f070059` = `assistant_message_avatar`（`res/Fi.xml`），**它是矢量**
> （二进制 XML 里是 `viewportWidth/Height` + `pathData`）⇒ 单靠 `Resources.getDrawable` hook 毫无作用，
> **必须有 ① 那一步**先把矢量分支骗掉。

## 三、tint 是怎么把照片变成纯色块的

`Icon` 的反编译（`Lme4;->a`）：

```
sget-wide v13, Lq32;->h:J                     # Lq32 = androidx.compose.ui.graphics.Color
invoke-static {tint, v13}, Lq32;->c(JJ)Z      # Color.equals(tint, Lq32->h)
if 相等  -> colorFilter = null                # 不染色
else     -> colorFilter = ColorFilter.tint(tint)      # new Lvk0(5, tint)
```

- `Lq32;->h` 就是 **`Color.Unspecified`**
  （`<clinit>`：`r = g = b = a = 0f` + `g42->u` = `ColorSpaces.Unspecified` 打包而成）
- 这里传入的 tint 是 `Lup2->e:Llv;->a:J`（主题色 = **品牌蓝**）
- `ColorFilter.tint` 默认 `SrcIn` ⇒ **alpha 保留、RGB 全换** ⇒ 彩色照片必然变成纯色块

## 四、修法：把 tint 中和掉

新增 `GmIconHook`，hook **`me4;->a`**（`Icon`）的 `beforeHookedMethod`：

```
if (args[0] === GmPainterHook.sPainter)            // 只认我们自己造的那个 BitmapPainter
    args[3] = getStaticLongField(findClass("q32", cl), "h")   // = Color.Unspecified
```

- 用**运行时反射**读 `Color.Unspecified`，**不硬编码那个魔数**（Compose 换版本也不怕）
- **身份比对**保证只影响助手头像这一处，其它图标一律放行
- 顺带把 `GmPainterHook.sPainter` 从 `private` 放开为包可见（供比身份）

## 九、教训（补充第十一节）

**第 61 条：`Icon(painter, tint=…)` 会把任何 painter 染成单色。**
Compose 的 `Icon` 默认 `tint = LocalContentColor`，内部用 `ColorFilter.tint`（`SrcIn`）实现：
**alpha 保留、RGB 全替换** ⇒ 彩色照片必然变纯色块。
往「本来是画单色图标」的位置塞位图，第一嫌疑就是它。
- **判据**：反编译 `Icon` 附近出现 `Color.Unspecified` 比较 + `ColorFilter.tint` 构造
- **修法**：在该调用点把 tint 换成 `Color.Unspecified`（= 不染色）

**第 62 条：读宿主常量优先用「运行时反射」，别硬编码魔数。**
`Color.Unspecified` 这种打包 long 每版都可能变；用
`getStaticLongField(findClass(<Color 类>, cl), <字段>)` 现场读，稳且省事。

**第 63 条：一个功能可能靠「多条 hook 接力」才生效，排查时要把链路画全。**
助手头像就是 `Resources.getValue`（骗分支）+ `painterResource`（换 painter）+ `Icon`（染色）三段接力；
只盯着其中一段看，永远解释不通「为什么 hook 明明挂着却没效果 / 为什么效果长这样」。
