## 2. 「捕获器还是抓不到记录」—— 两个**我自己埋的**坑

### 坑一（致命）：`show()` 的"已存在就 return"把**再武装**也吃掉了

```smali
sget-object v0, GmProbe->sInst
if-eqz v0, :go          # 悬浮点已存在 ⇒ 跳过去继续建
…
:go
…
sput-object v2, sInst
<武装 sProbeArm = true>   ← ★ 武装在这里
```

⇒ **只要 `sInst` 不为空（悬浮点已经挂过一次），`show()` 就 `return-void`，`sProbeArm` 根本不会被设上。**
⇒ 拨开关 = **Toast 说"已开启"，但 `dg()` 那扇门一直是关的** ⇒ **一条记录都不产生**。

**修法：把"武装 + 清缓冲 + 清零计数"移到存在性守卫**之前** ⇒ 每次拨到开都重新武装。**

```smali
:try_start_0
sProbeArm = true          # ★ 先武装（无副作用、幂等）
sProbeLog = null          # 清缓冲
sPgLogCnt = 0             # ★ 清采样计数（下次采集是干净的一窗）
sget-object v0, sInst
if-eqz v0, :go
return-void               # 已存在 ⇒ 不再重复创建视图（但武装已经做完了）
:go
```

### 坑二：进「模块日志」的记录窗口只有 8 条，且计数**从不清零**

- `dg()` 的 logcat/DIAG 门：`cnt <= 8` ⇒ **只有武装后的前 8 条绘制**会进 DIAG
- 而 `sPgLogCnt` 之前**不在武装时清零** ⇒ 反复武装时窗口可能一开始就是"用过的"状态

**修法**：门放到 **`0x18`（24 条）**；并在 `show()` 里把 `sPgLogCnt` **归零**（见坑一的代码）。

## 5. 教训（166~169）

| # | 内容 |
|---|---|
| **166** | ⭐⭐⭐ **"已存在就直接 return"的守卫，会把"每次调用都该做的副作用"一起吃掉** —— `show()` 的 `if (sInst != null) return;` 挡住了后面的"武装"。⇒ **铁律：把"不该重复做的事"（建视图）放在守卫后，把"每次都必须生效的事"（武装/清零/写状态）放在守卫前。** 判断方法是问一句：**"这个副作用，第二次调用时也需要发生吗？"** |
| **167** | ⭐⭐ **采样类功能的计数器，要在"开始采样"时归零** —— `sPgLogCnt` 不清零 ⇒ 反复武装时窗口状态不可预期。⇒ **"开始采集"= 一个明确的动作（武装），它应当把"采集相关状态"全部复位**（缓冲、计数、起点）。 |
| **168** | ⭐ **实验用的极端参数要记得收回，并在交付时标注**：`alpha=0` 是为了"一眼看出有没有效果"而选的极端值，效果确认后必须回到可用值（`0x80`）。⇒ **交付"实验版"时，在文档和回执里都写清"这个值是实验值，确认后要换"。** |
| **169** | ⭐⭐ **"Toast 说已开启"≠"功能真的在采集"** —— `GmProbeSwitch` 弹了 Toast，但 `sProbeArm` 没被设上。⇒ **凡是"开关 → 状态 → 行为"三段式的功能，开关的回执必须读"**状态**"，而不是"点击事件发生了"**（本版已让 Toast 之外还有模块日志的 `捕获器：已挂上` 作为状态证据）。 |
