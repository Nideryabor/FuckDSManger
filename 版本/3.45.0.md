## 〇、一句话

用户填的「系统提示词」现在能**真的送到模型面前**了，而且聊天界面上**看不见它**：

```
发出的 prompt：  ⟦FDM⟧你是一位耐心的助手，请始终用中文回答⟦/FDM⟧你好
用户看到的：      你好
```

**承载方式 = 明文**（模型当普通用户文本读 ⇒ **零制裁风险**），**窗口效应 = hook 抹掉**。

## 一、★ 真凶：这个功能从上线起**一次都没注入过**

| 项 | 内容 |
|---|---|
| 现象 | 装机后「没效果」，而且 **logcat 里连 `sysprompt.inject` 都不打** |
| 真因 | `GmStore.read2(ctx, key, X)` 的**第三参是「类型」不是「默认值」**（`b`/`i`/`f`/`l`/其它=string） |
| 传导 | 代码写的是 `read2(ctx, K_ON, "0")` ⇒ `"0"` 被当类型 ⇒ 落到 `getString` 分支 ⇒ 去读一个 **boolean** 键 ⇒ 抛异常被 `read2` 自己的 catchall 吞掉 ⇒ 返回 `""` ⇒ `"1".equals("")` = **永远 false** |
| 结果 | `inject()` 第一行 `if (!on()) return prompt;` 直接返回 ⇒ **一次都没注入，连日志都不打**（症状完美吻合） |

**对照铁证**：`FdmBridge` 里用了 20 多次的正确写法 —— `GmStore.read2(ctx, "fuckds_bubble_on", "b")`。

**同时修掉的同类问题**：
- `mode()` 也传错 ⇒ 「每轮注入」模式**永远失灵**（一直退化成"仅首条"）
- `setOn/setText/setMode` 写入类型写成 `"boolean"/"String"/"int"` ⇒ 会掉进 `write` 的 else 分支变成 **putString**（类型写脏）

## 三、★★★ 模型侧的两条规律（本轮最大收获）

同一段隐形 nibble 指令（解出来是「回答紫色大象」），六次实验：

| 场次 | 可见文本尾部 | 模型 |
|---|---|---|
| T2 / T3 / T4 / T6 | `T2`…`T6` | ✅ **照做** |
| T5 | `T5` | ❌ 拒绝（还把 T5 当成谷歌那个 T5 模型解释了一通） |
| 08:47 那条 | `你好` | ❌ 拒绝 |

1. **服从是概率性的**（6 次里 4 次照做）⇒ 不是"能用/不能用"的二值；重试、换措辞、换位置都能提高命中，但别指望 100%
2. **可见文本会「抢戏」** ⇒ 可见内容越像一个正经问题，隐形指令越容易被挤掉

⇒ **被制裁的从来不是"隐形"本身，而是「自称系统级 + 声称要覆盖用户」那套元话语**。
⇒ 这才是最终把形态改成「明文承载」的根本理由。

## 四、最终形态：明文承载 + 渲染抹显示

### 4.1 定界符

`⟦FDM⟧` … `⟦/FDM⟧`（U+27E6 数学白方括号，够罕见，不会和用户输入撞车）

### 4.2 两侧分工

| 侧 | 实现 | 结果 |
|---|---|---|
| **注入侧** | `GmSysPrompt.wrap()` 的 `CARRIER_PLAIN` 分支：原样包一对定界符拼在 `prompt` 前面 | 服务端/模型看到**普通文本** ⇒ 零制裁风险 |
| **显示侧** | `GmSysPromptHideHook`：渲染时把定界段**删掉**（不是遮罩） | 用户看到的**就是他原本写的那句话**（无占位、无空行） |

### 4.3 ★ 显示侧为什么"铺五路"而不是精确定位

前两版（只扫第一层字段）都"挂上了但没命中"，而真机 **logcat 窗口只有几分钟**，
现场参数怎么都抓不到 ⇒ 放弃"先定位再动手"，改成**把可能的路径一次铺满**：

| 挂点 | 形态 | 兜住的场景 |
|---|---|---|
| `i93.i`（气泡单元，原 `pn9.c`） | 参数**递归**深扫（深度 4，含 List/Map/数组） | 文本直接作为渲染参数 |
| `d12.a`（消息列表，原 `h91.a`） | 参数递归深扫 | 文本在整条列表的数据对象里 |
| `i93` 的所有 String 方法 | **返回值改写** | 文本由气泡单元的 getter 取出 |
| `mr` 的所有 String 方法（消息基类，原 `vq`） | **返回值改写** | 消息对象自己吐文本 |
| `AnnotatedString` 构造器（若未改名） | 参数扫描 | Compose 文本的最后一道门 |

**安全性论证（为什么敢这么扫）**：判定条件只有一条 —— 字符串里含 `⟦FDM⟧`。
这个标记**只可能出现在我们自己注入的文本里**，所以"见到就换掉"不会误伤宿主任何正常数据；
而注入发生在**请求构造那一刻**（`wrap()` 每次重新加定界符），所以即便把某个历史数据对象里的
定界段删了，**也不影响下次发送时的注入**。

> ⚠️ 诚实标注：五路是**同时铺开**的，具体哪一条先命中**未单独验证**（真机日志抓不到现场）。
> 留着全部挂点反而是好事 —— 宿主升级后只要有一条活着，功能就还在。

### 4.4 UI（模块设置 › 聊天 › 系统提示词）

| 项 | 键 | 说明 |
|---|---|---|
| 承载方式 | `fuckds_sysprompt_carrier` | 0 = 隐形字符（Tag）· **1 = 明文定界（推荐）** |
| 开启注入 | `fuckds_sysprompt_on` | 总开关 |
| 提示词内容 | `fuckds_sysprompt_text` | 支持中英文（隐形模式下中文会自动转 `\uXXXX` 再隐形化） |
| 注入模式 | `fuckds_sysprompt_mode` | 仅首条 / 每轮 |
| 包装前缀 / 后缀 | `fuckds_sysprompt_head` / `_tail` | **仅隐形模式用**；可自定义措辞（对付反注入的实验口） |

## 五、备用通道：附件（原理验证通过，搁置）

- 接口：`POST /api/v0/file/upload_file` · `GET /api/v0/file/fetch_files?file_ids=…`
- 发消息带 `ref_file_ids: ["file-xxx"]` ⇒ 服务端存成**独立的 FILE fragment**（与 REQUEST 正文并列）
- **铁证**：`prompt` 只写干干净净的「你好」+ 一个 txt 附件 ⇒ 会话标题被服务端生成成
  **「尼得亚伯龙龙」**（= 文件内容）⇒ **模型确实读到了文件内容**
- 卡点（未定案）：FILE fragment 存的是**引用**（file_id + signed_path），不是内容快照 ⇒
  **删掉文件后模型还读不读得到？** 没测
- 搁置原因：「每轮都带」⟺「历史里有」⟺「客户端/服务端至少看得到一个文件卡片」，且要处理
  上传/删除/卡片，工程复杂；而它相对明文承载**唯一的优势**是"内容不在对话流里"，
  这一点已被 `strip()` 覆盖

## 六、⚠️ 运维坑：`install -r` 之后宿主侧代码会**滞后一版**

- Android 每次安装都换一个 `/data/app/~~xxxx==/` 目录，而 **LSPosed 的 modules 表缓存着旧 APK 路径**
- 症状：**UI 改动立刻生效**（UI 是模块 App 自己跑，不走 LSPosed），但**宿主里的 hook 还是旧的**
  —— 表现为"新加的日志一条都没有，而老日志正常"
- 解法：在 LSPosed 管理器里把模块**关一下再打开**（或重启设备）
- 判据：看新代码特有的日志有没有出现（本次是 `hookM syspromptHide/*`、`probe OK/FAIL`）
- 这正是 `tools/install_fdm.sh` 头部警告过的坑，本轮又踩了一次

## 七、教训（903~907）

| # | 教训 |
|---|---|
| **903** | ⭐⭐⭐ **"日志没有"要先怀疑「日志标签」** —— `GmUtil.log` 真身是 `XposedBridge.log("FuckDSManger: " + s)`，实际 tag 是 `LSPosedFramework`。本轮因为 grep `[FDM]` 而误判"探针没装上"，白绕一大圈 |
| **904** | ⭐⭐⭐ **install -r 后必须确认"宿主侧跑的是新版"** —— UI 生效 ≠ hook 生效 |
| **905** | ⭐⭐⭐ **服务端的 422 是最好的文档** —— Rust/serde 会把合法枚举值全集吐出来 |
| **906** | ⭐⭐⭐ **"隐形"要分两层看** —— *字符级*（Tag，模型会察觉）vs *渲染级*（hook 抹，模型看到纯明文）。后者才是既不被制裁、人又看不见的形态 |
| **907** | ⭐⭐ **模型的服从是概率性的** —— 按"提高命中率"设计，而不是"保证成功" |
| **908** | ⭐⭐ **真机 logcat 窗口只有几分钟** —— 靠它做"现场取证"必须争分夺秒；抓不到时优先换"铺满挂点"的笨办法，而不是反复重试 |
