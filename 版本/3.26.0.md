# 3.26.0（vc530）—— 【致命】GmStore.write 参数顺序反了

> 2026-09-27 · 尼得亚伯 🐲
> 产物：`out/FDM-3.26.0-single-signed.apk`
> sha256 `f48cc5557757fe409f1e7eea9e0c15942d7563163af367cb1a5f800aecf1fcc8`

## 一、怎么发现的

**3.25.0 刚修好的 DS DATA 一眼就照出来了：**

```
kv_settings_search_state_on_login                = s     ← ！！！
kv_settings_search_state_on_launch               = s
kv_settings_search_state_on_manually_created_chat   = s
kv_settings_search_state_on_automatically_created_chat = s
```

**覆盖层里存的不是 `on`/`off`/`keep`，是字符串 `"s"`。**

## 二、病根：桩（stub）把参数顺序写反了

底座真身（反编译 `GmStore.smali`）：

```smali
.method static write(Context p0, String p1, String p2, String p3)V
    ed = sp.edit()
    if ("b".equals(p3))                          ← p3 是【类型】
        ed.putBoolean(p1, parseBoolean(p2))      ← p1=键  p2=【值】
```

**⇒ 真身是 `write(ctx, key, 值, 类型)` —— 类型在最后一个参数。**

铁证是 `bak()` 内部的调用：

```smali
invoke-static {p0, v1, v0, v2}, GmStore;->write(...)V
                 ctx 备份键 原值 "s"(类型)
```

**而我们的桩注释写成 `write(ctx, key, type, val)`** ⇒ 桥照着桩调
⇒ `write(ctx, key, "s", "on")` ⇒ **值槽收到 `"s"`、类型槽收到 `"on"`**
⇒ 类型不认识 ⇒ 落到 `putString(键, "s")` ⇒ **存进去的永远是 `"s"`**。

## 三、这一下把两个怪现象一并解释了

| 现象 | 原因 |
|---|---|
| 「搜索能开」 | `"s"` ≠ `"keep"` ⇒ 宿主判定为"非跟随" ⇒ **当作开** |
| 「改成 off 关不掉」 | 写进去的还是 `"s"` ⇒ 照样≠keep ⇒ **永远开** |

**⇒ 不是时机问题，是参数错位。**

## 四、修法

```java
// 之前（跟桩）
GmStore.write(ctx, realKey, type, val);
// 现在（跟底座真身）
GmStore.write(ctx, realKey, val, type);
```

同时把桩的注释彻底改写（跟错注释调过一次就够了），并在里面写死：
**`type`：`b`/`i`/`l`/`f`/`s`（`s` = string，不是 `t`）。**

## 五、真机验证

```
kv_settings_search_state_on_login                   旧 \x02\x01 s   → 新 \x03\x02 on  ✅
kv_settings_search_state_on_manually_created_chat   旧 \x02\x01 s   → 新 \x03\x02 on  ✅
```

（`\x03\x02 on` = 长度 3 含结尾 NUL + 类型 = 字符串 `"on"`）

症状是「tail: grep: No such file」「cat: Unknown option 'aoE'」这类诡异报错。
已把这个教训写进脚本头注释（我为此反复栽了三次）。
