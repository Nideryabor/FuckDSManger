## 一、指纹日志一次说清四件事

```
候选: see=null pair=d748c29@null new=d748c29@null j=null
      ↑没人        ↑同一实例（hash 相同）        ↑同一实例        ↑还没被 J 抓过
                          ↑↑ 会话读出来是 null
```

1. `pair` 与 `new` **是同一个实例**（说明只有一个 component 被我们握着）；
2. `see=null` ⇒ `h91.a` 的参数里**没有 `ao1`**（这条捕获点作废，可留作后备）；
3. **`@null`** ⇒ 该实例的"会话"读出来是空；
4. **但同一个实例调 `I()` 能发消息**（`I()` 里 `wr.a` 那步会 NPE，发不出去）⇒ **说明 `wr.a` 压根不是"会话"，实战里它就是 null**。

## 二、宿主自己的"会话 id"是这么取的

再读 `I()` 里跟会话有关的**两处**：

```java
v2  = wr.a                    // 只进遥测 tya.l(...)
v11 = wr.h() ?: this.N()      // ⭐ 这个才是"会话 id"的取法
```

⭐ **`wr.h()` 在整个 dex 里只被调用 1 次** —— 就是这一处。**"只用一次"通常意味着"这就是它的唯一用途"**。

⇒ 我前三版（`wr.a` / `L().a`）都在猜，**这版直接照抄宿主的表达式**。

## 三、2.14.8 的改法

```java
sid(ao1):
    wr = ao1.M()                 // ((ho1)this.v.getValue()).b()
    if (wr != null) {
        s = wr.h()               // 新helper hid()，独立 try/catch
        if (s 非空) return s
    }
    return ao1.N()               // 兜底：z09.getValue()
```

⇒ 选择逻辑不变（4 候选取"会话 id 非空"的第一个），但**这次"会话 id"是宿主认可的那一个**。
⇒ 指纹行会直接显示真 id（例：`pair=d748c29@1f4f3f9c-…`），一眼能验证。

## 六、教训

| # | 教训 |
|---|---|
| **532** | ⭐⭐⭐ **"只用一次的方法"往往是"它的唯一用途"**：`wr.h()` 全 dex 仅 1 处调用（就在取会话 id 那里）⇒ 这类信号比任何命名/位置推断都硬。**找字段/方法含义时，先看"调用次数"**。 |
| **533** | ⭐⭐⭐ **指纹（identityHashCode）是分诊利器**：`pair=new` 一眼看出"只有一个实例"、`@null` 一眼看出"属性读不到"，省掉了两轮"是不是同一个/是不是没读到"的猜测。**诊断输出带上它，成本几乎为零。** |
| **534** | ⭐⭐ **同一处猜错三次的根因是"没照抄宿主表达式"**：`wr.a` / `L().a` / `wr.h()` 三个候选，正确做法不是三选一猜，而是**把宿主自己那一行代码原样搬进 `sid()`**。**语义可疑时，"与宿主同构"永远是最低风险的实现。** |
