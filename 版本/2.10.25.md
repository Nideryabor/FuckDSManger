## 一、先核对方法再调用（吸取 2.10.23 的教训）

这次先把 `GmSuggestHook` 的**全部 28 个成员**列出来核对 ⇒ 发现：

| 方法 | 存在？ |
|---|---|
| `build()Ljava/util/List;` | ✅ **存在**（无参，返回我们自建的对象列表；内部走 `findClass("g56")` + `make` + 缓存） |
| `make(Ljava/lang/Class;ILjava/lang/String;)Ljava/lang/Object;` | ✅ 存在（**3 参**） |
| ~~`make(I)Ljava/util/List;`~~ | ❌ **不存在** ⇒ 这正是 2.10.23 崩溃的原因（我把签名写错了） |
| `tryCtor(Constructor,int,String)` / `dumpCtors(Class)` / `put` / `putInt` / `str` | ✅ 全在 |

⇒ 正确的入口是 **`build()`**。

## 二、本版改动

宿主列表为空 ⇒ 调 `GmSuggestHook.build()`：

```smali
    invoke-static {}, …->build()Ljava/util/List;
    move-result-object v3
    if-eqz v3, :self_fail
    → noteOk("自建列表成功（空列表兜底）") + 返回该列表
    :self_fail
    → note("退出:宿主列表空且自建失败")
```

## 三、两种结果都会给出下一步

| 现象 | 含义 | 下一步 |
|---|---|---|
| chip 显示**我们的文字**（`最优：自建列表成功…`） | 🎉 **通了** | 收尾：场景区分 / 清理诊断 / 文档 |
| `最优：(还没有成功过)` + `最后：退出:宿主列表空且自建失败` | `build()` 失败 | 日志会有 **`[建议] g56 构造器 → …`**（`dumpCtors` 输出宿主真实构造器签名）+ `suggest build FAIL` ⇒ 按真实签名精修 `tryCtor` |

## 四、教训

| # | 教训 |
|---|---|
| 205 | ⭐⭐⭐ **调用前先核对签名**（`make(I)` 与 `make(Class,int,String)` 是两回事）—— 有了「列出类成员」这个手段就该每次都用；`NoSuchMethodError` 只在运行时爆 |
