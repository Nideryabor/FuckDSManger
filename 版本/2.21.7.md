## 一、主人回执（一次非常准的观察）

> 「背景找得不太好：**只修改了输出时文字的背景**，但**助手图片附近以及已思考的标题处仍然是黑的**；

**最后那句是钥匙**：长按高亮覆盖「标题+头像+内容」⇒ **存在一个把三者包在一起的可点容器**，那才是「气泡」的容器。

但那个 Modifier 是**上层用来给「内容列」定位/撑宽**的 ⇒ 只作用于内容块 ✓ 现象完全吻合。

## 二、两个改动

### 1️⃣ 注入层级上移：`c30.a` → **`pn9.c`**

```
xref Lc30;->a(...) → 唯一真正的 Composable 调用者：
Lpn9;->c(ILpe5;Ljb1;Lwr;Lvq;Lc76;Ley3;I)V      ★ 助手消息「项」级 Composable
      └─ 第 6 个参数就是 Lc76;(=Modifier) = 【整条消息项】的 Modifier
```
（`pn9.c` 在 2.21.2 的崩溃栈里也出现过：`at pn9.c(...:1210)` ✓ 与「组合链上层」吻合）

**改动只有注册里一个词** —— 因为钩子当初就是「**扫 args 里第一个 instance-of `c76` 的实参**」而不是写死下标
（`c30.a` 里是 args[11]，`pn9.c` 里是 args[5]，钩子代码一行没动）✓
顺带：作用域 `sDepth` 自动变成「整个消息项」⇒ 替换路线的覆盖面也跟着变大 ✓

### 2️⃣ 🐛 修「同一个错误只改了一半」——`GmBubblePaintHook` 从来没装上过

回读入口时发现注册表里还是：
```smali

const-string v3, "...GmBubblePaintHook"
```
2.21.3 我只把 **`GmBubble.wrap()` 里面**的 `"Luia"` 改成了 `"uia"`，**注册表那两行忘了改** ⇒
- `hookM` 里 `findClass("Luia")` 直接失败 ⇒ **paint hook 从未安装**
- ⇒ 「替换路线」（`uia.v`/`uia.u` 的参数替换）**一直没生效**
- ⇒ 也一直没有 `[气泡][v]` / `[气泡][u]` 日志，以及 `sCntV/sCntU` 恒为 0 —— **全都对上了**

本版把两条注册都改成 **`"uia"`** ✓

## 六、教训

| # | 要点 |
|---|---|
| **657** | ⭐⭐⭐ **「要美化哪一块」= 先找「哪一块会被当作一个整体响应交互」**。主人一句「长按高亮覆盖 标题+头像+内容」直接点出**正确的容器层级** —— **交互边界就是视觉容器边界**，比读一堆 Compose smali 都快。 |
| **658** | ⭐⭐ **注入点要问「这个 Modifier 在上层是干什么用的」**：同样是 `Modifier` 参数，**项级**（撑宽/点击）与**内容列级**（定位）语义不同；注错层级 → 只裹住一半。 |
| **659** | ⭐⭐ **钩子写成「扫参数类型」而非「写死下标」，换挂点就是零成本**（本轮从 `c30.a` 换到 `pn9.c`，下标 11→5，钩子代码一行没动）。 |
| **660** | ⭐⭐⭐ **修一个「名字/常量写错」的 bug 时，必须全局搜同一个错误串**（教训 268 的兄弟：`grep -c "Luia"` 就能一把捞干净）。本次只在 `wrap()` 改对了，**注册表漏了**⇒ 症状是「功能半死 + 诊断全无」，极难看出。 |
| **661** | ⭐⭐ **回读产物是唯一能抓这类漏网的地方**：`edit_check` 全绿、构建全绿，**但注册表里那两行就是错的**——因为它在语法上完全合法。**每次回读都顺便当一次「代码审查」。** |
