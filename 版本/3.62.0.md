## 〇、一句话

**那个「提示词内容」字段变成了"派生值"：系统提示词正文 = 容器里卡片们的内容按顺序拼。**

    回复建议（卡） ⇒ 它自带的【追问建议】约定
    音乐（卡）     ⇒ 它自带的【音乐变量】示例
    富文本（卡）   ⇒ 它自带的【回答排版】约定
    自定义文本卡   ⇒ 卡片里写的字（默认「这是尼尼的卡片」）

* 段间 **空一行**（`\n\n`）
* **容器空 ⇒ 文本字段清空**（主人确认过这个语义）—— 之前那些"灌进去的段落"从此由**卡片**承载
* ⇒ `⋮ 更多` 里的「提示词内容」**撤了**（它成了抽屉里那张卡片）

## 一、三种卡片、三套手势

| 卡片 | 手势 |
|---|---|
| **内置三张**（回复建议 / 音乐 / 富文本） | **搬** —— 拖进容器 = 这一段进提示词；拖回抽屉 = 这一段不进（因为要重算）。右边 ▸ 跳对应页 |
| **「系统提示词内容」源卡片** | **复制** —— 拖进容器 ⇒ **长出一张新副本**（源卡留在抽屉，能**无限拖**）；没 ▸、**不可删** |
| **自定义文本副本** | 展开 = 编辑标题/正文/「标题也进提示词」；**暂存在抽屉时**右边出现**红色删除**（二次确认）；再拖回容器 = **搬家** |

* 新建副本的默认：标题 **「点我编辑」** · 正文 **「这是尼尼的卡片」** · 「标题也进提示词」**默认关**
* 卡片展开的**形态**：标题行左边一个 ✏（点了就地编辑标题）；展开区是正文文本框 + 标题开关 + 一个「提交」按钮
* **写回时机**（主人定）：**文本失焦 / 收起卡片时提交** —— 不边敲边往宿主发广播；
  **摆放变化**（搬进搬出 / 删除 / 切开关）**立刻**重算

## 二、桥侧：新增 `prompt_compose`（让宿主自己拼）

**为什么拼在宿主**：那三段"自带内容"的**真身**在模块类里
（`GmRichText.suggestSpec()` / `GmPromptVars.spec()` / `GmRichText.spec()`，
还会跟着模板池变）⇒ 界面只送**类型名**，文案由宿主自己取 ⇒ **不抄第二份**。

```json
arg = {"items":[{"t":"suggest"},{"t":"text","title":"…","text":"…","withTitle":true}]}
```

宿主逐个取内容、`trim` 后 `\n\n` 拼接 ⇒ `GmSysPrompt.setText(out)` ⇒ 回执"几段/几字"。

**顺带**：`cfg_state` 多回一个 `sysprompt_text` —— 给源卡片**播种**用
（第一次进来读一次宿主那个字段的原字，装进源卡片，免得旧内容"没地方找"）。

> 上一版（3.61.0）那套「拖进 = merge 一段 / 拖回 = 摘一段」的 `spec_*` / `spec_remove`
> **不再是主路径**了：现在靠"重算整段"。（命令还留着当后门，不动它。）

## 七、3.62.1（vc683）—— 补一个我自己抓出来的真 bug

**症状**：改**标题**的时候，标题会被写进**正文**里。

**真因**：标题和正文**共用同一个输入缓冲** `editBuf`，而 `flushEdit()` 只看缓冲、
**没看"这次编辑的到底是哪一个"** ——

```kotlin
if (editBuf != c.text) { c.text = editBuf; commit() }     // ✗ 编辑标题时也走这条
```

⇒ 改标题（标题短、正文长）⇒ 提交时把标题当成正文写进去；而且**新建卡片的默认正文「这是尼尼的卡片」会被覆盖**。

**修法**：
* `flushEdit()` 按 `editTitle` 分流（标题进 `title`、正文进 `text`）
* 新增 `beginEdit(key, title)`：**切到"编辑标题 ⇄ 编辑正文 ⇄ 另一张卡"之前，先把上一次的编辑收干净**
  （顺便修掉"改了标题没失焦就点正文 ⇒ 标题那一笔丢了"）
* 展开/收起一律先 `flushEdit()`

**产物** `FDM-3.62.1-single-signed.apk`（vc683 · 8077710 B）sha256 `e0971a85…`，已装机（`versionName=3.62.1`）。

> **1014 · ⭐⭐⭐ 两个输入共用一份缓冲时，"提交"必须知道自己在提交哪一个。**
> 　　`editBuf` 同时服务标题与正文 ⇒ 提交逻辑必须带**上下文**（`editTitle`）。
> 　　⇒ 凡"一个缓冲服务多个目标"的地方，问一句：**提交的那一刻，我凭什么知道这笔属于谁？**

> **1015 · ⭐⭐ 交付前的那一遍自查，比多写一段代码值。**
> 　　这个 bug 不是主人发现的 —— 是我在写文档前把"编辑链路"在脑子里过了一遍才看见的
> 　　（**改标题 → 缓冲 → 提交 → 写进 text**）。⇒ 交付清单里加一条：
> 　　**"每个输入/开关，走一遍'改了会发生什么'"**。

> **1016 · ⭐⭐⭐ 「改文件」和「跑构建」并排发 —— 这一版又踩了（第四次）。**
> 　　3.62.0 / 3.62.1 两次构建都出现过"编出来的是中间态"，只能重编确认。
> 　　⇒ 从这一节起把它当**硬规矩**：**构建/安装/推送这类"读世界"的命令，
> 　　必须在所有写命令都落定之后单独发一条。**

## 八、3.62.2（vc684）—— 主人实测抓到的两个 bug（都是我的锅）

### bug ① 抽屉里那三张内置卡「被当夜宵吃了」

**现象**（主人）：「之前的抽屉三个卡片被你当夜宵了」

**真因**：**存档兼容性**。3.60 / 3.61 那套格式的存档**只有 id 列表、没有 `cards` 表**；
而我在 3.62.0 写的归一化要求「**卡片表里得有这一张**」才认 ⇒
三张内置卡（`suggest` / `music` / `richtext`）被当成脏数据**整批丢掉**，
丢掉之后**又被写回存档** ⇒ **永久丢失**。

**存档实锤**（读我们自己的 SP，`cfg.sysprompt_v2_layout`）：

```json
{"drawer":["textsrc"], "box":["text#1"], …}      ← 三张内置卡确实没了
```

**修法两条**：

* 内置三张 + 源卡片的**键就是它自己的类型名** ⇒ 卡片表里没有也能**现造**；
* 「两边都没有」的它们**补回抽屉** —— 它们本来就**删不掉**（没有删除按钮），
  所以"失踪"只可能是存档坏了，补回来是安全的。

**验证**：装 3.62.2 之后主人又试了一轮，存档变成
`{"drawer":["textsrc"],"box":["music","suggest","text#3","richtext","text#2",…]}` ——
**三张内置卡回来了**，而且他把它们都拖进了容器、还复制出 `text#1..#7` ⇒ 自愈生效 ✅

> **1017 · ⭐⭐⭐ 改数据格式时，「读」永远要比「写」宽容一个版本。**
> 　　我把「卡片表里有它」当成了卡片存在与否的**唯一判据**，而旧存档里根本没有那张表 ——
> 　　**读旧存档时，不许按新格式的完备性去要求它。**
> 　　⇒ 规则：**判别「这东西在不在」要退回到最原始的线索**（这里：id 列表 + 「内置卡的键就是类型名」），
> 　　并且在**写回之前**先把缺的补回来（否则一次误读就把数据永久改坏）。

### bug ② 标题「没法正常退出」

**现象**（主人）：「标题没法正常退出，改成回车自动保存+失焦」

**真因**：标题输入框只认「收起卡片 / 切到别的编辑目标」这两条退出路径 ——
**敲完字既没有"完成"按钮、也没有失焦处理**，人就卡在里面了。

**修法**（按主人给的方案）：

* **回车（IME Done）= 保存并退出** · **失焦 = 保存并退出**
* 进来**自动拿焦点**（点了 ✏ 直接能敲）
* 正文输入框一并改成**焦点驱动**（拿到焦点 = 开始编辑、失焦 = 保存），
  顺手把原来那坨「监听 `pointerInput` 里有没有按下」的脏手法删了（那版还会漏事件）
* ★ 加了一道 `hadFocus` 闸：输入框刚出现在组合里时会先报一次「未聚焦」，
  不加闸就会被当成「失焦」⇒ **一个字都没敲就退出了**

**主人那边的印证**：他展开的那张 `text#1` 正文仍是默认值「这是尼尼的卡片」，
标题也还是「点我编辑」⇒ **那一笔编辑确实没落下去**（正是这个 bug）。

### 顺带确认的两件事

* **你自己的正文没有丢**：本地 `cfg.fuckds_sysprompt_text` 一直是 **0 字**
  ⇒ 你以前没有在那个框里手写过内容（用的都是"灌入"按钮），所以这次事故没吃掉任何你的字。
* **宿主侧桥还是旧的**：让宿主现跑一次 `cfg_state`，回的 31 个键里**没有**新加的 `sysprompt_text`
  ⇒ 说明**模块在宿主里是活着的**（LSPosed 路径没问题），只是**进程没重启**：
  **`prompt_compose` 还没生效** ⇒ 现在拖卡片，宿主那个字段**还不会跟着变**。重启宿主即可。

**产物** `FDM-3.62.2-single-signed.apk`（vc684 · 8077703 B）sha256 `8f7137fa…`，已装机（`versionName=3.62.2`）。

> **1018 · ⭐⭐⭐ 一个输入框，必须给用户至少一条「明确的退出/保存」路径，而且最好是回车。**
> 　　我写了「失焦提交」，却**没给失焦的机会**（敲字时焦点一直在框里）——
> 　　**「能提交」和「能退出」是两件事。**（对照 3.55.1：便签那次也是「编辑中不刷新」埋的坑。）
