## 1. ⭐ 本次真正的教训：`if-nez` / `if-eqz` 的反向

**这是本项目第 N 次栽在同一类坑上（教训 100 / 826 同源）**，而这次是**成片**写反的。语义必须先背死：

```
if-eqz  vA, :label   ⇒  跳转条件 = (vA == 0)      「等于 0 就跳」
if-nez  vA, :label   ⇒  跳转条件 = (vA != 0)      「不等于 0 就跳」

而「0」在对象世界里 = null，在布尔世界里 = false。
```

**写守卫时的正确读法**：先在心里念一遍"**我要在什么条件下跳过/返回**"，再决定用哪个：

| 想要的语义 | 正确写法 |
|---|---|
| `if (x == null) return;` | `if-eqz vX, :ret` |
| `if (x != null) return;`（"已存在则不做"） | `if-nez vX, :ret` |
| `if (!flag) skip;` | `if-eqz vF, :skip` |
| `if (flag) update;`（"非 flag 才跳过"） | `if-eqz vF, :skip` ← **最容易写错的一类** |

### 本轮实际改掉的 6 处

| # | 位置 | 原（错） | 改（对） | 症状 |
|---|---|---|---|---|
| 1 | `GmProbe.show` `sInst` 守卫 | `if-nez v0, :go` | **`if-eqz v0, :go`** | **第一次点静默无反应**（主人碰到的） |
| 2 | `GmProbe.toggle` `sInst` | `if-nez v0, :show` | **`if-eqz v0, :show`** | 空的时候反而去 `hide()` |
| 3 | `GmProbe.onClick` `sProbeLog` | `if-nez v0, :empty` | **`if-eqz v0, :empty`** | 有记录也报"还没有记录"；真为空时 NPE |
| 4 | `GmProbe.onTouchEvent` 拖动分支 | `if-nez v3, :true` | **`if-eqz v3, :true`** | 拖了不动、没拖反而动 |
| 5 | `GmProbe.onTouchEvent` 抬手分支 | `if-nez v0, :true` | **`if-eqz v0, :true`** | 拖动结束会被当成点击 |
| 6 | `GmDumpDialog.copy` `ctx` | `if-eqz v0, :go` | **`if-nez v0, :go`** | 拿不到 ctx 时不返回、继续用 null ⇒ NPE |

> ✅ **复查过、确认是对的**（属于"照抄原类"的部分）：`GmDsDialog.open` / `GmDumpDialog.open` 的 `sAct`・`sDlg`・`isShowing`・`window` 四处；`GmProbe.hide` / `actOf` / `onLong` 三处。
> ⚠️ **`vercheck.pl` 查不出这一类** —— 它只管「未初始化 / 类型冲突」。**守卫反向是纯逻辑错误，字节码完全合法**。这就是它总能活到真机的原因。

## 4. 教训（121~126）

| # | 内容 |
|---|---|
| **121** | ⭐⭐⭐ **`if-eqz`/`if-nez` 是手写 smali 的头号杀手，而且要成片检查**：本轮**一次写反 6 处**（5 处在同一个类里）。原因是"心里想的是「非空则跳过」，手上写成了 `if-nez`"。**铁律：写完每个守卫，立刻在旁边用中文写一句"走这条跳转的条件是什么"，逐个念一遍**（与教训 44 同源，但这次是**批量**复发 ⇒ 说明"想着写"不够，必须**逐条落字**） |
| **122** | ⭐⭐⭐ **`vercheck.pl` 查不出守卫反向** —— 它只覆盖「未初始化 / 类型冲突」，而**反向的守卫字节码完全合法**。⇒ **校验工具通过 ≠ 逻辑正确**。守卫/判据类改动，必须**在真机上按"最朴素的路径"走一遍**（本版就是"第一次打开开关"这种最简单的路径被打死了） |
| **123** | ⭐⭐ **"开关"和"二级菜单"是两种不同的 UI 语义**：二级菜单 = `>` 箭头 + 整行可点 + 点完跳走；**开关 = `Switch` 控件 + 状态常驻 + 点完留在原地**。判断依据：**这个入口"进去又出来"还是"就地切换状态"** —— 前者用菜单，后者用开关。本项目开关的家族：`GmBubbleSwitch` / `GmBgSwitch` / `GmSwitch` / `GmModelSwitch` / `GmEnvSwitch` / `GmAvatarSwitch` ⇒ **新开关照抄它们即可** |
| **124** | ⭐⭐ **`setChecked()` 必须在 `setOnCheckedChangeListener()` 之前**：否则**初始化时就会触发一次 `onCheckedChanged`**（表现为"一进页面功能自己开了/关了"）。全项目开关都是「先 `setChecked` 再挂监听」⇒ **这是约定，不是巧合** |
| **125** | ⭐ **开关的状态要能"回头看见"**：`GmProbe.shown()` 读静态实例 ⇒ 再次进「调试」页时开关位置正确。**若开关背后是"临时对象"（没有可回读的状态来源），就该给它加一个 `isOn()`/`shown()` 之类的查询方法**，否则下次进页面只能靠猜 |
| **126** | ⭐ **`matchText` 要从「当前读到的原文」里复制，并且要意识到 MT 会剥掉行尾注释**：`dex_class` 存盘时把 `const/high16 v6, 0x41900000  # 18.0f` 的注释**去掉了** ⇒ 带注释的 `matchText` 永远匹配不上。**正确姿势：`mt_apk_read_text` 读一次现场原文，逐字复制**（与教训 120 同源，但这次踩的是"注释被规范化"这一层） |
