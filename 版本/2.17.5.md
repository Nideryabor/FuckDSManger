## 一、主人反馈的现象
> 发送已经跑通；但**不开深度思考 ⇒ 页面停在「思考中」**，**开深度思考 ⇒ 停在「识别中」**

**根因：我的状态机只有"进入"，没有"出口"** —— 见下表（只有单向设置，没人把它改回去）：

| 事件 | 我设的状态 |
|---|---|
| `AudioRecord.startRecording` | 聆听中… |
| `AudioRecord.stop` | 识别中… |
| 语音发送命令 `fn1`（字段 `a` 非空） | 思考中… |
| ~~AI 回复结束 / 朗读结束~~ | **（缺）** ← 就是这里 |

⇒ 两种设置下"卡的位置不同"，只是**最后一次设置落在哪**的差别（语音发送那条 `fn1` 是否触发也受影响）；打字的发送路径（`cn1`）我**从来没设过**「思考中」。
⇒ 所以缺的是 **"朗读结束 ⇒ 回待机"** 这一跳，外加"任何发送都进思考中"。

## 二、2.17.5 的修法
宿主的 TTS 播放用 **`android.media.MediaPlayer`**（还设了 `OnPreparedListener` / **`OnCompletionListener`** / `OnErrorListener`；完成回调类 = `Lrj9;`）⇒ 三个信号全部可挂：

| 挂点 | 动作 |
|---|---|
| `MediaPlayer.start()` | 状态 → **朗读中…**，日志 `[通话][TTS] 播放开始 ⇒ 朗读中` |
| `MediaPlayer.stop()` | 状态 → **待机｜按住说话** |
| `Lrj9;->onCompletion(MediaPlayer)` | 状态 → **待机｜按住说话**（宿主自己的"播完"回调，最准） |

另：`GmCallHook` 里**任何发送**（`cn1` 打字 / `fn1` 语音）都会把状态切到「思考中…」（原来只有语音路径设）。

**现在的完整状态流**：
```
待机(按住说话) →[按住]→ 聆听中… →[松手]→ 识别中… →[发送]→ 思考中… →[TTS开始]→ 朗读中… →[播完]→ 待机
```

## 三、复测
装 → 强停宿主 → 点 🎧 → 按住说话 → 松手；**两种深度思考设置各试一次**。期望日志：
```
[通话][TTS] 播放开始 ⇒ 朗读中
[通话][TTS] 播放结束事件=onCompletion
```
页面状态应能在 AI 说完后**自动回到「待机｜按住说话」**。

⚠️ 若宿主**没开自动朗读**（自动 TTS 关），则不会有播放事件 ⇒ 状态会停在「思考中…」；那种情况我再补"AI 回复结束"的信号（挂 `nn1.A` 的完成或流结束）。
