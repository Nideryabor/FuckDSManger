## 一、`n=0` 的含义：我一直在读一个**空壳**

反查 `wr.x()` 的完整实现（宿主 vc273）：

```smali
.method public final x()Lhp8;
    iget-object p0, p0, Lwr;->j:Lrs8;          # 状态持有者
    invoke-virtual {p0}, Lrs8;->getValue()…     # 取当前状态
    check-cast p0, Lor;
    instance-of v0, p0, Lnr;
    if-eqz v0, :cond_11                        # 不是 nr → 直接 return null
    check-cast p0, Lnr;
    iget-object p0, p0, Lnr;->a:Lhp8;          # 只有 nr 状态下才给列表
    return-object p0
    :cond_11
    const/4 p0, 0x0
    return-object p0
.end method
```

**⇒ `x()` 不是"消息列表 getter"，而是"某个渲染状态（`nr`）下的列表"** —— 状态不对时返回 `null`，状态对时给的也可能是**渲染期用的那份**（空）。

**⇒ 我们抓了半天的 `hp8`，就是这么个空壳。**

## 三、本版改动：`sync()` 三级取数

```
① sList 已有内容（nOf() > 0）        → 直接用
② sWr 非空 ⇒ 读 wr.f（LinkedHashMap）
     非空 ⇒ new ArrayList(map.values()) ⇒ 存 sList        ★ 新增
③ 回退：反射调 wr.x()（原逻辑）
```

实现要点（smali）：

```smali
invoke-static {}, …->nOf()I          # ① 判"非空"，不是"非 null"
move-result v1
if-lez v1, :sync_done

sget-object v0, …->sWr:Ljava/lang/Object;
if-eqz v0, :sync_done

:try_start_sync
… getClass().getField("f") … invoke Field.get(sWr) …
instance-of v2, v1, Ljava/util/Map;
if-eqz v2, :sync_x                    # 不是 Map ⇒ 回退
… Map.size() … if-lez v2, :sync_x      # 空 map ⇒ 回退
new ArrayList(map.values()) ⇒ sList    # ★ 成功即用
return-void
:sync_x
… 原 wr.x() 回退 …
```

> 关键改动：① 的判断从"`sList != null`"改成"**`sList` 非空**" —— 否则空壳会把好数据挡住（这正是上一版 `n=0` 却"看起来已捕获"的机制）。

## 五、教训

| # | 教训 |
|---|---|
| **404** | ⭐⭐⭐ **别把 getter 的名字当语义**：`wr.x()` 叫得再像"取列表"，实际是"**某个状态下的**列表"（带 `instance-of nr` 前置条件）。**要看实现，而不是名字**（与 2.10.77 的教训 373 同源，这是第二次栽在"想当然的 getter"上） |
| **405** | ⭐⭐⭐ **缓存"容器"不如每??取"最新"**：`sList` 一旦被赋值就再没更新过（因为判断条件是"非 null"）⇒ **空壳永久占位**。诊断里加"量"（`nOf()`）后立刻暴露 |
| **406** | ⭐⭐ **主存储往往藏在"写入路径"里**：找 `write`/`put` 的方法（这里是 `wr.z`）比找 `get` 的方法更快命中真相 |
| **407** | ⭐⭐ **`Map.values()` 转 `ArrayList` 做统一**：不同容器（List / Map）先在取数层归一成 List，让下游只处理一种类型 |
