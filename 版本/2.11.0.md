## 一、澄清之后的推理（很重要）

| 事实 | 推论 |
|---|---|
| 是 **Toast**，不是崩溃 | `probe()` **正常返回了**，只是返回的是失败文案 |
| 我的 catch **一条都没响** | **异常根本没发生** |
| 没有日志 | ⇒ 说明失败发生在"**不抛异常**"的路径上 |

**⇒ 而 `pick()` 里恰好有一条"静默失败"路径：**

```smali
invoke ... Method;->invoke(...)      # 方法存在，调用成功
move-result-object v1
if-eqz v1, :pick_ret                 # ← 结果为 null ⇒ 直接返回 null，不抛、不记
```

**⇒ 所以：方法**存在**、被**调用**了、但**返回 null/空** —— 这也解释了为什么"没有日志"。**

（另外：主人说的"arraylist 报错"，应该就是 Toast 里那句 `cls=java.util.ArrayList n=2` 的 `ArrayList` 字样。）

## 二、本版：给 `pick()` 加"户口登记"

每次成功进入调用点时，写一行日志：

```smali
… invoke … → result
new StringBuilder("call ").append(p1)   # p1 = 方法名
GmUtil.log(...)
if-eqz result, :pick_ret
```

**⇒ 日志里将出现 `call l` / `call t` / `call k` … ⇒ 一眼看清：**
- **有 `call X`**：方法存在且被调用 ⇒ 问题是**返回值**为空（=> 换字段/换路径）
- **没有 `call`，但有 `NoSuchMethodException`**：方法不存在 ⇒ 换方法名
- **啥都没有**：`pick` 根本没被调用 ⇒ 问题在 `ctxText`/`grab` 之前

另外把方法链扩到第 7 个：`l → t → k → G → D → A → d`。

## 四、教训

| # | 教训 |
|---|---|
| **449** | ⭐⭐⭐ **"没日志"分三种，别混为一谈**：① 逻辑没走到 ② 走到了但**静默返回**（本次）③ 日志调用本身失败（2.10.93~96 是这种）—— **三者要用不同手段分辨** |
| **450** | ⭐⭐⭐ **反射调用永远要"记名"**：`getMethod` + `invoke` 这条链上"成功但返回 null"和"方法不存在"是**完全不同的两个病**，**不给成功路径留日志，就永远分不出来** |
