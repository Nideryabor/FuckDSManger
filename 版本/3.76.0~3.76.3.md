### 为什么扫描放在**我们进程**

看清单得出的，不是猜：

- 宿主 `2.7.5` 清单只有 `READ_MEDIA_IMAGES`，**没有 `READ_MEDIA_AUDIO`** ⇒ Android 13+ 它在 `/sdcard/Music` 里什么也看不见
- 我们的单包清单有 `MANAGE_EXTERNAL_STORAGE`（`build_ui.py` 声明，`targetSdk=34`），但设备上实测是 **`default`（未授权）**

⇒ 两条路都写：**有授权直扫 `File`**（能看见用户自己丢进去的 mp3 和 `.lrc`）；**没授权退 MediaStore**（至少能看见我们自己导入的）。两条都空就明说「还没扫到歌」，不装作有歌。

## 二、「仅首条」只复用音乐那部分（3.76.0 → 3.76.1）

### 主人原话

> 「顺便修一下开音乐提示词以后在仅首轮的情况下整套提示词一直复用的情况，改成只音乐对应部分复用」

### 第一版（3.76.0）——**我把它做成了事故**

实现是：`仅首条 && !first` ⇒ 用空行切段，**只保留含音乐变量的段落**。

问题：主人的提示词正文是**一整段**，里面同时装着：

```
【回答排版】<b>/<c1>/<bg1>/<br> + ⟦FDM:模板⟧ …
【音乐变量】[[正在听：{music}]] [[当前唱到：{lyric}]]
【追问建议】<Suggestion>…</Suggestion>
```

音乐段一保留，**富文本和追问建议的规则就被裁掉了** ⇒ 模型不再输出 `<b>`、`<Suggestion>` ⇒
主人截图里就是「富文本渲染和回复建议炸了」。

更糟的是：**在功能上线前就建好的老会话**里，第 2 条消息 `first=false`，
而历史里从来没有过那几段静态约定 ⇒ 一裁就**永久**没有。

### 修法（3.76.1，主人拍板的 B 方案）

> 「保留裁剪，但加会话兜底：只对「本会话已完整发过」的情况才裁，靠超时/标记判定」

实现：**标记判定**，不猜时间。

```
GmSysPromptHook.beforeHookedMethod
  └─ historyHasFull = GmSysPrompt.hasAnchor(args[3])   // args[3] = 历史消息 List
       └─ 逐条找 ⟦FDM⟧（明文）或 U+E0000 区字符（Tag 隐形）
inject(prompt, first, historyHasFull)
  └─ if (MODE_FIRST && !first) {
         if (!hasVar) return prompt;
         if (!historyHasFull) → **整段重发**（自愈，记一次日志 sysprompt.selfheal）
         else                 → src = varyingPart(sp)   // 只取时变段落
     }
```

⇒ 老会话第一轮先整段补一次，补完历史里就有锚点了，从下一轮起才真正省 token。
**任何结构不认识 ⇒ 返回 false ⇒ 走整段重发**（安全侧）。

## 三、2.7.5 富文本其实一直是死的（3.76.2 / 3.76.3）⭐ 本轮最贵的发现

### 日志铁证

```
[FDM] AI气泡富文本：未就绪 · SpanStyle 候选字段数不足（2.7.2 应为 tba/15 字段），不像 SpanStyle
      · 链接：未就绪 · 未初始化（已出 0 个可点击）
      · 发送：未就绪 · 未初始化
```

⇒ 从 **3.75.x 适配 2.7.5** 起，`GmRichTextHook.prepare()` 在**第一步**就 bail，
`install()` 直接 return 0 ⇒ **富文本 / 追问建议 / 可点击 三族全静默失效**，
而日志里只有一行「未就绪」，看起来像「功能就是这样」。

### 反查（`tmp/h275` 2.7.5 全树，按结构不按名字）

| 角色 | 2.7.2 | **2.7.5** | 判据（可复查） |
|---|---|---|---|
| AnnotatedString | `sn` | **`tn`** | `implements CharSequence` + `a:List` / `b:String` / `c,d:ArrayList` + `ctor(String,List)`；⚠️ `sn` 已换主人（`a:Object b:I c:I d:String`） |
| Builder | `qn` | **`rn`** | `implements Appendable` + `a:StringBuilder` + `c(tn,II)` / `e(String)` / `j(cca)I` / `f()` / `k()Ltn;` |
| SpanStyle | `tba` | **`cca`** | 15 字段 + 15 参 ctor `(JJ,Ljs4;,Lhs4;,Lis4;,Lzq4;,String,J,Ljl0;,Lpwa;,Lqr6;,J,Lkua;,Lty9;,I)V`；⚠️ `tba` 只剩 2 字段 |
| FontWeight | `fs4` | **`js4`** | `a:I` + `b~f:` 自引用 |
| FontStyle | `ds4` | **`hs4`** | `a:I` |
| TextDecoration | `cua` | **`kua`** | `a:I` |
| MarkdownTextKt | `k27` | **`s27`** | 全树唯一 `b(Ltn;Lfk7;Liya;Lk;Lv15;II)V` |
| Link 父类 | `ho6` | **`no6`** | `lo6`/`mo6` 共同父类 |
| LinkAnnotation.Clickable | `fo6` | **`lo6`** | `.super Lno6;` + 串 `LinkAnnotation.Clickable(tag=` |

**⚠️ 坑**：2.7.5 的 `lo6`（Clickable）与 `mo6`（Url）**构造器签名逐位相同**
`(String, nxa=TextLinkStyles, oo6=Listener)`、同父 `no6` ⇒ 结构上分不开，
只能靠类里的 toString 常量区分 ⇒ **`CAND_RI6` 里 `lo6` 必须排第一，别按字母排**。

## 四、我自己搞出来的一次事故（必须记）

为了让 `kotlinc` 编过，我跑了 `tools/i18n_migrate.py render`。
`render` 是**拿 `keys.json` 覆盖 `strings.xml`** ⇒ 把 `strings.xml` 里
**手改过、没回写 keys.json** 的文案回退了（`pg_030` / `pg_031` 两条灰度文案）。

- 与「富文本炸」**无关**（那条是 2.7.5 名表 + 我的裁剪逻辑）
- 已按 `HEAD` 还原，并顺手把 `bbl_001~017` / `pg_047` / `pg_048` 补进 `keys.json`（现在 820 = 820 对齐）

> **教训**：`i18n_migrate.py render` 是**破坏性**操作。
> 改文案只在 `res/values/strings.xml` 改不算数，必须同步 `i18n/keys.json`，
> 否则下一次 `render` 就把它吃掉。要出新 key 就改 keys.json 再 render —— 别反过来。

## 五、教训（编号续 285）

| # | 教训 |
|---|---|
| **285** | **「未就绪」不是状态描述，是故障报告**。`GmRichTextHook` 的 `bail()` 只打一行日志就静默不启用，而宿主照常工作、界面照常出字 ⇒ 一天不看日志就等于没这个功能。凡是 `prepare()` 有 bail 的模块，启动时都该把 `sWhy` 打出来（这条已经做了）。 |
| **286** | **R8 换主人之后，「名字对得上」毫无意义**。2.7.5 的 `tba`/`sn`/`qn` 都还存在，只是**变成别的类**了 ⇒ `Class.forName` 成功、自检失败、功能全灭。升级宿主的固定动作必须是**结构反查**（字段类型 + 构造器签名 + 唯一串），不能只换名字。 |
| **287** | **两个类构造器逐位相同 = 结构上不可分**。`lo6`(Clickable) vs `mo6`(Url) 就是。这时候只能退回到**类内字符串常量**（toString 里的 `LinkAnnotation.Clickable(tag=`）。顺序也不能按字母排，否则认错。 |
| **288** | **删内容之前先问「别人靠什么判断我已经说过」**。裁掉静态段这件事，理论上省 token；但**模型没有跨轮记忆的锚点**，历史里没那几段就是没有。任何「只发一次」的功能，都必须有一个**可验证的痕迹**（这里是 `⟦FDM⟧` / Tag 字符）来证明它真的发过。 |
