## 一、这一版只做一件事：**回滚**

3.71.3 我给 `GmStore.get()` 加了「`getAll()` 为空就丢缓存」的就绪校验，判断"宿主启动早期 MMKV 还没初始化"。

**这是错的。**

`bridge/FdmBridge.java` 的注释里早就写着（就在 `syncPins` 上方）：

> ★ 不用 `allKeys()`（MMKV 的 SharedPreferences 包装类上反射不到 ⇒ **实测回读 0 个键**）

`getAll()` 是同源问题（同一个包装类）。于是：

```
每次 getAll() → 空表 → 判空 → 丢缓存重取 → 又空 → ...
⇒ 所有配置读取全乱
```

**主人现场反馈**：「不仅玻璃没了，而且系统提示词的抹掉内容也失效了，背景还是一样的」

## 二、回滚内容

```smali
.method public static get(Landroid/content/Context;)Landroid/content/SharedPreferences;
    .registers 4

    sget-object v0, Lcom/nidyaber/fuckdsmanger/gm/GmStore;->sSp:Landroid/content/SharedPreferences;

    if-eqz v0, :cond_5

    # ★ 2026-10-24 回滚说明：
    #   我一度在这里加了「getAll() 为空就丢缓存」的就绪校验，**这是错的** ——
    #   MMKV 的 SharedPreferences 包装上 getAll()/allKeys() 实测回读 0 个键
    #   （见 FdmBridge.syncPins 的注释），于是这里每次都判空 ⇒ 每次都丢缓存重取
    #   ⇒ 所有配置读取全废（现场：玻璃失效 + 系统提示词抹除失效）。
    #   ⇒ 恢复原逻辑：缓存命中直接返回。
    return-object v0

    :cond_5
    ...
```

与改动前的备份 diff **只剩这段注释**，逻辑完全一致。

## 四、本轮教训（已写进指南 v2.3 规则 P/Q/R）

| 规则 | 内容 |
|---|---|
| **P** | ⭐⭐⭐ **动「全局读取路径」前，先把项目自己的注释翻一遍** —— 坑基本都写在同一文件里 |
| **Q** | ⭐⭐⭐ **`GmStore.get()` 的 `sSp` 永久缓存是「已知设计」，别去"修"它** —— 所有"就绪校验"的路子都会踩 P 那个坑；真要处理时序，**只能在调用方延迟重试** |
| **R** | ⭐⭐ **别拿真机当第一个验证场** —— 改完全局路径，先在产物上回读 smali 确认逻辑，再装机 |
