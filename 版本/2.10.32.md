## 二、🎯 第二个：两个反判断（同一类错误的第 6、7 次）

```smali
    size() → v4 ; v2 = 1
    if-lt v4, v2, :sz_ok          ← ① if-lt = 「v4 < v2 才跳」
    [空列表分支…]
```

**列表明明 4 条（4 < 1 为假）⇒ 永远不跳 ⇒ 永远走"空列表"分支** ⇒ 宿主那 4 个对象**从未被用到**
⇒ 所以「宿主原型」日志从未出现、chip 永远是宿主原样 ✓✓

```smali
    :dg_done
    size() → v7
    if-lez v7, :dg_ok             ← ② if-lez = 「v7 ≤ 0 才跳」= 空才跳去成功！
    goto :self_fail
```

⇒ 直连造出 1 条却**跳去失败**分支 ✓（所以日志只有"自建失败"、没有"直连成功"）

### 修法

```smali
-    if-lt v4, v2, :sz_ok
+    if-ge v4, v2, :sz_ok        ← 宿主列表非空 → 走"改造宿主对象"路径
-    if-lez v7, :dg_ok
+    if-gtz v7, :dg_ok           ← 自建非空 → 成功
```

## 五、教训（本项目最痛的一类）

| # | 教训 |
|---|---|
| 225 | ⭐⭐⭐ **`if-XX` 家族必须"读出来验证"**：`if-lt`(v4<v2 跳) / `if-ge`(v4≥v2 跳) / `if-lez`(≤0 跳) / `if-gtz`(>0 跳) —— 写完后**用具体数字念一遍**（"4 < 1？否"）比盯着代码看有效得多 |
| 226 | ⭐⭐ **两次"明明有数据却报空"**（模板池、宿主列表）都是同一类反判断 ⇒ 一旦出现"有数据/报空"的矛盾，**优先怀疑比较方向**，而不是数据源 |
| 227 | ⭐ **遗留的旧诊断文案会撒谎**（"传入列表为 null" 实为"非空"）⇒ 改代码时要同步改它的措辞，否则会把自己带沟里 |
