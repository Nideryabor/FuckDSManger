# 2.10.32-probe（versionCode 150）

> 2026-09-18 · 「回复建议」第 33 轮：**修 2.10.31 的 VerifyError（我手写 smali 少传参数）+ 把停产改成真删**
> 一句话：2.10.31 我一激动把 `inject()` 改成一行 `logOnce`，**只传了 1 个寄存器，可签名要 2 个**
> ⇒ Verifier rejected ⇒ **整个 `GmSuggestHook` 类被否** ⇒ 挂在它身上的 **30 个注册全部 `hookM FAIL`**
> ⇒ 那一版「回复建议」的所有钩子**一个都没装上**。

## 一、事故复盘（2.10.31 为什么全灭）

主人日志（23:27:09）：

```
FuckDSManger: hookM FAIL xo6.l | java.lang.VerifyError: Verifier rejected class
    com.varuns2002.disable_flag_secure.gm.GmSuggestHook:
    void ...GmSuggestHook.inject(XC_MethodHook$MethodHookParam) failed to verify:
    [0x2] Rejecting invocation, expected 1 argument registers,
          method signature has 2 or more
```

我当时写的是：

```smali
const-string v0, "2.10.31: inject() 已停产…"
invoke-static {v0}, …GmUtil;->logOnce(Ljava/lang/String;Ljava/lang/String;)V   # ★ 只给 1 个寄存器
```

`GmUtil.logOnce` 是 `(String, String)` ⇒ 校验器在第 1 条指令就否掉整个方法，
而**方法是类的一部分 ⇒ 整个类作废**。

| 关键认知 | 说明 |
|---|---|
| ⭐ `hookM` 走 `Class.forName(hookClass)` | 类一坏，**挂在它上面的注册全灭**，不是「坏一条剩 29 条」 |
| ⭐ 因此 hook 类里任何方法改写，都**必须保证可校验** | 最稳的写法：能不加指令就不加 |

> ⇒ 2.10.31 上跑出来的任何「没反应」都**不算数**（等于没打模块）。

## 五、教训

| # | 教训 |
|---|---|
| 156 | ⭐⭐⭐ **手写 smali 时，`invoke-*` 的寄存器数量必须跟签名严格对上** —— 少传一个 = VerifyError = **整个 hook 类作废** |
| 157 | ⭐⭐⭐ **hook 类是「全有或全无」**：类一坏，挂它上面的几十个注册全灭；所以 hook 类里的代码要**极简** |
| 158 | ⭐⭐ **改完要从产物读回来核对** —— 只看编辑会话容易自我催眠；本轮我核了 4 项（方法正文 / 关键字归零 / 注册计数 / 版本串） |
| 159 | ⭐⭐ **「指向不存在的类」当停产开关虽然好用，但会留红字** —— 主人会当成 bug 来问；正式做法还是**删掉注册** |
| 160 | ⭐ **一版全灭的日志其实是线索**：`hookM FAIL` 后面跟的 `VerifyError` 直接点名了方法，比盲试快得多 |
