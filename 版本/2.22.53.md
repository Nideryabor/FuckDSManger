## 1. 改动一：透明 → **半透明**（保留 RGB，只降 alpha）

**原来**：`args[1] = Long(0)` ⇒ **全透明** ⇒ 底下全透出来（深色模式下就是"全黑"）⇒ 文字失去依托。

**现在**：

```smali
    const-wide v2, 0xffffffffffffffL      # 掩码：保留低 56 位（RGB + 低 8 位）
    and-long/2addr v4, v2                 # 清掉高 8 位（原 alpha）
    const/16 v2, 0x80
    int-to-long v2, v2
    const/16 v6, 0x38                     # 56
    shl-long/2addr v2, v6                 # 0x80 << 56
    or-long/2addr v4, v2                  # 设 alpha = 0x80
    invoke-static {v4, v5}, Long->valueOf(J)Ljava/lang/Long;
    …
    aput-object v2, v0, v3                # args[1] = 半透明色
```

**效果**：`#FF0F0F0F` → **`#800F0F0F`**（50%）

> ⚠️ 注意：Compose 的 `Color` 打包成 `long` 时**高 32 位是 ARGB**，所以"改 alpha"= 改**高 8 位**。
> 这里先 `and` 掉高 8 位、再 `or` 上 `0x80 << 56`，**RGB 完全保留**。

## 2. 改动二：槽 3 直接覆盖 ⇒ 切主题不必重启

**原来**（三槽都满就跳过）：

```smali
    :try3
    sget-wide v1, sExtraColor:J
    cmp-long v1, v1, v6
    if-nez v1, :end              # 槽 3 也满 ⇒ 放弃
    sput-wide v4, sExtraColor:J
```

**现在**：

```smali
    :try3
    sput-wide v4, sExtraColor:J  # ★ 直接覆盖槽 3
```

**⇒ 切主题后，第一次遇到新颜色就会被记进槽 3 ⇒ 立刻生效**（不必重启）。
（`GmPageHook.before` 每次进 ChatPage 仍会清空三槽，两条路都能刷新。）

## 5. 教训（834）

| # | 内容 |
|---|---|
| **834** | ⭐⭐⭐ **「全透明」和「半透明」在视觉上是两种不同的需求**："让背景透出来"用**全透明**，而"**让背景透出来同时保住可读性**"必须用**半透明**。⇒ **凡"背景透出来"的功能，默认就该给"半透明 + 可调 alpha"，而不是一上来就置 0** —— 置 0 会连带把"内容衬底"一起抹掉。 |
| **835** | ⭐⭐ **"覆盖最旧那个"是比"满了就放弃"更好的降级策略**：三槽满时放弃 ⇒ 新颜色永远进不来（表现为"必须重启"）；改成"覆盖槽 3" ⇒ **永远有刷新通道**，代价只是"最多记 3 种"这个上限被随时更新。⇒ **缓存类结构满员时，优先考虑"淘汰最旧"，而不是"拒绝新的"。** |
