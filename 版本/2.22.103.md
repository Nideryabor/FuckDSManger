## 1. 我自己的探针 bug：`logOnce` 是**按 tag 去重**

- `[UB]` 探针：tag 写死 `"[UB]"`，**变化的部分全在消息里** ⇒ 每个 tag 只打出**第一条** ⇒ 四轮日志里 `[UB]` 只有一行 ⇒ 让我误以为"只有一个调用点"
- `[ROLE]` 探针：tag 写死 `"[ROLE] 参数数"` / `"[ROLE] #i"` ⇒ 同理只打一条
- `[CELL] 总项数`：tag 写死 ⇒ 只打出 `1`

**⇒ 修法（本版）**：让 **tag 与消息都等于那条唯一字符串** ⇒ `logOnce(s, s)` ⇒ **每个不同状态各打一行**。
（这样无论是"按 tag 去重"还是"按 tag+msg 去重"，都能全部打出来 ✓）

## 4. 拿到之后我怎么改（**一行常量 / 或换身份证**）

| 看到什么 | 结论 | 改法 |
|---|---|---|
| 用户项与助手项的 `role=` **值不同**（如 `USER` vs `assistant`，或大小写不同） | 就是**字符串比对没对上** | 把常量改成**真实值**（一行） |
| 两项的 `role=` **完全一样** | `D()` 不是用户/助手的分辨器 | 改用 **`vq` 子类（运行时类名）** 当身份证（结构判据，和 `sDepth` 同思路） |
| 只有**一个** `vq` 实参、且它的 role 在两项间不变 | 同上（换身份证） | 同上 |
| 完全没有 `#` 行 | 探针仍未跑 | 我改成"在查找前就打一行"继续定位 |

## 5. 教训 276 ~ 279

| # | 要点 |
|---|---|
| **276** | ⭐⭐⭐ **诊断工具本身要先验证"它一定会说话"**：`logOnce(tag, msg)` 的**去重键是 tag**，而我把变量放在 msg 里 ⇒ 探针"装死"四轮，还让我误判"只有一个调用点" ⇒ **凡是"每个不同状态都要一行"的探针，必须让 tag 也随状态变化**（或干脆 `logOnce(s, s)`） |
| **277** | ⭐⭐⭐ **"计数器"比"存在性日志"值钱**：`5 个消息项了但一次都没注入成功` 这一行**直接把"到底有几条消息走过这条路"钉死了**，一举推翻我前一轮"你没喂到"的结论。⇒ **让程序把"我处理了几个"写出来**，比任何推断都强 |
| **278** | ⭐⭐⭐ **"用户分支从未执行" ≠ "没有用户消息"**：同一条日志同时支持"没有用户项"和"用户项走了别的分支"。**必须让日志带上"对象身份（类名/角色值）"**才能区分 |
| **279** | ⭐⭐ **子程序里的 `findClass`/反射可以静默失败**：`roleLog` 拿到的 ClassLoader 与调用方相同、调用方 `findClass` 成功，**子程序里同样一行却让整个探针无声退出**（catchall 只写 logcat 不进 DIAG）⇒ **探针要"能少一步就少一步"**（本版改为直接接收已解析好的 Class） |
