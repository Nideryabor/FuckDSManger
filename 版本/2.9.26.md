> 综述：**「助手头像 = 蓝方块」遗留项的新修法** —— 不再去动 `Icon` 的 tint（2.9.10 那条路会连带改掉

## 一、一句话结论

「蓝方块」= 照片被 `Icon` 的 `ColorFilter.tint(主题色, **SrcIn**)` 染色（SrcIn 保留 alpha、RGB 全换 ⇒
不透明照片 = 一块纯蓝方块）。

**2.9.10 的错不在「去除 tint」这个目标，而在「去除的方式」**：把 tint 换成 `Color.Unspecified` 会让
`Icon` 走 `colorFilter = null` 那条路，于是 `Painter.paint` 内部 `useLayer` 由 `true` 变 `false`，
绘制走了**另一条分支** —— 整条链路被顺带改动了，变量不止一个。

**2.9.26 的做法：一个变量都不多动。**

```
tint 不动（还是主题色）      ⇒ Icon 照旧造 ColorFilter
useLayer 不动（还是 true）   ⇒ 还是 saveLayer + onDraw（今天能出「蓝方块」的那条路）
只把那个 filter 换成恒等     ⇒ 恒等 ⇒ 等于没染
```

恒等 filter 怎么来：**只换 blend mode，不换 color**。
`ColorFilter.tint(c, mode)` 在宿主里就是 `new Lvk0(mode序号, c)`，而
`PorterDuff.Mode.DST`（Porter-Duff `[Da, Dc]`）= **保留被绘制内容** ⇒ 完美恒等。

## 二、落点为什么选 `Modifier.paint`（而不是 `Icon` / 不是 `vk0.<init>`）

| 候选落点 | 评价 |
|---|---|
| `me4;->a`（= `Icon`）改 `args[3]`（tint） | ❌ 2.9.10 已证明会连带改 `useLayer`，且效果未知 |
| `Lvk0;-><init>(IJ)V` 改 blend mode | ⚠️ 可行，但要靠「armed 标志 / 颜色哨兵」把范围收窄，还要 hook 构造函数（现有 `hookM` 只封了 `hookAllMethods`，不含 `<init>`） |
| **`Lfh6;->N(...)`（= `Modifier.paint`）** | ✅ **最优**：`args[1]` 就是 painter（可直接身份比对，天然收窄到我们这一处）；`args[5]` 就是 ColorFilter |

**已逐字核对 `Lfh6;->N` 的宿主实现（2.5.2）**：

```
.method public static N(Lc76;Lku6;Lp9;Lae2;FLvk0;I)Lc76;
    and-int/lit8 v0, p6, 0x4     # mask 只影响 alignment
    if-eqz v0, :cond_6  → align = Lmva;->g
    and-int/lit8 p2, p6, 0x10    # mask 只影响 alpha
    if-eqz p2, :cond_d → alpha = 1.0f
    new-instance v0, Llu6;       # PainterElement(painter, align, ?, alpha, colorFilter)
    invoke-direct/range {v0 .. v5}, Llu6;-><init>(Lku6;Lp9;Lae2;FLvk0;)V
```

⇒ **`args[5]` 被原样塞进 `PainterElement`，没有任何 mask 二次判断**，替换它 100% 生效。

**blend mode 序号已核对**（宿主映射表 `Lqb;->S(I)` / `Lqb;->Q(I)`）：

| 序号 | Compose `BlendMode` | 落到 Android |
|---|---|---|
| 2 | `Dst` | `PorterDuff.Mode.DST` / `BlendMode.DST` ← **本次用它（恒等）** |
| 5 | `SrcIn` | `PorterDuff.Mode.SRC_IN` ← 「蓝方块」用的就是它（与现网行为吻合，可交叉验证） |

## 六、教训（补充）

**第 110 条：⚠️「日志里的旧类名」会造出幽灵锚点，必须以代码里的 `hookM` 实参为准。**
`GmPainterHook` 里那行日志一直写着 `Li65.x called`（2.5.1 时代的挂载点），而**实际注册早就改成
`kf5.K`** 了。本轮我差点据此认定「2.5.2 里 `i65` 没有 `x` 方法 ⇒ 头像 hook 全死」——
查了 `DisableFlagSecure` 的注册代码才发现是**日志标签没跟着改**。
（旁证：2.5.2 的 `Li65;` 确实只有 `<init>`/`A`，而头像调用点 `Lcka;` 是**直接** `invoke-static {v1,v2,v5}, Lkf5;->K`。）

**第 111 条：⭐「去掉某参数 → 效果剧变」时，别顺着那条路继续调参，要换成「值中性化、路径不变」。**
2.9.10 把 tint 换成 `Color.Unspecified`，等于顺手把 `useLayer` 从 `true` 翻成 `false` ——
一次改动动了两个变量。正确姿势是找一个**只改值、不改分支**的落点（本次 = `Modifier.paint` 的 filter 参数），
这样既拿到效果，又不会踩到未知那条分支的坑。

**第 112 条：`BlendMode.Dst` 是 ColorFilter 的恒等变换，只改 blend 序号即可「解除染色」。**
Porter-Duff `DST = [Da, Dc]` ⇒ 输出 = 被绘制内容（原样）。
`ColorFilter.tint(c, Dst)` 与 `ColorFilter.tint(c, SrcIn)` 共用同一个构造（只差一个 int），
所以「解除染色」可以做到**零几何改动**。序号映射可在宿主里核对：`Lqb;->S(I)`（PorterDuff）/ `Lqb;->Q(I)`（BlendMode）。

**第 113 条：怀疑「内容是空图」之前，先看存图实现。**
`GmAvatar.saveImage(ctx, uri)` = `ContentResolver.openInputStream(uri)` **字节直拷**到 `files/fuckds_avatar.png`，
不做解码/重编码 ⇒ 只要选图成功，文件内容就一定是那张原图，「画出来是空白」不可能是文件内容问题
（除非所选图本身就是空白/纯白）。这一条把排查范围直接压回渲染层，省掉一整轮试探。
