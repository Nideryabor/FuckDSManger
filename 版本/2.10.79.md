## 一、这条日志的真相（我把自己的诊断坑了）

**`[AI] h91.a args:` 后面是空的** ⇒ 拼接循环**一次都没跑** ⇒ 触发的那个方法 **0 个参数**。

而 `h91.a` 有 **10 个参数** ⇒ **这行日志根本不是 `h91.a` 打的**。

真凶：**同一个 hook 类（`GmSuggestAi`）同时挂在两个点上**：

| hook 点 | 参数个数 |
|---|---|
| `h91.a`（要的） | 10 |
| `wr.x`（上一版留的双保险，`after` 缓存返回值） | **0** ← 就是它 |

而我的日志前缀**写死了 `"h91.a"`** ⇒ `wr.x` 触发时也打出 `h91.a args:`，**把我自己骗了一轮**。

> 副作用更严重：`sDbg` 是**混着计数**的 —— 若 `wr.x` 先跑满 3 次，`h91.a` 的真实 args **根本不会被打出来**。
> 也就是说：**上一版的主人看到的"3 次"，很可能全是 `wr.x` 的**。

### 修正

| 项 | 内容 |
|---|---|
| **0 参方法一律跳过** | `array-length` 后立刻 `if-lez v1, :end_h91` ⇒ `wr.x`/空参调用直接 return（不计数、不扫描） |
| **日志前缀动态化** | `"[AI] hook " + param.method.getName() + " args:"` ⇒ **一眼分清是哪个点** |
| **计数只在有效调用上 +1** | `sDbg++` 移到"参数个数检查"之后 |

## 二、新增第三条路：`ao1.M()`（**即使 `h91.a` 不调也能拿到**）

反查早已确认：`ao1` = `ChatSessionComponent`，`ao1.M()` 返回 `wr`（会话消息容器）——**任何业务/渲染都绕不开它**。

⇒ 本版加挂 **`hookM("ao1", "M", "GmSuggestAi")`**：

```
afterHookedMethod：
  result == null                      → 直接 return
  param.method.getName().equals("M")  → 存 sWr（消息容器）
  否则（wr.x 的 "x"）                  → 存 sList（消息集合本身）
```

再加一个 **`sync()`**：

```
sList 为空 且 sWr 非空  ⇒  反射调 wr.x()  ⇒  拿到 hp8 ⇒ 存 sList
```

`probe()` 开头调用 `sync()` ⇒ **只要 `ao1.M()` 被调用过一次，点按钮时就能现取最新消息列表**（`sync()` 只在点按钮时跑，低频、零性能负担）。

### 现在的三条腿（谁先到用谁）

| # | 路径 | 说明 |
|---|---|---|
| 1 | `h91.a` 的 args 里 `isInstance(hp8)` | 渲染时拿，最直接 |
| 2 | `wr.x()` 的返回值 | 已挂在 `after` 上 |
| 3 | **`ao1.M()` → `wr` → 反射 `x()`** | **兜底，最可靠**（本版新增） |

## 三、回答主人的疑问

> 「按钮在设置里面，要点开宿主 app 的设置才能用它，这会不会跟无法捕获到聊天页有关？」

**无关。** hook 是 `handleLoadPackage` 阶段（模块随宿主进程加载时）**一次性注册**的，跟"你此刻打开哪个页面"没有任何关系。

唯一相关的是**捕获时机**：`h91.a` 只在**聊天页渲染**时才被调用 ⇒ 所以流程必须是"**先进聊天页停一下 → 再进设置页点按钮**"。本版起，`ao1.M()` 这条路会把这个要求进一步放宽。

## 五、教训

| # | 教训 |
|---|---|
| **381** | ⭐⭐⭐ **诊断日志必须自证身份**：一个 hook 类挂多点时，**写死的方法名前缀＝假情报** —— 前缀一定要取自 `param.method.getName()`。本轮为此白跑一轮真机 |
| **382** | ⭐⭐⭐ **多个 hook 点共用一个回调时，先做"参数个数/类型"分流**：0 参方法（getter）根本不该进 `args` 扫描逻辑，更不该占用限流计数 |
| **383** | ⭐⭐ **限流计数器要按"有效调用"计数**：混计会让"真正想看的那条日志"被别人的调用挤掉（本版 `sDbg` 已修） |
| **384** | ⭐⭐ **多留一条"兜底获取路径"永远是值得的**：`ao1.M()`（会话组件）比渲染函数更基础 ⇒ 即使注入点选错，也能在 `probe()` 时**现取**数据 |
