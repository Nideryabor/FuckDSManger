## 一、"空对话正常、老对话新开"说明了什么

新开对话 = **我们交给宿主的会话 id 是空的**（宿主只能新建一个）。
而"空对话时正常"恰恰是因为：**空对话本来就该新建** —— 也就是说，**我们拿到的 id 一直是空的**，跟"当前有没有会话"无关。

⇒ 判据不是"就绪没就绪"，而是 **"我们有没有拿到会话 id"**。而我之前**读错了字段**。

## 二、读错的字段：`wr.a` ≠ 会话 id

再看 `Lao1;->I(Lyp1;)V` 的后半段：

```java
v2 = wr.a                       // ← 我一直拿这个当会话 id（错！它只进遥测 tya.l）
v3 = tga.F(wr)                  // int（掩码之类）
v9 = yp1.b()                    // 文本
v11 = wr.h() ?: this.N()        // 另一个 String（也进遥测）
...
v2 = this.L().a                 // ⭐⭐⭐ 这个才是随命令发出去的会话 id
V(this,text,attachments, v2 /*会话id*/, pr8, wr, …)   → 组 nn1 命令 → 派发
```

`V(...)` 的签名是 `V(Lao1;Ljava/lang/String;Ljava/util/List;Ljava/lang/String;Lpr8;Lwr;ZZZ)V`，第 4 个参数（那个 String）就是 `this.L().a` ⇒ **命令携带的会话 id = `this.L().a`**。

**2.14.4 的 sid() 读的是 `M()` → `wr.a`** ⇒ 读错了字段：它其实**只跟"消息容器"有关**，不是会话 ⇒ 于是"非空判据"既会误杀（2.14.4 全空 ⇒ 不发）、也会误放（2.14.5 配对后不看 sid ⇒ 挑到没会话的 component ⇒ 新开）。

## 三、2.14.6 的修法

| 改动 | 说明 |
|---|---|
| `sid(Object)` 改读 **`L()` → 字段 `a`** | 这才是命令真正携带的会话 id |
| 选人优先级改为"**有会话优先**" | ① 配对 component 有会话 ⇒ 用它 ② 最新 component 有会话 ⇒ 用它 ③ `J` 捕获的有会话 ⇒ 用它 ④ 配对 component（无会话 ⇒ 真在空对话，新开是对的）⑤ 最新 component ⑥ 都没有 ⇒ 弹提示 |
| 新增一行诊断 | `[通话] 候选会话: pair=<id> new=<id> j=<id>` ⇒ **一行就能看出"当前对话的 component 到底在不在我们的候选里"** |

## 六、教训

| # | 教训 |
|---|---|
| **526** | ⭐⭐⭐ **同名/相邻字段最容易读错**：`wr.a` 与 `this.L().a` 都是 String、都在同一个方法里出现，**只有后者进了命令**。⇒ **"这个字段是什么"必须用"它最终流到哪里"来判定**（读调用链末端：`V(...)` 的参数位），不能看名字/位置猜。 |
| **527** | ⭐⭐⭐ **"某种情况下反而正常"是最高价值的线索**：本轮"空对话正常"直接推出"我们给的 id 一直是空的"—— 一步就砍掉了"就绪判据""配对错误""组件挑错"等一堆假设。**遇到这类现象，先问"为什么这种情况会正常"。** |
| **528** | ⭐⭐ **诊断行要能"一行定性"**：本次加的 `候选会话: pair=… new=… j=…` 让"到底有没有拿到 id"一眼可见（无论成败），比"成功/失败"两种结局有用得多。 |
