## 一、主人日志引出的两个发现

### 1.1 ⚠️ `FuckDSManger v1.0.5 [NEWPKG-ENTRY]` 是个「僵尸字符串」

主人日志里出现：

```
FuckDSManger v1.0.5 [NEWPKG-ENTRY] handleLoadPackage ENTER
```

查证：这行**确实在模块里**，但位于**转发入口类**
`com.little_femaleboy.cannot_show.the_big_won_whale.DisableFlagSecure`，
**是 1.0.5 时代写死的，从未随版本更新** ⇒ **不代表实际安装版本**。

转发链（已核实）：

```
little_femaleboy.DisableFlagSecure.handleLoadPackage
  → XposedBridge.log("FuckDSManger v1.0.5 [NEWPKG-ENTRY] …")
  → new varuns2002.disable_flag_secure.DisableFlagSecure()
  → 转发 handleLoadPackage(真实实现)
```

**已改为 `v2.9.18`**，以后不会再误判。

### 1.2 ✅ 好消息：AndroidAppHelper 的问题确实修好了

| 时间 | 日志 | 说明 |
|---|---|---|
| 17:20 | `GmEnv install FAIL … AndroidAppHelper` | 2.9.16 及以前 |
| 17:23 | （无此行）+ `hooked MainActivity.onResume OK` | **2.9.17 生效** ✅ |

即：`GmUtil.app()` 上线后，取 Context 链路不再报错，`GmResumeHook` 也正常注册。

## 二、本版改动（纯诊断，不动业务逻辑）

| # | 位置 | 改动 |
|---|---|---|
| 1 | 转发入口类 | 版本字符串 `v1.0.5 [NEWPKG-ENTRY]` → `v2.9.18` |

**哪一行断了，问题就在哪一环。**

## 四、教训（补充第十一节）

| # | 教训 |
|---|---|
| 92 | ⭐ **"转发入口类"里的日志字符串最容易变成僵尸**：它只被调用一次、改动时容易被忽略，于是日志里永远显示老版本号 —— **排查时先别信日志里的版本号，去 manifest/dex 里核** |
| 93 | ⭐ **诊断点的选址原则：放在"必经之路"上**，而且**无论分支结果如何都要留痕**。`promptIfNeeded` 之前只在"决定弹"时打日志 ⇒ 分不清"没被调用"和"被调用但没弹" |
