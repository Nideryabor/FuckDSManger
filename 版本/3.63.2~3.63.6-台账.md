## 二、★ 3.63.3 真凶：`width()` 服从父约束

```kotlin
Row(Modifier.width(pageDp * 2))         // ✗ 无效：被"一屏宽"的父约束夹回去
Row(Modifier.requiredWidth(pageDp * 2)) // ✅ 忽略传入约束，真能撑到两屏
```

**症状对应**：Row 被夹成一屏宽 ⇒ 第二个子项（右列）拿到的剩余宽度是 **0** ⇒ **右列整列零宽**
（卡片都在存档里，就是画不出来）；左列排在前面、吃掉整屏 ⇒ 正好是主人那句
「**左边三个都有，右边一个都没有**」。

## 三、★ 3.63.5：把"不可能出错"的版本先做出来

前两版都在给一个**手搓分页器**打补丁（自己维护浮点位置 + 自己写动画 + 自己算吸附），
症状换来换去：**两列同屏 / 卡在中间**。3.63.5 直接换掉思路：

* **只渲染当前那一列** —— 另一列**根本不进组合** ⇒ 「两列同屏」在结构上不可能；
* 切换只有 **0 / 1 两个状态**（点标签，或横滑一下 = 只做"换列"、**不跟手不做连续位移**）；
* 过渡交给 `AnimatedContent`（离散滑入滑出）—— 它自己保证"要么在这头、要么在那头"。

> 顺带一个小体验：**把卡片拖回抽屉时自动切到它该去的那一列**（内置→左列 / 自定义→右列）。

## 四、★ 3.63.6：卡片下面那个按钮点不动

两个原因（都改了）：

**① 长按拖动罩住了整个展开区。**
`pointerInput { detectDragGesturesAfterLongPress(...) }` 原来挂在**整张卡的外层**
⇒ 展开区里的**输入框 / 「标题也进提示词」开关 / 「提交」按钮**全在它的手势范围里。
⇒ 现在把拖动**收窄到标题行**（标题行本来就是"抓手"），展开区**没有任何拖动手势**，点哪儿都算数。

> ⚠️ 这是**第二次**栽在同一件事上（老账 3.51.0 悬浮便签：按钮压在整条可拖区里 ⇒ 必须做拖动把手）。
> 结论写死：**可拖区域绝不允许罩住可点区域。**

**② 按钮点了没有任何反馈。**
`提交` 的唯一效果是"把文本写进宿主"，**屏幕上什么都不变**（正文照旧在框里、卡片照旧开着）
⇒ 在用户眼里就是"点了没反应、点不动"。
⇒ 现在提交会**明确回一句**：`已提交到系统提示词 ✓` / `没有改动（内容与已保存的一致）`，
并且按钮文案改成「**提交到提示词**」。

## 六、教训

**1027 · ⭐⭐⭐ `width()` 服从父约束；要突破必须 `requiredWidth()`。**
　　`Modifier.width(n)` 是"**期望**"：父给的 max 更小就被夹住（我第一版就是这么白改的）。
　　⇒ 想让一个东西**真的比父容器宽**（分页、长横条、溢出内容），用 `requiredWidth`。

**1028 · ⭐⭐⭐ 能"派生"的状态，就别"自己存"。**
　　分页位置原来是自己维护的浮点 + 自己写的 `animate` ⇒ 动画被打断就**停在中间**。
　　改成 `animateFloatAsState(target = colIdx)`（从整数派生）之后，"停在中间"这个状态**根本不存在**。
　　⇒ **凡是"必须只有几个合法值"的东西，就让状态本身就是那几个值。**

**1029 · ⭐⭐⭐ 症状换来换去时，换方案，别换补丁。**
　　"右列没有 → 两列同屏 → 卡在中间"—— 每一版都在修上一个症状，却总冒出新的。
　　这说明**方案本身不对**（手搓连续位移分页）。⇒ 停下来换成"结构上不可能出错"的那版
　　（只渲染当前列），一次到位。**跟自己的代码较劲，不如跟问题较劲。**

**1030 · ⭐⭐⭐ 可拖区域绝不允许罩住可点区域（这是第二次栽）。**
　　3.51.0（悬浮便签）已经结论过一次：拖动要收进**专用把手**。
　　这次长按拖动挂在整张卡上，把展开区的输入框/开关/按钮都罩住了 ⇒ **按钮点不动**。
　　⇒ 规则：**拖动的手势范围 = 明确的一块"抓手"**（这里是标题行），永远不要"整张卡"。

**1031 · ⭐⭐ 没有反馈的按钮 = 用户眼里的坏按钮。**
　　「提交」其实**生效了**，但屏幕上没有任何变化 ⇒ 主人只能判断成"点不动"。
　　⇒ 凡是"点了之后界面不变"的动作，**必须给一句话**（成功/无改动/失败）。

**1032 · ⭐⭐ 先把证据拿到，再改代码。**
　　3.63.4 我基于"分页卡在中间"的**猜测**改了状态机 —— 结果又不对。
　　真正定位准的是**主人那张截图**（一眼看出"两列并排画在同一屏"）。
　　⇒ `uiautomator dump` 对 Compose 基本是空的（试过，根本没自己的节点）⇒
　　**遇到纯视觉问题，先要一张截图**，比盲改三轮便宜得多。

**1033 · ⭐（给自己记的）这一轮我反复踩同一个操作坑。**
　　· 写文档脚本时**中文串里混 ASCII 引号** ⇒ 脚本直接语法错（栽了 3 次以上）；
　　· **"改文件"和"跑构建"并排发** ⇒ 编出来的包跟最终源码不一致（栽了 4 次以上）。
　　⇒ 从这版起：脚本里的中文引用**一律用「」**；**构建/安装/拉取这类命令，永远单独发一条**。
