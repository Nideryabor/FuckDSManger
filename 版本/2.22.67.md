## 1. 本轮改动：合并判据

```
depth <= 0                                     ← 原有守卫，未动
 且 方法名 == "v"                               ← 原有守卫，未动
 且 args[1] 是 Long                             ← 原有守卫，未动
 且 ( caller() == "ju.q:2104"                    ← 调用点白名单（精确）
      OR  sPageCnt < 10(0xa) )                    ← ★ 新增：本页前 10 层兜底
     ⇒ 全透明（alpha = 0）
```

**为什么加 `< 10` 这一条**：
- 旧日志显示遮盖层是 `bg#1~#8` ⇒ **前 10 层足以覆盖它们**
- 而按钮的 `cnt` 在 20+ ⇒ **不会被误伤**
- ⚠️ 2.22.51 曾用「最外前 6 层」**成功出过背景**（那是当时唯一成功的版本）⇒ 这条规则是**被验证过的**

### `sPageCnt` 的重置点（本轮已核实）

`GmPageHook.beforeHookedMethod`（**每次进 ChatPage**）：
```smali
sPageDepth++            # 作用域 +1
sPageCnt = 0            # ★ 本页计数清零
sPageColor = 0          # 三槽颜色清零
sSurfaceColor = 0
sExtraColor = 0
```
⇒ **每进一次聊天页，`cnt` 就归零** ⇒ "前 10 层"这条规则**每页都重新生效**，不会像"一次性配额"那样永久失效（教训 132 的那个坑）。

## 5. 教训（143~146）

| # | 内容 |
|---|---|
| **143** | ⭐⭐⭐ **「过渡时能看见」= 稳定态被额外的层盖住 —— 判据只覆盖了一部分层**：2.22.51 就记过这条心法，这轮又踩。**"透空的判据"必须是"覆盖层的全集"**，只放开一个调用点 ⇒ 剩下的层照样盖。⇒ **下次遇到"只在某瞬间可见"，第一件事是"列出稳定态比过渡态多出来的那些层"**（而不是去查"图有没有画"）。 |
| **144** | ⭐⭐⭐ **被验证过的"旧规则"要当资产用，不要当包袱扔**：「最外前 N 层」是 2.22.51 唯一成功过出背景的规则，后来因为"颜色三槽"的引入被丢掉了。**这一版把它捡回来当兜底**。⇒ **回退/放弃一条规则时，要写清"它为什么被换掉"**；如果被换掉的原因是"另一个 bug"，那它本身可能还是对的。 |
| **145** | ⭐⭐ **"计数配额"不一定都是坑 —— 关键看它**在哪里**清零点**：`sPageCnt` 同样是"配额"，但它在**每次进 ChatPage 时清零** ⇒ 每页重新生效；而 2.22.55 那个"连续同色计数"失效是因为**补货条件永远不满足**。⇒ **判断"配额型判据"是否可靠，只看一件事：它的重置点是不是"每次该生效的时候都会走到"。** |
| **146** | ⭐ **改判据时保留旧守卫，这次立刻收回了成本**：`method=="v"` / `args[1]` 是 `Long` / `sDepth<=0` 三个守卫从 2.22.53 起**一个字没动** ⇒ 这轮出问题能直接把范围压到"判据那几行"去看。 |
