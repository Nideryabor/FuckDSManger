## 二、★ 修掉 `NoClassDefFoundError: Lg56;`

```
java.lang.NoClassDefFoundError: Failed resolution of: Lg56;
    at GmSuggestHook.add → build → fill
Caused by: ClassNotFoundException: Didn't find class "g56" on path:
    DexPathList[[dex file "InMemoryDexFile[…]"], nativeLibraryDirectories=[…/com.little_femaleboy…/base.apk!/lib/arm64-v8a, …]]
```

关键在 **DexPathList**：里面**只有我们模块自己的 in-memory dex**
⇒ `GmSuggestHook` 是被**模块专属 ClassLoader** 加载的，它**看不到宿主 `base.apk` 里的 `g56`**
⇒ 所以 `new-instance v0, Lg56;` 这种**直连宿主类**的写法必然炸。

> 🔎 佐证：项目里 `GmSendRun.send` 早就在用
> `宿主对象.getClassLoader().loadClass("cn1")` + `XposedHelpers.newInstance(...)`
> —— **前人踩过这个坑**，只是这段 suggest 代码抄了直连写法（而且因为 `fill()` 从没跑到过，一直没暴露）。

**修法**：`add()` 改成

```
宿主对象（GmEntry.sAct，兜底 GmUtil.app()）
  → getClass().getClassLoader()
  → loadClass("g56")
  → XposedHelpers.newInstance(cls, [Integer(7), Integer(id), "default", 文字])
  → list.add(obj)
```

> `XposedHelpers.newInstance` 对「装箱 Integer 匹配 int 形参」是 OK 的 —— `GmSendRun` 那条
> `new cn1(text, mask)` 在 2.10.14 真机验证过。

## 三、★ 顺手把 `g56` 的字段语义钉死（用字段引用查，不靠猜）

| 字段 | 谁在读 | 语义 |
|---|---|---|
| `a` (int) | **`yb5.f`**（`check-cast Lg56; iget a` → 建 `LinkedHashSet<Integer>` 做**防抖点击 key**） | **id** ✓ |
| `b` (String) | `g56.toString`（印成 `Scene(value=…)`）· **`nb5.c`**（`:414`） | **scene 名**（"default"/"image"/…）✓ |
| **`c` (String)** | **`Lpd5;->H(Lg56;Ley3;)` 与 `Lpd5;->I(Lg56;Landroid/content/Context;)` —— 两个「取文字」函数** | **★ chip 上显示的文字** ✓ |
| `d` (Integer) | `g56.toString`（印成 `scene=`） | scene 的数值形态（本版留 null） |

**⇒ 原来的填法 `(mask=7, id=0x2329, "default", 文字)` 本来就是对的**（`mask=7` ⇒ 全参数走 synthetic 构造），
坏的只有**类加载器**这一件事。

**另一个好消息**：`yb5.f` 渲染时**只读 `a`，完全不做 scene 过滤**
⇒ 即使我们填的是 `"default"`，chip 也会照常显示。

## 七、教训

| # | 教训 |
|---|---|
| 161 | ⭐⭐⭐ **模块类不能直连宿主类** —— 模块由专属 ClassLoader 载入，看不见宿主 dex；必须 `宿主对象.getClassLoader().loadClass(...)` + 反射 |
| 162 | ⭐⭐⭐ **「日志堆栈逐帧对齐」是最高效的验证手段** —— 30 轮悬案靠一张调用栈一次结案，比任何推理都硬 |
| 163 | ⭐⭐ **字段语义要查「谁在读」** —— 用 `dex_xref` 查 field 的读点，比读 `toString` 猜字段可靠得多（本轮靠它确认 `c` 才是显示文字） |
| 164 | ⭐⭐ **先修「跑不到」，再修「跑不对」** —— 前 33 轮全卡在「钩子不命中」，一旦命中，真正的坑才暴露出来 |
| 165 | ⭐ **项目里已有的写法就是线索** —— `GmSendRun` 的反射写法说明了 Loader 问题早就存在 |
