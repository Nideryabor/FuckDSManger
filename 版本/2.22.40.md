⇒ 那就只剩「条件跳转写反」一种可能。

**搜 `if-gtz`（限定模块包）⇒ 命中 4 处，全是我手写的**：

| 类 | 位置 | 我写的 | 语义 | 实际后果 |
|---|---|---|---|---|
| **`GmBubblePaintHook.pg`** | `sPageDepth` 检查 | `if-gtz v0, :end` | 「**> 0 就跳过**」 | `depth=1` ⇒ **立刻 return** ⇒ **透明化从未执行** |
| **`GmShadowHook`** | `sDepth` 检查 | `if-gtz v0, :end` | 同上 | ⇒ **阴影归零从未执行** |
| **`GmAlphaHook`** | `sDepth` 检查 | `if-gtz v2, :end` | 同上 | ⇒ **图片透明度从未执行** |
| **`GmPageHook.after`** | 防负保护 | `if-gtz v0, :end` | 同上 | ⇒ **`sPageDepth` 永不递减**（只增不减） |

**smali 条件跳转的正确语义**：

```
if-eqz  vA, :L   →  vA == 0 跳
if-nez  vA, :L   →  vA != 0 跳
if-ltz  vA, :L   →  vA <  0 跳
if-gez  vA, :L   →  vA >= 0 跳
if-gtz  vA, :L   →  vA >  0 跳     ← 我误当成「<= 0 跳」
if-lez  vA, :L   →  vA <= 0 跳     ← 我真正想要的
```

⇒ 我要的一律是「**计数器 <= 0 才跳过**」⇒ 必须用 **`if-lez`**。

## 4. 教训（810~812）

| # | 内容 |
|---|---|
| **810** | ⭐⭐⭐ **smali 的条件跳转是「按跳转条件命名」，不是「按你想干什么命名」**：`if-gtz` = 「**大于** 0 跳」—— 我脑子里想的是「小于等于 0 才跳过」，于是写成了 `if-gtz`，**语义正好相反**。⇒ **手写每个 `if-*z` 之后，立刻用一句话注释「跳到 X 的条件是什么」**（这条在教训 743 里写过，这次是**同一个坑的第 N 次复发**）。 |
| **811** | ⭐⭐⭐ **「静默 return」的组合最危险**：`if-*z → :end → return-void` 这种「提前返回」写法本身很干净，但一旦条件写反，**整个功能变成空转**，而且 **hook 日志、注册日志全部照常**。⇒ **凡是新写的前置守卫，必须在「守卫通过」的那条路径上留一条可观测痕迹**（本次的 `cnt=` 就是这样的痕迹 —— 正是它把 9 版空转照出来了）。 |
| **812** | ⭐⭐ **「计数不动」是最省事的定位信号**：`depth` 正常而 `cnt` 恒 0 ⇒ 一句话锁定「卡在 `pg` 的判据链里，且卡在 `cnt++` 之前」。⇒ **在关键分支上放一个只增不减的计数器**，比在每条分支上写日志便宜得多、也更容易读。 |
