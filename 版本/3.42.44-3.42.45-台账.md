## 二、⭐ 这一轮最重要的结论（一句）

> **封顶（`min(sCover, zoomF)`）会造成"盖不满"，而"盖不满"这件事
> ——任何 `TileMode` 都补不回来。**

**为什么补不回来**：`TileMode` 只决定"shader 平面上超出位图范围的坐标取什么颜色"。
但**"哪里被画"是由宿主的绘制区域/裁剪决定的，不是由 shader 决定的**。
我们拿到的 `size` 与宿主真实绘制区域不一致时，超出部分的 shader 再漂亮也画不上去。

⇒ **「永远铺满」是硬要求，糊是软代价。**
⇒ 想铺满，就**必须**让 `s = sCover`；一旦 `min` 了，必然有区域盖不满。

## 四、3.42.45 的具体改动（1 处）

`GmBubbleFitHook.beforeHookedMethod`：

```smali
- invoke-static {}, GmBubble;->zoomF()F
- move-result p0
- invoke-static {v10, p0}, Ljava/lang/Math;->min(FF)F     # ← 封顶：这才是"盖不满"的来源
- move-result v10
+ invoke-static {}, GmBubble;->zoomF()F
+ move-result p0                                          # ← 只留作日志对照，不再参与计算
```

⇒ `v10 = sCover`（铺满所需的缩放）**原样使用**。
⇒ `TileMode` 固定 `CLAMP`（正好盖满时它用不上，只兜浮点误差）。
⇒ 日志多了 ` zoom=` 字段，主人能直接看出"这次放大了几倍 / 配置上限是多少"。

### 现在日志长这样

```
[FIT] 图=1440x3168 目标=(1440,25349) scale=8.00 zoom=2.00
```

`scale=8.00` 就是**图被放大的倍数**。它 > `zoom=2.00` 时，图会糊 —— 这是"铺满优先"付出的代价。
**如果主人觉得糊得不能接受** ⇒ 一句话切回封顶（`min` 一行），但那样必然留白。
