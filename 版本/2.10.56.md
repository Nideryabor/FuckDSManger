## 一、从这份日志里读出的两件事

### 1.1 ⭐ 宿主**只在启动时读一次**配置

```
1789792933810 [mmkv] 命中 model_configs 键   ┐
1789792934284 [mmkv] 命中 model_configs 键   │ 4 次，全在启动头 500ms 内
1789792934285 [mmkv] 命中 model_configs 键   │
1789792934285 [mmkv] 命中 model_configs 键   ┘
1789793132729 MainActivity.onResume …        ← 第二次进 App：**一条 [mmkv] 都没有**
1789793166375 （第三次：只有 PHook）
```

⇒ **宿主把配置读进内存后就再也不读 MMKV 了**（走缓存）。
⇒ 所以「模型切换要生效」，**必须在启动那一次读取时就替换成功**；onResume 之后再写盘，对本次会话没用（得等下次启动）。

### 1.2 ✅ 字段名没问题（在宿主里验证过）

```smali
# 宿主 w46（ModelConfig 的序列化器）
const-string v0, "switchable"
invoke-virtual {v1, v0, v3}, Lm47;->j(Ljava/lang/String;Z)V
```

```smali
# 宿主 v56 的 toString 里也有
const-string v1, ", switchable="
```

⇒ **`switchable` 确实是那个 boolean 字段** —— 我们替换的目标串没错。

### 1.3 链路（已确认存在）

```
Activity.onResume ─┐
                   ├─► GmSync.reapplyAll() ──► GmModel.reapply(ctx) ★
```

## 二、问题：`reapply` 内部一步日志都没有

53 版改造 `reapply()` 时我**忘了埋点** ⇒ 日志里只有 `[mmkv] 命中`（说明 hook 在跑），却看不出 `reapply` 走到哪一步断的。

**⇒ 本版把它的每条出口都打出来：**

| 出口 | 日志 |
|---|---|
| 开关没开 | `[model] reapply 跳过：模型切换开关未开` |
| 读不到宿主配置 | `[model] reapply 跳过：读不到宿主配置（host=null）` |
| 值里没有目标串 | `[model] reapply 跳过：配置里没有 switchable:false` |
| 成功 | `[model] reapply 已替换，写宿主=<true/false>` |

（配合 55 版已有的 `[mmkv] 样本 …` / `[mmkv] 跳过：…` / `[mmkv] …已替换`，整条链从读盘到落盘都有话。）

## 三、我的先验怀疑（等日志验证）

按可能性排序：

1. **`GmModel.isOn(ctx)` 在启动早期读不到**（模块侧 SharedPreferences/Context 还没就绪）⇒ 返回 false ⇒ 直接跳过
2. **`GmPrompt.host()` 拿到 null**（宿主 MMKV 还没初始化完）
3. 宿主配置里那一项**不是 `false`**（例如已经被别的灰度值覆盖）⇒ 替换无变化

⇒ 三种都会在 56 版日志里**各有一句话**，下次必定能定位。

## 五、教训

| # | 教训 |
|---|---|
| **300** | ⭐⭐⭐ **"读一次就缓存"型数据，注入必须在首次读取时成功**：之后再写盘只对**下次启动**有效 —— 这解释了"闪一下就没" |
| **301** | ⭐⭐⭐ **改造旧函数时不许丢埋点**：53 版重写 `reapply` 却没加日志，白白多耗一轮 |
| **302** | ⭐⭐ **字段名要在宿主侧验证**（`w46` 里的 `"switchable"`），别只信自己几周前写的常量 |
| **303** | ⭐⭐ **"命中 N 次、成功 0 次"是最有用的信号**：它把"没接上"和"接上了但没生效"一刀切开 |
